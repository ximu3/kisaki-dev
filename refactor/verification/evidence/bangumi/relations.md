# Bangumi 主体、参与范围与配音分类

验证日期：2026-10-13。使用官方 API 与官网公开资料页，未连接账号或执行写入。[观察数据](2026-10-13-relations.json)保存本轮 17 次 API 请求的相关字段投影，以及两部动画角色页面的资料区提取结果。原始简介、图片字节和页面评论不进入该数据文件。

## 现实参与者与虚构档案

官方 schema 的 PersonType 将 1、2、3 分别用于个人、公司和组合；CharacterType 的 1、2、3、4 则分别用于角色、机体、舰船和组织。两个资源中的“组织”含义不同，不能只按中文词面合并。

实际读取的角色档案包括：

| 来源身份         | 名称               | 来源类别           |
| ---------------- | ------------------ | ------------------ |
| character/86246  | 芙莉莲             | 角色，type = 1     |
| character/170241 | EVA-05 暂设 5 号机 | 机体，type = 2     |
| character/5090   | 特务机关 NERV      | 虚构组织，type = 4 |

这些资料说明 character 资源的范围超出通常的人物角色。舰船类别已在 schema 中确认，但本轮没有得到可用于验证的舰船样本。已确认的[角色采用规则](../../../design/extensions/sources/bangumi.md#characters)只采用 type = 1，排除机体、舰船与虚构组织；这属于产品范围取舍，不能因 API 使用 character 路径就全部接入。

官方角色搜索只声明 keyword 和 nsfw 条件，没有 CharacterType 筛选参数。现有搜索样本同页同时出现 type = 1 与 type = 2 或 4，因此扩展须在返回后按类别过滤并正常续页；样本中的主角、配角等作品定位不代替对象类别。

类型字段同样可能包含源站录入错误。本轮 person/51697、person/47194 的 type 都为 2，但同一公开档案的生平与生日描述的是个人。这不改变字段的官方枚举含义，也不能用这些记录作为“真实公司”的正例；本材料不将按来源字段分类宣称为已经纠正所有主体身份。

## 工作与版本说明

GET /v0/subjects/400602/persons 返回《葬送的芙莉莲》第一季的 862 项参与记录。其中 source type 为 1、2、3 的行数分别为 843、17、2。行数表示工作关系数量，不等于独立人物数量；同一主体可以承担多项工作。

relation 提供本作岗位，career 表达人或组织的常见职业，eps 表达参与范围。不能用 career 代替本作岗位，也不能把所有名称含“监督”的岗位都归为导演。例如，摄影监督与美术监督应分别按实际摄影、美术职责解释，细分称谓与参与集数仍可保留在关系说明中。

漫画 subject/305429 的 10 项参与中包含原作、作画、译者、连载杂志、出版社、出品方和图书品牌。Norma Editorial 的出版社关系以 eps 标明“西班牙版”，Altraverse 的关系标明“德国版”。因此 eps 不能一律解析成集号，也不能将全部出版社都称为原版出版社。采用遵守已确认的[主体参与范围](../../../design/extensions/sources/bangumi.md#staff-scope)。

后续[版本分组验证](versions.md)确认 API infobox 与官网保留了书籍版本分组，能够解释部分 eps 为空的译版署名；主体出版社还可能只在基础资料中出现。版本采用不能只靠参与者列表的 eps 是否为空判断。

## 跨媒介联系的准确含义

先前[作品范围样本](2026-10-13-subject-scope.json)中，动画 subject/400602 同时以“书籍”关联漫画 subject/305429 和小说 subject/535646。本轮读取后者，确认它是《小説 アニメ 葬送のフリーレン》，另有作者与原作署名。

“书籍”只说明关联记录所属媒介，不能单独证明哪一方是另一方的原作；“动画”也同样不能直接转换为改编方向。采用仍遵守[直接关系含义](../../../design/domains/relations.md#work-relations)：来源明确但方向不足的直接联系可以使用 related 及真实说明，不根据媒介、日期或名称自行推导改编。

## API 与官网的配音分类

两类 API 都返回了混合配音：/v0/subjects/{id}/characters 的 actors，以及 /v0/characters/{id}/persons。后者的 staff 在芙莉莲样本中都是“主角”，不能用于判断配音语言。

官网作品角色页面保留演员关系类型。资料区中的每项演员块含 attr-rlt-type 与类别名称，本轮观察如下：

| 作品与角色             | 人物           | 来源类别 | 原配采用 |
| ---------------------- | -------------- | -------- | -------- |
| 葬送的芙莉莲／芙莉莲   | 种崎敦美       | 0，CV    | 采用     |
| 葬送的芙莉莲／芙莉莲   | 李蝉妃、李昀晴 | 3，中配  | 不采用   |
| 时光代理人第二季／陆光 | 杨天翔         | 0，CV    | 采用     |
| 时光代理人第二季／陆光 | 樱井孝宏       | 4，日配  | 不采用   |

《葬送的芙莉莲》的 API 与官网资料区均有 91 个角色、203 项角色与演员对应；网页分为 88 项 CV 与 115 项中配。静态提取原型对两部动画分别核对了全部角色身份和演员对应，结果一致；目标资料片段独立解析通过。页面其他区域不是数据来源，也不作为本材料的正文内容。

这个结果支持使用官网 CV 类别承接[原配范围](../../../design/extensions/sources/bangumi.md#cast)，并证明它并非固定表示日语配音。规则依赖来源的正确分类，不能保证自动识别源站漏标译配，也不按演员国籍或姓名修正来源类别。网页中的真人演员、其他作品出演和评论不能变成当前动画的配音关系。

## 验证边界

本轮验证了实际字段、角色与人员列表、来源岗位和版本说明，以及两部动画的配音类别提取；没有验证全部来源枚举、所有作品页面、授权记录、完整扩展实现或生产解析器。角色和主体参与范围已写入正式设计，资料质量限制继续成立。

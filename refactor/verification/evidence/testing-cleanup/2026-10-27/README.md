# 测试必要性收敛实施

本轮按用户确认落实[全面测试必要性复核](../../comprehensive-review/2026-10-26/testing.md)的代码、任务、CI 和文档调整。实施环境为 Windows x64，开发 Node 24.11.1、pnpm 11.11.0、Turbo 2.11.10、Electron 44.5.1；没有改变产品能力、公开合同、平台支持或 RPC 方案。

## 用例与实际边界

- Husky 测试保留空 hooksPath 与一个非空冲突路径，删除同分支的 `.lefthook` 参数。项目继续使用 Husky。
- 不覆盖移动只执行一次操作，再核对同一结果的错误类型与原因。原生装载用一个无效模块核对错误及 cause。
- 窗口交互保留键盘和关闭错误反馈，圆角由既有成品消费者验证。发布配置只约束实际要求的 public access。
- 原生套件在启动前核对一次 Electron 宿主和 Node-API 下限；版本读取应用 manifest。有限构建和 Electron fixture 也读取同一依赖声明，fixture 继续核对构建与启动宿主相符。
- 11 项依赖边界案例共享一个合成工程和一次真实 dependency-cruiser 分析，逐来源核对独立规则，保留全部有效反例和正例。
- 配置与公共包输入监听转到真实 Vite 集成测试，覆盖首次快照采用导致的 Vite 重启；输出清理在临时文件系统核对 out／dist 删除及 profile／缓存保留。
- 真实开发会话拆成退出取消与正常关闭、运行程序编译失败与改名恢复、公共包失败与 HMR／快照采用三个独立场景。三个场景共用一次隔离工作区准备，各自关闭控制器并恢复输入。首次准备取消与重试仍单独保留；控制器启动和收尾由已有场景共用的测试辅助负责。

没有添加浏览器缺失、重复故障注入或针对简单删减的探针。新增的较小接入用例承接原综合用例的职责；任务选择用例验证这次改变的 CI 调度边界。

## 任务输入与 CI

采用 Turbo 已有的[任务输入选择](https://turborepo.dev/docs/reference/configuration#inputs)和 [affectedTasks 查询](https://turborepo.dev/docs/reference/query)，用实际任务配置决定影响范围。查询文件只选择并读取任务，不重新推导包依赖或实现路径分类器。运行检查继续禁用结果缓存。

构建准备与测试触发分开：根桌面测试入口显式先构建；应用脚本和对应 Turbo 测试任务消费已准备输入。CI 为选中套件共用一次目标构建。原生、窗口、开发、性能与制品分别选择，通用 Chromium 交互在 Ubuntu x64 执行一次；八包消费者仅在其实际输入或依赖变化时执行。

浏览器套件沿 UI 构建及其 appearance 依赖准备；开发套件沿公共 extension-cli 启动器及其 desktop-contracts 依赖传播变化，避免遗漏启动与退出协议变更，也避免把普通 UI 源码变化作为开发工具回归的前置。

全局工具链变化、初次提交或缺失基线按完整范围处理；查询失败使验证失败。手动 CI 及可复用工作流的 complete 输入请求完整验收。选中的原生与桌面任务仍使用六目标矩阵，性能保持每目标 20 次样本。Required checks 要求全部选中任务成功，不能把执行失败记成未选择。首次交付、发行前及主要后端的正式要求保持。

隔离 Git 工程使用真实 manifest、锁文件、任务配置和 Turbo 查询，验证了以下变化：

| 改动 | 额外选择的验证 |
| --- | --- |
| refactor 文档 | 不选择桌面或消费者套件 |
| 浏览器用例 | 浏览器 |
| 窗口端到端用例 | 窗口端到端 |
| 仓库外消费者用例 | 公共包消费者 |
| 开发会话工具 | 开发会话 |
| 公共 UI 源码 | 消费者、浏览器、窗口、性能与制品 |
| 公共 UI 编译配置 | 上述任务及开发会话 |
| 私有原生源码 | 原生、窗口、开发、性能与制品 |
| 公共开发启动器源码 | 消费者、开发、窗口、性能与制品 |
| 根 Node 工具链输入 | 全局任务变化，转入完整验收 |

普通类型、lint 和 Node 检查另按各自任务输入执行。显式输入排除 Cargo target 等生成目录；公共包 pack 的触发输入与实际打包文件及上游 build 对应。

同一隔离工程还核对了原生 `turbo run --affected --dry=json` 与查询结果一致。Turbo 对声明的全局输入返回 TaskGlobalDepsChanged；工作流同时识别 TaskAllChanged 和 TaskGlobalFileChanged。未知基线在查询前转入完整范围，其他查询错误不作为空结果使用。

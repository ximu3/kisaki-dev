# 文件识别方案与分部匹配

文件识别将名称或路径解释为已有分部的匹配条件，再在所属作品内查找并校验目标。本篇定义方案、规则语言、内置识别及完整输出；目录和文件的登记见[本地持有](holdings.md)，结果采用与持续维护见[文件维护](file-maintenance.md)。

<a id="recognition-responsibility"></a>

## 命名解释的职责

自定义规则在“文件名或路径 → 分部匹配条件”这一层独立、完整地解释命中的输入。内置识别与自定义规则处于同一层，交付相同语义的分部匹配条件，供 holdings 使用同一套查找、校验和关联能力处理。

| 阶段                 | 责任                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------- |
| 文件发现与作品范围   | holdings 按目录登记和发现设置确定当前作品、实际文件及可读性                               |
| 命名解释             | 本次采用的内置识别或自定义规则明确分部种类、编号或名称，以及分集或附加内容类型与适用范围  |
| 查找、校验与保存关联 | holdings 在当前作品内查找已有分部，检查唯一性、冲突和完整性，并遵守关联保护与提交基线约束 |

完整指匹配条件的语义足够明确：所选目标的必要条件必须齐全，可选条件省略时不形成约束。目标种类、编号含义及适用范围不能留给另一种识别方式补齐。自定义规则不读取内置识别结果，也不对内置结果逐字段覆盖、补充或应用偏移；内置识别同样不补齐或重解释已命中规则的输出。仅提供偏移、要求内置先猜出分部目标，不构成完整规则。

一份方案可以覆盖部分命名格式。每次命名解释完整采用一个来源，按下方[有序规则](#recognition-rules)选择自定义或内置识别。文件发现、资料获取、分部创建和关联写入由各自流程完成，识别始终使用调用方已经确定的作品范围。

<a id="recognition-profiles"></a>

## 文件识别方案与共享引用

文件识别方案保存文件名或路径如何解释为已有分部的种类、编号、名称与范围。方案不保存作品 ID、分部 ID、目录绝对路径、实际文件关联、首选或使用位置，也不创建分部。识别始终限定在采用该方案的目录所属作品内。

| 方案类型                    | 表                              | 目录引用                                 |
| --------------------------- | ------------------------------- | ---------------------------------------- |
| AnimeFileRecognitionProfile | anime_file_recognition_profiles | anime_directories.recognition_profile_id |
| ComicFileRecognitionProfile | comic_file_recognition_profiles | comic_directories.recognition_profile_id |
| NovelFileRecognitionProfile | novel_file_recognition_profiles | novel_directories.recognition_profile_id |

三张方案表分别由 library.holdings 的对应媒介管理，目录字段使用真实外键，只能引用同类方案。一个方案可以供多个同类作品的目录共同使用，不属于某个作品，也不会随某个引用作品删除。它们不进入 Entry、MetadataProfile 或 scanner.recognizers，不建立 Game 文件识别方案。

| 共同字段    | 类型与约束                                                  |
| ----------- | ----------------------------------------------------------- |
| id          | TEXT，稳定主键                                              |
| name        | TEXT，非空且非空白；允许重名，不作为引用键                  |
| description | TEXT，可空，说明方案用途                                    |
| definition  | TEXT，经过该媒介完整语义校验的 JSON 命名解释规则            |
| sort_order  | INTEGER，非负，默认 0；人工排列，同序以 id 稳定排序         |
| created_at  | INTEGER，UTC 毫秒，由本体在创建时生成                       |
| updated_at  | INTEGER，UTC 毫秒，由本体在实际编辑时更新，不随识别执行变化 |

方案按具体媒介提供 list、get、create、update、delete 和 reorder，使用[配置管理](scanner.md#configuration)的草稿、字段基线和整体 definition 校验规则。没有作品级或全局默认方案；每个目录至多引用一个方案，或保留 NULL 使用内置规则。一个方案可以包含多条有序规则，同一目录中的不同文件可以分别命中不同规则。方案不可读取或定义无效时保留引用并报告问题，不能当作未选择后静默使用内置规则。

修改共享方案的规则定义后，所有引用目录的后续识别采用新定义。每次识别固定目录路径、方案引用与规则定义，提交关联前重新核对这些依据；实际识别依据已经改变的未提交结果不能按旧依据写入。新发现的登记另须核对发现设置，已有文件的识别不依赖过滤条件。已经提交的非空关联继续保留，用户可以通过重新识别修正；规则测试与发现预览仍属于各自编辑器。开启自动刷新时，方案定义修改后合并调度实际引用目录中具备自动匹配资格的空关联文件；仅改名、说明或排列不触发识别。

需要局部差异时，复制方案并让相应目录明确选用副本。复制创建新的独立身份，不保留父方案或同步关系；修改副本不改变原方案及其引用。目录、文件和分部的真实身份也不随方案复制而变化。

管理界面显示引用数量及实际目录列表。仍被引用的方案不能直接删除，须先明确替换或解除引用；删除时再次检查引用，不级联删除目录，也不自动选择另一方案。解除引用表示用户明确改用内置规则，与方案失效分别处理。

目录编辑器提供方案选择和通往管理对话框的入口。目录草稿与方案编辑分别保存；创建方案不会自动提交目录，用户明确选用后才改变目录草稿。编辑已有共享方案时显示实际引用范围，保存仍按方案自身的完整操作完成。

<a id="recognition-rules"></a>

## 有序规则与分部目标

definition.rules 是有序命名规则列表。每项保存方案内稳定的 id、可编辑 name、enabled、input、pattern、ignoreCase，以及该媒介明确的输出目标。规则没有独立表，数组顺序决定求值顺序。input 选择下方[匹配文本](#recognition-inputs)中的 baseName 或 path；完整字符串匹配、正则 flags、命名捕获组与输出模板复用[共同值合同](scanner.md#rule-values)。文件识别使用自己的分部目标，不输出 WorkClues 或任意对象路径。

| 方案媒介 | 允许的目标   | 最低匹配条件                                                                               |
| -------- | ------------ | ------------------------------------------------------------------------------------------ |
| 动画     | Episode      | 当前作品内的分集编号或完整名称，可附加分集类型条件                                         |
| 动画     | Extra        | 当前作品内附加内容的完整名称，可按附加内容类型限定                                         |
| 漫画     | ComicVolume  | 当前作品内的卷编号或完整名称                                                               |
| 漫画     | ComicChapter | 当前作品内的话编号或完整名称；使用话号时明确采用作品话号或卷内话号，卷内话号还须明确卷范围 |
| 小说     | NovelVolume  | 当前作品内的卷编号或完整名称                                                               |

规则明确声明目标种类。只指定目标种类、分集类型、附加内容类型或漫画话所属的卷，不构成完整目标，即使当前作品中恰好只有一个候选。编号也可以使用符合[完整关联合同](#recognition-ranges)的明确编号范围；多个目标各自满足最低条件，并共同遵守完整关联要求。Extra 没有结构化编号，必须使用完整名称，不能从名称中的数字补造编号字段。

漫画话只按名称匹配时不需要编号依据；使用编号或编号范围时必须明确采用作品话号或卷内话号，不能根据本地资料能命中哪一种来选择。明确指定卷范围时，使用该卷的编号或完整名称唯一确定卷；只限定卷而没有话的编号或名称，不能据此选取其中一话。

所提供的编号、名称、分集或附加内容类型与范围约束必须同时成立。分集类型和附加内容类型用于过滤相应分部，省略时接受该种类的全部类型。识别只建立文件对应，资料字段继续保持原值。漫画卷、话和小说卷按其各自字段匹配。

文件使用其目录引用的方案，按顺序尝试启用规则。第一条完整匹配的规则决定解释，再校验输出并查找已有分部。只有全部自定义规则未匹配时才使用内置识别；未引用方案、规则列表为空或全部停用也属于这一情况。已匹配但输出无效、目标缺失或存在歧义时，保留问题，不继续试用后续规则，也不改用内置规则。规则之间不接力改写输入或合并解释。

方案自身不可读取或定义无效不属于未匹配，遵守方案失效合同。文件的登记和可读性与分部关联分别处理；无法形成关联，不阻止合法文件登记和使用。

<a id="recognition-context"></a>

## 文件识别的目录上下文

已明确的本地分部或规范外部身份先遵守[使用目标对应](holdings.md#files)的校验；以下流程处理仍需命名解释的文件。文件始终直接属于当前作品，参与目录限于该作品的同类目录，不能因为绝对路径相同就跨作品合并文件或匹配分部。

按已登记文件的当前位置和本作品的目录路径，确定唯一包含它的目录；目录根本身是图片阅读目标时也属于该目录上下文。此判断只依据路径包含关系，不使用深度、包含或排除条件。目录不互相包含，因此同一文件至多有一处上下文，不需要目录优先级、方案结果合并或新的文件目录外键。

例如，只登记 `作品A` 时，`作品A/第02卷/01.cbz` 使用这处目录的方案；`第02卷` 仍是普通子文件夹。规则可以从路径提取卷号和话号，不必额外登记这个子目录。文件被自动发现条件排除，或由用户明确手动添加，都不改变这项解释依据。

位于所有已登记目录之外的文件按零散文件处理，只将 baseName 交给内置识别。不臆造父目录作为相对根，不访问祖先名称，不新增文件级方案引用或全局默认方案。用户仍可明确关联真实分部。目录路径或方案自身不可读取时报告相应问题，不能按没有目录或未选择方案继续执行；发现过滤的不可用与它们分别处理。

新登记目录默认不引用方案。手动新增明确选择了已保存同类方案时，将其引用随目录一起提交；不会从 MetadataProfile、scanner 的作品线索规则或相邻目录推导文件方案。scanner 自动新增的目录使用默认发现设置与内置识别，不新增隐含的扫描配置文件方案字段。首次识别沿用这些实际已提交设置。

提交关联前，重新核对文件身份与归属、当前位置、实际目录上下文、方案引用和规则定义，并重新验证所有分部条件仍唯一成立。目录新增、移除或路径变更改变上下文时，旧结果不能继续提交；只改发现过滤不使已有文件的识别结果失效。自动提交还须确认 associationMode 仍为 automatic，且全部直接关联仍为空，保留准备期间用户建立或清空关联的决定。新发现文件登记前另核对实际路径仍符合本次发现设置，不用既有文件维护流程绕过过滤。

规则测试与实际识别共用文本准备、规则解释和目标校验；已有明确作品时，实际目标查找也使用同一能力。结果分别说明目录上下文、实际识别方式及命中规则、匹配条件、对应分部和问题。未识别、无效输出、目标缺失、目标歧义、解释冲突、配置失效、不可读取与取消分别表达。发现过程的过滤结果说明具体条件，不将其混为已有文件的识别状态。关联问题不妨碍合法文件登记和使用，不将每个未关联文件分别弹出错误通知。

<a id="recognition-inputs"></a>

## 自定义规则的匹配文本

input 只决定当前自定义正则匹配哪段文字，界面使用“匹配文本”。它不表示添加或导入方式，也不产生目录记录。正常使用内置识别不要求用户选择此项。每条规则明确选择一种文本，不在匹配失败后自动改用另一种。

| input    | 界面名称 | 文本准备                                                                                         |
| -------- | -------- | ------------------------------------------------------------------------------------------------ |
| baseName | 文件名   | 普通文件去除最后一个扩展名；图片目录使用完整目录名，无扩展名文件保持原名，开头的单个点不算扩展名 |
| path     | 路径     | 登记目录的末级名称与目录内相对路径用 `/` 连接，文件保留扩展名，目录无尾分隔符                    |

两种文本均保留原文和大小写，目录中的点号不按扩展名处理。path 固定包含登记目录名，不将根名作为可开关选项。例如，登记 `作品A`、目标为 `第02卷/01.cbz` 时，得到 `作品A/第02卷/01.cbz`；登记一处只包含部分作品内容的 `第02卷` 时，得到 `第02卷/01.cbz`。

根自身是图片阅读目标时，path 为根目录名。文件系统根或共享根没有普通末级目录名时，只使用目录内相对路径，不伪造盘符、服务器名或共享名。组合文本不读取根外内容或祖先名称，也不把实际根名、绝对路径或作品身份保存进共享方案。

scanner 为发现新作品准备的[线索文本](scanner.md#extraction)仍采用自己的候选边界。两者复用正则匹配和输出模板机制，不将扫描根和作品内容目录混为同一种业务范围。

<a id="recognition-targets"></a>

## 规则输出的结构与两种顺序

三个方案的 definition 都只保存 rules 字段。动画规则使用 `FileRecognitionRule<AnimeFileTarget>`，漫画使用 `FileRecognitionRule<ComicFileTarget>`，小说使用 `FileRecognitionRule<NovelFileTarget>`。rules 可以为空；每条规则的 output.targets 必须是非空列表，表示同一文件实际包含的全部声明目标。

```ts
interface FileRecognitionRule<TTarget> {
  id: string
  name: string
  enabled: boolean
  input: 'baseName' | 'path'
  pattern: string
  ignoreCase: boolean
  output: { targets: readonly TTarget[] }
}

interface FileNumberValue {
  value: string
  offset: number
}

type FileNumberOutput =
  | ({ kind: 'single' } & FileNumberValue)
  | { kind: 'range'; start: string; end: string; offset: number }

interface NumberedPartOutput {
  number?: FileNumberOutput
  name?: string
}

interface ComicVolumeScopeOutput {
  number?: FileNumberValue
  name?: string
}

type AnimeFileTarget =
  | (NumberedPartOutput & {
      kind: 'episode'
      episodeType?: 'regular' | 'special' | null
    })
  | {
      kind: 'extra'
      name: string
      extraType?: 'opening' | 'ending' | 'promotion' | 'interview' | 'other' | null
    }

type ComicFileTarget =
  | (NumberedPartOutput & { kind: 'volume' })
  | (NumberedPartOutput & {
      kind: 'chapter'
      numberBasis?: 'work' | 'volume'
      volume?: ComicVolumeScopeOutput
    })

type NovelFileTarget = NumberedPartOutput & { kind: 'volume' }
```

结构校验同时执行前述最低条件：NumberedPartOutput 和 ComicVolumeScopeOutput 至少配置 number 或 name，Extra 必须配置 name。目标只允许该媒介和所选 kind 声明的字段；例如，Extra 不接受 number，卷目标不接受 numberBasis、volume 或动画类型条件。同一列表可以明确包含该媒介允许的不同分部种类，全部目标仍受同一作品范围约束。

kind、episodeType、extraType、numberBasis 和 offset 都是规则中的固定值，不展开模板。只有编号的 value、start、end，以及分部和卷范围的 name 使用文字模板；固定文字与捕获引用沿用同一机制。offset 是已定义的有正负号安全整数，新建编号输出时初值为 0，保存的输出结构明确包含它；范围只有一个 offset，两个端点共同使用。卷范围的编号与话编号分别保存和应用自身偏移。

episodeType 和 extraType 使用[动画分部](anime.md)既有类型值。字段缺席表示不限类型，明确为 null 表示只匹配资料中类型未知的分部。具体枚举值只匹配该类型。未知类型不是捕获失败的替代值，非法枚举也不能转换成 null 后继续执行。

漫画话配置 number 时必须同时配置 numberBasis。work 使用作品话号；volume 使用卷内话号并要求配置 volume。只配置话名称时省略 numberBasis，也可以明确限定 volume。任何明确的 volume 都须通过自身编号或名称唯一确定一个卷，不能使用卷编号范围。该对象只限定话的查找范围；只有列表中另外存在 kind 为 volume 的直接目标时，才同时要求文件与卷的关联。

单编号的 value 不因包含连字符而变成范围。例如，single 的 01-03 是一个编号文本；range 的 start 为 01、end 为 03 才表示整数编号 1、2、3。范围上的 name、类型和卷范围条件对每个编号分别成立；需要不同条件时分别列出目标，不为每个范围成员重新展开模板或猜测名称。

本节结构保存输出定义。执行时展开文字并应用编号偏移，产生实际分部匹配条件；后续查找不再解释模板或重复换算。内置识别交付同一语义的实际条件，并沿用相同的查找与校验。

| 顺序               | 实际作用                                                                   |
| ------------------ | -------------------------------------------------------------------------- |
| rules 数组的排列   | 决定尝试规则的先后；首条完整匹配的启用规则决定本次解释                     |
| targets 数组的排列 | 保留目标在编辑和预览中的呈现顺序；全部目标共同成立，不产生目标之间的优先级 |

例如，两条规则都完整匹配 01 (329).mkv，一条输出编号 329，另一条输出编号 01，交换规则顺序可能改变所采用的解释。某条规则对 01+02.mkv 明确输出第 1、2 集时，交换这两个目标的排列仍关联相同的两个分集，不表示优先匹配哪一集，也不改变文件中的实际内容次序。

每个目标都须独立满足全部条件，之后才按真实分部身份去重并整体建立关联。目标列表不保存分部的 sort_order、文件内位置、首选或播放队列；调整其排列不会修改这些事实。不同目标解释发生冲突时也不能用列表先后决定采用哪一项。

<a id="recognition-output"></a>

## 输出展开与完整性

模板先产生本次匹配的实际输出，再按分部目标校验完整性。模板引用的任一捕获组未参与本次匹配时，整个字段缺席，固定前后缀也不保留；捕获到空字符串则照常展开模板，再校验最终值。编号或名称的最终值只有空白时为错误，不能将无效值当作字段缺席而忽略。模板语法与展开机制仍使用[共同值合同](scanner.md#rule-values)。

| 本次输出情况                     | 处理                                                       |
| -------------------------------- | ---------------------------------------------------------- |
| 分集编号存在，可选名称缺席       | 仅由编号形成目标的标识条件，其他已经输出的条件仍同时适用   |
| 编号与名称都缺席                 | 目标不完整，报告问题                                       |
| Extra 的名称缺席                 | 目标不完整，报告问题                                       |
| 已声明卷范围，卷编号与名称均缺席 | 报告问题，不能扩大到整个作品，也不能将卷内话号改作作品话号 |
| 明确编号范围的任一端点缺席       | 报告问题，不能省略范围或改成单编号                         |
| 多个声明目标中有一个不完整       | 整体报告问题，不能省略该目标而只采用其余部分               |

合法的实际输出共同组成匹配条件。可选名称没有输出时不形成名称约束；名称已经输出却无效或不能与编号同时匹配时，不能丢弃名称后只按编号关联。例如，同一条规则明确允许名称缺席，可以对 03 - 相遇.mkv 输出编号和名称，对 03.mkv 只输出编号。

保存时校验完整定义，包括停用规则的结构、方案内唯一的规则 id、非空名称、正则、模板引用、输出结构和必要配置，拒绝未知捕获组引用等可以在配置阶段确定的问题。预览和实际执行共用模板展开、编号换算和分部目标校验，先确认输出完整且合法，再查询已有分部。具体文件导致目标不完整或输出无效时，属于已命中规则的问题，遵守停止本次解释的约定，不尝试后续规则或内置识别。

文件规则的保存校验、规则测试和实际识别，共用[可终止的正则执行机制](scanner.md#validation)，不能在主进程同步执行用户正则。编译、匹配与输出展开受相同的预算和取消约束；分部查询与正式关联由 holdings 完成，不借用 scanner 的作品发现流程。执行预算遵守共同[验收预算](../../verification/acceptance.md#performance)，不能按入口或媒介另行放宽。

在一个作品的本次核对中，某份方案的规则求值超限时，终止对应执行单元，停止继续求值该方案快照。已经完整形成的结果保留，后续未处理文件明确报告未完成，不能标作未命中或改用内置规则。其他方案以及独立的文件发现、技术核对可以继续；超限不持久停用方案，也不扩大到其他作品的执行。正常输出无效仍按单文件问题处理，与执行单元超限分别表达。

## 内置识别的覆盖与参考依据

内置识别按完整命名结构理解发布组、标题、分部编号、修订和技术附注。常见发布组格式由本体直接支持，不要求用户先创建自定义方案；方括号中的编号、标题后约定位置的集号也可以提供明确线索。预设和自定义规则用于特殊命名、编号换算及需要用户明确声明的约定，不以此替代常见格式的内置覆盖。

各媒介使用以下资料核对格式覆盖、词元分类和测试样例。它们是实现参考，本体的输出与关联行为仍遵守本规格，不直接采用第三方程序的资料模型或全部默认判断。

| 媒介 | 主要参考                                                                                                                                                                                                   | 借鉴范围                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 动画 | [Anitomy](https://github.com/erengy/anitomy)、[AnitomySharp](https://github.com/chu-shen/AnitomySharp)及其[测试样例](https://github.com/chu-shen/AnitomySharp/blob/main/AnitomySharpTests/test-cases.json) | 发布组命名结构、括号与分隔符、集号和季号线索、修订及音视频附注     |
| 漫画 | [Manga Naming Scheme](https://github.com/Daiz/manga-naming-scheme)、[Kavita 命名约定](https://wiki.kavitareader.com/guides/scanner/managefiles/)                                                           | 卷号、话号、范围、发布组、语言、修订与来源卷的不同含义             |
| 小说 | [calibre 文件名提取](https://manual.calibre-ebook.com/regexp.html#adding-books)、[EPUB 元数据定义](https://www.w3.org/TR/epub-33/#sec-belongs-to-collection)                                               | 卷号与作者、标题的命名结构，以及系列归属、组内序位和本作卷号的区别 |

括号、分隔符和附注处理等共同机制可以复用，目标种类与编号范围由各媒介解释。分辨率、编码、位深、音频、语言、校验码和发布修订不能误作分部编号。不能删除所有括号内容后再猜编号，也不能无条件采用最后一个数字或按发布组名称白名单决定是否支持。

提取命名线索与关联正式分部分别完成。动画发布中的 BD 分卷不创建 AnimeVolume，也不转换成漫画卷或小说卷。漫画的 c012 (v02) 可以表示作品第 12 话取自第 2 卷，不能据此宣称完整覆盖第 2 卷、建立文件卷关联或改用卷内话号。EPUB 的系列归属与组内顺序同样不直接证明本作卷身份。

本体不继承与既定模型冲突的第三方转换。内置识别不能仅为套用上游结果，将上、下直接改成数值编号，将 153b 自动改成 153.5，或将所有卷、章标记统一当作 Episode。只有符合当前媒介语义、编号合同与明确范围的结果，才可用于匹配当前作品中的已有分部。原始编号、真实身份、唯一对应与完整关联要求保持一致。

输入覆盖须落实为本体自己的固定样例和期望值，并区分线索提取与关联结果。至少覆盖以下代表性结构；上游测试中的期望值须按本体合同核对，不以复现第三方默认行为代替验收。

| 输入示例                               | 必须表达的结果                                                       |
| -------------------------------------- | -------------------------------------------------------------------- |
| `[组] 作品 - 03 [1080p][HEVC].mkv`     | 匹配正片分集 03；技术标记不参与编号                                  |
| `[组] 作品 [13.10][Ma10p_1080p].mkv`   | 匹配正片分集 13.10，保留完整编号文本                                 |

| `作品 第3巻.epub`                      | 小说卷号线索 3，仍须对应当前作品中的已有卷                           |

## 动画内置匹配的默认行为

动画内置识别先按完整命名结构确定标题、内容编号、季号、替代编号、修订和技术附注各自的角色，再形成分部匹配条件。不对任意数字片段直接套用集号规则，也不通过查询哪个编号能命中来决定其含义。

已经识别为普通分集命名，且没有特别内容、附加内容或解释冲突的线索时，明确输出 Episode、episodeType 为 regular，以及主集号。标题后的编号、内容位置的括号编号、明确集号标记和非零季的普通季集格式都采用这一默认。作品标题不作为分部名称条件，完全未识别的命名不能仅因没有特殊标记就归为正片。

正片条件只匹配资料中类型为 regular 的分集。同号的 special 或类型为 NULL 的记录不参与该目标的候选集合；没有正片候选时保持未关联，不用其他类型替代，也不将已有未知类型改写为正片。这个默认是内置解释明确给出的类型条件，普通匹配条件省略类型时仍保持不限类型的既有含义。

主集号用于匹配，明确的替代编号只保留为识别说明。例如，主次结构中的 01 (329) 采用 01，不能把 329 当成第二个目标，也不能在 01 未匹配时改用 329。03v2 的主集号为 03，2 是修订；分辨率、编码、位深和校验码等技术信息不参与分部编号。相同角色的多个明确编号互相矛盾，且命名结构没有将它们表达为范围或清单时，报告解释冲突。

非零季的普通季集格式按其中的集号匹配目录已绑定作品的正片分集。S02E03 的目标编号为 03，季号 02 保留在识别说明中，不创建季实体、不改换所属作品、不自动换算全系列集号，也不据此声称已经校验作品的季号。目录归属继续作为本次识别的作品范围。

普通分集命名中的整数范围与明确编号清单均输出正片条件，并遵守完整关联。01-03 对应 1、2、3；01+03 只对应 1、3。每个目标都必须找到唯一且符合类型条件的已有分集，之后才整体关联，缺少任何一项都不提交部分结果。

能够明确识别附加内容种类与完整内容名称时，生成 Extra 目标。例如，内容段 NCOP01 生成 name 为 NCOP01、extraType 为 opening 的匹配条件，遵守已有名称比较，不因类别或尾部数字相同就采用其他名称。仅有 SP、S00 等仍不足以确定分部种类的线索时，保留问题，不退回普通正片默认。识别和关联结果均不创建分部或改变已有分部种类；无法关联不妨碍合法文件登记和使用。

## 特殊内容标记与完整内容名称

内置识别在已识别的内容标记位置使用以下映射。作品标题、发布组名称或技术字段中偶然出现同样文字，不触发内容分类。英文标记不区分大小写，形成名称条件时仍保留原文字母、数字、内部空白和标点。

| 内容标记或明确结构                            | 分部匹配条件                                                    |
| --------------------------------------------- | --------------------------------------------------------------- |
| `Special Episode <编号>`、`特别篇 第<编号>话` | Episode，episodeType 为 special，采用其中的编号                 |
| OP、NCOP、Creditless OP                       | Extra，extraType 为 opening，使用完整内容名称                   |
| ED、NCED、Creditless ED                       | Extra，extraType 为 ending，使用完整内容名称                    |
| PV、CM、Trailer、Teaser、预告                 | Extra，extraType 为 promotion，使用完整内容名称                 |
| Interview、访谈、インタビュー                 | Extra，extraType 为 interview，使用完整内容名称                 |
| Making of、制作花絮、メイキング               | Extra，extraType 为 other，使用完整内容名称                     |
| 仅有 SP、S00、特典、Bonus 等宽泛线索          | 不足以确定分部种类，保留问题，不生成普通正片或 other 的默认目标 |

明确的特别分集结构也可以使用既定编号范围与清单表达，每个目标均采用 special 条件。宽泛说明不能覆盖更具体且兼容的内容标记；两个具体标记给出互不兼容的目标种类或类型时，报告解释冲突，不能按出现顺序取首项。

完整内容名称指分部的内容名称，不包含已识别的作品标题、发布组、来源、技术附注和发布修订。内容标记自身、名称内的序号和后续标题均保留。只能按已识别的命名结构分离这些部分，不能删除所有括号块，也不能丢弃无法解释的文字来凑出已有名称。

| 文件名中的内容部分           | 目标及说明                                           |
| ---------------------------- | ---------------------------------------------------- |
| `特别篇 第01话 [1080p]`      | 特别篇分集，编号 01                                  |
| `NCOP01 [BD 1080p]`          | Extra，名称 NCOP01，类型 opening                     |
| `NCOP01v2 [BD 2160p]`        | Extra，名称仍为 NCOP01；v2 是已识别的发布修订        |
| `NCOP02 [BD 1080p]`          | Extra，名称 NCOP02，不能因同属 opening 而匹配 NCOP01 |
| `NCOP01 - 歌曲名 [1080p]`    | Extra，完整名称为 NCOP01 - 歌曲名，类型 opening      |
| `Interview - 声优名 [1080p]` | Extra，完整名称为 Interview - 声优名，类型 interview |

发布修订不改变内容名称；原版和修订版可以作为独立文件关联同一分部，各自保存位置。只有结构明确将 v2 等片段识别为发布修订时，才从内容名称中排除；不从任意名称中删除类似文字。NCOP01 中的 01 仍属于名称，不生成 Extra 编号，也不应用编号偏移。

名称继续只修整首尾空白后精确比较。NCOP01 与 NCOP 1、NCOP1 不自动等价，OP、NCOP 和 Creditless OP 的类型映射相同也不使名称等价。没有完整名称对应时保持未关联，不能只凭同一类别或当前仅有一个候选完成匹配。

## 漫画与小说的内置匹配

漫画与小说共同使用阅读格式能力，卷、话含义来自明确命名结构。CBZ、PDF、EPUB、TXT 等格式本身不决定分部种类；没有分部对应的合法文件仍可阅读。内置解析先区分作品标题、内容标记、来源和发布附注，再形成以下条件，不查询哪个编号能命中来反推含义。

| 媒介与明确内容结构                                                             | 匹配条件                                                              |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| 漫画 `Vol.03`、`Volume 03`、`v03`、`第3卷`、`第3巻`                            | ComicVolume，卷号 03 或 3                                             |
| 漫画 `Ch.012`、`Chapter 012`、`c012`、`第12话`、`第12話`、`第12章`，没有卷范围 | ComicChapter，作品话号 012 或 12                                      |
| 漫画 `Vol.02 Ch.01`、`Vol.02/Ch.01.cbz`、`第02卷/第01话`                       | 唯一的第 2 卷中，卷内话号为 01 的 ComicChapter                        |
| 漫画明确采用 `c012 (v02)` 的来源卷命名规范                                     | ComicChapter，作品话号 012；v02 只作来源说明                          |
| 小说 `Vol.03`、`Volume 03`、`v03`、`第3卷`、`第3巻`、`第3册`                   | NovelVolume，卷号 03 或 3                                             |
| 漫画或小说 `上卷`、`中卷`、`下卷`、`上册`、`下册`                              | 对应媒介的卷，使用文字编号上、中或下                                  |
| 只有 `03.cbz`、`03.epub`、`2/1.cbz` 等裸编号                                   | 不确定卷或话粒度，不形成内置目标                                      |
| 小说 `第3章`、文件内部目录章节或 EPUB 分组序位                                 | 文件内章节或分组信息，超出 NovelVolume 的识别范围；小说模型仅有卷分部 |

英文内容标记不区分大小写，但捕获到的编号仍保留原文。上述标记须在内容位置成立，标题、发布组或已确定的修订位置中的相同文字不能触发分类。普通卷标记与话标记共同明确表达层次时，默认使用卷内话号；括号来源卷采用所识别命名规范的来源含义，不能仅因出现卷数字就套入卷范围。

按卷内话号查找须先唯一确定真实卷，再使用该卷已有收录关系的 number_label。卷内 1 可以对应作品话号 13 的同一话。卷缺失、卷不唯一或没有相应卷内编号时保持未关联，不能改查作品话号、采用卷中第一行，或复制作品编号来填空。卷范围不是文件卷目标，不顺带建立文件卷关联。

明确命名同时声明彼此不兼容的卷范围、话号依据或内容单位时报告解释冲突。没有卷话层次依据的相邻数字不构成层次，即使本地恰好有唯一卷或话，也不能补齐缺失语义。单纯作品标题文件不生成“正文卷”或完整作品覆盖声明。

明确卷号或话号可使用非负整数范围及编号清单，沿用[完整关联](#recognition-ranges)；卷内话范围限定在同一个唯一卷内。`第1–3卷` 对应编号 1、2、3，`Ch.01+03` 对应话 1、3，不表示当前列表的前几项。点号、字母和文字编号保持完整文本；`153b` 不换算成 `153.5`，`013x1` 不截成 13，上中下不换算为 1、2、3。文字或点号范围不按算术展开，须使用明确的离散编号目标。

电子书内部目录只属于实际文档的阅读导航。系列名称、series_index 或 EPUB group-position 也不能普遍证明本作卷身份；已经取得的规范分部身份仍走正式身份校验。命名解释不因缺少卷资料而请求 provider 或创建分部。

<a id="number-label-matching"></a>

## 文件识别中的编号与名称比较

编号比较先修整首尾空白。两边都是完全由 ASCII 数字组成的非空整数文本时，只消除前导零，全部为零时得到 0；其他编号按修整后的文本精确比较，保留点号、字母、中文、大小写与内部空白。不进行浮点转换、Unicode 兼容折叠或中文数字换算，也不回写正式 number_label。

| 两个编号  | 比较结果 |
| --------- | -------- |
| 03、3     | 相同     |
| 000、0    | 相同     |
| 1.10、1.1 | 不同     |
| 1.0、1    | 不同     |
| SP01、SP1 | 不同     |
| 上、上    | 相同     |

名称只修整首尾空白后精确比较，不进行相似度猜测或其他文字改写。所有匹配仍须唯一：同一范围内若分别存在编号为 03 和 3 的两条记录，比较等价只会产生歧义，不优先采用原文恰好相同的一项，也不合并记录。

漫画按卷内话号识别时，先唯一确定卷，再使用 comic_volume_chapters.number_label 查找该卷收录的话，不能使用作品话号代替。例如，自定义规则明确将路径 2/1.cbz 解释为第 2 卷中的第 1 话时，可以对应作品编号为 13 的同一 ComicChapter；裸路径本身不提供这种含义。该卷只限定查找范围，不顺带创建文件与卷的直接关联。

<a id="recognition-offset"></a>

## 编号输出的偏移

编号偏移属于识别规则中的具体编号输出，随方案保存。作品与目录不保存另一份偏移或覆盖值。同一规则同时提取卷号与话号时，两者分别决定是否调整；不同规则之间也不传递偏移。Extra 没有编号输出，不把名称中的数字当作结构化编号调整。

偏移是有正负号的安全整数，默认 0。0 表示不调整，模板展开得到的文本保持原值，之后使用普通编号比较。非零偏移在模板展开并修整首尾空白后执行，只接受 ASCII 数字组成的非负整数，或整数后跟一个点号与至少一位数字的形式。

换算只处理整数部分：匹配编号的整数部分 = 提取编号的整数部分 − 偏移。计算使用精确整数运算，新整数部分采用不含前导零的十进制文本；原有点号及其后的数字逐字保留，不通过浮点运算删除尾零或改变含义。换算只生成用于查找的编号，不修改文件名、正式 number_label 或其他资料。

| 提取结果   | 偏移 | 用于匹配的结果 |
| ---------- | ---- | -------------- |
| 13         | 12   | 1              |
| 13.5       | 12   | 1.5            |
| 13.10      | 12   | 1.10           |
| 12         | 12   | 0              |
| 1          | -12  | 13             |
| 013.10     | 0    | 013.10         |
| 范围 13–15 | 12   | 范围 1–3       |

整数部分变为负数，或非零偏移遇到 SP13、上、多个点号等不支持的编号形式时，报告该文件的换算问题，不忽略偏移或另换规则。结果为 0 时正常查找已存在的零号分部，不能仅因是零号就丢弃。点号编号在换算后仍按文本精确比较，1.10 不等于 1.1。

范围的起止编号采用同一个偏移，换算后继续满足非负整数闭区间和完整关联要求。只有本次匹配规则的明确编号输出参与换算；未命中的规则、其他输出以及内置识别的结果都不隐含采用这个偏移。

同一方案供多个目录引用时，偏移与其他规则值一起共享。不同目录需要不同偏移时，复制方案、修改相应编号输出，再明确选用副本。规则编辑器在编号输出旁编辑偏移，预览分别展示提取值、换算值和实际匹配结果，沿用普通表单的保存流程。

## 范围与完整关联

数值范围只表示明确的非负整数闭区间，端点使用前述纯整数文本并要求起点不大于终点。1–3 表示编号 1、2、3，不表示当前列表前三项，也不自动包含 2.5 等其他编号。小数或文字编号的组合通过明确列举目标表达，不按数值大小或人工排列推导区间。

范围求值先以准确整数运算计算所需成员数，再与当前作品及明确范围内的实际候选核对。明显缺项直接报告；成员枚举和问题明细均限制在可处理范围内。计算须避免浮点截断或溢出，合法编号的值域仍遵守字段合同。

一份文件的本次自动匹配结果须整体成立。范围内每个编号或清单中每个目标都必须存在、唯一且满足已提供约束，之后才一次提交完整关联。目标缺失、歧义或约束冲突时保持未关联，并报告原因；不只关联已经找到的部分。关联按真实分部身份去重，不制造重复关系。

例如，第 1–3 卷合订文件暂时缺少第 2 卷资料时，不能先关联第 1、3 卷。关联方式为 automatic 的文件保留空关联，补齐资料后仍可按当前规则匹配；用户采用 manual 后则保留自己的完整选择，包括空集合。多分部关联不生成文件内时间或页面边界，也不拆分位置、活动或完成记录。

## 文件识别方案预设

文件识别方案提供由 holdings 管理的原生预设目录，沿用[共同预设界面](../ui/components.md#presets)和[配置副本规则](metadata-presets.md#ownership)。本领域的预设内容包括适用媒介、固定命名规则，以及正例、反例和歧义边界；名称、说明、目录身份和选择方式遵循共同约定。命名解释与已有分部对应使用同一套正式能力，不为预设增加特殊识别分支。

新建保存后得到用户自己的方案 ID，目录再引用该方案。载入已有方案时，本领域声明的替换范围只有规则定义草稿，保留身份、名称、说明和排列。保存后按方案的共享引用规则生效，预设本身不与目录建立引用关系。

未选择方案时使用内置识别规则，不在新库或首次打开目录时自动创建预设副本。预设不会仅凭文件扩展名决定卷、话或分集，也不会因为匹配命名就创建分部。每项预设须说明它要求用户确认的命名约定，并在预览中区分未命中、无法唯一对应与成功关联。

原生目录固定提供[十项文件识别预设](file-recognition-presets.md)，覆盖四项动画格式、两项漫画与小说共用的卷号格式，以及四项漫画话号格式。该文档给出完整初值与正反例。共用预设复用初始化内容，保存时创建当前媒介的独立方案；目录直接引用该媒介的方案，采用过程使用完整定义。

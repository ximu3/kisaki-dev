# 扩展运行与实例生命周期

extension-host 负责执行扩展代码，主进程中的原生模块负责应用业务和正式数据。extension-api 定义扩展可以使用的能力，extension-sdk 则把调用、登记、取消和资源管理接入真实的扩展实例及视图。本篇说明这些边界，以及扩展从激活到结束的完整过程。

<a id="boundary"></a>

## 运行边界与职责

| 所属部分                 | 职责                                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| main/features/extensions | 管理安装包、仓库、兼容性、启停和宿主进程代际；接入贡献，核对资源与窗口归属，并将公开 API 适配到本体能力。 |
| extension-host           | 加载启用的扩展，创建扩展上下文，调用扩展导出函数，收集登记与清理操作，并传输扩展请求。                    |
| extension-api            | 定义宿主与扩展之间的能力接口、贡献类型、输入输出和回调合同。                                              |
| extension-sdk            | 实现扩展声明、上下文、登记与调用桥接、取消传递和 Webview 通信。                                           |

desktop-contracts 描述本体的完整能力。extension-api 从中明确选择公开范围，并定义扩展如何接入；SDK 负责实现接入所需的共同机制。新增原生模块或方法不会自动成为扩展 API，公开接口也不照搬数据库表或源码目录。适配层只解析调用来源与上下文，并转换值和错误，业务实现仍由本体拥有。

扩展可以提供资料来源、识别器、主题、译本、菜单、页面，以及已定义的资料操作。扩展不能增加新的根类型、任意字段或未知关系。即使扩展停用或卸载，它已写入的核心资料仍须能由本体理解和管理。扩展私有数据也不能获得本体未定义的筛选、统计或合并含义。

可信的 Node 扩展可以执行 Node 代码。独立进程提供故障边界，不构成操作系统沙箱；宿主的归属校验用于保证产品调用正确，不能据此宣称已限制扩展任意访问文件或网络。

SDK 的公开内容直接服务扩展合同，并明确状态与资源的拥有者。SDK 负责回调桥接、实例订阅和取消传递；来源刷新、重试、账号、OAuth、PKCE 与限流由扩展或普通依赖实现。共用实现按稳定用途与实际消费者划分为模块或独立库，保持与应用私有源码的边界。

扩展的参与范围由[公开能力目录](#public-api)和[领域参与接口](providers.md#participation)共同定义。其他协作使用本体的完整操作和事实事件。游戏启动准备、文件与既有 Part 的匹配都由本体负责。SDK 的运行入口与 CLI、UI、视觉及分发工具包分别交付。

<a id="author-model"></a>

## 扩展上下文与能力选用

作者通过本次激活得到的 ExtensionContext 调用能力。同一领域的登记、目录和调用放在同一命名空间中，不另设并行的 capabilities 或 contributions 总树。register 只发布一种可供选择的实现；业务配置或本次操作负责选择具体实现及执行顺序。安装、启用和新增登记不会修改已有 Profile 或 ScanConfig，也不会使配置自动选中所有能力。

能力登记、单次回调、事实订阅和 UI 贡献分别表达。原生与扩展事实统一通过 [events.on](../communication.md#events)观察；通知描述已经发生的事实，运行观察和读取失效使用各自合同。

菜单通过 ui.menus.add 在指定上下文提供项目，回调随该次菜单或操作持有。需要选用的实现先登记，再由用户或业务配置选择，不能借回调登记自动介入全局流程。API 保持这些具体入口，不另设 hooks 或 callbacks 总树。

每项策略只有一个拥有者。资料方案、扫描配置和启动参数由本体业务保存；账号连接和扩展独立功能的状态由扩展私有设置保存。编辑界面来自本体还是扩展，不改变数据归属。已选能力不可用或缺少配置时，系统保留原引用并明确报告问题，不能静默跳过后报告成功。

library 通过所属命名空间提供 holdings 与各类记录能力。metadata 负责候选资料，ingest 负责本地对应和采用；已确定的 patch 或资料图可以直接交给 library。更新操作返回完整执行结果。扩展可显式组合 metadata、自身整理和 ingest，各步骤沿用正式语义。

ui、appearance 和 i18n 的贡献目录分别由对应原生模块拥有，extensions 只负责真实实例的接入。storage.values、storage.secrets 和 storage.commit 提供私有数据边界。网络偏好由 preferences 保存，扩展不能另存一份并行的应用网络设置。

<a id="public-api"></a>

## Node 公开能力与原生管理

| 能力              | 扩展 Node 可以使用的范围                                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| library           | 查询和完整修改条目、分部、四类关系、合集、标签、笔记、标注、记录及持有内容；合并、删除和备份遵循同一原生业务合同。                               |
| metadata、ingest  | 登记和使用提供者、字段处理器与资料方案，执行搜索、获取、完整新增、更新、批量处理和候选采用。                                                     |
| scanner           | 管理配置，预览规则，执行和观察扫描，读取报告，并管理配置内排除。                                                                                 |
| sessions、tasks   | 执行使用操作、定位、控制和观察会话，以及执行任务、取得结果、取消和管理历史；退出专用 game.detach 及原生 recordings 重试／放弃管理不向 SDK 开放。 |
| appearance、fonts | 贡献主题，按标准操作管理和读取用户主题及字体；主题可以 Clone，字体没有复制操作。                                                                 |
| preferences       | 类型化读取普通偏好、取得默认值并修改选项，包括主题选择、明暗和缩放；凭据与运行生效仍遵守各自边界。                                               |
| search            | 使用已定义的应用搜索和类型化结果；打开结果时复用原生导航。                                                                                       |
| ui、i18n、events  | 贡献菜单、页面、对话框和译本，使用明确的导航，接入有效语言与外观，并订阅已定义的事实事件。                                                       |
| 宿主设施          | 使用应用网络策略下的 HTTP、图片处理、附件与临时资源、外部地址打开、通知，以及本扩展的私有值和凭据。                                              |

这些能力复用本体的输入、结果、校验、并发和失败合同。作品完成历史使用 library.completions，当前状态、分部标记、活动和文件位置使用各自原生操作。合并按明确保留目标及固定规则核对引用与占用，不要求预览或差异编辑；恢复存档仍须完成其原生确认。后台场景无法取得必要输入或交互时返回明确问题，不能绕过业务规则。资源通过正式接口受控读取和释放，临时地址不写入持久数据。资料查询使用快照与失效通知，运行状态使用 observe；完整操作直接返回业务结果。

原生管理入口负责安装卸载、仓库信任、应用或扩展更新采用、共享宿主控制、系统集成及引导进度修改。扩展可以打开对应界面，并通过普通偏好合同修改适用设置。内部 helper、数据库、窗口与引擎实例由本体持有，扩展通过明确列出的业务 API 使用能力。

## Node 与 Webview 的分工

| 能力                                                    | 扩展 Node                                                                                | Webview                                                                  |
| ------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| library、metadata、ingest、scanner、sessions 等领域操作 | 直接调用本体完整操作。                                                                   | 调用扩展显式暴露的私有业务接口。                                         |
| tasks 与全局 events                                     | 按各模块合同查询、控制、执行和订阅。                                                     | 经扩展私有接口取得所需操作与状态。                                       |
| 提供者、处理器、识别器、事件、页面、菜单、主题和译本    | 负责定义、登记和管理。                                                                   | 不直接登记贡献。                                                         |
| 私有设置、账号及 storage                                | 负责业务校验和持久化。                                                                   | 经扩展业务接口取得可展示数据或提交操作，不直接访问原始存储与凭据。       |
| 当前视图与宿主环境                                      | 创建视图并管理其后端。                                                                   | 接收有效外观、语言和授权资源，处理当前视图的关闭、关闭确认及界面交互。   |
| 反馈                                                    | 使用 notifications 发送桌面通知。                                                        | 使用所属界面的 ui.toast。                                                |
| 页面通信                                                | 明确声明页面可调用的方法，并提供必要通知。                                               | 调用当前页面的私有方法，订阅私有通知。                                   |
| 浏览器数据联网与外链                                    | 官方业务通过 context.network.fetch；使用 context.ui.openExternal 打开明确 HTTP(S) 链接。 | 按页面 CSP 直接请求 HTTPS／WSS 数据；使用 ui.openExternal 打开明确链接。 |

Node 为页面提供明确的数据范围、操作目标和组合操作，本体继续负责模型规则与事务。简单方法可以直接绑定或一行转发，并复用已有合同，无须复制校验。私有业务函数可以同时供页面、菜单和后台使用，不必登记为全局稳定能力。请求关联与取消由 SDK 处理，作者无须自建消息框架。

Webview 通过明确开放的 SDK 能力调用宿主，事实订阅只交付事件；宿主自己的 UI 直接使用本体客户端。需要跨事实原子修改时，调用完整业务操作，不能传入 SQL 回调。页面关闭会清理其资源和观察；已经独立接纳的后台工作或授权操作按自身生命周期继续。扩展实例失效则按实例结束规则处理。

页面脚本、Worker、来源隔离、导航与浏览器权限遵守[Webview 容器规则](webview.md#isolation)。允许浏览器数据请求不会把官方扩展的账号、凭据或业务职责移入页面；浏览器 Session 与宿主 HTTP 的 Cookie 语义分别定义。

<a id="identity"></a>

## 稳定引用与运行身份

需要持久选择或订阅的 provider、processor、recognizer 和扩展事件等，使用 extensionId:localId。两部分均不能包含冒号。作者只提供局部 ID，宿主绑定真实扩展身份；官方扩展遵守同一规则。app.ready、sessions.game.sessionEnded 等原生事件不包含冒号，扩展不能取得原生身份。

登记句柄提供宿主绑定的只读 ref 和释放操作。事件 publisher 代表当前实例发布自有事件。ID 在各注册域内唯一，重复登记被拒绝；不同注册域分别管理命名。page、UiTranslationRef 等结构化引用保留其归属字段，由对应能力解释。

稳定身份由正式引用确定，名称、语言、版本和加载顺序作为各自属性处理。实现不可用时保留原引用，待该引用恢复后继续使用。Entry、TaskRun、locale、message key 与 ExternalIdentity 分别沿自身合同编码，运行实例由本次绑定标识。TaskRun.type 只用于结果分类。

<a id="calls"></a>

## 调用、登记与读取会话

作者使用普通异步方法、回调和读取会话。openSession 交付固定的 relationScopes 值与 read／close 能力，SDK 分别传输值快照和会话关联，实际函数与资源留在所属进程。方案保存稳定提供者引用，运行关联由 SDK 按实例寿命管理。

一次 metadata 执行开始时，会绑定所选的具体实现。后续定位和读取继续使用该绑定，不能每一步都按稳定 ID 改用后来登记的实现。新操作使用当前登记，旧实例失效后也不会因相同 ID 再次出现而恢复。

| 动作                   | 完成条件与影响                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| registration.dispose() | 完成撤销后返回，后续发现和选用不再包含该登记。已经开始并绑定实现的操作及会话仍可按原合同完成。                   |
| session.close()        | 使本次会话进入关闭状态，拒绝新的 read；等待已接纳的读取结束并释放资源。重复关闭复用同一次关闭结果。              |
| 取消调用 signal        | 向本次调用及其子调用传递停止请求，并按共同合同等待必要收尾。取消一次调用不会撤销整个 provider。                  |
| 扩展实例结束或失效     | 撤销实例贡献，结束依赖该实例的调用与会话。正常停用会请求取消和清理；异常断开只保证宿主释放自己的句柄并报告中断。 |

metadata 操作负责关闭它取得的会话。close 不会把已经读取的结果改为用户取消；需要停止时，应先取消对应 signal。单个登记的 dispose 不保证既有业务结束，实例终止也不能等同于撤销登记。系统不对所有 provider 统一设置一个短超时。

多个独立操作可以使用同一个 provider，同一个会话也可以并发 read。每次调用都有独立的输入、signal 和结果，不使用全局“当前输入”。provider 根据来源政策安排缓存和并发。close 开始后拒绝新读取，但已接纳的读取仍须完成收尾。

接收进程为每次调用创建本地取消控制器，SDK 通过消息桥接 signal，不把它当作 JSON 传输。调用预先取消时不再分发，调用结束后移除监听。context 只显式传递必要值。allowInteraction 只适用于完整操作合同规定的条件，不赋予 provider、processor 或 recognizer 临时要求人工补救的权限。

通信或实例中断时，系统依据已知事实结束调用，不自动重放。ExecutionFailure 及合法的 partialResult 保持原有语义，由业务决定能否安全重试。失去连接并不能证明本体已接管的工作被取消，也不能证明提交已回滚。

<a id="activation"></a>

## 激活与贡献发布

| 对象             | 表达的事实                     | 生命周期                       |
| ---------------- | ------------------------------ | ------------------------------ |
| 扩展身份与安装包 | 安装了哪个扩展和版本。         | 安装、更新、卸载。             |
| enabled          | 用户是否希望启用扩展。         | 由用户设置，故障不会自动改写。 |
| 运行实例         | 本次激活的上下文、贡献和资源。 | 激活、停用、宿主退出。         |
| 业务执行         | 导入、扫描、备份等实际工作。   | 由真正拥有操作的模块管理。     |

enabled 表达用户意愿，启动失败时仍保留该选择，界面显示“已启用但启动失败”。实例、调用和登记属于运行状态。manifest 描述包身份、展示、兼容与加载事实；provider、语言和页面贡献由激活后的登记建立。

activate(context) 及其静态依赖保持轻量，激活时可以读取配置并建立轻量资源；网络访问、大索引、重型客户端和 UI 按需加载。离线或缺少凭据时照常提供登录与设置入口。本次贡献先暂存，激活成功后统一发布；失败时撤销本次登记，应用继续基础浏览。贡献撤销处理登记状态，外部副作用按实际业务结果另行报告。

真实通信绑定 ExtensionContext，调用者不能通过传入扩展 ID 冒充其他实例。登记自动归属于上下文，也可以提前 dispose。额外资源通过可异步执行的 context.onDispose 清理，等待遵守下述生命周期预算。可变状态属于本次实例；旧 context 失效后不会重新生效，再次启用必须创建新上下文。进程级“当前扩展”变量不能使旧回调获得新实例权限，回复也必须同时核对进程代际和实例。

<a id="lifecycle-waits"></a>

## 生命周期等待

| 阶段             | 预算与范围                                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| 单个扩展激活     | 从开始加载入口模块到完成本次激活，共用最多 15 秒，包含模块依赖加载、activate 和本次贡献发布。                    |
| 单个扩展停用清理 | 从进入实际清理开始，本次全部清理回调共用最多 15 秒，不按回调数量累加。此前处理未保存编辑及关闭确认的时间不计入。 |

阶段提前完成便继续，不固定等待到期。激活超时表示本次激活失败，撤销本次贡献并使上下文失效，enabled 仍保留用户意愿。清理超时如实报告未完成，不能将停止等待当作扩展代码已结束或所有资源已释放；宿主管理的资源仍由各自拥有者收尾。失效实例的迟到回调不能重新发布贡献或取得新实例权限。

上述时限与[首屏准备的 5 秒预算](../architecture.md#startup-readiness)分别计算。首屏停止等待不终止仍在自身预算内的激活；资源后来就绪时，由 i18n、appearance 和文档外观接入按正常资源采用流程更新。资料获取、导入、同步等业务调用仍遵守自身的执行与取消合同，不统一套用生命周期时限。

<a id="disable"></a>

## 停用与共享宿主恢复

用户主动停用、卸载、采用更新或重启共享宿主前，先按[关闭确认规则](webview.md#closing)处理受影响视图的未保存内容。需要保存时，先等保存真正完成；用户取消则保留当前实例与待采用更新，不能先撤销调用能力再让页面保存。开发热重载和异常实例失效分别遵守自己的合同。

确认进入停用后，拒绝新调用并撤销贡献与订阅，再取消依赖该实例的工作，最后进行有界清理。工作如何结束取决于其实际依赖，不能只按发起者取消全部操作。

| 正在进行的工作                     | 停用后的处理                                                    |
| ---------------------------------- | --------------------------------------------------------------- |
| 扩展自身代码执行的任务             | 请求取消；无法正常收尾时记录中断。                              |
| 原生备份模块已独立接管的任务       | 按备份任务自己的规则继续。                                      |
| metadata 正在调用该扩展的 provider | 该来源调用失效。metadata 保留实际失败范围，由调用方按合同处理。 |
| 原生流程已经持有的有效资料         | 继续有效，不因扩展停用而自动作废。                              |
| 依赖该实例的页面与授权会话         | 撤销调用能力，按各自关闭或失效规则处理。                        |
| 已提交的条目、关系与个人记录       | 继续由本体管理。                                                |

页面草稿遵守宿主关闭规则。异常发生后应明确显示不可用，旧页面不能悄悄绑定新实例。异常断开只保证宿主释放自己的句柄并报告中断，不能声称扩展代码完成了清理。

普通启停可以在进程中保留同版本代码，但每次都必须创建新上下文。替换已经加载的代码时，需要重启共享 extension-host。删除 require.cache 或给模块 URL 添加随机值都不能实现完整的 ESM 卸载，参见 [Node ESM](https://nodejs.org/api/esm.html#no-requirecache)。

更新先准备新包并保留现用版本，界面明确显示待生效。采用更新时，系统切换版本、重建共享运行环境，并重新创建所有应启用的实例，同时说明其他受影响的调用和页面。原生模块已独立接管的工作继续运行。恢复过程只恢复登记，不重放导入、写入或请求，也不重发 app.ready。安装包与私有数据的处理结果分别报告，不能宣称私有数据一并回滚。

每次应用运行最多自动重建一次异常宿主；再次崩溃后停止自动恢复，保留手动重启。共享宿主故障按实际影响范围处理，不能凭最后一次调用就判定某个扩展有错并将其禁用。enabled 保留用户选择，界面也不能宣称每个扩展都有独立的进程崩溃或重载隔离。

## 主进程扩展模块的内部组织

main/features/extensions 拥有完整扩展管理，内部按管理操作、仓库、包处理、更新准备、运行环境和接入分别组织。目录表达实现职责，公开能力由既定扩展管理合同定义。

| 内部位置     | 负责内容                                                             |
| ------------ | -------------------------------------------------------------------- |
| manager.ts   | 完整安装、启停、卸载、更新采用及共享环境重启的管理编排与结果         |
| repositories | 仓库配置、信任、索引及相应绑定维护                                   |
| packages     | 明确制品的下载、校验、解包、受控使用和安全清理                       |
| updates      | 扩展更新候选检查与明确版本准备，不采用版本或激活实例                 |
| runtime      | 实际宿主进程、代际、实例、调用与资源寿命，以及共享宿主的重建互斥边界 |
| gateway      | 将真实实例身份、上下文、调用及登记适配到明确开放的原生能力           |

manager 对跨安装事实与运行环境的完整操作负责，具体包处理和运行资源由相应模块完成。当前版本、启用意愿和待采用内容以正式安装记录为准，运行状态以 runtime 的实际实例为准，不另存一份可以独立变化的扩展总状态。包准备成功、版本采用和激活成功分别形成结果。

完整的 extensions.runtime.restart 与更新采用均由管理入口组织，runtime.getState 和 observe 读取实际运行环境。装配按公开合同连接相应操作；manager 决定管理流程并调用 runtime 的内部生命周期能力，runtime 执行该决定。

同一扩展的安装、替换和卸载按管理操作互斥；涉及共享宿主的变化同时经过 runtime 拥有的同一个重建边界。管理入口不能自行复制宿主重建状态或绕过这项约束。用户确认、版本采用、激活报告和取消由本次完整操作组织，实际进程与实例的建立、失效和释放由 runtime 完成。内部生命周期步骤不进入公开 API。

采用更新前，先让受影响视图在仍可使用原实例的情况下完成未保存处理；用户取消时保留原安装和实例。确认后，在同一次受控重建中结束旧实例与宿主、采用明确准备结果，并建立新的实际运行环境。manager 汇总真实 adopted 与 activations，已采用但激活失败不被描述为回滚。普通重启与异常恢复只使用当前已提交版本，不顺便采用更新或重放业务。取消与失败保留已经发生的事实，字节只有在全部实际占用释放后才清理。

gateway 只承担接入与必要适配，不接管资料读取、库写入或其他领域规则。提供者、处理器、识别器及 UI 贡献的实际目录仍归各原生模块；runtime 管理实例与相应句柄的寿命，不复制一份总贡献目录。共享 RPC 内核与扩展宿主程序仍按各自边界使用，不在这里重建消息框架或执行扩展代码。

# 展示柜与查询区块

library.showcase 保存具名区块的查询、显示配置和排列。区块内容通过 entries、collections 或 tags 的正常查询取得。区块属于用户配置，不保存成员快照，也不承担真实归组。

<a id="model"></a>

## 区块范围与共同查询

query.kind 为 entry、collection 或 tag，直接组合对应对象的查询合同，不另存 entity_type、顶层 types 或平行条件。Entry 使用 scope、search、规则组和整体 sort；query 的 Entry 分支另带[referenceLabels](../domains/library-query-contracts.md#saved-references) 名称快照。执行时提取纯 EntryQuery，kind 与名称快照不传给列表方法。Collection 与 Tag 不进入 EntryType，也不增加 listSectionItems 转发或 Showcase 查询引擎。

每个组可以选择多个类型，并使用 all 或 any 条件。组间取并集并去重，再与固定范围和可见范围相交。组内字段必须对所有类型具有相同含义，整体字段排序必须适用于全部启用类型。一个 Section 只有一份 sort、一种布局和一个总上限，不给每组增加独立 sort、前 N 项、配额或模板，也不支持任意嵌套。默认使用一组，自定义可以多组，原生界面提供完整编辑，不设置隐藏的简单或高级模式。

“高分游戏或进行中动画”可表达为两组，再合并结果统一排序。需要各自标题、排序或数量时，建立多个区块。同一种类型占据前十二项是正常查询结果。动态合集表达组织归属并参与未分类计算，Section 负责展示；它可以引用真实动态合集作为 scope，并沿用既定递归限制。

手动新建时，标题为空并等待填写，query.kind 为 entry，选择四种 Work、全库范围、空 search 和一组空条件，使用 scope 顺序。显示初值为 horizontal、md、12、page，区块可见并追加到末尾。预设各自提供完整初值，不自动创建全部十项。首次引导从同一目录选择三项，见[引导](../domains/onboarding.md)。

## 十项固定用途预设

所有预设使用 md 卡片和 page 打开方式，创建时可见并追加到末尾。表中的“作品”包含 game、anime、comic 和 novel，数量限定区块的展示上限；实际读取区间按列表规则安排。

| 稳定目录键              | 名称     | 对象范围     | 筛选                 | 排序                       | 布局       | 数量         |
| ----------------------- | -------- | ------------ | -------------------- | -------------------------- | ---------- | ------------ |
| recently-used-works     | 最近体验 | 四类作品     | 存在最近实际使用记录 | 最近使用降序               | horizontal | 12           |
| active-works            | 进行中   | 四类作品     | 个人状态为 active    | 最近使用降序，未使用者在后 | horizontal | 12           |
| planned-works           | 计划中   | 四类作品     | 个人状态为 planned   | 加入日期降序               | horizontal | 12           |
| recently-added-works    | 最近加入 | 四类作品     | 不增加额外条件       | 加入日期降序               | grid       | null（不限） |
| favorite-works          | 作品收藏 | 四类作品     | favorite 为 true     | 沿用范围顺序               | grid       | 24           |
| personal-rating-ranking | 评分排行 | 四类作品     | 个人评分已设置       | 个人评分降序               | horizontal | 12           |
| favorite-characters     | 角色收藏 | character    | favorite 为 true     | 沿用范围顺序               | grid       | 24           |
| favorite-persons        | 人物收藏 | person       | favorite 为 true     | 沿用范围顺序               | grid       | 24           |
| favorite-organizations  | 组织收藏 | organization | favorite 为 true     | 沿用范围顺序               | grid       | 24           |
| collections             | 合集     | Collection   | 不增加额外条件       | 沿用范围顺序               | horizontal | 12           |

最近体验按真实使用记录选择作品。资料更新、配置修改与补录完成记录均不改变最近使用。最近加入按[有效加入日期](../domains/library-queries.md#fields)排序：优先采用 added_date，整个字段为空时才回退到创建日期，范围不限最近天数。

active 和 planned 对应当前状态，与是否持有文件、过去是否完成分别判断；打开内容不会自动设置 active。完成历史使用[完成记录查询](../domains/library-queries.md#completion-records)。评分排行排除未评分，保留 0 分，使用本地评分且不设置额外门槛。

收藏只判断 favorite。角色、人物和组织即使没有关联作品，也可以进入收藏区块。

四个收藏预设的 scope 顺序使用有效排序名或 name，并以 ID 稳定排序；合集使用自身排列和 ID，不附加无效的升降方向。六个作品用途预设都面向四种作品。需要单类时，先载入普通草稿，再明确修改类型，目录筛选不会动态生成参数化预设。目录不提供默认的四种“全部作品”或“全部标签”，用户仍可手动创建。Tag 没有图片，不能用成员封面冒充标签图。

目录名称、说明和初始标题可以翻译，业务配置只有一份。载入草稿时将初始标题解析为普通文本，保存后独立存在，查询或 UI 语言变化不会自动改名。有限区块的“查看全部”沿同一查询与排序去掉上限；标题不能宣称展示全部，实际却限制数量。

<a id="storage"></a>

## 十一列存储合同

showcase_sections 通过以下十一列保存区块查询、显示和排列。

| 字段       | 含义                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| id         | 稳定区块身份，主键                                                     |
| name       | 用户区块标题，去除首尾空白后非空，允许重名                             |
| query      | 非空 JSON 查询配置；Entry 分支采用共同规则查询，另有合集、标签查询分支 |
| layout     | horizontal 或 grid                                                     |
| item_size  | 既有 xs、sm、md、lg、xl 卡片尺寸之一                                   |
| open_mode  | page 或 dialog                                                         |
| limit      | 正整数或 null；null 表示不限制逻辑匹配数量                             |
| is_visible | 明确布尔值，新建默认 true                                              |
| sort_order | 区块在展示柜中的排列，非负整数                                         |
| created_at | 首次实际保存的 UTC 毫秒时间                                            |
| updated_at | 标题、查询、显示配置或可见性实际改变的时间；纯列表重排不刷新           |

索引使用 sort_order 和 id。排序值非负，limit 为正整数或 NULL，layout、item_size 和 open_mode 只接受各自封闭合法值。name 去除首尾空白后必须非空，允许重名。query 必须是合法的类型化 JSON，缺失时不能隐含采用无条件查询。区块 limit 只属于显示配置，实际读取另外使用 offset 和 limit。

系统不保存成员镜像、查询 token、预设绑定、类型标识开关或区块子项表。纯列表重排不更新 updated_at，内容资料变化也不改写区块配置。

## 配置操作与原子提交

| 方法                                 | 输入与返回                                                                                               | 完成含义                                                                                                             |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| library.showcase.list()              | 返回按正式顺序排列的全部区块配置，包括隐藏项；不携带区块内容结果                                         | 取得本次配置快照。配置列表属于明确的小规模数据，不借此读取全库条目                                                   |
| library.showcase.listPresets()       | 返回固定目录的身份、显示信息及完整配置初值                                                               | 只读取得同一份正式预设；名称与初始标题的本地化沿 [文案本地化](../domains/appearance.md#localization)，选用仍只填草稿 |
| library.showcase.applyChanges(input) | 明确的 create、update、delete 与可选 order 变更；返回实际提交后的区块配置和新建草稿 key 到正式 ID 的对应 | 在一个短事务内完成本次区块编辑，任一必要校验或基线失败则整次不提交                                                   |

DTO 属于 desktop-contracts/library，由主窗口客户端明确提供。SDK 的公开范围由 extension-api 选择。applyChanges 只处理本展示柜的 create、update、delete 和 order，不接受 method/args 或跨领域事务。

create 使用唯一草稿 key 和完整配置，由本体生成正式 ID。update 使用 ID、changes 和 expected，query 按整体比较，标题和显示值分别核对。表单 delete 携带它所依赖的原配置，同一目标不能重复出现或同时修改与删除。

不提供 order 时，保留旧项目的相对顺序，新项按 create 顺序追加，删除不重新排列其他项。提供 order 时，必须给出包含隐藏项的最终完整 ID 或 create key 顺序，并带上原完整 ID 与顺序基线。事务先比较增删前的基线，再检查最终顺序与增删后集合完全一致且无重复。只有修改顺序时才检查顺序基线，单独改标题不被无关排列变化阻挡。

短事务核对目标、基线、query 和引用，然后整体提交。任一必要检查失败则整次失败，草稿保留。返回的实际值用于建立新基线，不能覆盖等待期间的新输入。

配置变化或合并引起的引用重映射，使对应内容读取失效。内容查询另行响应 entries、relations、collections、tags 和 activities 的变化。修改展示配置不发送 entryUpdated。

## 列表、单项与筛选草稿

父列表管理区块、可见性和排列，单项使用 Form 与 FieldGroup 编辑标题、完整查询和显示配置。规则列表及单项复用标准 ListForm、ItemForm，条件使用共享 FilterDialog 与资料库查询合同。

筛选确认后进入单项草稿，单项确认后进入父草稿，只有父列表保存才写入。各层取消只丢弃本层尚未上交的内容，真正丢弃时使用共同关闭确认和焦点规则。类型变化使条件或 sort 不再适用时，保留输入等待修正，不能删除限制。切换 query.kind 可以在内存保留各分支草稿，最终只保存当前分支，不建立持久编辑历史。

标题独立于 search，scope 排序没有方向。错误使用共同 Toast 和字段可访问定位，字段说明直接解释输入含义。查询与草稿沿现有状态管理使用不可变更新。

预设可以批量填入父列表，也可以载入现有单项。载入现有项时，只替换 name、query、layout、itemSize、limit 和 openMode，保留 ID、isVisible 和位置。选择预设不立即提交，同一预设可以创建多个独立区块，不按目录 key 合并。保存快照与当前草稿隔离，后台响应不覆盖输入。

点击区块内容时，按 openMode 打开详情或合集内容，最近体验不会因此直接启动。明确的使用动作沿 sessions 选择规则执行。删除区块只删除配置，不删除资料、活动或文件；区块重排也不会创造内容成员顺序。

<a id="references"></a>

## 查询引用与失效

Entry、Tag 或 Collection 合并时，在完整合并事务中重映射 query 的结构化引用并去重。删除使引用失效时，保留原值与可辨识信息，读取报告不可执行，不能删除条件以扩大查询，也不能重新创建对象。引用识别和变换使用共同查询能力，写入仍归各数据拥有者。

新增区块、修改查询或重新显示区块时，核对结构、适用性、操作数和真实引用。已有引用后来失效，不妨碍单独改标题或显示配置，也不妨碍隐藏和删除；没有修改 query 时，保留其原异常。被当前显示范围隐藏不等于真实引用失效。

损坏查询在本区块内明确提示修正。非关键显示字段可以使用安全默认值，但不能把损坏查询变成空筛选。其余合法区块仍可使用和管理，不增加持久错误状态列。

内容按 kind 使用原生列表，Entry 摘要包含真实 type。卡片只呈现数据和发出意图，视图组织查询与打开操作；运行投影只用于展示，不改写最近使用。配置列表失败在页面层反馈，单区块 query 失败在区块内反馈，不能混同失败、未加载和空结果。没有匹配时保留标题、简洁空状态和编辑入口，不自动隐藏区块。

<a id="reading"></a>

## 视口读取与查看全部

先按固定范围、用户条件和当前可见性确定完整集合，再排序。有数量上限时，逻辑展示数量为 min(total, limit)；limit 为 null 时保留完整 total，不把 null 当作零。被敏感内容规则隐藏的对象不占可见名额，OR 也不能绕过该范围。区块共用页面纵向滚动，horizontal 自己横向滚动，grid 随页面展开，不另加纵向滚动框。

limit 为 null 时，仍根据 total 和视口有界读取，不能一次加载全库。只有可见区块按需取得内容。配置、查询或导航变化使旧响应失效，位置通过稳定身份恢复，不能把旧结果填入新配置。

有限区块的 total 超过上限时，才需要“查看全部”。该入口携带当前 query、相同顺序和可见性进入普通完整列表，只去掉显示上限，不建立持久查询会话。浏览修改不回写 Section，返回沿区块稳定锚点，见[详情来源](explorer.md#navigation)。

<a id="type-indicator"></a>

## 卡片类型与运行标识

启用组声明的类型并集多于一种时，在海报右下角常显共同七类图标；单类型范围省略该标识。显示规则由查询范围决定，位置与样式使用共同设计。右上角用于运行状态，关系上下文通过字段表达；Collection 与 Tag 使用自身的对象呈现。

类型图标采用紧凑中性底，在封面和小卡片上保持可辨，作为信息标识呈现，不提供按钮动作或独立焦点。悬停或聚焦时提供完整本地化类型提示，可访问名称包含类型与标题。共享卡片按调用方的显隐配置显示图标，沿用各视图的原有选择和焦点结构。封面、肖像与组织标志分别使用合适的适配方式，logo 保持完整；图标只参与界面呈现。

## 代表性验收

验收首先覆盖四类最近体验在完整去重结果中统一取 12 项、没有活动仍可使用 planned 或 active、0 分进入排行，以及首次三项草稿顺序。还要验证底部无限网格的 total、视口读取和返回，两组不同条件不会重复 Entry，类型变化保留失效条件，手动混合成员重排保留筛选外槽位。

同时核对混合选择、数量、定位与批量动作范围，query 在合并时的重映射和删除后的失效，失效后仍可单独改名或隐藏，以及动态成员失败与排序失败的区别。多层草稿取消和 applyChanges 原子提交必须按真实结果验证。预设目录与已经采用的首页配置独立，不能自动创建全部十项。

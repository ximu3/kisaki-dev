# VNDB 个人记录字段与状态组合

初次验证日期：2026-10-11。本节依据 [Kana API 的 List Management 合同](https://api.vndb.org/kana#list-management)、[公开标签定义样本](2026-10-11-public-list-labels.json)及源站公开源码。初次核对没有连接用户账号或执行回写，后续授权读取与读写结果见文末。

## 已核对的来源字段

| 来源字段或操作           | 来源语义                      | 与本体的边界                                                                      |
| ------------------------ | ----------------------------- | --------------------------------------------------------------------------------- |
| vote                     | 用户评分，整数 10–100 或 null | 与本体 0–100 评分的有效交集可以直接对应；0–9 不能夹到 10 或当成未评分             |
| started                  | 开始日期，日期值或 null       | 游戏当前记录没有同义的开始日期，不变成 Session、活动或加入日期                    |
| finished                 | 单一完成日期或 null           | 本体以最早已知完成日期回写；写入须为 1970–2099 年的完整年月日，当前接口不接受清空 |
| added、voted、lastmod    | 来源列表的技术时间            | 不改写本地 createdAt、updatedAt 或默认加入日期                                    |
| labels                   | 状态标签与其他标签的组合      | 需要按各标签含义解释，不能按数组顺序选第一个                                      |
| labels_set、labels_unset | 增加、移除明确标签            | 可用于最小范围的状态写入；不能用整份 labels 覆盖未选标签                          |
| notes                    | 远端备注                      | 沿共同规则保留，不能在同步其他字段时清空                                          |

固定标签的实际名称为：1 Playing、2 Finished、3 Stalled、4 Dropped、5 Wishlist、6 Blacklist、7 Voted。6 不映射本体当前状态或收藏，7 是评分产生的虚拟标签，不能当作收藏或主动设置、移除。

官方文档区分 Playing／Finished／Stalled／Dropped 这组互斥进度标签；网站选择其中一个时会移除其他进度标签，API 则不强制这个互斥。Wishlist 不属于文档列出的这组，因此不能把所有 1–5 标签都当作同一组互斥进度。

## 来源语义与当前采用规则

以下是来源合同允许的组合示例，不是已读取的私人账号记录。

| 标签组合           | 明确导入时的本体采用                           | 来源含义                                     |
| ------------------ | ---------------------------------------------- | -------------------------------------------- |
| Finished＋Wishlist | 当前状态 null；无历史时初始化一条完成记录      | 完成进度与独立愿望并存                       |
| Playing＋Wishlist  | 当前状态 active；finished 日期另按完成事实采用 | 正在进行的进度优先于愿望                     |
| Dropped＋Wishlist  | 不采用该状态字段，报告无法映射                 | 放弃进度与独立愿望并存，本体没有对应状态     |
| 只有 Wishlist      | 当前状态 planned                               | 没有另一项进度，可以表达计划                 |
| Playing＋Finished  | 不采用该状态字段，报告无法映射                 | 网页中的不同互斥进度并存，不能按数组顺序选择 |

当前[本人列表采用规则](../../../design/extensions/sources/vndb.md#account-status)使用三种当前状态和独立完成事实。只有愿望清单时对应 planned，正常进度写入保留远端独立的 Wishlist。Dropped 不采用为本体状态，也不触发本地删除。active 与过去完成记录只投影为 Playing，不同时设置 Finished；平台 API 允许标签并存不能证明它具有逐次完成历史语义。

只有本地当前状态为空且没有完成记录时，平台目标才是清空。只有 Wishlist 时可以撤回计划；进度与 Wishlist 并存时，只清进度会转为 planned，同时清除两者又会移除独立愿望。因此后一种组合按状态无法映射报告，其他独立字段继续处理。

[早期状态投影样本](2026-10-11-status-projection.json)记录了五态本体模型下的五个读取场景和六个写入计划，包括愿望与进度并存、进度冲突、计划撤回及未选标签保留。原始结果保留为当时的验证记录，不作为当前可写状态或完成历史合同。当前模型的断言见[个人记录验收](../../scenarios/library.md#completion)。这些合成样本不代表真实账号或新模型实现已经通过验收。

## 回写必须沿用的共同合同

PATCH 的未提供字段保持原状，但在用户列表没有该作品时也会创建列表项。因此清除评分等动作必须区分“已有记录上的清空”与“本来就没有记录”，不能为了撤回一个不存在的值反而新建列表项。

来源没有此接口上的逐条记录隐私参数。[当前隐私计算](https://code.blicky.net/yorhel/vndb/src/branch/master/sql/func.sql#L608)依赖所挂标签的隐私属性；改变标签可能改变整条记录的可见性。按 2026-10-16 确认的[原生写入规则](../../../design/extensions/synchronization.md#writes)接受并说明这一结果，不以保留原可见性为前置条件，也不改全局标签设置或添加无关标签。

## 本轮补充核对

2026-10-12 核对[账号操作的具体边界](../../../design/extensions/sources/vndb.md#account-fields)。无凭据调用 authinfo 实际返回 401；公开 API 源码中，写接口缺少 listwrite 也使用 401，因此不能把一次写入拒绝直接解释为令牌失效。本人完整读取需要 listread，写入另需 listwrite。

[评分触发器](https://code.blicky.net/yorhel/vndb/src/branch/master/sql/triggers.sql#L131)会随 vote 自动维护标签 7。结合前述隐私计算，向私有记录写入评分，在 Voted 为公开标签时会改变整条记录的可见性；新增一个私有标签也不能抵消公开标签。这是源站字段之间的实际联系，检查不能只覆盖 Playing／Finished 标签。

[合成投影检查](2026-10-12-account-projections.json)保留十项隐私与完整性、八项评分、十项日期的当时检查。日期规则已按后续实测修正。原隐私拒绝和逐条可见性前提已被 2026-10-16 的原生写入规则取代，不能继续作为当前验收断言；评分范围、不为清空而新建、日期精度等规则仍分别有效。该文件是历史合成投影，不是真实账号读写证据。

这些材料只验证字段、公开标签与源码所表达的约束。认证范围、私有标签、组合状态的实际读写、完成日期往返、缺项、重复调用、并发修改和可见性联动，仍需要授权账号的真实验收。API 未提供对应的原子条件写入，设计不宣称客户端检查能够排除源站同时修改。

## 清单读取范围补充

2026-10-12 再次核对 [POST /ulist](https://api.vndb.org/kana#post-ulist)、[标签定义](https://api.vndb.org/kana#get-ulist_labels)及[分页说明](https://api.vndb.org/kana#pagination)。列表只返回当前 API 可取得的作品，已经从站点数据库删除的 VN 不返回；完整分页不能据此取得所有网页列表占位项，也不能授权删除本地记录。

每批最多 100 项，按 id 顺序读取时可以用上一批末项继续过滤。设计据此区分[一次清单导入与已对应对象同步](../../../design/extensions/sources/vndb.md#account-reading)：前者完整读取所选清单，后者按明确 VN 身份分批取得当前记录。标签定义用于解释固定状态与可见性，私人备注不进入这些操作的字段请求。以上是公开合同核对，真实账号分页和私有标签仍待授权验证。

## 授权读写进展

同日用户另行指定《CHAOS;CHILD》《大图书馆的牧羊人》和《MUSICUS!》进行临时读写测试。[实际结果](account-roundtrip.md)确认状态与评分的局部修改、完成日期写入、三批分页，以及删除后恢复空清单。清空完成日期实际返回 400，原日期保留；只计数的 results = 0 也返回 400，results = 1 正常。正式设计与合成日期投影已采用这些实测限制，没有用删除重建模拟日期清空。

# 本地文件、扫描与识别验收

验证目录、文件身份、规则执行与使用占用。

下文普通刷新中的空关联匹配，均须满足[关联方式](../../design/domains/holdings.md#association-mode)为 automatic；manual 的空集合不参加自动采用。

环境、证据与完成条件见[验收标准](../acceptance.md)，各场景引用对应设计规则。

<a id="directories"></a>

## 目录身份与路径

A08 验证四类作品分别持有目录记录。同作品的重复规范路径被拒绝，跨作品不以路径唯一性错误合并。游戏目录候选与新作品原子提交，不生成空配置；未配置启动时仍能打开目录，平台配置也能在没有目录时存在。修改配置工作目录不改内容目录，移除目录登记保留配置；新增事务失败不留下半份登记。已有根作品按 registerExistingContent 的明确选择跳过或登记，关闭时保持原行为。

A08、A09 和 A27 验证[路径规范化与比较](../../design/domains/file-maintenance.md#operations)：Windows 的 `f:/Books/./Novel/` 与 `F:\Books\Novel` 采用同一规范路径，POSIX 路径遵守自身分隔符与根规则。非根尾分隔符被去除，根路径保留必要分隔符，目录名与文件名的文字和大小写保持。规范化、目录去重、文件复用与包含判断一致，Books2 不被判为 Books 的子目录。词法规范后的同一位置可以复用；位置暂不可访问且名称等价或包含关系无法确认时，保留现有记录，拒绝新增潜在重复或冲突登记。大小写不敏感目录中的 Books／books 视为同一范围，实际敏感目录中的不同名称保持独立；明确 Windows 目录标志及适用 macOS／Linux 文件系统分别验证，不仅按操作系统名称决定。

<a id="recognition"></a>

## 识别输入、规则和目标

A09 验证扫描正则与 output 模板的统一解释，包括固定来源、捕获组、明确前缀、字面量 `$`、未知引用和可选组缺席。UI 预览、SDK 与实际扫描使用相同配置时，产生相同线索；九项预设也使用同一模板合同。

九项扫描预设与文件识别预设采用相同的单行边界：正文、附注、块间和末尾出现 CR、LF、U+2028 或 U+2029 时均不命中。正常名称继续匹配，自定义正则明确允许这些字符时按其表达式解释，不套用预设的附加限制。

A09 同时验证分部默认文件的批量采用。按目录筛选不修改首选；确认的合法配对在同一事务更新指定范围，多个候选、关联变化或首选基线冲突不能按首项或旧观察覆盖。取消不修改数据，未选范围和后来发现的新文件不继承本次选择。移除目录仍保留文件、位置、关联及适用首选。

A08、A09 验证[共享识别方案](../../design/domains/file-recognition.md#recognition-profiles)。不同作品目录可以引用同类方案，结果仍只匹配各自作品内已有分部，跨媒介引用被拒绝。定义修改影响引用目录的新文件和空关联核对，非空关联保持；仅改名不触发识别。识别期间实际方案定义、引用或目录上下文改变，旧的未提交结果不能继续写入；发现过滤另按登记与已有文件维护的不同范围核对。复制并改选后独立维护；仍被引用时删除失败，目录与文件不被级联删除。

A09 验证[文件识别规则](../../design/domains/file-recognition.md#recognition-rules)：同一目录中的不同文件可以分别命中同一方案内的不同规则；同一文件能被多条规则完整匹配时只采用第一条。已匹配但输出错误、目标缺失或歧义时不继续尝试，不回退内置。全部未匹配、空列表或全部停用才进入内置识别，方案失效不能伪装成未匹配。关联失败仍可登记和使用合法文件。

A09 验证[命名解释职责](../../design/domains/file-recognition.md#recognition-responsibility)：完整自定义规则可以独立处理内置不支持的格式。两者能对同一文件给出不同解释时，命中自定义规则后只采用该规则的完整输出；省略的可选条件不由内置补充，缺失的必要条件也不能靠内置修复。仅输出偏移的定义不能保存为完整规则。两种识别生成相同匹配条件时，使用相同的本地分部查询与关联校验，均不创建分部或改变作品范围。

A09 验证分部目标具备编号或完整名称，Extra 只使用完整名称，不补造结构化编号。只指定分部种类、分集类型、附加内容类型或漫画话的卷范围时，即使当前只有一个候选也不能关联。分集编号 1 加正片类型条件时，不匹配同号特别篇；省略类型条件后两者均参与查找并产生歧义，不默认正片或未知类型。类型条件不写回资料，也不应用于漫画卷、话和小说卷。漫画话使用明确的作品话号或卷内话号依据，不能根据哪种能命中来切换。

A09 验证[目标列表及固定语义值](../../design/domains/file-recognition.md#recognition-targets)：空 targets、越过媒介的目标种类、Extra 的编号及不适用的字段在保存时拒绝。kind、类型条件、numberBasis 和 offset 不接受模板引用。类型条件缺席与明确为 null 分别对应不限和仅未知类型，非法类型不能按 null 执行。single 的 01-03 只作为一个编号文本查找，range 的 01 至 03 才查找三个整数编号；范围上的名称、类型与卷范围约束对每一项生效。漫画话的卷范围只形成查找条件，列表另列卷目标时才要求文件卷关联。

A09 分别验证两种顺序：两条规则均能完整匹配 01 (329).mkv、分别输出 329 和 01 时，交换规则排列改变所选解释；一条规则对 01+02.mkv 输出分集 1 和 2 时，交换目标排列仍产生相同的关联集合。多项目标对应同一真实分部时去重，但不能借去重省略任何目标的完整性校验。目标排列不改分部人工顺序、首选、播放队列或文件内位置，冲突也不能按前项取胜。

A09 验证[输出展开与完整性](../../design/domains/file-recognition.md#recognition-output)：

- 引用的可选捕获组缺席时，整个字段缺席；固定前后缀不单独形成输出。捕获空字符串时校验展开值，仅有空白的编号或名称报错。
- 编号存在而可选名称缺席可以匹配；两者均缺席或 Extra 缺少名称时失败。
- 已声明卷范围但缺少卷标识、范围缺少端点、多个目标中有不完整项时，报告该次解释失败，保留原有范围。
- 未知捕获组引用在保存时拒绝。同一输入在预览与实际执行中产生相同输出或问题。

A09、A27 验证文件规则在保存、测试和实际识别中使用同一执行隔离与预算，停用项不能绕过结构校验，重复规则 id 被拒绝。恶意回溯或其他求值超限可终止实际执行单元，当前作品中同一方案快照的未处理文件报告未完成，不回退内置；已形成结果保留，其他方案、作品及独立技术核对不被持久停用。正常输出问题仍只影响相应文件。超大整数范围不生成与跨度等长的数组，不使用浮点截断，也不输出无界缺项清单。

## 内置动画语义

A09 验证[内置发布命名覆盖](../../design/domains/file-recognition.md#builtin-recognition)：方括号编号、标题后集号、数字标题、季集组合、发布修订以及技术附注正确区分，13.10 保留文本含义。漫画话号与来源卷分开，小说卷号不由电子书系列顺序直接代替；动画 BD 分卷不生成新的本体层级。加入多种解释互相矛盾、缺少或重复分部、仅有技术数字以及未知发布组名称的用例，分别核对提取与关联结果，不直接沿用第三方测试期望。

A09 验证[动画内置默认](../../design/domains/file-recognition.md#builtin-anime)：普通分集命名主动输出 regular 条件。同号正片、特别篇和未知类型并存时只选择唯一正片；只有特别篇或未知类型时不关联、不改类型；同号存在两个正片时仍报告歧义。01 (329) 的已知主次结构只采用 01，即使库中只有 329 也不改用替代编号。S02E03 在已绑定作品内匹配正片 03，不换算全系列集号，也不声称完成季号校验。数字标题、修订及技术信息不误作目标编号；01-03 与 01+03 分别产生完整范围和两个明确目标。

A09 同时验证 NCOP01 使用完整名称与 opening 类型匹配已有 Extra，不将尾部数字当作 Episode 编号，也不仅凭类别匹配其他名称。仅有 SP、S00 等未确定种类的线索，或明确主集号发生冲突时，报告问题而不套用普通正片默认。未识别命名不默认正片，关联失败不阻止合法文件登记和使用。

A09 验证[特殊内容标记与名称](../../design/domains/file-recognition.md#builtin-anime-content)：Special Episode 01 和特别篇第 01 话使用 special 条件；附加内容词表分别形成 opening、ending、promotion、interview 或明确的 other 条件。标记位于作品标题、发布组名或技术字段中时不触发分类，互不兼容的明确类型不能按先出现者取胜。名称包含内容标记、原样序号和后续标题，不包含已识别的发布组、来源和技术附注。

A09 验证 NCOP01v2 只排除明确的发布修订 v2，与 NCOP01 的两个文件可以关联同一 Extra；NCOP02、NCOP01 - 歌曲名仍使用各自完整名称。名称中的数字不执行编号归一化或偏移，NCOP01 不匹配 NCOP1 或 NCOP 1；名称中的普通文字不能当作修订任意删除。同类型但名称不一致，或同名同类型对应多条 Extra 时，均不能自动采用某一项。

A09 验证同一目录中作品第 03 集的 TV、BD 和 v2 修订文件可以分别登记并关联同一条正片分集资料。已有文件完成关联后，新文件仍可关联该分集；它们保留独立文件身份与播放位置，不替换旧文件或自动改变首选，每集仍至多一个首选文件。相同场景分布在多个目录时采用同一规则。多个文件对应同一分集不构成歧义，两个不同分集资料记录同时满足同一目标才构成歧义。

A09 的编号用例覆盖 03 与 3 等价、000 与 0 等价，以及 1.10 与 1.1、1.0 与 1、SP01 与 SP1 不等价。原文不被回写，等价编号命中两条记录时必须报告歧义。漫画卷内话号正确对应作品中的同一话，不附加文件卷关联。1–3 范围要求实际编号 1、2、3 全部存在且唯一，不使用前三行，也不包含 2.5；缺第 2 项时保持空关联，补齐后才能整体匹配，不产生分部内位置或完成记录。

A09 验证[编号偏移](../../design/domains/file-recognition.md#recognition-offset)只作用于具体规则的编号输出。偏移 12 时，13、13.5、13.10 分别对应 1、1.5、1.10，12 可以匹配真实零号分部；偏移 -12 时，1 对应 13。偏移 0 不改写 013.10。范围 13–15 对应 1–3 后仍须完整匹配，卷号与话号不能互相套用偏移。非零偏移遇到不支持的文本或负结果时报告问题，不回退；内置识别及其他规则不受影响。共享方案修改和复制后的独立使用保持各自语义，文件名及正式编号均不改写。

A09、A18 和 A29 验证预设采用与方案编辑：文件识别方案复用其他预设的图标入口、选择器及载入草稿流程，没有专属采用阶段或额外确认。图标入口约定只覆盖选择预设，普通新建、添加按钮仍符合既有界面，不因此统一改为纯图标。预设只填入草稿，保存前不改变正式方案或目录引用；新建保存后生成独立方案，官方预设更新不改写旧副本。已有方案载入预设仅替换规则定义草稿，取消保留原值，保存后才按共享引用规则生效。方案管理的保存不提前提交仍在编辑的目录，游戏目录不出现分部识别方案。

## 发现、监听与刷新

A08、A09 验证[目录范围](../../design/domains/holdings.md#directory-discovery)：默认递归，maxDepth 为 1 时只新增直接子项及合法的根图片目标；包含不剪去仍可能命中后代的目录，排除目录覆盖子树。精确路径中的方括号、星号按原文处理，glob 的 `*`、`**`、`?` 和大小写开关符合[路径合同](../../design/domains/scanner.md#path-filters)。拒绝根外、绝对路径和非法片段；不自动跟随子链接，不将部分遍历或过滤跳过解释为已有文件失联。过滤不改变阅读目标内部页面，损坏发现设置停止新发现而不按无限范围执行。

A08、A09 验证首次启用、启动和恢复时的监听接续：在首次遍历已经经过的目录中新增、改名或移除文件，仍能由已接入的监听及后续合并核对处理。不能用“先遍历、后监听”遗漏中间变化，也不能重复登记同一目标。监听不可用如实报告，遍历结果不假称监听已生效，手动核对仍可执行。

A08、A09 验证发现与已有文件维护独立：排除尚未登记路径后不创建文件；排除已登记路径后，不删除记录、不清除关联或位置、不停止原有核对，也不改用零散文件规则。只修改过滤不触发已有文件重新关联；之后分部资料或方案改变时，空关联文件仍使用原目录上下文正常匹配。明确手动添加可以登记被自动发现过滤的文件，移除记录后仍被排除则不自动重新登记。发现设置损坏不阻断目录路径、方案及其他依据仍有效的已登记文件维护。

A09 验证[资料变化后的空关联核对](../../design/domains/file-maintenance.md#refresh)：资料源清单补入真实第 13 集、手动创建该分部或更正匹配依据时，都只在实际提交成功后核对相应作品的已登记空关联文件。自动刷新关闭、更新无实际变化或事务失败时不触发；开启时也不重新遍历目录或登记其他文件。资料更新完成不等于文件已经匹配，匹配失败或等待使用占用不回滚分部，原有非空关联不改写。多个相关变化可以合并，但提交时使用最新有效依据，匹配不会反向请求来源清单。

A08、A09 和 A16 验证[监听与定期刷新](../../design/domains/file-maintenance.md#refresh)：初次开启、启动和恢复先接入可用监听并立即核对。明确监听失败仅使受影响范围在上一轮结束 5 分钟后再次刷新，不影响正常监听范围，不重叠执行或积压轮次；普通安静目录不被判为失效。目录可读而无法监听时仍能发现变化，目录不可读时保留记录并表达实际问题。明确通知丢失触发一次合并刷新，不自动永久降级；监听恢复后核对并停止对应周期。关闭自动刷新不再产生自动触发，手动刷新仍执行同一套本地规则。

A09 验证两种[文件匹配文本](../../design/domains/file-recognition.md#recognition-inputs)：根 `作品A` 下的 `第02卷/01.cbz` 产生文件名 `01` 和路径 `作品A/第02卷/01.cbz`；只登记一处部分内容位置 `第02卷` 时，路径为 `第02卷/01.cbz`。根自身图片目标的 path 为根名，文件系统根与共享根不伪造普通根名、不读取祖先。普通卷文件夹不自动拥有目录记录、方案或第二份上下文。scanner 仍使用候选名称与相对于扫描根的路径，不借用已有作品文件的根。

A08、A09 验证[唯一目录上下文](../../design/domains/file-recognition.md#recognition-context)：同作品已登记父目录时拒绝再登记子目录，反向登记父目录也拒绝；排除子树或降低最大深度不能豁免这一约束。多个互不包含的目录可以独立采用方案。创建、改路径、批量写入和作品合并不得留下相互包含的目录，不自动删除或改写已有登记。方案仅在这一处上下文按规则顺序执行，不汇总多目录结果。

A08、A09 验证默认新增目录仅使用内置；明确的同类方案引用随手动目录登记原子提交。扫描规则与 MetadataProfile 不推导文件方案。真正位于所有登记目录之外的文件只使用 baseName 进行内置命名解释；过滤不改变目录包含关系，目录路径或方案错误也不能伪装成没有上下文。关联提交重新核对文件归属、实际目录上下文、规则定义、目标唯一性和空关联；新发现登记另检查发现设置。过滤变更使不再符合条件的新文件登记失效，但不使已有文件的同依据识别结果失效。

## 内置书籍与预设

A09 验证[漫画与小说内置语义](../../design/domains/file-recognition.md#builtin-books)：Vol.02/Ch.01 使用第 2 卷实际收录的卷内 1，可对应作品话 13；没有卷内编号时不改查作品 1，也不使用第一项。c012 (v02) 使用作品话 12，不要求卷 2 或额外文件卷关联。裸 03.cbz、03.epub 和 2/1.cbz 不决定目标种类；上卷保留文字编号，153b 与 013x1 保留完整文本，小说章节和电子书分组序位不形成卷目标。明确范围及清单仍完整匹配，不创建分部。

A09、A18、A29 对[十项文件识别预设](../../design/domains/file-recognition-presets.md#definitions)逐项校验完整表达式、输出、offset 为 0、适用媒介与正反例。共用卷号模板保存为独立同类方案；两个卷目录模板都验证实际卷收录，但分别查询作品话号和卷内话号。末尾换行、范围、修订、缺少卷范围和未知扩展名不能被模板误作已声明的单编号。预设未命中与命中后无法关联分别呈现，测试覆盖从草稿到实际执行的相同解释。

## 手动文件整理

A08、A09 验证[手动文件操作](../../design/domains/holdings.md#manual-files)：从作品文件列表添加时，没有分部对应的合法文件仍可登记；从分部详情添加时，以真实所选分部建立同作品关联，不被文件名改换目标。同作品同规范路径复用原文件和位置，增加另一分部关联不移除原有其他关联；重复关联无变化，另一文件对应同一分部仍独立保存位置。关联编辑使用完整直接集合，漫画卷的收录投影不成为直接文件话关联，单文件添加不登记父目录。

A09 验证[重新识别](../../design/domains/file-maintenance.md#reidentify)统一处理已关联和未关联的所选文件，原关联只作比较基线。未命中、目标缺失、歧义或执行失败时不产生空集合替换；完整结果相同则不写入。采用只包含所选有效结果，相关依据变动时整次选定修改不提交，也不静默换用新结果。保留关联的首选属性不变，移除关联同时取消依赖它的分部首选，新关联不自动成为首选；文件位置、作品首选和历史不被重写。

A08、A09 验证[重定位](../../design/domains/file-maintenance.md#relocation)：单文件位置更正保留身份和实际记录，另一版本不能作为迁移位置的替代。目录映射覆盖旧根下已登记文件，包括被发现过滤排除或超过当前发现深度的项，旧根外文件不迁移。游戏配置与手动字幕仅更新明确选择的当前位置，URL、自由文本、历史及备份快照不替换。目标缺失、不可读和登记冲突分别报告，不能覆盖、合并或凭同名替代；未采用项保留原位置，不以目录已更新冒充全部文件恢复。新根包含约束、原位置基线与有效选定映射的整体提交共同成立。

A08、A09 验证[应用外改名与移动](../../design/domains/file-maintenance.md#external-path-changes)：原记录的路径、身份、关联、首选和使用位置保留，可访问性依据实际核对改变；监听改名事件或内容相同不自动迁移身份。新路径处于发现范围时独立登记并使用自身位置，范围外不扩大搜索。新旧记录可以关联同一分部，但不因此合并；新记录不接替失联原记录的首选。明确重新定位遇到已登记目标时保留双方并报告冲突，目标未冲突时才按明确映射保留原身份更新位置。原规范路径恢复可访问时复用原记录，整目录外部移动也不隐式更新子文件、游戏配置或手动字幕路径。

A09、A18、A29 验证[文件整理与规则测试](../../design/ui/components.md#file-operations)：规则测试使用草稿，仅有样例文字时只给匹配条件；目录预览使用目录草稿与已保存方案，不登记文件、不拉取来源资料，也不为显示过滤结果遍历排除子树。重新识别对所选文件直接更新合法结果，无匹配或冲突保留原关联并报告。重定位使用用户选择的新路径，无效或登记冲突保留原位置。批量默认文件遇到同一分部选中多份文件时整次不提交，不生成配对预览或第二次采用步骤。

<a id="association-mode"></a>

## 手动决定与恢复自动匹配

A08、A09、A18 和 A27 使用真实文件记录与短事务验证以下确定行为。算法匹配样例沿用前文，不为每种入口重复整套命名测试。

| 起始事实与动作                                             | 必须成立的结果                                                                  |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 新发现文件没有显式关联，规则唯一匹配已有分部               | 初始为 automatic，采用完整关联；以后普通刷新不重写非空集合                      |
| 用户清空一份文件的全部关联，随后刷新、补分部、改规则并重启 | 同次保存 manual 与空集合；这些变化均不重新关联，位置与技术核对继续有效          |
| 漫画文件仅保留卷关联，或手动清空卷与话关联                 | 前者不自动补话；后者保持 manual 的完整空集合，不把卷收录关系写成直接话关联      |
| 从分部详情明确添加已有文件，或导入明确的文件关联           | 同次保存所选关系与 manual，保留其他关系、首选和位置；重复添加不重置为 automatic |
| manual 空文件恢复自动，自动刷新已开启                      | 先保存 automatic，再安排一次当前核对；保存成功与匹配成功分别反馈                |
| manual 空文件恢复自动，自动刷新关闭                        | 保存 automatic 后不启动后台读取；普通手动刷新可以匹配                           |
| 对 manual 文件明确重新识别                                 | 一次采用合法结果，模式保持 manual；失败保留原关联与模式                         |
| 自动识别已取得结果，用户在提交前清空并保存 manual          | 旧自动结果不采用；结果不恢复被用户移除的关系                                    |
| 使用期间改为 manual，原后台匹配正在等待占用解除            | 模式可以保存；会话结束后重查资格，不补交旧匹配结果                              |
| Part 删除使文件关联变空，或文件被重定位                    | 保留已有模式；manual 不重新匹配，automatic 按最新事实核对                       |
| 已保存模式损坏，或模式提交的 expected 不再相符             | 前者停止自动采用并保留其他可读内容；后者返回 Conflict，用户草稿保留             |

原生界面验证关联方式的展示、清空后的保持、一次重新识别和恢复自动的不同动作；Node SDK 验证同一归属、基线与结果合同。实际关联修改继续遵守使用占用。

<a id="occupancy"></a>

## 文件使用占用

A09、A10–A12 验证[文件使用占用](../../design/domains/file-maintenance.md#file-use)：从打开准备开始保护实际文件，测试和预览可进行，关联、路径或记录的实际修改须先结束受影响会话，无变化不制造冲突。后台匹配遇到占用保留现状，会话结束后按最新规则和资料重新核对；期间关闭自动刷新则不自动补做。手动采用不被延期提交，系统不自动关闭会话，旧识别结果及旧活动回调不能写入新上下文。

A09、A14 同时验证经由分部删除或作品合并间接改变文件关联的情况。完整操作须核对实际受影响文件的使用占用，不能因为入口不是文件编辑而绕过同一限制；冲突时相关事务不留下半份关联或引用迁移。

<a id="existing-content"></a>

## 扫描接续已有作品

A08、A09 和 A15 验证“为已存在作品登记本地内容”默认关闭；保存并开启后，配置按同一扫描生命周期接纳后续工作，已接纳执行保留开始时的选择。

| 输入与动作                                           | 预期结果                                                                               |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 先从平台编目，再扫描准确来源身份对应的目录，选项开启 | 复用作品，新增该目录；资料与个人值不变，适用首次核对由 holdings 完成                   |
| 相同输入但选项关闭                                   | alreadyExists 且 localContent 为 skipped，不追加内容                                   |
| 同作品已登记同一位置，再扫描                         | 返回已有登记，不复制文件、位置、首选或游戏配置                                         |
| 同作品另一个有效且不冲突的位置                       | 新登记该位置，原位置与记录保留                                                         |
| 只有同名或来源身份指向多个目标                       | 不追加；报告准确原因，不按名称或响应先后选择                                           |
| 对应完成后，目标被删除或身份改绑                     | 最终事务拒绝登记，旧请求不转投其他作品                                                 |
| 登记成功但首次本地核对失败／取消                     | 保留登记并报告合法部分结果，不重建作品或宣称全部完成                                   |
| 一个候选新增作品，后续候选对应同一作品的另一目录     | 按本次选项处理后续登记，仍按稳定候选顺序执行                                           |
| 游戏明确文件目标有一套或多套同目标配置               | 返回全部已有匹配配置，不改监测或首选；没有配置时只创建该文件入口，缺少监测条件明确报告 |

报告分别显示作品与持有成果：没有新增作品但新增目录时仍有实际成果；登记失败不抹去已经成立的作品对应。重复扫描与跨配置并发使用同一 holdings 规则，不增加扫描私有文件表。

## 外部改名后的重复文件登记

A08、A09、A14、A17 和 A27 验证[文件合并](../../design/domains/file-maintenance.md#file-merges)：原文件已失联，改名后的新位置已被发现为另一条记录；用户明确选择保留原文件身份与新位置后，一次操作保留其续读、设置和历史。只选新路径的普通重定位仍报告登记冲突，不自动合并。

| 输入或变化                                     | 通过条件                                                                                                          |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 两条登记有不同位置、设置、关联及标注           | 保留目标的完整续读／续播位置与设置，包括空值；采用明确路径，关联并集设为 manual；标注和活动保留 ID 并迁移文件引用 |
| 双方均有首选关系与备注                         | 指向源文件的首选改指目标，其他首选不变；不同非空备注按目标、源顺序保留                                            |
| 选择第三条路径、跨作品文件或同一 ID            | 输入失败，原登记不变；不移动、删除或覆盖任何媒体字节                                                              |
| 准备后路径被修改、出现第三份登记或文件正在使用 | 依据变化或占用使整项失败，无部分引用迁移                                                                          |
| 路径无法确认或所选内容不可验证                 | 保留双方及历史，明确未完成原因，不凭旧观察值报告成功                                                              |
| 同位置重复文件随完整作品合并处理               | 与同作品文件合并采用相同取值规则，与作品归属共同提交；不同位置仍独立保留                                          |
| 成功后继续打开与跳转标注                       | 返回实际保留身份和路径，holdingsChanged 带源与目标文件 ID；位置按当前内容校验，不能把坐标保留当成已经跳转成功     |

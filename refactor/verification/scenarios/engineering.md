# 运行、持久化与工程验收

验证实际数据库、后台拥有者、订阅及工程入口。

环境、证据与完成条件见[验收标准](../acceptance.md)，各场景引用对应设计规则。

<a id="private-native"></a>

## 本体私有原生入口与交付

A24、A26、A28 和 A31 按[本体私有原生规范](../../design/engineering/native.md)验证 Rust 实现、Node 入口和应用接入的职责。消费方从 `#native` 引用实际能力、类型与错误，文件设施不持有另一份绑定声明或加载实现。preload、renderer、extension-host 和 shared 不能绕过入口导入私有原生代码。

类型消费者在没有 .node 的环境中完成类型检查。原生构建生成的声明与受版本控制的声明一致，实际调用的参数、结果和错误与声明相符。应用装配从明确部署路径加载对应制品；缺失、架构不符或不能加载时提供安全错误，不搜索其他构建目录或现场编译。开发输出与不同目标构建互不覆盖，最终应用使用与本次构建身份相符的绑定和配套资源。

文件能力使用真实文件与目录验证正常移动、已有目标保留、来源缺失、跨卷和不支持的结果；系统调用已经开始时，停止等待不能冒充撤回。备份流程的完整中断与恢复继续由[存档场景](sessions.md)验证。具有持续资源的后续能力补充自己的创建失败、取消、正常关闭和环境退出用例，不为无状态文件操作虚构资源流程。

A13、A27 和 A28 核对[原生 syncFile](../../design/engineering/native.md#file-sync)：普通文件、空文件、错误类型、路径缺失、权限失败与不支持均保持明确结果，句柄在失败后仍关闭。Windows 不请求整卷管理员权限，macOS 不将 F_FULLFSYNC 失败改报普通 fsync 成功，Linux 的文件同步与父目录同步分别执行。恢复在关键准备同步失败时不修改目标；目标已经移动后的同步失败保留索引与材料，不以测试进程退出证明掉电保证。

<a id="source-quality"></a>

## 源码、注释与工具结构

A26、A31 和 A32 按[源码语言规则](../../design/engineering/conventions.md#source-language)检查应用、包、扩展、工具、配置、测试和模板。手写 JavaScript 源文件不能因位于产品 src 之外而漏检；编译产物、绑定生成结果和第三方发行内容分别按制品归属核对。

按[可读性](../../design/engineering/conventions.md#readability)与[代码对象的注释要求](../../design/engineering/conventions.md#comment-objects)审查完整操作的正常路径及相关失败、取消和清理路径。逐类核对注释覆盖，以及输入、完成、失败、状态和资源说明是否准确。名称、类型与实现相符，说明由实际合同拥有者维护；实现改变后，旧注释和已失效的临时标记同步修正。格式检查或注释数量不能替代这些审查。

A32 按[项目文档规范](../../design/engineering/documentation.md)核对各项目说明的完整性、规范适用范围、真实命令、可运行示例、skill 路由与引用。独立项目的说明应符合自身技术栈与公开职责。

A26、A31 和 A32 按[配置归属](../../design/engineering/conventions.md#configuration-layout)核对根工程、本体、公共包、官方扩展、作者模板、消费者样板与独立项目。默认发现入口、共享基线和工具专用位置承担实际职责；内部配置按所属工程及工具归组，不以配置数量保留例外，也不增加空目录或纯转发文件。迁移按实际影响核对有效编译选项、源码覆盖和编辑器项目归属；影响开发加载、构建或公开制品时，再验证相应运行与消费链路。文件移动成功不能单独证明正确，也不自动要求全部链路重跑。

按[tools 结构](../../design/engineering/layout.md#tools)核对工具归属、CLI 与工作流依赖，以及样本和输出位置。通过明确参数调用工作流与通过 CLI 调用应采用同一实现；模块导入不启动任务，工作流失败由 CLI 在清理后报告非零退出状态。工程实现不导入测试用例、fixture 或 tests/support；测试可以调用被测工作流和消费产物。工具本身保留必要的输入与输出校验，用例通过正常和失败场景验证其行为。fixture 不被生成制品覆盖，独立临时目录在资源释放后清理，本地与 CI 采用同一实现。

按[桌面工具布局](../../design/engineering/layout.md#desktop-tools)核对 dev、build、resources、native、package 和 clean 的实际调用与输出。开发与有限构建复用 Vite 程序配置，资源与原生制品各有唯一写入者，打包消费已就绪输出，测试通过既有运行器和所属配置执行。

按[测试任务](../../design/engineering/layout.md#test-tasks)核对常规、消费者和最终制品任务的输入及执行阶段。消费者任务接收实际 tarball，制品任务接收指定目标和构建身份的最终文件；输入缺失或不匹配时失败，用例不重建或替换待验证的产品制品。项目脚本、依赖任务和测试配置共同表达运行条件，没有另一份通用测试调度逻辑。包结构检查沿用现成工具，其结果与消费用例均进入任务结论。

按[测试结构](../../design/engineering/layout.md#tests)核对根、本体、公共包和扩展各自的用例。纯逻辑单测不依赖真实 I/O 或 DOM；原生与数据库套件在运行器启动前选定匹配的 Electron 宿主与 ABI，浏览器与 Electron 用例在对应真实环境执行。根 tests/tools/hooks 只操作隔离 Git 仓库；本体 tests/integration/native 与 tests/tools/native 分别验证运行接口和构建流程。测试按主要验证目的归档，运行环境由配置表达，不复制交叉分类的相同用例。测试、fixture 和消费者样板不进入运行输出、公开声明或 workspace 成员清单。

<a id="ci-events"></a>

## CI 事件与检查结果

A26 与 A31 按[PR、提交与 CI](../../design/engineering/workspace.md#collaboration)在实际 GitHub PR 上核对事件和检查结果。代码验证运行期间修改标题或正文，不取消原验证、不产生新的代码汇总；原代码失败后编辑元信息，失败仍保留。无效标题独立失败，正文编辑不能清除该失败；修正标题只更新标题检查。新提交与目标分支变化重新执行代码验证，并取消同一 PR 的过时验证。

核对实际检查名称、合并规则与最终汇总：仓库检查成功且所有应执行的桌面目标成功才可通过；未选择桌面任务与应执行却跳过分别处理。事件路由可用有限替身验证，但替身结果不计作仓库检查或六目标运行证据。

<a id="appimage-compatibility"></a>

## AppImage 启动兼容性

A24、A26 与 A28 按[AppImage 启动政策](../../design/engineering/build.md#appimage-compatibility)核对最终 AppRun 与 .desktop，桌面入口不无条件附加 --no-sandbox。Linux 实际运行分别覆盖允许用户命名空间、AppArmor 限制及系统禁用用户命名空间的条件；上游条件判断决定保留沙箱或降级启动。记录渲染进程的命名空间、Seccomp 与实际命令行，不能只用 sandbox 配置、页面没有 Node 全局变量或窗口成功出现证明进程隔离。条件变更限于隔离验证环境，结束后恢复。

<a id="database"></a>

## 数据库迁移

A27 和 A28 验证[Drizzle 原生迁移流程](../../design/engineering/database.md#initialization)：空库应用新基线及全部迁移，已有新架构库只应用未执行部分；重开不重复修改数据。使用带有关联、活动、Note 和非默认偏好的样本验证升级后身份、引用与用户选择保留，新增偏好字段按对应迁移补齐。迁移执行失败按事务回滚并报告错误，不继续开放业务或改建空库。正式制品能够定位并读取迁移 SQL 及所需元数据；旧实现和其他格式不被纳入这条升级链。

A27 和 A28 另核对[资料根文件系统](../../design/engineering/database.md#integrity)：本地普通与便携根正常初始化；确认的 SMB／NFS 或映射网络位置在打开数据库前被拒绝，原资料保留，不改成其他日志模式或另一空库。路径判断使用实际卷／挂载信息；媒体目录的读取不因资料根规则被一并禁用。macOS 读写连接回读 fullfsync，正式事务与性能测量使用相同同步设置；Windows 结果不代替这项平台检查。

<a id="history"></a>

## 任务与扫描历史

A15 验证[任务历史](../../design/domains/tasks.md#history)和[扫描历史](../../design/domains/scanner.md#history)保存失败：本次执行停止后续业务并完成必要收尾，已形成的合法结果按共同失败合同交付，已提交业务保留；结束后不补存历史或自动重做业务，也不阻止其他正常操作。历史中尚未保存的结果不能显示为已经保存。

A15 验证两份历史各自保存与完成：所需起始记录未保存时不开始业务副作用；ScanRun 保存失败向任务传播；ScanRun 已完成而 TaskRun 最后保存失败时，扫描报告与正式产物保留，完整调用报告任务历史失败并交付合法结果。每份记录自身的终态与结果共同提交，两份记录不依靠联合事务保证同时结束。正常执行共用同次生成的 ScanResult，历史停留在不同检查点或完成阶段时不互相推断、修补或重算结论。

A15 验证 scanner.finished 和 tasks.finished 分别表达实际边界，扫描结束不提前释放仍在托管的运行关联，也不让完整 scan 提前返回。TaskRun 终态保存失败时，当前观察者和等待者得到实际失败；上下文释放后，list、get 与新观察或等待把最后非终态历史投影为 interrupted，保留最后检查点和空 finishedAt。筛选、计数和明确清理使用同一判断，扫描完整报告继续独立可读。

<a id="events"></a>

## 事实订阅、连接与接纳

A15、A16、A21 和 A23 验证[统一事实订阅](../../design/communication.md#events)：本体与 Node SDK 均通过 events.on 订阅已开放的原生及扩展事实，原生事件名与载荷类型对应，扩展事件使用正式 ref。同一事实没有领域模块的并行订阅别名；运行 observe 仍交付当前快照及变化，onInvalidated 仍用于合并重读。订阅能力不附带发布权；原生与扩展 publisher 均不能发布归属之外的事件，旧扩展实例不能继续发布。

A16、A21 验证[集中订阅与执行归属](../../design/architecture.md#app-composition)：自动备份和持有维护的固定跨模块订阅由 app 建立和释放，目标模块通过完整入口处理输入，不依赖全局 events 单例或发布方的完整实例，也不重复登记同一固定关系。连接代码不判断业务开关、维护业务队列或代替执行收尾；动态实例的订阅和内部监听由实际拥有者清理。启动失败释放本次已建立的连接，正常退出保留必要通知的交接和在途等待。解除订阅不取消已独立接纳的工作；依赖扩展实例的工作仍遵守实例寿命。订阅者失败按事件合同隔离，不改写已完成操作的结果，也不使其他订阅者遗漏应交付的通知。

A06、A15、A16 和 A21 验证[模块入口与依赖范围](../../design/architecture.md#module-interfaces)：自动备份的原生事实处理入口与手动入口复用创建业务，窗口和 SDK 的开放范围仍按各自合同限定；扫描复用 ingest 完整单项业务和实际任务上下文，不穿透私有执行步骤或生成嵌套任务。资料修改取得范围明确的占用检查能力，仍以 sessions 的实际登记为依据，不另存占用副本。

A15、A16、A21 验证[通知交接与业务完成](../../design/communication.md#event-delivery)：主进程发布完成通知交接后，已接纳工作即纳入接收方的在途管理，实际业务仍可尚未完成。延迟备份准备或 TaskRun 建立时，应用退出仍能等待该工作；接收方准备、执行或收尾失败都不把会话结束改写为未发生。同步订阅异常与异步失败均不阻断其他订阅者，消息发送成功不被视为远端扩展业务完成。

A16、A20 验证启动与退出的连接顺序：必要初始化由启动流程直接等待，固定连接就绪前不开放相关工作，不通过 app.ready 订阅补齐必要前置步骤。退出等待期间仍能交接真实会话结束及必要备份；取消退出恢复接纳后，每次事实仍只触发原有的一次处理，不重放事件、不重开已结束内容。达到退出条件后才解除固定连接并释放依赖，数据库在使用它的收尾完成后关闭。

A06、A15、A16 和 A27 验证[接纳与执行边界](../../design/communication.md#admission)：监听变化尚未接纳时，关闭监听可丢弃待核对范围，且没有为其预建 TaskRun；已经接纳的扫描或备份即使仍在准备或等待资源，也纳入实际等待与控制，不因之后关闭触发开关而隐式取消。异步准备期间既有更新目标被删除时，提交失败，不重建或另选目标；无关字段变化不阻止合法提交。取消观察或等待既有执行的调用，不取消实际工作；取消退出不重开内容或撤销已提交结果。

<a id="extension-deeplinks"></a>

## 扩展 deeplink 注册与交付

A21、A23 和 A28 按[扩展入口合同](../../design/ui/navigation.md#extension-deeplinks)验证纯值、真实 SDK、宿主与最终制品，各层分别记录结果。使用独立测试资料和验收扩展，不增加官方扩展交付项，也不使用真实个人下载目录。

纯解析与格式化覆盖正式和开发协议、符合[身份合同](../../design/extensions/distribution.md#package)的单段与点分扩展 ID、业务路径中编码后的 /、Unicode、空路径、空组件及有序查询项。带 /、大写、空段或其他非法字符的扩展 ID 被拒绝，不能当作 npm 包名接纳。重复键、空值和参数顺序往返后保持，编码只解一次；非法百分号转义、非法 UTF-8、目标结构、用户名、密码和端口均明确失败，不替换字符或改投其他入口。原生 view、open、add 的未知参数和重复单值参数仍失败，不能因新增 extension 分支放宽。扩展拒绝未知路径或业务参数时，不执行下载安装或改用缺省动作。

解析实际收到的 /alpha/../beta/install、/alpha/%2e%2e/beta/install 及单点、混合编码和大小写变体时，在点路径被规范化移除前拒绝，不交给 beta。format 同样拒绝完整的 .、.. 输入组件；其他含点号的正常路径仍可生成和解析。合法值的往返保留原扩展归属与路径，不用对规范化后的目标重新路由来掩盖输入错误。

fragment 覆盖缺省、显式空片段、普通定位值、Unicode、百分号转义、+ 和编码后的 #，往返保持缺省与空值的区别，不重复解码，也不把 + 改为空格。片段不参与扩展身份或宿主导航；测试扩展自行解释并执行定位，或者按自己的业务合同拒绝。扩展 ID 及路径中的非法值不能通过附带片段得到放行，原生入口的公开输入也不因此扩大。

用仓库外 SDK 消费者验证 context.deeplink.register 的输入、回调、执行上下文和释放句柄。两个扩展各自接收自己的地址，同实例重复登记失败；伪造拥有者、旧 context 或旧代回复不能取得有效入口。激活期间的登记尚不可接收，成功后才交付；失败撤销本次登记。dispose 后拒绝新交付，已有调用按原业务收尾；再次登记后，旧句柄不能撤销当前处理器。Webview 没有登记入口。

冷启动只等待已启用目标扩展的必要能力；主窗口尚未创建或其他扩展延迟激活时仍可交付 Node 处理器。未安装、停用、激活失败或激活完成后未登记时明确失败，不自动安装、启用或重新激活。未交付队列超量、超时和退出分别覆盖，已交付且耗时超过未交付预算的业务不因此中断。引导不抢占扩展链接要求的界面。

连续发送相同请求及仅查询项顺序不同的请求，宿主均按接收顺序发起交付，不按原生规则合并。前次异步下载未结束时，后续请求仍可进入处理器；各自输入和取消互不串线，同资源互斥或幂等由测试扩展的业务明确处理。取消、实例停用、宿主断连和应用重启后不重放已交付安装，已提交结果保留，旧实例迟到结果不能进入新实例。

用本地测试资源贯通“网页链接 → 扩展准备资源信息 → 确认具体操作 → 下载与安装”的实际业务。宿主不增加通用入口确认；具体业务展示资源、资源来源、版本、安装位置和覆盖影响，已有同等确认只出现一次。确认前不下载待安装资源或执行安装，取消时清理准备资源且没有安装副作用；确认后使用本次确定的资源与范围执行。链接中的值和 allowInteraction 都不能替代用户确认。只打开页面或定位内容时，不出现与该操作无关的安装确认。

记录接收、业务结束、结果反馈及临时资源清理。handler 不在下载或收尾尚未完成时返回，交付成功不被显示为安装成功；失败与用户取消分别报告。确认后的下载可以在后台继续，不依赖页面 setup 触发，也不因观察界面关闭失去实际拥有者；同一结果只反馈一次。浏览器授权仍走 loopback，不转入扩展普通链接。

Windows、macOS、Linux 的实际制品分别验证系统关联、冷启动和运行中点击链接，开发协议与正式协议不串应用。一次系统激活不会因启动参数与后续接收路径重复执行；调用协议注册 API 成功或纯函数测试通过，都不代替系统真实交付证据。覆盖范围和未实测环境沿[统一交付边界](../acceptance.md#runtime-coverage)记录。

<a id="startup"></a>

## 首屏准备与扩展生命周期

A23、A29 和 A30 验证[首屏准备](../../design/architecture.md#startup-readiness)：内置资源与及时完成的扩展资源不固定等待，所选译本、主题及必要字体共享从开始准备起最多 5 秒的阻塞预算，不按资源数量累加。部分资源失败或超时只采用对应回退，已就绪的选择保持，数据库等必要初始化仍须真实完成。每次应用进程启动重新准备，恢复或重新打开已有应用的主窗口不重开这段等待。用户原选择不被覆盖，迟到资源按届时仍保存的选择恢复实际呈现，草稿和业务状态保留，不因首屏等待结束自动停用扩展。

A21、A23 和 A29 验证[扩展生命周期等待](../../design/extensions/runtime.md#lifecycle-waits)。模块加载与激活合计超过 15 秒时，本次激活失败，enabled 保留，迟到贡献失效。停用清理另有共用的 15 秒预算，用户关闭确认不计入；超时报告剩余清理范围。

首屏第 5 秒回退、所选扩展第 8 秒完成激活时，i18n 或 appearance 按正常机制采用可用资源，文档完成所需字体加载。期间用户改变选择或开启预览时，迟到资源遵守当前决定。普通获取、导入和同步使用自己的执行预算。

<a id="hooks"></a>

## 仓库 hooks

A26 按[hooks 合同](../../design/engineering/workspace.md#hooks)验证自有本地 core.hooksPath 的设置与撤销。其他显式配置，包括空值和继承值，按冲突报告；无关本地配置、全局与系统配置，以及安装后由用户改写的值均保留。多个 worktree 共用配置时，明确安装与卸载的仓库级作用范围。不能将正确安装所需的本地修改判为验收失败。

<a id="repository-lifecycle"></a>

## 临时仓库与正式接续

A25、A26、A28 和 A33 按[仓库阶段规则](../../design/engineering/repository.md#temporary-repositories)核对项目级开发远端的 public 可见性、来源历史、目标环境和产物取得方式。后续工作包继续同一新工程历史，阶段完成不会自动新建仓库、正式发行或清理临时远端。跨仓候选通过固定提交、版本与摘要关联，不用源码 link 或另一项目的 CI 代替自身验证。

在隔离测试环境核对发行入口：临时库中的 release 标记或版本 PR 不能自动触发正式发布；正式入口还须核对实际目标仓库、公开初始化与发布配置，不能只凭仓库名称或可见性放行。已有公开包和旧公开仓库保持各自实际状态，不因新工程开发联调而被自动改成私有或删除。

正式接续前验证来源存档、完整新工程历史和保留制品可读，接续后核对初始及后续提交身份、正式远端、协作检查和实际发行绑定。历史运行记录保留原仓库、提交与制品摘要，另行验证正式环境需要的检查；新取得路径成立后才处理不再使用的临时远端。仓库切换、公开可见性、包发行与服务切换分别记录实际结果。

<a id="release-identities"></a>

## 发行身份与说明地址

A23、A25 和 A31 按[发行身份](../../design/engineering/releases.md#release-identity)核对项目 manifest、Git tag、说明 URL 和 JSON。@kisaki3/desktop 生成 desktop@0.1.0 与 `/release-notes/desktop@0.1.0.json`，@kisaki3/extension-sdk 生成 extension-sdk@0.1.0 与对应地址；npm 包保留完整作用域。两个项目去掉作用域后重名时，发行检查在发布前失败；目录移动不改变地址，根工程和内部工具没有自己的发行项。

私有桌面和官方扩展项目也保留 @kisaki3 作用域，同时设置 private: true。npm 发行清单只包含实际公开包，桌面与 .kisx 的 GitHub Release 交付分别按所属项目执行；不能由作用域推定项目需要发布到 npm。

官方扩展 @kisaki3/ext-vndb 生成 ext-vndb@0.1.0 和 `/release-notes/ext-vndb@0.1.0.json`，说明 JSON 的 project 为 ext-vndb。来源、导入器和译本项目都检查 ext- 前缀，缺失时拒绝发行；SDK、CLI 的包名和 tag 保持各自的 extension-sdk、extension-cli。扩展 ID 与资料来源键不由此前缀生成或改写。

在同仓混合放入桌面、SDK、CLI 和扩展发布，并使公共包版本号与发布时间高于桌面版本。桌面只选择 desktop 标签，排除 draft，并按偏好处理 beta／rc；乱序和分页不改变最高兼容桌面版本的判断。为桌面 URL 返回 project 为 extension-sdk、版本不匹配或正文损坏的 JSON 时，说明读取失败，已核验更新候选和准备结果保持。

静态说明覆盖实际已发行的桌面、公共包和官方扩展。各版本按[所属语言要求](../../design/engineering/releases.md#notes)提供正文，GitHub body、静态 JSON 及适用的扩展索引保留相同语言与内容；未公开版本即使源文件存在也不能部署。同版本说明更正后，tag、URL、首次发布时间和制品哈希保持，缓存复查能够取得新正文。扩展客户端仍直接消费签名索引内的说明，独立技术项目不进入 Kisaki 的 Pages 部署。

A23 和 A25 分别核对说明语言：桌面与官方扩展缺少任一必需译文时拒绝发行；技术包只提供有效 en.md 时可以通过，并生成仅含 en 的 LocalizedText。技术包补充译文后，GitHub 与静态 JSON 同时包含它；缺译按既定规则回退英语，不生成空字段。更正或明确移除可选译文保持版本、tag、制品与 URL 不变，必需英语不能移除。语言范围不从安装状态、UI 语言或当前文件数量推断。

<a id="library-backup"></a>

## 完整退出后的资料恢复

A27 和 A28 按[冷备份流程](../../design/engineering/build.md#library-backup)使用隔离资料根验证：源完全退出后复制完整目录，恢复到干净目标并实际打开；核对笔记与附件、完成历史、字体、扩展私有值及导入批次进度。缺媒体只产生路径不可用，不能清空资料。跨保护环境的凭据不可读与整库损坏分别表达；不支持结构拒绝打开，原备份和先前资料副本保持。主窗口隐藏不被当作可以复制，任务历史恢复不自动重放写入。使用说明与这条实际流程一致，不暗示存在应用内备份或导出入口。

<a id="protocol-contracts"></a>

## 帧版本、实例与开发交接

rpc 独立验证双向调用、完成与取消竞态、重复关闭，以及断开连接后清理等待。Electron 和 iframe 接入另行验证代际、回调会话和资源流；纯 Node 机制通过不能代替真实接入。

A20、A21、A23、A26 和 A31 按[协议合同](../../design/engineering/protocols.md)验证：握手前调用拒绝；wire／端点版本、API 范围与本体 buildId 分别失败；用户的扩展安装与启用意愿保持。双方相同数字的请求 ID 不串线，嵌套回调不阻塞消息泵，void 与 null 不混淆；取消晚于真实完成时不撤销已完成事实。

旧宿主 generation、旧 Webview document 和已释放端口不能对新实例提交或推送。断连释放等待与资源，已发出写入的结果未知时不重放。实际 iframe/source/origin、端口交接与方法开放表必须在真实环境验证，不能只检查自报字符串。

开发工具分别以源码 Electron 和打包应用验证真实父子 IPC、显式开发模式及隔离 profile、初始化版本、非法消息与就绪前操作。工具只交付一批采用，等待期间同扩展的新构建只更新工具侧候选；应用不维护第二份队列。采用成功而激活失败分别呈现；只有 buildsReleased 或确认全部读取进程结束后才清理构建目录。真实窗口取消关闭后，共享宿主、监听、服务器和后续构建仍可用；再次停止能正常结束。断连不能冒充退出，正常 stop 不因固定超时自动强杀。三平台及 AppImage 各记录实际运行和现行 fuses，历史字节帧试件不计入新连接验收。

<a id="date-range"></a>

## 完整年份与边界年号

A03、A04 和 A27 按[日期验证分工](../../design/domains/values.md#date-operations)覆盖完整值域。纯 date 模块集中验证七种分量组合、公历周期与极值；接入验证各自新增的条件。

正式表单选取 year = 0、无年闰日和缺月日期验证精度保留，并用最小年份对应的公元前年号验证原始文字到正式 number 的无损往返。存储与公共参数验证编码，四语显示验证本地化，查询验证同一事实在筛选、计数和定位中的一致性。各层复用纯规则，不分别重跑完整极值矩阵；真实时间点按自己的范围与时区验证。

<a id="public-consumers"></a>

## 公开包、作者入口与样式消费

全部公开包都在仓库外使用真实 tarball 检查 exports、声明文件、CSS 和运行环境。框架无关视图不能暗中依赖 Solid 或私有源码。公开包声明的兼容范围必须由实际消费者验证。

A23 验证[公共包的组织与消费](../../design/engineering/workspace.md#package-organization)：纯 Node 扩展从 SDK 获得完整作者类型与实际上下文，框架无关 Webview 使用对应接入，Solid Webview 按需增加 ui 和 Solid。三种路径都不读取应用或其他包的私有源码；纯定义入口不初始化 Node、DOM 或框架运行环境。CLI 的程序化入口与命令复用同一工作流，生成模板实际随制品提供，分发仓库维护可以只消费已经构建的安装包。

A20、A23 和 A29 验证[样式交付](../../design/engineering/workspace.md#visual-packages)与[窗口入口](../../design/engineering/layout.md#renderer-styles)：无 Tailwind 的消费者可以使用 appearance 的普通能力与 UI 的成品 CSS，选择映射的项目可以编译自己的语义工具类；两者都不读取包内源码。四个窗口分别加载自身入口和共同基础，在不加载主窗口 CSS 时仍完整呈现。组件基础规则不无条件重置消费文档，阅读正文保持自身排版；主题与字体改变通过各文档的正常接入生效，不需要重新构建样式或维护四份主题值。

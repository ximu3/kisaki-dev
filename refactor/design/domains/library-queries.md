# 资料库查询、范围与定位

资料库查询同时考虑入口的固定范围、用户检索与筛选，以及当前可见范围。纯合同定义类型、字段、运算和返回投影，library 实现数据库查询，renderer 维护当前视图与交互状态。可传递的字段标识、条件联合、区间参数、分组与选择结果见[公共值合同](library-query-contracts.md)。

<a id="query"></a>

## 查询定义与固定范围

读取接口按列表摘要、对象详情、关联选择、分部、文件和活动等实际需要组织。系统使用有限且可穷尽的字段与运算合同，不开放任意 SQL，也不为每个页面复制一套查询。主进程核对类型、ID、权限和窗口上下文，客户端类型不能代替授权。

| 部分     | 表达的含义                                                              |
| -------- | ----------------------------------------------------------------------- |
| 对象范围 | 全库、某合集、某标签等固定入口范围；Entry 类型由规则组声明              |
| 检索文字 | 用户希望查找的名称或正文线索                                            |
| 筛选条件 | Entry 规则组取并集；组内按明确类型使用全部或任一条件，结果按 Entry 去重 |
| 排序选择 | 沿用当前范围的顺序，或明确使用某个字段和方向                            |
| 读取范围 | 本次需要的起点与有上限的数量，可直接读取远处的数据范围                  |

EntryQuery 对启用的规则组取并集。每组明确类型，并按 all 或 any 计算条件，最终按 Entry 去重。scope、共同 search 和可见范围始终与结果相交，普通 OR 条件不能撤销这些限制。

没有启用组时结果为空。启用组的条件为空时，只放开该组声明的类型。损坏规则不能被解释为全库查询。动态合集先按保存规则形成范围，再与临时条件相交；查看不会修改合集定义。

组内字段必须对该组所有类型具有相同含义，字段排序则必须适用于全部启用组涉及的类型。专属条件应通过缩小组类型或另建组表达。例如，人物没有作品状态，不能把人物当作“状态未设置”的作品。

合集或标签等固定入口先核对目标是否存在、模式是否适用。目标失效应报错，真实存在但没有成员的合集才返回空结果。条件、字段含义和数值规则只定义一次；SQL 与索引位于主进程，控件和文案位于 renderer，不组合成万能 EntrySpec 或全局查询服务。

视图拥有者把公共结果传给子组件。相关提交发生后，视图合并重查需求，同时考虑可能新进入结果的对象，不能只监听已经显示的 ID。

<a id="api"></a>

## 读取方法与返回投影

EntryQuery 保存 scope、search、规则组和结果排序。类型由启用组声明，不在顶层重复保存。offset、limit 和 fields 只属于本次读取参数；更换显示列不改变结果集合，也不向 library 传递 UI 组件或私有列定义。

```ts
const query: EntryQuery = {
  scope: { type: 'collection', id: collectionId },
  search: '',
  rules: [{ enabled: true, types: ['game'], filter: { match: 'all', conditions: [] } }],
  sort: { type: 'scope' }
}

const result = await library.entries.list(query, {
  offset: 0,
  limit: 80,
  fields: displayedFields
})
```

| 方法                             | 实际读取含义                                                |
| -------------------------------- | ----------------------------------------------------------- |
| list(query, options)             | 返回有界区间的 items 及同一次读取中的完整匹配数量 total     |
| get(ref)                         | 返回条目详情；当前可见范围内没有相应记录时返回 null         |
| locate(query, target, options)   | 返回目标在当前结果中的位置、附近区间及总量；未命中返回 null |
| groups(query, grouping)          | 返回当前查询按指定方式分组后的实际分组身份、顺序和成员数量  |
| selectRefs(query, selection)     | 只读解析全选或区间选择，返回读取当时确定的条目引用集合      |
| findByExternalIdentity(identity) | 按精确外部身份查询本地条目映射                              |

这些读取方法均可独立调用。list 同时返回 items 和 total。摘要固定包含身份、类型和名称，其他内容从有限的公共字段目录选择。未请求的字段不返回；已请求且适用于该行类型但没有值时，使用该字段规定的 null 等语义；混合类型中的不适用字段不出现，见[投影目录](library-query-contracts.md#projection)。筛选或排序所用字段无须同时返回。fields 不接受任意关系展开或 SQL，其他对象的读取则由各自合同定义。

普通 Entry 列表每项对应一个 Entry，多标签或多关系命中不会产生重复项，total 也按 Entry 计算。真实关系列表则每行对应一项事实，并提供其备注、剧透和顺序。选择器只读取最低必要辨识资料，但需要完整滚动时仍返回总量。

EntryDetails 包含自身资料及适量摘要。长正文、历史、文件和完整关系按所属模块另行读取。列表、数量和选择器共用同一谓词；类型总数等不同统计必须另行命名。只读投影不能原样写回。领域内的混合检索使用专属 SearchResult，不扩大 Entry 联合；全应用搜索由独立 [search](search.md) 负责。

<a id="intervals"></a>

## 本地大列表与有界区间

资料库、应用搜索、任务历史和扫描历史等本地可完整查询的大列表，统一通过 { items, total } 读取区间。offset 和 limit 必须是合法整数，并遵守接口上限。起点无须按页长对齐，省略数量也不表示无限读取。

items 与 total 在一次短只读事务中使用相同条件和稳定排序，不另存可以推导的 hasMore，也不跨请求保持快照。分批读取限制传输量，虚拟化限制绘制量，但列表始终代表完整结果。total 决定逻辑范围，已加载数组长度只表示当前取得的数据。

客户端可以直接读取第 4200 项附近，无须先读完前面的记录。加载中的位置不能伪装为空记录。小数组可以直接读取，不要求所有列表虚拟化。外部来源的续读能力则遵守 [metadata](metadata.md) 自身合同。

区间读取必须同时限制单次响应量、在途请求和视图保留的数据。视图按视口与相邻预取范围请求数据，超过接口单次上限时分次读取；过期请求取消或忽略，离开范围的数据释放。具体批量和预取参数属于内部调优，不改变完整 total、任意区间直达和稳定定位的合同，示例 limit 不是全局页长或容量。索引、计数和排序成本都需要测量，返回记录少并不能证明远处定位高效。 [代表查询探针](../engineering/database.md#query-evidence)比较同义谓词的相关子查询与候选集合组织方式；实现可以调整 SQL 形态，但不能改变集合去重、total 或同项关系语义。通用虚拟化只处理数量、几何和测量；分组标题、网格行等映射由视图负责，见[虚拟化](../ui/virtualization.md)。

## 稳定定位、分组与选择

locate 在同一次只读事务中返回 index、offset、items 和 total。index 表示目标在当前完整结果中的零基位置，items 包含其附近的有界区间。范围、条件、排序、空值处理和 ID 补序均与 list 一致；持久目标始终通过稳定引用标识。

目标在当前范围内未命中时统一返回 null，不区分隐藏、被筛选排除或不存在，也不自动清除条件。参数或读取错误仍须报错。记录尚未加载时，应读取相应区间，不能据此删除选择、修复路径或判定身份失效。

界面滚到预计位置后，等待真实行渲染，再核对 ID 和可见位置。新的导航或查询会使旧定位失效，不能根据近似下标宣告成功。允许用户主动调整过滤的入口应始终可用，不依赖是否存在隐藏目标，也不能绕过可见性。

groups 交付当前查询的组身份、顺序和数量，组内读取继续使用原查询条件。普通 list 只返回业务记录，视图负责标题、占位及布局行。同一 Entry 在多个组中出现时，各显示实例以组身份和 EntryRef 共同标识，定位及范围选择携带组上下文。定位折叠组时先展开，再读取附近区间。Entry 总数按实体去重，虚拟行数按实际显示实例和标题计算。

来源上下文失效时，按本体当前有效归属处理；原组尚未加载不算失效。需要默认归属时，可按当前可见合集和顺序查询，不建立全库归属映射。

当前视图只保留可见及预取区间，可以释放远处数据，结束后释放全部。不维护全局镜像、TTL 或历史结果缓存。选择、焦点和返回锚点使用稳定 ID、范围或查询，以及必要的行内偏移，不依赖 DOM、旧数组或固定像素。布局、列数或数量变化后重新定位和测量。普通切换查询可以从头开始，明确返回或定位则直接读取目标附近。

selectRefs 只读解析 all，或由稳定端点及组上下文表达的 range，返回读取当时确定的引用集合。端点失效时明确失败，主进程不保存 UI 选择状态。条目按 Entry 去重，成员和关系按自身真实身份处理。选择寿命与批量提交见[固定目标集合](library-operations.md#selection)。

<a id="refresh"></a>

## 变更后的重读

相关提交会使旧区间位置和计数失效，界面应根据当前稳定锚点重新读取。等待期间可以暂留旧的可见内容，但新数量、位置和记录必须作为同一批结果采用。迟到结果按查询及读取实例核对，不能覆盖后续输入、滚动或定位。稳定排序只保证同一数据状态下的顺序，不保证跨请求快照一致。

批量修改和动态合集转手动合集由完整操作解析全部目标。规则草稿的查询结果用于编辑反馈，提交时按最终规则执行。规则修改、合并和重排由[完整操作](library-operations.md)维护一致性，失效通知在完成后触发重读。

验收须覆盖远处直接定位、滚动条快速跨区、键盘跨未加载边界、释放数据后保留选择、折叠组、重复显示实例、返回列表、网格列数变化、筛选排除和真实删除。同时验证读取期间排序变化及迟到结果，并按[固定性能场景](../../verification/acceptance.md#performance)检查请求次数、传输量、常驻数据和主进程耗时，不能只凭减少返回条数判定通过。

## 文字检索与上下文排序

七类 Entry 的文字检索覆盖显示名、原名、排序名、别名和简介，[应用搜索](search.md#query)中的 Entry 使用相同文字范围。合集、标签和 Note 分别使用自己的名称或正文范围，私人笔记不隐式加入 Entry 检索。普通文字采用片段匹配，忽略英文大小写、全半角差异及查询首尾空白，不自动转换简繁体、假名或罗马音。多个检索词必须全部命中，可以分布在允许的不同字段中。输入始终按普通文字处理，不作为正则或脚本；显示保留原值，检索比较不改写资料。

简介和笔记检索面向可读文字，不能意外匹配 Markdown 结构或内部附件地址。检索只产生候选，不修改资料，也不判断身份或触发合并。精确外部身份查询使用 source 加完整 sourceId，不使用标签名称归一化规则。

| 列表范围                 | 默认顺序                                               |
| ------------------------ | ------------------------------------------------------ |
| 普通 Entry、收藏与未分类 | 有效排序名升序；未指定排序名时使用显示名，再以 ID 稳定 |
| 手动合集成员             | 已保存的成员排列，再以成员 entry_id 稳定               |
| 动态合集结果             | 已保存的一份统一字段顺序                               |
| 标签或笔记的关联列表     | 当前这一侧已经保存的关联排列，再以相应目标 ID 稳定     |
| 全库合集                 | 合集自身的列表排列与 ID                                |
| 全库标签                 | 名称与 ID                                              |
| 全库笔记                 | 内容修改时间降序与 ID                                  |

sort 区分 scope 和明确字段及方向。scope 不带无意义的方向字段。输入搜索文字不会改变当前排序。名称采用下述固定 Unicode 自然序，切换界面语言不改变结果。数据库排序、区间读取和定位使用同一比较键，前端不再对局部结果独立排序。

有效排序名使用 sort_name，未设置时使用 name；显示名排序直接使用 name，原名排序使用 original_name，别名不任取一项参与排序。未设置值始终后置，升序和降序均如此，同值再按稳定 ID 排列。字段排序不写入人工顺序。拖拽或相对移动前应回到对应人工排序；筛选子集的重排仍核对完整范围。

空检索或空条件可以明确表示不增加限制。但已经添加的条件若无效、缺少操作数、使用未知字段或不支持的排序，应报可处理错误并保留草稿，不能静默删除或回退，从而扩大查询。

<a id="name-order"></a>

### 名称的固定 Unicode 自然序

本规则比较一个完整名称字段，不按拼音、读音或当前 locale 排列中文、日文及其他文字。排序只生成比较键，保存和显示的原文保持不变。外部身份、标签 nameKey、来源对应以及文件路径等价继续使用各自的规则；名称排序相等不表示同一个对象。

使用 Unicode 18.0.0 的规范化、默认完整大小写折叠及十进制数字数据。比较文字依次执行 NFKC、默认完整 Case Folding、再次 NFKC。Case Folding 使用 C／F 映射，不采用按语言选择的 T 映射；第二次规范化处理折叠后的组合形式。全半角及其他兼容字符按 NFKC 取得比较形式，重音不被额外删除，也不执行简繁体、假名与罗马音互转。依据见[固定版本规范化](https://www.unicode.org/reports/tr15/tr15-58.html)和[大小写数据](https://www.unicode.org/Public/18.0.0/ucd/CaseFolding.txt)。

从左到右将比较文字分成两类单元：连续的 Unicode 十进制数字 Nd 构成一个整数单元，其余每个 Unicode 标量值各为一个文字单元。数字使用所属字符的十进制值，连续的不同数字字形仍属于同一数字串；长度按规范化后的数字字符数计算，不按 UTF-16 单元数。负号、小数点和其他标点仍为文字单元，不另行解析有符号数、小数、科学计数或汉字数词。

按以下顺序得到名称的比较结果：

1. 逐单元比较。两个整数单元先移除前导零，全部为零时保留一个零，再比较有效位数和同位数的十进制数字；不转换为 number。两个文字单元按 Unicode 标量值比较。
2. 整数与文字相遇时，整数单元统一占 U+0030 的比较位置；因此空格、连字符等较小码点在数字之前，冒号、字母等较大码点在数字之后。所有 Nd 都采用这一分类，不依原始字形切换比较方法。
3. 共同单元全部相同时，先结束的名称在前。整条主比较相同后，才按出现顺序比较各数字串的宽度，较少前导零在前；不能在中途用宽度越过后续文字的主次序。
4. 名称仍相等时，使用该列表既定的稳定身份补序，不再按原始大小写或字形追加一套次序。Entry 的 ID 按 UTF-8 字节升序补序；其他列表使用各自定义的完整目标身份。

字段降序只反转名称比较，缺省值始终后置，同值身份补序仍保持原定顺序。应用搜索的相关性档次先于名称比较，Explorer 的人工 scope 顺序也保持原义。

| 输入或条件 | 确定结果 |
| --- | --- |
| 作品 10、作品 2 | 作品 2 在前 |
| 作品0002、作品02、作品2 | 作品2、作品02、作品0002 |
| 作品02a、作品2b | 作品02a 在前；后续 a／b 先于数字宽度决定主顺序 |
| 八、阿 | 八在前，按 Unicode 次序，不按拼音 |
| A2、ａ２ | 名称比较相等，使用稳定身份补序 |
| é、e 加 U+0301 | 名称比较相等，原文各自保留 |
| file9、file١٠ | file9 在前；阿拉伯数字串的值为 10 |
| a-b、a2、a:b | a-b、a2、a:b |
| 作品9007199254740992、作品9007199254740993 | 前者在前，不受浮点舍入影响 |

比较与索引键生成由同一纯实现承担。键的二进制编码、索引及缓存布局由实现决定，但字节比较必须与上述次序一致；普通 list、total 对应区间、locate、混合查询和应用搜索不得混用比较器。排序键是可重建派生数据，Unicode 数据或键编码更新时重建相关索引，不改写名称或外部身份。不得直接用系统 locale、SQLite 默认 NOCASE 或未经版本核对的运行时排序代替这份合同。Kana 的成员路径顺序继续由独立库拥有，不从本体导入排序政策。

## 缺省值、枚举与集合运算

查询反映已经记录的值，不推断现实。未评分不同于 0，未设置当前状态不同于 planned，没有完成记录不证明从未完成。没有评价行时，评分解释为未设置，收藏解释为 FALSE；必要主体缺失或读取失败不能解释为字段未设置。字段不适用于某类型时，应先由类型范围校验拒绝。

| 值类型   | 条件能力                                                 |
| -------- | -------------------------------------------------------- |
| 布尔值   | 为 TRUE 或 FALSE，按字段已定义的缺省值解释               |
| 枚举值   | 包含所选值、排除所选值；可空枚举可明确选择未设置         |
| 数值     | 包含边界的最小值、最大值或两端范围，以及已设置、未设置   |
| 日期     | 年月日范围、实际适用的月日条件，以及整体或已知分量的筛选 |
| 关联集合 | 包含任一、包含全部、排除所选目标，以及未关联、已有关联   |

数值条件使用字段自身的单位和值域。范围包含两端，两端相同即精确值，可以只有一个端点，但不能两端都空。非有限数、倒置范围或越域输入应报错，不交换端点或截断值。空条件组表示不增加限制，已添加条件的空操作数则无效。枚举和关联选择必须非空，并准确去重。

可空枚举用 null 表示未设置，不添加一个“未设置”枚举字符串。排除条件计算所选值的补集；只要未设置未被明确排除，就继续保留：

| 条件                 | active | onHold | 未设置 |
| -------------------- | ------ | ------ | ------ |
| 包含 active          | 匹配   | 不匹配 | 不匹配 |
| 排除 active          | 不匹配 | 匹配   | 匹配   |
| 排除 active 与未设置 | 不匹配 | 匹配   | 不匹配 |
| 包含 onHold 与未设置 | 不匹配 | 匹配   | 匹配   |

数值范围只比较实际数值，未评分不能当作 0。需要同时查询未设置和某个数值范围时，使用已有条件组合。角色年龄和身体属性采用 number/text 值：只有 number 参与数值比较，text 保留原文；“字段存在”则包括两种形式。数值排序先排 number，再排 text，文字部分使用稳定名称与 ID 顺序，完全未设置最后。不能从“17—18 岁”中截取数字。

关联集合的“包含任一”表示交集非空，“包含全部”要求所有所选目标都存在，但允许其他目标，“排除”要求所选目标均不存在。“未关联”和“已关联”判断该字段定义的集合是否为空。空选择不能借“包含全部空集”命中全库。引用目标失效时保留明确失效状态，不能删除条件后执行更宽查询。

每个字段先明确自己的比较集合。例如，“没有手动合集”不同于同时考虑动态匹配的“未分类”。关系集合使用当前可见事实；集合为空只表示该范围内没有相应记录，不证明现实没有，也不证明数据库中绝无记录。

<a id="dates"></a>

## 部分日期、时间点与精度

绝对日期范围的边界可以是年、年月或完整日期。查询将起点展开为该期间开头，将终点展开为该期间最后一天，只用于比较，不回写资料。记录必须包含年份，且已知精度足以确定全部可能日期都在范围内，才算匹配。没有年份的日期不参与绝对年代比较。

| 已保存日期 | 查询 2024 年 | 查询 2024 年 5 月 | 查询 2024 年 5 月 3 日 |
| ---------- | ------------ | ----------------- | ---------------------- |
| 2024       | 匹配         | 不匹配            | 不匹配                 |
| 2024-05    | 匹配         | 匹配              | 不匹配                 |
| 2024-05-03 | 匹配         | 匹配              | 匹配                   |
| 仅 05-03   | 不匹配       | 不匹配            | 不匹配                 |

例如，2024-05 可以确定属于整个五月，却不能确定属于五月三日至十日。未知月日不补成 1。生日等适用字段另有忽略年份的月日范围：只知道五月的记录可匹配整个五月，不能匹配五月三日；05-03 无须补年份。月日范围允许跨年，如 12-20 至 01-10，绝对日期范围倒置则非法。

年、月、日分量分别按数值或未设置语义查询，不重复存储列。整体未设置只表示没有日期，合法部分日期仍属于已填写。日历组合统一校验，无年份的 02-29 合法，02-30 非法。

年代排序依次比较年、月、日。相同上级值下，未知分量排在已知分量之后，升序和降序都保持该规则。没有年份的日期排在有年份之后，完全空值最后，再按 ID 补序。升序可能为 2024-05-03、2024-05、2024、2025，这不表示未知日期在现实中更晚。生日月日排序忽略年份，必须与年代排序分别命名。

created_at 和 updated_at 存储 UTC 毫秒。按日历筛选时，以当前显示时区展开为 [开始日零点, 结束日次日零点)，不能假设每日固定时长。同次列表、数量、定位和预览使用同一解析时区。时区改变后重新查询，不修改已存 UTC 值。保存的日历条件按当前显示时区解释，不根据合集名称猜测滚动规则。发行日和生日是日历事实，不因时区换日。

数据库验收需使用真实查询，覆盖无评价行、0 与 null、枚举排除、空集合和重复操作数、number/text、各级日期精度、跨年月日范围及日界限，并核对 list、total 和 locate 一致。只测纯函数不足以验证这些合同。

## 完成记录查询与统计

当前状态和完成情况是独立条件，可以组合。active 与“有完成记录”同时匹配正在重玩、重看或重读的作品；“已完成”范围表示存在完成记录，不排除当前进行中的作品。当前状态查询不接受 completed 作为枚举值，“无完成记录”也不等于未开始或从未完成。

完成日期条件查询实际记录，不只比较作品的最早或最近日期。查询“2024 年完成过”的作品时，只要存在一条完成日期位于该年的记录就匹配；最早或最近一次在其他年份不影响该事实。日期为空的记录不匹配年、月、日范围。“有日期未记录的完成”要求确实存在这样的记录，没有任何历史的作品不因空摘要而命中。

完成日期只保存完整 CalendarDate 或 null。年、月条件可以展开为完整日历范围，用于查询，不回写日期。日期与备注等同一条完成记录上的条件，必须由同一条记录满足，不能拿一次的日期和另一次的备注拼成匹配。按完成事实筛选作品时仍按 Work 身份去重。

完成记录列表默认按已知完成日期降序，日期未知的记录在后，同日或未知记录按 created_at 降序、id 升序补足稳定顺序。创建时间只决定同组显示次序，不作为完成日期，不生成“第一次”“第二次”等固定业务序号。日期修改后记录可以换位，编辑和删除仍使用原 ID。

完成统计对明确 Work 范围和完成记录日期条件计算：

| 指标                   | 计算规则                                                                     |
| ---------------------- | ---------------------------------------------------------------------------- |
| 完成次数               | 命中条件的完成记录数；同一记录因关系连接重复出现时只计一次                   |
| 完成作品数             | 命中记录所属 Work 的去重数量                                                 |
| 累计完成次数           | 不限定完成日期时计入所有记录，包含日期未知的记录                             |
| 日期未知的完成次数     | 同一 Work 范围内日期为 null 的记录数，单独说明，不分配到日历期间             |
| 最早、最近已知完成日期 | 对非空 CalendarDate 分别取最小值与最大值，不保证覆盖用户一生的首次或最近经历 |

同一作品在一年内完成两次，该年为两次完成、一部作品。日期未知的记录计入不限定日期的总量，但不进入年度、月度图表或期间排名。补录日期、更正日期或删除记录后，统计按实际保存的完成事实重新计算，不以导入或修改时间固定旧归属。

分部按集、附加内容、卷、话的真实范围统计当前已标记数量和已登记数量。作品状态分布统计当前值，完成历史和活动分别按自己的时间事实统计。状态、完成历史和活动是独立维度，查询结果保留它们的区别。

作品完成、实际活动和四类作品附加时长各自统计。手动记录完成可以没有任何当日活动；真实使用可以没有作品完成记录。详情、库查询、动态合集、展示柜、统计页和 SDK 使用同一组只读定义，不各自维护计数或日期镜像。

<a id="activity-statistics"></a>

## 活动统计的时间与计数

library.activities 按同一活动集合提供统计。有效时长采用记录中的 durationMs，不用起止差值替代。各活动分别计入所属作品，重叠区间直接相加；总计与同一范围内的作品明细相加一致，不按时间并集去重。筛选或关系连接不能让同一活动在同一统计范围内重复计入。

时间范围采用 [from, to)，包含起点、不包含终点。活动与查询范围有实际交集时参与统计；分日、周、月、年和小时段共用当前显示时区，与普通日期查询使用同一规则。日界按真实日历取得，不能假设每天固定为 24 小时。时区变化只改变统计分组，不改写已存时间。

一条活动分配到某个时间范围或分组的时长为 durationMs × 重叠区间长度 ÷ (endedAt − startedAt)。查询范围与分组边界共同限定交集，起止相接但没有重叠时不计入。按原始精度计算与汇总，只在显示时格式化；分组是读取投影，不拆分或改写原活动，也不声称知道区间内部更细的使用分布。

例如，23:30–次日 00:30 的活动，有效时长 60 分钟时两天各分配 30 分钟；有效时长为 30 分钟时，两天各分配 15 分钟。同时发生的两部作品各有一小时活动，总计为两小时。

次数统一表示“活动记录数”。每条活动在同一统计范围只计一次，跨媒介按活动类型与 ID 区分。跨日活动在各日分别参与当天统计，但整段范围的记录数仍为一条；总记录数从当前范围的活动集合计算，不累加日期分组的计数。记录数不表示应用启动次数、运行会话数或作品完成次数。

平均与最长活动时长使用本次统计范围内各活动实际计入的有效时长。活跃日期与连续天数依据相应日期是否具有正的有效时长，不取记录创建或编辑时间。没有日期的附加时长只进入不限定发生日期的累计时长，不参加日期图表、期间排名、活动记录数或单条活动的平均与最长统计。

附加时长只归属 Work。统计限定某个文件、分部或其他活动上下文时，不分摊作品附加值，也不将它重复计入各文件或分部小计。

## 活动与持有汇总

| 查询内容       | 含义                                                   |
| -------------- | ------------------------------------------------------ |
| 累计使用时长   | 四类作品已记录有效活动的汇总，加上各自已确认的附加时长 |
| 最近使用       | 最近一次实际使用事实，不取资料修改时间                 |
| 已登记分部数   | 按卷、话、分集等真实类别分别统计                       |
| 已完成分部数   | 相应分部的当前完成标记数量                             |
| 已登记文件数   | 文件记录数量，同一文件关联多个分部只计一次             |
| 有文件的分部数 | 存在文件关联的分部数量                                 |
| 文件可访问情况 | 最近核对所得的状态，保留未检查与已知不可访问的区别     |

资料声明数量、实际登记数量、已完成数量、有文件数量和最近可访问数量分别命名。例如，资料声明十二集、八集有文件关联、七集最近可访问，是三个不同的值。同一文件关联多个分部时，文件数仍只计一次。

普通列表的显示、筛选、排序和数量，只使用本次读取时已经保存的观察与事实，不因查询条件遍历磁盘、探测文件或启动程序。已经登记文件或配置，不保证现在可以打开；未检查与已知不可访问必须保留区别。

实时计时器可以另外显示有效增量，普通列表允许晚一个持久化周期，不在前端临时累加时长来改变筛选。totalDurationMs、lastActiveAt 等派生汇总不复制为独立可修改的资料列。

[活动补录、修正与删除](library-operations.md#activities)使用相同汇总。最近使用按活动的发生时间计算，不取补录或编辑的提交时间；删除后从剩余活动取得结果。文件或配置的继续目标仍须来自具有相应上下文的活动，只有作品与时间的补录不制造继续目标，也不改变已有文件位置。

关系条件中的目标、职责、作品、角色及适用分类必须在同项事实中成立。“甲参与配音”不能由“甲参与编剧”和“乙参与配音”拼成。“甲为 C 配音，且 C 是主角”要求同一条工作关系，并核对 C 在同一作品中的角色分类。

一个条件内选择多个职责表示任一职责。要求甲同时编剧和配音时，使用两个条件并以 all 组合，可以由两条真实工作记录分别满足。不提供任意关系路径语言。

work_person_links 中有角色和无角色的记录，共同参与人员汇总。详情仍保留每项工作 ID、职责、角色和说明。具体角色条件必须由 character_id 对应，无角色工作不表示负责该作品全部角色。作品始终明确，角色范围可以限制为无角色、有角色或指定角色；角色的关联人物及人物的角色工作只读取有角色事实。

作品的人员作者查询 creator，组织作者查询组织 creator，角色创作者查询 characterCreator，三者不能互相补足。同一人物在不同作品中的工作分别成立，不根据说明里的名称生成引用。角色 role 为 NULL 表示已经关联但尚未分级，不等于无关联或没有主角。人物或组织的 other 表示存在尚未细分的参与，也不同于没有关系。

关系说明可以作为同项事实的文字或存在性条件，不隐式加入 Entry 检索或 Note，也不能从“日语”“幼年”等说明推导未定义的配音语言或阶段字段。目标名称只用于帮助用户选择稳定 ID。

<a id="relation-sets"></a>

## 关系集合、方向与数量

查询先按当前可见性、职责、作品、方向及其他限制选取事实，再投影为目标 ID 集合，执行任一、全部、排除和有无运算。要求甲乙都参与配音时，各自有符合条件的工作即可，角色可以不同。若要求各自对应指定角色，应拆为明确条件，不能猜测两个列表的配对关系，也不生成笛卡尔积。

“没有配音人物”检查所定义集合是否为空；“排除甲”则仍允许其他人物。一个声优配多个角色，人数仍为 1。同一人物以多个职责参与同一作品，或同一对作品存在多条关系时，对象集合均去重。详情保留事实条数与 ID，不能用对象数量冒充关系数量。

作品关系读取时，查询当前作品作为任一端点的记录，并将类型解释为从当前作品看对方的含义。两端共享同一关系 id 和说明，各自使用对应的人工顺序，不合并两份镜像陈述。同一对作品存在不同类型的关系时，事实分别保留，目标集合仍按作品身份去重。

例如，“有小说原作的动画”必须由同一关系同时满足目标是小说、关系是 sourceMaterial。漫画原作关系和小说普通关联不能拼出这一条件。小说侧对应查询动画 adaptation。跨类型只是一项端点条件，不创建 crossMedia 记录。人物和组织也只查询真实参与，不通过共同背景传递署名。

<a id="visibility"></a>

## 可见事实与完整维护范围

普通列表、反向名单、选择器、动态合集、分组、计数和定位，共用可见事实及同项匹配规则。数据库通过存在性判断和目标去重完成查询，不先生成重复 Entry 再交前端去重，也不加载整张资料图。

剧透范围排除了某条角色关联或具体工作时，该事实不参与对应筛选、人员汇总或计数。同一人物若有其他可见工作，仍可出现，不能因此隐藏整个人物，也不能新增普通参与镜像绕过限制。正向与负向条件都在同一可见集合中正常计算，不能因为条件提到隐藏目标就一律返回空。

合法保存条件不会因目标隐藏而失效或被删除。系统不提供特殊隐藏错误、原因或专属条件按钮。未匹配统一反馈“当前可见范围内，没有相应记录。”，不泄露隐藏名称、数量、类别或状态。真实参数错误、读取失败和引用失效仍须明确报告。

主动显示剧透是始终可用的普通范围选择，其寿命见[查看范围](preferences.md#visibility)，入口不取决于实际是否存在隐藏项。动态合集按当前可见范围计算结果，不修改保存规则。

普通隐藏也不能缩小明确关系编辑、合并和移除的完整指定范围，或让依赖记录逃过处理。用户可以在普通查看和编辑中主动显示剧透；维护操作仍按完整范围核对，必要确认不披露隐藏内容，也不另设影响预览。查看不改变人工顺序或已保存事实。

验收需覆盖同项绑定、多职责、多角色、有无角色合并查询、作品作者与角色创作、分类、去重及反向关系。可见性场景还包括隐藏目标的正负条件、真实空集合、其他可见事实、动态范围切换，以及定位时的一致反馈。

## 实例、输出与帧寿命

createMpv(options) 异步建立可用的 Mpv，内容随后通过 loadfile 命令加载，由消费方判断自己的完整打开条件。初始化失败时清理已经取得的库内资源，不交付半初始化实例。同一 Mpv 可以加载和替换内容；播放到末尾属于内容状态，不自动关闭实例。mpv.close() 永久结束该实例，关闭后的对象不能再次加载内容。

| 对象         | 资源归属与寿命                                                       |
| ------------ | -------------------------------------------------------------------- |
| Mpv          | 拥有 libmpv 核心、控制与事件处理，以及适用的视频输出工作             |
| VideoOutput  | 由 Mpv 持有，负责图形上下文、渲染调度和产帧，关闭时停止新的帧交付    |
| NativeFrame  | 每次交付后由接收方持有，保持画面有效所需资源，release 后归还本次持有 |
| 截图命令结果 | 拥有已经取得的独立图像数据，不继续借用播放器缓冲或依赖 GPU 帧存活    |

受管视频输出是同一包内的可选技术能力。创建时明确是否启用；启用时，库先准备图形环境与渲染上下文，再由调用方加载带视频的内容。纯音频和不使用图形输出的调用不必创建图形上下文。按照 [libmpv Render API](https://github.com/mpv-player/mpv/blob/master/include/mpv/render.h)，每个播放核心最多有一个活动渲染上下文，并在播放前完成建立、在播放核心销毁前完成释放。

Windows 已采用官方合入的直接 D3D11 Render API，macOS 与 Linux 保留各自的 OpenGL 接入，软件输出仍为独立选择；固定上游来源与终态合同见[视频输出设计](video.md)。

受管 GPU 输出固定不透明，透明片源沿用上游处理；Kisaki 使用 sRGB SDR，HDR 片源由 libmpv 映射到 SDR；库另保留 Display P3 SDR，HDR 显示与显式亮度单位不纳入受管输出。

共享 GPU 纹理由本库在其上完成平台互操作，并非上游直接交付的统一纹理结果。图形上下文、原生渲染调度、输出尺寸、平台同步及资源寿命由本库负责，调用方不调度原生渲染线程。JavaScript 帧接收速度不直接驱动播放时钟；帧交付机制必须满足渲染更新、呈现时序和有界资源约束。六个平台目标分别验证实际渲染到共享纹理、SDR 宿主显示和引用回收的完整路径。

已交付 NativeFrame 具有独立于 Mpv 的资源持有权。mpv.close() 停止新调用与新帧交付，结束自身的播放、控制和渲染工作，清理尚未交付的帧与库内临时资源；已经交付的帧不参与等待调用方归还的关闭条件。帧通过自己的持有关系保留纹理、同步对象及保持画面有效所需的图形资源，可以在 Mpv 关闭后继续使用，直到持有者调用 release。不能仅交付指向播放器临时缓冲的地址，也不能通过保留完整 Mpv 来阻止其关闭。

停止帧订阅只停止新交付，已经交付的帧仍由持有者释放，不因回调返回或订阅停止而自动失效。帧队列与资源池保持有界，可以丢弃尚未交付的画面；已交付纹理在持有期间不能被覆盖、复用或强行释放。尺寸变化、内容切换和 Mpv 关闭都不撤销已经成立的帧持有关系。

## 创建入口与配置归属

```ts
const mpv = await createMpv({
  options: [
    ['pause', true],
    ['volume', 80],
    ['hwdec', 'auto']
  ],
  videoOutput: { width: 1280, height: 720 },
  signal
})
```

采用以下配置：

| 字段               | 含义与缺省行为                                              |
| ------------------ | ----------------------------------------------------------- |
| options            | 按顺序应用的原生选项二元组列表；缺省为空                    |
| input              | 这些选项值的表示，javascript 或 native；缺省 javascript     |
| videoOutput        | 显式传入 GPU 或软件输出配置时建立库拥有的输出；缺省不建立   |
| initializationLogs | 可选的初始化阶段日志接收器、level 与 output；缺省不公开日志 |
| signal             | 控制此次创建，成功交付后不再控制 Mpv 的寿命                 |

createMpv() 本身有效，使用 libmpv 的嵌入默认配置。当前基线包括 config=no、terminal=no、idle=yes 等；绑定不自动加载 Kisaki 偏好，也不另外改写音量、暂停、硬件解码或网络偏好。调用方可以通过 options 显式使用上游能力，受管渲染确有资源约束的部分须单独列明。

未配置 VideoOutput 时，库省略自身受管图形输出，视频解码与 mpv 原生输出仍按原生选项执行。纯音频调用可以显式设置 vid=no，其他输出选择也由对应原生选项表达。

受管模式要求对应输出准备成功才交付 Mpv；创建失败不能静默降为另一种输出方式。配置、返回类型、帧结构和 GPU 不透明播放边界由[视频输出](video.md#configuration)定义，声明复用这些类型。renderer 选择 GPU 或软件能力，Windows 直接 D3D11 与其他平台的 OpenGL 接入保持内部实现；sRGB 与 Display P3 SDR 的实际颜色、HDR 片源到 SDR 的映射及六个平台目标的完整链路仍须验证。

## 原生选项与设置顺序

options 中每项为 readonly [name, value]。名称不带命令行的 -- 前缀，使用上游名称；可以是普通字符串或独立 Uint8Array 名称字节。input 只改变每项 value 的解释，不改变名称或列表的结构。

```ts
await createMpv({
  input: 'native',
  options: [
    ['pause', { format: 'flag', value: true }],
    ['volume', { format: 'double', value: 80 }]
  ]
})
```

默认值沿用 MpvValue 的校验与复制；native 值沿用 MpvNode 的八种格式。初始化没有另一套自动识别 format 字段的规则。名称、值、字节和列表在提交原生工作前形成库持有的有效输入，后续修改调用方对象不改变创建操作。

使用有序列表，因为它明确表达设置次序，并允许同名选项重复出现。重复项依次调用上游设置，不去重、不合并，也不笼统规定为最后一项覆盖；profile 或列表类选项的具体效果仍由 mpv 决定。代价是常见的简单配置会比对象写法稍长，但不需要为顺序或重复设置增加第二种入口。

绑定先校验全部输入形状，再由该实例的原生拥有者顺序设置。首个原生设置失败即停止后续设置，清理此次实例并拒绝创建；成功时才交付完整配置的 Mpv。其他实例按自己的生命周期执行。

初始化选项使用 mpv_set_option 的选项语义及原始错误码。虽然上游称该函数为 semi-deprecated，未初始化的 mpv_set_property 当前也转发至它，并会将选项错误重分类为属性错误；这里不为统一函数名称而丢掉选项失败的含义。运行期仍通过已确认的属性与命令入口操作。

已知选项提供对应类型提示，未知名称保留通用值入口；不能让宽泛重载吞掉已知名称的类型错误。普通已知值也按声明做运行时校验，native 表示则由对应原生格式和上游选项合同检查。完整目录仍须与最终上游构建核对，局部声明样例只覆盖用于检查推断规则的少量名称。

options 明确应用在 mpv_initialize 之前。调用方启用 config、profile 或脚本后，后续配置文件和脚本效果遵守上游规则，绑定不承诺这些显式选项永远拥有最高优先级，也不把配置文件重新解释成自己的设置语言。创建成功只证明本次调用完成约定的初始化，不证明配置文件的每一行都被上游接受。

## 初始化与可用条件

工厂拥有创建期间的全部原生资源。Promise 成功交付前，必须完成输入与选项设置、核心初始化、所选受管输出的准备、内部事件与关闭处理登记，以及初始化日志和早期日志缓冲的收尾。

工厂完成初始化后直接交付可用实例，调用方通常在成功后调用 loadfile。工厂自身不加载媒体，创建成功只表示实例就绪，具体媒体和画面的就绪由其各自流程确认。

调用方显式配置的脚本可能在初始化期间运行命令，甚至加载内容或退出。绑定不能因此假定初始化结束时播放器一定空闲。若已确认引擎在交付前进入关闭，结束清理并拒绝创建；不能交付一个已经知道不可用的实例。交付后发生关闭则按已有 Mpv 寿命规则处理，不承诺实例不会立即受到脚本等后续动作影响。

若启用受管渲染，在 mpv_initialize 前准备图形设备与 Render API 上下文，使显式脚本提前加载时已有可用输出。各平台的实际后端验证这一顺序及跨入口设置约束，相关机制依据见[图形初始化验证](../../../verification/evidence/libmpv-gpu/verification.md)。

## 初始化日志

提供可选 initializationLogs：

```ts
const mpv = await createMpv({
  options: [
    ['config', true],
    ['config-dir', configDirectory]
  ],
  initializationLogs: {
    level: 'warn',
    observer: {
      next: receiveInitializationDiagnostic,
      error: receiveDiagnosticFailure,
      complete: finishInitializationDiagnostics
    }
  },
  signal
})
```

它复用已确认的 MpvObserver、日志消息、缺口、level 和 output 选择。level 缺省 info，output 缺省 javascript；日志输出方式独立于原生选项的 input。缺省不捕获为公共诊断，也不默认写控制台。

接收阶段从原生日志请求建立后开始，在创建交付或失败前结束。绑定尽早在自己的未初始化控制句柄登记日志请求，以覆盖随后设置选项和初始化的诊断；这些是工厂拥有的内部资源，运行期 observeLogs 仍使用独立弱客户端。无法捕获 mpv_create 之前或原生请求登记之前的内容，也不保证原生初始化阻塞期间能够实时交付。

这与运行期创建独立订阅有一个明确区别：初始化日志回调可以在 createMpv 的 Promise 完成前执行，因为它用于观察此次创建过程。首次回调仍安排在后续调度轮次，工厂不在调用栈内直接调用用户接收器。它不返回另一个订阅句柄，寿命由本次创建拥有。登记接收之前就失败时，只拒绝创建 Promise，不调用尚未开始的接收器。

正常结束接收阶段时，交付已经接纳的有界诊断与待报告缺口，然后 complete；随后工厂才完成 Promise。即使引擎初始化失败，日志阶段本身仍可以正常 complete，实际创建错误由 Promise 拒绝表达。complete 只表示这段日志接收结束，不表示创建成功。

日志流自身不能继续时，交付一次 observer.error 并结束这段接收；它不自动将本来可成功的创建改成失败。文本转换保留原始日志快照。MpvNotificationConversionError.operation 为 createMpv 时，表示失败发生在初始化日志中；getNativeNotification 遵守通知快照类型与独立持有规则。

同步回调抛错、异步上下文、void 返回值和异步任务归属沿用订阅规则；库不等待接收器启动的 Promise。工厂结束后不再开始初始化日志回调。signal 取消主动停止此次创建，也立即抑制尚未开始的初始化日志与终止回调，继续完成原生清理。

运行期日志需要成功后显式 observeLogs，不把初始化日志重放给它，也不承诺两次不同接收之间没有空档。若调用方需要从初始化到运行期的连续诊断，这是另一项寿命合同，不能把有限的 initializationLogs 偷换成持续订阅。

上游早期 terminal-default 缓冲仍由初始化流程取得并释放。已经登记的初始化日志请求负责自己的诊断流，不把早期缓冲再次合入而造成重复；没有初始化接收器时也不能把这段历史留给第一个运行期订阅。

## 创建取消与失败清理

signal 只覆盖此次创建。开始前已经取消时，不申请原生实例；创建中取消时，不再开始后续阶段，已有资源由工厂收尾。取消在成功交付后发生，不关闭已经交给调用方的 Mpv；调用方使用 close 管理其寿命。

创建失败或取消的 Promise 在其拥有的资源清理结束后才拒绝。这里没有可交给调用方继续释放的半成品，因此不能只结束等待而留下无法等待完成的隐藏实例。正在执行的原生调用不一定可以中断；取消不等于强制打断，也不提供可保证的完成期限。不能为响应 signal 而与未初始化句柄并发调用不受支持的 API。

失败清理按实际取得的资源进行：停止登记和新交付、释放受管渲染资源、结束辅助客户端，再终止和销毁主客户端。若在交付前取消，尚未交付的画面与临时资源也由工厂回收。绑定不得因没有成功返回 Mpv 而跳过清理。

成功装载的原生代码归[进程运行库](#runtime-lifetime)拥有，不属于此次创建失败后应卸载的实例资源。取消一次创建不会取消其他实例的创建，也不卸载其可能正在使用的运行库；本次未交付的核心、输出与回调仍须全部收尾。

错误应保留发生阶段；逐项设置失败时保留对应的零基 optionIndex，原生错误仍携带实际数值码与名称。错误消息不嵌入选项值、日志正文、媒体地址或配置文件内容。具体错误类和阶段字段见[控制接口与运行时](api.md#errors)，原生错误传递仍须实际验证。

工厂结束确认其持有的资源已经清理。显式配置或脚本产生的外部效果按实际执行结果判断。

## 进程运行库、实例与环境

同一进程使用一套固定版本的 libmpv 及媒体运行库，成功装载的代码映射保留至进程结束。运行库版本更新随下一次进程启动生效。各实例共享装载代码与只读构建信息，分别拥有播放器状态、JavaScript 对象和环境清理责任。

| 拥有者            | 资源与收尾边界                                             |
| ----------------- | ---------------------------------------------------------- |
| 进程              | 固定原生运行库的代码映射与只读构建信息                     |
| Mpv 实例          | 播放核心、辅助客户端、请求与订阅、渲染上下文和自身输出资源 |
| Node 环境／Worker | 本环境的 JavaScript 对象、Promise、回调及退出清理          |
| 已交付帧          | 独立图像资源的持有关系，按既有 release 合同回收            |

关闭一个 Mpv 不影响其他健康实例；终止一个 Worker 时只收尾其所属工作，不卸载其他环境仍在使用的运行库。实例的解码器、线程和输出自身资源仍须按 close 合同实际回收，已有帧继续按自己的持有关系释放。代码映射驻留本身不承担 Node 事件循环的保活，ref／unref 仍只按下述实例与有限操作的规则处理。

文件加载失败、输出失败和环境退出各自在已确认的责任边界结束与清理。沿用主进程直接接入的路线，进程级原生故障仍可能影响整个宿主，不能承诺将任意原生终止转换成某一个 Promise 的失败。宿主的暂停与恢复策略见[显示变化与故障](../../engineering/integrations.md#host-lifecycle)。

正式依赖的验证覆盖多实例并行、反复创建关闭、Worker 退出、其他实例继续工作，以及已交付帧的独立使用和回收。进程运行库与实例寿命的机制依据见[运行时验证](../../../verification/evidence/libmpv-runtime/runtime.md)，实际进度见[实施状态](../../../implementation/status.md)。

<a id="node-lifetime"></a>

## Node 保持、显式释放与环境退出

活动 Mpv 默认保持所属 Node 环境存活，提供与 Node 资源习惯一致的 ref()、unref()、hasRef()。ref／unref 同步、幂等并返回自身；关闭后不重新激活资源，hasRef 为 false。unref 不关闭播放器、取消调用或停止订阅，只撤销实例本身的保持作用。

已接纳的有限公开操作在完成前持有自己的运行引用，包括创建、调用和清理。因此 unref 不表示所有进行中的工作都会被放弃，也不证明进程可以退出；其他 Node 或 Electron 资源仍有自己的引用。客户端和内部通知通道不另设公开 ref 开关；它们通过所属 Mpv 协调，不能由一个遗留的线程安全回调引用意外覆盖 unref。

Mpv、MpvClient 和 MpvSubscription 分别通过 Symbol.asyncDispose 接入已有的 close 或 dispose。MpvNode、普通通知和独立截图字节是普通数据；帧使用自己的 release 合同。

显式释放是可以等待的资源边界，GC 只作兜底。Node 环境清理使用 Node-API 的异步清理机制，停止 JavaScript 交付、解除未继续的 hook、销毁辅助客户端和渲染资源，再结束核心与原生工作；不依赖已经不可执行的 JavaScript 回调或调用方 Promise。每个 Node 环境分别拥有自己的资源，不能在环境之间共享裸句柄或线程安全函数。

真实 addon 验证覆盖原生线程、队列容量、Node-API／napi-rs 交付、控制接口、hook、运行引用、渲染及环境退出。流工作与迟到资源的机制依据见[Node 桥接验证](../../../verification/evidence/libmpv-node-bridge/verification.md)。

## 输入、执行与结果的归属

| 执行范围   | 拥有的内容                                             | 结束条件                                |
| ---------- | ------------------------------------------------------ | --------------------------------------- |
| 进程运行库 | 固定版本代码映射、ABI 与只读构建身份                   | 进程退出；不随一个 Mpv 或 Node 环境卸载 |
| 播放核心   | 主客户端、初始化、核心关闭、实际播放器状态             | 该 Mpv 的关闭完成                       |
| 原生客户端 | 本客户端的请求关联、事件读取与登记                     | 所属客户端停止，或核心关闭              |
| Node 环境  | JavaScript 对象、Promise、接收器、异步上下文与交付入口 | 对应登记停止或该环境退出                |
| 已交付结果 | 普通值的独立数据；NativeFrame 的独立资源持有           | 普通值由语言管理；帧由持有者 release    |

Rust core 拥有原生工作，binding 拥有 Node 交付。两者共享同一操作的状态与结果，不分别保存播放器当前位置或复制一套关闭流程。core 不持有 napi_env 和 JavaScript 引用；binding 不直接越过原生客户端的事件读取与关闭次序。

客户端是同一核心的控制入口，具有自己的原生事件队列与请求关联；它不创建另一套播放状态。日志订阅继续按已确认规则拥有各自的弱客户端，普通事件订阅可在控制客户端上分发。弱客户端的清理在主客户端终止销毁之前完成。

<a id="execution"></a>

## 客户端调用次序

一次调用依次完成输入校验和独立复制、资源接纳、原生提交、回复接纳与复制、Node 结果交付。命令、属性、初始化选项以及原生／普通两种值表示共用这些阶段，转换规则仍由所属合同定义。

submitted 在进入对应原生调用时确定。原生立即返回错误仍表示已经进入该入口；排队期间取消则没有提交。提交后的取消只结束调用方等待并请求适用的原生中止，绑定继续消费迟到回复并释放关联，不重放操作来取得另一种结果表示。

请求编号只在所属客户端及尚未结束的原生关联中解释。它与 playlist entry id、hook id、实例身份分开，不能仅按一个数值把另一个客户端的回复交给当前 Promise。公开结果只完成一次，资源接纳占用在原生关联及所需结果持有结束后归还。

每个原生客户端只有一个事件读取拥有者。原生唤醒只通知该拥有者继续工作，不在回调中执行 JavaScript；事件循环在下一次 mpv_wait_event 之前复制仍需使用的 C 数据。请求回复、关闭、hook、属性、普通事件与日志分别路由，不能让公开事件筛选关掉内部收尾。

绑定通过所属环境的 Node-API 交付入口安排 JavaScript 执行，并恢复登记时的异步上下文。原生事件读取不等待普通接收器返回的 Promise。已确认需要参与操作的 hook 和流提供器，才按各自合同接续异步工作；不能把所有回调都当成同一种通知。

<a id="queues"></a>

## 接纳预算与结果持有

预算同时覆盖条目与持有字节，接纳量由实际拥有者核算，不能只限制一个队列长度。输入复制、原生关联、待交付快照、诊断和帧分别占用；同一份共享只读数据按真实持有关系处理，不为计数再复制内容。

| 类别             | 达到上限时的处理                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| 新调用及其输入   | 尚未提交时以 resourceLimit 拒绝，不进入无界等待队列                                               |
| 已提交请求的回复 | 必须继续消费和释放；结果不能在预算内安全持有时，结束该次调用并保留 submitted=true，不丢掉原生关联 |
| 属性通知         | 保留首次待交付状态，随后合并为最新状态；不把允许合并当作审计历史                                  |
| 普通引擎事件     | 连续性无法维持时按既有规则结束受影响订阅，不伪造遗漏事件                                          |
| 诊断日志         | 丢弃允许舍弃的未交付记录，并在独立有界状态中聚合缺口；先交付缺口再继续普通消息                    |
| 视频帧           | 只丢弃未交付帧；已交付资源保持到 release，不覆盖旧帧或阻塞音频时钟                                |

错误、终止与原生清理不依赖普通数据队列再腾出一个位置。它们由操作／订阅的终止状态表达，避免队列已满时无法结束自己。普通交付采用有限批次，让 Node 事件循环继续处理取消和其他工作；不建立跨所有 Mpv 的业务串行队列。

结果预算不足与值转换失败不同。前者不能声称已保存完整原生快照；只有确实复制成功的内容才可由既有转换错误的提取方法返回。大截图和字节结果按真实长度计算，不能截断、降采样或重执行命令来伪装原结果。

接纳、丢弃和结束遵守上述合同。具体容量与批次由真实 addon 的测量确定，形成内部基准并按既定性能要求验收。语言级调度、原生事件与 Node 流桥接的已有证据分别支持其覆盖范围。

<a id="closing"></a>

## 关闭次序

正常关闭、创建失败、调用方主动停止和 Node 环境退出使用同一套资源拥有关系，按各自已确认的回调语义结束：

1. 标记对应范围不再接纳，结束未提交工作；已提交操作按其真实状态完成取消或失败，仍消费必要的原生回复。
2. 解除仍由库承担的 hook 等待，按[流提供器的交付前后规则](streams.md#cancellation)结束读取与资源收尾。正常 close 不以环境强制退出规则跳过已接管的用户资源。
3. 停止输出生产与新的帧交付，结束本实例的渲染上下文；已交付帧仍持有自己的设备和图像资源。
4. 结束登记并销毁辅助客户端，再完成主客户端与核心的终止销毁；已经无效的 C 句柄不再参与事件读取。
5. 交付仍适用的完成结果，释放对应 Node 引用与原生占用。环境已经退出时只执行可独立完成的原生清理，不再回到 JavaScript。

主动 dispose 的立即抑制、生产者正常结束的终止交付、接收器异常和流清理的聚合失败继续遵守既有合同。释放某项失败时仍结束其他已取得资源，不以一次异常跳过剩余收尾。

ref／unref 只控制所属实例的 Node 保活。有限调用、清理与已接纳工作有自己的运行引用；共享代码常驻和内部线程安全交付入口不得额外制造一个无法取消的保活。原生进程级故障仍可能终止宿主，这项设计不承诺把任意 C／驱动故障转换成 Promise 拒绝。

<a id="library"></a>

## 固定运行库的加载与隔离

平台包提供与主包匹配的 addon、libmpv 和实际媒体运行依赖。加载从包内确定位置完成，核对目标、ABI 与构建身份；不从任意 PATH、当前目录或用户自装播放器借用同名库。成功装载的代码映射按已确认策略保留至进程结束，升级随下次进程启动生效。

多个 Mpv 共享的是代码与只读身份，各自拥有核心、请求、线程和输出。Node Worker 之间不共享 JavaScript 对象或环境回调；一个环境退出只释放该环境拥有的工作。独立帧的持有仍不要求整个核心存活。

<a id="close"></a>

## 关闭后的结果寿命

沿用已经确认的 Mpv、VideoOutput、NativeFrame 和独立截图结果关系。close 可重复调用：首次关闭开始后拒绝新工作，后续调用等待同一次收尾；未完成的公开调用明确结束，不能永久留下悬空 Promise。关闭不接受一个能够撤销资源回收的取消信号。

命令或脚本引发的 shutdown 进入同一收尾流程。引擎实际关闭和 JavaScript 主动调用 close 不各自维护一套实例状态。释放顺序遵守 Render API，只有库自身的事件、渲染和核心资源实际收尾后，close 才完成。

[流提供器合同](streams.md#cancellation)还会将所交付源的工作与清理纳入本次收尾，其协作等待条件单独明确；普通控制请求的取消不会代替外部资源清理。

关闭不等待调用方释放已经交付的 NativeFrame，也不使既有帧或截图字节失效；帧仍须由持有者按 release 合同归还。Kisaki 的会话关闭还包括显示引用回收与记录收尾，不能只凭 Mpv.close 完成就报告整个会话结束。

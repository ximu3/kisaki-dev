# Vantage 验收

A10、A23、A28 和 A33 验证普通 Node 消费、原生后端和 Kisaki 中的进程监测、窗口控制与采集。公共规则见[独立项目联合交付](projects.md)，行为依据见[公开 API](../../design/projects/vantage/api.md)、[平台后端](../../design/projects/vantage/backends.md)和[Linux 接入](../../design/projects/vantage/linux.md)。

## 实例身份与独立消费

从正式包取得 processes、windows，以及库级 getForeground、observeForeground；窗口取帧通过 windows.capture(windowRef)。快照包含实际实例引用，重新查询产生新快照，保留的旧快照不被原地改写。

实例发现、名称变化、编号复用和后端断连分别验证：有效实例可以复用引用，失效引用不能换绑到复用 PID 或窗口编号的新对象。局部不可读时保留可靠事实，监测中断不伪造退出；未知、对象缺失、权限不足和后端不可用分别表达。原生操作的目标对应与并发保证按[平台身份合同](../../design/projects/vantage/backends.md#identity)核验；一次编号检查或类型引用不足以证明原子操作成立。

无图形会话或采集权限时，普通进程能力仍能独立加载和使用。多个 Node 环境分别创建与释放资源，一个环境退出不影响其他环境，也不依赖已不能执行的 JavaScript 回调完成清理。

## 观察与前台

建立观察后先交付初始状态，再接续后续变化。覆盖快速变化、创建与回调顺序、取消、监听器异常和独立释放；终止与中断按合同交付，停止后不再产生新回调。共享底层观察的订阅可以分别停止。系统事件和轮询结果只表达它们实际观察到的事实。

getForeground 与 observeForeground 使用同一快照含义。分别验证已知前台、确认没有前台和前台未知，以及两种部分已知情形：前台进程已知但具体窗口未知，窗口已知但进程归属无法核实。保留已确认引用，不补造关联，也不因局部未知丢弃全部前台事实。观察中断不表示没有前台。

## 控制与协作退出

读取和观察不隐式恢复、聚焦或结束目标。恢复、聚焦、requestExit、requestClose 和 forceTerminate 各自只操作明确目标；进程退出不要求调用方选择窗口。协作退出只使用后端规定的机制，不追着新出现的保存确认窗口继续关闭，不向其他进程追加请求。

分别验证没有可用协作机制、请求失败、请求已发出和目标实际退出。普通终止信号、强制终止和应用正常退出保持各自含义。等待超时或取消不自动重试、扩围或升级为强制终止；取消等待不撤回已发出的请求。释放观察或采集资源不结束外部程序。

## 单窗采集

覆盖指定窗口、最小化、恢复、缩放、保护内容和关闭竞争。核对窗口归属与实际画面来源，取得完整图像和来源信息；成功、失败、取消都释放本次内部采集资源，消费者无需管理额外录屏会话。

图像为独立的 sRGB RGBA8、straight alpha，遵守[原生单窗范围](../../design/projects/vantage/api.md#capture-boundary)：排除系统光标，保留合法透明区域及后端提供的装饰，输出像素对应有效内容。原生边缘差异不能掩盖截错目标、截断内容或无效缓冲区。采集不暗中改用整屏、不恢复或聚焦窗口、不返回占位图；来源关闭后已交付图像仍可使用。

## 平台与权限

| 环境或场景           | 核对内容                                                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows 权限组合     | 普通／提升消费者与普通／提升目标的四种同账户组合，以及不同账户、受限对象、UAC 安全桌面的限制与恢复；查询、原实例退出观察、前台、事件接续、控制和 WGC 分别记录 |
| Windows 局部权限不足 | 控制失败不结束可靠监测，路径不可读不丢弃已确认实例，前台未知不伪造后台或自动切换计时规则                                                                      |
| Windows 图像         | HDR 输入、颜色转换、有效缓冲与独立字节，以及取消竞争和资源回收                                                                                                |
| macOS 窗口与系统     | 同标题多窗口、快速重建、后台工作区、最小化和许可撤销；AX 与 SCWindow 对应可靠，缺失符号与失效对象准确失败；覆盖 macOS 13、当前支持系统及两种架构              |
| macOS 消费者授权     | 普通 Node 与签名 Kisaki 分别记录执行文件、签名、启动身份和系统提示对象，覆盖首次请求、已有授权、撤销、重启及更新                                              |
| X11 归属             | XRes 提供的实际进程归属与窗口目标一致                                                                                                                         |
| GNOME／KWin          | 会话服务、脚本到宿主的有限调用、版本差异、重启、取消及多消费者；组件重建使旧引用失效，动作不重放，资源分别回收                                                |
| Mutter／KWin 采集    | Mutter 由同一 sender 创建并控制采集；KWin pipe 的元数据与有效字节共同采用；旧 KWin 正确处理真实执行文件与首个匹配桌面条目                                     |
| Linux 交付接入       | DEB／RPM、AppImage 与便携形式的实际路径、登记、缓存更新、多实例及异常退出清理，并实际执行窗口控制与采集                                                       |

每个目标记录所需桌面组件、权限交互与清理结果。已有[WGC／Direct2D 机制证据](../evidence/vantage-wgc/capture.md)保留其原始范围；正式验收覆盖上述权限与窗口状态，进程枚举通过不足以证明控制和采集可用。

Kisaki 的游戏监测、计时、窗口选择、完整截图及退出备份继续执行[会话场景](sessions.md#games)。

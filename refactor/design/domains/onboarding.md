# 首次使用与更新引导

onboarding 在主窗口的分步 Dialog 中呈现推荐，组织用户编辑和采用。正式配置及完整操作由各业务模块负责，引导管理当前编辑过程与推荐的采用、跳过记录。

<a id="catalog"></a>

## 首次使用的五组内容

首次引导依次展示偏好、扩展、资料方案、扫描器和展示柜。完整目录始终可见，用户可以按类型和语言筛选，也可以只采用自己需要的部分。模板、默认值和校验直接使用各业务拥有者提供的内容。

各组的初始选择及采用方式如下：

| 分组     | 展示与推荐                                                       | 初始选择与采用                                                                                       |
| -------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 偏好     | 界面语言、明暗模式、缩放、关闭主窗口后的行为                     | 按系统语言建议具体译本，由用户选用；本体默认主题、system 明暗、100% 缩放及关闭后后台驻留沿正式默认值 |
| 扩展     | 按资料与平台、迁移导入、语言浏览全部官方扩展                     | 不预选整套资料来源；译本或方案的必要依赖明确列出，经用户采用后加入仓库、安装与激活                   |
| 资料方案 | 七类、四种语言的完整正式目录，初始按界面语言筛选                 | 不预选创建；用户选择所需类型及版本，明确是否设为该类型默认                                           |
| 扫描器   | 正常 ScanConfig 创建表单，填写目录、作品类型、资料方案及必要规则 | 不预建空配置；监听默认开启并明确保存后扫描的效果，九项线索提取预设按需选用                           |
| 展示柜   | 全部十项正式预设，通过列表及必要说明选择，不提供布局预览         | 默认勾选「最近体验」「合集」「最近加入」并按此排序；前两项横向十二项，最后一项为不限数量网格         |

展示柜将 recently-used-works、collections 和 recently-added-works 按此顺序放入普通草稿，用户可以取消、增加或重排。采用时复用同一份 applyChanges 写入规则，只追加本次新建区块，保留已经存在的区块及其相对顺序。推荐内容是正式预设的副本，不存在首页专属配置。这三个区块共用页面纵向滚动，底部网格按需读取完整范围。

系统语言只用于建议具体 UiTranslationRef，偏好步骤只保存用户明确选定的译本。译本和资料方案需要的依赖在所属位置显示，加入官方仓库、安装和激活的必要操作要明确说明。扩展步骤和方案步骤读取同一份真实状态。补齐依赖期间保留选择和草稿，并分别表达未安装、已停用、不兼容、激活失败和需要账号等情况；安装完成不代表授权也已完成。

扫描器直接复用正常的 ScanConfig 表单，要求资料方案存在且类型一致。监听默认开启，保存后先接入监听，再核对已有范围，并合并处理期间发生的变化。引导必须说明这个效果，并分别报告配置创建、监听和实际扫描结果，不另设引导专用的保存行为。

每组通过“应用并继续”明确提交，当组立即生效。后续步骤失败或用户退出，不回滚已经采用的前几组。最终完成只结束引导并汇总实际成果，不再次应用全部配置。

<a id="interaction"></a>

## 草稿、跳过与暂时关闭

选择和调整先保存在内存草稿中。切换步骤、返回上一步、校验失败，以及同一编辑会话内暂时关闭后重新打开，都保留草稿。关闭按钮和 Escape 表示暂离，不再提供含义相同的“稍后继续”。用户可以从固定入口继续，未完成引导也不要求每次启动都强制弹出。编辑会话结束或应用重启后，只恢复正式成果和处理进度，不承诺恢复尚未采用的输入，也不迁移草稿。

跳过表示本组尚未采用的内容本次不采用。操作将相应推荐记为已处理，再进入下一步。已经安装的扩展和已经保存的配置不会回滚，在途工作也不会自动取消；取消仍使用原业务操作的入口。未采用输入在本次编辑会话中暂时保留，返回时说明它还未应用，完成引导或结束编辑会话后清除。

部分采用后再跳过，界面分别显示已完成与未采用项目。跳过会停止同一推荐的主动提醒，用户仍可手动采用；业务界面的缺依赖状态照常显示。

处理记录已表达提醒选择，无需第二个同义开关。没有待采用内容时只显示“继续”。

完成只结束引导，不会把尚未结束的业务操作标成成功。页面位置、当前输入和模板目录不持久保存，各分组也不成为独立业务实体。模板采用后形成普通用户配置，与模板不再持续绑定。用户以后修改或删除成果，不清除处理记录，也不会触发自动重建。

<a id="state"></a>

## 推荐身份与处理记录

引导合同属于 desktop-contracts/onboarding，仅供本体使用。OnboardingGroup 包含 preferences、extensions、metadataProfiles、scanner 和 showcase；OnboardingMode 包含 firstUse、update 和 manual。onboarding_state 是单例，正式 JSON 保存 firstPresentedAt、firstCompletedAt、lastPresentedVersion 和 handled。前两个时间可以为空，否则使用 UTC 毫秒；版本保存实际展示时的版本或 null。handled 按稳定 itemId 保存处理结果，不另设逐项表或持久草稿。

初始迁移创建这一单例行，firstPresentedAt、firstCompletedAt 和 lastPresentedVersion 均为 null，handled 为空对象。这表示尚未展示、完成或处理任何推荐；创建记录本身不触发引导界面。

itemId 是本体推荐目录中的非空唯一身份。修改文案或顺序时保留原 id，新增推荐使用新 id。资料方案和展示柜项目引用正式 presetId，扩展项目引用正式 extensionId，偏好和扫描设置项目由本体目录定义。处理记录只保存项目结果及成果引用，不复制整个模板。

处理结果和成果引用定义如下：

```ts
type OnboardingHandled =
  | { outcome: 'skipped'; handledAt: number }
  | {
      outcome: 'applied'
      handledAt: number
      resources: readonly OnboardingResourceRef[]
    }

type OnboardingResourceRef =
  | { type: 'extension'; extensionId: string }
  | { type: 'metadataProfile'; profileId: string }
  | { type: 'scanConfig'; configId: string }
  | { type: 'showcaseSection'; sectionId: string }
```

handled 中没有对应项目表示尚未处理。正式配置尚未保存或扩展尚未完成安装时，不能提前记为 applied；配置或安装已经成立后，运行采用与激活问题单独报告，不撤销已经成立的处理结果。偏好采用的 resources 为空数组；其他成果引用描述已经采用的结果，即使资源后来被删除或不可用，记录仍然保留。展示时从实际拥有者读取当前情况，不抹去既有历史。扩展启用状态、激活状态、版本、准备状态和任务结果都不复制进引导记录。

修改处理状态时只更新相关内容，不能用旧的完整快照覆盖后来产生的结果。处理记录与当前业务现状分别表达事实；再次采用必须来自用户新的明确选择。

## 操作与输入范围

引导提供以下本体操作：

| 方法                             | 输入和结果                                                                               | 完成含义                                                                                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| getState()                       | 返回完整正式 OnboardingState                                                             | 只读，不因查询推进引导                                                                                                   |
| listItems({ mode })              | 返回当前模式下适用的目录项，含 itemId、group、正式预设或扩展引用、推荐说明及该项处理结果 | 适用条件由本体目录解释，不接收扩展提供的任意判断脚本；首次、更新、手动分别使用 [首次使用与更新引导](#catalog) 的选择规则 |
| markPresented({ mode, version }) | 返回更新后的正式状态                                                                     | 仅在引导实际展示后登记；关闭或未完成不意味着每次启动强制再弹                                                             |
| apply(input)                     | 返回该次已实际采用项目的处理结果及成果引用                                               | 按本节五个闭合输入分支执行；长工作与错误使用完整业务结果                                                                 |
| skip({ items })                  | 返回这些项目的实际处理结果                                                               | 对明确未采用项记 skipped，保持其他已采用事实；不取消在途工作                                                             |
| complete({ mode })               | 返回正式状态                                                                             | 结束当前引导；首次完成时登记 firstCompletedAt，不替未结束业务制造成功                                                    |
| onInvalidated(listener)          | 返回 Disposable                                                                          | 正式处理状态变化后通知重读，不传未提交草稿                                                                               |

apply 接收 `{ group, items }`，items 是有序、非空且 itemId 不重复的数组。每项包含 `{ itemId, expectedHandled, input }`；expectedHandled 必须为该项已读的完整 OnboardingHandled 或 null，null 表示尚未处理。group 与每个 itemId 的目录分组一致，input 的允许形状如下。

| group            | input 与明确限制                                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| preferences      | `{ changes, expected }`，复用偏好字段值与相关基线；本组只允许一个项目，限定 general.uiTranslation、general.closeMainWindow，以及 appearance.theme、mode、interfaceScale。身份引用整体比较。 |
| extensions       | 正常安装入口的明确包来源、版本及已经确认的仓库和信任输入；不接受调用脚本或省略信任决定。                                                                                                    |
| metadataProfiles | 普通 create 的完整输入与显式 isDefault；设为默认时带 expected.defaultProfileId，使用下述同类型默认基线。                                                                                    |
| scanner          | 普通 ScanConfig create 的完整输入；registerExistingContent 保持正式默认 false，监听与首次核对遵守普通创建规则。                                                                             |
| showcase         | 普通 applyChanges.create 中的一项完整输入，包含本次唯一草稿 key；只创建新项，按 items 顺序追加，不开放对已有区块的 update、delete 或完整排列替换。                                          |

每个项目只使用自己分支的业务输入，所有未知字段按正式边界校验拒绝；目录身份不能扩大业务操作范围。expectedHandled 只比较该项正式处理记录，业务 expected 仍由所属领域核对，两者均不能由返回当前值后自动刷新来绕过冲突。查询不会推进状态。markPresented 只在引导真正展示后登记；complete 首次完成时写入 firstCompletedAt，不代替业务声明成功。skip 只处理明确未采用的项目，不取消任务。onInvalidated 只通知正式处理状态变化，不传递未提交输入。

<a id="commit"></a>

## 提交与运行结果

preferences、metadataProfiles、scanner 和 showcase 的一次 apply，以本组全部 items 为一个短同步事务：先核对所有 expectedHandled 与业务基线，再调用各拥有者提供的同步写入能力，最后写入实际资源引用与 handled。任一项失败全部回滚；不存在先建配置、再补标记的可观察中间状态。准备期间状态变化时报告冲突，保留草稿。具体协作入口见下节。

提交进行中，界面不重复发起同组操作。失败时正常反馈并保留输入。重新打开引导时，读取当前 handled 与成果，按已保存状态展示。

扩展按 items 顺序逐项安装，再核对该项 expectedHandled 并保存处理记录；安装与引导记录不构成跨文件系统事务。首个未完成项停止后续项目，保留此前成果。安装已成立但处理记录冲突或保存失败时，结果保留实际 extensionId；用户修正后重新采用同一包时，安装器核对已安装版本与包身份，不能仅因缺少 handled 重装或改装另一版本。安装及所选启用状态已经保存时可以记 applied，激活失败作为运行问题返回。译本安装不会代替语言选择。

ScanConfig 与引导处理记录先提交，再由 scanner 建立监听并执行初始核对。监听失败时，界面说明配置已经建立、监听暂不可用；重试针对实际运行，不重复创建配置。引导记录不再复制安装、配置或执行状态。

查看和编辑成果时，通过正式引用调用正常业务能力。用户明确从同一预设再建一份时，执行新的创建操作。如果还需记录这次引导采用，仍携带已读处理状态，并与同库写入一起提交。删除成果、模板更新或重新打开引导，都不会自动清除标记或再次创建配置。

<a id="composition"></a>

### 有界的原生组合入口

onboarding 的完整 apply 拥有本次组合事务，app 只负责注入依赖。各业务模块提供下表中的本体内部同步写入能力，由普通完整操作和引导共同使用；onboarding 不导入私有 write 文件，也不向其他调用者提供任意事务执行器。

| 拥有者提供的能力                 | 事务外准备                                 | 同一事务内完成                                                              | 提交后处理                         |
| -------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------- | ---------------------------------- |
| preferences 的 writeUpdate       | 校验本次偏好输入和引用；没有网络或安装动作 | 读取相关当前字段、比较 expected、保存修改                                   | 发布偏好失效，所属运行能力采用选择 |
| metadata.profiles 的 writeCreate | 解释完整定义与来源能力要求                 | 创建方案；isDefault 为 true 时比较当前同类型默认 ID，取消旧默认并设置新默认 | 发布方案变化；不因创建自动获取资料 |
| scanner.configs 的 writeCreate   | 验证配置、路径及明确的资料方案             | 保存配置及正式引用                                                          | 发布配置变化，再接纳监听与首次核对 |
| library.showcase 的 writeChanges | 校验实际 create 输入及查询定义             | 复用 applyChanges 规则创建区块，保留当前已有项顺序并追加本次新项            | 发布 showcaseChanged 和读取失效    |

这些依赖接收当前事务连接和所属领域的正式输入，只返回实际写入结果与待发布的变化摘要；不自行提交、不嵌套开启事务，也不执行文件 I/O、订阅者、扩展代码或后台任务。正式公开 API 不含这些能力。准备与失败清理仍由原拥有者提供，不能在引导复制字段解释或附件规则。

onboarding 在同一事务写入 `handled[itemId] = { outcome: 'applied', handledAt, resources }`，resources 来自本次实际结果。全部必需业务写入和 handled 共同成功后，各拥有者发布变化、交接运行工作并通知引导状态失效。事务失败时保留原状态；提交后的运行失败保留已保存配置和 applied，并返回实际问题。

普通配置 create/update 中，`expected: { defaultProfileId?: string | null }` 只用于 metadata.profiles 设置 isDefault 为 true 的操作：比较同类型当前默认的真实 ID，null 表示要求当前无默认；其他修改不接受这个条件。引导表单设默认时必须提供它，一次采用同类型多份默认方案为 InvalidInput。现有来源能力的可用性按正式保存规则判断，不要求引导安装器或网络调用进入事务。

apply 返回 `{ group, items }`，每个结果保留输入顺序，并含 `{ itemId, outcome, resources, issues }`。outcome 为 applied、notApplied 或 notStarted；resources 仅包含已经成立的成果，issues 为 `{ stage: 'installation' | 'commit' | 'runtime', error: ErrorSummary }[]`。成功时全部为 applied，可以有运行问题。完整失败通过 ExecutionFailure<OnboardingApplyResult> 交付已经形成的报告：同库事务失败时全部 notApplied 且没有新资源；扩展安装已成立而标记失败时为 notApplied，但保留 extensionId，后续未执行项为 notStarted。未知的安装提交结果按原安装合同表达，不能伪造资源引用。

输入或目录归属错误为 InvalidInput；必要资源缺失为 NotFound；handled 或业务基线不符为 Conflict；实际安装、持久化或运行错误由拥有者提供稳定分类。提交前取消不写同库配置；提交后的取消不撤销成果，也不重复创建。skip 接收非空且 itemId 不重复的 items，每项仅含 { itemId, expectedHandled }；在短事务中比较所选项目的处理基线，只将尚未采用的项目记为 skipped。已经 applied 或 skipped 且基线相符的项目保留原结果与时间，无变化不发失效；并发采用使旧基线冲突，不能被 skip 覆盖。

<a id="availability"></a>

## 依赖反馈与日常补齐

已知依赖不足时，所属项目持续展示状态及补齐入口，不等到提交才反馈，也不因一次读取自动弹出警告。FieldDescription 解释字段用途，可用性状态单独呈现。提交校验遵守[共同表单反馈](../ui/components.md)。失败通知由原业务操作负责，引导保留草稿及已有结果，长时间工作复用 TaskCenter。

Profile Select 缺少适用方案时，右侧继续提供快捷创建入口，调用正常创建能力。创建成功后，只有字段仍对应本次编辑意图，才可以选入新方案，不能覆盖用户后来作出的选择。默认方案始终由用户明确指定，不能因它是第一份、唯一一份或通过快捷入口创建而自动改变。

常规预设选择沿用[共同预设界面](../ui/components.md#presets)。引导保留推荐文字说明，图形表达不改变 presets 与 templates 的目录命名，也不改变所属业务的草稿与采用规则。

仓库、扩展、主题、偏好、资料方案、扫描和导入各自拥有完整的操作与结果，引导通过这些操作采用选定内容。已经采用的用户配置不会随模板更新或界面语言变化重写。

<a id="updates"></a>

## 更新引导与手动打开

只有实际升级后，且存在适用于本次版本、尚未处理的新项目时，应用才自动展示更新引导。新增能力、推荐模板或需要用户配置的设置可以成为新项目；普通修复、说明及仅有版本号变化的内容由更新日志承载，不重放首次使用目录。

更新中的新配置默认不勾选，也不替换既有默认方案或展示柜。firstUse、update 和 manual 共用项目定义与采用规则，只在展示范围和时机上不同。手动模式可以查看完整适用目录及已处理结果，但再次采用必须由用户明确发起，不能自动覆盖正式成果。

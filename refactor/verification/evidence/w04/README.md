# W04 通信机制验证

2026-11-05，在 Windows x64、Node 24.11.1、pnpm 11.11.0、TypeScript 6.0.3 和 Electron 45.0.0 上验证 `@kisaki3/desktop-rpc@0.1.0-dev.0`。验收范围是 [W04](../../../implementation/work-packages.md#w04) 对 A23、A31 的包合同断言。

| 边界          | 实际验证                                                                                                                                                                            |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 帧与握手      | 八种帧保留普通 JSON 值和缺省语义。未知 wire 版本只读取 hello 信封。端点版本不符、上下文拒绝、提前调用和十秒握手超时分别结束。                                                       |
| 双向调用      | 相同 ID 可在两边同时在途，嵌套调用可以完成，已结束请求的重复回复被忽略。仅执行方法表显式开放的方法，安全失败可以携带由方法解析的部分结果。非法关联和倒退 ID 关闭连接。              |
| 取消与释放    | 已发出的取消等待执行者的实际结果。断连拒绝本地等待，向在本端执行的调用发出停止信号。迟到的完成和帧无法进入新连接。通知处理错误在接收端交付。                                        |
| Node 父子 IPC | 仓库外父子进程使用同一 tarball，经 JSON 序列化往返嵌套值、Unicode 和自有 `__proto__` 键。权限错误可在父进程识别，取消后收到已提交结果。通道断开后，父进程另行观察到子进程正常退出。 |
| Electron 窗口 | 主进程把实际 MessagePort 通过隔离 preload 转交沙箱文档。结构化克隆值往返成功，执行者响应取消后返回可识别错误。窗口销毁结束在途等待。测试使用临时 profile。                          |

## 结果与复现

本机 `pnpm check` 通过，153 项常规测试中有 12 项直接验证 RPC 机制。五个公共包的 15 项仓库外消费检查全部通过，其中两项运行上述真实通道。另以构建后的入口核对安全整数耗尽时先完成在途调用再关闭，以及原生发送失败时等待与监听的释放。

`pnpm check` 检查工作区类型、lint、导入边界、格式和常规测试。`pnpm exec turbo run test:consumers --filter=@kisaki3/desktop-rpc` 构建 ESM 与声明，生成一份 tarball，通过 publint 和 ATTW 的 ESM 检查，再安装到两个临时工程。NodeNext 与浏览器 Bundler 消费分别启用完整声明检查和类型感知 lint。

包内制品位于 `out/package/package.tgz`，消费者报告位于 `test-results/consumers/results.json`。连接内核与宿主适配的分工见[协议合同](../../../design/engineering/protocols.md#frames)。产品窗口、扩展实例与开发应用的身份绑定、就绪和退出分别随 W07、W18 和 W19 验收。

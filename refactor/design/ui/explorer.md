# Explorer、混合浏览与详情导航

Explorer 是资料库导航栏，按当前查询组织真实合集分组，并连接主体详情。查询范围、对象选择、当前显示实例、键盘焦点和返回来源分别拥有明确状态。

<a id="model"></a>

## 对象与视图状态

EntryRef 只指七种真实条目，Work 只包括四种作品。Part、文件、Note、Activity、合集和标签都不进入 EntryType。EntryPicker 只选择 Entry，其他选择器使用自己的合同。Part 导航需要作品时，应定位真实 Work，不能建立影子条目。

评价、个人记录、活动、持有内容和资料分别持久保存。查询可以组合它们，但不能将其重新塞回 Entry。手动合集保存真实的跨类型成员顺序，动态合集保存规则，不保存成员镜像。标签应用、笔记和资料关系保留自身身份、属性及两侧顺序。Section 保存查询和展示配置，不创造归属。

EntryQuery 保存 scope、search、规则组与 sort，读取形状见[查询值合同](../domains/library-query-contracts.md)。声明范围由启用类型的并集确定，offset、limit、fields、可见性、时区与权限由本次读取提供。草稿、摘要、分组实例、选择、焦点和返回锚点按视图寿命管理。显示位置使用 group ID 与 EntryRef，未分类采用派生组身份。

| 入口                   | 初始类型范围             | 固定范围及原因                                                                     |
| ---------------------- | ------------------------ | ---------------------------------------------------------------------------------- |
| Explorer               | 四类作品                 | 全库作品导航；类型控制明确显示该选择，避免自动获取的大量人物／角色挤满日常作品入口 |
| 收藏页                 | 七类 Entry               | 用户明确收藏的所有对象；角色、人物、组织收藏具有独立价值                           |
| 未分类页               | 四类作品                 | 日常待组织的作品；可明确改看其他类型，判定规则不因初值而改变                       |
| 合集成员、标签反向列表 | 七类 Entry               | 完整表达用户建立的组织范围，不因默认类型省略其中的成员                             |
| 参与与关系入口         | 该关系实际允许的类型     | 人物选择固定 person，相关作品允许四类 Work 等，不给不适用类型入口                  |
| EntryPicker            | 调用场景明确允许的类型   | 泛条目选择可多类型，固定目标直接锁定；选择资格仍由实际业务校验                     |
| ShowcaseSection        | 预设或用户保存的类型集合 | 新建普通区块为四类作品；不随 Explorer 当前类型或结果变化改写                       |

“作品”和“全部条目”快捷项只填入类型集合，不增加额外模式。字段条件必须对组内所有类型具有相同含义，统一排序也必须适用于全部启用类型。不适用输入应保留供用户修正，不能当作未设置。各浏览视图共用查询合同，但独立持有自己的查询；固定收藏或合集范围不能被 OR 条件撤销。

## 共同规则与混合浏览

每个规则组包含 enabled、非空类型集合和一层 all 或 any 条件。组间取并集并去重，再与共同 search、固定范围和可见范围相交。没有启用组时结果为空；启用组没有条件时，包含该组类型的全部适用对象。启用组无效时不能跳过后执行更宽查询。

多类型组表达共同意图，多组表达不同条件。例如，四类进行中作品使用一组，高分游戏或进行中动画使用两组。组没有独立 scope、sort、优先级或配额，编辑顺序和 types 数组顺序不决定结果，也不支持任意嵌套树。动态合集、Section、完整浏览和选择器复用同一值与执行规则，各入口另外明确自己的限制。

Section 可以直接使用多组查询，无须先建立隐藏合集。只有确实需要归组、封面、说明和可引用身份时，才建立合集。手动和动态合集都使用一份混合列表、网格或表格，不先分类型，也不保存各类型独立顺序。手动成员允许跨类型穿插；动态合集只有一份统一字段排序，新建时为有效排序名升序。不能分别按游戏时长、动画日期排序后拼接。需要独立排序或数量时使用多个 Section，跨类型逐项计划可以使用手动合集。

动态合集定义面向全库，只引用手动合集条件。Section 可以将动态合集作为外层范围，定义本身仍保持无递归。

默认排序失效时，保留仍可判断的成员范围，提示用户选择合法字段后继续浏览。条件求值失败单独报告，既不作为空结果，也不作为未分类的判断依据。

动态转为手动时，采用正式规则的完整去重结果和保存顺序，不使用临时筛选、视口内容或 Section 上限。该行为复用[共同查询](../domains/library-queries.md)，不建立专属引擎。

## Explorer 的单组查询

Explorer 只编辑一组启用规则，可以选择多种类型。完整多组编辑放在动态合集、Section 和确有需要的主体浏览中，Explorer 不增加简单、高级或规则组入口。复杂动态合集先独立计算成员，再与 Explorer 单组相交，不展开成窄栏编辑稿。详情来源中的查询也不导入 Explorer。

顶部依次放置页面导航、类型范围，以及搜索、排序、筛选三个控制层。它们共用控制带底色，通过间距和轻分隔区分。Toolbar 保留搜索宽度，空间不足时换行，不压缩命中区域。类型控件显示真实摘要，展开后提供作品、全部条目、七种单类快捷项，以及任意非空组合确认。长组合使用完整可访问名称，不能含糊显示为“自定义”。

类型操作只修改组内类型，筛选使用共同 FilterDialog，搜索作用于整个查询。sort 区分范围顺序和字段排序，范围顺序没有方向。切换快捷类型不能静默清除既有条件或排序。不适用时保留草稿，通过 Toast 和字段状态说明；可以保留旧有效结果，但必须明确新输入尚未应用，并给出恢复路径。未确认时不清选择，普通合法改动也无须进入完整高级编辑器。

筛选按钮不显示条件数量。有条件时，在右上方贴近放置独立清除小按钮，拥有独立命中区域、焦点和名称，不能嵌套按钮。清除只移除本组条件，保留类型、搜索和 sort，不打开 FilterDialog，也不修改动态合集定义。清除按钮消失后，焦点回到主筛选按钮。搜索仍非空时，不结束查询期间的临时折叠状态。

## 合集分组、折叠与数量

Explorer 初始使用全库、四类作品和 scope 顺序，显示真实合集分组并在最后追加未分类，不提供平铺切换或类型子组。搜索与筛选只缩小组内 Entry，合集标题命中不会使整组成员入选。没有匹配成员的组暂时隐藏，空合集仍可在合集管理中访问。

组按合集人工顺序排列，未分类最后。使用 scope 顺序时，手动合集成员按人工序，动态合集成员按保存的字段序，未分类按有效排序名。显式字段排序在每组使用同一规则，不按成员值改变组序。组内读取携带真实 group 上下文，并与原 scope、规则、search 和可见性相交，不能用 group 替代 scope 后丢失原限制。

本体提供全查询去重后的 Entry 总量和各组匹配数，视图再根据展开状态与几何计算显示位置数。这三种数量不同。重复显示实例和组标题不能算成新条目，也不能从局部加载内容推测全组数量，或相加各组数量冒充去重总量。

未分类根据当前可见手动成员和有效动态匹配计算，临时筛选不会改变归属。某动态组失败时显示局部问题，未分类不能假称是可靠余集；其他可用组和独立的平铺全库浏览仍可使用。

搜索或条件生效期间，匹配组默认临时展开。用户主动折叠后，同一组保留该选择，不随每次输入重新打开。搜索与条件都清空后，恢复查询前的普通折叠状态。只切换类型或 sort 不开启另一种折叠模式。定位引起的临时展开也遵循同一规则，不能持续覆盖用户后来作出的折叠选择。

## 当前项、选择与键盘

对象选择保存去重 EntryRef，同一对象在各组中的显示实例共享对勾。详情当前项、键盘焦点和 Shift 起点则指向具体显示实例。当前项使用整行 bg-accent、text-accent-foreground、圆角和 shadow-raised。普通选中使用文字强调与最右侧固定对勾，类型图标放在对勾左侧；整行底色仅用于当前项。未选项没有常驻 checkbox，对勾没有独立焦点或动作，名称与图片不因选中而位移，焦点使用共同描边。

普通点击单选并打开详情。Ctrl 或 Cmd 点击只切换选择，不导航；Shift 按当前展开的逻辑行选择范围。方向键移动焦点，Enter 激活，Space 切换选择，Escape 或明确空白点击清除选择但保留详情。行区之外的输入框、Dialog 和详情各自处理按键。右键点击未选项时，先收束为该项再打开菜单，不导航；右键点击已选项时保留整个选择集合。

详情自动跟随只改变当前显示实例和位置，不增加或减少选择，也不抢键盘焦点。已有三项选择时，主体打开另一条目仍保留这三项。真正采用新的类型、search、filter、入口或可见范围时清除选择；sort、滚动、折叠、详情变化，以及网格和表格切换都保留选择。

普通刷新不自动选中新项，离屏或未加载也不删除选择。删除或合并前核对真实身份，不能只裁剪缓存，也不能自动改选合并目标。全选取得完整查询的引用，折叠不是过滤。Shift 通过稳定的两端实例、分组和实际展开范围解析，已展开但尚未加载的成员仍参与，折叠成员不属于屏幕范围。请求传递真实上下文，不传 DOM、像素或旧索引，端点失效时明确报错。

批量动作必须适用于全部目标，不能按右键所在一行的类型或合集静默裁剪。Entry 删除使用对象身份，合集移出使用成员身份，关系操作使用真实关系身份。合集动作要求全部选择处于同一声明范围。收藏和标签等通用操作可以混合类型，状态操作要求全部为 Work，专属使用动作核对各自前提。updateMany 为每个目标选择适用方案。扩展菜单接收打开时的非空 EntryRef 集合快照，不限同类，也不由宿主裁剪。

重排必须发生在同一个合法人工范围内。合集头、手动合集成员和 Section 管理分别排序，动态合集与平铺字段排序不增加人工序。跨组拖动不能暗中改变归属，筛选子集移动保留未显示槽位，见[统一重排](virtualization.md#reorder)。

## 详情来源、定位与返回

详情目标、浏览来源和 Explorer 显示实例分别保存轻量状态，不合成一个 from，也不写成 Entry 的默认归属。从组内打开时保留原查询与确切实例；从 Section、搜索或统计打开时保留各自返回上下文，不能伪造合集来源。需要新的显示位置时，按当前查询和真实合集顺序查找，不预载全库的 default-from。

主体明确打开详情时，触发一次 Explorer 跟随：按需展开分组，读取目标附近区间，等待真实行挂载后定位并标记当前项。目标已经可见时保持位置。刷新、重排和用户滚动不会反复将列表拉回，新导航或查询会使旧定位结果失效。自动跟随不转移焦点，用户显式定位时的焦点交接按同一控件操作验证。

| 当前定位状态                   | 入口表现与行为                                                |
| ------------------------------ | ------------------------------------------------------------- |
| 没有正在打开的条目             | 不显示定位入口                                                |
| 目标属于当前查询且已经可见     | 不需要重复定位，入口可隐藏；自动跟随不额外移动列表            |
| 目标属于当前查询但离屏或被折叠 | 定位入口可用，展开必要合集并滚动到实际行                      |
| 实际查询确认目标未匹配         | 保留禁用入口，通过 Tooltip 说明当前范围未匹配，点击不改变查询 |

目标未加载或尚在挂载时显示加载状态。查询确认未匹配后，详情继续打开，查询保持原样，定位入口禁用；共同 Tooltip 说明“当前条目不在 Explorer 的显示范围内”，支持悬停和键盘访问。读取失败单独反馈。这个状态只说明当前查询没有匹配，不推断隐藏或删除原因。

已经明确且仍有效的显示实例优先，只有它真正失效时才按当前有效归属重新选择。被筛除、折叠或尚未加载都不改写来源。返回时使用原视图、查询和稳定锚点，从当前资料重新读取，不恢复旧像素或历史结果快照。

Section 的“查看全部”复制当前查询并只去掉上限。浏览中的临时编辑不回写 Section，后续 Section 修改也不覆盖已经打开的浏览。返回使用仍存在的区块和锚点，区块删除后不重新创建。从浏览创建 Section 时只取得能够表达的查询，不保存折叠、选择或位置。想展示某个组时明确选择合集 scope，不建立任意视图转换框架。

## 名称补全与控制带

实际截断的名称在原行横向延展，保留位置、字号、类型和动作对象。补全部分使用不透明底向内容区展开，不改变栏宽、占位或邻行。接近边缘时限制宽度，必要时只在补全区域换行，不叠加 Tooltip。

补全不会选中对象。点击、右键和修饰键仍作用于原项，并支持键盘查看。移开、Escape、滚动、卸载或布局失效时结束补全，不增加第二个 Tab 焦点或业务对象。测量、碰撞和释放使用共同机制，外观贴合原行。

导航与 Toolbar 共用控制带底色，通过排列和间距区分，各自拥有业务职责与状态。区域层次、hover、选中、当前和焦点分别可辨，辅助文字降低强调但仍可读。浮层遮住下方文字，同一连续区域统一绘制底色。明暗模式保持相同职责，表面层次按视觉分组表达。

## 状态归属与验收

查询、草稿、组上下文、展开状态、选择、焦点、锚点和局部区间属于当前视图。导航只保存轻量恢复参数，重新进入时重新读取。明确的宽度等布局偏好独立保存，不持久化整份 Explorer store。折叠和资源释放不会改变集合。

纯字段合同、主进程谓词与排序、分组与定位、domain-ui 筛选与摘要、场景状态和虚拟几何分别分层。基础卡片和详情不能反向依赖 Explorer 或 Showcase，也不建立万能 EntrySpec。

验收覆盖混合摘要与动作、规则适用性、统一排序、远处及重复实例定位、焦点与对勾分离、草稿冲突、动态组失败后的未分类、Section 返回和迟到响应。加入人物类型使作品字段不再适用时，必须保留输入。跨分组选择、成员操作，以及混合类型下的原生与扩展菜单，都按真实目标验证。

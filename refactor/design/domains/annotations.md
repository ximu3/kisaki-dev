# 标注、摘录与内容定位

Annotation 保存针对四类作品实际内容的书签、选区、高亮、画面和批注。位置用于返回内容，摘录、图片和用户文字则作为正式资料保存。即使源文件不可用，用户仍能查看、检索和保留这些内容。

书签是用户主动保存的点位标注，可以留下多个值得返回的位置。文件的续读位置则由实际使用自动更新，表示上次停在哪里，归文件使用记录管理。

<a id="model"></a>

## 所属作品与分表存储

每项 Annotation 只属于一部作品。[Note](notes.md) 则是一篇独立文章，可以关联多个条目。四类标注共用公共值、校验和界面组件，存储时直接按作品类型分表，不建立 annotations 总表、总表与类型明细的组合，或另一套身份注册表。

各表直接引用所属作品和适用的内容：

| 表                | 作品引用                      | 适用的内容引用                                                  |
| ----------------- | ----------------------------- | --------------------------------------------------------------- |
| game_annotations  | game_id 引用 games.entry_id   | image_id 必填并引用 attachments.id，保存实际采用的游戏画面      |
| anime_annotations | anime_id 引用 animes.entry_id | file_id 引用 anime_files.id；image_id 可空并引用 attachments.id |
| comic_annotations | comic_id 引用 comics.entry_id | file_id 引用 comic_files.id；image_id 可空并引用 attachments.id |
| novel_annotations | novel_id 引用 novels.entry_id | file_id 引用 novel_files.id；image_id 可空并引用 attachments.id |

文件记录删除后，为保留标注，文件引用允许为空。创建标注时必须验证作品有效、内容目标有效，并确认文件属于目标作品，不能只检查两个外键分别存在。漫画和小说共用文字与页面定位能力，按实际内容选择适用的定位值。固定页面也可以包含可选择文字，标注方式与文档版式分别判断，不由 Work 类别限制。

正文图片分别由 game_annotation_content_attachments、anime_annotation_content_attachments、comic_annotation_content_attachments 和 novel_annotation_content_attachments 保存引用。每张表通过 annotation_id 和 attachment_id 直接引用对应标注表与 attachments，不使用泛型父引用。全局查询由数据库联合四张标注表，再整体筛选、排序和分页，renderer 不分别获取一页后自行拼接。

<a id="fields"></a>

## 公共字段与显示

四张表分别保存以下公共字段，不通过公共父表保存：

| 字段       | 含义与约束                                          |
| ---------- | --------------------------------------------------- |
| id         | 稳定标注 ID，所在表的主键                           |
| title      | 可空标题，不唯一；未填写使用 NULL                   |
| content    | Markdown 批注，非空列，默认空字符串                 |
| created_at | 标注首次实际保存时的 UTC 毫秒时间                   |
| updated_at | 标题、批注或采用的内容目标实际修改时的 UTC 毫秒时间 |

首次保存为 created_at 和 updated_at 使用同一个时间。无变化保存、打开或跳转、源文件变化和缩略图生成不更新这些时间；文件删除导致引用置空也不算用户修改标注内容。各表索引包含 (created_at DESC, id ASC) 及作品、文件和附件引用的反查。

标题去除首尾空白后为空时存 NULL。批注保留有意义的缩进、行尾空格和换行，不对全文执行 trim。漫画和小说另有可空的 quote，原文按实际取得的文本保存，不改写或截短真正选区的完整摘录。视频和阅读标注必须保存各自适用的 location，游戏不保存文件位置。标题、批注或 quote 为空不否定已经取得的完整内容目标，也不要求补造文字；相同标题、位置或内容不构成标注的唯一身份。

显示名称依次采用用户标题、原文片段、批注的纯文本片段、可读位置，仍无合适文字时采用对应的本地化标注名称。图片与名称一起帮助辨认。片段保持有界，不把完整长文塞入列表；CFI、节点路径等技术地址不直接充当名称。显示值不写回 title，也不为生成名称重新打开原文件。

<a id="values"></a>

## 画面、位置与摘录

四类标注的 image_id 引用正式保存的画面附件。游戏标注必须有画面，其他类型可以没有。游戏先采集并固定一帧图片，再按需要裁剪；裁剪始终处理这帧已取得的图像。用户采用局部截图后，将裁切结果作为完整图片保存，原截图的编辑 region 随草稿结束；截图不提供可恢复的游戏剧情位置。

阅读标记采用统一的高亮、区域框线及当前选中样式，在实际阅读配色下保持可辨。四类标注都不保存逐条颜色，也不提供颜色选择器；应用的文字、背景和主题配色继续由各自偏好管理。

漫画和小说的 location 采用本体 ReadingAnnotationLocation。quote 保存当时取得的原文：文字选区保留完整的所选纯文本，文字书签保留当前位置附近的一小段原文供辨认。书签仍按点位定位，不因带有原文就产生文字高亮范围。content 保存用户批注。文件变化不会重建并覆盖原文或图片，位置也不重复携带全文。

阅读内核通过公开协议提供定位值、实际选中的文字或指定位置的邻近原文，Kisaki 分别采用为 location 与 quote。重新定位可以借助已有 quote，不要求每次返回内容都核验历史全文。定位编码和恢复过程见[阅读器](reader.md)。

<a id="video-values"></a>

## 视频时间点、片段与画面

动画标注的 location 使用以下值，单位为所在文件内的秒数：

```ts
type PlaybackAnnotationLocation =
  | { type: 'position'; positionSeconds: number }
  | { type: 'range'; startSeconds: number; endSeconds: number }
```

所有时间值必须是有限非负数，可以包含小数，0 是有效位置。范围满足 startSeconds < endSeconds，包含起点但不包含终点，并且只属于一个文件。空范围或反向范围写入失败，不自动改成时间点。start 是执行指令，不进入持久值。保存核对纯值约束和文件归属，不要求重新打开媒体核验时长；实际跳转由内容执行者核对请求起点是否仍可定位，不夹改已保存的历史范围。

新建视频标注默认取得当前画面及同次采集的时间点。用户将它设为片段或调整已有片段的起止时间时，保留已经采用的图片。图片不要求来自范围起点，也不因范围缩小后原画面落在范围外而自动替换。只有明确重取当前画面时才替换图片；同一文件内重取画面不自动移动点位或改写片段范围，新的采集时间不另存为图片的第二个跳转位置。

例如，在 12:40 取得画面，将范围设为 12:30–12:50，再改成 12:28–12:55，图片始终保留 12:40 的那一帧。采集使用当前真实画面，不为生成起点预览而隐含跳转、暂停或恢复播放器。更换源文件仍须明确采用相互对应的文件、定位和画面，不能把别的文件的当前画面挂到旧目标上。

返回时间点时使用该点，返回片段时使用范围起点，并在播放器中显示完整标记范围。跳转沿用正常播放控制，不自动循环片段或在终点停止；标注保存的图片也不代替原视频片段。

<a id="bookmarks"></a>

## 书签的内容与辨认

添加书签时，直接取得位置及适合当前内容的原文或画面，不要求用户先填写标题，也不区分仅存位置和附带截图两种创建模式。

| 当前内容             | 默认保存                         |
| -------------------- | -------------------------------- |
| 可重排的文字正文     | 当前源位置及其附近的一小段原文   |
| 漫画、图片等固定页面 | 当前页内位置及可见阅读区域的画面 |
| 动画                 | 当前文件内时间点及当时画面       |

两类阅读作品都按实际内容采用上述规则。可重排内容的当前位置没有可用文字时，保存当前可见内容画面；文本读取失败与没有文字分别处理。原文提取由阅读内核完成，使用有界长度，不改写为生成式摘要，也不跨文件补取内容。

页面书签保存的是当时可见的内容画面，可以包含实际的单页、双页或连续阅读呈现，排除应用控件和临时选框。位置仍来自阅读内核，不能由截图推导源坐标，也不将视口画面伪装成某一张原始页面的 ReadingPageRegion。画面或原文与本次位置一起固定，后续滚动或切换文件不改变归属。

这些原文和图像随书签正式保存。列表直接读取保存内容，图片缩略图从保存的 image_id 生成，不依赖原文件此刻可读。标题和批注仍可为空；编辑文字或重新打开列表不自动重取内容。采集使用[同一内容接入](sessions.md#capture)，完整目标取得后才创建记录。

<a id="ordering"></a>

## 列表与内容顺序

全库、作品及普通文件标注列表默认按 created_at 降序排列，再按 workType、id 的稳定键升序补齐。编辑旧标注不改变其默认位置；文字筛选沿用所选列表顺序。应用搜索仍按[搜索结果规则](search.md#results)排列，不把列表默认顺序套到相关性结果中。

当前已打开文件内的播放器或阅读器标注面板按内容位置升序排列：视频使用时间点或范围起点，阅读使用实际源内容顺序。相同起点按 created_at、id 升序补齐。不能恢复的位置保留在末尾并按 created_at、id 排列，不丢失记录，也不假装定位到了文件开头。

阅读顺序由 Kana 对本次文档和已有标记定位的解释提供，不比较 CFI 字符串、成员路径或 quote 长度。内容界面使用会话内的轻量定位索引安排标记与列表，正文和图片仍按可见范围读取；不把当前加载的一页重新排序后冒充完整结果，也不保存另一列进度或人工标注顺序。关闭文件后释放该索引。跨文件列表不推断不同文件之间的内容先后。

<a id="api"></a>

## 采集、编辑与返回内容

标注使用以下 library API：

```ts
library.annotations.list(query, options)
library.annotations.get(ref)
library.annotations.create(input)
library.annotations.update(ref, input)
library.annotations.delete(refs)
```

AnnotationRef<T extends WorkType = WorkType> 为 { workType: T, id }。Annotation 按 workType 区分四类，带有 id、对应作品 ID、公共字段和该类型的内容值。create 返回新的 annotationId，update 和 delete 返回 void。get 返回完整 Annotation，当前可见范围内未命中时返回 null；list 返回 { items: AnnotationSummary[], total }，其中 items 是本次有界区间，total 是同一次读取中的完整匹配数量。完整查询、摘要、listLocations 定位投影及创建／更新形状见[标注调用值](annotation-contracts.md)。

AnnotationSummary 包含本次结果的标注身份、所属作品与可空文件引用、标题、必要的有界纯文本片段、imageId、位置种类、无需打开文件即可解释的显示位置资料，以及创建和修改时间，不传输完整长批注、完整摘录或选区几何。详情与跳转按身份取得完整记录；内容界面所需的定位投影与长正文分开读取。list 统一处理筛选、排序和分页，支持按作品类型、作品、文件、明确标注身份及关键词检索，关键词匹配标题、批注和摘录。明确身份范围也须与其余条件和可见范围相交，可用于读取当前内容顺序中可见项的摘要。

update 接收 changes 以及可选的 expected；标题、批注和完整 target 的[比较单位](library-write-contracts.md#expected)分别限定，delete 接收明确的单条或多条选择，并遵守短批量提交规则。

session 与阅读内核负责采集实际位置、选区、文字或截图，library 只保存已经明确的业务值。取得完整目标后，即使原 session 已结束，用户也能继续编辑并保存草稿。标注不持久保存 sessionId，提交时也不重新读取全局当前目标来改绑草稿。

不同创建入口有各自明确的提交时机：

| 用户动作                         | 提交行为                                         |
| -------------------------------- | ------------------------------------------------ |
| 添加书签、创建高亮、标记当前画面 | 取得完整目标后直接创建，不要求补填标题或批注     |
| 打开新标注编辑器准备填写批注     | 保留编辑草稿，明确保存时创建；取消不保留占位记录 |
| 编辑已有标注                     | 保存实际修改；取消保留原记录                     |

先创建高亮、再编辑批注是两次独立操作。取消后一次编辑，不会撤回已经创建的高亮。修改普通标题或批注不要求源文件在线。重新选择内容目标时，必须采用相互对应的文件、位置、摘录和画面。调整文字选区表示选择新内容，因此更新位置和摘录；重新定位表示恢复原内容的对应位置，因此保留原摘录和批注。视频在同一文件内调整范围或明确重取图片，遵守[时间与画面规则](#video-values)，允许保留其他内容值。所有操作均通过完整的 update 校验，不为每个界面按钮增加专用方法。

并发检查只核对实际相关的基线，例如修改批注不能覆盖另一处刚更新的标题。目标删除或冲突发生时保留草稿，不为标注另设全行 revision 或恢复历史。附件准备遵守[附件合同](attachments.md)，不能为了挂图插入空标注。

查看、检索和编辑标注属于 library；返回内容则由界面通过 sessions 组织。游戏展示已保存画面，其他类型使用文件和位置。内容不可用时，标注继续保留，并提供明确的重新定位操作。get 本身不打开窗口，library 也不反向调用 sessions。提交成功后，由 library 发出变更并使相关查询失效，使用界面据此更新标记；阅读内核不维护另一套永久标注库。

# Kana 资源执行与部署验证

2026-10-20，按已确认的[资源加载与部署](../../../design/projects/kana/resources.md)验证执行机制。最终采用原生可转移 ReadableStream；书籍路径、授权输入和公开 Reader 合同保持原有边界。这里是设计机制证据，未运行生产 Reader。

## 试件与来源

[run.cjs](run.cjs)启动三个隔离浏览器和[隐藏 Electron 窗口](electron.cjs)。[fixture.cjs](fixture.cjs)只提供程序资产与自建控制页面；虚拟书籍地址由 Service Worker 响应。没有读取真实出版物、上传用户文件、安装依赖或修改系统配置。

[owner.js](owner.js)拥有本次源、内容占用与取消，[bridge.js](bridge.js)适配字节源和原生流，[worker.js](worker.js)将流用于响应，[storage.js](storage.js)验证顺序快照写入与保留字节限制，[cases.js](cases.js)检查完整调用链。结果、全部脚本摘要、固定浏览器基线及 Electron 可执行文件摘要见 [runtime-contract.json](runtime-contract.json)。

| --------------------- | ------------------------------- | ---------- | ------------------------ | -------------- |

| Firefox 测试浏览器    | 153.0                           | 通过       | 通过                     | 通过           |

## 选择原生流

先运行了[分块消息候选](../kana-resource-chunks/comparison.md)，再使用同组生命周期与部署检查比较原生流。四个环境均能真实转移并消费 ReadableStream，原生路线也完成了后续全部检查，因此采用原生路线；分块消息实现只保留为历史对照。

原生转移后，字节流量与背压由平台传递，控制消息负责元信息、取消和实际结束。没有保留一套根据浏览器选择的备用 chunk 协议。

直接暂停消费时，各环境在首次需求前取得一块，消费第一块后至多再预读一块，随后保持停止。本次单块上限为 64 KiB，8 MiB 的测试源只取得 128 KiB，取消后释放占用。有限预读是原生管线行为，不能把流转移描述成零预读或零拷贝。

正式维护线的能力另由 [Safari 27.0 发行说明](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/)和 [WebKitGTK 2.54 发行说明](https://webkitgtk.org/2026/09/16/webkitgtk-2.54-highlights.html)核实；两者均列出可转移流。规范见 [Streams 的转移定义](https://streams.spec.whatwg.org/#rs-transfer)。这些来源支持机制选择，不替代实际端口验收。

## 字节、读取许可与取消

四个环境均执行以下检查：

| 检查           | 实际结果                                                                  |
| -------------- | ------------------------------------------------------------------------- |
| 完整读取       | 2 MiB 响应逐字节核对通过，嵌套 CSS 导入可用，结束后占用归零               |
| 缓冲所有权     | 提供方交付带偏移的视图；响应取得有限副本，提供方缓冲没有被分离            |
| 共享源         | 两份响应使用同一源，取消其中一份后另一份完整取得 1 MiB，两个占用分别释放  |
| 浏览器取消     | cancel 到达实际读取，原生流取消与源释放成立；没有继续取得完整 32 MiB 输入 |
| 拥有者关闭     | 第一块已交付后关闭，等待中的读取失败；等待实际中止完成后才结束 close      |
| 中途读取失败   | 已取得部分字节后发生失败，响应失败，没有报告完整结束                      |
| 清理失败       | 三项同时读取中，一项释放故意失败；仍等待另外两项，最后报告 readFailed     |
| 并发与排队取消 | 八项工作同时请求，最多四项实际读取、四项等待；取消后许可和队列均归零      |
| 前后台次序     | 当前阅读请求排在已经等待的后台请求之前，不改写已取得许可的所有权          |

提供方中止故意延后 80 ms 的场景确认 close 会等待它；清理失败场景的其他读取分别延后 80／120 ms 结束，首项失败没有提前结束整体收尾。这些时间是控制试件，不是生产性能承诺。

暂停页面的 Fetch 消费并不意味着浏览器立即停止内部读取。本轮暂停 200 ms 后，累计取得量分别为 Chromium／Electron 262144 字节、Firefox 2686976 字节、WebKit 983040 字节。它们是本次调度下的观察值，不是引擎上限；Kana 的分块和许可不能据此宣称控制了浏览器总内存。

受查取消通过原生流的 cancel 到达源；记录中的 FetchEvent.request.signal 中止计数为零。设计因此同时保留原生消费取消和内容拥有者的显式取消，不能仅等待 Request.signal。

## 拥有者消失与 worker 重启

三测试浏览器没有观察到 MessagePort 的 close 事件，Electron 观察到了。当前统一机制不以该事件作为唯一断开依据，而在尚未结束且没有进展的传输中核对端点。

四个环境都在元信息仍延迟准备时移除了拥有者 iframe，存活消费文档的请求以 410 结束。另一个延迟 1250 ms、拥有者仍存活的请求正常完成，说明检查间隔本身不是超时失败条件。打开阶段明确取消也结束了准备，未取得源字节，未留下任务。

Chromium 和 Electron 另通过测试 CDP 命令停止运行中的 Service Worker。正在等待的数据读取失败；拥有者确认执行实例已经更替后，中止并释放旧读取，不等待手动 close。随后同一个存活拥有者再次提供文档成功，书籍入口没有被替换成新文件。Firefox 和 WebKit 没有执行强制中断 worker 的用例。

这证明传输端的结束，不承诺已经销毁的页面还能执行异步 JavaScript 清理。真实宿主对借出文件句柄的回收仍遵守原有窗口和授权范围寿命。

## 登记、PWA 与版本协作

四个环境均检查：

- 根 PWA 继续控制宿主，已有章节仍由更具体的内容 worker 控制。
- v1／v2 作用域同时工作，旧章节不被新版本接管。
- 同页两份独立控制器通过各自路由身份分派；关闭一份不影响另一份，过期入口返回 410。
- 相同作用域已由其他脚本拥有时，返回 assetUnavailable，原登记保持不变。
- CSP 禁止创建 worker 时，明确返回 assetUnavailable。
- 取消尚在安装阶段的打开，不发布内容占用；共享静态安装可以完成并被之后的使用复用。
- 资源打开本身失败时返回失败结果，没有开始字节读取。
- 在旧版本消费已经结束后清理旧登记，新版本和 PWA 仍能继续使用。

并发检查曾发现：原生登记对象可以在脚本仍下载时已被枚举，此时 active／installing／waiting 都可能为空。最终使用原生 register 的完成路径取得尚未就绪的登记，再等待其 worker；没有将登记存在等同初始化完成，也没有另建登记重试系统。

v1／v2 是固定试件身份，未运行真实包升级器或最终资产构建。对活跃旧版本的保留责任已经明确；正式部署工具按此执行并验收。

## 临时存储与容量失败

Chromium、Firefox 与 Electron 在专用源的 OPFS 内创建 2048 字节文件，分段写入后读取 700–1600 的 900 字节，逐字节核对并删除自己创建的目录。WebKit 测试构建未提供该 API，记录为不可用，没有宣称其 OPFS 通过，也没有因此改变其他源输入的阅读能力。试件没有请求持久存储授权。

快照适配另执行真实 ReadableStream 消费与受控存储故障：

- 无临时存储时，96 KiB 输入能在 128 KiB 保留预算内完成。
- 1 MiB 输入超过同一保留预算后停止；第三块用于确认超限，随后取消，不消费余下输入。
- 第二次临时写入注入配额失败，已创建对象被释放，输入停止，没有转为整份内存快照。
- 创建临时对象被拒绝时，不消费输入，也不留下已创建对象。

128 KiB 是该边界试件的控制值，不是正式书籍大小上限。配额失败与创建拒绝是提供方注入的故障，未通过填满真实磁盘触发系统配额。

## 结束状态与证据边界

各运行环境结束时，内容入口、占用、正在读取和等待许可均归零，当前源的 CacheStorage 为空；专用登记与窗口随试验收尾。WebKit 将五项故意失败的响应同时报告为 page-error 事件，按受控失败记录，不能写成“所有环境零错误事件”。

本轮没有运行完整格式解包、实际出版物、最终资产制品、真实辅助技术或全部平台。它闭合资源执行与部署的设计疑问；格式展开与显示资源的具体容量、正式 Reader 实现及完整发行矩阵仍分别验收。

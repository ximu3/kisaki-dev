# 独立技术项目

四个项目分别维护仓库、公共合同、版本与发行。项目自身的技术规则在本目录定义；Kisaki 的业务归属和接入规则见[应用接入](../engineering/integrations.md)。

| 项目                                 | 责任与阅读入口                                |
| ------------------------------------ | --------------------------------------------- |
| [Vantage](vantage/README.md)         | 进程、窗口、前台观察、控制和单窗采集          |
| [Kana](kana/README.md)               | 文档解析、源定位、排版、阅读交互与资源        |
| [libmpv-node](libmpv-node/README.md) | libmpv 的 Node 绑定、可选视频输出与独立帧持有 |
| [oauth-relay](oauth-relay/README.md) | 通用授权中转协议、上游适配与部署              |

Vantage 和 libmpv-node 共同遵循[原生库运行与交付](native-runtime.md)，各自实现并拥有自己的原生能力。设计与实施进度统一见[实施状态](../../implementation/status.md)。

四个项目的运行覆盖按[运行覆盖与交付](../../verification/acceptance.md#runtime-coverage)判定，各目标分别记录运行结果与兼容性依据。

<a id="purpose"></a>

## 独立产品定位与实际消费

Vantage、Kana、libmpv-node 和 oauth-relay 均按可独立消费、独立版本与发行的长期技术产品维护。现有公共范围继续由各自合同定义；Kisaki 是明确的联合验收消费者，其当前调用集合不自动成为这些项目的全部公开范围。

| 项目        | 独立目的                                                                           | Kisaki 的实际消费                       |
| ----------- | ---------------------------------------------------------------------------------- | --------------------------------------- |
| Vantage     | 为 Node 消费者提供进程、窗口、前台观察、控制与单窗采集                             | 游戏实例监测、前台计时、窗口操作与截图  |
| Kana        | 为浏览器阅读器提供源定位、解析、排版、选择、内容读取及资源能力；纯值入口可独立使用 | 漫画和小说阅读、恢复位置、摘录与标注    |
| libmpv-node | 交付 libmpv Client API 的 Node 绑定，以及可选视频输出和独立帧寿命                  | 视频播放、轨道与截图、Electron 显示交接 |
| oauth-relay | 为明确注册的客户端提供独立授权中转协议与上游适配                                   | 来源授权、账号核验后的凭据采用          |

独立维护包括公开合同、示例、类型与制品消费、兼容性、发行说明及必要平台资源。测试样例证明实际消费方式，不据此宣称已经存在其他真实产品用户。库内验证各自承诺，Kisaki 验证新增的业务接入风险，不在每层重复整套用例。

各项目独立构建、消费和维护，编码规范遵守[归属规则](../engineering/conventions.md#ownership)。

本体的私有能力仍由本体拥有，例如恢复所需的不覆盖移动不扩入 Vantage。独立边界同样不替本体承担 Work、Part、Session、数据库与用户流程。范围依据与确认记录见[项目取舍](../../verification/evidence/technical-tradeoffs/2026-10-22/README.md#projects)，正式交付仍须通过各项目自己的完整验收。

<a id="delivery"></a>

## 仓库、制品与联合交付

| 项目                             | 独立交付内容                                                                                | Kisaki 接入验证                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Vantage / @ximu3/vantage         | 进程与窗口的观察、控制和窗口画面采集；公开 API、Rust 与 Node 实现、桌面接入、平台制品和测试 | 验证真实实例与窗口归属、集合监测、前台计时、恢复与聚焦、结束操作和截图                     |
| Kana / @ximu3/kana               | 阅读内核、源定位合同、配套资源和公开发行                                                    | 验证全部支持格式的阅读、位置恢复、选区标记和资源释放                                       |
| libmpv-node / @ximu3/libmpv-node | libmpv 的 Node 原生绑定、可选受管渲染与帧资源、平台依赖和公开发行                           | 验证主进程加载、Electron 纹理交接、轨道与采集，以及六个目标的制品                          |
| oauth-relay                      | 基于 Node 和 Hono 的通用中转协议、上游适配、配置、测试、仓库和部署                          | 按 [服务合同](../extensions/private-data.md#relay-protocol) 验证授权、取消、刷新和错误处理 |

Kisaki 与四个独立项目分别位于 F:/project 下的同名目录，仓库建立和来源存档按 [仓库规范](../engineering/repository.md) 执行。每个项目交付完整源码、工具链、锁文件、测试、发行说明、CI 和使用文档，并按自身环境提供 TypeScript 或 Rust 配置及所需原生制品。oauth-relay 的交付不以存在旧源码为前提。

正式 manifest 和锁文件引用可实际取得的版本及配套资源。私有联调使用固定提交生成的 tarball 和原生资源，不通过跨仓源码路径或 link 接入。联合验收记录所用版本、制品摘要和服务合同，并检查真实客户端调用；各项目保留独立版本。

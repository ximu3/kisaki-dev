# 实施工作包与完成门槛

工作包按职责与真实依赖组织，编号表示推荐接续顺序，独立项目可以提前并行。每个工作包完成自身范围的实现、制品和适用验收，项目文档、整体验收和首次公开发行分别由末尾工作包承担。产品规则见[设计目录](../design/README.md)，验收编号见 [A01–A33](../verification/acceptance.md#scenarios)，实际进度见[实施状态](status.md)。

<a id="boundary"></a>

## 完整交付

公共包、独立项目和各项官方扩展分别拥有完整的实现责任。每个实施工作包交付其范围内可实际使用的终态能力：公开合同、操作与对应界面、正常和失败行为、取消与清理、构建资源、适用制品、实际消费及验证共同满足要求。纯合同包完成接口、值约束与规范编码，工程工作包完成真实工作流；后续消费者负责自己的接入。

一个工作包可以按依赖分步实现。全部交付项完成后，才能把该包登记为已完成。接口声明、随包提供的调用文档、运行文案、发行说明和许可材料随实现维护；成篇项目文档由 W23 负责。后续修改属于缺陷修复、合同维护或新需求，已知的未实现操作和占位结果仍记为当前工作包未完成。

交付前，从正式入口审阅本次修改的操作，核对各模块的职责、操作结果和资源释放时机。涉及公共包时，一并检查构建后的类型声明。见[可读性要求](../design/engineering/conventions.md#readability)。

有界面的工作包通过正式入口交付所属页面、Dialog 或控件。实施前按[桌面 UI 设计基准](../design/ui/components.md#existing-ui)对照旧版对应界面，新增界面沿用同类部件。业务操作及预期结果以当前规格为准。各包以默认 100% 应用缩放完成[既有界面对照](../verification/scenarios/ui.md#baseline)，再按场景复验缩放边界。功能拥有者负责把动作接入适用的页面、菜单、快捷键、通知和公开链接，检查操作成功后显示的页面或状态、失败时的提示、草稿是否保留，以及返回时的位置。W24 在整套候选上复核跨功能体验。

本体业务先通过 desktop-contracts 定义的值、操作与参与接口实现，完成真实存储、资源和窗口路径。提供者、处理器及识别器通过本体登记接口验证完整调用、取消与释放；W18 消费这些已有操作，联合完成 SDK、宿主及全部跨进程业务接入。业务实现与扩展接入各有自己的完成边界。

实现与适用验收、项目文档和对外发布分别记录。W24 汇总固定候选版本的发布前整体验收，W25 完成本轮首次公开发行与发布核验，整体完成条件见[最终交付](../verification/acceptance.md#completion)。签署与隔离部署随所属工程取得证据，正式仓库接续、公开发布和生产服务切换按[首发规则](../design/engineering/releases.md#first-release)及已有授权执行。

所有交付遵守[共同原则、终态实现与可读性](../design/engineering/conventions.md#quality)、[代码与资源规则](../design/engineering/conventions.md#coding-style)、[界面文案](../design/ui/components.md#copy)和[文档归属](../design/engineering/documentation.md#owners)。

验证按[实际影响](../verification/acceptance.md#verification-scope)选择，目标环境按[统一交付边界](../verification/acceptance.md#runtime-coverage)判定，证据按[实际用途](../design/engineering/documentation.md#evidence)保留。

<a id="unexpected-issues"></a>

### 实施中的判断

从[全局设计与一致性](../design/engineering/conventions.md#global-design)确定变更的共同拥有层、同类入口和全部受影响的消费者。遇到原则、正确性、质量或技术实践问题，按[整体判断](../design/engineering/conventions.md#judgment)说明依据、选项和影响，由用户确定方向。模型、主要行为、公开合同、架构边界或交付范围的变化遵守同一规则。

已确认合同内的实现选择、缺陷修复与验证由实施者完成。依赖新决定的工作等待讨论，其他工作继续推进；已确认方向与已有授权直接落实。

| 工作包 | 交付对象 | 首次实际消费与接续 |
| --- | --- | --- |

| W13 | 来源获取与资料采用 | 本体调用参与接口并写入 W09 资料库 |
| W14 | 作品发现与扫描 | 新作品使用 W13 采用，已有作品使用 W09 登记 |
| W15–W17 | 共同使用会话与游戏、视频、阅读 | 分别接入 W10、W08、W11，使用 W09 的文件与记录 |

| W20 | 桌面制品、安装、更新及仓库发行流程 | 用已锁定的项目制品和隔离发行源验证 |
| W21 | 30 项官方功能扩展 | 按各自能力消费 W18、W19，需要中转的来源另消费 W12 |
| W22 | 首次与更新引导、三个官方译本 | 在完整英语基准和实际扩展上验证推荐、采用与语言切换 |
| W23 | 项目文档与协作入口 | 各对象按已验证的实现和制品分批交付 |
| W24、W25 | 发布前整体验收、首次公开发行 | 先固定和核对候选，再按授权接续仓库、公开发行与切换生产服务 |

W09 的编目、持有和记录可先接入 W06、W07。动画作品详情须消费 W08 的固定制品，打开实际文件并显示探测结果，才满足 W09 的完整交付条件。W14 的新作品发现依赖 W13 的资料采用，与 W09 的已有文件维护分别运行和报告。W15 的共同会话依赖记录、资源准入与窗口寿命，游戏专属接入另需 W10 的 Vantage。W16、W17 可以并行，分别接入 W15 的共同会话和各自的引擎。

W13、W14 先用符合合同的参与实现验证本体行为。W18 可先核实宿主的进程、登记和资源寿命，再按已就绪的领域挂接真实扩展调用，应用搜索汇集实际贡献。W21 按来源或导入器取得真实业务结果，需要中转的来源另依赖 W12。W22 先完成引导及其英语，再用正式业务操作验证三个译本和全部 33 项扩展的引导消费。各包的完整依赖与门槛见所属条目。

同一 A 场景可以覆盖多个交付对象。各工作包记录自身断言，W24 汇总发布前证据，W25 补齐实际发布与生产接入结果。

验收：A24、A26、A28、A31 的工程入口范围。验证记录注明对应输入、环境与实际结果。

验收：纯值、普通 CSS 和映射分别可消费，默认外观完整，包保持纯视觉职责；仓库外制品、声明、资源许可与接口说明通过 A23、A29、A31 的对应断言。

依据：[视觉基础](../design/engineering/workspace.md#visual-packages) · [共同外观](../design/domains/appearance.md)。

<a id="w02"></a>

## W02：extension-distribution

依赖：W00 与分发合同。

交付：扩展身份、manifest、registry、静态展示与本地化格式、兼容声明、规范化和纯校验，以及独立 Node 签名和验签入口。

依据：[扩展制品与信任](../design/extensions/distribution.md) · [作者仓库工作流](../design/extensions/development.md#registry)。

<a id="w03"></a>

## W03：desktop-contracts 与 desktop-localization

依赖：W01、W02 的实际公共值。

交付：desktop-contracts 定义完整桌面能力的 API、输入输出、编辑基线、错误、事件、参与接口与资源合同，以及调用方和实现方共同遵守的值约束、规范编码和运行时校验；覆盖资料、查询、写入、会话、管理、deeplink 与开发控制。desktop-localization 独立交付按领域维护的英语 ICU 源文、同源生成的关联消息类型、作者基准、译本校验与纯格式化能力。两个包分别提供构建制品与仓库外消费入口。

验收：同一值在各公开入口含义一致，查询与写入语义明确，公开声明不暴露校验库内部构造类型；类型、值约束与格式化在 Node 和浏览器中独立消费。消息键与参数关联、译本合法性、缺词的英语回退及字面标签规则成立。按 A03、A04、A23、A31 验证两个包各自的合同、制品和消费边界。

依据：[公共值](../design/domains/values.md) · [查询合同](../design/domains/library/query/contracts.md) · [写入合同](../design/domains/library/write/contracts.md) · [本地化](../design/ui/localization.md) · [接入协议](../design/engineering/protocols.md)。

合同包拥有接口语义及其值的合法性，不以函数是否有副作用决定归属。产品默认配置、预设、业务计算、匹配与结果选择、存储异常处理由所属本体能力实现；规范编码与必要校验随对应值维护。本工作包不建立本体业务源码；业务实现、对应测试、生成数据和资源随所属工作包交付。数据库 codec 消费所属值规则，实际存储接入仍由 W06 完成。

本地化包不持有当前译本、登记实例或窗口状态；本体 i18n 负责有效语言、生命周期、恢复与同步。SDK 在 W18 从两个包选择作者所需的合同、英语基准与校验能力，扩展作者仍使用 SDK 的纯作者入口。各能力的英语文案随所属功能继续维护同一源文，W22 核对完整界面覆盖与三个官方译本。

## W04：desktop-rpc

依赖：W00 与已确认的通信合同。

交付：环境无关的有限帧、握手、双向调用、通知、取消、错误交付和断连清理。真实通道的测试适配核对消息边界与资源寿命；窗口接入归 W07，作者与源码开发接入归 W19。

验收：独立消费者通过完整机制、声明与制品检查；Electron 窗口和 Node 父子通道试件验证序列化、取消、错误和断开。覆盖 A23、A31 的包合同断言；产品端点、就绪和退出分别由实际消费者验收。

依据：[通信分层](../design/communication.md#clients) · [帧与开发控制](../design/engineering/protocols.md)。

<a id="w05"></a>

## W05：desktop-ui

依赖：W01 与 Solid 2 工程基线。

交付[完整的公共 UI 家族](../design/ui/package.md#families)。Form、Field 和控件统一表单提交、关联与反馈，Dialog 统一区域、焦点和关闭，Toaster 统一文档队列。包维护控件密度、键盘交互、图表、Markdown、拖拽、样式与资源寿命，按家族子路径交付声明与 CSS Modules 构建后的普通 CSS。

验收：浏览器行为、完整视觉状态、声明、无 Tailwind 与宿主工具类消费、独立资源清理分别成立，满足 A18–A20、A23、A29、A31 的[公共组件与反馈断言](../verification/scenarios/ui.md#ui-package)。支持范围和真实环境由[视觉交付](../design/ui/package.md#delivery)核对。

依据：[UI 包](../design/ui/package.md) · [交互与可访问性](../design/ui/components.md) · [拖拽与虚拟化](../design/ui/virtualization.md)。

## W06：存储与原生基础

依赖：W03 与 W00 工程基础。

## W07：应用运行与设置

依赖：W01、W03–W05、W06。

交付：启动与退出、窗口接入、TaskRun、通用历史、事实事件、偏好、网络、主题与字体、英语运行文案及对应设置和任务界面。完整交付文件输入、附件与图片准备、受控读取及资源绑定，完成系统集成、运行保护、取消和收尾。

各业务通过已声明的执行、事实和退出接口接入。任务观察、业务执行和历史保存分别保持自身寿命；外观与字体从真实持久状态交付给窗口和后续 Webview。

接续 W00 的构建与打包能力，维护真实应用的程序输入和隔离运行入口，供后续业务、SDK 和作者流程复用。从源码会话和指定的打包候选分别核对窗口、数据库和退出行为。制品验证从部署路径加载原生资源并执行迁移。两条路径均通过后，退役已由正式应用用例接替的工程载体入口及其任务依赖。热更新状态保留、编译失败恢复和拒绝退出继续由开发工具的可编辑样板验证。

窗口控制通过 desktop-rpc 接入，main、preload 与 renderer 按公开合同和最小能力边界协作；启动、资料路径和窗口寿命随本包完成。

W07 拥有平台激活接收、待交付请求、窗口就绪与退出边界，首先用任务与偏好等现有目标验证冷启动和运行中导航。后续业务包把自己的原生目标接到同一入口，按该请求所需的窗口或后台能力决定就绪。W07 交付系统通知的目标恢复。发送方把可序列化的原生导航目标交给操作系统，运行端从点击载荷恢复目标，窗口就绪后交付一次。W20 负责安装登记和实际安装身份下的冷启动验收。

W07 建立正式桌面 UI 框架。各文档逐实例装配语言、外观、反馈和窗口就绪。主窗口拥有标题栏、侧栏、固定工具、应用菜单、已登记页面的内容出口和 Dialog 宿主。任务中心保留筛选、滚动和详情返回。偏好、主题、字体及系统集成从应用菜单进入，消费公共部件，按各自合同提交。在默认窗口及最小窗口以 100% 应用缩放核对[标题栏通栏分隔线与窗口操作](../design/ui/components.md#titlebar)、控件尺度、滚动视口和固定反馈，再复验缩放边界、键盘与嵌套焦点返回。W09 将资料库、展示柜和统计接入同一内容出口，并从有选择和位置的真实页面复走固定工具流程。[应用交互](../design/ui/components.md#layout) · [验收场景](../verification/scenarios/ui.md#baseline)

验收覆盖 A14–A16、A20、A27–A29 的运行基础、状态、资源与管理界面。需要安装身份的登记、升级和卸载在 W20 用对应载体验收，按环境分别记录。

依据：[任务](../design/domains/tasks.md) · [偏好](../design/domains/preferences.md) · [外观](../design/domains/appearance.md) · [网络](../design/engineering/network.md) · [附件与图片](../design/domains/attachments.md) · [受控资源](../design/domains/resources.md) · [应用生命周期](../design/architecture.md#lifecycle)。

## 独立项目交付

W08 和 W10–W12 各自拥有完整工程、公共合同、实现、测试、工具链与锁文件、平台资源、制品、可运行示例和发行流程。项目文档由 W23 在各自仓库完成，本轮正式接续与首次公开发行由 W25 执行。项目按[独立产品定位](../design/projects/README.md#purpose)实现全部公开范围，持续开发遵守[仓库合同](../design/engineering/repository.md)。

<a id="w08"></a>

交付：六目标桌面制品、完整资源装配、安装升级、便携模式、签署与许可材料，以及本仓库的发行工作流和输入校验；同时完成应用更新的检查、说明、下载准备、退出协调、安装交接、状态与界面。

本包完整实现并验证构建、安装与更新能力，使用实际应用候选和隔离发行源核对系统下限、目标载体、更新失败、恢复及资源寿命。源码与打包候选的基础运行入口由 W07 接续，后续功能与文档使用同一套已完成的构建流程。

按[通知激活身份](../design/engineering/build.md#notification-activation)交付各载体的登记与清理。用安装后的应用发出通知，分别在运行中和完全退出后从系统通知中心点击，核对程序身份、原目标和单次导航。

分别在安装、升级、卸载、便携模式和 AppImage 登记下检查协议、登录启动和 Linux 桌面组件。双击安装器提供的应用入口和用户创建的作品桌面快捷方式，验证冷启动及运行时打开目标。

分别从应用菜单、搜索和 SDK 导航打开更新对话框，核对下载或安装失败后保留的状态。有未保存记录或正在使用的作品时，取消退出后仍可继续使用，确认退出后才将更新交给安装器。

本包交付根工程的版本检查、说明生成、发布与说明更正流程。以隔离发行源验证桌面、公共包、官方扩展的版本选择，说明、签名索引及展示资源的一致性，以及并发和部分失败后的同源续办。W19 提供 kisx 的仓库工具，W21、W22 提供各自的实际安装包、展示资料与发行说明，W25 执行正式部署。

独立项目提供已经完成的目标输入，本包核对锁定版本在桌面中的装配与消费。官方扩展通过分发仓库安装，桌面不内置其安装包。W24 再以全部功能和文档就绪的候选版本核对最终待发布文件。

验收：A16、A23–A28、A31、A33 的桌面制品、更新及联合消费的发布前断言成立，干净 checkout 按锁定输入可生成正确目标，字节来源与签署结果可追溯。

依据：[构建](../design/engineering/build.md) · [应用更新](../design/domains/updates.md) · [发行](../design/engineering/releases.md) · [许可](../design/engineering/licensing.md) · [仓库](../design/engineering/repository.md)。

## W21：30 项官方功能扩展

交付：[官方目录](../design/extensions/catalog.md#catalog)中 01–30 项的完整功能，即 17 个资料与平台扩展、13 个导入器。每项分别完成声明的全部能力、页面、适用认证、私有状态、测试、资源、版本与独立 .kisx，并核对真实宿主、仓库外公共包和安装消费。

各来源随其声明的能力交付资料、凭据或账号、导入及同步页面。各导入器交付输入与范围选择、进度、取消和适用的继续操作；从已安装扩展的真实页面核对部分完成及重开后的结果。扩展自有页面的文案、显示和键盘操作由该扩展维护。来源解析、个人记录、卸载与独立更新按自身语义验证。各扩展按实际依赖分项实施和登记，通用机制复用拥有层证据；三个官方译本由 W22 与引导联合交付，成篇说明由 W23 完成。

## W22：首次与更新引导、官方译本

依赖：W07、W09、W13–W20 的本体与宿主能力，以及 W21 的 30 项完整功能扩展。

交付首次使用和更新推荐、固定入口的手动引导、分组采用，以及[官方目录](../design/extensions/catalog.md#catalog)中 31–33 项简体中文、繁体中文和日语译本。三个译本保持普通扩展的身份、激活机制、独立版本与 .kisx。

先完成引导文案并核齐各功能已交付的英语基准，再形成三个完整官方译本。通过首次启动、更新后、日常重新打开和 SDK 导航进入引导，验证明确目标的外部激活优先。使用全部 33 项实际扩展联合验证推荐、安装、激活、偏好、资料方案、扫描配置和展示柜的分组采用，以及语言选择与切换。功能扩展在进入本包前已经完成；引导与译本在同一工作包内完成相互消费。

onboarding 拥有推荐记录、待采用输入与采用编排，各业务模块继续拥有完整操作。引导通过明确的分组采用提交配置，已有成果使用正常单项保存；字段控件复用不改变两者的提交含义。核对主界面与独立窗口的导航、焦点、草稿、共同菜单、失败和退出体验，以及译本在真实界面、菜单、提示和无障碍信息中的完整呈现。

验收：A18–A23、A27、A29、A30、A32 及相关 R 要求的应用级入口成立。三个译本分别通过构建、独立安装和宿主生命周期验证，完整基准、实际界面与所交付译文一致，逐项结果见[交付清单](delivery-checklist.md#extensions)。

依据：[引导](../design/domains/onboarding.md) · [导航](../design/ui/navigation.md) · [视图状态](../design/ui/state.md) · [本地化](../design/ui/localization.md) · [官方译本](../design/extensions/languages.md)。

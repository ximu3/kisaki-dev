# TMDB 接入设计

TMDB 提供动画影片、标准季、分集及制作资料，并支持动画影片的本人连接、导入与同步。本文规定来源身份、字段、关系、应用配置、四个页面和源码职责。

<a id="scope"></a>

## 动画作品范围

Anime 继续表示独立管理的动画作品。同系列作品通过既有关系与合集组织，不为了容纳来源资料或个人记录增加整剧聚合条目、系列父层或影子对象。

| 来源对象      | 接入范围                                                                           |
| ------------- | ---------------------------------------------------------------------------------- |
| Movie         | 适用的独立动画影片，使用影片自身资料；没有真实分集时不补造分集                     |
| TV Series     | 仅作为搜索和读取真实标准季的上下文，不作为 Anime 候选或作品绑定目标                |
| TV Season     | 仅在标准季与本地独立作品范围一致时采用；来源季号不证明它等于作品实际发行季度       |
| TV Episode    | 采用真实分集身份及资料；所属作品、分集与附加内容的种类分别按已有合同核对           |
| Episode Group | 不支持，不作为搜索候选、可绑定和可读取的作品目标，也不作为内部读取或匹配的回退路径 |

TMDB 的标准季可能因连续集号容纳多个实际发行季度。范围不一致时保留未匹配，交由其他适用来源提供作品资料和分部清单；不能截取前 N 集、按年份猜边界、改名绑定整剧，或恢复剧集组读取来补齐范围。TV 即使目前只有一季、已经完结或与某季集数相同，也不增加作品绑定例外。

搜索命中的上层 TV 只用于发现和读取真实标准季，不交付为可采用的 SourceEntry，不创建本地条目，也不随季绑定保存为等价作品身份。季读取可以取得所需父级上下文，但不能据此把整剧简介、图片、参与名单或个人记录直接当作该季的事实。不读取剧集组方案或具体组，不提供组身份解析、选组设置或隐藏组映射。

<a id="search-and-names"></a>

## 搜索与完整季名

复用既有动画 Entry 搜索接口。扩展内部查询适用影片和 TV，并从 TV 命中读取真实标准季；最终可选择的对象仅为影片和标准季，不要求先创建上层 TV 条目。已知完整季身份时直接定位和读取，不依赖此前搜索状态。标准季是否对应目标作品仍按实际范围核对，不能因为成为候选就视为已经完成对应。

完整季名由 TMDB 扩展根据真实父标题与季名形成，例如“作品名 · Season 2”。季名已经以完整父标题开头或与其相同时不重复添加前缀；其余情况保留来源季名并加上父标题。不从搜索词、季排序位置或本地作品标题反造来源名称，也不把来源标准季号改写成未经确认的实际发行季度。

搜索 identification.name、resolve 的识别名称和 read 请求的 name 共用相同的来源命名规则与语言条件，最终采用到本体的 name。字段采用取决于本次明确选择的 fill 或 overwrite，名称重新组合不会自动覆盖本地名称。

这类名称映射描述来源完整记录，仍只是普通名称线索；不能替代完整来源身份、唯一对应及归属核对，也不使 TV 与季成为等价身份。原名与别名分别依据实际来源资料，不把当前语言的完整名称自动当作原名。

动画名称搜索可以使用 multi search 的来源顺序，过滤人物与不适用作品；影片形成候选，TV 命中只用于读取并展开真实标准季。父命中顺序保留，所属季按明确季号组织。不能从名称猜动画类别，缺少类型依据时补读实际资料。

每次取得有界候选批次。游标保存来源页、页内位置及必要的季位置，绑定同一查询、语言和搜索设置；不保存搜索会话实体、不携带凭据，也不成为作品身份。过滤后的空页仍按真实游标判断是否结束。搜索阶段不读取所有分集详情、全部演职员和原图，候选展示使用共享搜索器及既有字段。

人物与公司使用各自名称搜索；播出机构只按已知身份或真实作品关系进入。完整 Movie、Season、Person、Company、Network 身份可以直接定位；已有分部通过作品读取中的明确 refs 定向读取，不增加 Part 搜索或独立定位入口。跨站查找仍须核对返回资源的种类和范围，不能把 TV 结果直接当作 Season。

<a id="identities"></a>

## 来源身份与重新读取

source 使用 tmdb，来源身份沿[共同合同](../providers.md#identity)保存。影片使用 movie/{movieId}，标准季使用 tv/{seriesId}/season/{seasonNumber}，分集使用 tv/{seriesId}/season/{seasonNumber}/episode/{episodeNumber}，完整来源坐标与本地名称、编号及排序分别表达。上层 tv/{seriesId} 只作为扩展内部读取坐标，不生成作品绑定。

来源身份只表达其真实对象。上下级关系、目前成员相同或一次弱匹配，不自动使 TV、标准季和分集成为等价身份。单纯读取、搜索和换图不保存绑定；正式采用时仍核对既有身份与本地归属冲突。

TMDB 提供者不接受上层 TV 或剧集组作为作品读取目标，不生成其作品候选或绑定。通用外部身份的保存、离线查找、应用寻址及备份继续遵守本体合同，不为 TMDB 添加特殊数据库结构或联网验证。目标缺失、范围冲突及读取失败时保留本地资料，不替换成上层整剧或其他标准季。

<a id="reading"></a>

## 按需读取

read 按本次字段、关系和 refs 请求组织。会话只缓存当前实际读取所需数据，同一来源记录和语言的数据可以复用；不能因为底层详情返回更多字段就扩大输出或采用范围。引用明确的分部可以定向读取，清单读取才取得本季实际成员。关系集合完成本次所需分页后交付，不能把截断结果声明为完整。

图片候选按用途和支持对象读取，先交付资源信息，界面只加载可见预览。正式下载、附件保存、裁剪和更换由本体已有流程处理。图片地址、尺寸和格式遵守来源配置及现有附件能力，不用猜测文件尺寸创造新的用途。

## 普通字段与取值

| 来源对象                   | 提供的本体字段                                                                                                                                                               | 范围要求                                                                                              |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 动画影片                   | name、originalName、aliases、description、primaryImage、externalLinks、isNsfw（仅明确为 true）、releaseDate、originalLanguages、backdropImage、titleLogo、declaredDurationMs | 名称和正文取本作实际资料；原名来自 original_title，原作语种来自 original_language，片长为原版影片片长 |
| 标准季                     | name、aliases、description、primaryImage、externalLinks、releaseDate                                                                                                         | name 使用已确认的完整季名规则；其他字段来自本季记录，不继承整剧简介或图片                             |
| 已明确身份的分集或附加内容 | name、aliases、description、primaryImage、externalLinks、releaseDate、declaredDurationMs；仅 Episode 提供 numberLabel                                                        | 各字段来自该分集资源；Extra 不增加编号字段，读取不改变既有种类或归属                                  |
| 人物                       | name、aliases、description、primaryImage、externalLinks、birthDate、deathDate、gender                                                                                        | 别名不附会语言；没有真实原名字段时不把主名或某个别名猜成原名                                          |
| 公司                       | name、aliases、description、primaryImage、externalLinks                                                                                                                      | 标识图作为组织主图；成立、解散日期缺席，不从简介或总部推断                                            |
| 播出机构                   | name、aliases、primaryImage、externalLinks                                                                                                                                   | 来源没有简介及成立、解散日期字段时保持缺席；与公司身份分开                                            |

别名只采用同一来源记录的真实其他名称、可核对的翻译名称或 alternative names/titles。季别名需要相应真实父标题与季名，沿同一完整名称规则形成，不将来源的通用季标签单独加入作品别名。只有拼接名称使用父级命名上下文，不因此扩展其他字段的继承。

正文按来源实际格式转为本体 Markdown，保留段落，不把宣传 tagline 拼成来源未提供的简介。字段缺席不返回清空值。原作语种、当前资料语言、片中出现的语言与译配语言分别处理；不把 spoken_languages 或当前界面语言直接写成 originalLanguages。

<a id="dates-and-values"></a>

## 日期、时长和状态

[发行日期规则](https://www.themoviedb.org/bible/movie/59f3b16d9251414f20000009?language=en-US)表明，TMDB 默认主日期会优先选院线上映，其次才是首映和其他发布，因此不能直接把默认主日期当作全球首次正式公开日期。

影片从 release_dates 的同作正式公开与发行记录中确定最早可信日期，包含已明确的公开首映；明确的其他版本专属记录不作为原版首发。日期按来源日历分量读取，不按用户时区换算成前一天或后一天。标准季和分集采用自身 air_date；缺少可信依据时保持未知，不用当前日期、最新分集日期或本地文件时间补足。

[基础资料规则](https://www.themoviedb.org/bible/movie/59f3b16d9251414f20000001?language=en-US)要求影片片长使用原版、包含片尾，并以分钟向上取整。正值换算为毫秒时保留这份资料精度，不宣称得到精确文件时长；零或缺失不能作为已知零时长。分集采用自身片长，不用 TV 平均片长，也不将分集相加生成作品声明总时长。

同一规则还说明，来源可能在全球首映前四天自动改为 Released。这与本体的发行结束不严格同义。TMDB 不提供 releaseStatus，也不从日期或当前目录推断 releaseEndDate、正片声明数和特别篇声明数。电影预算、票房、热度、站点评分和投票数不作为本体普通资料或个人评价。

adult 标记主要用于硬核色情，不等于全部敏感内容。影片 adult=true 时提供 isNsfw=true；adult=false 时省略该字段，不能据此清除本地已有敏感标记。人物职业或关联作品的成人属性不直接成为该人物档案的敏感标记。

<a id="images"></a>

## 图片读取与候选

| 对象               | 实际图片用途                                                         |
| ------------------ | -------------------------------------------------------------------- |
| 影片               | posters → primaryImage；backdrops → backdropImage；logos → titleLogo |
| 标准季             | 本季 posters → primaryImage；不把整剧背景图和 logo 作为本季字段      |
| 分集与已知附加内容 | 本资源 stills → primaryImage                                         |
| 人物               | profile 图片 → primaryImage                                          |
| 公司与播出机构     | logo 图片 → primaryImage                                             |

图片请求按用途读取对应集合，不用尺寸或裁剪把海报推成背景图、标题 logo。来源不提供某用途时省略字段，不返回空集合假装已确认没有图片。实际回答为空与读取失败继续遵守共同合同。

独立图片候选搜索复用已支持的影片、标准季、人物和公司查找能力，按字段返回实际图片；播出机构依靠已有身份，分集图片通过已知身份或明确目录读取，不增加 Part 搜索。上层 TV 继续只作为季查询上下文。

正文语言可以按 TMDB 支持的语言与地区请求，图片通常只有语言标记，不能把 zh 图片自动认定为简体或繁体。首选语言和回退由资料方案提供，不在扩展页面复制一套字段语言或来源优先级。

<a id="parts"></a>

## 分集读取与已有记录

已明确身份并确认属于当前作品的分集，可以直接补充自身字段，无须本地作品具有同源根身份。例如 tv/209867/season/1/episode/29 始终指向该标准来源分集，不因本地将它排在第一位或修改编号而改变。

没有准确作品范围或分集身份时，不承诺从宽泛的整剧目录自动发现和对应某个独立季度的分集。作品范围清单更新与已有分部字段更新仍遵守[共同采用规则](../../domains/metadata.md#update)，读取上下文不扩大本次写入范围。

资料更新复用稳定本地 ID、文件关系、首选和个人记录。来源漏项不删除已有分部，本地改名、改编号和重排不产生另一套来源身份。清单与字段的更新分别处理，详见[动画分部规则](../../domains/anime.md#identity)。

标准季清单只采用该季实际回答的分集，不从数量声明补出成员，也不自动读取并混入整剧的零号季。零号季的 Specials 是宽泛来源分类，不能直接等同于本体 Extra 或一种固定附加内容类型。

已明确身份及本地归属的零号季资源仍可定向补充公共字段。episode_type 所表达的普通集、季中或季终等集次位置，不能直接当作 regular、special 或 Extra 分类；分类没有同义依据时保持缺席，不撤销用户已有的种类更正。

<a id="people-and-organizations"></a>

## 人物与组织的搜索和身份

| 对象     | 搜索与定位                                                |
| -------- | --------------------------------------------------------- |
| 人物     | 支持名称搜索，也可按 person/{personId} 直接定位           |
| 公司     | 支持名称搜索，也可按 company/{companyId} 直接定位         |
| 播出机构 | 不提供名称搜索；按 network/{networkId} 或实际作品关系读取 |

人物、公司和播出机构使用各自真实资源身份，不因编号相同或名称相近合并。它们的普通字段遵守[取值目录](#fields)。

<a id="participation"></a>

## 人物与组织参与

影片人员从本片 credits 读取；标准季人员从本季 credits/aggregate_credits 读取，必要时使用本季实际分集署名。当前作品之外的参与不能因同一人物或公司出现而并入。

配音采用依据是来源的原版署名约定及明确的配音工作，仍遵守[原作语种范围](../../domains/relations.md#voice-scope)。明确译配或不属于当前作品的署名不采用；不能以人物母语、界面语言或职业标签推断配音语种。来源无法按这项约定确认范围时，沿资料完整性合同处理，不把未经核对的混合名单声明为原配名单。

人物职责使用实际 job 与署名范围映射。例如明确的 Series Director 对应 director、Series Composition 对应 seriesComposition、Storyboard 对应 storyboard、Key Animation 对应 drawing、Animation Director 对应 animationDirector；原始细项在所选 note 中保留。Director 不能在所有资源层级无条件解释为同一种工作；无法可靠细分的真实参与使用 other，不从 known_for_department 推断职责。

角色文字和 credit_id 不形成 Character 身份。配音工作没有可靠角色实体端点时保持角色为空，把实际角色文字放在关系说明中；不按同名角色自动与其他来源的角色绑定。同一人物在同一作品中的相同职责按共同业务键归并，细项说明按实际事实合并。

公司出现在 production_companies 中并不证明它负责动画制作。无法细分的真实制作参与使用 other 并保留原始说明，不按公司名称或通常业务改为 studio。播出机构使用 other，并在所选 note 中注明首播机构；没有这种实际范围依据时不建立参与关系。

| 关系读取方向      | 采用范围                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------- |
| 人物 → 影片       | 本人实际 movie/combined credits 中适用的动画影片                                                     |
| 人物 → 标准季     | TV 署名经 credit 详情取得明确 seasons 或可核对分集范围后，才形成对应季的参与，不把 TV 署名复制到每季 |
| 公司 → 作品       | 明确参与的动画影片；不从 TV 的 production_companies 推出逐季公司参与                                 |
| 播出机构 → 标准季 | 先发现相关 TV，再核对具体季自身的 networks，仅采用明确包含该机构的季                                 |

官方 credit 详情提供人物反查所需的实际季范围，known_for 仅供搜索摘要使用。关系读取须完成相应资源的分页、署名和范围核对。

作品根的 organizationWorks 使用 other 范围；Organization 根使用 scope:null：Company 反查只覆盖影片，Network 反查只覆盖标准季，两者都不能代表该组织全部 anime 参与。人物关系覆盖本页支持的实际 job 映射，workTypes 限于 anime、character 为 none。会话固定这些范围，成功结果返回普通数组；补充资料与移除旧关系分别按共同采用合同处理。

<a id="tags-and-relations"></a>

## 标签与作品关系

动画影片将自己的 genres 与 keywords 作为普通标签候选，保留来源名称并按本体 nameKey 去重，不虚构标签说明或敏感标记。标准季没有自身标签接口时，不直接继承整剧标签。

belongs_to_collection 表达来源影片合集成员，不单独证明前传、续作、重制或改编关系，也不自动创建本地合集。TMDB 不提供 workCharacters 或由合集、推荐、相似作品推导的 workRelations。用户的手动合集与本人清单导入保持已有独立入口。

<a id="application-access"></a>

## 应用访问与普通配置

统一使用 TMDB 的 API Read Access Token，供 v3 资料与 v4 授权流程使用，配置项称为 API 访问令牌，不重复提供另一份 API Key 选项。保留项目默认应用配置与用户自定义覆盖；正式发行需要准备并核实有效的默认应用凭据，尚未验证时如实显示配置状态。

凭据从个人 TMDB 账号的 [API 设置页](https://www.themoviedb.org/settings/api)申请，官方称为[申请 API 访问](https://developer.themoviedb.org/docs/getting-started)。API Key 和 API Read Access Token 都用于[应用认证](https://developer.themoviedb.org/docs/authentication-application)；前者也可用于[部分 v4 GET 请求](https://developer.themoviedb.org/v4/docs/authentication-application)，统一采用后者是为了覆盖本扩展的完整请求和授权流程。填写应用令牌不自动建立本扩展的本人连接，用户 access token 与 v3 session 仍由[本人连接](#account)取得。

[本人接口实测](../../../verification/evidence/tmdb/account-api.md)发现：当前自有应用与同一账号的组合中，应用 Read Access Token 也能读取本人私密测试列表。因此凭据范围以实际授权和验证结果为准，`api_read` 名称本身不保证只读公开资料；该结果也只适用于已测账号组合。

私人操作通过本人的连接及用户凭据确定归属。v3 请求可以同时携带应用认证与用户 session，不以单独的应用令牌代替用户连接。发行前核对默认应用凭据的可读范围及登记账号承载的资料，确保分发凭据不会暴露维护者的个人内容。

| 配置                       | 初值与含义                                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------------------------- |
| 应用访问凭据               | 优先使用明确的自定义值，否则使用已准备的项目默认值；界面只显示来源与配置状态                             |
| API 根地址                 | 默认官方 API 地址；版本路径由客户端分别组织，允许明确设置兼容的 API 服务地址                             |
| 图片地址                   | 默认官方图片服务，允许明确覆盖；不由 API 失败触发隐含镜像回退                                            |
| 搜索包含 TMDB 成人标记条目 | 默认开启，可手动关闭；仅影响名称搜索及依赖名称查询的定位，不改变已知身份读取、本人清单范围或库内敏感标记 |
| 单次请求超时               | 默认 20 秒，保留有限、有效的自定义值                                                                     |
| 读取重试次数               | 默认 2 次；只对已知安全的读取操作适用，不盲目重放写入或授权交换                                          |

地址、超时、成人搜索和读取重试能力在当前扩展中已有使用场景，重构保留这些明确配置。它们属于本来源设置，不成为 MetadataProfile 的逐次 options。语言、字段优先序、来源匹配和字段加工仍由本体资料方案管理。

保存配置与联网测试分开。格式合法的配置可以保存，测试失败如实报告；配置保存不启动导入或同步。正在执行的业务使用开始时的配置与账号快照，不能中途切换端点。恢复普通默认设置与清除自定义凭据分别操作，不连带清除本人连接或本地资料。

<a id="account"></a>

## 账号与个人接入范围

资料读取的应用访问令牌与本人账号登录分别管理。本人连接采用一次 v4 浏览器授权，取得用户 access token，再通过官方转换接口取得所需的 v3 session；用户不执行两次登录。用户 access token、session_id 及自定义应用凭据沿扩展私有秘密合同保存，回调、核验、换账号与断开连接遵守[共同授权边界](../private-data.md#authorization)。不增加来源未定义的 OAuth 授权码、PKCE 或 refresh token 流程。

v4 授权结果的 account_id 是其 account object id，v3 account 的 id 是对应数值身份，按各自端点分别保存和使用。本次实测以用户 bearer 与转换后的 session 读取 v3 account，确认同一用户；应用凭据的登记者身份不代替连接用户的身份。

个人记录读取、导入与出站同步仅采用已准确对应的动画影片。TV 记录、标准季和分集不参加个人记录接入；不将 TV 评分、收藏、待看或列表成员拆成多个季，也不把单集评分转换为完成标记。自定义混合列表只采用适用的动画影片成员，其余成员按不支持范围报告。

页面按[账号、资料采集、导入、同步](#pages)组织。账号页管理本人连接，资料采集页管理应用访问配置，资料方案仍由本体拥有。导入与同步分别配置，自动执行默认关闭；评分转换遵守[明确的来源刻度与共同舍入规则](#rating-precision)。

<a id="import"></a>

## 本人影片导入

可选来源为本人的收藏影片、待看影片、已评分影片及明确选定的本人自定义列表。完成必要分页后，只采用符合动画范围的 Movie；混合列表中的 TV 和真人影片不导入，也不展开为标准季。相同 movie 身份在多个所选清单出现时复用同一目标，来源清单与本次采用字段分别选择。

新影片通过 ingest 正常创建，所选初始个人值与资料一同提交；已有影片只按本次选择采用个人值，不顺带刷新名称、简介或图片。调用已有完整操作，沿[共同导入合同](../synchronization.md#import)处理身份冲突、已存在对象及局部失败。

| 来源个人字段    | 明确选择该字段时的本地采用                                     |
| --------------- | -------------------------------------------------------------- |
| 本人评分        | 按实际分制转换；明确未评分时可以清除本地评分，不使用站点平均分 |
| favorite        | 采用来源实际回答的布尔值；缺席不作为 false                     |
| watchlist=true  | 设置 planned，保留已有完成历史                                 |
| watchlist=false | 不推断进行中、搁置或完成，不覆盖当前状态                       |

评分采用遵守[已确认转换规则](#rating-precision)：按本人实际十分制评分乘 10，再沿共同合同取最近整数，居中取较高值。来源未返回本人记录、字段缺席、无权读取或请求失败，均不能当作未评分或 false。评分、收藏、列表成员、影片片长及来源技术时间不生成完成历史、完成日期、完成次数或实际观看时长。

用户可以选择一个本地手动合集作为导入目标，只加入实际采用的影片。自定义列表仅用于读取和导入，不提供远端列表创建、编辑、删除或成员同步，也不维护列表与合集的长期镜像；远端移出列表不删除本地影片或合集成员。

私密列表使用本人 v4 用户凭据读取。本人列表枚举的 public 数值与列表详情的 public 布尔值分别按端点解析，不用通用真假转换掩盖异常结构。本次实测覆盖官网创建的真实私密列表；测试辅助的 API 创建请求出现 `public: false` 与返回公开状态不符的情况，不据此增加本扩展的列表写入或隐私修复功能。

自动导入沿[自动补齐合同](../synchronization.md#automatic-import)，默认关闭，只根据当前所选完整清单补齐本地缺项。已有影片不自动覆盖资料或个人值；连接、手动导入与自动导入均不隐式启用出站同步。

<a id="sync"></a>

## 影片个人字段同步

仅以本地为准更新明确选择、已绑定 movie 身份的动画影片。手动与自动执行共用相同规则；对象、字段和账号范围在执行前确定。评分、收藏和待看分别选择，不提供 TV、标准季或分集的个人同步。

| 本地字段                      | TMDB 目标                                                    |
| ----------------------------- | ------------------------------------------------------------ |
| 本人评分                      | 使用来源实际接受的分制与精度写入；远端取整不反向改变本地评分 |
| 明确未评分                    | 调用独立评分 DELETE；已确认未评分时无需写入                  |
| 收藏标记                      | 写入相同的 favorite 布尔值                                   |
| status=planned                | watchlist=true                                               |
| status=active、onHold 或 null | watchlist=false；不声称平台能表达完整本地状态                |

<a id="rating-precision"></a>

### 评分转换与确认

本体采用 0–100 整数，null 表示未评分。以下均以本次明确选择采用或同步评分为前提，按[共同评分合同](../synchronization.md#ratings)处理线性换算、舍入、越界与未评分。

| 方向或情况           | 接入规则                                                  | 示例                              |
| -------------------- | --------------------------------------------------------- | --------------------------------- |
| TMDB → 本体          | 本人实际评分乘 10，取最近整数；恰好居中向较高值取整       | 8.25 → 83；0.75 → 8               |
| 本体 → TMDB          | 使用 0.5–10、步长 0.5；有效区间内取最近刻度，居中取较高值 | 本地 87 → 来源 8.5，本地仍保留 87 |
| 本地 0–4             | 超出本接入的来源评分范围，保留本地并报告无法映射          | 0 不当作未评分，也不改写为 0.5    |
| 明确撤回评分         | 使用独立 DELETE；已确认远端未评分时无需写入               | 本地 null 表示撤回意图            |
| 来源返回四分之一分值 | 按实际值处理入站，不将其作为出站刻度                      | 8.25 不先改成 8.5 再导入为 85     |

2026-10-16 的[隔离游客实测](../../../verification/evidence/tmdb/live-api.md)确认半分代表值能往返，但四分之一分值的新增与修改表现不一致；2026-10-21 的[本人 session 实测](../../../verification/evidence/tmdb/account-api.md)补齐 0.5、8.5、10 的写入回读与独立撤回。本接入对新增和修改使用同一半分规则，不通过先创建另一分值再修改来绕过差异，也不从单个成功响应推断完整来源精度。

每次写入前取得必要当前事实，目标值相同则不重复写入。写入后按业务对象和所选字段有界回读；短暂旧值不触发立即重写。只有实际结果符合目标时才保存确认值，复查结束仍不能确认时报告未确认，保留本地值和其他字段已经取得的结果。200、201 或 success=true 不替代实际确认，也不因删除本地影片而删除远端记录。

不提供完成历史、完成日期、分部完成标记、实际观看时长、笔记或其他自由文字的持续同步，不增加执行前差异稿或逐项确认页面。

<a id="rating-watchlist"></a>

### 评分与待看的来源联动

TMDB 的评分 POST 默认会将影片移出待看列表，账号设置可以改变这一行为，但已核对的账号状态响应没有提供该设置。不能仅因评分请求未携带 watchlist 就认定它不会修改待看。

- 同时选中评分和待看时，先处理评分，再核对和写入本次选定的待看目标。各字段分别报告，不承诺跨端点共同原子成功。
- 只选评分时，正常提交需要新增或修改的评分，接受平台依其账号设置移出待看的行为；有界回读评分及实际待看结果，不因待看未选而拒绝评分，也不补发恢复待看的请求。
- 已有评分已经等于目标值时不发 POST，不因待看为 true 报告无法同步；明确撤回评分仍使用独立 DELETE，不能用特殊分值代替。
- 不自动扩大字段选择，不用补偿写入恢复未选字段，不修改账号全局设置，也不增加补选字段或前置设置向导。

这项行为遵守[平台原生写入](../synchronization.md#writes)合同。来源待看联动不改变本地当前状态，不触发反向导入或循环补偿。平台没有条件写入时，不宣称读取前后核对可以阻止同时发生的远端修改。

自动同步默认关闭，沿[共同触发与连接寿命](../synchronization.md#automatic)执行。关闭页面不取消任务，关闭自动开关停止后续触发；换账号成功后停止旧任务后续调用并关闭自动功能，断开连接保留本地资料及平台记录。

## 四个页面

| 页面     | 用户可见的完整职责                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 账号     | 当前账号与连接状态、浏览器连接、换账号、断开、进行中授权的观察和取消                                     |
| 资料采集 | 应用访问配置、API 与图片地址、成人搜索、超时和读取重试、连接测试、恢复普通默认值                         |
| 导入     | 本人清单选择、适用影片浏览与选择、资料方案、个人字段、已有对象采用选项、可选手动合集、执行与独立自动补齐 |
| 同步     | 明确的本地已绑定影片范围、评分／收藏／待看选择、手动执行、独立自动同步、任务与最近结果                   |

账号页不保存其他页面尚未提交的草稿。普通元数据读取只需要有效应用配置，不因没有本人账号连接而被禁用。私密本人清单和个人写入则需要已核验的本人连接，不提供临时游客评分或密码代登录分支。

导入清单和采用字段分别选择；影片在清单中出现不自动采用所有个人值。自动导入始终只补缺项，不继承手动导入中覆盖已有对象的选项。同步范围可以是全部符合条件的已绑定影片，或明确选择的本地合集范围；未绑定和不属于影片范围的对象不会被补建后推送。

评分、收藏和待看首次由用户明确选择，之后可以记住配置；自动功能另行开启，默认关闭。评分与待看的来源联动在同步说明和实际结果中准确表达，不增加逐项确认、差异稿或补选字段向导。

页面使用项目已确定的 Solid 与基础 UI，复用表单、列表、任务反馈和焦点规则。表格保持一列一个字段，不把账号、状态或备注叠在名称下面。页面通过扩展私有 IPC 发起完整业务，不直接请求 TMDB 或读取秘密。

<a id="runtime"></a>

## 执行与数据归属

Node 拥有客户端、连接、元数据会话、导入和同步任务。页面关闭只释放该视图及其监听；明确取消、实例结束和连接更换按现有任务及账号合同处理。只有发起界面负责对应用户反馈，后台结果使用既有任务与来源状态呈现。

客户端统一处理请求、响应校验、有界并发和取消。429 遵守 Retry-After，其他临时读取失败采用有限退避；配额以来源实际响应为准。

安全重试依据操作含义判断。写入结果未知时先回读；授权交换等无法回读确认的阶段报告结果未知，由所属流程处理。

设置保存在扩展 values，用户令牌及自定义应用凭据保存在 secrets。公开元数据缓存可以有界保存并按端点、参数及语言区分；私人清单读取不形成第二份权威资料库，同步只保存必要的账号内字段确认值。没有永久已导入名单、隐藏对应表、独立资料中心或远端清单镜像。

日志记录操作类别、必要状态与安全错误摘要，不写令牌、认证头、完整来源正文、本人清单或完整响应。未知来源字段与枚举按各自边界处理，不根据错误消息文字控制业务分支。

## 署名与验收

在扩展的关于／来源说明区域使用获准的 TMDB 标识及其要求的说明，并保留官网链接；不为此增加第五个业务页面。发行时核对实际用途与来源授权要求，项目开源许可不代替上游资料授权。[官方说明](https://developer.themoviedb.org/docs/faq)

实施验收覆盖三个相连范围：

- 来源映射：影片／标准季／分集身份、完整季名、字段缺席、日期、分钟片长、正向敏感标记、图片用途、实际季署名与反查、跨站身份及不支持对象。
- 完整业务：无文件影片导入、已有对象所选个人值、手动合集加入、评分转换与待看联动、部分失败、取消和有界回读。
- 运行与界面：一次 v4 浏览器授权及 v3 session 转换、真实回调、凭据保存、换账号与断开、页面与任务寿命、自动开关、分页、429、配置快照及恢复默认。

公开 API 与游客评分已有[实测](../../../verification/evidence/tmdb/live-api.md)。回归样本包括半分代表值往返、异常小数新增／修改差异、回读滞后、Network 身份重复、SVG 候选与详情 PNG 地址。游客 Account States 的 401 和空列表的 404 不推广为普通本人账号的空值合同。

公开读取与游客评分的依据见[接口核验](../../../verification/evidence/tmdb/live-api.md)，本人授权、会话、私密清单与记录写入见[账号核验](../../../verification/evidence/tmdb/account-api.md)。测试辅助的列表创建只用于核验，不属于正式写入范围。

页面、任务寿命、秘密存储、取消与本体完整操作的运行验收在实现后进行。项目默认应用凭据属于发行准备，发布前需要核实有效性；游客结果和文档示例不替代上述核验。

字段依据见[资料映射核验](../../../verification/evidence/tmdb/metadata-mapping.md)，本人操作见[账号接口实测](../../../verification/evidence/tmdb/account-api.md)。

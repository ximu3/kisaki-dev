# Bangumi 目录成员范围

验证日期：2026-10-13。[观察数据](2026-10-13-directories.json)保存四次匿名 API 响应的必要投影，以及官方网页与固定版服务端源码的核对依据。没有读取凭据、写入账号或保存目录成员的完整个人评论。

## 网站目录与作品接口

| 实际目录                                        | 官网显示的成员 | 目录详情 total | /subjects 的 total 与数据 |
| ----------------------------------------------- | -------------- | -------------- | ------------------------- |
| [2023 个人年度单回](https://bgm.tv/index/49551) | 13 个章节      | 13             | 0，空数组                 |
| [大亮额头](https://bgm.tv/index/63502)          | 39 个角色      | 39             | 0，空数组                 |

四次 API 请求均为 200。/v0/indices/<id>/subjects 只回答作品 subject 成员，不覆盖网站目录能够收录的全部资源类别。返回空数组可以证明本次作品成员范围为空，不能证明整个目录为空，更不能据此清除已经导入的角色或其他成员。

目录成员必须按其实际资源识别。章节行同时显示其所属作品链接，但那部作品不是因此成为目录成员；角色行的标题链接指向角色本身，也不能通过同名作品搜索替换。单卷 subject 仍须沿已确定的作品与分部规则解释。

## 元信息与成员说明

官方 schema 与固定版响应定义提供目录 title、desc、total、nsfw、creator 和技术时间。IndexSubject 提供对象身份及 comment；写入合同另有 sort。comment 描述目录编纂者对这次收纳的说明，与被收纳对象的简介或查询者本人的评价不同。

来源目录的创建者不自动成为作品人员，目录技术时间不作为本地加入或完成日期。目录收藏数量也不是条目评分、喜爱标记或合集成员数。目录 nsfw 描述该目录包含敏感条目的情况，不能反向标记所有成员。

官方公开页面能够显示上述角色和章节成员。若设计采用这些页面补足成员范围，需要在 Bangumi 扩展内核对分类、真实链接、页面范围和完整分页；本轮没有实现或验收生产解析器，也没有把全部页面内容复制为本地笔记。

## 对后续设计的约束

本体合集只收纳七类 Entry，因此作品、角色、人物或组织与章节、卷等分部必须分别判断。不能为了导入目录而扩大合集成员类型，也不能把目录中的一集或一卷自动替换为其所属作品。仅取得目录中的作品部分时，界面与结果须准确说明采用范围。

目录导入、合集的本地编排与远端目录写入是独立的产品能力。本材料说明实际来源范围；是否补读公开网页、怎样采用说明和顺序，以及是否提供目录回写，仍由本轮接入设计讨论决定。

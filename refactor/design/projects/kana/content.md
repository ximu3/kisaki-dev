# Kana 内容与视图读取

文字提取、搜索、页内几何与稳定视图读取基于同一份源解释。

<a id="text"></a>

## 源文字、可读内容与搜索文本

三个层次分别保留自己的含义，但共用源映射：

| 层次       | 责任                                                                                   |
| ---------- | -------------------------------------------------------------------------------------- |
| 规范源内容 | 依照已确认的格式规则解释节点、字节、编码和页面；作为持久位置的依据                     |
| 可读文字   | 从本次实际正文或所选片段取得原文，处理内容角色、可见性和排版空白；每一片段仍对应源内容 |
| 搜索文本   | 为匹配生成临时转换结果，并保留转换区间到原文及源地址的对应；不写回原文或持久位置       |

格式不先被强制转换成统一 AST。上述对应由所属格式的源结构与 view 的呈现事实协作完成，selection、search、marks 和 getTextContext 复用它。不能以当前 DOM 编号、innerText 的长度或搜索结果字符串的下标代替源地址。

CSS text-transform 可以使源文字 Straße 的原生选择结果成为 STRASSE；ruby 的原生选择也可能把 base 与 rt 串在一起。原生 Selection.toString 和 innerText 用于核对浏览器行为，原文与位置仍由源映射及下述提取规则确定。

<a id="text-flow"></a>

## 原文与搜索的来源映射

格式按源顺序提供文字片段，保留所属阅读路径、内容角色、正文块和源端点对应。view 提供当前呈现的可读资格与空白处理事实，内容层据此生成原文片段，搜索消费同一结果。各格式继续拥有自己的解析结构与源位置，文字消费使用统一能力。

| 环节     | 采用的事实与输出                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| 源片段   | EPUB／FB2 的逻辑文字与节点路径，MOBI／KF8 的词法来源，TXT 的原始解码序列；PDF 使用页面文字与可靠四边形对应 |
| 可读投影 | 格式内容角色加实际呈现资格；正文、ruby 注音、独立注释分别形成可连续读取的内容，不把它们交错拼词            |
| 原文片段 | 原始字符、处理后的空白和结构 LF；每段保留源区间，结构分隔只有相邻源边界，不伪造节点                        |
| 匹配片段 | Case Folding／NFC 后的临时文字，保留转换区间到原文片段的映射；命中最终回到已有 TextRange                   |

普通文字采用连续区间映射；字符引用、多字符展开、折叠空白和规范化组合使用局部的多对一／一对多记录，不为整本书每个 UTF-16 单元常驻一个对象。视图中同一源片段出现多次时，摘录读取一次，高亮可以投影到多个显示片段。

HTML 修复可能改变显示顺序。两端确定正式源范围后，原文沿该范围所属阅读路径读取，显示层绘制它对应的全部片段；不改用最终 DOM 顺序解释已存范围。原生选择只提供候选端点，采用后的正式范围、可见高亮与交付原文必须一致。

文本处理沿同一正文块连续进行，跨 Text、解码块或存储页时接续空白、扩展字素与规范化尾部。真实块边界和显式换行产生结构 LF，跨章正文沿正文路径读取，独立注释使用自己的路径。源地址保存后，片段与显示文档按需要释放或重建。

空白处理读取适用的 white-space／white-space-collapse、语言和相邻内容，区分保留、折叠、保留换行等规则。软折行不变成原文换行；浏览器决定的段落源换行处理由[同一呈现适配](styles.md#readability)提供，不能拿字符宽度为零一律判成“没有文字”。CSS Text 明确保留了部分段落换行转换的浏览器选择，见 [CSS Text 的空白处理](https://www.w3.org/TR/css-text-3/#white-space-processing)。

适配按源片段执行已确定的空白规则，并用可回收的原生空白容器取得浏览器选择；容器只包含必要上下文、语言和空白设置，关闭 text-transform。它不接管源地址，不设置用户 Selection，也不从整章 innerText 反搜原文。普通保留区间与折叠区间分别记录映射，输出非空白字符须保持原输入。

## 摘录与邻近原文

原文采用以下规则：

| 内容                      | 取得规则                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| 正常正文                  | 保留源文字的字符、大小写、标点及 Unicode 组合形式；CSS 大小写转换不改写摘录                  |
| 普通排版空白              | 按实际文本空白规则处理折叠；软折行不增加原文换行，不能用全局空白正则代替所有 CSS 情形        |
| 显式换行及正文块边界      | 显式换行和相邻正文块之间保留换行；结构分隔使用 LF，重复结构边界不重复添加空段                |
| TXT、pre 及保留空白的正文 | 保留适用的源空格、制表和硬换行；TXT 的 CRLF 不因显示转换改变其源偏移                         |
| ruby                      | 普通正文采用 base，rt／rp 不串入正文；用户直接选择注音时保留该注音的原文和源范围             |
| 隐藏及非正文内容          | 脚本、样式、界面注入和不可见片段不进入当前摘录；可访问性属性不能单独代替视觉可见性判断       |
| 生成内容                  | CSS 计数器、伪元素、自动列表标号及布局插入的装饰字形不冒充源文字；实际写在源中的字符照常保留 |

原文可以包含按正文结构形成的分隔符，但这些分隔符不生成虚构的源节点或字节地址。选区端点仍指向真实源内容。源范围内存在未绘制的节点，也不要求把所有原始文本节点一律拼入摘录。

getSelection 固定本次调用的逻辑选区，再取得完整原文。只加载了其中几个章节时，继续按需取得其余内容；失败或资源不足则报告失败，不能把已取得的前半段作为完整摘录。不同块的源地址不从 quote.length 累加反推。

跨章节范围遵守[正文与独立内容路径](positions.md#order)。正文 A 到 B 的摘录沿正文路径取得，中间的独立辅助单元保留自己的范围。恢复时以源结构和端点判断是否属于同一路径，跨路径端点不能形成一次连续选择；用户访问历史不参与解释，也无需保存 flowId。

getTextContext 在指定点所属的可读正文块内取得邻近片段，最多 160 个 UTF-16 单元，并收敛到完整扩展字素边界。优先围绕点位选取；靠近块边缘时可向另一侧补足。它不跨入无关章节、另一段注音或尚未打开的注释内容来凑长度，不追加省略号或生成摘要。该位置没有可用正文则返回 null；存在内容但读取失败仍报告错误。文本超过预算而无法形成有效的完整字符片段时属于资源限制，不能伪装成没有文字。

TXT／XML 的源解码规则、CFI 与 MOBI 字节规则保持不变。历史 quote 是当时实际采用的文本；以后字体、排版或提取实现更新，都不回写已保存的摘录。

## 匹配转换与源命中

搜索以 Unicode 18.0.0 的标准数据作为本次基线。默认不区分大小写时，使用默认完整 Case Folding，再进行 NFC；caseSensitive 为 true 时只做 NFC。使用默认规则，不根据应用界面语言切换土耳其语等专用大小写规则。

NFC 允许由不同组合形式表达的同一文字互相匹配。搜索不默认执行 NFKC、去重音、简繁转换或假名转换。硬换行的 CRLF／CR 可以在搜索视图中对应为 LF，但原文及其源偏移继续保留。匹配转换的字节和字符长度不成为新的定位条件。

转换必须保留区间映射。例如 Straße 匹配 STRASSE，或跨两个源文字节点的 e 与组合重音匹配 é，命中都返回完整原始范围。多个转换字符来自同一个源字符时，不能生成半个源字符的地址；映射到同一源范围的重复命中只交付一次。扩展字素也可以跨展示 Text 节点，展示拆分不改变结果。

正文和 ruby 注音分别形成可检索内容；注音命中落在注音自身的源地址，不把正文与注音交错串成一个不存在的词。脚注等有独立阅读入口的内容保留自身范围和入口，不能因为当前未打开就永久丢失。纯脚本备用内容或实际无法呈现的隐藏内容不作为可跳转正文命中。

默认搜索覆盖可呈现的正文和独立辅助内容，并按源顺序交付命中。每次文字匹配限定在同一可读路径内，正文导航与搜索分别遵守自己的范围。

默认搜索顺序取得每个相关阅读单元的可读文字投影，逐段匹配并交付结果。必要的样式与资格核对在独立、可回收的内容范围完成，不移动用户当前页面，不让全书 DOM 或页面 canvas 常驻；辅助内容使用其实际可打开的内容上下文。后台承载位置不能通过给正文设置 display:none 等方式改变本来要判断的可读资格。

源文字预筛只作为可证明不会漏报的优化。不能先要求原始字符串中存在完整关键词，再过滤隐藏文字：`ab<span hidden>x</span>cd` 的可读结果可以匹配 `abcd`，折叠空白或跨节点组合也有同类问题。尚未加载与作者明确隐藏不是同一件事。

搜索保留本次采用的源解释和呈现配置，匹配状态随同一路径的文字流接续；进入另一条独立路径或正文／注音分支时结束前一匹配，不穿过边界拼词。连续正文中的结构 LF 可以参与包含换行的查询。每个结果恢复完整源范围后再交付，重复展开命中按源范围去重；excerpt 从对应原文取得，不使用大小写折叠后的字符串。

消费暂停时只保留当前单元、必要的匹配窗口和未完成的字素／规范化尾部。后续读取受迭代需求推动，已经离开的单元可以释放显示资源；完成完整 getSelection 所需的结果存储与搜索迭代的窗口分别计量。搜索按迭代需求推进，不依赖预先建立的常驻全书倒排索引。

wholeWord 使用 Intl.Segmenter 的 word 边界，优先采用当前内容合法且受支持的语言，缺失或不支持时固定使用 en。浏览器 ICU 的词边界行为纳入支持矩阵；版本变化可以影响检索结果，已保存的源地址保持原含义。默认 wholeWord 为 false。

PDF 的临时文字层可以参与匹配与选区，持久结果仍是原始页上的有序四边形，不采用文字项编号。扫描页或缺少可靠文字映射的内容按实际能力表达，图像本身不被自动当作已有 OCR 文本。

## 原始页面到当前视图

源页面先由格式解释成规范朝向与边界，再应用阅读显示变换：

| 来源      | 进入规范页面前完成的解释                            |
| --------- | --------------------------------------------------- |
| PDF       | 有效 CropBox、UserUnit 和文档固有 Rotate            |
| 图片      | 原始尺寸与文件内的固有方向信息                      |
| 固定 EPUB | 本次 spine 出现、实际声明的固定 viewport 与内容结构 |
| 固定 KF8  | 原始 skeleton 文档及其有效固定版式尺寸              |

规范页面的左上角与 0–1 坐标含义沿用[源位置合同](positions.md#selection)。显示裁边、缩放、平移、用户旋转、双页排列和容器位置由当前视图的可逆变换处理。双页与连续布局不合并原始页面身份。

selection 和 marks 共用正反变换。输入的明显越界、退化或自交几何仍须拒绝；库自己的浮点计算误差在形成公开值前收敛，不能把任意越界输入都夹回页面。几何判断采用适用精度，不要求浮点正反变换逐位相等。

公开的视图矩形使用 ViewportRect：left、top、width、height，单位为 Reader 所在文档视口的 CSS 像素。它与 NormalizedRect 的 x、y、width、height 不同，不进入 ReadingPageRegion。位置或范围先在 Kana 内映射，宿主不遍历书内私有 DOM 来重建转换。

## 稳定视图读取

Reader 提供 readView，让宿主在一个受管理的短读取范围中取得真实画面。Kana 提供目标、当前源位置和显示矩形，宿主提供实际像素读取；接口不依赖 Electron、NativeImage 或 PreparedImage。

```ts
const raw = await reader.readView({ type: 'viewport' }, async (view, signal) => ({
  location: view.location,
  image: await host.readPixels(view.rect, signal)
}))
```

目标为 `{ type: 'viewport' }` 时，回调取得当前实际位置、该位置的固定／重排版式和可见内容矩形。目标为 `{ type: 'region', region }` 时，回调取得已经验证的原始页面区域与对应矩形，不另造点位书签。两类结果在类型上关联；书签画面可以包含单页、双页或连续呈现，不能伪装成一张原始页面区域。

readView 进入导航与布局的同一执行次序。先等待此前接纳的更新和当前可见内容就绪，从准备阶段起持有本次视图，再取得几何并调用宿主。期间新的导航、设置和显示变换在其后接续；内部交互不会把视图换到另一页。已经运行的平滑滚动、影响几何的动画和待交付布局都须在读取前形成明确的稳定状态。

读取时保留书本实际内容及当前阅读配色、缩放、旋转和裁边，暂时排除 Kana 绘制的选区、高亮、标记框、控件和临时参考查看。书本本身的样式、背景和 authored mark 内容继续保留。结束后恢复这些显示，原选区和正式标记不被删除。临时显示排除不改变内容的可读资格、活动选区或已经固定的原文读取范围。

viewport 目标始终读取主阅读画面，region 目标仍属于主视图已经呈现的原始页面；临时查看不会暗中改变两者的对象。临时内容中的 getSelection、摘录和文字标注使用它自己的真实源范围。默认的当前阅读位置书签继续采用主位置；明确指定源位置的其他记录操作按原有 Annotation 合同处理。

区域必须属于本次文档、对应当前已呈现页面，而且请求的完整区域在当前可见范围内。缺失、未加载、被裁掉或部分位于视口外时明确失败，不截取交集代替完整区域，也不自动跳页或改变缩放。当前图片区域采集继续是 Kisaki 内部的 captureRegionImage(region)，不因此向 SDK 新增漫画／小说的 captureImage。

宿主窗口尺寸、缩放、挂载位置或其他无法在库内延后的变化，使本次几何失效时，中止本次读取并拒绝迟到结果。关闭和取消也会传递给读取回调；在回调尚未结束时，不能报告 Reader 已经全部收尾，再让旧读取碰到复用后的新内容。回调结果只有在范围仍有效时才成功交付。

readView 的回调只执行宿主读取，以及 getTextContext 这类不改变视图的有界内容读取，不调用或等待同一 Reader 的导航、设置、closeReference、再次 readView 或 close。这是保持视图期间的读取回调；后续编码、裁剪准备和记录保存在 readView 成功后继续。它与 observe 不同：此处 Promise 的结束明确决定读取范围何时释放，观察回调则仍是通知。

阅读书签也在同一个范围内选择内容：固定页面取得画面；重排正文先对 view.location 调用 getTextContext，有文字则采用原文，没有文字才读取同一视图的画面。原文读取失败直接失败。不能先在范围外读位置和文字，得到 null 后再截取已经移动的当前页面并沿用旧位置。

回调产生的资源归宿主，readView 不猜测任意 Result 应如何释放。若操作失效，宿主释放已取得但未采用的结果；取得独立原始内容后，后续处理可以在 Reader 关闭后继续。应用在开始操作时固定文件与 Reader 绑定，不在异步返回后读取“当前文件”来补归属。

viewChanged、targetNotVisible 和 unsupportedTransform 分别描述本次读取失效、目标未完整可见和宿主显示变换无法正确映射。接口与分类共同属于 Reader 和纯值合同，运行实现按这些分支验证。

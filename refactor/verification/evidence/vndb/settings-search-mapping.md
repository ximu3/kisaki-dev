# VNDB 设置、搜索与中文映射核对

核对日期：2026-10-12。[证据记录](2026-10-12-settings-search-mapping.json)保存公开搜索响应、网页顺序摘录、来源代码依据、映射材料的版本与校验值，以及范围投影结果。本轮没有取得或使用私人令牌，没有修改远端记录，也没有改动扩展运行代码。

## 适用度作为扩展设置

此前完整采集的决定保留为默认值。新增可选的适用度上下限，两端包含，0–3 内允许有限小数；非法或颠倒的范围不能保存，存储读取沿已有宽容读取合同。过滤使用来源实际数值，不能先四舍五入。lie 的排除、剧透标记及来源排序分别执行。

实际 v17 默认保留 198 项非 lie 标签，范围 2–3 时保留 102 项；v11 对应 195 项和 135 项。角色特征没有适用度，不因调整作品标签范围而缺失。设置仅影响未来的来源回答，正式保存仍服从主应用的采用范围。

## 搜索相关度与网页差异

核对时的旧项目实现中，searchEntity 已传入 sort: searchrank，见[当时引用的来源实现](F:/project/3/kisaki/extensions/vndb/src/host/api/client.ts)；本轮将它补为[正式搜索规则](../../../design/extensions/sources/vndb.md#search-order)。不能因为旧代码已使用，就省略新设计中的查询和分页合同。

实际公开查询分别对 VN 的 fate、Character 的 Rin、Staff 的 Asakawa 使用 searchrank、reverse = false、每页十项，三次均返回 HTTP 200。前两次 more = true，明确只是首页；Staff 样本 more = false，且含同一人物的多个署名。

[API 的排序实现](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/API.pm#L227)在相关度后按 id、subid 排序；[网页角色列表](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/Chars/List.pm#L117)、[职员列表](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/Staff/List.pm#L63)和[作品列表](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/VN/List.pm#L38)使用名称等后续条件。三组实际首页均有顺序差异，不能保证逐项一致。

设计采用 API 的原生相关度顺序，不增加本地模仿排序；别名归并保留首次位置，来源类型过滤保持相对顺序。按身份读取和无关键词名单不使用 searchrank，因为其需要明确的顶层关键词条件。

## 社区文本材料

[VNDB 中文翻译计划](https://github.com/mokurin000/vndb_chinese_translation)使用 Unlicense，其 README 指向“VNDB 优先原文和中文化”脚本。后者的执行代码标为 GPL-3.0，独立的 [VNDBTranslatorLib_ 数据库](https://greasyfork.org/en/scripts/445990-vndbtranslatorlib) v5.0.0、版本号 1315038 则标为 MIT，二者需要分开识别。

本轮静态解析数据文件的标签／特征映射块，读取了 5,438 个字面文本对，没有执行下载的脚本。其中有三个带粗译标记的值，并有 99 组规范中文名称重合；这些重合并不全是错误，但说明材料不能未经上下文校对就直接作为本体标签词典。

| 已采用的实际样本  | 原始名称精确命中映射      |
| ----------------- | ------------------------- |
| v11 的 195 项标签 | 190 项                    |
| v17 的 198 项标签 | 195 项                    |
| c15 的 97 项特征  | 97 项同时命中特征名和组名 |
| c42 的 52 项特征  | 52 项同时命中特征名和组名 |

这是文本命中率，不是译文质量验收。Romance → 恋爱、Science Fiction → 科幻可以核对其上下文；Short → 矮小/短 则不能直接作为发长特征的最终中文名。实际交付须整理静态词典、核对上下文及名称冲突，并保留来源与许可；无可靠映射的项目继续采用原文。

已确认中文作为[实际采集名称](../../../design/extensions/sources/vndb.md#chinese-tag-names)，不只是显示层替换。已有英文标签不会因开关改变而自动重命名；需要统一时使用主应用的标签管理。这一后果必须在设置中说明，不能隐含为无成本的语言切换。

## 角色字段与标签的分工

当前来源 traits 作为角色标签采用。已有年龄、生日、性别、血型和尺寸字段用于明确值、日期精度及数值查询；发色、瞳色、种族、性格等描述性特征使用标签。不因一个来源具有大量分类就将它们逐一扩成本体字段。

当前不增加发色、瞳色专属字段，也不引入通用自定义字段机制。开放颜色文字缺少相对于标签的明确查询收益，统一颜色分类则需要额外的语义与来源映射；现有需求采用可复用标签及其组合查询。来源特征保持这一分工，不通过解析标签名另建隐藏属性。

## 授权账号的后续核验

后续[授权只读核对](authenticated-read.md)已确认令牌、读取权限和空清单；另获授权的[三条临时记录测试](account-roundtrip.md)补充状态、评分、日期、分页与清理结果，并发现日期清空和零结果查询限制。自定义及私有记录、并发与完整扩展运行仍待验证。

临时令牌可以补齐目前未验证的真实账号行为。先用 listread 验证账号身份、权限、本人列表分页、私有标签可见范围、评分与日期缺项；只保留测试所需字段，公开证据记录结构与判定，不复制私人列表。

回写测试另需 listwrite，并明确测试账号、作品和允许字段，优先使用专门测试记录。取得当前业务值后验证修改、回读、未选字段保留与重复操作，再恢复获准恢复的业务值。源站 lastmod、vote_date 等技术时间不一定可还原，不能承诺测试后完全没有痕迹。

令牌通过本地临时文件或既有受保护凭据输入提供，不写进设计材料、脚本正文、命令参数或日志。真实成功路径与权限行为仍需和已有失败、范围及并发场景检查一起判断；一个账号的成功响应不等于所有来源边界都已验证。

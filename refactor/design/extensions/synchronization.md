# 平台个人记录导入与同步

来源扩展负责本人连接、清单导入和个人字段同步，调用本体已有完整操作。手动导入按本次选择采用平台信息，自动导入补齐所选清单中本地缺少的对象；持续同步以本地为准更新平台。账号、配置、写入确认值和自动触发由来源扩展保存和管理，本体继续拥有资料库。

<a id="scope"></a>

## 方向、对象与字段

连接账号不导入资料、不修改平台，也不启用自动导入或自动同步。用户分别发起手动导入、启用自动导入、执行手动同步或开启自动同步。持续同步只处理选定范围内已经绑定真实平台身份的本地对象；平台清单中的本地缺项通过手动或明确启用的自动导入创建，不由出站同步负责发现。

当前采用的同步方向固定为本地到平台，不提供双向合并、本地优先与平台优先之间的冲突选择。用户在平台修改已有对象的所选字段后，本地保持原值；后续同步按本地值核对和更新。采用这些平台修改须明确执行手动导入，自动导入不覆盖已有记录。

| 个人字段     | 同步含义                                                                |
| ------------ | ----------------------------------------------------------------------- |
| 作品状态     | 按三种当前状态与完成历史形成来源能表达的状态，见下文                    |
| 作品完成日期 | 对应单一完成日期时采用最早已知完成日期；来源不具备同义字段时不提供此项  |
| 评分         | 只采用本人评分，按实际分制、有效范围与精度转换                          |
| 收藏         | 只对应独立且同义的喜爱标记；加入清单、愿望单、购买或持有不代替 favorite |
| 分部完成标记 | 采用真实对应的分集、卷、话或附加内容；数量进度必须满足下文的顺序条件    |

作品完整完成历史、逐次备注、短评、私人备注、自由用户标签和 Note 不参加持续同步，不将这些内容编码进平台标签或备注。元数据更新、平台列表和成员操作保留各自入口，不因同步状态而修改名称、简介或合集。一次本地备份迁移的采用范围见[迁移导入](importers.md)。

一轮执行开始时固定对象范围。对象被本地删除、解绑或不再属于同步范围后，停止它的后续写入，不将旧请求转投其他对象。删除本地作品只是退出同步范围，不删除平台收藏或用户记录；明确撤回平台收藏是另一项平台操作。

<a id="import"></a>

## 本人清单导入

手动导入由用户选择来源清单、对象与采用字段后直接执行。清单读取完成必要分页，不把首页、权限不足、读取失败或缺项解释成确定没有记录。自动导入复用相同的来源读取、对象对应与新增操作，采用范围另见下节。

真实身份已经对应的对象复用本地条目；没有对应的适用作品沿 ingest 正常创建，可以没有本地文件。作品、季、卷和分集必须先按真实粒度对应，不能将单卷记录直接建成整部作品的完成事实。身份冲突的项目报告失败，其他独立项目继续。个人记录导入不会自动刷新已有条目的名称、简介和封面。

新建作品时，所选个人值作为 ingest.add 的 initial 与资料一同提交，自动同步只观察正式提交后的完整事实。手动导入遇到已有条目或新增返回 alreadyExists 时，按照本次已有对象采用选项分别调用 entries 的当前值操作与 completions 的历史操作，不从新增入口隐式覆盖；自动导入只复用已有对象。

本人个人值只从当前明确核验的账号采用。导入他人公开清单时，只采用适用作品资料、清单与成员，不将对方的评分、状态或完成信息作为用户本人的记录。

来源扩展按所选字段分别解释当前值与完成事实，并选择[本体完整操作](../domains/records.md#operations)。评分、收藏与普通当前状态使用 entries.update 或相应的即时设置；历史新增使用 create / createMany；只有本次意图同时包含新增完成事实与清除当前状态时，才使用 recordCurrent。以下映射各自以所选字段为范围：

| 来源信息                               | 本地采用                                         |
| -------------------------------------- | ------------------------------------------------ |
| 计划、进行或搁置                       | 设置对应当前状态，保留已有完成历史               |
| 放弃                                   | 不采用状态，保留已有状态；新建作品仍为未设置     |
| 已完成，本地没有完成记录               | 初始化一条完成记录，并清除当前状态               |
| 已完成，本地已有完成记录               | 保留全部原记录，并清除当前状态                   |
| 进行中且有明确的完成日期，本地没有历史 | 设置 active，并初始化一条过去的完成记录          |
| 来源只有完成日期且当前状态未提供       | 可以初始化完成事实，不修改本地当前状态           |
| 平台记录存在，所选状态字段明确为空     | 清除当前状态，保留已有完成历史                   |
| 没有个人记录或状态无法识别             | 不据此清空本地状态或删除历史，分别报告未采用原因 |

已有作品的历史初始化携带读取所得的 expected.completionCount: 0，按[历史数量基线](../domains/records.md#creation-baseline)在提交事务内确认仍为空。本地已有历史时不发起初始化；仅采用日期或过去的完成事实时使用 create，保留当前状态。recordCurrent 的条件失败时，新增和清状态都不提交，不能退回只清状态来冒充本次操作完成，也不自动刷新条件重试。

已有条目的采用以各个完整操作为提交边界。评分已经采用而历史操作发生冲突时，保留已完成的独立修改并准确报告未采用部分；其他不依赖失败项的修改可以继续。导入不承诺同一平台项目的全部个人字段共同成功，变更订阅也按各个真实提交处理，不以补偿写入撤回已完成结果。

来源的放弃状态没有本体对应值，报告该字段无法映射，不转换为搁置，也不触发本地条目删除。其余所选字段分别采用，包括语义明确的完成日期；该状态本身不构成完成事实。

新记录只有在来源提供合法完整年月日时才填写日期，否则日期保持未知。来源明确表达完成但只给出不完整日期时，保留完成事实，日期留空；不补齐月日，也不额外提示日期精度。

本地已有历史时，平台单一完成日期不用于新增、配对或覆盖某条记录。日期相同不证明是同一次完成。用户可以通过正常的完成记录编辑或补录采用该日期，不增加导入配对界面。删除全部本地历史后再次通过手动导入采用平台的完成信息，可以重新初始化一条；对象仍存在时，自动导入与后台同步都不会反向补回。

## 自动补齐所选清单

VNDB、Bangumi 等能够读取本人清单的来源可以提供自动导入，入口放在导入页，默认关闭。用户明确账号、清单范围、资料方案、新对象采用的个人字段及可选目标合集后启用。目标合集须为手动合集，已有手动导入使用的身份、粒度、匹配和新增规则继续适用。

自动导入根据当前所选远端清单和当前本地库判断结果。每轮完成所选清单的必要分页，逐项核对真实来源身份与本地对应；本地缺少的对象正常创建，已有对象只复用或跳过，并可加入选定目标合集，不自动覆盖其资料、评分、状态、喜爱标记或完成历史。分部按自身身份判断，不能因为父作品已存在就认为目标分部已经存在，也不能把分部身份提升为作品。

每轮自动导入核对当前所选清单与本地缺项。技术缓存、分页位置和上次执行结果只服务于对应读取或执行，不能成为永久跳过依据，也不能用远端新增时间代替完整核对。仅在本地删除，而对象仍符合所选远端范围时，之后会再次导入；启用说明须准确表达这项行为。远端移出清单不删除本地对象或合集成员。

启用时执行一次，应用启动且扩展恢复已启用配置后再次执行；应用运行期间默认每小时检查一次，并遵守来源的分页、配额和限流。应用关闭或扩展停用时不继续执行，不补跑离线期间的历史轮次。一次执行固定使用开始时的配置与资料方案，同一连接的执行不重入；新的定时触发可以合并，下一轮重新读取当前事实。

自动导入不启用或扩大本地到平台的同步范围。对象原本就属于用户明确选择的出站范围时，仍按正常同步合同处理，不增加隐藏的导入来源标志或例外规则。两个功能分别配置和报告，不将其组合成双向记录同步。

清单或项目读取失败按实际范围报告，不能当作空清单或成功导入；身份冲突不自动合并。后续轮次按当前状态处理缺项。普通配置、必要缓存和任务运行状态由扩展已有私有存储与任务能力承担。

关闭自动导入停止后续触发，已接纳任务沿普通任务规则完成或由用户明确取消。换账号后停止旧连接的后续导入，并关闭新账号下的自动导入；重新启用后按新账号的当前清单核对。连接失效不在后台打开授权页面。界面显示启用状态、最近结果和正在执行的任务，无新增内容的检查不重复弹出成功通知。

## 评分精度与有效范围

评分只读取用户本人的记录，不使用站点均分、热度、发行状态或他人评分。本体采用 0–100 整数，null 表示未评分。来源提供百分制接口时优先使用百分制；线性分制按其实际比例转换，例如 10 分乘 10、20 分乘 5、5 分乘 20。离散评价和多维评分按来源的明确合同处理，不能按图标序号造数值或求平均。

线性分制入站按来源实际分值完成比例换算，再取最近的本体整数，恰好居中时向较高值取整。例如来源十分制的 8.25 对应 82.5，采用为本体 83；不能先将来源值改到其出站刻度再换算。该舍入不改变来源分制、有效范围或未评分语义。

出站只能提交来源接受的分值。在线性有效区间内，采用最近可表达的步长，正好居中时向较高分取整；例如本地 87 对应整数十分制的 9，本地仍保留 87。超出来源有效评分范围的值不夹到边界、不改为未评分，保留本地并报告评分无法映射。来源中的 null、0 和未评分按真实语义分别解释。

写入确认保存本次本地值与实际平台值，供后续核对，不据远端取整结果反向修改本地。明确再次导入并选择采用平台评分时，才按平台当时的本人评分形成新的本地值。

<a id="status-and-progress"></a>

## 作品状态、完成日期与分部

本体 status 只接受 planned、active、onHold 或 null，completed 和 dropped 仅可出现在来源自己的状态值中。对于只接受一个状态的平台，出站规则如下：

| 本地事实                   | 平台目标                               |
| -------------------------- | -------------------------------------- |
| 当前状态非空               | 对应的当前状态，保留本地全部完成历史   |
| 当前状态为空，存在完成记录 | 平台的已完成状态                       |
| 当前状态为空，没有完成记录 | 清除所选状态；平台不支持时报告无法映射 |

因此 active 与两条过去的完成记录向这类平台表达进行中；用户记录本次完成后，本地为 null 与三条记录，平台才表达已完成。来源确实独立支持完成事实时可以分别采用；API 允许同时写入多个互斥进度标签，不等于平台具有独立的完成历史语义。

来源状态映射保持明确的来源词义：

| 来源     | 当前安排与完成信息                                                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MangaDex | plan_to_read、reading、on_hold 对应三种当前状态；re_reading 对应 active，completed 表达完成标记，dropped 不采用状态；来源支持明确撤回状态与评分，见[具体映射](sources/mangadex.md#sync) |
| MAL      | plan_to_watch / plan_to_read 对应 planned，watching / reading 对应 active，on_hold 对应 onHold；completed 表达完成事实                                                                  |
| AniList  | PLANNING、CURRENT、PAUSED 对应三种当前状态；COMPLETED 表达完成事实；REPEATING 对应 active，不增加完成记录                                                                               |
| VNDB     | 按[进度标签与 Wishlist](sources/vndb.md#account-status)分别解释，不按数组顺序或自建同名标签猜测                                                                                         |
| TMDB     | 仅动画影片：入站 watchlist=true 对应 planned，false 不推断完整当前状态；出站 planned 对应待看，其余状态对应不在待看列表；不提供完成事实，见[具体规则](sources/tmdb.md#sync)             |

入站与出站映射分别定义。平台当前细分值已经表达同一本地当前状态时，保留该值，例如 REPEATING 对应 active，不为规范化而重写。未知或无法表达的值报告该字段无法映射，不新增本体当前状态或备用值。

单一完成日期取作品全部非空 CalendarDate 的最小值，即最早已知完成日期。未知日期不参与计算，不推断它在已知日期之前或之后。新增更晚记录不改变该日期；补录更早记录、更正日期或删除记录后重新计算。没有已知日期时目标是清空，来源不支持清空则保留本地修改并报告该字段未同步，不能删除重建整条平台记录。来源的单一日期不承载完整历史；日期与当前状态分别映射。

来源开始日期没有本体当前状态或完成记录的同义字段，不建立体验起止、额外来源列或虚构活动区间来保存。来源技术时间也不改写本地创建、修改、加入或完成日期。

分部按真实身份和粒度对应。来源只表达“连续完成前 N 项”时，必须取得完整来源顺序及相应本地对应；入站采用这些明确分部，出站要求本地标记恰好形成相同范围的连续前缀。只标记第 1、3 项时，不能写成完成至第 2 项。来源独立支持逐项标记时，直接按实际对象同步。正片、附加内容、卷和话的不同范围不相加，分部写入不创建作品完成历史。

## 平台原生写入、创建与清除

支持范围按来源实际操作分别确定，读取、创建、更新和清空不能互相推导。用户选择决定扩展直接提交的对象与字段；平台正常处理这些操作时产生的默认状态、日期、进度、次数、名单或可见性联动，按原生行为接受，并在来源说明和实际结果中表达。不为了保留未选字段而阻止正常操作，也不提交原值、反向补偿或修改账号设置来压制这些联动。

平台确认没有个人记录后，所选字段具有可写值时，可以调用来源支持的创建操作。MAL 动画、AniList 或 Bangumi 在只写评分时默认建立进行中状态，这是来源创建行为，无需额外选择状态。

仅请求清空评分或撤回状态时，缺少记录表示无需修改。读取失败和无权限访问分别报告，不据此推断记录不存在。

请求仅携带本次选中且需要修改的字段及来源要求的身份、认证与实际可用的创建参数，不重发整条记录。平台确实要求整记录写入时，先读取并保留未选内容，不能用空文字、空标签或默认值直接覆盖。来源自己产生的联动不反向改写本地个人值或完成历史，也不使未选字段成为持续同步目标。

多个所选字段按来源支持的同次请求或明确顺序处理。例如 AniList 状态与所选完成日期同次提交；TMDB 同时选择评分与待看时先评分，再设置所选待看目标。只选评分时接受其原生待看变化，不补发恢复待看的请求。最终无法同时保存所选值时，如实报告实际值与未能表达的字段，保留已经完成的结果，不循环改写来制造表面一致。

扩展直接写入的范围限于所选条目及具有本体同义值的来源操作。来源缺少对应值或清除能力时，该操作不可用；需要另建未选父记录、修改其他条目或无关字段、删除重建才能实现的操作，同样排除在入口之外。

依赖当前记录的限制在来源说明和结果中给出。权限不足、连接失效和临时失败分别处理，来源能力限制不进入网络重试流程。

来源有独立的逐条可见性参数时，新记录使用用户明确选择的值，普通更新不重设已有值。没有这一参数时，沿平台自身的清单、标签和账号规则，不提供虚构的逐条隐私控件；评分或状态引起的可见性变化同样按原生行为接受并说明，不阻止写入、不改全局隐私设置或添加无关标签。账号连接和写入行为在来源界面说明，不为每条记录增加确认。

发送前读取必要当前事实，已一致的字段不重发；发送后核对实际结果，再保存本次本地投影与实际平台确认值。可预期的原生联动按实际结果记录，不作为需要补偿的失败，也不单独触发下一次写入。结果未知时有界回读，不能因短暂旧值立即重放或重复切换。只有本地指纹未变不足以证明平台仍然一致；手动同步全部仍须核对平台当前值。平台没有条件写入时，不宣称客户端检查能够阻止来源端的并发修改。

<a id="automatic"></a>

## 自动触发、重试与连接生命周期

自动同步默认关闭。用户明确账号、对象范围、字段及来源实际支持的新记录可见性后启用；手动和自动执行使用同一套映射与业务实现。

自动同步在启用时、应用启动并恢复有效连接后，以及范围内的来源对应或所选本地个人字段变化后执行。出站同步不设置远端定时轮询，也不补跑停用或离线期间的旧事件；远端清单的定期读取只属于另行启用的自动导入。启用时先建立相关本地订阅，再安排当前范围核对；执行期间的新变化有界合并后重新读取最新本地值。未选字段、实际计时和私人备注变化不触发无关同步。

同一连接与对象的在途写入协调执行，重试重新读取当前本地事实，不重放已经过时的负载。本地已从完成改为 active 时，重试采用 active。网络和限流失败按来源规则有限退避并遵守 Retry-After；写入结果未知时先回读核对，不盲目重复创建或切换。认证失效时停止该连接的后续执行，用户主动重新连接，后台不打开授权窗口。

本地个人记录保存不依赖远端成功。同步结果分别说明更新、未变化、字段未同步、部分完成和失败，失败不回滚本地记录或已完成的平台写入。任务使用 TaskRun 和来源自己的报告，不等待用户在后台任务中裁决冲突，也不增加通用 sync_run 或持久冲突队列。

关闭页面不取消任务。关闭自动同步停止后续触发，已经接纳的执行仍按原任务完成或由用户明确取消。取消停止后续工作，已经提交的内容保留，已发出的远端请求不能宣称已经撤回；实例结束时清理订阅并终止依赖该实例的后续调用，未确认的结果如实报告。

更换账号成功后，停止旧连接的后续工作，清除旧账号写入确认状态并关闭自动同步。用户在新账号下重新启用后，按当前配置执行首次核对，旧任务不转投新账号。连接更换失败或取消时保留旧有效连接；同一账号的正常令牌刷新不重置同步选择。断开连接清除本地凭据，保留本体资料和平台记录，见[连接合同](private-data.md#connection)。

来源界面显示连接与自动同步状态、正在执行的任务及最近结果。只有原操作入口拥有用户反馈，事件订阅与任务中心不重复通知，不增加执行前预览、差异选择页或常驻冲突处理入口。

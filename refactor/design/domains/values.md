# 领域值与边界规则

公共值表达可以交换的业务含义。纯值校验负责值本身是否合法，存储编码负责持久表示，完整业务操作负责跨对象约束。字段缺席、明确空值和日期中的未知分量分别有自己的含义，不能混用。

<a id="ownership"></a>

## 合同与存储的归属

desktop-contracts 按业务含义组织完整桌面功能的公共值、纯校验、操作、结果、参与接口和错误。它的范围不受当前向扩展开放的能力限制，也不复制实现中的 app、features 和 infrastructure 分类。内部策略与运行实例类型留在实际模块。

database 负责 SQLite schema、索引、外键、编码、初始化和版本迁移。查询投影根据调用用途定义，不能反过来决定公共模型。窗口接入与 extension-api 分别选择实际开放的能力，并直接引用共同定义；SDK 通过 extension-api 使用这些合同。制品格式由 extension-distribution 定义，共同视觉值由 appearance 定义，字体资源与主题的持久语义由桌面合同定义。

两个值即使结构相同，也不一定含义相同；含义相同的值，也不因经过 IPC 就需要重新定义。只有边界两侧的语义或表示确实不同，才进行转换，不逐层复制 DTO。数据库连接、引擎实例、原生窗口对象、构造依赖和可变运行实例留在实现内部。会话、任务等需要对外读取的运行快照，由对应公共合同定义，不暴露内部实例或句柄。

## 值、空值与修改

| 值           | 统一规则                                                                           |
| ------------ | ---------------------------------------------------------------------------------- |
| 本体 ID      | 创建后保持稳定，不编码来源或路径。                                                 |
| 评分         | 使用 0–100 的整数，未设置时为 null。UI 可以显示为 0–10，转换在显示和输入边界完成。 |
| 收藏         | 使用明确布尔值，适用于七类条目。                                                   |
| 作品当前状态 | 使用 planned、active 或 onHold，也允许未设置。具体动词由 UI 本地化。               |
| 时间点       | 使用 UTC 毫秒，显示时转换为所需时区。                                              |
| 时长         | 使用非负毫秒值，不能与时间点混用。                                                 |
| 完整日期     | CalendarDate 必须包含合法的年、月、日；未知时整值为 null，不包含时刻或时区。       |
| 部分日期     | 保存实际知道的年、月、日分量，并按真实日历校验，不补造未知分量。                   |
| 顺序与编号   | 内部排序与展示编号分开，允许特别篇、非整数编号和未编号对象。                       |
| 未知与空集合 | 字段缺席表示没有回答；明确空集合表示有权威地回答“没有”。                           |
| 清除与不修改 | patch 中字段缺席表示不修改；明确 null 或清除动作才清除对应可空值。                 |

个人评分统一使用上述单位。站点评分保留其来源含义，即使完成单位转换，也不自动写成个人评分。

个人作品当前状态以 null 表示尚未填写或已明确清除，记录行缺席时同样读取为未设置。新增或导入没有提供状态时，初值保持 null；用户的使用计划通过明确状态表达。实际完成情况由[逐次完成记录](records.md)得出，当前状态与完成历史分别管理，completed 留在完成事实的语义中。

<a id="read-write"></a>

## 宽容读取与严格写入

本地存储以宽容读取为基本规则，尽量返回能够解释的内容，将格式异常限制在相关字段、值或能力。一个可独立处理的字段异常，不应使其他合法字段、记录或整个页面不可读取。读取和执行分别判断：保留可读资料并展示配置问题，无效定义停止执行。

| 业务值                                 | 宽容读取规则                                                                                                     |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 别名、普通相关链接列表                 | 保留符合各自合同的项目及原顺序；整个值无法解析为数组时，读为空列表。外部身份绑定不属于这类列表。                 |
| 可空的 PartialDate                     | 按完整日期值校验，无法解析或不合法时读为 null；不删除错误分量、补齐或进位成另一个日期。                          |
| 可空的 CalendarDate                    | 必须能够解释完整年月日；不合法时读为 null，保留所属完成记录与未修改的原始存储，不补造日期。                      |
| 普通偏好的独立字段                     | 保留合法字段，只对缺失或格式异常的字段采用其既定默认值；JSON 分组不扩大缺省或失败范围。                          |
| 查询、扫描、识别、启动、代理等执行配置 | 保留原存储和其余可读内容，明确报告无法采用的部分并停止相关执行；用户可以明确重建或删除，不将无效定义变成空限制或默认配置。 |
| 用户正文、身份引用、历史与定位值       | 保留原值及其余可读内容；不能清空正文、伪造身份、补计历史或改换位置，无法采用的部分按所属合同报告。               |

已保存的资源引用与实际资源可用性分别处理。译本、主题或字体暂不可用时保留选择，实际呈现按资源自身的回退规则处理，不能当作未选择。其他值沿用所属合同，不因底层同为数组、数字或 JSON 而套用相同缺省。连接、查询或必要结构读取失败仍按相应错误边界报告，不解释为空结果。

格式损坏的持久配置不提供原地修复流程，也不增加原始存储文本的公开编辑或 expected 基线。重建使用正常创建及选择操作，删除遵守原有引用与资源约束。合法定义的普通编辑、草稿校验和失效引用更换继续使用各自合同。

宽容读取不自动写回数据库。修改其他字段时保留未涉及的原值，不能把经过缺省处理的读取投影直接作为整行或整组替换。正式写入完整校验此次明确提交的业务值及相关约束，保证读回后语义等价；非法项目或分量应拒绝写入，不能沿用读取时的筛除规则静默改变提交内容。读取不承担已经退出使用的旧格式兼容或迁移。

<a id="codecs"></a>

## 自定义列与运行时校验

| 存储情况                                             | 接入方式                                      |
| ---------------------------------------------------- | --------------------------------------------- |
| 设置、资料方案和具有明确结构的 JSON                  | 使用 customType 接入所属值合同。              |
| 已决定序列化保存的数组、部分日期和定位值             | 使用 customType，按值的实际含义选择存储粒度。 |
| 需要自定义规范化、运行时校验或未知值处理的枚举与标量 | 使用 customType 复用对应纯规则。              |
| 普通标量和适用的内置映射                             | 使用 Drizzle 原生列类型。                     |
| 主键、外键、唯一性、非空和行级约束                   | 在实际 schema 中声明数据库约束。              |

同一种存储合同只保留一份列适配，放在 infrastructure/database/codecs。需要自定义编解码、规范化或读取规则的值统一通过 Drizzle customType 接入，普通标量继续使用原生列类型。不能仅因语言列表和来源列表都表示为 string[]，就共用排序、去重或缺省规则。

codec 引用公共合同或内部模块的纯校验，表单、IPC 和存储复用同一规则。$type 只标注编译期类型，不能证明运行时数据合法，也不能代替编码。codec 校验值内部的结构；provider 是否可用、附件是否存在、作品归属和跨记录一致性，由业务与数据库约束保证。codec 不查询数据库，也不访问网络、文件或窗口。

codec 按上述逐值规则处理读取异常，不能统一回落到 {}、[] 或 0，也不能用写入校验直接拒绝整份可部分读取的内容。无法安全解释的部分由所属合同表达，不伪造身份或关系。原始 SQL、表达式和特殊查询未必经过列映射，使用这些路径时必须显式保持同一合同，并验证读写往返。

<a id="calendar-date"></a>

## CalendarDate 的完整日期

CalendarDate 表示确定的公历年月日，三个分量全部必需：

```ts
type CalendarDate = { year: number; month: number; day: number }
```

它与 PartialDate 分别定义，不能省略分量或用 null、0 占位未知月日。年份使用下文的天文纪年和安全整数范围，月份为 1–12，日期按对应年份的真实月长校验。没有日期时由所属字段使用整值 null。完成记录使用这个值，不接受只有年、年月或月日的个人完成日期。

完整日期通过 date 模块的纯规则校验，以固定 year、month、day 分量编码为 JSON，使用同一 CalendarDate 列适配。比较与排序按三个分量进行，不将它转换为午夜时间戳，也不按 JSON 字符串排序。显示时区变化不会移动完成日期；“今天”由界面按当前显示时区取得后作为明确的 CalendarDate 提交。

<a id="partial-date"></a>

## PartialDate 的结构与日历合法性

PartialDate 保存普通公历日期中已知的分量，至少包含 year、month、day 中的一个。它是一个完整值：未知分量省略，不另存 precision、kind 或 has_year。month 的范围是 1–12，day 表示月内的日。它不包含时刻、时区、时间戳、近似含义或不确定区间，定义位于 date 模块。

以下七种分量组合均有明确含义：

| 已记录分量       | 表达的信息                     |
| ---------------- | ------------------------------ |
| year             | 已知年份                       |
| year、month      | 已知年月                       |
| year、month、day | 已知完整年月日                 |
| month、day       | 已知月日，未记录年份           |
| month            | 已知月份                       |
| day              | 已知月内的日，未记录年份和月份 |
| year、day        | 已知年份与日，未记录月份       |

每个分量都必须是安全整数，并且组合后至少存在一个符合已知分量的合法日期。完整年月日按该年实际月长校验；没有年份的 02-29 合法，02-30 非法。缺少月份时，不把已知的日强行归入某个月。会补值、进位或修整输入的日期构造函数不能用于判断输入是否合法。

整个日期未设置时使用 null。空对象、值为 null 的分量和占位值均不合法，month 和 day 不接受 0；year = 0 则是有效纪年。类型通过非空联合表达“至少一个分量”的要求，运行时仍须校验数值与日历合法性。

条目 patch 中，日期字段缺席表示不修改，null 表示清除，PartialDate 表示整值替换。例如，将完整日期替换为 { year: 2024 } 会移除旧月日，不能合并新旧分量。是否采用精度更粗的日期由资料更新策略决定。表单可以暂存未完成的原始输入，但正式提交必须校验本次输入，不能静默提交上一次合法值。

<a id="years"></a>

## 纪年、数值范围与输入

所有日期使用前推公历，地区历史改历不改变这套规则，也不另存 calendar。year 使用连续的天文年份：公元前 n 年对应 1 - n。纪元从 year 推导，不重复保存 era 或 eraYear。

| 用户看到的年份 | 内部 year |
| -------------- | --------- |
| 公元前 2 年    | -1        |
| 公元前 1 年    | 0         |
| 公元 1 年      | 1         |
| 2024 年        | 2024      |
| 12000 年       | 12000     |

year = 0 必须正常参与存在性判断、显示、排序和查询，不能用真值判断年份是否填写。负零规范为 0。年份范围为 -9007199254740991 至 9007199254740991，包含两端。超界值、非整数、NaN 和无穷值均拒绝写入，不截断、不钳制，也不舍入。

公共值、数据库 JSON、跨进程传输和正式编辑支持同一安全整数年份范围。纯 date 模块统一负责纪元换算、闰年和区间运算，必要时临时使用 BigInt，校验后返回正式 number。输入框和各接入复用这些规则。

公元年份直接输入；公元前年份选择纪元并输入正整数年号，例如“公元前 1 年”转换为 0。年份留空时不保存纪元，清除年份可以保留月日。显示包含明确纪元及完整年号。编辑器将原始数字文字交给 date 模块换算：内部最小年份对应公元前 9007199254740992 年，须先精确处理年号，再形成安全整数 year；临时 BigInt 不进入存储或公共 API。

筛选使用同样的输入方式和连续年份。“公元前 10 年至公元 10 年”是正向范围，“公元前 1 年至公元前 2 年”则是倒置范围。闰年按内部 year 计算，不对公元前年号取绝对值。

来源适配器必须明确转换来源的纪年约定，包括公元前正年号、没有零年的有符号年份，以及表示未知的占位值。来源的 0 若表示未知，应转为缺席；含义不明的负年份不能猜测。儒略历、农历、年号和作品自有纪年，只有能够可靠确定公历对应时才写入 PartialDate，否则保留原文说明。

<a id="date-operations"></a>

## 日期的显示、查询与验证

合法的 PartialDate 不一定足以表达确定时刻或查询边界。显示、按分量筛选、日期范围和排序分别检查自己需要的信息，并遵守 [库查询](library-queries.md) 的精度与未知规则。year 与 day 的组合可以用于有依据的分量和范围判断，但不能作为精确起止日期。用于展示的稳定排序也不证明真实的时间先后。

日期直接按分量与公历规则运算，不要求先转换为时间戳。接入 Date、Temporal 或时间点格式时，适配器分别校验自身范围和所需分量，不能补造分量、允许溢出或回落到当前日期。真正的时间点字段继续遵守自己的时间戳与时区合同，不自动拥有 PartialDate 的年份范围。

纯 date 模块验证七种分量组合、公历周期、跨纪元、year = 0、无年份的 02-29、长年份、安全整数边界和超界拒绝。存储、编辑、语言显示、来源转换及查询各验证自身接入：精度保留、输入往返、来源纪年转换，以及筛选、计数和定位的一致性。共用算法的极值矩阵在纯模块覆盖，接入层只补自己引入的条件。

算法与 SQLite 映射的现有依据见[隔离日期探针](../../verification/evidence/technical-tradeoffs/2026-10-22/README.md#dates)。正式表单和来源接入按上述分工验收。

# Kana 阅读布局

浏览器承担原生排版，Kana 拥有阅读单元、阅读面、导航和展示投影。源结构、作者 CSS 能力与用户呈现意图分别解释。

<a id="model"></a>

## 源内容、技术输入与实际布局

| 层次         | 内容                                                   | 拥有者                                       |
| ------------ | ------------------------------------------------------ | -------------------------------------------- |
| 源内容事实   | 固定／重排性质、源顺序、原始尺寸、作者页位和书写规则   | 格式解释                                     |
| 技术呈现输入 | 阅读流、原始页和正文的呈现参数、已解析的字体选择与颜色 | Kana 的 ReadingSettings 合同；由宿主明确提供 |
| 实际布局     | 当前内容、输入和视口共同形成的可见范围、方向与几何     | view 及其必要的状态反馈                      |

宿主的偏好、配置层级、主题与字体库身份位于库外。Kisaki 如何准备本次输入由[阅读接入](../../domains/reader.md#settings-boundary)负责，本页不规定主应用的存储形状或默认值。

固定／重排决定内容如何形成阅读面；flow 决定主阅读分页推进还是连续移动。原始页编组与正文生成面数分别使用 pages.arrangement 和 text.pagesPerView。当前实际布局不反写宿主偏好，生成页号也不成为源页身份。

<a id="content-units"></a>

## 阅读单元与按需内容

formats/document.ts 的内部能力围绕实际消费形成：文档顺序、阅读单元的版式与必要尺寸、按需内容、源目标解释、源文字及释放。它只描述阅读所需事实，不复制 Kisaki 的作品资料，也不公开一套供调用方实现的格式插件接口。

“阅读单元”是内部加载和呈现边界，其形成方式由格式决定：

| 格式          | 内部单元的依据                                | 稳定位置的依据                     |
| ------------- | --------------------------------------------- | ---------------------------------- |
| EPUB          | 每个 spine 出现对应的内容；同一资源可重复出现 | 完整 CFI 或原始 spine 页面         |
| MOBI／KF8     | 格式结构及适用的正文边界、skeleton 文档       | 原始标记字节或 skeleton 文档内字节 |
| FB2           | 正文和独立注释的语义结构                      | 原 XML 逻辑节点路径                |
| TXT           | 按需展示的文字块                              | 已确定编码与原始 UTF-16 偏移       |
| PDF           | 原始页面                                      | 原始页面及其规范几何               |
| 图片目录／ZIP | 确定源顺序中的图片成员                        | 精确 memberPath 与页面几何         |

内部块编号不能因为恰好是整数就成为公开位置。TXT 可以改变分块，FB2 可以改变章节加载组织，而既有位置保持不变。EPUB 中同一资源出现两次时可以共享字节和只读解析事实，但各自的出现上下文、显示文档和位置必须分开。

固定与重排属性归具体阅读单元。一本包含重排正文、固定插图页和后记的书，仍是一个文档、一个 Reader；视图根据当前单元组织呈现，不把整本书锁定为单一版式。共同能力可以由浏览器文档、图像或 PDF 页面提供，不能为接口外观一致而强迫它们经过同一种中间表示。

Foliate 的 sections 与按需加载是这项设计的参考，见其[内容与呈现接口](https://github.com/johnfactotum/foliate-js/blob/78914aef4466eb960965702401634c2cb348e9b1/README.md#the-main-interface-for-books)。Kana 的单元版式、源地址和实际完成规则仍按本库用途定义。

<a id="shared-settings"></a>

## 阅读流与呈现参数

flow、原始页编组和正文面数按[设置合同](settings.md#principles)独立取值。view 协调同一个主阅读流程，fixed 与 reflow 分别处理当前内容的测量、排版和绘制，navigation 沿源路径推进。

普通行内插图参与正文排版；独立固定页则按自身版式呈现。设置值保留调用方意图，当前显示同时受内容性质和作者页位约束。临时查看使用当前 Reader 的适用设置与局部呈现。

<a id="pages"></a>

### 固定页与正文双面

双面呈现将两个阅读面左右并排，各 flow 与内容类型的组合见[设置示例](settings.md#principles)。固定与重排的交界在分页时结束当前配对，在连续模式下按源顺序衔接。

默认不跨固定／重排边界凑双页，是为了使当前显示变换与控件作用对象清楚。它保留各项内容与源位置，但不承诺复现跨两种版式的复杂跨页组合；遇到明确的跨类型页位设计，仍需单独验证呈现与控件的完整含义，不能宣称这项简化覆盖全部 EPUB 布局情况。

正文按阅读顺序填充，不为让末屏看起来对称而平衡两面的文字；作者 CSS 的段落、寡行／孤行和显式分页约束按[分页支持边界](#保留原生排版边界)处理。格式内容顺序与明确页位仍由 Kana 保证。

<a id="authored-layout"></a>

### 文档页位、用户意图与实际显示

原始页的单页／对页是调用方提供的呈现意图，文档明确的独立显示约束与左右页位仍需解释。EPUB 对 spread-none 和 page-spread 属性有实际要求，见[固定版式处理](https://www.w3.org/TR/epub-rs-33/#sec-fixed-layouts)。

pages.arrangement 为 single 时显示单页；为 spread 时，在文档允许的范围内形成左右对页。明确要求独立显示的内容仍单独呈现；明确左右槽位优先于缺省配对。pages.firstPage 只参与没有明确页位时的起始配对，不在每次重新打开、跳转或进入固定内容时重新制造一个“第一页”。

只有正文阅读路径开头的固定源页面才参与这项首张规则。正文中途的固定插图不因它是刚加载的第一个固定单元就自动当作封面。为槽位留下的空白只是视图空位，不获得 pageIndex、标记身份或源进度。一张本身就是跨页画面的图片仍是一张源页面。

作者页位使实际组只含一面时，仍保留请求中的对页选择。视口约束按[空间不足规则](#space)处理。

<a id="directions"></a>

### 书写、推进与页面方向

源顺序决定内容先后；页面推进方向决定阅读面顺序；writing-mode、direction 与文字朝向决定局部排版。改变左右排列不反转源索引，竖排也不等同于把整份文档旋转九十度。相关轴向见 [CSS Writing Modes](https://www.w3.org/TR/css-writing-modes-4/#logical-directions)。

next／previous 按阅读顺序前后移动，视图根据已采用布局解释物理按键、拖动和滚动。writingMode 提供真实书写方向，ReadingView.forwardDirection 与 pageSlots 提供前进方向和当前组面数，宿主使用这些运行结果安排控件。

<a id="flow"></a>

## 连续阅读与轴向接续

同轴的连续章节自然连接：横排正文沿纵向，vertical-rl 正文向左，vertical-lr 正文向右；保持未分页的正文流。纯固定页面的连续模式沿纵向排列单页或对页组，组内左右顺序仍按原始页设置与文档页位解释。

相邻内容的主连续轴不同时，把换轴处作为明确的呈现交接边界。正文源顺序不变，同一 Reader 的 next／previous、源选区、搜索和历史仍可跨越；进入下一段后采用其实际方向。它不形成新的业务会话、持久路径 id 或另一份设置。段落内部的横竖混排继续在当前正文内排版，不因一小段异向文字就建立边界。

同轴章节可以无缝滚动，换轴处不承诺同时呈现在一条笔直的滚动带里。滚动或翻页接续必须以已就绪的真实目标为准；惯性余量不在换轴后突然推动另一段很远。不能为消除这个边界而旋转整章、改掉作者书写方式或按屏幕像素伪造新源位置。换轴时的手势、焦点和跨段拖选仍须用实际交互样本补证。

<a id="space"></a>

## 面数选择与空间不足

pages.arrangement 和 text.pagesPerView 表达明确的单面／双面选择。窗口变窄时仍采用请求面数，不依据设备名称、横竖屏或未公开的最小字数阈值自动改单面，也不缩小用户字号来维持双面。原始页沿既有 fit 与缩放规则显示，正文在剩余阅读区域内重排；用户可以明确切换面数。

文档规定的独立页、左右槽位与最后一面内容不足，仍按作者页位规则解释。该差异来自源内容，不把空槽位当作一张源页。连续正文不采用分页的面数。

视口与明确留白使阅读区域无法成立时，本次操作按 layoutUnavailable／insufficientSpace 失败，保留最后可信位置与所选设置。窗口隐藏、再次可见及失败对 Reader 的影响遵守[错误合同](api.md#errors)。用户可以调整面数或窗口后重新布局。

<a id="feedback"></a>

### 实际布局反馈

ReadingView 按[公开状态](api.md#state)交付已采用布局的方向、组面数、书写模式和适用的缩放／旋转。固定与重排交界以实际主位置决定这些值，临时查看保持主阅读字段原义；尚未完成的布局不提前发布。

<a id="pagination"></a>

## 原生排字与阅读面组织

按所需阅读面的尺寸，让原生 CSS multicol 生成片段，使用 column-fill:auto 顺序填充；每份展示文档保留章节的完整结构。字号、ruby、双向文字和行内混排仍由浏览器排字；view 解释片段几何、组织本次显示组并连接源地址。

共同路线采用每面一份完整章节投影。普通分栏在横排中沿横轴生成片段，在竖排中沿纵轴生成片段；每份投影通过自己的布局偏移显示所需片段，再由 view 在屏幕上组成左右阅读面。vertical-rl 从右往左推进，vertical-lr 从左往右推进；不能把两者一律当成 rtl。底层片段轴与屏幕上的阅读面顺序各自解释，不旋转正文，也不把生成页切成新的源内容单元。

各引擎不必产生相同的内部片段带，view 负责组织实际阅读面。特殊作者分页与跨栏规则由呈现转换解释，按[支持边界](#保留原生排版边界)验证。

生成面只是当前布局中的片段。章节源节点、CFI、FB2 路径和字节地址不随面数变化；定位与重排通过实际 Range 几何找到本次片段。底层正负 scrollLeft 及偏移只属于该布局，公开的“下一页”按阅读面的推进含义解释。

章节起始需要留空槽位时，由 view 的显示分组处理，不插入一个会参与源子节点编号的空白段落。EPUB 的明确页位也适用于重排项，完整跨类型组合仍按[作者页位要求](#authored-layout)验证。

这条路线保留[整章上下文与预算](#context)要求。原生分栏不能证明巨大章节可以任意切开，也不能自动解决表格、跨栏元素、作者分页指令与读者分页容器的作用范围。需要转换的样式由同一呈现转换负责，并用完整场景验证，不在导航中临时修补源树。

[断页含义](#meaning)与[支持边界](#保留原生排版边界)分别规定格式结构保证与作者 CSS 能力。排版使用浏览器原生机制，作者 CSS 分页按已验证的引擎能力支持；Firefox 的当前强制换栏缺口列为明确限制。

<a id="projections"></a>

### 阅读面的完整展示投影

源内容与格式索引由同一个拥有者维护，展示文档按实际阅读面建立。正文双面时，两份完整章节投影各显示一个相邻片段；单面只需一份，连续内容仍按自身流组织。浏览器完成每份文档内的普通分栏排字，view 决定片段在屏幕上的左右位置。

这种方式保留整章 CSS、继承、计数器及布局上下文，每个内容文档的视口对应一个阅读面的尺寸。显示投影共用同一个 Reader、格式实例、主位置与设置。CFI、节点路径、字节地址、文字提取、搜索和标记继续由原格式拥有；每份投影维护自己的实际 DOM 到同一源语义的对应。

多面呈现的成本是：同一章节占据两个阅读面时，会增加一份完整展示 DOM，以及相应布局和绑定开销。字体、布局参数与更新结果由同一次采用协调，所有投影遵守已有占用、预算和释放规则，不能出现两面使用不同版本设置。[语义文档与焦点分工](interaction.md#documents)让同一份文档承担语义入口与实际焦点，另一份保留显示和原生命中；语义文档按源目标调整所在阅读面，完整辅助技术接入仍须验证。

<a id="保留原生排版边界"></a>

## 分页支持边界与取舍

呈现保留完整章节上下文与浏览器原生排版，作者 CSS 片段化按已验证的引擎能力支持。Firefox 属于一般阅读支持环境，当前缺失的作者 CSS 强制断页按本节限制处理，相关内容按自然流继续阅读。

Kana 的目标是完整阅读原书、调整样式、保留源位置与标记，并支持选择和访问内容。由浏览器排版完整章节，可以保留作者样式上下文与原生交互。Kana 据此承担阅读面的组织与源映射，将完整 CSS 片段化留给浏览器，并明确各环境支持的作者分页能力。

[路线比较](../../../verification/evidence/kana-pagination-review/review.md)说明更完整的分页后端可以在 Firefox 执行列表与表格断页。这里选择保留原生排版与明确的 CSS 能力差异，以限定库的作者样式解释和分页责任。

| 内容                         | 保留的责任                                                |
| ---------------------------- | --------------------------------------------------------- |
| 格式内容、章节与原始页面     | 完整读取、正确源顺序、按已确认规则切换与呈现              |
| 格式明确的左右页位与独立显示 | 仍由格式解释与阅读面组织处理，不降为可忽略的 CSS 声明     |
| 自动分页与连续阅读           | 保留两种阅读方式、横竖排方向及明确的单／双面设置          |
| 定位、选择、标记与历史       | 继续以源地址为依据，不依赖生成页数跨环境相同              |
| 内容可读性与交互             | 不能以 CSS 能力差异掩盖丢失内容、无法到达的正文或错误选择 |

外部 CSS、style 元素与 style 属性进入同一展示样式处理，按阅读面的分页语境作明确适配。样式解析和实际布局分别验证，支持范围以原生片段化的真实结果为依据。

不支持的作者强制断页在该环境中按自然流继续排版。实际影响是小节可能接在当前面，而没有按作者要求另起一面，生成页数也可能不同。固定源页、章节切换与格式页位不受这项缩减牵连。

支持说明按环境、声明与实际上下文记录能力，不只写一个笼统的“支持分页”。Firefox 的已知缺口明确列出；Chromium、WebKit 也按自己的实证范围说明，不从品牌名称推导完整 CSS 符合性。底层可以做有清楚语义与验证依据的适配，不将重新实现整套片段化作为兼容义务。

这项边界不新增按浏览器分叉的公开阅读设置。普通阅读也不需要每遇到一个受限 CSS 声明就改变模式或中止打开。

<a id="meaning"></a>

### 强制断页与避断偏好

| 情况                        | 处理含义                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------- |
| 明确在内容前／后断页        | 在适用的分页语境中进入下一个阅读面；双面显示时不自动等同于跳过整组两面                             |
| 相邻内容同时声明断页        | 按同一个边界解析有效条件，不机械执行两次而制造无意义空面                                           |
| 明确左右页位                | 双面时按实际阅读方向与既有槽位规则安排，必要空位不成为源页；单面保留断页，不为不可见槽位增加空翻页 |
| avoid、寡行／孤行等避断要求 | 在可满足时尽量保持；与强制断页冲突或内容超过一面时，按规则允许续排，保证前进且不丢内容             |
| 连续正文                    | 保持未分页连续流，不因为分页样式插入一个视口高度的空白；内容结构与正常段落间距仍保留               |

强制条件、避断偏好及冲突次序参照 [CSS Fragmentation](https://www.w3.org/TR/css-break-3/#breaking-rules)。只解释有效、适用且对应实际排版盒的声明，不能把隐藏节点、失效条件或不适用的定位盒也变成分页命令。page、column 和左右页要求具有不同语义，不通过统一替换一个关键词假装它们等价。

作者 CSS 按实际环境和上下文采用其支持的断页能力，未支持的声明按自然流继续排版。格式规定的章节、原始页面和明确页位由 Kana 在全部支持环境中保证，阅读方式保持用户选择。

形式上的强制断页也不能以缩小用户字号、反转源顺序、删掉内容或改变固定页面身份来满足。生成面与为配对保留的空位仍属于当次布局；CFI、字节地址、节点路径、原始页面及已有标记继续按源合同解释。

<a id="ownership"></a>

### 重排约束的实现归属

展示转换负责取得有效作者样式与断页含义，view/reflow 负责在当前尺寸、字号和书写方向下形成阅读面。外部样式表、style 元素和 style 属性都需要进入适用的作者样式解释，不因资源加载形式不同遗漏断页。格式仍拥有源内容与定位，navigation 仍以实际可见源目标完成操作，selection 仍拥有一份源选区。

作者 CSS 的含义保持一致，实际执行范围按引擎与上下文记录。格式结构、完整正文、源定位和选择的验收目标仍适用于全部支持环境。浏览器差异不成为另一套用户设置、正式页身份或不透明的自动阅读模式切换。

有明确语义和实证的适配仍须保留原有间距、作者上下文与源映射。补白与浮动模拟不作为通用修正机制；声明的能力通过实际表格、列表、浮动和混排上下文验证。

样式适配与能力验证仍要考虑有效断点及其实际排版上下文，并同时检查前文、目标与后文；只看到目标移动到另一个片段不足以通过。既有源位置、统一选区、语义文档与焦点接续的责任不变。

<a id="context"></a>

## 巨大章节与布局上下文

按章节卸载与在一个章节内任意切 DOM，是两种不同的技术问题。源字节索引可以分段，原始节点也可以按需恢复，但 CSS 选择器、计数器、表格布局、浮动和混排可能依赖当前片段之外的内容。

以格式原有内容文档／页面作为加载和释放单位。巨大章节的局部分片必须证明保留上下文：边界须考虑表格、ruby、继承、计数器和书写方向，不能把块元素边界当成天然安全边界。TXT 等由库自己生成展示结构的内容可以使用更直接的分块策略；具体分片与容量仍须按实际后端验证。

源字节和只读索引可以单独分段，昂贵的 DOM、解码图像与页面绘制再按实际需要驻留；保持布局上下文不要求所有表示一起常驻。回收条件也须包含正在使用的焦点、活动选择和可访问内容，不能只按离视口的像素距离卸载。

这里有明确代价：保持章节上下文可能增加峰值内存。语义与显示正确是分片条件，不能只凭源对应仍在就采用通用切分。整章已经超出预算又没有已验证拆分方式时，明确以资源限制结束该次操作，不能呈现被悄悄改写的部分内容。

<a id="typography"></a>

## 正文字号与内容层次

text.fontSize 调整正文基准，标题、小字、注音及其他内容保留适当层次。字号、字体、行高、段距、配色与特殊图文的完整规则见[读者样式](styles.md)；布局采用同一次转换结果，不改变源结构、地址或宿主偏好。

<a id="view"></a>

## 呈现、选择与标记协作

view/view.ts 拥有主阅读流程与当前布局，采用完整技术设置协调 flow、当前内容及混合边界。view/fixed.ts 处理原始页面的测量、编组和显示变换，view/reflow.ts 处理文字设置、生成阅读面以及连续正文；原始页编组与正文分页可以独立指定，两者不另存主位置或阅读流程。view/geometry.ts 处理规范页面坐标与当前视图之间的正反变换。PDF 的固有旋转和有效页面边界先由 pdf 解释，用户旋转、裁边和缩放再由视图处理。显示排列不改写源页面身份。

view/document.ts 拥有书内 HTML、SVG 和 CSS 的隔离呈现、受限资源接入及内部链接交互。它保留格式提供的源对应，不重新定义 CFI 或字节地址。独立文档保留书籍样式上下文，内容 CSP 限制书内执行与加载，资源入口拥有具体读取范围；sandbox 参数服务于实际接入，不作为不可替换的产品要求。展示转换与资源改写在所属入口完成，不在各层重复全部检查，正常阅读能力仍须完整成立。

呈现使用[独立章节文档](#documents)。跨文档选择由 Kana 在源地址层协调，输入、原文与复制见[阅读交互](interaction.md#selection)，宿主不拼接局部 Range。

selection 持有当前逻辑选区，浏览器 Range、命中位置和局部几何只作为当次呈现状态。普通选择和跨章节选择最终都交付匹配的源范围与原文；只能可靠表示固有页面文字时，按既定规则交付有序四边形。marks 消费已经定义的源位置或范围，复用同一映射取得当前几何；排版更新后重算显示，不改写正式位置或已保存摘录。

search 读取格式提供的正文及源对应，按需建立可回收的临时索引，逐步交付带有可恢复地址的命中。getTextContext 使用同一源文字能力取得有界邻近原文，不通过移动阅读视图或改写当前选区实现。文档没有可提取文字、某一标记无法恢复和一次操作读取失败分别按真实含义交付。

navigation 组合源定位与视图更新，按[完成条件](api.md#completion)确认实际可见结果。字号或尺寸变化时，以源位置维持落点，重算布局和标记。

reader 关闭时停止接受新工作，取消或结束未完成操作，停止观察，解除交互与视图，再释放格式及资源。可重入调用、操作替代和关闭期间的结果交付遵守[公开合同](api.md)；普通异步工作不因此获得永久任务身份或跨实例队列。

<a id="documents"></a>

## 独立章节文档与浏览器排版

使用独立 iframe 呈现章节投影或固定页面，保留书籍自己的根元素、选择器、字体命名和纵横排布局，不与应用工具栏或其他章节竞争样式。重排分页按[多投影机制](#projections)为实际阅读面建立完整章节展示文档，共用同一份源解释与阅读状态。Kana 的宿主代码负责 DOM 测量、事件接入与高亮；书内代码不执行。隔离以这些实际行为为合同，不把某个 sandbox 参数组合定为不可替换的要求。

各机制分别承担自己的职责：

| 拥有者或机制 | 责任                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| 独立内容文档 | 保持文档与样式上下文，隔开书籍布局和应用界面                           |
| 内容文档 CSP | 禁止书内代码执行，约束自动加载、表单、嵌入内容及可执行动作             |
| 资源入口     | 只交付本次授权范围内的字节，解释成员路径并将资源引用映射到实际可用地址 |

内容 CSP 在书籍内容进入活动文档之前建立。需要通过 allow-scripts 保持正常事件接入的浏览器，可以采用该参数；此时不能再把 sandbox 当作禁脚本的保障，实际执行限制由内容 CSP 承担。宿主自己的控制代码与书籍代码的权限分别确定，不向书籍注入 Node、IPC、SDK 等宿主能力。

宿主 CSP 与内容 CSP 共同生效：部署允许库实际使用的受控资源形式，内容策略限定书籍可请求的范围，资源入口再核对本次授权并交付具体字节。每次读取同时满足这些条件。

脚本、事件属性和不支持动作的处理与已有展示转换合并，保留源映射。HTML、SVG、srcset、CSS 引用、样式导入和字体资源由同一资源解释入口处理；使用成熟语法能力完成实际所需的改写，不为每一层各建一套重复检查。内链由 Kana 解释，外链在用户操作后交给宿主。正常排版、选择、链接和资源加载与边界行为一起验收，不以限制层数判断方案是否成立。

内容文档地址不作为持久身份。正式制品中的 worker、样式和解码资源从公开发行资产部署，书内资源由资源模块建立独立的短期引用，不授予文档任意访问宿主资产的权利。

需要浏览器原生引用的内容资源按[资源加载与部署](resources.md)交付：浏览器与 Electron 共用包内 Service Worker，保留目录关系，由本次 Reader 的资源访问提供字节。同源资产、专用作用域与相应协议能力属于接入条件；静态登记与本次内容占用分别释放。

内容就绪按[共同完成条件](api.md#completion)确认。竖排、ruby、双向文字、跨章滚动和巨大章节使用真实出版物样本验证。

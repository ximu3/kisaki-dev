# VNDB 标签、图片与账号边界验证

核对日期：2026-10-12。本轮将剩余能力与现有标签、图片、记录和扩展边界一起核对。[实际资料](2026-10-12-tags-images-account-boundaries.json)保存三个公开 POST 的请求与完整响应，以及一个无凭据的 authinfo 失败响应。没有使用账号令牌，没有执行远端写入，也没有下载或展示原图。

## 公开样本与完整性

| 查询                      | 结果                         | 核对用途                                               |
| ------------------------- | ---------------------------- | ------------------------------------------------------ |
| VN v11、v17               | HTTP 200，2 条，more = false | 直接标签、主图、截图与图片评定                         |
| Character c15、c42        | HTTP 200，2 条，more = false | 特征组、同名特征、性内容与剧透标记、肖像               |
| Release r174、r541、r3748 | HTTP 200，3 条，more = false | 封面类型、单作品与多作品包装、图像归属和语言范围       |
| 无凭据 GET /authinfo      | HTTP 401                     | 认证失败的实际响应形态，不代表已验证有效令牌或权限组合 |

三个成功查询完成了这组指定记录的读取，不表示已枚举来源所有图片或全部发行。原文简介未进入这些请求。源站公开源码保留文件地址、Git blob SHA 与下载内容的 SHA-256，用于说明本轮依据，不复制整个源码仓库。

## 标签含义与名称

[源站标签规范](https://vndb.org/d10)按适用程度区分 1、2、3 级，角色特征则没有这种等级。lie 可以描述故事中出现过、后来被揭示为不实的情况，不能当作普通真假错误或无效网络结果。

| 作品 | 返回直接标签 | lie | 排除 lie 后全部正分 | 排除 lie 且 rating ≥ 2 |
| ---- | ------------ | --- | ------------------- | ---------------------- |
| v11  | 195          | 0   | 195                 | 135                    |
| v17  | 203          | 5   | 198                 | 102                    |

v17 的 No Sexual Content 虽 applicable = false，仍在实际响应中。[源站编辑器](https://code.blicky.net/yorhel/vndb/src/branch/master/js/contrib/TagEdit.js#L38)把 applicable 与 searchable 分别用于“允许添加”和“允许检索”。它们不是当前条目是否具有该标签的布尔值。

c42 同时返回 i6 的 Hair／Brown 和 i53 的 Eyes／Brown。只取 name 会错误地归成同一个 nameKey；以来源组限定组成 Hair: Brown、Eyes: Brown，可以直接使用现有平面标签模型。[API 特征字段说明](https://api.vndb.org/kana#post-trait)也明确要求名称与组一起理解。

已确认[标签采用规则](../../../design/extensions/sources/vndb.md#tags)：默认完整保留正分直接标签，排除 lie，按适用度排序；用户可以通过扩展设置收窄适用度范围。角色特征采用限定名称，并保留应用的剧透标记，不参与作品标签的适用度过滤。上表第二种计数对应用户将范围设为 2–3 的效果，不是默认门槛。

## 图片用途与归属

实际 r174、r541 分别有正面与背面包装图；r3748 同时包含六部作品，图片未指定单独 VN。前两项的 pkgfront 能作为当前游戏主图候选，后者不能自动成为六部游戏各自的封面。图片归属与发行包归属必须分开判断。

[发行图片规范](https://vndb.org/d3#6)将数字宣传图用于网站、商店的封面和横幅，也允许特定情形下只有标志。因此 dig 本身不足以声明 titleLogo 或 iconImage。封面与截图分别适配现有 primaryImage、backdropImage，用途解释留在 VNDB 扩展内。

v11 的十张截图中，两张 sexual 分别为 1.13、2；其他八张的 sexual、violence 均不超过 0.4 且已有评定票数。v17 的十张截图均满足后一个条件。[源站图片分类](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/Images/Lib.pm#L40)按 0.4、1.3 分界，无票图片另行处理。

已确认[图片采用规则](../../../design/extensions/sources/vndb.md#images)：默认保留全部符合用途和归属要求的图片，因此两个作品均有十张截图候选；只有用户在扩展中限制为 Safe／Tame 时，才分别保留八张和十张。扩展内处理来源评定，主应用不增加筛选阶段。样本另以六个合成场景检查默认包含未评定图片、限制时排除未评定图片，以及两个阈值的边界。

这只核对来源字段和候选过滤效果。图片字节未取得，分辨率、安全解码、准备与最终附件采用尚未运行；也没有从图片评分推导作品或角色的 isNsfw。

## 账号字段与可见性

来源提供单一完成日期。本体完成记录使用完整 CalendarDate 或 null，回写取最早已知日期，不补精度，也不把单一日期当成完整历史。当前状态与完成事实分别处理；开始日期没有本体同义字段。[个人记录说明](personal-records.md)记录可对应字段与权限要求。

公开源码确认评分会自动维护 Voted 标签，而记录隐私由其全部标签共同计算。评分与状态需要核对最终效果；2026-10-16 确认按平台原生规则接受可能的可见性变化，不再以保留原可见性为条件阻止写入，不修改全局标签设置，也不增加本体同步模型。

[合成账号投影](2026-10-12-account-projections.json)包含十项隐私与完整性、八项评分、十项日期检查，日期范围和清空规则已按后续[账号读写实测](account-roundtrip.md)修正。其中隐私保护拒绝与逐条可见性前提已被[原生写入规则](../../../design/extensions/synchronization.md#writes)取代；标签隐私配置均为虚构示例，不作为真实私有记录证据或当前验收断言。令牌、三条临时记录的回写及分页已另行核对；服务器并发、自定义与私有记录组合、完整 provider 运行尚未验收。

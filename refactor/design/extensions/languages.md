# 三个官方界面译本接入方案

三个官方译本分别提供简体中文、繁体中文和日语的完整主应用消息目录，遵守[本地化合同](../ui/localization.md)，各自维护身份、版本、安装包、源码与审校。繁体中文采用台湾常用措辞。

<a id="projects"></a>

## 三项身份与范围

| 序号 | 项目目录         | 扩展 ID                 | 译本登记 id         | locale  | 选择器自称 |
| ---- | ---------------- | ----------------------- | ------------------- | ------- | ---------- |
| 31   | language-zh-hans | kisaki.language.zh-hans | simplified-chinese  | zh-Hans | 简体中文   |
| 32   | language-zh-hant | kisaki.language.zh-hant | traditional-chinese | zh-Hant | 繁體中文   |
| 33   | language-ja      | kisaki.language.ja      | japanese            | ja      | 日本語     |

项目均位于 clients/desktop/extensions/projects/。扩展 ID、译本 id 和 locale 分别表示包身份、包内具体译本与语言，不互相替代。每项当前登记一个译本；展示名称、措辞和文件组织调整不改变稳定引用。主应用的完整英语基准仍为内置 en，不另计第四个语言扩展。

三项都使用基本 Node 模板，仅加载包内消息并调用 i18n.translations.register。用户入口为原生引导、扩展管理和语言设置；没有独立 Webview、菜单、账号、资料 provider、导入或同步业务，也没有私有设置与持久数据。主题、字体和资料语言仍由各自能力负责。

译文覆盖主应用实际可翻译的界面、菜单、提示、操作反馈、无障碍名称和状态说明，含详情、整理、阅读、播放、任务、设置及失败／部分完成情形。扩展自有页面、来源返回的文字、作品名称、用户笔记和媒体正文不属于主应用译本的覆盖范围。

## 安装、选用与生命周期

三个包经普通分发仓库在线安装，安装后可以离线使用。首次运行使用完整英语，按系统语言推荐具体译本，并用各语言自称帮助识别。用户明确选用后，完成所需安装与激活，再保存 UiTranslationRef。下载、安装、激活和选用分别交付结果，当前语言以保存的选择为准。

引导根据发行提供的三项固定推荐身份、语言与自称展示未安装选项，不从 categories 推断语言，也不执行未安装包来探测贡献。推荐项只用于安装和选用草稿；正式可用目录仍来自真实登记，不把推荐表当作第二份译本注册表。

偏好保存包含 extensionId 和译本 id 的完整引用。安装其他语言、系统语言变化或另一份同语言译本出现，都不改写选择。已选包停用、卸载、不兼容或激活失败时，实际界面回到英语，但保留所选引用；原译本重新可用时正常恢复。新选用失败保留原选择与草稿，不先切换再留下半套消息。

登记归属于真实扩展实例，在激活成功后统一发布，失败时不发布其中的有效子集。旧实例和旧登记释放句柄不能撤销后来同名的新登记；迟到回调不能重新发布失效实例的消息。包内目录只作为纯数据交给宿主，普通取词不会调用扩展函数或联网。

已有窗口与菜单随有效译本更新，当前表单、焦点和用户内容保持。即使 locale 相同，改选另一具体译本或采用它的新内容，也要更新消息显示，不能仅按语言码缓存。只有实际有效语言改变时才需要让扩展自有消息系统切换语言；主应用的译文内容变化由自身 i18n 通知处理。

冷启动沿用[共同 5 秒首屏预算](../architecture.md#startup-readiness)与普通扩展激活生命周期。已经就绪便继续显示，失败或超时只回退尚未就绪的资源；稍后在有效实例中登记成功时正常采用。语言扩展不增加专用启动阶段，也不因首屏停止等待而被冻结。

## 英语基准、目录与参数

主应用英语拥有消息键、含义与调用参数。三个译本按领域维护嵌套 ICU 字符串，完整路径是消息身份；对象是分组，字符串是叶子，不使用函数、数组、运行代码或公开 AST 作为消息值。单段键不含点，文件移动不改变消息身份。

从同一英语基准生成叶子键、参数约束和作者校验所需的源文。公共纯合同归 desktop-contracts/i18n，经 extension-api 与 SDK 的作者入口提供；本体和扩展项目使用这一份生成合同，消息身份遵循本体的键与参数规则。

三个官方项目在普通构建前检查中导入自己的纯消息目录，并对公开基准验证完整性、ICU 和参数。通用 kisx 的静态制品校验不执行 activate 来发现译文；正式登记仍由宿主按当前英语合同核验。SDK 中的作者基准与运行应用可能来自不同已发布版本，运行时规则负责处理新增与缺失键，不拿包版本冒充消息版本。

ICU 解析与格式化采用[现成 FormatJS 实现](https://formatjs.github.io/docs/intl-messageformat/)，不自研语法和复数规则。普通插值接受 string 或 number，number／plural／selectordinal 要求 number，date／time 接受 Date 或毫秒，select 接受 string。多处使用同一参数取兼容约束的交集，交集为空时英语构建失败；select 分支不是参数的封闭枚举。

译文可以调整参数位置、复数和选择分支，也可以省略该语言不需要的参数。它不能新增参数，或收窄成某些合法英语调用无法满足的类型；例如英语允许 string 或 number 的插值，译文不能单方面要求 number。调用方始终遵守英语合同，不能因某种译文省略了参数就省掉公共调用参数。

t 只产生普通字符串。解析与格式化采用相同的 ignoreTag: true 规则，HTML／XML 样式的文本按字面值处理，UI 用文本方式呈现；消息与参数不执行标记，也不通过富文本回调返回组件。真正需要链接或视觉结构的界面由组件提供，不把结构藏进译文。参数中的大括号和标签不再次解释为 ICU。

日期、时长、数值与业务单位按其实际语义格式化，不在译文中改变时区、换算数据或补齐 PartialDate。格式化调用明确使用当前有效语言；locale 保持规范 baseName，日期、数字或排序选项不混入语言标签。官方 zh-Hant 的用词基准是台湾表达，不把身份改成 zh-TW，也不承诺其他地区的独立词汇版本。

## 完整交付与运行回退

每次官方译本发行完整覆盖所依据的英语基准，同时完成目标语言的措辞审校和真实界面检查。消息须是适切、完整的译文。英语仅调整措辞时保留键，含义或参数发生不兼容变化时按共同合同使用新键。

旧译本遇到本体后来新增的键时，逐条回退英语；第三方部分译本沿用同一运行合同。回退消息以英语的语法和格式化规则解析，不借用另一份已安装中文或日文，也不把句子拆成混合语言片段。空字符串与缺键是不同事实，不能在解析时混同。

已知键的 ICU 或参数错误拒绝整份登记，原有效译本／英语继续可用。未知键不参与当前应用解析，不能因为它们属于较新基准就执行其内容；目录整体仍须满足纯数据与资源预算。调用缺参或类型错误是程序错误，不当作缺词，也不通过语言回退隐藏。

manifest、registry 和发行说明使用 LocalizedText，自有 defaultLocale 与匹配规则保持独立；名称以原生语言自称显示。zh-CN 与 zh-Hans、zh-TW 与 zh-Hant 可在相同文字体系中匹配，简繁不互相转换。安装包展示文案的匹配不会改选 UI 译本。

<a id="simplified"></a>

## 第 31 项：简体中文

采用自然、简洁的大陆简体中文表达。按钮与菜单使用明确动作，字段名称使用稳定名词；“设置、文件、保存、添加、导入、导出、扩展”等用词保持一致。已有中文资料可作为审校参考，但以新英语基准及已确认的业务含义为准。

作品类型使用“游戏、动画、漫画、小说”，共享实体使用“角色、人物、组织”；动画与漫画分开，不将 Anime 泛称为动漫。合集、喜爱、标签分别表达，个人评分不混为公众评分。当前状态采用在玩／在看／在读等媒介语境，完成记录、附加时长和实际运行状态保持不同含义。

“记录本次完成…”与“补录完成记录…”分别对应既有完整操作，不把动作翻译成一个可直接写入的已完成状态。日期未知显示“日期未记录”，不表达为尚未完成。“移除”和“删除”按真实对象与影响使用，不为了词面整齐省掉关联、记录或文件的区别。

<a id="traditional"></a>

## 第 32 项：繁体中文

依用户选择，以台湾常用措辞独立编辑和审校。典型用词采用“設定、檔案、儲存、新增、匯入、匯出、擴充功能、載入、重新整理、預設”，不把简体逐字转为繁体就视为完成。

保留与其他译本相同的对象和操作语义，例如“動畫／漫畫”“合集／喜愛”“目前狀態／完成紀錄”。动词“記錄”与名词“紀錄”按实际句子使用；“記錄本次完成…”与“補登完成紀錄…”分别表示当前完成动作与补录历史。完整句子的语序、语气和常用词都须审校。

登记名称固定为“繁體中文”，locale 为 zh-Hant，用语采用台湾措辞。zh-TW、zh-HK 等系统语言用于推荐，实际安装和选用由用户决定。译本作用于主应用界面，用户正文与来源资料保持原样。

<a id="japanese"></a>

## 第 33 项：日语

采用自然日语界面表达，标签偏简洁名词，动作使用清楚的动词短语，说明与反馈使用一致的です／ます语气。术语、汉字与片假名按实际习惯选择，不照搬中文词序或对每个英文词机械音译。

作品类型使用“ゲーム、アニメ、マンガ、小説”，角色、人物与组织分别使用“キャラクター、人物、組織”。喜爱使用“お気に入り”，合集使用“コレクション”；在玩、在看、在读分别使用“プレイ中、視聴中、読書中”，与实际执行的“実行中”区分。

完成动作可表达为“完了を記録…”，历史补录为“過去の完了を追加…”，日期未知为“日付未記録”。翻译不能把阅读进度、文件末尾或记录操作变成不同的业务行为。计数和参数位置采用日语语法，不照搬英语复数分支。

## 三语共同的文案与显示要求

| 含义                    | 简体中文      | 繁体中文      | 日语                   |
| ----------------------- | ------------- | ------------- | ---------------------- |
| Save                    | 保存          | 儲存          | 保存                   |
| File                    | 文件          | 檔案          | ファイル               |
| Extension               | 扩展          | 擴充功能      | 拡張機能               |
| Anime                   | 动画          | 動畫          | アニメ                 |
| Organization            | 组织          | 組織          | 組織                   |
| Collection              | 合集          | 合集          | コレクション           |
| Favorite                | 喜爱          | 喜愛          | お気に入り             |
| Metadata profile        | 资料方案      | 資料方案      | メタデータプロファイル |
| Record completion       | 记录本次完成… | 記錄本次完成… | 完了を記録…            |
| Past completion         | 补录完成记录… | 補登完成紀錄… | 過去の完了を追加…      |
| Unknown completion date | 日期未记录    | 日期未記錄    | 日付未記録             |
| Running content         | 正在运行      | 執行中        | 実行中                 |

术语表按所述含义使用，具体译法结合上下文确定。业务术语遵循当前模型，翻译公司、完成状态、来源读取和计数等概念时，分别核对其对象与业务含义。

沿项目文案规则，单句界面文案省略句末句号，多句说明逐句完整标点；问号、感叹号和表示后续输入的省略号按实际用途保留。占位文字只给搜索提示或格式示例，不重复字段标签，也不增加“请输入”等礼貌填充。

中文与日语采用各自标点、助词和量词；不通过机械增删空格修饰用户名称、代码、路径或 URL。专名保留官方写法。真实标题、长路径、数字 0、复数、未知值、英文缩写和补充平面字符都进入界面验收，不能为了适配短按钮而改变操作含义。

界面语言更新根文档 lang 和适用的格式化环境，字体选择与回退继续由外观／字体模块处理，译本包不捆绑或强制字体。用户内容自身的语言与排版由内容所属功能决定。现有资料方案、合集、扫描器及展示柜已经保存的名称保持普通用户文本，不因译本切换重写。

无障碍名称、输入提示、错误说明和可见文字采用相同语义。实际布局核对默认、75% 与 200% 缩放、窄窗口、长名称和 CJK 换行；表格仍一字段一列，保留必要列并横向滚动，不通过隐藏字段或重写译文来掩盖布局缺陷。

## 源码、依赖与独立交付

三个项目各自保持如下简洁结构，messages 下按实际领域拆分：

    src/
    ├── entry.ts
    ├── messages.ts
    └── messages/
        ├── actions.ts
        ├── library.ts
        ├── records.ts
        ├── reader.ts
        └── settings.ts
    tests/
    └── fixtures/

entry 轻量登记稳定身份；messages.ts 汇总本项目的完整嵌套目录；领域文件只保存本语言文本。不为三项建立共享运行译文、简繁转换层、英语运行继承或互相导入的私有目录。共用纯校验与 ICU 工具由既有公共能力提供。

每项维护 package.json、kisx.config.ts、README、四语 release-notes 与测试。包版本以 package.json.version 为唯一来源，manifest 提供实际 API 兼容范围、ESM 入口、英文默认展示文案及四语名称／说明。分类只用于发现，不推导激活顺序或权限。

消息无需平台专属二进制，每项交付一个明确覆盖 windows-x64、windows-arm64、macos-x64、macos-arm64、linux-x64、linux-arm64 的自包含 .kisx，不使用 any 或空 targets。格式化引擎由本体 i18n 消费，语言包不重复捆绑另一套解析运行时。开发校验依赖与实际运行依赖分别声明，安装不再下载代码或执行构建。

完整性检查和审校针对每次发行采用的英语基准，三个译本可分别更新；新本体的新增消息仍有英语回退。运行包身份与 API 兼容继续遵守[分发合同](distribution.md)，不因为语言包只有数据就绕过安装、更新、哈希或生命周期校验。

来源核对与样本范围见[验证记录](../../verification/evidence/extensions.md#languages)。

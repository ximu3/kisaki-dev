# Bangumi 本人收藏接口验证

验证日期：2026-10-13。使用用户为本轮测试提供的临时 token，先通过 GET /v0/me 核验账号，再检查本人收藏和写入路由。[脱敏结果](2026-10-13-authenticated-collections.json)不保存 token、账号编号、用户名、完整个人档案或已有收藏对象的身份。

## 读取与现有收藏

人物、角色收藏列表均返回 200。基线为一条角色收藏、零条人物收藏。对既有角色执行 POST /v0/characters/<id>/collect 返回 200，回读后仍为同一收藏，原 created_at 保持不变。这验证了该收藏入口确实可调用，以及本次重复请求的幂等行为；没有将其写成一次新收藏创建测试。

人物与角色的独立收藏和作品 subject 收藏清单是不同接口。作品收藏的 type 表达想看、在看、看过等状态，不能由这些接口名称推出作品另有一个独立喜爱字段。

## 取消路由与对照请求

先核实 character/10596 和 person/603 不在本人收藏中，再分别调用 DELETE /v0/characters/10596/collect 与 DELETE /v0/persons/603/collect。两项均返回默认 404，回读仍未收藏。

为区分资源状态与路由是否接收请求，使用明确无法成为资源编号的 not-a-number 做对照：

| 资源路径                            | POST | DELETE |
| ----------------------------------- | ---- | ------ |
| /v0/characters/not-a-number/collect | 400  | 404    |
| /v0/persons/not-a-number/collect    | 400  | 404    |

POST 进入参数校验，而 DELETE 没有进入同类处理路径。结果与[当前官方路由](https://github.com/bangumi/server/blob/4223d14057fea5078595e40470f8602d3301abb5/web/routes.go)中登记 POST、注释 DELETE 的情况一致。本次部署的这两个取消接口不能作为已可用能力，不能按 schema 声明就提供取消同步，也不能把 404 当作已成功撤回收藏。

## 数据保留与验证范围

最终角色、人物收藏数量与基线一致，既有角色的收藏时间保持不变。没有新增可能无法通过 API 撤回的测试收藏，也没有修改作品状态、评分或其他个人记录。

本轮验证了本人读取、角色重复收藏请求与两类取消路由的实际边界。人物 POST 的合法新增、角色新增后撤回、作品记录写入、授权刷新和完整扩展运行不属于已完成项。后续只开放实际支持的独立操作，不用其他平台行为模拟取消。

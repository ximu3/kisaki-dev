# 开发连接的完整替换草案

本稿记录确认前的完整方案。确认后的唯一规则已进入[正式合同](../../../../design/engineering/protocols.md#development)，实现与验证见[实施记录](implementation/README.md)；后续细化以正式合同为准。技术依据与探索覆盖见[探索记录](README.md)。目标是让源码桌面开发与第三方扩展开发使用同一套父子消息接入，减少自行维护的通信和重复调度，同时保留真实的构建交接与退出语义。

## 一条启动与通信链

唯一启动器通过 Node child_process.spawn 创建应用，使用 stdio 的 ipc 项与 JSON 序列化。源码开发启动项目中的 Electron 和本次 main 入口，作者开发启动已安装或明确提供的 Kisaki；平台适配只负责取得实际可执行文件和参数，不建立另一种消息通道。

desktop:dev 继续拥有应用进程的启动、源码重建后的重启与退出，组合 extension-cli 的程序化构建监听能力。独立 kisx dev 则由 CLI 拥有应用进程。程序化工作流使用启动器交给它的本次连接，不自行再启动应用，也不从运行进程中查找并附加。连接与回调归实际子进程对象；重启建立新的连接，旧等待结束。

删除专用命名管道／Unix socket、端点路径及权限装配、一次性连接 token、每条消息上的 sessionId、四字节长度头、手写 UTF-8／拆包／合包，以及这些机制专用的测试。Node 内部如何实现 IPC 不成为本项目的线协议。没有第二种传输、自动重连、消息重放或旧协议回退。

## 显式开发模式与资料归属

正式和源码应用都通过明确的开发启动参数进入受控开发模式，并接收启动器选定的绝对 profile 路径。主进程在数据库、日志和浏览器 Session 建立前选择该路径，要求本次父子 IPC 已存在；普通启动继续使用正常安装或便携规则。模式判断不再等同于 !app.isPackaged。

构建目录属于本次会话，profile 按已有 .local 规则跨会话保留。复用本体已有的资料根占用规则，不增加工程锁。renderer 开发地址仍只用于源码应用开发；作者开发只按已登记的 Webview 映射开放本次扩展的开发内容。

开发入口在包内正常主模块中实现，保留现行 fuses；不使用 ELECTRON_RUN_AS_NODE、NODE_OPTIONS 或外部主脚本注入正式包。扩展 Node inspector 与 Webview 调试继续由明确的开发选项和实际宿主提供，不因改用 IPC 开放全局调试或远程控制。

## 消息与单一调度拥有者

development 的版本继续表示 CLI 与应用共同理解的消息合同。启动器建立通道后发送一次 initialize；应用先核对版本，完成自身启动后报告 ready。profile 等必须在 app.ready 前确定的输入通过启动参数给出；异步初始化不在 ESM 顶层等待 app.whenReady。

纯值、消息结构与校验由同一公共合同拥有；父进程和应用分别接入自己的公开 send／message API。少量接入代码留在实际拥有者中，不为这条连接新增包或通用通信框架，也不把旧字节帧实现搬进 rpc 后继续保留。

| 消息 | 方向与用途 |
| --- | --- |
| initialize | 启动器 → 应用；声明本次 development protocolVersion |
| ready | 应用 → 启动器；交付实际 protocolVersion、appVersion、apiVersion 与桌面 buildId；可以接纳构建，不表示扩展已激活 |
| buildsReady | 工具 → 应用；交付一批已经完成且不会继续修改的扩展构建引用 |
| adoptionResult | 应用 → 工具；报告这批构建的实际采用、激活结果，以及完整结束或中途停止 |
| buildsReleased | 应用 → 工具；列出已无宿主、视图或资源读取者使用的构建引用 |
| stop | 启动器 → 应用；请求按本体正常退出流程结束当前实例 |
| stopResult | 应用 → 启动器；说明退出被取消、失败或已经进入退出；实际进程结束仍由启动器观察 |
| failed | 应用 → 启动器；启动或连接已无法继续，交付安全错误 |

同一连接只允许一批构建正在采用。CLI 拥有等待交付的最新构建集合：编译仍可继续，每个扩展只保留最新待交付结果；当前批次结果到达后，再发送下一批。应用负责一次采用及自身共享宿主的真实重建，不维护第二份跨消息的候选队列。

因此删除跨消息 batch sequence 和线上 superseded 结果。尚未交付的旧候选由工具自己替换和清理；已经交付的批次必须交付自身结果，不能拿下一批结果代替。stop 同样至多有一个在途请求，重复调用等待同一次处理，不另设 stop requestId。终态未确定的请求不会被超时后清空，再继续复用同一关联。

每份构建仍保留 extensionId、buildId、rootPath 与实际 webviews。buildId 只关联这份临时构建及其释放，不作为用户版本或跨进程并发锁。删除 manifestSha256：构建拥有者已经保证目录完成后不再改写，应用正常读取并校验实际 manifest、入口、兼容和文档映射。安装包的签名与字节校验仍属于正式安装流程。

adoptionResult 按输入构建引用交付 adopted／notAdopted，激活结果另列真实尝试的实例；整体不能继续时保留已有确定结果和实际错误。编译成功、采用成功、激活成功和旧目录已释放继续分别表达。Node send 的回调只说明传输结果，不代替这些业务结果。

## 停止、取消与资源释放

启动之前的准备可以通过 AbortSignal 取消，完成实际编译与资源收尾即可。应用已运行后的普通停止，由开发会话请求本体退出；保留正在使用的构建目录和 Web 服务，等退出决定成立后再关闭其余资源。

退出被取消时，stop 返回 cancelled，会话继续可用；不能先永久 abort 全部编译与服务器，再留下仍运行的窗口。重复停止共享当前等待，之后的新停止是明确的新请求。DevSession.closed 只在本会话实际结束并完成资源收尾后完成。

开发 CLI 的运行期中断接入按上述停止语义组织，不直接复用有限命令的一次性 abort 作为全部流程。通用构建、打包和有限工具的 runCli 无需因此改成能够撤回取消的通用框架。源码热重启与扩展宿主重建继续遵守各自明确的开发重建规则，普通停止不借重载语义强制丢弃编辑。

启动器通过实际子进程的 exit 确认结束，分别处理创建失败和自己取得的日志流。IPC disconnect、stopResult.exiting 和等待超时均不能证明进程已经结束。已经交付的构建仅在得到释放通知，或正常收尾已确认相关读取者结束后清理；异常结束且读取者状态不明时保留目录并报告。

连接丢失停止后续交接并结束相应等待，已提交事实保持。应用按既有正常退出规则处理；退出被取消时明确开发连接已经结束，已保存 profile 保留。强制结束只用于开发者明确要求结束本会话拥有的进程，不扩大到普通实例或外部业务进程。这里不新增监控守护程序、PID 轮询、自动恢复或跨运行的清理协议。

## 唯一合同与完整落点

| 拥有者／位置 | 一次替换时完成的工作 |
| --- | --- |
| desktop-contracts/development | 唯一定义启动输入、必要版本、有限消息和业务结果；不再定义字节帧、端点或 token |
| extension-cli 的 dev 工作流 | Node 连接接入、最新待交付构建、逐批采用、目录释放，以及独立作者启动器；导出程序化入口供源码开发组合 |
| app 的开发接入与 extensions | 识别开发启动、选择隔离资料、初始化版本、调用真实采用／退出操作并交付结果；共享宿主的重建仍由实际 runtime 拥有 |
| app/tools/dev | 保留源码编译、Vite 与进程拥有权，消费同一开发合同和程序化会话；移除自己平行维护的控制消息 |
| app/src/shared/development-session.ts | 删除私有 ready／shutdown 定义，实际消费者改用唯一公共入口 |
| app/src/main/app/bootstrap.ts、paths.ts | 移除只凭未打包状态开放控制的逻辑；显式开发模式与正常模式各自选择正确资料和能力 |
| app/tools/dev/electron-process.ts、session.ts、cli.ts | 统一消息、实际退出观察与可取消停止；避免旧的固定等待后强杀与已 abort 会话继续运行 |
| 正式设计 | 同步 protocols、development、workspace、layout、通信入口及相应 W01／W03／W08 责任，清除旧线协议和重复的队列／身份描述 |
| 验收及旧证据 | 移除拆包、非法 UTF-8、端点权限和 token 的新实现验收；历史探针保留原范围并注明设计已替代，不改写为新方案通过 |

当前 socket 方案尚未正式实现或发布，替换直接更新这一未发布合同与实际 W00 控制链。实施时完成上述所有实际消费者和正式引用，不让“源码桌面用旧控制、作者工具用新控制”长期并存。未到实施阶段的业务仍由所属工作包交付，不为证明替换完整而提前生成空模块。

## 验证范围

验证开发模式资料隔离、版本不符、正常就绪、构建交接、激活失败、旧构建释放、源码重启，以及停止被取消后继续使用和真正退出。业务机制在所属层验证，两类启动方式各贯通其实际接入；不把同一批故障复制到每个扩展。

平台接入使用真正的 Windows exe、macOS bundle 可执行文件和 Linux 应用／AppImage，记录实际 IPC、退出及既有加固条件。Windows 本轮试件提供机制依据，其余目标仍需相应运行证据；来源资料、媒体、全库性能和全部 UI 流程不因通信层替换机械重跑。

# Kana 资源与部署

资源访问、字节传输、取消、预算与临时存储沿同一实际拥有关系收尾。

<a id="resources"></a>

## 授权读取与临时资源

resources/access.ts 适配一份文档字节源或图片目录成员集，支持有界范围读取、按需成员读取和取消。宿主只需提供读取能力；内部格式识别、解包与排版由 Kana 完成。File、Blob 和 URL 是便捷入口，不使浏览器包依赖 Node fs，也不把 Kisaki 的 ReadResourceRef 或 IPC 合同复制进库。

源文件、归档成员、格式内部引用和显示用临时 URL 分别保留其含义。资源访问按照当前授权范围和规范成员路径解析相对引用；临时 URL 不成为成员身份，文件后缀也不授予网络访问权限。样式、字体和图像的嵌套引用同样经过这一边界。

resources/transport.ts 拥有临时内容地址、当前资源拥有者与静态登记的连接，content-worker.ts 是实际随包交付的转发程序。两者遵守[部署条件](#deployment)，不拥有格式解析或另一套 Reader 状态。内容呈现转换仍归 view/document.ts；源成员及授权字节仍从既有 resources/access.ts 取得。

PDF 接入可以使用 [PDF.js 的自定义 range transport](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)，ZIP 接入可以对接 [zip.js 的自定义 Reader](https://gildas-lormeau.github.io/zip.js/api/classes/Reader.html)。归档字节的范围读取不代表压缩成员内部能够任意随机解压；所需成员的解码、缓存、取消和释放仍由后端负责。不能先把整份大归档放入内存，再把外层接口称为范围读取。

resources/cache.ts 只维护本实例确需复用的字节或解包结果及其有界回收。资源访问拥有自身创建的临时 URL 及使用引用；view 拥有 DOM、canvas 和布局资源；PDF.js 文档与 worker 由 pdf 实现关闭。不能用一个全局缓存吞掉所有资源，也不要求把第三方库的内部缓存复制出来再管理一次。字体或图像被视图使用时不提前撤销引用，内容卸载或 reader 关闭后应能够真正释放。

Kana 取消并收尾自己发起的读取，释放自己创建或明确接管的适配资源。宿主借给本实例的授权读取范围由宿主拥有：Kisaki 在 reader.close 完成后关闭该范围。旧文档的请求和回调不得读到或更新后来打开的文件。

<a id="budget"></a>

## 资源预算与调度

缓存分别计量压缩字节、解压正文、源索引、DOM、解码图像、页面 canvas 和字体的实际成本。例如，同样一页扫描图与短文字章节有不同的解码和呈现开销。源索引与昂贵显示资源可以分别释放。

由现有 reader 协调本实例的工作准入，各拥有者管理自己的资源。当前可见内容、正在形成的目标及正在交付的完整选择先取得必要额度；搜索和预取使用余量。额度不足时，先取消预取、回收可重建缓存、暂停未消费的搜索，再决定能否继续用户操作。这些职责不形成第二套通用任务平台。

选区保留源端点，DOM 按可见范围及实际交互占用管理。getSelection 固定调用时的源范围，分段读取后交付完整结果，并遵守单次结果上限。搜索按消费者取用进度继续读取，迭代结束或取消后释放本次占用；共享字体、图片等资源按各使用者的持有分别保留和释放。

硬上限与缓存目标分开：前者约束输入展开、原生堆和单次结果，后者决定可以保留多少可重建内容。实际数值由代表性内容及后端测量确定，不用一个任意总 MB 数宣称约束了浏览器全部内存，也不立即增加一组公开调优参数。

搜索消费变慢时，相应减少后续读取和解码，保持未消费结果有界。取消传递到实际工作；长计算无法协作中断时，明确所属 worker 的终止、重建方式及成本。

<a id="ownership"></a>

## 资源交付与执行归属

| 拥有者                 | 责任                                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| 格式与展示转换         | 解释源成员和内部引用，生成可安全呈现且保留源对应的文档                 |
| 每个 Reader 的资源访问 | 取得授权字节，按需解包、缓存、取消与释放；按源事实处理成员路径         |
| 包内 Service Worker    | 接收原生加载请求，转给仍存活的资源拥有者，再交付响应；不解释电子书格式 |
| 浏览器                 | 按文档与各样式表的地址处理相对引用、导入、变量求值和层叠               |
| 宿主                   | 部署发行资产、提供授权输入和允许相应运行能力                           |

地址包含本次拥有者与不可复用的阅读实例标识，后续部分保留书内目录关系。例如同一临时根下的 book/chapter.xhtml、book/styles/main.css 和 book/art/cover.svg。这些地址只用于本次显示，不成为成员身份、CFI、续读或其他持久值。

同一窗口中的独立库副本各有自己的路由身份，内容占用另有本次标识。消息先找到对应副本，再查找仍存活的内容入口；其他副本不抢答，所属副本对已撤销入口明确结束请求。路由只连接资源拥有者，不复制 Reader 的状态或格式事实。

目录相对引用优先原样使用。格式内部专用引用、根路径引用、绝对地址和作者 base 仍须按实际语义映射到授权范围；不能把“保留目录关系”扩大为所有输入属性都永远无需转换。必要转换继续遵守[原值投影](styles.md#attributes)。

宿主不需要解包电子书、解释 CSS 或代理每一个书内成员，也不新增公共资源宿主端口。File／Blob、ByteSource、MemberSource、TemporaryStorage 和字体输入保留各自职责。

<a id="deployment"></a>

## 部署与接入条件

浏览器消费者在 HTTPS 或浏览器认可的本地安全上下文中部署同源包资产。资产包含固定版本的内容转发脚本和专用作用域，注册完成后即可打开书籍，普通宿主页面继续独立运行。脚本使用受控的同源固定地址，平台条件见 [register](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register)。

Electron 通过标准、安全且支持 fetch 与 Service Worker 的受控协议提供应用页面和包资产，并注册到真实窗口的 Session。内容文档与宿主控制代码保持测量、事件所需的同源 DOM 访问，资源加载同时遵守 CSP。实现依据[协议能力](https://www.electronjs.org/docs/latest/api/protocol#protocolregisterschemesasprivilegedcustomschemes)完成登记与读取。

assetsBaseUrl 表示明确部署的同源发行资产目录。资产清单包括实际转发脚本，同源、专用作用域及 Electron 协议能力属于[公开接入合同](distribution.md#assets)。缺少必要能力或资产时，在打开相关内容的准备阶段以 assetUnavailable 明确失败，不悄悄退回另一套有不同 CSS 语义的 Blob 改写路线。

模块导入仍不登记 worker 或加载资产。实际打开需要这种呈现的内容时，Kana 建立或复用对应版本的登记；纯值入口、Node 消费和不涉及该机制的计算没有这一副作用。

<a id="scope"></a>

## 传输目录与内容权限

内容 CSP 禁止书内脚本、可执行动作和未授权加载，允许实际使用的专用传输目录。传输入口再根据请求所属内容文档、本次实例和规范路径交付字节；猜到另一个阅读实例的地址不授予读取权限。请求越界、实例关闭或资源缺失时明确结束，不回到网络寻找同名资源。

实测 Firefox 对合成子资源响应还检查了 Service Worker 脚本地址。只允许每本书路径的 CSP 因此拦下正常资源。统一采用“CSP 约束专用传输目录、资源入口核对实例”的分工后，受查内容在四个运行环境中成立，且受查跨实例取图和目录外加载仍被拒绝。这里没有按 User-Agent 分支，也不能因此把 CSP 放宽为任意同源内容。

浏览器看到形似 HTTP 的临时地址，不表示书籍上传到了服务器。资源拥有者在本地响应，转发脚本不持久保存书籍字节，也不取得书内任意网络访问权。实际缓存与临时存储仍服从已有明确合同。

<a id="lifetime"></a>

## 阅读实例与静态登记的寿命

Reader 拥有授权字节的本次使用、响应中的读取和内容地址。关闭时先停止接纳，取消或结束未完成读取，移除内容文档，再释放自身资源；旧地址不能读到新打开的内容。一个 Reader 关闭不撤销其他 Reader 的资源。

Service Worker 可能由浏览器停止并重新启动，不能让它的内存表成为阅读实例或授权的唯一依据。请求应能找到仍存活的拥有者；拥有者不存在或已经撤销该实例时结束请求。试件使用存活页面的 client 身份与本次实例标识完成这个连接，Chromium 已实际停止 worker 后重新取得内容。[规范的寿命约定](https://www.w3.org/TR/service-workers/#service-worker-lifetime)与 [Clients.get](https://developer.mozilla.org/en-US/docs/Web/API/Clients/get)支持这一责任划分。

静态转发程序的登记可以跨 Reader 保留，登记中不保存书籍与读取权限。单个 Reader 的 close 不注销共享登记。发行版本使用明确的资产目录和作用域，避免活跃实例被其他版本接管；具体部署协作见下文，不靠无条件 claim 或 skipWaiting 切换活动阅读文档。

<a id="streams"></a>

## 原生流与字节交付

资源拥有者将已授权内容提供为原生 ReadableStream，经 postMessage 转移给内容 worker，再形成浏览器响应。采用原生跨上下文流及其背压，不维护第二套 pull／chunk 消息协议。控制消息只承担请求元信息、取消和实际清理完成；本次资源仍由原来的拥有者读取与释放。

范围字节源可以按需填充流，已有顺序解码输出也可以直接接入，不能为了传输额外生成整份常驻 ArrayBuffer 或一套可随机访问的全文副本。借入的字节不被分离；进入响应队列前取得大小明确的独立块，避免一个小视图继续持有巨大后备缓冲。转移流对象不承诺所有字节零拷贝。

转发适配采用单次至多 64 KiB、每个 Reader 至多四个实际源读取的内部基准。许可按实际读取占用并在结束后释放；等待中的当前阅读工作先于后台工作，取消排队项不遗留许可。原生流可以有有限预读，不能把“消费者暂停”解释为已经取得的所有块都立即消失。

这些数值限制 Kana 发起的读取及其持有的交付块。浏览器网络管线、CSS／图像解码和原生队列按自身机制分配资源，格式展开、源索引、字体与 DOM 按所属后端核对容量。各类实际占用和性能分别进入正式验收，调优由实际拥有者实施。

[Streams 标准](https://streams.spec.whatwg.org/#rs-transfer)定义跨上下文流。[Safari 27.0](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/)和 [WebKitGTK 2.54](https://webkitgtk.org/2026/09/16/webkitgtk-2.54-highlights.html)的正式说明均列出可转移流，支持在已确认的滚动维护窗口采用这条原生路线；实际端口验证仍按发行矩阵完成。准备阶段核对真实能力和转发程序身份，不能只检查全局名称存在。

<a id="cancellation"></a>

## 读取占用、取消与收尾

浏览器取消消费、内容占用结束和 Reader.close 都能结束所属读取。原生流的 cancel 与资源拥有者的 AbortSignal 分别接到实际工作；不把 FetchEvent.request.signal 当作唯一取消来源。共享资源的其他使用者继续成立。

异步打开、等待许可、正在读取和释放都纳入当前内容的任务范围。关闭先撤销入口和发出取消，再等待本次实际读取与释放结束。已经交付的字节不能撤回，但取消后的迟到结果不再作为新内容采用；读取中途失败不能把部分响应报告为完整成功。

一个释放步骤失败时，继续等待其余步骤，最后按已有错误合同失败。closed 仍只表示句柄不能继续使用，不代表所有释放都成功。浏览器响应失败只用于结束该次加载；根输入变化、局部资源失败与取消的正式分类继续由资源拥有者交给 Reader，不能由 HTTP 状态反推业务原因。

MessagePort 关闭事件不能作为唯一的端点寿命依据。活动传输在无进展期间核对端点：worker 检查拥有者 client，拥有者检查 worker 的执行实例。只有端点消失、实例已更替或核对本身失败时结束相关传输；经过一段时间本身不是失败依据。后台调度不构成精确时限承诺。

这项核对只在尚未结束的传输中存在，有进展时重新计时，结束时清除。它不维持静态登记常驻，不恢复旧请求、不切换源文件，也不为普通失败建立重试系统。正常 close 直接取消并等待实际工作，不等待这项核对。拥有者页面销毁后，宿主仍按原有窗口寿命关闭其持有的原生读取范围。

<a id="versions"></a>

## 作用域、并存与版本退役

每个发行版本使用不可变的资产身份和专用作用域。已有 PWA 可以继续控制宿主页面；章节进入更具体的内容作用域，PWA 与内容 worker 各自处理所属请求。包不登记根作用域、不接管宿主页面，也不自动替换其他脚本占用的相同作用域。

登记入口先核对既有拥有者；冲突以 assetUnavailable 失败。登记对象存在并不表示脚本已经安装或激活；尚未就绪时沿原生 register 过程取得对应登记，再等待自己的 worker，而不使用可能指向 PWA 的全局 ready 代替。

取消打开会停止该调用的等待和书籍资源准备，不发布迟到的内容地址。共享静态安装可以由浏览器继续完成，失败也由其拥有者接收；它不因此取得书籍字节或复活已取消的 Reader。已取消信号不启动新的打开。

不同版本及同页独立库副本可以同时存在。宿主停用一个旧发行版本时，须先结束使用该版本的消费方和内容，再清理它自己的登记与静态资产；不能只因新版本已启动，就移除旧页面仍依赖的资源。库不按某个 Reader 的 close 枚举删除其他版本，部署清理也不注销 PWA。

<a id="storage"></a>

## 临时存储失败

TemporaryStorage 仍是明确输入，浏览器适配按需使用可用的私有存储，不自行请求持久存储授权。没有临时存储时，只采用合同允许的有界内存与重读；已经需要形成大快照却没有可用容量时明确失败。

临时写入逐段等待，形成实际背压。创建或写入失败时停止继续消费，取消本次输入并释放已创建对象，不再尝试把余下整份内容收进内存。保留块的预算与在途读取缓冲分别计量；缓存不能通过保留一个小的 ArrayBuffer 视图而无意持有巨大源缓冲。

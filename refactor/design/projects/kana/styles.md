# Kana 样式

作者样式输入与读者覆盖进入同一展示转换；源身份、原文和格式结构不随呈现改变。

<a id="styles"></a>

## 正文字号与相对层次

从当前展示条件下、尚未施加读者字号覆盖的作者样式取得正文根基准 B，以及各文字元素的计算字号 s；读者选择的基准为 F 时，该元素采用 s × F／B。原书的绝对字号也因此建立相对关系，不需要猜哪一个段落出现最多，或用一组书籍 class 名寻找“真正正文”。

例如正文根为 14px、标题 28px、注音 7px，选择 20px 后得到 20px、40px、10px。若正文根为 16px，某一段明确使用 14px，选择 20px 后该段为 17.5px；这是保留作者相对小字的结果。fontSize 是正文根基准，不能同时承诺每个段落都精确等于该数值。

字号变换作用于文字排版。普通文字按正文比例缩放，相关 em 尺寸沿原关系参与布局；固定像素图像、原始页面与 SVG 绘图按各自尺寸规则呈现。HTML 根保留作者字号，rem 图形继续使用该基准。图形继承、伪元素及特殊字形按[统一转换规则](#conversion)保持上下文。

正文根、零字号及更新次序见[样式转换](#conversion)。Kana 负责作者样式推导，主应用提供读者设置。

行高、段距和对齐见[段落设置](#spacing)，私用字形与特殊结构见[字体来源](#font)，document 与 custom 的配色范围见[颜色](#colors)。

## 语义、盒结构与覆盖范围

格式先标明标题、正文、列表、代码、诗歌、注音、数学与图形等已有语义；呈现转换再结合原生 display、定位和文字所在的盒结构决定具体覆盖。每项设置分别确定作用范围，避免把“普通文字”错误地等同于“所有属性都可以覆盖”。

| 内容                                         | 字体与字号                               | 行高、段距、对齐                                        | 配色                                   |
| -------------------------------------------- | ---------------------------------------- | ------------------------------------------------------- | -------------------------------------- |
| 普通正文、列表正文、仅含普通行内内容的通用块 | 所选字体与正文比例                       | 正文规则；段距施加到实际段落盒                          | 阅读前景和普通底色成对采用             |
| 标题、引用、注音及其他普通文字层次           | 保留大小比例；字族按已确认范围选择       | 保留各自局部布局，明确行高随字号比例，normal 留给浏览器 | 普通文字配色规则                       |
| 代码、数学、明确诗歌与表格结构               | 保留字体语义；适用文字仍按其字号层次处理 | 保留缩进、逐行结构、单元格及对齐，不套普通段距          | 保留必要关系，普通色块仍按明确范围处理 |
| 图形内部文字、固定页面与明确图文对象         | 保留图形本身的字体和尺寸关系             | 原生图形／页面布局                                      | 保留画面与所依赖的绘制上下文           |

正文范围根据内容与实际盒结构判断。只有直接文字和行内内容的普通 div 按段落盒处理，混合容器中的直接文字也采用正文文字设置。段距仅作用于已经存在的段落盒，匿名文字与混合容器保持原结构。display:contents 的子内容按自身语义参与处理，盒与元素的对应见 [CSS Display](https://www.w3.org/TR/css-display-3/#box-generation)。

作用范围由实际语义和盒结构确定。表格、浮动、嵌套列表及图文对象保留必要上下文，按已有章节单位加载与呈现，沿同一 Reader 管理资源。

嵌套范围按属性分别处理。表格中的文字仍可取得适用字号，而单元格对齐和间距不会被普通段落规则覆盖；私用字形保留字族，也仍可随所在普通文字调整字号。代码与数学保留字体和内部结构，基准变化由所在文字层次及原生排版接续，不把数学内部盒逐个重写成普通正文。

## 字体选择与字形来源

document 保留作者字体链；系统字体或资源字体选择用于普通阅读文字，覆盖字号层次中的正文、标题、注音等字族选择，但不清除粗细、斜体、文字朝向与字形特性。原有字体链继续作为所选字体缺字时的后备，字体资源失败仍按既有 fontUnavailable 合同处理。

明确的等宽代码、数学排版与图形内部文字保留各自字体语义。私用区字符的含义依赖文档字体；所选字体即使包含相同码位，也可能提供另一字形，因此这类内容保留原字体链。

对承载私用字符的最小现有文字元素、以及承载这类字符的伪元素，保留其文档字体链。整段文字直接位于同一个元素中时，这个元素可能保留整段原字体；这样保留了选择器、计数器和源映射的结构，代价是字体选择的作用范围以现有元素为界。格式自身已提供更小的独立字形元素时直接使用。

普通 Unicode 码位被某些字体用作自定义图案时，不能仅凭码位判断其含义；选择 document 能保留此类作者安排，显式换字体不承诺保留所有未声明的字形设计。字素簇、连字、字体字重选择与语言规则仍交给浏览器，不按 UTF-16 单位拆字。

字体匹配及私用区机制见 [CSS Fonts](https://www.w3.org/TR/css-fonts-4/#font-matching-algorithm)。

## 行高、段距与对齐

text.lineHeight 作为普通正文段落、列表正文及其他普通正文流的无单位行高倍率。它必须覆盖这些内容已有的绝对行高，不只改根节点后期待继承。它不通过测量 normal 并假定一个固定数字来反算比例；normal 本身依赖字体度量，实际行框还可能被 ruby、大字或行内对象撑开。

标题、代码、数学内容、图形与注音自身保留相应的局部行布局。其字号发生已确认的比例变化时，明确的文字行高按原有字号关系保持，normal 继续由浏览器计算；不把所有元素的行高设成同一个像素数。正文的 lineHeight 是排版基准，不承诺每一行最终恰好等于该数值乘以字号。

paragraphSpacing 为 document 时保留段落规则；明确数值以正文根基准 em 形成普通段落的逻辑块向间距，从同一侧施加，避免相邻两段各加一次后变成双倍。横排沿上下，竖排沿左右；不改成一律 margin-top／margin-bottom。原有段首缩进、引用块边距、列表层级、表格单元格与明确诗歌逐行结构分别保留。

alignment 为 document 时保留作者规则；显式 start／justify 用于普通正文，标题、表格、代码以及明确诗歌结构保留自身排列。按源语义和格式解释确定作用范围，不能将全部 div、全部子元素或所有居中文字都猜成普通段落。实际排版含直接文本的通用容器时仍须覆盖其中的普通正文，不能仅支持恰好使用 p 标签的书。

相关机制见 [CSS 行高](https://www.w3.org/TR/css-inline-3/#line-height-property)；[Readium 的用户设置建议](https://readium.org/css/docs/CSS14-user_settings_recs.html)也把正文覆盖与特殊结构分开。Kana 仍须用自己的格式样本验证这些边界。

## 原书配色与阅读配色

document 保留书籍的颜色关系；custom 将调用方提供的前景与背景用于阅读内容。两种选择按下表处理。

| 意图       | 可重排正文的行为                                                                                 | 明确代价                                           |
| ---------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| 原书配色   | 保留作者前景、底色、局部强调、色块与边框关系；未声明的文档颜色使用格式的正常基准                 | 暗色界面中可以出现原书白底，正文不保证与界面同色   |
| 阅读配色   | 普通阅读文字及其普通色块成对采用指定前景与背景；链接保留可识别的下划线，标记仍由独立标记投影绘制 | 原书只靠文字或色块颜色表达的区分可能消失           |
| 图像与图文 | 原始页面、插图、SVG 以及依赖背景图共同表达内容的视觉对象保留画面与必要继承上下文                 | 阅读配色不保证整本书仅剩两种颜色，也不自动反色插图 |

单纯背景色的正文提示框属于成对覆盖范围，不能只把文字改浅而留下白底。带背景图的图文组合保留使其可读的原有前景与背景关系，不以删除背景图解决对比度。正文内的透明图形依赖原来文档底色时，也保留这份承托背景，不能只冻结黑色线条后把它放到黑色纸面。

保护按实际绘制关系形成范围：明确的图形或背景图对象是起点，继续包含它依赖的背景提供者及共同参与遮罩、滤镜、混合的内容。纯粹且不透明的单色承托可以在现有图形盒上保留；渐变、图片、半透明叠加和混合则保留原来的绘制规则及必要范围，不把它们压成一个 RGB 背板。范围可以包含整个提示框或更大的祖先；其中需要共同保持的前景、背景与伪元素一起保留，不逐个后代重新染色。

这项保护按性质生效：保留配色组合不自动冻结其中所有普通文字的字号；图形内部文字才保留图形尺寸关系。结果保留作者的绘制关系，布局仍随正常重排变化。复杂图文范围内可以继续出现原书颜色，这是既有“阅读配色不保证全书仅剩两色”的具体执行方式。

原书配色保留其文档画布。原书未声明画布和文字颜色时，采用格式的正常文档基准，例如普通 HTML 的黑字白底，不将黑字直接铺到宿主暗色背景。阅读区域在书页之外的底色仍由调用方提供；透明原始页面与纯图片仍沿已有页面合同使用该底色。

颜色输入的类型与默认值见[呈现设置](settings.md#shape)。

document 的 background 只决定阅读区域外底色，不覆盖可重排正文的文档画布；custom 的 background 同时作为阅读配色的底色。原始页面始终保留自己的画面，foreground 不用于统一着色固定内容。这里的 custom 表示已解析的技术颜色，既可以来自应用主题，也可以来自用户自定义值。

## 样式转换与采用次序

呈现转换按读者设置派生自己负责的属性。格式提供语义与源映射，浏览器完成级联、排字、字形和最终几何。各自的结果通过现有呈现流程共同采用。

### 作者基准与继承边界

正文根由格式指定，普通 HTML／XHTML 使用 body 的正文上下文；字号按[相对层次](#styles)派生。HTML 根保留作者字号，rem 图形沿用该尺寸。源字号为 0 的内容保持 0；正文根缺少正字号时，使用格式的正常正文基准。

作者基准是在本次视口、内容状态和资源条件下，撤去读者覆盖后取得的值。相关条件改变时重新准备；读者覆盖自身引起的尺寸反馈不成为再次乘算的基准。其他选择器、变量、逻辑尺寸和视口单位继续由浏览器解释。

图形边界保留会被外部读者覆盖改变的作者继承值，包括实际依赖的字号、字族、颜色、行布局及书写上下文。自定义属性也按实际计算语义保留：已计算的注册属性值和仍由浏览器在使用位置求值的 token 分别处理，不统一提前解析 URL。非继承的透明度、滤镜和混合不复制到子边界再叠加一次，绘制关系由前述保护范围继续承载。

### 伪元素仍是样式对象

before、after、marker、first-letter 与 first-line 根据所属源元素及伪元素身份取得作者值，再按同一范围规则派生。原生 content、计数器、列表标号和布局结构保持；来自文字字面量、attr 或自定义计数器的私用字形保留相应字体链。普通文字中的私用字形在保留字体来源的同时采用适用的正文比例。

只为需要覆盖的属性生成伪元素规则，不把生成内容物化成正文 Text。样式如何取得优先级、如何保留作者原属性，统一见[覆盖写入](#overrides)。

### 准备、采用与重排

一次更新沿现有布局次序完成：

1. 固定目标设置、视口、源位置、选区、焦点目标及本次内容状态，准备必要样式和字体资源。
2. 在各投影中撤去上一轮读者写入，采集作者基准与保护范围，立即保存所需普通值；不把活的 CSSStyleDeclaration 留到后续异步阶段。
3. 派生本轮属性与伪元素规则，应用并完成当前必要布局，使用原有源绑定恢复位置、选择几何和焦点。
4. 所有当前阅读面就绪后一起采用。失败、取消和宿主变化继续按已有布局合同处理。

撤去覆盖、读取和恢复的同步批次不跨异步等待暴露给用户。若基准读取发现还需等待资源，先恢复已采用的呈现，再等待并重新采集；不通过重新创建语义文档获取“干净基准”。正常字号、字体和配色调整保留已有节点及其源绑定。

同一章节的多份展示投影采用同一组输入与源解释，但每份文档分别处理自己的原生 DOM、字体加载与样式结果；不能因来自同一章就共享属于另一个 Document 的活对象。所有可见阅读面必要布局就绪后一起采用，源位置和选区保持原有地址，生成页和字体名不成为持久位置。

同一内容出现的交互样式状态也由同一个拥有者提供。焦点、hover、active 和书内目标等状态按源元素投影到各显示文档，具体分工见[焦点与样式状态](interaction.md#style-state)；显示副本不因自己的原生焦点不同而改变分页依据。

读者接管属性的过渡不延后设置采用：对这些属性的活动 transition 结束其旧效果，使新值在本轮生效；其他作者动画继续交给浏览器。需要多投影的同一内容出现，以语义文档的原生动画状态为基准同步显示副本的效果进度，不让副本独立起一段时间。布局采用当前必要帧，不等待无限动画结束；readView 对影响本次几何的动画短暂保持当前状态，结束后接续。没有将动画帧或时间加入源地址。

## 可读资格、空白与文字流

源文字是否属于正文、注音或独立内容由格式决定；呈现适配补充实际显示与空白事实，交给[带来源的文字流](content.md#text-flow)。资格、当前可见几何、是否可聚焦分别判断。

| 情况                                                  | 处理                                                                                  |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 作者 display:none 或明确禁止渲染的内容分支            | 普通摘录中不产生可读片段；有独立打开语义的内容在相应上下文另行处理                    |
| visibility:hidden                                     | 该处文字不可读，但继续核对后代；后代可以显式恢复 visible                              |
| display:contents                                      | 继续处理子内容，不因父元素没有盒而删去文字                                            |
| 作者 opacity 为 0、实际字号为 0                       | 核对其有效作用范围；只排除确实受影响的文字，字号为 0 的祖先不阻止子元素显式设置正字号 |
| 暂未驻留、content-visibility:auto、位于当前阅读面之外 | 按需准备所需布局，不当作作者永久隐藏                                                  |
| aria-hidden、inert 或选择限制                         | 不单独作为视觉文字是否存在的依据；语义、输入资格仍由相应拥有者处理                    |

透明字色可能配合文字描边或背景裁切形成可见字形，零宽片段也可能属于组合字符。不能仅凭一个颜色或矩形条件删除源字符。图文绘制保留原生机制；当前视口裁切、阅读器显示副本的语义排除，不改变全书文字资格。

空白处理按实际 white-space／white-space-collapse、语言和相邻内容执行，每次折叠或保留同时形成来源映射。TXT 继续保留它的源解码序列。浏览器自行决定的段落源换行转换，通过一个可回收的原生空白求值容器取得：只放入必要文字上下文和相关空白／语言设置，关闭 text-transform，不加载作者装饰或移动原生 Selection。

这个容器只回答空白如何处理。保留空白逐段映射，折叠区间对应完整的原空白区间；结果文字的非空白字符必须与输入一致。源端点仍来自原片段，不能拿 innerText 的字符下标重建地址，也不以重搜相似文字补映射。软折行、伪元素和装饰继续不产生新的原文字符。

样式输入的解析、逻辑地址、原属性和层叠关系见[样式来源](#sources)；统一 Service Worker 交付与实际宿主条件遵守[资源加载与部署](resources.md)。

## 样式来源与语法处理

| 来源       | 需要保留的上下文                                     |
| ---------- | ---------------------------------------------------- |
| 外部样式表 | 资源自己的逻辑地址、导入位置、层叠层、条件与出现次序 |
| style 元素 | 所属文档及适用基址、它在文档中的次序、规则与条件     |
| style 属性 | 所属元素的原属性值、行内声明的优先关系及适用基址     |

同一个 CSS 资源出现多次，可以复用字节和只读语法结果，但不能合并它在不同位置、不同层叠层或不同导入条件下的出现。异步取得资源的先后不成为样式顺序。

保留选择器、声明顺序、important、@layer、@media、@supports 和 @import 的关系。浏览器负责级联、继承和变量求值；Kana 不将全部计算样式复制成一批固定行内值，也不为每种样式来源维护一套不同解释。

外部 CSS 按[样式表自身的编码规则](https://www.w3.org/TR/css-syntax-3/#input-byte-stream)进入语法处理；需要产生转换结果时统一输出 UTF-8，并使响应编码和开头的 charset 声明一致。style 元素和属性已经是所属文档解释后的文字。CSS 的解码不借用 XML 声明规则，也不因插入规则破坏原来开头的编码识别。

## 资源地址与逻辑目录

每份内容文档与样式表都保留自己的逻辑位置，资源入口再把实际请求对应到本次授权的字节。能够通过受控地址空间保持相对目录关系时，优先使用这条路径，让原来的相对地址、属性选择器与样式条件继续由浏览器解释。

相对 URL 不能一律在看到它的地方立即解析。未注册自定义属性里的 URL 是尚未求值的 token：在另一份样式表或行内声明中使用时，会按实际使用位置解释。注册为 URL 类型的自定义属性则有自己的计算值规则，可以在定义位置形成绝对 URL。相关区别见 [CSS Variables](https://www.w3.org/TR/css-variables-1/#defining-variables)与[注册属性的计算值](https://www.w3.org/TR/css-properties-values-api-1/#computed-value-time)。

因此，不按变量名提前绑定一个图片资源，也不把变量值中的全部 URL 按定义文件固定下来。由浏览器完成这些语义，实际读取仍经过资源入口。

需要改写引用时，由既定的 CSS 语法解析器识别其作用：样式导入、普通声明中的资源、命名空间 URI、条件中的语法检查和普通字符串不能混为同一种链接。例如 @namespace 中的 URI 表示名称空间身份，不能当作待加载图片替换；字符串里恰好出现 url(...) 或 page-break 字样也不是声明。

资源通过[统一加载与部署](resources.md)定义的受控地址空间交付，同源条件和登记寿命由该合同负责。

## 属性改写与作者原值

资源地址、展示所需属性或读者覆盖确实需要改变时，要同时考虑作者 CSS 如何读取它们。比如 img[src="cover.svg"]、根据 style 原值匹配的规则，以及 attr(href) 生成的文字，都可能因实际展示地址变化而失效。

展示绑定保存属性的作者原值，并将相关 CSS 属性选择器或受支持的 attr 读取映射到内部属性，供原生 CSS 使用这份源事实。导航、资源授权和源位置继续由各自拥有者解释。

映射必须保留属性的有无、命名空间、名称大小写语义、匹配操作、标志和选择器权重。源中没有某个属性时，不补一个空字符串冒充原值。不同命名空间下的同名属性分别处理；命名空间通配也不能随意改成只检查其中一个属性。

内部名字需要避开作者名字，且仅存在于展示文档。原始源树与持久地址不增加这组字段；CSS 也不能通过这些值取得新的资源读取权限。能够保持原属性不变的路径，优先不做这一层改写。

名字收集覆盖实际属性、CSS 属性读取、名称空间和已有层名。私有名字与它们避碰；后续样式加入时在采用前完成相同核对。名称空间通配按当前内容中实际存在的对应属性展开，保留选择器权重；HTML 与 XML 的名称大小写分别遵守自己的语义。无法理解但不需要转换的 CSS 保留给浏览器，必要改写继续使用语法位置，不用全局文本替换处理未知嵌套。

原值投影用于技术性改写。details 的 open 属性、控件状态及内容交互产生的源状态采用当前原生值参与 CSS，随实际交互正常更新。

## 覆盖优先级与状态恢复

真正的元素只写入本轮读者拥有的属性，保留原 style 的有无和完整原值。行内 important 不能靠追加普通样式表可靠覆盖，因此需要时在实际 style 声明中采用读者值，同时让作者 CSS 对 style 的读取继续使用原值投影。更新前撤去读者写入，恢复已经完成必要资源／属性转换、尚未叠加读者覆盖的展示基线；不能把原始专用资源 URI 重新塞回实际 style，也不能在上轮字号结果上累乘。原值是源事实，展示基线是本次转换的派生值。

伪元素没有可供写入的行内 style。为其建立私有读者层，在每份顶层作者样式的合法前导位置预声明同一个层名，再让读者规则向该层写入必要的 important 声明。预声明放在 charset 之后、import 和 namespace 之前，不插在 import 与 namespace 之间；作者自身各层的相对次序不变。该机制利用原生 important 层顺序，不通过不断增加选择器权重争胜。规则依据见 [CSS Cascade 的层声明与排序](https://www.w3.org/TR/css-cascade-5/#layering)。

每个 Document 拥有自己的读者样式表和元素绑定。规则通过私有展示标识作用于实际元素，源结构、兄弟顺序与持久地址保持原义。没有作者样式时也可直接建立读者表，后续更新复用这张表和受管属性。

这些覆盖属于作者来源内的阅读适配，浏览器与系统的用户样式、强制配色等更高层机制继续生效。读取结果以浏览器实际采用的样式为准。

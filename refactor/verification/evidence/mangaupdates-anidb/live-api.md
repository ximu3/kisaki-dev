# MangaUpdates 核验与 AniDB 取舍

接口核验日期：2026-10-16（UTC）。本页记录真实来源行为；MangaUpdates 方案随后已获确认，完整扩展仍待实现验收。主要依据是[官方 OpenAPI](https://api.mangaupdates.com/openapi.yaml)、公开编辑说明、官网客户端、匿名资料响应及用户明确允许的本人读写。

结构化证据分别为[公开接口与账号摘要](2026-10-16-api.json)、[11 次写入及清理](2026-10-16-mangaupdates-writes.json)。证据不含密码、Cookie、账号编号、账号名称或私人正文。

## 公开资料与实际范围

30 次公开 API 请求覆盖《四叶妹妹》《葬送的芙莉莲》、小说《刀剑神域》、漫画《刀剑神域：艾恩葛朗特》《阿兹漫画大王》及其合编作品，另核对东清彦、CLAMP、三浦建太郎和出版方档案。

| 实测或官方说明                                                             | 对方案的影响                                               |
| -------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Series 类型可区分 Novel 与漫画；SAO 名称搜索返回大量模糊结果               | 逐项核对类型与身份，不自动采用首条结果                     |
| Author 的 CLAMP 档案也带 gender=Female，模型无个人／团体类别               | 不据姓名、岗位、性别自动创建人物                           |
| Author.actualname 的编辑说明明确是原文发表用名                             | 可为已明确档案提供 originalName，不等于法律本名            |
| 三浦建太郎 status=Deceased，status_date=2021-05-06，官网显示为死亡日期     | 同时满足状态和有效日期时可提供 deathDate                   |
| 《四叶妹妹》status 为 16 Volumes (Ongoing)；completed 在页面对应“完全翻译” | 当前卷数不是最终总量，翻译完成不是原作完结                 |
| 《阿兹漫画大王》4 Volumes (Complete)，latest_chapter 为 5                  | 完结卷总量与发布章节数分别解释，不拿最新话号作声明话数     |
| 原版与英语译版出版项分别存在，Media Works 档案当前名称为 ASCII Media Works | 同一 ID 不因改名拆成两个组织；按作品上的真实出版范围采用   |
| 出版方反查同时返回 2077 个作品与 52 个连载刊物                             | 刊物不当作出版社，也不冒充作品目录成员                     |
| Author 反查实测东清彦 14 项、CLAMP 58 项                                   | 反查需复核作品媒介和署名；混合主体不妨碍已明确主体自身履历 |
| Author 搜索请求每页 3 条，实际返回 40 条                                   | 按实际分页响应判断完成，不假设请求参数必然生效             |
| 36 个 genre 带正式说明，category 主要是名称和投票信息                      | 标签语义、说明与统计分开，敏感标记只采用明确事实           |
| 两张原图 GET 均成功，HEAD 均返回 400                                       | 图片可用性不能仅靠 HEAD 判断                               |

[姓名规则](https://api.mangaupdates.com/v1/faq/7/questions/59)、[原作出版状态规则](https://api.mangaupdates.com/v1/faq/7/questions/51)、[出版年份规则](https://api.mangaupdates.com/v1/faq/7/questions/52)和[合编规则](https://api.mangaupdates.com/v1/faq/7/questions/65)用于解释字段。合编 associated 可能含所收短篇标题，不能无条件作为整作 aliases。

官网发布脚本确认网站使用公开 loginWithCookie、profile、列表部分更新和独立评分接口；这支持采用公开 API 自己维护会话，不需要提取浏览器 Cookie 或依赖内部页面数据。脚本与页面保存了公开地址、摘要和内容哈希，仅作为本次证据，不成为运行依赖。

当前页面 base36 代码与 API 十进制 ID 已按公开响应核对，包括 Series、Author 和 Publisher；来源身份沿用既有 MangaDex 对 MangaUpdates 的类别加代码语法，不能混入旧式历史数字编号。

## 本人读取与限定写入

用户先允许本人只读核验，后另行同意对唯一测试作品执行限定写入及清理。实际 PUT /account/loginWithCookie、GET /account/profile、GET /account/refresh 及续期后的本人核对均成功。稳定身份只在内存中比较，未写入证据。

五个系统列表为 read、wish、complete、unfinished、hold，本次账号的五表均为空且为私密。列表全量查询必须省略空 search；提交空字符串返回 400，省略后五表均正常返回。GET /lists/series/{id} 不应依赖不存在的 list_type 字段，应联接列表定义。

测试目标仅为原本没有本人记录或评分的《四叶妹妹》，每次写后均回读，写请求至少间隔 5.2 秒。11 次请求均得到成功响应：

| 测试                                                  | 实际结果                                       |
| ----------------------------------------------------- | ---------------------------------------------- |
| 无评分时提交 0                                        | 评分仍不存在；未证明有效零分或零能清除既有评分 |
| 提交 8.7                                              | 回读 8.7，未创建列表成员                       |
| 提交 8.75                                             | 回读 8.8，说明来源量化为一位小数               |
| DELETE 评分                                           | 本人评分恢复不存在                             |
| 只指定作品与愿望列表新增                              | 来源默认 volume=1、chapter=1、priority=1       |
| 移至 read 并设测试进度 2／3                           | 回读状态及进度正确                             |
| 只改 list_id，依次转 complete、hold、unfinished、wish | 每次均保留 2／3 与原优先级                     |
| 删除本次列表项                                        | 该作品本人记录与评分均恢复不存在               |

因此状态更新可以使用来源的部分负载，评分可以独立存在；创建默认进度不代表本地阅读事实。删除测试记录只用于获许可的清理，不能推导出正式同步应以整条删除来清除本地空状态。

清理后再次读取五个列表，total_hits 和实际成员均为 0；该目标记录和评分均为 404。logout 成功，本机临时接收器已关闭，会话与凭据引用已清除。账号长期安全和浏览器历史不属于这些清理结果；核验过程中临时登录表单曾错误使用 GET，已单独向用户说明并改为原生 POST 后重新连接，不在证据中保存该地址或凭据。

## 尚未通过的验证

真实非空自定义列表没有样本，不能宣称它已通过运行核验。其 type、可见性、完整分页与移动联动在实现验收时继续验证；官方 schema 已提供类型及 custom 标志，不按用户列表名猜含义。

本次接口脚本未实现完整扩展，不替代账号切换、停用、取消、分页中断、写入响应不明、本地并发变更、ingest 原子采用、全部页面与独立安装测试。公共字段缺席和部分失败也必须按共同合同验证。

## AniDB 的保留调查与排除决定

官方[标题数据](https://anidb.net/api/anime-titles.xml.gz)本次可以直接读取，包含 17,063 个动画对象，最后更新时间为 2026-10-16 03:00:07 GMT。此前调查的 17,055 项属于前一天快照，不能混成同一次结果。

HTTP／UDP Wiki 在工具、内置浏览器及用户 Chrome 中均受访问防护拦截。用户没有 AniDB 账号，也没有为 Kisaki 登记 API 客户端；本次没有验证完整动画／分集协议或 MyList。标题数据可读不证明这些接口已经通过；Wiki 被拦截也不能证明整个平台不可用。

用户同意在资料增量价值不大时排除。当前判断是：AniDB 的细分集型、特殊内容与文件对应有独特价值，但既有 Bangumi 真实分集目录和 TMDB 补充资料已覆盖主要需求，产品又未选择 AniDB 文件校验体系，剩余增量不足以支持额外客户端登记及协议维护。这是投入范围的取舍，不声称其他来源完全等价。

因此 AniDB 已从官方来源和默认预设移除，正式目录变为 17 个资料／平台来源、13 个迁移导入器、3 个译本，共 33 项。调查证据、其他来源返回的真实 AniDB 外部标识及历史记录继续保留；它们不再触发 AniDB provider 或协议读取。

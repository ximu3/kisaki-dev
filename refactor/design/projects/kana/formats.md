# Kana 格式与输入

格式解释拥有源结构、地址、读取顺序和解析后端。展示层消费这些事实，不重新解释源格式。

<a id="format-scope"></a>

## 支持格式

Kana 直接支持 EPUB、MOBI6／KF8 及实际属于这些容器的 AZW／AZW3、FB2、TXT、PDF、图片目录和 ZIP／CBZ。所有格式共用完整 Reader，按真实内容进入固定或重排视图。

<a id="rar"></a>

### RAR／CBR 的使用边界

RAR／CBR 不在直接支持范围内，识别出 RAR 容器时报告 unsupportedFormat。判断按实际容器内容，不只看后缀：RAR 改名为 .cbz 不会变成 ZIP；实际为 ZIP 的文件也不会仅因后缀是 .cbr 而被拒绝。

排除 RAR／CBR 可以减少专用解码与维护成本；相应文件需要用户自行解压为图片目录或转换为 ZIP／CBZ；没有可靠的使用占比作为“格式冷门”的判断依据。读取失败不触发自动转换，也不改变用户文件、登记或正式记录。

<a id="decoding"></a>

## URL、文本编码与密码

URL 输入通过 openUrlSource 明确建立读取对象。它接收可选请求头、credentials、取消信号和临时存储；默认 credentials 为 same-origin。URL 本身和请求头不成为源位置或持久身份，也不授权书内引用的其他 URL。

URL 在打开阶段选择可验证的范围读取或单响应快照，满足稳定字节与资源预算后才交付 Reader，完整规则见[HTTP 接续](#url)。

TXT 的 textEncoding 只接受规范编码名称。存在已存 textOffset 位置时，先采用该位置的 encoding；显式输入与之冲突则失败。没有已存编码条件时，使用显式编码或首次检测结果；最终位置总携带确定的编码。修改字号和重新排版不重新检测编码。

password 是本次打开的运行时输入。需要密码、密码错误和不支持的保护机制分别报告；内核不打开密码对话框，不保存到设置、位置或日志。需要用户补充输入时，宿主取得答案后重新发起明确的打开。失败的打开先清理已取得资源，不交付等待宿主补齐的半初始化 Reader。加密文件的实际支持范围和密码失败分类仍随各后端样本验证，不把任意 DRM 声明为可读取。

<a id="inputs"></a>

## 输入一致性

根输入在持有期间提供同一版本的字节。本地读取也须保证这一条件，路径或文件句柄未变不足以证明字节未被改写。TXT 编码与组合 MOBI／KF8 的分支参与源地址解释；密码只属于本次输入，字体与排版属于显示，各自按所属合同管理。

<a id="url"></a>

## HTTP 范围读取与单响应快照

URL 适配的目标是提供既有 ByteSource 所要求的稳定字节。HTTP 范围针对所选表示的字节，If-Range 失配可能返回完整 200，压缩表示的字节坐标也不同于解压后的文件。见 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-range-requests)。跨域响应还可能无法读取 ETag、Content-Range 等所需信息；[Fetch 的响应头规则](https://fetch.spec.whatwg.org/#cors-safelisted-response-header-name)不会因服务器支持 Range 就自动暴露它们。

openUrlSource 在打开期间选择下述一种方式，完成后交付稳定的 ByteSource，由普通 Reader 输入合同消费。

| 方式         | 采用条件                                                                       | 交付后的含义                                                                   |
| ------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 远程范围读取 | 实际 206、合法 Content-Range 与总长度、可见的强 ETag，且能确认范围对应文件字节 | 后续每次请求使用 Range 与 If-Match，并校验 URL、版本、总长度、区间及实际字节数 |
| 单响应快照   | 不能可靠采用远程范围读取，但可完整读取一次响应                                 | 将该次响应的解码字节流式写入 TemporaryStorage，完成后从同一快照读取            |

Accept-Ranges 声明、HEAD 成功或弱 ETag 都不能单独证明输入稳定。后续使用 If-Match 的目的是只取得原版本；版本不再匹配时让请求失败，而不是接纳另一份完整表示。该条件的含义见 [HTTP If-Match](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)。实际服务器还须正确执行协议；客户端无法发现服务器在内容改变后错误复用同一强 ETag。

CORS 下读不到 Content-Encoding，可能只是该头部没有暴露，不能据此推定没有传输编码。范围模式要求响应让必要元信息及编码的存在或缺席可验证；否则取完整快照。带凭据时的暴露规则也要按 [Fetch](https://fetch.spec.whatwg.org/#cors-protocol-and-credentials)处理，不把通配符理解成始终可见。协议细节属于 URL 适配，不进入应用偏好或文档格式模块。

Fetch 可能已经解开 HTTP 压缩，Content-Length 仍描述压缩后的传输量。因此快照大小和预算按实际交付的文件字节计数；不据该头部分配整书缓冲。服务器忽略初始 Range 并返回完整 200 时，可以直接把这一响应流式存成快照；若初始部分响应不具备采用条件，则丢弃它，另取一次完整响应，不能拼上先前的前缀。浏览器在响应交付前拒绝范围请求时，允许打开阶段尝试一次普通 GET；取消不触发重试。

输入已经交付后不再切换来源。明确的版本／最终 URL／总长度变化报告 sourceChanged 并使该输入失效；区间不符、截断、验证头缺失或不合约的状态报告 readFailed，不能把所有异常都称为“文件变化”。Reader 按已确认的失败范围处理，不能继续拼入新版本字节。

打开调用的 signal 只控制打开；交付后每次 read 的取消只结束自己的读取，dispose 才停止并收尾全部尚未完成的读取及临时文件。没有可用暂存能力、配额不足或超出预算时明确失败，不隐式改为整书内存缓存。临时存储异常、认证部署、跨浏览器与大输入纳入正式验收。

<a id="formats"></a>

## 格式语义与呈现分工

formats/document.ts 定义下游需要的内部文档能力：源内容顺序、按需取得内容、定位解释、文字与地址对应、源顺序比较以及释放。各格式保留适合自身的源结构，解析器与协作接口保持内部可见。

每个格式拥有自己的解析结果和地址映射。EPUB 的 spine 出现位置与完整 CFI、MOBI/KF8 的原始重建字节、FB2 的源逻辑树、TXT 的确定解码与 UTF-16 偏移，都在所属格式中解释；PDF 则保留原始页面、文本与规范页面几何。定位、文字选择、搜索命中和标记恢复共用这些结果，不能各自重新解析一遍地址。

| 格式实现 | 拥有的格式事实                                          | 呈现接入                         |
| -------- | ------------------------------------------------------- | -------------------------------- |
| epub     | 包结构、spine 出现位置、章节资源、目录、CFI 及逐项版式  | 按各项实际内容进入固定或重排视图 |
| mobi     | MOBI6/KF8 识别、记录解压与源重建、资源和各自字节地址    | 按实际源结构进入重排或固定视图   |
| pdf      | PDF.js 文档与页对象、页面尺寸／朝向、文字和原始页面对应 | 固定页面绘制与可选择文字层       |
| fb2      | XML 源逻辑树、内容与注释结构、内嵌资源、节点地址        | 生成保留源对应的重排内容         |
| txt      | 已确定编码、原始解码序列、UTF-16 位置及必要索引         | 生成保留换行和源对应的重排内容   |
| images   | 图片目录或归档的成员身份、显示顺序、图像尺寸与方向      | 固定页面视图                     |

AZW／AZW3 按实际容器和内容进入 mobi 实现。EPUB 与图片归档通过 resources 复用 ZIP 成员访问，图片目录直接使用成员输入。页面导航由相应内容格式提供。

同一文档可以交替出现固定与重排内容。文档顺序和地址保持不变，view 根据当前内容选择实际呈现方式。分页／连续滚动是显示组织，固定／重排是内容性质；两组概念分别建模，也不由漫画／小说类别代替。[EPUB 3.3](https://www.w3.org/TR/epub-33/#layout) 明确允许逐 spine 项覆盖布局。完整阅读意图、源内容事实与实际布局的职责见[设置模型](layout.md#model)。

源内容树与展示 DOM 分开。格式转换和展示过滤保留文字、元素及原始页面的对应；注入包装、加载批次、排版页数和高亮节点不参与源寻址。格式可以复用确定性的映射机制，但源规则仍归格式拥有。只有格式确实支持的文字或页面能力才能对外声明，不能把缺失的文字提取伪装为空正文。

## 格式后端与依赖

Kana 自己拥有文档语义和阅读流程，成熟依赖只承担明确的解析、解码或绘制责任。

| 输入                                     | 实现路线                                                   | 源语义与必须保留的能力                                                             |
| ---------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| EPUB                                     | 自有包结构、导航、逐项版式和 CFI 实现；ZIP 成员使用 zip.js | 原始 spine 出现位置及源 XML 树；重复资源、完整端点、固定与重排混合、书内字体和竖排 |
| MOBI6／KF8、实际属于这些容器的 AZW／AZW3 | 自有 TypeScript 记录读取、解压接入、原始内容重建和源映射   | PalmDOC／HUFF-CDIC、记录尾部信息、编码、skeleton／fragment、组合文件及固定 KF8     |
| FB2                                      | 自有源逻辑树、正文／注释及内嵌资源解释                     | 按已确认 XML 规则生成 nodePath，不用转换后的 HTML 编号                             |
| TXT                                      | 按确定编码解码，保留原始解码序列，按块建立文字索引         | BOM、换行、UTF-16 和代理对边界；显示分页不改变 offset                              |
| PDF                                      | PDF.js 的文档、worker、页面绘制、文字层和链接数据          | 原始页、CropBox、UserUnit、固有 Rotate；高亮按规范页面几何恢复                     |
| 图片目录、ZIP／CBZ 图片归档              | 直接成员输入与 zip.js；共用固定页面视图                    | 成员路径身份、确定页序、图片方向；解包不产生另一套阅读导航                         |

采用的依赖基线为 PDF.js 6.4.299（Apache-2.0）、zip.js 2.24.0（BSD-3-Clause）；XML 语法使用 Expat 2.9.0（MIT），扩展 XML 编码采用 GNU libiconv 1.19（LGPL-2.1-or-later）及已核对的六项 CP932 映射校正；HTML 解析使用 parse5 8.0.1，CSS 解析使用 css-tree 3.2.1（两者 MIT）。版本、来源和包校验见验证记录；正式发行固定完整锁文件、传递依赖、Wasm 工具链和发行资源。

EPUB／FB2 保留各自 XML 解释，MOBI 的 HTML 可以使用 parse5 的树修复和源位置能力；两者不能静默换用对方的解析规则。parse5 的字符位置并不等于 MOBI 字节地址，也不直接提供每个字符引用展开后的反向映射。CSS 解析器负责语法结构，授权和过滤策略仍由 Kana 拥有。

Foliate 的模块协作、浏览器排版和按需内容组织可以作为设计参考；MOBI 的记录、压缩和 KF8 重建也提供了具体算法依据。对设计的借鉴按 Kana 的实际职责判断，代码取用另行核对来源、许可和维护成本。已核对版本会在组合文件中优先切到 KF8，并在转换中加入链接定位节点、替换资源和序列化 DOM；原始字节地址及分支恢复仍须满足本项目自己的合同。

<a id="decisions"></a>

### 选型与源码取用

成熟实现用于对照模块分工、原生机制、算法、边界用例和维护经验。具体设计是否值得借鉴、代码是否适合取用，按 Kana 的用途、清晰性、正确性和维护成本判断；不能因参考某个项目就预先确定整库采用范围。取用代码时固定来源、保留许可并记录修改。

源表示按格式需要组织，原始 XML DOM、逻辑节点投影与格式索引都可以承载源语义。各格式选择适用的结构；验证试件中的树和解析器结构只用于证明相应机制。

<a id="xml"></a>

## XML 语法与源树

EPUB 的 package／导航／XHTML／SVG 与 FB2 可以共用 XML 语法能力，各格式分别拥有准入及实体解释规则。底层可以提供 DOM 或解析事件，格式层取得所需的元素、属性和文字事实；FB2 的 body／注释解释、EPUB 的包结构和 CFI 仍分别归各自格式拥有。MOBI 的 HTML 不借用 XML 修复规则。

EPUB 的 XML 资源与 FB2 共用 Expat 2.9.0，放在可终止的 worker 中，Kana 的窄桥接负责本地标准实体目录、输入编码及资源预算。它交付元素、属性和文字事实；格式层按需要建立源树或索引，并拥有各自的准入、正文结构和资源规则。XML 桥接是 Kana 内部实现。

Expat 用于 worker 中的增量处理、取消、可计量预算和内容不完整时的明确失败。格式层基于源语义实现稳定 CFI、书签及呈现绑定；下述独立资源处理扩展编码。语法解释、编码和源地址各自承担明确职责。

标准 XHTML 字符实体使用 [HTML 的 XML 解析规则](https://html.spec.whatwg.org/multipage/xhtml.html#parsing-xhtml-documents)给出的本地 DTD，按规定的 public identifier 解析，文字和属性中的实体遵守 XML 属性空白规范化。内部声明覆盖标准实体也按 XML 规则生效。未知外部标识不会触发联网或宿主文件读取。

决定性的差别是：浏览器路径在部分内部参数实体、外部实体依赖用例中接受文档却省略文字；saxes 的流式接口可用，但内部 DTD 的实体、默认属性及替换内容需要另补解释；其余 JavaScript 路径在实体、namespace 或规范化上也需要额外语法责任。为这些差异叠加预扫描器，或按格式选择互不相同的解析器，会增加源位置解释的维护面。采用 Expat 能将这些责任收在一个语法后端；这比依赖数量本身更符合整体清晰性的目标。

这条路线需要维护上游版本、Wasm 构建和显式发行资产。上游 C 源码保持不改，标准目录与固定编码表由接入持有。浏览器仍负责展示 DOM、文字布局、Range 和绘制。

源树采用以下规则：XML 1.0 的行结束和字符引用处理；忽略注释、处理指令；CDATA 参与文字；相邻文字合并，空字符串不占 FB2 子节点，实际空白保留。不同回调次数和输入分块不改变节点身份。属性与 namespace 不成为子节点。

XML 入口需要同时满足正常格式兼容与源内容完整性：

- 普通 DOCTYPE、适用的内部实体及标准 XHTML 字符实体按所属格式解释；不一概禁止 DTD。
- 不按书内任意标识联网或读取宿主文件。标准字符实体采用明确的内置规则；未取得的任意外部实体若参与内容解释，必须明确失败，不能发布省略文字后的源树。
- 未使用的外部一般实体声明可以存在；实际引用时因不能取得其内容而明确失败。未知外部子集按非验证处理跳过，正文随后引用其中不可得的实体也必须失败。不能用“禁止外部读取”一概拒绝普通 DOCTYPE，也不声称执行了外部 DTD 验证。
- 展开文字、节点、属性、输入和深度分别受实际预算约束；达到限制按 resourceLimit 结束。失败解析的临时结果不可成为可用文档。

[EPUB Reading Systems](https://www.w3.org/TR/epub-rs-33/#sec-epub-rs-conf-xml) 的非验证 XML 处理要求、HTML 的标准实体规则，以及 FB2 的源解释共同参与选型。取消与暂存结果交付由 Reader 协调；worker 的存在不代替总内存、输入量和输出预算。

XML 编码与 TXT 编码分别遵循所属格式。TXT 使用 WHATWG 规则与错误替换；XML 输入错误不能用替换字符掩盖，XML 的 ISO-8859-1 也不能通过 WHATWG 的同名别名变成 Windows-1252。扩展 XML 编码使用固定 libiconv，声明、BOM、别名和按需加载见[输入规则](#xml-codecs)。

按有界输入接续解析，成功前不发布部分源结果；取消时停止本次任务，必要时终止其 worker，其他仍被消费的内容由各自占用保留。同步解析不占用界面线程。该路线不要求整书 DOM 永久常驻；流式语法入口与按需建立大书索引分别验收，不能把解析器支持增量输入当作后者已经完成。

<a id="xml-codecs"></a>

### XML 编码与输入规则

扩展 XML 编码采用 GNU libiconv 1.19 的独立转换资源，并维护六项 CP932 解码校正。XML 输入入口从文件字节识别 BOM 和声明，确定本次唯一的编码解释。UTF-8、UTF-16 及明确端序形式、US-ASCII 和 ISO-8859-1 直接进入 Expat；其他受支持编码才加载 libiconv，增量转为 UTF-8 后交给同一语法后端。转换器不解释 XML 结构、实体、正文路径或源地址，也不提供另一种 Reader。失败后不改用另一个编码重试。

这补充的是字节解释能力，XML 语法仍由 Expat 解释。其 [UnknownEncodingHandler](https://libexpat.github.io/doc/api/latest/#XML_SetUnknownEncodingHandler)对非内建编码限制 Unicode 标量及字节对应，无法完整覆盖 GB18030 的补充平面字符等情况。浏览器 TextDecoder 则遵循 [WHATWG 标签规则](https://encoding.spec.whatwg.org/#names-and-labels)，不能直接承担所有 [XML 声明名称](https://www.w3.org/TR/xml/#charencoding)的原义。

原库在 CP932 中有意保留六项 JIS 映射，与微软 CP932 表不符；接入只在这六处按微软发布表校正。源归档、差异及实际结果见[编码验证](../../../verification/evidence/kana-xml-codecs/codecs.md)。固定版本、校正与对应发行材料随包交付。

输入按以下规则解释：

- 先读取有界前缀，按 [XML 的字节识别规则](https://www.w3.org/TR/xml/#sec-guessing)辨别 BOM、编码单元宽度及端序，再取得起始声明。声明语法仍由 Expat 校验，识别阶段不另写一套 XML／DTD 解析器，也不改写声明中的 encoding 文本。
- 没有 BOM 和编码声明时按 UTF-8；通用 UTF-16 必须有 BOM。UTF-16BE／LE 可以通过其声明与字节形式确定端序。其他编码必须有声明，UTF-32 的 BOM 也不替代这项要求。字节签名、声明宽度或端序有明确矛盾时失败。
- 名称按 XML 的 ASCII 不区分大小写规则匹配，保留原始声明，不猜测地区或自动换编码。编码名周围的空格、空名字、非法标点及 IGNORE／TRANSLIT 后缀不是可修整的别名。
- 合法声明但没有受支持解码能力时为 unsupportedFeature；声明语法、非法字节、确定的编码冲突或格式编码限制不符为 invalidDocument；输入、前缀或解码资源超限为 resourceLimit，并由所属边界填写已有 resource 分类。加载转换资产失败为 assetUnavailable，读取失败、已确认来源变化和取消沿已有分类传递。

支持的编码及别名从固定转换器构建输入生成，并作为版本化发行内容保存，不运行时读取系统 locale。排除宿主内部字表示、编程语言转义表示、不能按本入口识别 XML 声明的裸字符集，以及不符合 EncName 的名称；当前得到 97 个规范解码名称、292 个有效名字。生成与排除记录见[输入验证](../../../verification/evidence/kana-xml-entry/entry.md)。依赖升级时核对该集合及映射差异，遵守既有源定位兼容要求，不自动改变已保存值的解释。

各格式独立限定准入编码：[EPUB 的 XML 资源](https://www.w3.org/TR/epub-33/#sec-xml-constraints)使用 UTF-8 或 UTF-16，FB2 在本 XML 输入能力内按声明解释，TXT 遵守自己的 WHATWG 语义与设置。文件字节入口依据 BOM、声明和格式约定确定编码，MIME charset、URL、系统语言及正文外观不参与覆盖。同一字节在多种编码下均合法时，也沿这些明确依据解释。

状态编码保留本次转换状态，不完整字符只保留必要尾部；原始输入、解码输出及 XML 展开／节点分别计量。原始字节仍是来源，UTF-8 转码输出只是语法输入；FB2 nodePath 和 EPUB CFI 继续来自格式源结构，不公开转码后的字节地址。任何阶段失败都不发布部分源树，关闭与取消等待本次读取收尾。

发行包含独立转换 Wasm、CP932 校正，以及 LGPL-2.1-or-later 要求的许可、源码与可重建材料。独立转换 Wasm 和对应桥接保持可替换的资产边界，随包提供来源、差异、构建和接入说明。运行预算由实际资源拥有者确定。只在扩展编码路径加载转换脚本与 Wasm，普通原生编码路径不承担该加载。

## EPUB CFI 与严格源定位

EPUB 格式模块直接实现 CFI 语法值、源图解析与展示绑定，按本库的严格恢复规则统一核对目标。实现可以复用独立验证的算法和测试，CFI 的源语义与适配责任始终由该模块持有。

CFI 使用源 package 的真实 spine 路径和本次 itemref 出现位置。同一个 href 在 spine 中出现多次时，资源字节可以复用，但出现身份与地址不合并。内容中的元素、逻辑文字槽、空槽及首尾虚拟边界按 CFI 规则解释；不能直接复用 FB2 的零基 nodePath 编号。

语法层保留转义、断言、范围、side bias，以及时间／空间终点，不把合法表达式截短为“章节加文字偏移”。范围进入现有 TextRange 时展开为两个完整 CFI 点。CFI 的 `^` 转义与外层 URL 百分号解码分开，后者只在真正解析 URL 时发生。

数值令牌保留精确的十进制值，不能先经浮点数舍入再比较；访问源内容时才按真实节点和文字长度核对边界。比较忽略断言及 side bias，保留隐式文字偏移 0、范围两个终点和时间／空间的规定次序。生成地址从源事实补齐路径中的已知 XML ID；XML 语法后端提供的 ID 类型信息也要保留。未知扩展参数保留语法值，不自行解释。

格式层逐步核对节点、ID、偏移、引用目标和源文本断言。文字断言可以跨元素边界并按 CFI 的空白规则核对；失败不搜索邻近段落重新绑定。嵌套引用只访问本次授权的出版物资源，并保留原 spine 上下文。side bias 保留分页边界的前后归属，不改变文字源顺序。

同一资源、同一根片段从不同嵌入引用进入时，完整引用链仍是上下文的一部分。普通超链接不充当 indirection。书内 CFI 链接按指定 rendition 的 package 解释；链接给出范围时采用其完整起点，持久文字范围仍保留两端。已有持久地址的严格恢复不因此改成资源或近邻选择。

源地址解析、可呈现性与阅读能力分别判断。可以解析时间终点，不因此增加书内音视频播放职责；没有可呈现对应时按现有 locationUnavailable 原因报告，不能丢弃不支持的终点后跳到另一处。依据与机制用例见 [CFI 1.1](https://w3c.github.io/epub-specs/epub33/epubcfi/)和联合验证记录。

内部 Text 拆分与包装不参与 CFI 编号，合法持久端点仍不得切开代理对；不另增公共位置类型。

## MOBI／KF8 的原始字节与展示映射

MOBI／KF8 的解析顺序与内容分支由格式事实和原始字节地址决定。Foliate 的记录、解压、索引、重建及导航处理可用于核对局部算法；其默认生成章节 CFI 不提供 Kana 所需的原始字节映射。代码取用范围仍须按具体责任评估。

以已核对的 Foliate 记录、压缩与 KF8 重建代码为底层取用起点，在格式模块内维护明确的源字节输出和分支选择；不把其整套 book／renderer 接口作为 Kana 内部合同。固定提交、保留 MIT 许可并记录调整；这项取用不要求上游同时承担 Kana 的地址或呈现责任。

旧 MOBI 分支先去除记录尾部附加数据，按对应算法解压，再组成逻辑连续的原始标记字节流。KF8 以原 skeleton 索引为 documentIndex，按 skeleton／fragment 表重建文档字节；源地址在资源替换、HTML 修复和序列化之前产生。组合文件保留两条分支，既有 mobi 地址不会因默认呈现 KF8 而换算为 kf8 地址。

实际存储采用记录长度索引、所需字节区间和有界解压块。一次处理过的记录可留下长度信息，昂贵字节按预算回收；不依赖全书字符串永久常驻，也不以每条记录固定 4096 字节推算地址。

字符映射保留三个层次：原始编码字节、字符／字符引用的展开结果、修复后展示节点中的区间。一个字符引用可以展开为多个 Unicode 字符；UTF-16 偏移仍不能切开代理对。HTML 换行处理造成的零宽源边界可以映射到同一显示边界，不能把它谎报为编码字符内部；源字节身份继续保留。

parse5 的现成 sourceCodeLocationInfo 不足以独立承担这项映射。在词法发射时记录来源，再通过文字插入和 treeAdapter 跟随树构建。这层接入依赖固定版本的内部发射与插入接缝，包括上游标为 protected 的方法，须集中在格式适配中维护；不能将它描述为仅使用稳定的公开定位 API。升级时核对这些接缝及字符引用、词法回放和树修复行为；公开能力能够完整提供同义来源映射后，优先移除这部分内部依赖，不从最终节点文字反搜原文。具体依据见[源映射试件](../../../verification/evidence/kana-formats/format-sources.md)及 [parse5 Tokenizer](https://github.com/inikulin/parse5/blob/v8.0.1/packages/parse5/lib/tokenizer/index.ts)。

表格中的文字可能被 HTML 修复移到表格外，多个不连续源区间也可能合并到一个节点。定位、高亮和原文提取因此使用源区间与多个展示片段的对应；源顺序仍按格式合同决定，不改成最终 DOM 顺序。

词法文字回放、格式元素复制、属性合并、外来内容替换、舍弃节点与展示 Text 拆分均须保留来源对应。源标签可以对应多个真实呈现节点，自动补出的包装不能制造源地址；已经解释但没有可呈现对应的目标按 locationUnavailable 结束。

格式以确定的源解释结果建立呈现 DOM 并保留来源绑定，浏览器负责其后的布局。节点编号与持久地址以源解释为准，避免不同浏览器修复内容树时改变地址；parse5 与浏览器在 select 内容树上的差异见对应验证。各格式继续拥有自己的源结构。

固定 KF8 依据原始版式元数据、固有视口、资源及 skeleton 文档组织页面。固有页面的源索引保持原 skeleton 次序，阅读方向和当前缩放不改写它；页面内图片与文字继续使用原始字节来源。已声明固定版式但缺少有效固有视口时明确失败，不猜测为重排内容。纯图片页中的排版空白不使它自动取得正文文字能力。

HTML 展示保留 iframe 已初始化的根元素，按源根的属性及子节点建立内容并绑定来源。实际几何就绪后才交付可读内容，样式表已加载或计算样式正确不能代替这一条件。此项属于 HTML 文档建立和布局核对，不更改源树编号，也不泛化为 SVG 根的处理。

## 图片成员、页序与身份

两种容器使用同一条流程：取得本次完整的规范成员列表，识别图片成员，按下述路径规则排序，随后固定本次页面序列。目录枚举顺序和 ZIP 中央目录顺序都不成为阅读顺序；图片像素按需解码。文件名与元信息可以帮助发现候选，实际类型以字节头和必要格式元信息为准；无图片后缀的有效图片仍可进入页表，改名为 .png 的普通文本不会成为页面。

直接呈现的页面类型为 JPEG、PNG、GIF、WebP、AVIF、BMP 和 SVG。像素解码使用浏览器现有能力，SVG 沿既有 XML／SVG 内容及授权资源路线处理；不把任意 XML 当成 SVG，也不另加桌面图像库。明确识别出的其他图像类型仍保留源页项，读取时报告 unsupportedFeature，不靠删页伪装为完整书籍。尺寸与固有方向在进入规范页面时处理一次，用户旋转是之后的显示变换。动画属于同一个源成员，不把动画帧展开成新的页码。

打开时取得成员身份和识别页面所需的信息，固定页表后按需解码目标图片。说明文件等非页面成员保留在资源目录中；已经识别出的图像页在解码失败后仍保留位置和后续编号，并报告相应错误。该页加载负责完整解码校验与像素预算，头部识别只完成类型及必要元信息判断。

ZIP 使用固定 zip.js 的范围读取和流式成员输出，不先把整包解压到目录。名称沿同一固定解码规则取得：显式 UTF-8、有效 Unicode Path 信息优先；没有声明时使用该固定版本的有效 UTF-8／CP437 判定，不依赖系统区域设置，也不在定位失败后尝试另一种名称。保留原始名称信息供核对，禁止有损替换、大小写或 Unicode 归一化后合并成员；规范路径出现歧义时不任选一个。目录则使用 MemberSource 已提供的规范路径。这里不新增名称编码偏好。

路径逐段比较，每一段完整分出顺序后才比较下一段，因此不同原名的目录始终各自成组。段内规则为：

1. 文字使用固定版本的 Unicode 默认完整大小写折叠，再按 Unicode 标量值比较，不依赖系统区域设置。它只产生比较键，不修改成员路径。
2. Unicode 十进制数字 Nd，包括全角数字，连续组成整数；按十进制位数及数字比较，避免浮点精度上限。不把负号、小数点、汉字数词或罗马数字另猜成数值。
3. 主比较相同才比较数字串宽度，较少前导零在前；仍相同再按完整原名的 Unicode 标量值补序。原名不同就不会因折叠后相同而合并。数字与非数字的比较也使用一致的数字分类，不能因原始码点混用而形成排序循环。

当前数据固定 Unicode 18.0.0，与已有文字规则采用的版本一致；不做 NFC／NFKC 名称重写。Unicode 数据的升级属于库的显式版本维护，不跟随浏览器 ICU 自动变化。排序键和数据可以在内部共享，不要求主应用继承该排序或该类型。

| 输入例子                                   | 确定顺序                                   |
| ------------------------------------------ | ------------------------------------------ |
| `10.jpg`、`2.jpg`、`1.jpg`                 | `1.jpg`、`2.jpg`、`10.jpg`                 |
| `Page10.jpg`、`page2.jpg`                  | `page2.jpg`、`Page10.jpg`                  |
| `001.jpg`、`01.jpg`、`1.jpg`               | `1.jpg`、`01.jpg`、`001.jpg`               |
| `vol01/1.jpg`、`vol1/10.jpg`、`vol1/2.jpg` | `vol1/2.jpg`、`vol1/10.jpg`、`vol01/1.jpg` |

本规则解决无出版物顺序声明的图片成员页序；EPUB spine、PDF 原始页、KF8 skeleton 等格式已有的顺序仍由各自格式解释。不按 cover、front、彩页等名称推断另一条隐藏顺序，也不把左右翻页方向当作排序方向。

持久位置仍是准确的 memberPath，页码只是本次序列的派生值。同一路径的原名差异不得静默纠正；当前输入中的成员列表和内容不在阅读途中自行刷新。以后重新打开时新增成员可以改变页码，却不会把旧位置重新解释为旧页码处的另一张图片。已发布的页面解码失败也不能通过删除该页、挪动后续页码来掩盖，按已有失败规则报告。

## 源索引与按需驻留

索引需要解决“重新找到原内容”，不承担保留全部显示内容的责任。轻量目录、结构计数和来源关系可以比 DOM、像素与解码块活得更久；它们均归本次格式文档拥有，消费者通过已有能力取得结果，不得到一套公共索引 API。

| 格式          | 索引与读取方式                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EPUB          | 首先取得 package、spine、manifest 和成员目录；按需解压、解析目标内容文档，建立该文档的 CFI／ID／文字对应。重复 spine 共享只读源事实，各自保留出现上下文 |
| KF8           | 取得记录、skeleton／fragment、FDST 和资源索引；按实际解压记录长度定位所需区间，重建目标 skeleton 文档，再建立 HTML 来源映射                             |
| MOBI6         | 记录长度和原始标记流分别缓存；原始字节地址跨记录仍连续。HTML 修复依赖完整上下文，按受管的内容文档解析，不把任意记录边界当成安全 HTML 边界               |
| FB2           | Expat 顺序解释 XML，写入格式拥有的节点、文字、正文／注释与资源索引；逻辑子节点编号和文本合并规则固定。正文读取按源结构恢复必要内容                      |
| TXT           | 固定本次编码，持续解码并记录原 UTF-16 累计偏移；已解码文字按块保存，CRLF、替换字符和编码状态的含义不随展示分块变化                                      |
| PDF           | 复用 PDF.js 的范围输入和页面能力；按页取得文字、几何与绘制资源，页面数量来自文档结构                                                                    |
| 图片目录／ZIP | 完整成员身份和页表常驻或分页存储，成员字节、解压结果和像素按需取得，页表不因缓存回收改变                                                                |

有状态解码器和 XML parser 的暂停状态只属于仍存活的实例。不能只记一个原始字节 offset，就假定之后可以从该处新建解码器继续；[Encoding 的解码状态](https://encoding.spec.whatwg.org/#decoders)和 [Expat 的暂停／恢复](https://libexpat.github.io/doc/api/latest/#XML_StopParser)都不提供这样的通用随机重启合同。

需要保留已解释结果时，使用现有 TemporaryStorage 写入格式自己的分块文字和索引记录。XML 记录保留节点关系、逻辑子序号、属性／ID 及文字片段的累计偏移；大索引也分页读取，不把节点对象和整段字符串永久留在 JS 堆中。写入在解析输入块之间排空并等待完成，形成背压；不为此新增数据库、通用 AST 或可序列化 parser 快照。

暂存保存的是可重建的派生内容，原始 ByteSource／MemberSource 继续是本次来源权威。索引页和热内容可以分别回收；重新打开可以重新建立索引，暂存文件不成为跨会话书籍格式或持久位置的一部分。未提供 TemporaryStorage 时沿已有有界缓存和允许的重读工作，不另造隐式磁盘缓存。

对 XML 结构完整性要求覆盖整个输入的格式，仍须完成相应语法解释才能发布可信结果；这不要求同时建立全书显示 DOM。对 EPUB／KF8 等已有独立内容边界的格式，只等待本次目标和必要目录。搜索、索引推进和预取通过同一内容拥有者接续，前台需要某个尚未完成的区间时提升它的优先级，不再启动第二份全书解析。

parse5 的同步树构建与巨大章节的布局上下文继续按实际后端限制处理，不承诺通用的任意节点换出或任意 DOM 切片。可按块组织的 TXT／源索引与必须保留完整上下文的 HTML 文档采用不同驻留单位，这是格式和浏览器机制带来的差异。

缓存目标用于回收可重建内容，展开量、解码像素、原生堆和单次结果的限制用于控制实际操作。优先次序和失败范围沿用[资源预算合同](resources.md#budget)。具体容量在正式实现的代表性内容上测量、调参；不凭小试件制定全库总 MB 数或新增公开调优字段。

<a id="progress"></a>

## 结构进度

progress 继续是主阅读路径中的辅助反馈，不参与位置恢复、完成次数或已读判定。独立辅助内容为 null；临时查看保留主阅读进度。格式提供源结构计数，Reader 仅组合已确认位置与这些计数，不从当前分栏数、页面像素或 quote.length 推算全书进度。

| 来源                                   | fraction 的依据                                                                                  | estimated |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ | --------- |
| PDF、图片目录／ZIP、全部为固定页的正文 | 当前原始页的序号除以原始页总数；序号从 1 开始，双页空槽和阅读方向不加入计数                      | false     |
| TXT                                    | 当前原 UTF-16 位置除以完整解码序列长度；总长度尚未取得时为 null                                  | false     |
| EPUB、KF8 的重排或混合正文             | 正文中的原始 spine 出现／skeleton 文档等权；单元内部按源内容索引的位置细分，固定单元按原始页处理 | true      |
| FB2、MOBI6 重排正文                    | 按格式正文索引中的源文字与结构位置计算，排除独立辅助路径、元信息及脚本／样式载荷                 | true      |

重排单元的内部计数采用候选正文源文字的 UTF-16 长度，明确的非文字内容叶项各占一个结构单位，普通容器不额外加权；位置由前缀计数加当前文字偏移确定。结构单位只用于比例，不生成字符或地址。它不根据压缩率、图片文件大小或 CSS 隐藏结果猜测阅读耗时。EPUB／KF8 的章节等权是有意采用的结构估算：长短章可能贡献相同的区间，换来不扫描全书正文就能提供稳定依据；本次 Reader 不在后台逐章加载后悄悄换成另一组权重。

TXT 的完整分母在顺序解码到末尾后取得，与首个可读目标的打开分别安排。空正文没有有效比例时为 null；缺少可细分文字的位置使用所属结构边界。fraction 为 1 表示结构坐标到达末端，作品完成由所属业务另行记录。

进度序号是正文路径内的派生值，排除独立辅助单元；原始 spine、skeleton、PageRef 和 memberPath 仍保持原身份。它不因为用于计算比例而变成另一套可保存地址。

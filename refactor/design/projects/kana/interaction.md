# Kana 阅读交互

选择、复制、按键、焦点和辅助技术由明确的阅读交互拥有者协调，共享稳定的源状态。

<a id="selection"></a>

## 源选区、原文与显示投影

selection 在源层保存一次连续选择的起止点、方向与匹配文本，各章节的 Range 和高亮投影这份状态。显示片段随章节加载、排版与回收重建，源选区保持连续。Kana 统一接续跨页、跨章、横竖排和自动滚动中的选择。

内部保留选择的固定端与活动端，使用所属格式能够可靠表达的定位；有序范围在交付时由实际源顺序导出。PDF 的页面几何与可靠文字锚点继续沿既有合同分别处理，不为外观统一再创造一种通用文字坐标。命中与视觉移动由视图提供，源比较与原文由格式能力提供，selection 组合它们。

[Selection API 草案](https://www.w3.org/TR/selection-api/#definition)将选择关联到所属 Document，嵌套文档不共享同一个选择；Range 的端点又会受 DOM 变化影响。因而卸载或替换文档前必须已经保存源端点，跨文档过程也不能只持有一个活的 Range。Kana 只管理本 Reader 所属内容文档的选择，不清空宿主输入框或其他 Reader 的选区。

摘录保留用户本次实际选择的正文，排除脚本／样式、界面注入内容和布局产生的装饰字形；空白、段落分隔、ruby 与隐藏内容遵守已确定的[文字流与提取规则](content.md#text-flow)。源范围可以覆盖不绘制的节点，不要求把其中每个源字符都拼入用户摘录，也不允许只返回当前已加载章节的部分文字。已保存摘录不会因后续排版或提取规则变化而重写。

getSelection 固定调用时的源范围，完整读取该范围的原文；期间改选不使旧范围与新文字混用。提取与搜索共同遵守[文字流与提取规则](content.md#text-flow)。

标记只读投影复用源映射和当前几何，来源顺序、同起点并列和无法恢复的 ID 一并回传。高亮不得靠改写源树实现。PDF 仍使用原始页上的有序四边形，不增加 PDF.js 文字项编号作为持久身份。框选区域始终属于一张原始页面，截图与业务保存仍由 Kisaki 接入负责。

<a id="interaction"></a>

## 连续选择与输入协调

selection 统一协调固定端、活动端、取消、键盘扩展、自动滚动和复制。章节内、跨章、跨页及重排使用同一语义，浏览器 Selection、Range、命中测试和显示几何提供实现能力。输入先在本 Reader 的内容边界汇合，再按工具和动作交给实际拥有者。

<a id="presentation-selection"></a>

### 指针与原生选区

普通文字拖选从 pointerdown 开始就由 selection 持有固定端和活动端，并捕获该次指针。命中当前实际内容文档后，使用浏览器 caret 命中、Range 与局部几何，再由格式对应为源端点。章节内、跨章节、跨生成面和反向经过起点都沿同一条路径，不在越过 iframe 时才临时切换为另一套选区规则。

只接管属于阅读内容的文字选择动作，并沿既有 read／pan／region 模式分派。链接单击、拖选阈值、双击选词和焦点具有各自明确的输入含义；不能为了统一拖选而吞掉正常链接操作。外部输入框仍归宿主，触控也需要自己的手势判定。

selection 协调连续选择，浏览器提供字形排布、连字、双向文字、ruby 和局部文字边界。按键移动先将逻辑端点投影为所属文档的原生 caret，再取得实际移动结果，核对并采用其源端点。到达文档边界后，navigation／view 准备下一处可读内容。

浏览器 Selection 可以承载活动文档的原生反馈和输入，但只投影同一个源选区，不保存第二个正式范围。程序性投影按预期端点抑制回送；有效原生改选不要求先出现 pointerdown 或 keydown，以允许触摸、辅助技术和浏览器命令接入。具体核对见[输入归属](#ownership)。只处理本 Reader 的文档，不能清空宿主表单或其他 Reader 的选择。

<a id="ownership"></a>

### 输入汇合与去重

每份所属内容 Document 登记自己的原生事件入口，全部交给本 Reader 的内容交互拥有者。它先识别主阅读、临时查看、原生控件和当前工具，再调用 selection、navigation 或 view；不同 Reader 不共享一次手势，也不借宿主监听整棵私有 DOM。

同一内容的显示副本负责命中，实际焦点、原生选择和原生控件操作落到语义文档。链接、details、表单控件等先按源目标进入真正拥有语义的文档，再执行一次对应动作。原生控件的当前值和打开状态按[共享内容状态](#style-state)同步；用户在控件内输入的值不成为书籍原文、搜索索引或可保存文字锚点。

去重只针对已处理的具体输入序列。指针抬起后的兼容 click、长按后的 contextmenu 与原生键盘／辅助技术激活分别识别，不能把所有 detail 为零的点击当键盘，也不能要求辅助技术必须先产生 pointerdown。

原生 selectionchange 可以直接提供有效输入：触摸选择、辅助技术或浏览器命令未必有前置按键。以所属语义文档、有效源绑定和实际端点核对；库自己刚投影的预期端点不再回送为一次改选。isTrusted、事件次数或“上一条事件是键盘”均不能单独区分这两者。控件内部选择保留原生含义，不被书籍选区替代。

<a id="input-selection"></a>

### 跨界接续与取消

内部只保留一个固定端、一个活动端和本次动作身份。交付时按源顺序得到有序范围，原生 Range 与高亮均为这份范围的投影。

| 输入或变化                                  | 执行规则                                                                                |
| ------------------------------------------- | --------------------------------------------------------------------------------------- |
| 鼠标／笔从正文开始拖动                      | 从 pointerdown 登记同一次动作，超过拖选阈值后延伸；捕获文档在动作结束前保持有效         |
| 链接单击                                    | 保留链接激活；确定拖选后才取消该序列的激活，不能按下时先跳转                            |
| 双击选词                                    | 使用当前原生文字边界，按同一源映射形成范围；不按空格切词或假定一个字形等于一个字符      |
| 越过阅读面、章节或固定／重排边界            | 命中当前实际面，按既有阅读路径接续；不改变固定端，不将独立辅助路径接到正文范围          |
| 边缘停留                                    | view 解释当前可推进方向并驱动自动滚动／翻页；按新布局重新命中，不能累计旧面上的屏幕偏移 |
| 下一处内容尚未就绪                          | 活动端停在最后确认的源位置；同一动作只等待必要接续，失败保留已确认范围并反馈            |
| pointerup                                   | 停止延伸和自动滚动，释放捕获；未完成的跨界加载不再改变选区                              |
| pointercancel、失去捕获、窗口失焦或页面隐藏 | 结束本次手势和待接续工作，保留已经确认的文字范围；未完成的区域框不成为正式 PageRegion   |
| 字体／视口／方向改变                        | 保留源端点，等待同一布局采用后更新几何；不凭旧坐标反推新源范围                          |

指针捕获使事件继续交付原文档，view 再按当前布局将坐标转换到实际命中文档的视口。语义文档换槽位、页面旋转和原始页缩放都使用这份当前变换。

按键重复与持续拖动都不得积压一串异步跨章动作。准备完成时，动作仍有效才继续一次，并重新读取当前输入；用户已经松手、松键或转去其他内容时，迟到结果只结束资源占用。相邻章节的源字节、原文和索引可以按需保留，跨章范围本身不要求经过的全部 DOM 常驻。

已采用的区域选择仍限于一个真实源页。区域绘制越过页界时按该页边界约束；不把跨页框猜成另一种公共范围。工具切换、明确定位、参考查看和关闭沿既有完成规则结束旧动作；选择中的自动推进不算清空选区的明确导航。

<a id="touch"></a>

### 触摸浏览、长按与拖柄

read 模式允许当前阅读轴的正常触摸浏览与浏览器缩放。touch-action 在接触开始前按当前面配置，已有原生控件保留自己的操作范围。横竖轴交界仍按[换轴交接](layout.md#flow)处理，不能在同一个已开始的手势中修改 touch-action，试图夺回浏览器已经接管的指针。该限制来自 [Pointer Events 的直接操纵规则](https://www.w3.org/TR/pointerevents3/#the-touch-action-css-property)。

长按识别只在仍未形成浏览手势的正文接触上进行。长按成立后按原生词边界形成源选区，松开后通过选区拖柄继续扩展。触摸已经移出容差、浏览器发出 pointercancel 或进入多指缩放时，取消尚未成立的长按；不在后台补一次选词。

选区拖柄从下一次 pointerdown 起拥有指针，使用自己的 touch-action: none，再复用同一固定端／活动端、跨章接续和自动滚动。明确的 pan、region 工具同样只在其操作面内接管拖动。不会为了正文选择而在整个宿主页禁用触摸或缩放。

库已接管的长按序列抑制重复的原生选择、兼容点击和上下文菜单；其他原生选择及辅助技术命令仍由前述输入入口接受。拖柄提供可聚焦的端点控制和可辨认名称，键盘可以调整对应端点；不能把精确拖动当作完成选择的唯一方式。阈值和触控尺寸在实际输入实现中调定，不成为公共设置。

<a id="keyboard"></a>

## 键盘处理顺序

处理顺序是原生编辑／组合控件、当前阅读内容、宿主快捷键、尚适用的浏览器默认动作。输入法组合期间的键和原生控件保留键不被解释为翻页；已经取消的事件不再次执行。箭头、Enter、Space 或 Escape 在控件中有原生含义时，不能仅因阅读区有焦点就抢走。

| 内容操作                           | 执行方式                                                                                           |
| ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| Shift 加方向键及平台文字移动组合   | 将当前活动端投影到所属语义文档，用原生 caret／Selection 移动取得下一端点；固定端不变               |
| 字符、词、行首尾与段落移动         | 按平台组合和实际书写模式调用相应原生移动，保留双向文字、组合字符与 ruby 边界；不用 UTF-16 加减模拟 |
| 原生移动到达章节边缘               | 由 view 准备相邻可读单位，再继续同一个文字操作；加载期间不发布估算端点                             |
| 已有选区中的普通方向移动           | 按原生视觉方向折叠或移动活动 caret；不同时再执行一次主阅读翻页                                     |
| Ctrl／Command+A                    | 针对当前语义范围全选，临时查看限于实际参考范围；不选择显示副本或宿主控件，也不因全选加载整本书     |
| 复制                               | 使用固定源范围的完整原文，见[复制入口](#input-copy)                                                |
| 平台顺序焦点按键                   | Tab、Shift+Tab 及平台适用组合按浏览器与用户键盘设置遍历；出入口见[焦点接续](#focus)                 |
| 未被局部操作使用的翻页／窗口快捷键 | 通过下述宿主入口交付；主阅读按键使用已采用的 forwardDirection，不猜作品类型                        |

文字移动使用各受支持引擎的原生适配；原生端点无法映射时停在最后确认位置并报告，不能用“下一个字符”冒充正确的视觉移动。正式适配按[运行覆盖与交付](../../../verification/acceptance.md#runtime-coverage)覆盖实际浏览器引擎、平台输入、书写模式与辅助技术分支；[版本维护窗口](README.md#browser-versions)和系统下限继续遵守所属支持合同，没有实质差异的组合可引用适用证据。已有局部 caret 证据不代表其他适配分支已通过。

Escape 先让输入法、编辑框、打开的原生弹出内容处理自己的取消。阅读内容内则依次结束正在进行的动作、清除活动选区、关闭当前参考查看、退出主阅读的临时工具；一次只结束最内层仍有效的一项。仍未处理时才交给宿主，因此关闭选区不会同时退出整个阅读窗口。此顺序不把临时查看强制定为模态。

<a id="host-keyboard"></a>

### 宿主同步按键入口

内容 iframe 的 KeyboardEvent 只沿自己的文档传播，[DOM 事件路径](https://dom.spec.whatwg.org/#concept-event-dispatch)不会跨到宿主容器。宿主容器上的普通 keydown 监听不能收到它；主应用又不应依赖库的私有 iframe。OpenReaderOptions 提供一个可选回调：

```ts
interface ReadingKeyInput {
  readonly key: string
  readonly code: string
  readonly altKey: boolean
  readonly ctrlKey: boolean
  readonly metaKey: boolean
  readonly shiftKey: boolean
  readonly repeat: boolean
}

interface OpenReaderOptions {
  // Receives keyboard input left unhandled by the reading content.
  readonly handleKeyDown?: (input: ReadingKeyInput) => boolean
}
```

ReadingKeyInput 归纯值合同，回调归浏览器打开输入，主入口直接引用同一份纯值定义。

回调只接收局部未使用、适合交给宿主的 keydown 快照，返回 true 表示宿主已接手，由库同步 preventDefault；返回 false 或未提供时保留默认动作。宿主若开始异步操作，也须同步返回是否接手，并在自己的动作边界处理完成和错误。回调异常由宿主错误边界处理，不归类为书籍损坏。

调用仍处于原按键分派中，不制造另一条伪装成真实输入的 DOM 事件，不公开内部 Document，也不把 KeyboardEvent 放进状态或 IPC。回调可以读取宿主当前快捷键配置，无须为改绑键位重开 Reader。关闭后注销相应文档入口。

浏览器和 Electron 宿主通过同一输入接入全屏、面板及阅读快捷键。Electron 确需窗口级处理的快捷键仍由本体拥有，但同一按键只走一条动作路径，不能同时在 before-input-event 与此回调翻页。

<a id="documents"></a>

## 语义文档与显示副本

| 能力                   | 语义文档                         | 显示副本                               |
| ---------------------- | -------------------------------- | -------------------------------------- |
| 完整章节与作者上下文   | 保留                             | 保留                                   |
| 当前阅读面的排字与绘制 | 显示所需片段                     | 补齐另一面的片段                       |
| 标题、链接、语言等语义 | 通过正常文档结构交付             | 从辅助技术入口排除，避免全文重复       |
| 键盘焦点与原生选择投影 | 承担本上下文的真实焦点和原生反馈 | 不进入键盘遍历，不成为正式焦点或选区   |
| 指针命中               | 使用本地原生命中并对应源端点     | 同样使用本地原生命中，再交给共同拥有者 |

语义文档与显示副本用于同一内容出现的双面呈现。不同章节、同一 href 的不同 spine 出现、主阅读与临时查看分别保留自己的上下文和身份；固定页面也各自保留源页身份。它们可以复用字节，同时保持实际内容范围独立。

语义文档保留浏览器的正常标题、段落、链接、表格和语言结构，不用一个 aria-label 替代整章，也不把正文整体改为 application 角色来接管辅助技术的阅读方式。

显示副本通过其文档入口的 aria-hidden 排除重复语义，并退出顺序焦点导航。仅设置 aria-hidden 不会同时阻止键盘和鼠标获得焦点；指针输入仍由既有内容交互入口接管默认动作，再落到语义文档。所需行为分别验证，不把一个属性视为完成整个接入。相关要求见 [WAI-ARIA 的隐藏内容规则](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)与[顺序焦点检查](https://www.w3.org/WAI/standards-guidelines/act/rules/6cfa84/)。

显示副本保留精确的文字和链接命中，因此不将整个副本设为 inert。其原生命中差异见[焦点机制验证](../../../verification/evidence/kana-focus/focus.md)，隐藏语义与处理输入仍分别实现。

<a id="style-state"></a>

### 内容状态与真实焦点

同一内容出现的各投影使用同一份源交互状态，包括实际 hover／active 目标、焦点及其可见指示状态、书内目标和已打开的原生内容。状态由现有内容交互拥有者从真实输入与导航取得，按源元素对应到各文档；不同 spine 出现、独立章节和参考查看不因复用字节而共享这些状态。

作者选择器中的 hover、active、focus、focus-visible、focus-within 和 target 等受控状态通过 CSS 语法投影到私有状态属性，保留原来的选择器权重、嵌套和祖先匹配含义。支持查询中的语法检查仍检查原生能力，不把它改成“私有属性存在”的条件。浏览器对 visited 的隐私规则继续保留，不尝试读取或同步浏览历史。

显示副本的状态属性只影响原生 CSS 匹配，不使它获得第二个焦点、键盘入口或正式选择。语义文档才真正调用 focus，并承担浏览器的焦点可见性判断；details／控件等原生状态按源对象同步实际状态。需要显示焦点指示时，view 保持统一的可见反馈，配色与重排不能把它留在旧几何上。

这项同步也用于排版。作者可以通过 focus 或其祖先条件改变边距、尺寸和可见内容；仅同步文字和设置不足以保证两面一致。共享源状态使两面采用同一排版条件，真实焦点仍只在语义文档中；相关对照见[机制证据](../../../verification/evidence/kana-style-conversion/conversion.md)。

<a id="slots"></a>

### 语义文档的阅读面切换

语义文档不固定在左面或右面。焦点或选区活动端进入另一面时，view 让同一份语义文档显示那个源片段，并让显示副本补齐另一面。按当前页组与阅读方向重新安排位置，屏幕上仍是原来连续的两面。

这一过程只改变两份文档的布局偏移与屏幕位置，不互换源顺序、不重新创建语义文档，也不通过将 iframe 从 DOM 移除后重新插入来移动它。已聚焦链接和原生 Range 所属的 Document 因此可以保持。

例如右向推进的两面原来分别显示第 4、5 个生成片段，语义文档在第 4 面。用户点击第 5 面的链接后，语义文档移到该面并聚焦同一个源链接，显示副本接替第 4 面。竖排从右向左时按相应槽位解释，生成片段编号仍不进入源地址。

指针捕获、固定端与活动端继续由同一次选择拥有。跨面与反向拖选使用当前真实文档的命中结果；不能因为显示副本换了槽位，就按旧 iframe 屏幕坐标解释后续事件。原生 Selection 仍只投影同一个逻辑源范围。

<a id="input"></a>

## 链接与焦点

链接单击执行链接激活，超过拖选阈值后转入文字选择。指针、键盘与辅助技术的激活按完整输入序列对应到一次源动作，并完成去重；click.detail 只提供局部事件信息。

跨文档的焦点采用先进入实际语义文档，再聚焦其源目标。视图先保证目标所在阅读面可见；不能在显示副本中留下一个已从辅助技术入口排除的实际焦点。重排保存源目标，并尽量保留原文档中的同一节点；更换文档确有必要时，由已有源映射恢复目标，不沿用旧 Document 的活对象。

顺序焦点导航沿浏览器、平台和用户键盘设置执行，跨页时显示实际取得焦点的目标。阅读区边界允许继续进入或返回宿主控制，不建立键盘陷阱。进入内容时从仍有效的焦点目标或当前阅读位置附近接续，不因换页每次回到章节第一个链接；焦点项、入口和边界交接统一见[完整焦点接续](#focus)。

内容交互拥有者只补充跨页显示、源目标对应及必要的边界交接。当前语义文档能够按原生规则完成遍历时，保留默认动作；从实际焦点变化取得目标，不另维护一套竞争的焦点次序。局部输入框、组合控件及原生编辑行为先按自己的规则处理。文字的视觉移动仍使用已确认的原生 caret／Range 路线，不把焦点导航当作文字选区扩展。

Safari 的 Tab 与 Option-Tab 受系统和浏览器键盘设置影响，不能把跳过某类链接直接判作库缺陷，再用统一 Tab 处理器覆盖用户选择。各平台通过自身适用的键盘操作到达内容和宿主入口，具体依据见 [Safari 键盘导航](https://support.apple.com/guide/safari/keyboard-shortcuts-and-gestures-cpsh003/mac)。验证记录保留实际设置，不修改全局设置来制造同形结果。

临时查看继续遵守已有进入、明确关闭与焦点返回规则；本方案不另定它必须模态或非模态。其语义范围应对应实际呈现的参考内容。关闭后恢复原触发位置的合理焦点；原节点已不再有效时按源目标或当前可用阅读区恢复，不能落到已释放的显示副本中。

<a id="focus"></a>

### 焦点顺序与内容入口

需要为跨页或边界交接解析目标时，依据 HTML 的焦点范围、tabindex 顺序及当前平台导航规则，覆盖链接、原生表单项、summary、可编辑区、显式 tabindex、SVG 链接和实际可进入的嵌套范围。禁用、隐藏、inert、闭合 details 等状态必须参与；单选组与原生复合控件保留自身内部规则。不能只查 a[href]，也不能为探测而逐个调用 focus，触发作者样式和控件副作用。规则依据为 [HTML 顺序焦点导航](https://html.spec.whatwg.org/multipage/interaction.html#sequential-focus-navigation)。

进入阅读内容时，先使用当前语义范围内仍有效的最近焦点；没有时，按阅读位置附近的源目标建立入口，再沿实际焦点顺序继续。需要临时聚焦正文时复用现有语义容器，不添加持久源节点或新的书内地址。只有当前一份语义入口进入遍历；显示副本仍用于命中。

跨面时先使目标可见，再聚焦同一语义节点。正常样式更新保留节点和焦点身份；真正切换内容时按源目标交接，不复用旧 Document 的活对象。焦点指示和滚动位置在同一次布局采用后可见，不能把聚焦留在裁剪区域之外。

Tab 到达当前语义内容边界后，可以到达章节／页组接续控制和宿主控件；反向同理。不为寻找“下一项”自动装入全书，也不循环回当前章起点。内容区域的协调仅用于保持正确顺序、跨面可见性及边界交接，不改用户的系统键盘设置。

参考查看的语义入口只覆盖实际查看范围，并保留解释它所需的原章节上下文。关闭后优先返回原触发目标；目标不再有效时回到主阅读的有效入口。打开、替换、失败和关闭均沿既有操作完成规则执行。

<a id="lifetime"></a>

## 辅助技术与语义范围

键盘焦点、文字选区与主阅读位置各自保留已有含义。焦点用于下一次输入落在哪里，选区表示所选源范围，主位置用于阅读落点与进度；它们通过同一源解释协调，不要求始终是同一个字段。

屏幕阅读器的浏览游标还可能独立于 DOM 焦点。不能把 document.activeElement 当作“正在朗读的字”，也不能从无障碍树快照猜测读者进度。可观察的实际焦点、选区、激活动作与原生滚动可以经源映射接入，未观察到的辅助技术内部位置不伪造为阅读记录。

章节占用与释放仍按已有预算管理，但正在承担焦点、活动选择或实际可访问阅读的文档不能仅因离开像素视口就回收。[有界语义内容](#accessible-lifetime)以完整章节／源页组保持稳定范围，并由明确内容动作交接；单纯滚动和预取不推定浏览游标已经离开。跨章朗读通过明确导航接续；真实辅助技术验收核对该接续，不把保留节点身份当作已经通过。

这项机制归现有 view／内容文档和 selection 的协作边界。格式负责真实源目标，view 负责哪个文档与目标当前可用，selection 负责选择；主应用不拼接副本的 Range，也不维护另一套书内焦点位置。

<a id="accessible-lifetime"></a>

### 语义内容的保留与接续

DOM 焦点、可见位置和屏幕阅读器的朗读位置分别表达不同状态。网页通常无法读取辅助技术的浏览游标，因此普通书籍文档只能依据实际可观察的交互管理章节保留；游标可能仍在旧章时须保留其可访问内容。需要额外互操作约定的 [APG feed 模式](https://www.w3.org/WAI/ARIA/apg/patterns/feed/)不适用于这里的普通书籍正文。

每次明确接续选定一组必要的完整内容单位作为稳定语义范围：通常是当前章节；当前阅读组跨两个源文档时包含二者。固定页面采用当前真实源页组，TXT 采用已有可安全分块单位。范围内保留正常文档语义和节点身份，不按生成面分页拆掉正文；一经采用也不随像素视口自动增删。巨大内容单位继续遵守既有资源预算与明确失败规则，不以读屏需要为由无限保留全书 DOM。

| 情况                                             | 语义内容的处理                                                               |
| ------------------------------------------------ | ---------------------------------------------------------------------------- |
| 只发生布局更新、预取、原生 scroll 或后台预算压力 | 不据此移走当前语义范围，也不猜测浏览游标已经离开                             |
| 用户明确定位、翻过语义边界、激活下一章／页组     | 准备新内容，成功后采用新语义范围并交接焦点；失败保持原范围                   |
| 已识别的鼠标、触摸或键盘浏览确实进入下一单位     | 作为这次内容导航的一部分交接；仅看到 scroll 事件不足以推定该动作             |
| 原生选择／焦点明确指向另一可用源目标             | 交互拥有者根据实际可观察的源目标完成接续                                     |
| 选择手势仍捕获旧文档，或原生投影仍由它承担       | 保留必要占用；动作结束或已交接后释放，不因跨章范围很长而钉住所有中间章       |
| 参考查看打开                                     | 保留主阅读语义范围和一处实际参考范围，按既有上下文区分；关闭时恢复主阅读入口 |

连续视觉布局可以准备相邻章节；未作为当前语义范围的显示内容不重复进入辅助技术入口。单纯的预取或辅助技术自动滚动不会让这份稳定范围跟着像素位置淘汰。用户主动滚动、选取或聚焦另一单位时，才通过识别出的内容动作完成接续；不自动探测用户是否启用了读屏软件。

语义文档内部可观察的原生滚动仍由 view 对应到实际源片段，并更新显示面；它只证明实际显示内容改变，不证明精确朗读位置，也不自动扩张或回收语义范围。库自己的布局滚动不再反向触发一次导航。范围外暂不暴露的内容与同一章的重复显示副本有不同原因，不能合并不同章节的源身份。

范围边界提供可发现、可用键盘和辅助技术激活的上一章／下一章或上一页组／下一页组控制，并交付当前内容名称。它们调用同一 navigation；不暴露第二个 Reader 或新的持久位置。交接成功后将实际焦点放到新内容的合适入口，失败仍可继续读原内容。提示只报告明确接续和失败，不把正文设为 live region 逐字重复播报。

**当前章节支持连续朗读和按标题等结构浏览，跨章节／页组通过明确导航接续。** “全部朗读”和活动标题树限定于当前语义范围；普通视觉连续阅读、跨章选择、目录与全书搜索保持原有能力。正式实现须以真实辅助技术验证入口与接续体验，验证依据是用户可操作的行为，不能被表述成能读取辅助技术的内部游标。

### 不同内容交付各自真实语义

HTML／XML 格式保留标题、段落、列表、表格、语言、链接及明确的出版语义，既不把整章压成 aria-label，也不改为 application 角色。显示副本排除重复语义；装饰与真正不可读内容仍按各自含义处理。

PDF 使用 PDF.js 的文字、结构树和注释能力，并保留结构节点与文字的对应。缺少标记结构时，交付能够可靠取得的文字及页面关系；图片页提供真实源页标识与已有替代文字。正文朗读依赖实际可提取文字，OCR 在当前范围之外。来源与文字可靠性见[格式能力](formats.md#format-scope)。

## 复制完整原文

复制与 getSelection 使用同一份[源文字投影](content.md#quotation)，不能以某个 iframe 的 Selection.toString 代替。选择期间有界准备原文，复制时固定范围及内容占用，后续改选不改变这次载荷。

原生 copy 与宿主按钮都须在真实用户入口满足实际写入条件。完整载荷、异步读取、权限及取消按下述流程处理；库与宿主分别承担自己发起动作的反馈。

<a id="input-copy"></a>

### 写入、失败与取消

1. 原生 copy 事件有完整载荷时，同步写入 text/plain 的 clipboardData 并阻止该次默认复制。
2. 仍需读取时，先阻止默认复制，避免浏览器只复制当前 iframe；在仍具调用条件的同一次入口构造 Promise 型 ClipboardItem 并立即调用 write，Promise 只交付完整载荷。
3. 已开始的读取失败、取消或 Reader 关闭时，尚未交付的载荷拒绝完成；不写空字符串、占位符或部分章节。写入已交给系统后无法由库承诺撤销，不把后续关闭误报成“已恢复旧剪贴板”。

原生控件中的复制保留控件行为；宿主输入框和其他 Reader 不被截获。右键或系统复制命令未必具备异步写入所需激活，安全上下文、焦点、权限与嵌入策略都由实际环境决定，不能伪造事件补出授权。规范依据见 [Clipboard API](https://www.w3.org/TR/clipboard-apis/#clipboard-event-api)。

缺少异步能力或被拒绝时保留当前选区并明确报告未完成。原文之后就绪也不擅自重试写入；用户再次复制才形成新入口。权限拒绝或能力缺失沿现有 unsupportedFeature 报告为本次操作不可用，源读取失败保留实际类别；不把 Reader 状态改成书籍损坏，也不永久关闭文字选择能力。

库内原生复制的失败由 error 事件交付一次。Kisaki 自己的复制按钮经 getSelection 取得完整结果，再走本体已有剪贴板能力和通知边界；它不解析书籍，也不把 Electron 对象注入 Kana。浏览器宿主的按钮若仍需异步取文，同样必须在真实用户入口启动适用的写入，不能先等待 getSelection 再假定激活尚在。

# 官方来源接入

17 个官方来源各自交付完整的资料能力及适用的个人操作。本文规定共同职责、页面与源码组织；具体对象、字段和账号范围由[逐来源设计](catalog.md#catalog)定义，公开接口见[Provider 合同](providers.md)。

<a id="responsibility"></a>

## 能力与职责

| 扩展能力       | 交付内容                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 资料获取       | 所有适用条目类型、主字段、关联对象、关系、分部与图片能力，按来源实际支持完整实现                                                 |
| 账号连接       | 真实需要的登录或凭据配置、授权、续期、连接状态与断开；按平台支持选定可持续的接入方案                                             |
| 库与收藏导入   | 用户拥有、想玩/想看、已完成等真实列表，以及适用的收藏夹和成员；明确目标对应、新增与已有对象处理                                  |
| 个人记录对接   | 从用户本人的记录读取状态、总评分、收藏与实际支持的进度，并提供适用的导入和回写                                                   |
| 同步           | 对确有读取和写入能力的平台，以本地为准更新选定个人字段；明确导入另行采用平台值，来源能力、创建与清除、可见性、触发和失败分别定义 |
| 相关操作与界面 | 实际有用的菜单、站点跳转、配置和账号操作，以及任务与结果反馈；站点特有且有价值的操作按其真实含义承接                             |

同一平台的 provider、导入、同步与界面共用客户端、连接和必要私有状态，通过公开本体 API 与 events 协作。账号操作与公开元数据各自完整交付，提供来源实际具备的能力，采用结果保存到本体既有模型。

账号连接、手动导入、自动导入和持续同步的触发与采用规则见[个人记录接入](synchronization.md)，凭据与账号寿命见[私有数据与认证](private-data.md)。连接账号或选择资料方案不隐式执行导入、远端写入，也不开启自动导入或同步。迁移备份另按[导入批次](importers.md#repeat)处理。

来源多维评分、累计进度和累计时间，分别按本体同义值采用，不推造总分、逐 Part 记录或活动区间。没有同义值的选中内容在结果中明确说明未采用或仅在来源内展示。

<a id="source-mapping"></a>

## 对象与资料映射

每个 provider 按真实字段、对象、关系和图片能力声明，并在七种 Entry、五种 Part 和四类资料关系内解释来源数据。出版版本、商品、翻译发布和声明数量，只有与本体含义相同时才能映射，不能仅因来源存在某字段就扩展模型。

映射先对照本体已经确定的对象粒度、字段和关系语义。已有概念能够准确承载时就直接采用，必要的来源称谓保留在相应别名或说明中；不因名称不同而新增类型，也不把已有明确语义降为笼统关联。只有现有模型确实缺少实际需要的语义或操作时，才讨论新增设计。

所有来源的配音资料都遵守[作品与原作语种范围](../domains/relations.md#voice-scope)，只采用作品正式使用的角色—声优关系，译配不进入人物工作关系。

所有来源的角色资料都遵守[角色范围](../domains/catalog.md#characters)。来源目录同时包含机体、舰船或虚构组织时，应按明确类别限定采用范围，不能因同属 character 资源就全部建立角色，也不能把虚构组织映射为现实组织。

每个接入核对对象粒度、字段与关系含义、语言、更新方式、出处和完整用户流程。聚合资料保留原始出处，同一上游的数据按同一份证据处理。

四类资料关系的 scope 按逐来源的对象范围与映射表声明。workCharacters 在角色根限定本来源支持的 workTypes；personWorks、organizationWorks 限定支持的作品类型、职责及人物工作的角色有无；workRelations 限定映射表支持的类型与目标作品类型。声明覆盖所有可能合法映射的组合，在读取前固定，不能从本次返回成员反推。仅有无角色制作署名的能力使用 character:none，具有可靠角色端点的配音分支使用 character:present；实际同时支持两者时分别声明。

同一 Entry 类型因来源资源不同而改变范围时使用 scope:session。例如 VNDB 的 Staff／Producer、MangaUpdates 的 Author／Publisher、RanobeDB 的 Staff／Publisher，在 openSession 中按实际身份选定本页规定的职责分支。来源查询完整、但其范围无法由上述有限维度表达时，使用 scope:null 保留补充能力。缺少分页、未知主体或无法解释的来源值仍属于读取失败。

<a id="platform-operations"></a>

## 页面与平台操作

每个扩展提供实际适用的设置、连接状态、资料操作、来源跳转和反馈。只有来源确有个人能力时，才提供本人导入或同步范围。远端写入明确账号、对象、字段、方向和来源实际支持的可见性，直接负载不覆盖未选择的文字与标签，平台原生联动正常接受并说明。完整分页、冲突、取消和未知结果遵循[同步合同](synchronization.md)。

VNDB、Bangumi 这类同时提供资料与个人接入的扩展，页面按账号、资料采集、导入、同步的顺序组织：

| 中文页面 | 英文页面 | 内容                                                             |
| -------- | -------- | ---------------------------------------------------------------- |
| 账号     | Account  | 凭据或浏览器连接、当前账号、连接状态与断开                       |
| 资料采集 | Metadata | 本来源的标签取法、图片筛选等采集设置；通用资料方案仍由本体管理   |
| 导入     | Import   | 手动导入、自动导入的启用与范围、资料方案、采用内容及可选目标合集 |
| 同步     | Sync     | 本地到平台的对象范围、字段、适用的可见性、手动执行和自动同步     |

页面与操作按实际来源能力提供，匿名可读资料在未连接账号时仍可使用。界面采用“资料采集”，公开接口使用 metadata 与 MetadataProvider。任务、进度和结果沿用本体的任务与反馈机制。

每项私有操作定义自己的结果，并按实际输入关联来源引用、本地引用、已完成或未采用的内容及安全问题摘要。Task 原样承接这份业务结果，只保存执行所需的摘要与引用，完整来源记录留在本次读取上下文。读取、回写、删除与同步分别按来源能力开放。

<a id="organization"></a>

## 来源扩展的源码组织

对象、字段和采用规则分别由 [VNDB](sources/vndb.md) 与 [Bangumi](sources/bangumi.md) 的专门设计完整列明。两项各自使用以下源码主干，客户端、账号与来源规则分别由自己的项目维护：

```text
src/
├── node/
│   ├── entry.ts
│   ├── client/
│   ├── account/
│   ├── metadata/
│   ├── import/
│   ├── sync/
│   └── settings.ts
├── webview/
│   ├── index.html
│   ├── entry.tsx
│   ├── pages/
│   │   ├── account/
│   │   ├── metadata/
│   │   ├── import/
│   │   └── sync/
│   └── styles.css
└── shared/
    ├── contracts.ts
    └── validation.ts
```

资料、导入与同步共用本扩展的客户端和账号连接，页面通过私有 IPC 调用相应完整业务，不拥有账号或后台执行的寿命。metadata 解释来源资料，import 组织手动导入与已启用的自动导入，sync 负责选定范围的本地到平台同步及其手动、自动触发。entry.ts 负责装配、轻量激活与登记，不承担具体联网与业务判断。shared 只保存本扩展的纯界面通信合同及共用输入规则，已有正式值直接引用 SDK，不复制本体 DTO 或保存运行状态。

VNDB 的 Release、人员别名和作品署名由自己的 metadata 解释；Bangumi 的 subject、episode、person 与 character 沿其专门设计处理。相同的目录结构不合并两者的来源语义。

其他来源按实际能力组织：[YMGal](sources/ymgal.md#organization)仅保留在线资料与配置，[MangaDex](sources/mangadex.md#organization)则复用自己的卷话分组和等价身份规则。各来源的完整目录见其专门设计，不从共同示例推断应有页面或能力。

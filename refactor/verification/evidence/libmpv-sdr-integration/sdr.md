# Windows 原生 SDR 与宿主颜色衔接

2026-10-21，复用既有 libmpv GPU addon、已确认补丁版引擎和 Electron 44.5.1，执行 sRGB、Display P3、十位 PQ 到 sRGB 三个场景。每场景取得 63×47 与 31×23 两份独立帧，再经 Electron 导入、跨进程 VideoFrame 与明确颜色空间的 Canvas 读回。没有重建 addon 或修改历史探针。

## 输入与判据

[prepare.py](prepare.py)核对原生 addon、引擎 DLL、原探针源码和已有自有 PQ 夹具的摘要，生成一张有明确 sRGB 标记的六色色块图和一个 ASS 红色绘制区域。固定输入及所有自有文件摘要见 [source-input.json](source-input.json)。

P3 预期由原色坐标、D65 白点和 sRGB 分段传递函数独立计算，经 XYZ 转换并量化到八位。它不从原生输出反推预期。六色之外保留原探针要求的中心灰块；实际采样点避开这个灰块。

PQ 夹具沿用已固定的十位 BT.2020 输入，七档源亮度为 0.1、10、100、203、400、1000、4000 nit。本轮采用实际 auto 色调映射，检查灰阶层次、近中性及字幕颜色，而不将源 nit 解释为显示器亮度或宣称全部画质已经通过。

自有 Lua 夹具在开始读取内容前应用目标设置，并锁定首次实际 video-params 的记录。由于复用探针在采集后还会测试修改传递曲线与切换 vo，不能用最后一次属性读取描述早先采集的帧。该夹具不是正式 VideoOutput 配置实现。

## 结果

| 核对                      | 本轮结果                                                                        |
| ------------------------- | ------------------------------------------------------------------------------- |
| sRGB 原生色块             | 两种尺寸均与源八位颜色一致                                                      |
| P3 原生色块               | 两种尺寸均与独立矩阵的量化预期一致                                              |
| 正确 P3 标签后回到 sRGB   | 最大误差为 2 个八位码值，处于往返量化判据内                                     |
| 同一 P3 纹理错误标成 sRGB | 最大误差为 117，负对照被明确区分                                                |
| PQ 到 SDR                 | 原生观察为 yuv420p10／bt.2020／pq；七档输出保持递增                             |
| PQ 输入上的 ASS 绘制      | 选中字幕，受查红色区域输出为不透明红色；宿主读回保持                            |
| 独立帧与消费寿命          | 核心关闭后仍可导入；关闭首个 VideoFrame 后 clone 仍可读；最终回收每次仅完成一次 |

第一份 PQ 帧的中性阶梯 RGB 为 1、44、137、约 182、218、246、255，其中一档绿色分量为 183；没有强行将原生量化差异修成完全相等。正确标签的宿主读回保留相同结果。

[sdr-contract.json](sdr-contract.json)保存六份帧的全部采样、真实 WebCodecs 颜色名称、原生设置观察与负对照。Electron 的 p3／srgb 描述实际读回为 smpte432／iec61966-2-1；sRGB 则读回 bt709／iec61966-2-1。窗口隐藏，未修改系统显示设置，未捕获桌面或用户内容。

[平台来源核对](platform-sources.json)记录固定 Electron 导入源码、颜色字段和对应平台规范；其中的 IOSurface、dma-buf 和同步规则只支持候选实现设计，不构成 macOS／Linux 执行证据。

## 探索修正与范围

初次自有夹具没有提供复用探针所要求的中心灰块，触发其已有灰阶断言。补齐灰块并锁定首份源元数据后，三个场景及全部像素判据通过；原生探针保持未改动，没有放宽检查来接受错误颜色。

本轮只在 Windows x64 上验证固定构建和受控输入，Canvas 颜色空间读回不等于物理显示器校色。探针为比较关闭了抖动，未验证正式抖动默认、HLG、复杂动态字幕、全部 HDR 片源、带字幕的 screenshot-raw、持续呈现或六平台制品。macOS／Linux 没有执行记录。三份场景各用独立进程运行，不用该结果声称旧动态库重复装载问题已修复。

复现使用已有固定依赖与引擎缓存：

```powershell
python refactor/verification/evidence/libmpv-sdr-integration/prepare.py
python refactor/verification/evidence/libmpv-sdr-integration/run.py
```

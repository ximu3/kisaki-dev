# 管理软件迁移导入

十三项官方导入器读取用户明确提供的导出、备份或一致只读副本，通过本体完整操作迁入能够准确解释的资料。默认采用输入中已知且合法的事实，联网补充由用户另外发起。每个导入器负责自己的格式、范围选择、批次进度与继续执行，复用本体已有能力。

正式项目与来源选择见[官方目录](catalog.md)，格式比较的依据见[调查记录](../../verification/evidence/importer-selection/comparison.md)。

<a id="scope"></a>

## 输入与对象范围

源输入保持只读，导入器不覆盖本体数据库，不修改源软件、执行其插件或恢复账号凭据。识别外部格式版本是导入器的源格式合同，不提供旧 Kisaki 库自动转换。源软件的备份操作可能带有退出或重启等副作用，不能由普通读取暗中发起。

软件库迁移由导入器解释来源身份、普通资料、个人记录、整理和本地配置。需要新建作品时，以来源中的已知资料形成 prepared 候选，经 ingest 完成本地对应与新增；显示名等最低创建条件满足即可，不要求来源站点在线或先选择资料方案。已有条目按完整来源身份或本次明确的本地目标复用，不因导入自动联网刷新资料。

NFO、ComicInfo 及各导入器明确支持的独立资料文件也使用同一规则。新对象直接采用文件中能够准确解释的资料；已有对象按本次明确的补空或覆盖范围使用 prepared 更新。整作、卷、话和版本的对应仍须成立，缺少必要归属或名称的项目报告问题，不能补造母作品、来源身份或占位名称。

条目按真实来源身份或本次明确的本地目标复用，没有对应的对象按正常创建操作处理。名称相同不触发合并，源内部 ID 不能冒充公开来源身份。作品、季、卷、话和版本先核对粒度，分部记录不能变成整部作品的完成事实。身份冲突或无法确定正确归属的项目报告失败，其他独立项目继续，不弹出配对向导。

## 选择、执行与默认采用

用户选择输入、对象、要迁入的资料、记录与本地配置，以及已有数据的处理方式后直接开始导入。批次固定实际输入和采用范围，使用导入器的格式映射形成资料；界面随后显示进度与结果。

导入器先解释来源中的对象粒度、正式身份与已知字段。准确对应已有对象时直接复用；缺少对应的作品调用 ingest.add 的 prepared 输入，以经过映射和校验的来源资料新增。缺少公开来源身份不阻止创建合法作品，源软件内部键只用于本批次对应；同名本地对象不自动复用。无法确定作品／分部范围或最低创建字段不足时，报告具体项目，其他独立项目继续。需要用户补充的对象或名称可以在重新执行未开始步骤前明确提供，不在后台猜测。

新条目的评分、当前状态和初始完成记录通过 initial 与作品一同提交；可准确映射的来源普通资料默认选中，用户可以取消相应字段。来源缺席不补造值。笔记、活动、合集、文件和启动配置分别通过各自完整操作迁入。已有条目或 alreadyExists 继续按本次已有对象采用选项处理，默认保留本地值；明确选择补空或覆盖时再调用 prepared 更新，不从新增入口隐式修改。

本地图片字节通过正常附件准备采用。仅有远端图片地址时，下载作为独立可选内容，默认不选；离线或下载失败不阻止其余合法资料迁入。导入结果可以按实际成功目标打开普通资料更新器，供用户另选 profile 和范围联网补充。该补充是新的资料操作，不回滚导入、不重放私人内容，也不把尚未补全的资料报告为导入失败。

sortName、addedDate 等不属于 MetadataCandidate 的本体字段，在取得目标后通过 entries 的完整修改操作明确采用，按同一批次记录步骤。它们不混入 provider 资料或 initial。各导入器继续核对字段的实际含义，技术时间不能代替用户日期。

格式不受支持或必要输入无效时在写入前拒绝。实际未迁入的所选字段和记录在结果中说明，不能把部分完成称为全部成功。

| 数据                           | 新建对象                                       | 已有对象的默认处理                                                                   |
| ------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------ |
| 作品资料、图片、分部与资料关系 | 默认采用可准确映射的来源资料，经 prepared 新增 | 复用现有对象，不因导入自动刷新资料                                                   |
| 来源名称、简介、图片等所选字段 | 随新对象采用所选有效字段                       | 默认保留本地；明确选择采用来源资料时才修改                                           |
| 当前状态、评分、收藏、文件位置 | 采用本体能够表达的源值                         | 保留本地；用户选择采用来源个人值后才修改，null、false 和 0 不统称为空                |
| 作品完成历史                   | 按下文初始化记录                               | 默认保留；明确选择追加时新增逐条来源记录，不用累计次数覆盖或推算差额                 |
| 笔记、短评与摘录文字           | 按选定内容建立笔记或标注                       | 本次选择导入的内容按正常创建操作新增，不覆盖已有正文，也不追踪是否曾在其他迁移中创建 |
| 标签、分类与合集成员           | 按各自模型建立                                 | 按真实身份和普通关系规则整合，不用同名或同正文合并独立笔记、合集                     |
| 作品累计时长                   | 用户选定时按总量形成附加时长                   | 默认保留；选择采用来源总时长后，按下文设置附加时长绝对值                             |
| 文件关联与启动配置             | 核验实际文件和同义设置后建立                   | 按本次明确输入登记，保留已有首选与位置，不执行启动                                   |

来源资料、个人值、历史和累计时长分别选择。真实分部结构按本来源的身份与归属规则采用，进度计数按其原有含义迁入。独立资料文件的新对象经 prepared 新增，已有对象按所选字段补空或覆盖。

prepared.data 交付普通候选。完整取得且本来源合同允许替换的关系集合，通过 prepared.relationScopes 声明一次范围；其余输入只补充或更新已知事实。声明以实际输入与映射为依据，缺失分段保持未回答。获取候选后继续调用 prepared 时，一并转交 data 与 relationScopes，并保留获取阶段的问题说明。

私人内容按本次选择迁入；持续同步另按[同步字段范围](synchronization.md#scope)执行。

## 完成历史与累计次数

迁移使用[作品完成记录](../domains/records.md)，不恢复独立可写的 completed 状态或完成计数。当前状态单独采用，历史迁入本身不改变已存在的当前状态。

| 来源事实                         | 迁入规则                                                       |
| -------------------------------- | -------------------------------------------------------------- |
| 真实逐次作品完成记录             | 保留每条能够采用的日期和备注，形成独立记录；日期未知可以为空   |
| 只有已完成标记                   | 本地没有历史时初始化一条未知日期记录；已有历史时保留           |
| 明确的整部作品完成总数 N         | 仅在本地历史为空时初始化 N 条记录；没有明细的日期留空          |
| 总数 N 与其中一次明确完成日期    | 在 N 条中为一条填写该日期，其余未知；不把日期复制到全部记录    |
| 启动次数、打开次数、实际活动条数 | 不转换为完成次数                                               |
| 分集、卷或话的完成信息           | 只采用对应 Part 的完成标记，不生成作品完成历史或分部日期、次数 |

各导入器必须按已核实的字段含义解释次数。重复使用次数不自动等于完成次数，来源总量和逐条明细描述同一组完成时不重复采用。输入中的次数、日期或对象范围相互矛盾时，报告对应完成信息无法采用，不猜测更正值。

为已有作品初始化空历史时，导入器读取该作品的历史数量，调用 completions.create 或 createMany 并携带 expected.completionCount: 0。同一作品的多条初始记录在本批插入前一次核对数量，再共同提交，见[历史数量基线](../domains/records.md#creation-baseline)。条件变化时整次历史操作不提交，保留已经成功的其他独立操作并报告实际结果，不自动刷新基线重放。新建作品的初始记录仍随条目共同提交。

本地已有历史时默认保留。用户明确选择“追加来源完成记录”后，将来源真实逐条记录作为本次新增输入提交；另建批次并明确发起相同追加仍然新增；继续原批次不重复已完成步骤。只有累计完成次数的来源不能向已有历史直接追加 N 条、相加或取最大值。不同批次不按同日或相同备注合并事实；同批次按已确认步骤保存源记录与实际结果的对应。

明确追加真实逐条历史使用普通 create / createMany，不附加空历史条件。当前状态、评分和收藏按已选择的当前值操作分别采用，历史迁入本身保留当前状态。

## 累计使用时长与真实活动

真实活动必须提供能够准确解释的发生区间和有效时长，迁入[实际活动](../domains/library-operations.md#activities)。只有日级汇总或累计量时，不能推算起止区间、分摊到虚构日期或放到导入当天；游戏、动画、漫画和小说均通过 additional_duration_ms 保存没有明细的附加时长。来源明细与同范围总量不能重复计入。

已有时长默认保留。用户选择“采用来源总时长”时，固定本次来源总量和已保存的实际活动量，以两者差额设置附加时长绝对值，不在已有附加值上累加来源总量。例如，实际活动三小时、采用来源总量十小时，附加时长设为七小时。之后新增的一小时活动仍正常计入，总量变为十一小时。

再次明确采用十小时是一次新的操作，按本次实际活动四小时将附加时长设为六小时；新批次重新确定本次采用值；继续原批次则跳过已经完成的绝对值设置。来源总量小于已有实际活动时，报告该总量未采用，不删除活动或生成负附加时长。同一次操作的重试沿用已确定的附加值，在途新活动继续累计，见[时长完整操作](../domains/records.md#duration)。

来源同时给出活动明细和总量时，按确认的覆盖范围采用一份；只有能够确认不包含在明细中的时长才形成额外附加量。只有累计数据的输入不会因此获得日、周、月统计。

<a id="files"></a>

## 笔记、标注、文件与配置

源笔记和选中的短评迁为独立 Note，建立明确条目关联。普通文字、源标题和日期不用于与现有笔记自动合并；本地已编辑的正文保留，另建批次并明确再次导入可以创建另一篇笔记，继续原批次则复用已完成引用。

标注只有在同一个实际文件上、来源坐标可以准确转换时，才保留本体定位与跳转能力。摘录文字或用户备注已经选入本次导入，而坐标无法转换时，可以作为普通笔记保存，并报告定位未迁入。不能将未知 CFI、页码或 XPointer 冒充本体坐标；没有文字、图像或其他可保存内容的纯定位失败项报告未迁入。

媒体文件默认在原位置核验并登记。用户可以提供明确的旧根与新根映射，随后直接核对和执行，不生成逐项路径预览；无效路径和登记冲突分别报告。缺少媒体文件不阻止独立资料和个人记录迁入，也不制造有效文件登记。

输入包含媒体字节时，用户明确持久目录后复制，或明确采用已经完成的持久解包目录。临时目录不能成为正式文件位置，导入不搬走、删除源媒体或覆盖目标已有文件。封面、背景和正文图片通过 attachments 正式接收，保存后不依赖来源缓存或临时目录；文字完成而图片失败时分别报告。

启动配置只转换本体支持且同义的路径、参数与设置，导入过程不启动游戏，也不执行源软件的脚本、插件或回调。文件和位置不明确时不生成看似可用的启动或继续入口。

<a id="repeat"></a>

## 导入批次与继续执行

新建批次与继续原批次是两个明确动作。每个导入器在自己的私有数据中保存 batchId、输入摘要、所选范围和采用选项、源对象到本地引用的对应，以及已经接纳的写入步骤。继续原批次只处理尚未完成且结果明确的步骤；新建批次按新的选择执行，仍可明确追加真实的笔记或历史。

导入器持有持续保存的 batchId 及其步骤进度，每次开始或继续执行分别建立新的 TaskRun。旧任务保留当时结果，批次当前状态列出已完成、待执行、失败、待核对和跳过的步骤。两者由各自拥有者维护，并通过本次执行关联。

<a id="batch-input"></a>

### 输入身份与保存范围

输入摘要来自实际选择的导出文件，或一致数据库副本的必要文件清单与 SHA-256。清单使用来源内的规范相对路径，记录文件摘要并按路径稳定排序；不使用路径、修改时间或软件显示版本单独判断相同输入。原始秘密、完整来源行、笔记正文与媒体字节不复制进进度记录。恢复时重新读取并核对原输入，可以重新选择字节相同的位置；输入内容改变时应建立新批次。

源键优先使用本输入实际提供的稳定记录键。CSV 等没有记录键的格式，使用固定输入摘要下的记录序号；序号仅在该份输入和批次内有意义。一个源对象有多个笔记、活动或配置时，各自使用源记录键或该固定输入内的局部序号。相同文字和相同日期不成为去重依据，两个真实来源记录仍可分别迁入。

概要与步骤记录使用本扩展的 storage.values，按 batchId 和 stepKey 分键保存；同时更新的进度与对应使用 storage.commit。步骤键由源对象键和明确业务动作组成，结果记录保存实际返回的本地引用、必要结果摘要、错误及操作输入摘要。原始输入、所选范围和采用方式固定；修正未完成项目的目标、缺失名称或资源路径时，保留原选择并记录本次明确修改，不改变已完成步骤。需要更换源内容或整体采用范围时建立新批次。

### 步骤状态与中断

每个写入步骤只执行一次本体完整操作；相关对象与附件需要共同成立时，继续使用已有原子操作。多个独立提交分别形成步骤，不能把“已创建作品但笔记失败”合成一个允许重做全部工作的失败步骤。

| 状态      | 含义                                 | 继续原批次时的行为                               |
| --------- | ------------------------------------ | ------------------------------------------------ |
| pending   | 尚未发出本体写入                     | 核对输入与现有目标后执行                         |
| running   | 已登记将发出操作，尚无持久的确定结果 | 当前仍在执行时等待；实例重建后转为 uncertain     |
| completed | 已取得确定结果并持久保存实际引用     | 跳过写入，复用本批次对应，不重新创建             |
| failed    | 有明确依据证明该步骤没有提交         | 修正原因后可重新执行；不得据超时或断连推定此状态 |
| uncertain | 无法确认写入是否成立                 | 不自动重发；先由用户核对结果                     |
| skipped   | 用户明确不再迁入此步骤               | 保留说明，不执行                                 |

发出有副作用的调用前，先保存 running 及实际输入摘要；保存失败则不发出调用。取得确定结果后立即保存 completed 与返回引用，再开始依赖它的下一步。调用返回已经成立的合法部分结果时，先保存那些事实；未完成的附带工作作为单独后续步骤处理，不重放已经成功的创建。

本体提交与扩展进度不共享事务。回复丢失、扩展失效、进度保存失败或进程中断后，仍为 running 的步骤须按 uncertain 处理；不能因为没有 completed 收据，就认定没有写入。这份进度支持安全接续，不承诺跨边界恰好一次。

结果待核对时，页面展示来源项目、操作种类、已知目标和实际问题，不按正文相似度或时间猜测已经写入。用户确认已完成时，明确选择并核对相应本地结果引用后记录 completed；确认未提交时重新置为 pending；也可以跳过。没有足够依据时继续保留 uncertain，并允许其他独立步骤执行。这个处理属于已结束批次结果的明确操作，不让旧 TaskRun 常驻等待用户。

核对入口先展示本步骤已经取得的引用和输入摘要，并通过普通详情或选择器打开用户选定的本地结果。选择器按对象类型及所属作品限定范围，保存核对结果前再次检查引用。相同文字或日期只供用户辨认，不自动证明某条记录来自本步骤。十三个导入器可以复用纯步骤状态、私有进度存取和接续测试；来源对象与字段含义仍由各导入器解释。

已经完成的本地对象后来被删除时，进度仍保留曾完成的事实；继续批次不能据此重新创建它。依赖该对象的步骤报告目标缺失，需要用户明确处理。重复点击继续或同批次已经执行时，共享当前执行或返回正在执行，不启动并行的追加。

### 页面、保留与清理

导入页可以重新打开本扩展的批次，提供“继续未完成内容”和“新建导入”。关闭页面不取消已经接纳的任务；取消只停止后续工作，完成必要收尾并保存已知步骤。继续操作形成新的任务报告，旧任务、旧错误和当时结果不被改写。

批次保存到用户明确清理或删除该扩展私有数据。TaskRun 历史清理不删除批次进度；清理进度不删除已经迁入的资料。未完成批次可先明确放弃再清理，页面说明之后不能继续该批次；不自动将它转成新的导入或按原输入重放。

完成判定按本次所选内容：全部步骤完成或被用户明确跳过、且没有 uncertain 或失败依赖时，批次可以结束。部分完成、取消、输入改变与结果待核对分别呈现。每个导入器使用自己的输入与结果合同实现这些规则，源软件内部 ID 始终不进入本体 ExternalIdentity。

## 导入器源码组织

十三个导入器按下列共同职责组织，具体格式、对象映射、选择界面、结果和模块由[逐项设计](#catalog)规定。

```text
src/
├── node/
│   ├── entry.ts
│   ├── input/
│   ├── mapping/
│   └── import.ts
├── webview/
│   ├── index.html
│   ├── entry.tsx
│   ├── selection/
│   ├── results/
│   └── styles.css
└── shared/
```

input 负责真实格式识别、支持版本检查与只读解析，mapping 解释本次来源对象与字段，import.ts 通过公开本体完整操作组织执行、任务及实际结果。界面负责输入、对象和采用范围的选择以及结果呈现；shared 只保存本导入器自己的纯通信合同与共用规则。转换结果属于本次执行；继续批次所需的源键对应与步骤结果按[批次进度](#repeat)保存在本扩展私有数据中，不成为本体资料身份。批次保存与步骤接续由 import 实现负责，复杂后再在其内部拆分，不增加本体导入中心。

格式读取按[逐项输入](#catalog)展开：Goodreads 的 CSV、Mihon/Tachiyomi 的备份消息、Vnite 的 PouchDB 文档、各软件的数据库与资源副本，以及 KOReader 的数据子集分别有自己的解释。成熟格式库可以复用，来源语义与采用政策仍由各导入器负责。专属样本放在各项目的 tests/fixtures，不能用同类导入器通过代替本项目验证。

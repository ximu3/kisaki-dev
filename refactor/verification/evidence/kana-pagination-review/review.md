# 原生补齐与独立分页路线的比较

2026-10-20，针对“Firefox 的作者强制断页能否干净、清晰、稳定地解决”继续比较。当前事实不支持“功能无法实现”的结论：本轮独立分页内核与完整排版引擎都在受测 Firefox 中执行了列表和表格行间的强制断页。需要判断的是采用哪一种工程边界，以及为此承担哪些其他职责。

## 固定输入

- 原生分栏与局部补齐沿用此前的[原生声明与补白](../kana-breaks/breaks.md)、[Foliate 实际加载](../kana-breaks/foliate.md)及[浮动辅助](../kana-breaks/float.md)记录，不将它们的局部失败扩大为所有算法都不可行。
- 独立分页内核使用 @pagedjs/paged-layout 仓库提交 d5639e71be3e5c94ba4f436eae36e5afddc0b161，清单版本为 0.1.0。本次 npm 包查询返回 404，实验直接使用固定 Git 源码，没有执行安装或构建脚本。README 声明 MIT，受查树未含独立 LICENSE 文件；正式采用时仍须核对完整来源与许可。
- 完整引擎复用固定的 Vivliostyle Core 2.45.2；来源、完整性与许可见[原输入记录](../kana-breaks/layout-input.json)。另外从同一 npm 制品的 source map 提取源代码，仅用于检查内部逻辑。

[prepare.py](prepare.py)记录固定来源与摘要，[source-input.json](source-input.json)保存结果；没有改变工作区依赖。运行器与夹具分别为 [run.cjs](run.cjs)、[probe.mjs](probe.mjs)，最终观察见 [browser-contract.json](browser-contract.json)。

三个引擎仍为 Chromium 149.0.7827.55、Firefox 153.0、Windows WebKit 26.5 测试构建，不代替正式稳定版矩阵、实际 Safari 或 WebKitGTK。

## 比较场景与判断方法

每个原版后端分别运行三种书写模式和四类内容：

| 内容                           | 要观察的事实                                            |
| ------------------------------ | ------------------------------------------------------- |
| 三个普通块，两个强制断点       | 是否分别进入三页，20px 块起始间距是否按实际方向保留     |
| 三个有序列表项，两个强制断点   | 是否逐项断页，原来的兄弟与 nth-child 选择器结果是否保持 |
| 三行自动列宽表格，两个行间断点 | 是否分别进入三页，列宽是否在分页后保持一致              |
| 六个 100px 块，无显式断点      | 是否按 280×400px 页面自然续排，内容是否仍落在实际页面内 |

另对 Vivliostyle 做一个范围明确的诊断修改，仅将核心 isVertical 判断从只识别 vertical-rl 改为同时识别 vertical-lr。修改只发生在实验服务交付的内存 bundle 中，原缓存和上游源码未改；修改位置、替换内容与摘要均写入记录。诊断不是完整修复，也未被采用。

共 84 组场景：原版两个后端各 36 组，方向识别诊断 12 组。每组均保留原生完整内容的样式与尺寸参考。比较源标记的完整顺序、逐页分组、颜色／粗细／边框、文字前缀占位、表格列宽与实际阅读区域。表格尺寸和页面边缘允许约 1px 的整像素取整差异；普通块的逻辑起点与尺寸单独以 0.5px 容差核对。原始数值完整保留，没有把取整容差当作像素完全一致。

paged-layout 的输入直接带有它认识的 data-break-before 标记，本轮检验的是已解析断点的布局执行，没有执行完整 Paged.js 的作者 CSS 转换链路。不能把这个内核的结果概括为全部 Paged.js 版本的能力。

## 独立分页内核：可以断页，作者上下文需要另有负责人

通过公开 ContentParser 和 Layout.renderTo 接口逐页创建容器，按 BreakToken 接续。在全部 27 组显式断页场景中，源标记都按 A、B、C 顺序分别进入三页，包括 Firefox 的重复列表和表格行。

原生分栏缺少强制换栏并没有阻止这种算法主动拆页。这是“功能可以由其他组织方式实现”的直接正向证据。

与此同时，本次直接使用该内核没有保持全部作者上下文：

- 原来的第二个元素移到新页后成为该展示子树的第一个元素，nth-child、相邻兄弟选择器产生不同结果；受查红色、粗体和边框不再保持。
- 普通块的计数器前缀占位发生变化。这里比较的是原生文字几何，没有将宽度检查扩大为完整计数器符合性验证。
- 自动列宽表格被按行重建后，各页重新形成不同列宽。例如 Chromium 横排参考的两列约为 191.56／88.44px，输出三页分别约为 46.67／233.33、259.98／20.02、40／240px。
- 自然续排的 vertical-rl 场景只生成一页，后续块越过页面左侧；vertical-lr 也有内容超出页面边界。

这些结果说明直接接入该内核不够。调用方还需要拥有作者样式解释、分页后上下文、逻辑方向与源映射；它们可以形成清楚的模块，但不能被记为已经由这个内核解决。其[源码](https://github.com/pagedjs/paged-layout/tree/d5639e71be3e5c94ba4f436eae36e5afddc0b161/src)确实提供逐页断点、溢出接续和树重建，不能将其描述为一组简单 CSS 别名。

## 完整引擎：更完整的上下文处理，以及明确的方向缺口

Vivliostyle 通过公开 CoreViewer.loadDocument 接收已解析 XHTML Document，并使用正常作者 CSS 声明。原版在本次横排和 vertical-rl 的 24 组场景中完成受查断页、自然续排、选择器结果及表格列宽保持；表格约 1px 的取整差异仍记录在结果里。

这进一步证明，列表和表格断页不必依赖我们此前的浮动辅助方案，也不能将“干净的完整实现不存在”作为结论。

原版的 vertical-lr 场景未满足要求。受查源代码中：

- css-cascade.ts 的 isVertical 仅将 vertical-rl 识别为竖排。
- vtree.ts 的 before／after 边缘及块推进方向，在 vertical 为 true 时仍按右起竖排解释。
- vgen.ts 在部分流程中也从布尔 vertical 推导为 vertical-rl。

这些位置对应同一制品中的原始源代码，并非根据一次错误截图猜测。[上游 #1480](https://github.com/vivliostyle/vivliostyle.js/issues/1480)也将额外书写模式列为尚未支持的能力。

只改变 isVertical 之后，受查源顺序、选择器、计数器占位、表格列宽及自然续排均有改善，但普通块与列表后两页的 20px 块起始间距变为 0，未满足实际方向下的起点要求。这个诊断排除了“只改这一处判断就完成支持”的说法，没有证明进一步的逻辑方向修订不可行，也没有量化完整修复的工作量。

完整引擎拥有自己的作者样式解释和生成页面 DOM。若 Kana 选择这条路线，需要正式设计输出元素／文字到格式源地址的映射、跨页选择、重排后的焦点、辅助技术入口、按需布局与取消释放，并重新核对相关呈现取舍。当前没有执行这些接入，不能将它们写成已经失败，也不能把短样例的正确输出当作整库可以直接采用。

## 证据能支持的结论

| 判断                                           | 当前证据                                               |
| ---------------------------------------------- | ------------------------------------------------------ |
| Firefox 原生分栏中的强制换栏存在缺口           | 已在固定环境中复现，相关上游问题仍开放                 |
| 已试的通用补白／浮动操作可以覆盖完整要求       | 不成立，已有列表、表格和作用范围反例                   |
| Firefox 中无法实现列表与表格强制断页           | 不成立，本轮其他后端实际完成了这些场景                 |
| 独立分页可以形成职责清楚的工程方案             | 有明确实现路线可以参考；完整 Kana 接入与稳定性仍未验证 |
| 当前存在已经验证可以直接替换 Kana 呈现层的组件 | 尚未建立这一结论                                       |
| Kana 是否值得承担完整 CSS 分页职责             | 属于目标与工程边界的取舍，不能包装成技术不可能性       |

基于这些事实，后续已确认[分页支持边界](../../../design/projects/kana/layout.md)：保留完整章节与原生排版，明确作者 CSS 能力差异，不再保证补齐 Firefox 当前缺失的强制换栏。原有格式结构、内容完整、定位和选择要求继续保留。

## 运行与限制

```powershell
python -B refactor/verification/evidence/kana-pagination-review/prepare.py
node refactor/verification/evidence/kana-pagination-review/run.cjs
```

本次所有用例都完成了观察，最终没有页面异常或外部请求。Vivliostyle 的异步命令通过公开事件入口等待 done，再验证目标页面可见后读取几何；早先只等待绘制帧或只观察可见性的试运行存在命令尚未完成的问题，保存在忽略缓存，不作为最终几何结论。

没有运行真实出版物、复杂 rowspan／colspan、完整 CSS 级联符合性、源地址往返、实际辅助技术、原生复制、交互接入或完整 Reader。浏览器上下文、实验页面与本机服务均按所属 finally 结束；本轮没有修改生产代码、依赖、许可或正式支持范围。

## 需要处理的实质问题

| 事项 | 依据与影响 | 建议与验收 |

| **优先修正 Linux 数据库资料根识别** | 私有原生模块枚举若干网络文件系统，FUSE 返回 `unknown`，其余未识别类型一律返回 `local`。Linux 标识 `0x7461636f` 的 OCFS2 是可供多主机使用的共享集群文件系统，会进入 `local` 分支。SQLite WAL 要求访问同一库的进程位于同一主机。该判断来自静态分支和上游定义，实际挂载待验收。[分类分支](../../clients/desktop/app/native/src/filesystem.rs) · [Linux 类型标识](https://github.com/torvalds/linux/blob/master/include/uapi/linux/magic.h) · [OCFS2](https://docs.kernel.org/filesystems/ocfs2.html) · [SQLite WAL](https://www.sqlite.org/wal.html) | 将能确认本地语义的类型判为 `local`，其余保留 `unknown` 或已知共享分类。资料根提供可操作的反馈，普通媒体读取维持自己的策略。取舍是部分此前能打开的罕见文件系统需要补证。用已支持的本地卷及一个共享类型核对分类，真实挂载另记。 |
| **优先更新运行时维护基线** | 工程锁定 Node `24.11.1` 和 Electron `45.0.0`。2026-11-14 查得 Node 24 同线已有标记为安全更新的 `24.22.3`，Electron 45 同线已有带 Chromium/V8 回补的 `45.3.2`。固定版本保证复现，升级频率决定是否持续接受修复。[工程版本](../../pnpm-workspace.yaml) · [Node 发布索引](https://nodejs.org/dist/index.json) · [Electron 45.3.2](https://github.com/electron/electron/releases/tag/v45.3.2) | 先更新同一维护线的补丁，精确锁定并复验 Node-API、SQLite、窗口、退出、fuses 和制品。工程 Node、Electron 自带 Node、消费方 Node 分别登记。桌面声称支持 macOS 13，固定 Node 24.11.1 的官方 macOS 二进制下限为 13.5，单独核对 13.0 的桌面运行与公开 Node 库支持范围。[桌面系统合同](../design/engineering/build.md#platforms) · [Node 24.11.1 构建基线](https://github.com/nodejs/node/blob/v24.11.1/BUILDING.md) |
| **移出 main 的长同步工作** | 同一份 5 万条目数据的 ICU 索引切换同步占用约 433–464 ms，明显超过现有主线程 50 ms 的定位预算。数据库语义正确，切换时窗口和 IPC 仍可能等待。[数据库设计](../design/engineering/database.md) · [性能原则](../design/engineering/performance.md) · [Electron 性能建议](https://www.electronjs.org/docs/latest/tutorial/performance) | 单个串行执行端持有写连接。main 发布语言与列表顺序时等待索引采用，同时可处理窗口事件。验收覆盖后台切换、重开、失败、短事务和定位一致性。 |
| **纠正菜单键入的语言与字符识别** | `createFocusNavigation` 仅接收 `event.key.length === 1`，比较时调用无 locale 的 `toLocaleLowerCase()`。真实 Chromium 156 中，文档语言为土耳其语、宿主偏好为英语，`H` 跳到 Hello，`ı` 无法定位 Işık，`𠮷` 无法定位以它起首的选项。试验用实际模块及合成键盘事件，原生输入法另行验收。[焦点实现](../../clients/desktop/packages/desktop-ui/src/internal/focus.ts) · [应用语言](../design/ui/localization.md) | 从实际控件或文档继承的 `lang` 取得比较语言，识别一个可打印字素，保留组合输入与控制键语义。沿菜单、选项和所有共用调用方核对，清理重复匹配逻辑。 |

## 需要保留的差异与文档落点

- **来源账号接入（W21）。** MangaDex 公开资料可以匿名读取。实现个人书单、导入或同步时，再核实第三方应用能否注册浏览器授权。现有个人客户端方案要求把密码交给应用，与 RFC 9700 第 2.4 节冲突。MAL 的 PKCE 支持按其注册端点单独核对。[MangaDex 账号设计](../design/extensions/sources/mangadex.md#account) · [上游公共客户端说明](https://gitlab.com/mangadex-pub/mangadex-api-docs/-/raw/main/02-authentication/public-clients.md) · [RFC 9700 第 2.4 节](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.4)
- **文件格式和来源合同。** 曾经发行的用户数据仍需能导入。Anx 的 MD5、KOReader 的分段摘要、YACReader 的局部 SHA-1 是历史关联线索，不能承担完整性或认证。保留格式语义和损失报告。NDL 已停止书影 API，当前设计已去掉相应调用。三份官方译本以 BCP 47、ICU 消息与用户选定的译本为入口。[Anx](../design/extensions/importers/anx.md) · [KOReader](../design/extensions/importers/koreader.md) · [YACReader](../design/extensions/importers/yacreader.md) · [NDL](../design/extensions/sources/ndl.md) · [译本](../design/extensions/languages.md)
- **受控通信与网络。** JSON RPC 处理有界控制消息，字节由流与资源入口承担。Electron `net.request` 当前设计依赖代理认证、重定向事件、多值头和增量上传，换用更短的 fetch 调用须先证明这些语义。扩展 Webview 的文档隔离、MessagePort 身份、签名索引和取消归属继续保留。[网络](../design/engineering/network.md) · [协议](../design/engineering/protocols.md) · [Webview](../design/extensions/webview.md) · [扩展分发](../design/extensions/distribution.md)
- **工程文档的迁移范围。** 建议获确认后同步更新工程 workspace、layout、build 和 conventions，公共 UI、扩展作者模板、开发说明、工程验收与实施状态。扩展作者仍可选框架及运行接入，Vite+ 负责第一方模板的工程默认值。历史测量保留原提交和工具版本。W20–W25 以及独立项目的发布承诺按所属工作包继续核对。[工程目录](../design/engineering/README.md) · [作者工具](../design/extensions/development.md) · [工作包](work-packages.md) · [文档归属](../design/engineering/documentation.md)

Linux 文件系统和 UI 键入是现有源码问题。凭据、独立仓库、来源个人功能和正式发行由各自工作包接续。归档时按[工程重构方案](engineering-modernization.md)记录本轮已采纳的调整和验收结果。

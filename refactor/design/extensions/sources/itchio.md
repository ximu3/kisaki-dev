# itch.io 接入设计

itch.io 提供独立游戏资料，以及本人拥有库、可编辑项目和公开合集导入。本文规定公开读取、稳定身份、只读授权和三类页面，不提供个人状态或评分同步。

<a id="scope"></a>

## 职责与页面

| 能力           | 终态方案                                                               |
| -------------- | ---------------------------------------------------------------------- |
| 游戏资料       | 公开游戏的搜索、定位、名称、项目介绍、主图、截图候选、外链与实际分类   |
| 人物与组织     | 不提供；平台账号和 authors 列表不能决定现实主体类型或正式作品职责      |
| 本人导入       | 拥有库、本人可编辑项目及选定的本人公开合集                             |
| 公开清单       | 可按明确公开合集链接导入游戏，不采用他人的评价或私人记录               |
| 私密合集       | 不提供；当前可授予的只读 OAuth 权限不能读取其成员                      |
| 同步与平台管理 | 不提供状态、评分、喜爱、时长或合集写入，不下载游戏、购买内容或许可密钥 |
| Webview        | 账号、资料采集、导入三个页面                                           |

只接入 Game，不因平台同时托管漫画、小说、素材、工具、音乐或桌游而扩大根类型。游戏项目按实际独立内容范围处理；素材包、数字手册、音乐包及只有商业包装意义的附加商品不能当游戏。公开资料不要求账号，连接也不隐式执行导入。

<a id="identity"></a>

## 来源身份与公开读取

source 使用 itchio，正式身份为 game/&lt;规范十进制 project ID&gt;，例如 game/106599。项目 ID、上传文件 ID、账号 ID、购买记录 ID 和合集 ID 各自独立；不以可改名的作者账号和 URL slug 作为作品身份。

按数字 ID 读取官方公开 embed 页面，取得当前项目地址，再读取该项目的 /data.json 与必要 HTML。这一链路已由官方 widget、公开 JavaScript API 及《DDLC》的真实响应核对，不依赖上次运行留下的 ID→URL 私有表。公开 JSON、页面 itch:path 与所请求 ID 必须一致，重定向不得暗中换成另一个项目。

名称搜索使用站点公开搜索表单的 q 参数。game_cell 与按钮可能重复携带同一个 data-game_id，只按真实项目 ID 去重。结果仍需读取项目并核对媒介和范围，素材包挂有 visual-novel 标签也不能作为 Game。使用服务端 API 时核对 classification=game；公开页采用平台生成的项目类别信息，不从作者的任意介绍或标题猜类型。

search 和 resolve 遵循共同候选与 matching 规则。已知 itchio 身份优先，不在身份冲突后改搜名称；本次取得的是候选，不把第一条、同名或同一上传者视作已匹配。公开合集和搜索的下一页只沿当前页面给出的同来源链接读取，不猜游标。

同一项目的 Windows、macOS、Linux 上传以及更新版本不另建作品。另一项目究竟是独立作品、试玩版、重制、扩展内容或镜像，须有真实范围依据；不靠标题后缀自动合并，也不从同作者项目建立作品关系。

<a id="fields"></a>

## 字段、图片与分类

| 来源值                               | 采用                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------- |
| title、当前项目标题                  | name；保持来源实际名称，不自行去除 Demo 或版本字样                        |
| 项目介绍正文、实际 short_text        | description；完整介绍优先，来源确无完整正文时可采用实际短简介，不重复拼接 |
| cover_image／cover_url               | primaryImage 候选                                                         |
| 真实 screenshots 与页面给出的原图    | backdropImage 候选，标注“作品截图”，沿已确认的图片用途规则处理            |
| links.self、项目声明的主页等普通链接 | externalLinks；不把自由外链宣布为其他平台的同目标身份                     |
| Genre 与实际 Tags                    | entryTags；以真实显示名称或来源原有标签值供给，不生成隐藏平台分类         |

HTML 只读取项目介绍与平台生成的信息区域，安全转为共同 Markdown。论坛、评价、开发日志、购买弹窗和下载正文不混入介绍；源码或 HTML 不作为可执行组件加载。页面和公开 JSON 缺项、解析失败及来源确实为空分别处理，不能用搜索词补正文。

没有正式多语言字段时，保留发布者实际文字，不承诺切换资料语言就能得到译文。不提供 originalName 或虚构 aliases；Languages 表示支持语言，不能成为 originalLanguages。published_at、created_at、updated_at 分别是平台发布或技术日期，不冒充作品首次发行。游戏模型没有独立发行状态字段，来源的开发阶段也不转成个人状态。

公众星级与评价人数不属于本人评分。没有同义敏感／剧透字段时保持未知，不从某张图片、作者账号、页面警告或未出现成人标签反推 false。

主图与截图保留原始用途、真实尺寸和已有静态／动图格式。仅使用来源实际给出的原图与预览地址，不修改 CDN 尺寸段制造高清地址。标题标志、图标及独立人物／组织图片没有可靠字段，不以站点 favicon、普通头像或封面裁图填补。

分类默认采用 Genre 和 Tags，资料采集页可选择仅 Genre。标签名称按来源实际文本去重，不自动翻译；不读取全站标签树或将用户的合集名称变成标签。资料语言、字段顺序与匹配仍由本体方案决定。

## 账号与权限

采用官方推荐的授权码流程、S256 PKCE、随机 state 和系统浏览器。Kisaki 公开应用已登记，Client ID 为 d2130481662895284e997a0662dfd21e，无 Client Secret；登记回调为 http://127.0.0.1:49152/itch/callback，实际使用已成功绑定的环回空闲端口，主机与路径保持一致。回调先核对 state，授权码只换取一次，参数不得进入日志或结果页。

连接请求 profile:me、profile:owned、profile:games、profile:collections 四项只读权限。通过 /credentials/info 验证实际权限，再以 /profile 的稳定 user.id 确认本人。密码仅在官网输入；不读取浏览器 Cookie，不接入账号密码登录、个人无限权限 API key、隐式流程或受特批限制的设备授权。

当前文档把合集成员接口标为 collection:view，但实测该 scope 在授权阶段被拒绝；只请求上述四项后，合集元信息正常，成员接口仍返回 403。正式方案不申请 collection:edit 来补足读取，也不把权限失败当作空合集。

OAuth token 不过期，没有 refresh token；再次授权同一应用会复用同一 token 并扩大其权限。凭据只放 secrets，验证失败后停止本人任务并重新连接，不伪造刷新步骤。公开读取客户端与账号客户端分开，公共网页和图片请求不携带授权头。

“断开当前设备”停止当前连接的后续工作、清除本机凭据与私有缓存，保留本地条目和来源记录。由于同一应用的 token 可能被其他安装实例共用，日常断开不自动撤销整份平台授权；账号页提供官网授权管理链接，并明确撤销可能使其他 Kisaki 连接一同失效。本次新应用的测试授权已单独撤销，不改变以上正式交互。

## 拥有库、开发项目与公开合集

| 入口             | 实际含义与读取                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------- |
| 拥有库           | /profile/owned-keys 返回已产生下载许可且仍公开的项目；同一游戏可有多个许可，按 game.id 去重 |
| 可编辑项目       | /profile/games 返回本人上传或可编辑项目，不等于购买库；按实际 Game 分类和用户选择导入       |
| 本人公开合集     | /profile/collections 取得列表、public/private、数量和 URL，再匿名读取所选公开页面           |
| 明确公开合集链接 | 读取实际公开成员；无需借用该合集所有者的账号记录                                            |
| 私密或受限合集   | 说明无法读取，不提取网站登录会话，也不自行扩大授权                                          |

拥有库按实际 page、per_page 继续分页，直到来源明确返回空集合；官方特别说明短页后仍可能有下一页。实测空 owned_keys 和 games 使用空对象 {}，边界只将真正无键的对象解释为已知空，非空对象不能随意 Object.values 成数组。

购买、礼包、赠送、免费领取和收藏是不同事实。未领取的礼包成员、没有产生许可的免费访问、已下架项目等可能不在 owned-keys 中；不声称这是全部付费订单或全部下载历史，也不调用受应用所有者限制的 ownership 接口补齐任意游戏。

公开合集按真实 game_cell 和项目 ID 读取、去重，跟随 Next page。实测最后一页仍显示 Next page，下一页返回 404；仅在已经取得有效前页、下一页属于同一合集、再次核对首页仍正常时，才把这个分页 404 解释为公开列表结束。首页不可读、结构变化、循环页或读取失败都不视为空清单。

本人合集还核对 API games_count；数量不符时报告未完整读取，不把未出现的成员当作删除。其他公开合集只能承诺当前公开可见范围。私密、受限或来源未返回的项目分别报告，不能静默宣称整份合集已经迁入。用户本人的公开合集已匿名读到 20 个不同项目，与 API 数量相同；这一结果只验证项目枚举，不证明它们都是游戏，尚未逐项核验媒介。另一个公开样本已核对 30＋11 项的分页及末尾 404。

枚举结果先按实际项目类型识别，再采用符合本体 Game 范围且被用户选中的对象。game、games_count 和 game_cell 按各自来源含义解释。报告分别统计读取项目、识别出的游戏、实际新增或复用的目标，以及素材包等不支持项目和无法判断的项目。

导入按准确游戏身份调用完整 ingest。新项目采用来源真实元数据；已有项目只复用，不借导入全面刷新资料。本人 API 返回的未公开可编辑项目，可以采用其明确 Game 类型、名称、短简介和实际图片等有限字段；公开详情不可读时，不访问私有页面或伪造缺失信息。

来源没有可采用的个人状态、完成日期、评分、喜爱或游玩时间，因此不提供这些导入开关。拥有、收藏、进入合集或下载次数都不生成游玩记录。可选本地手动合集仅组织本次成员；不创建、改名、排序或删除来源合集，也不持续镜像来源组织。

自动导入默认关闭，默认来源范围只选拥有库，开发项目与公开合集另行明确选择。本地目标合集默认不选。启用后按共同合同在启用、应用恢复及每小时检查当前来源范围，只补缺项、复用已有对象并按所选目标加入成员，不覆盖已有个人资料或因远端变化删除本地内容。

## 页面与运行

账号页提供连接、账号状态、权限核对、重新连接、断开当前设备和官网授权管理。资料采集页提供标签取法与公开连接测试。导入页提供上述实际来源范围、资料方案、可选本地合集、手动执行及独立自动导入；没有同步页或空白个人记录设置。

客户端共用来源请求队列，默认每次至少间隔 1.1 秒，超时 25 秒，安全读取最多重试两次。429 尊重 Retry-After；缺少明确间隔时至少暂停一分钟，不并发换路径规避限流。公开档案与名称查询缓存一小时；私有返回按账号隔离，运行结束释放完整响应，只保留必要设置和执行结果。

私有传输只向 api.itch.io 发送 Bearer；网页、embed、公开 JSON、图片和项目自定义域名走无凭据通道，遵守公共 URL 与资源边界。HTML 结构变化、项目改名、删除、私有化、公开集合不完整及 API errors 信封各自核对。返回中无关的收入、许可或其他私密字段在客户端边界丢弃，不写入资料、Task 历史或日志。

## 验收与预设

来源依据见[公开接口与账号核验](../../../verification/evidence/reference-sources/live-api.md#itch)。验收覆盖非空购买许可、开发项目、完整分页、重复许可、私有项目的有限资料、账号切换、取消和完整 ingest；空账号结果只证明相应分支。

itch.io 作为用户可选的独立游戏来源，提供本页声明的能力与三个页面。固定游戏预设继续采用既定的 Gal 优先来源组合。

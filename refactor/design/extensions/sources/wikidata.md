# Wikidata 接入设计

Wikidata 提供可追溯的结构化事实、真实对象身份与部分内容目录。本文规定类型、粒度、陈述、限定信息及读取范围，采用与本体语义一致的资料。

<a id="scope"></a>

## 职责与入口

| 能力               | 终态方案                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------ |
| 七类 Entry         | 对可准确归类的 Game、Anime、Comic、Novel、Character、Person、Organization 搜索、定位及读取 |
| 资料关系           | 当前作品的角色、适用人员／组织参与及直接作品联系；已明确主体的实际反向履历                 |
| 真实分集与卷       | 明确单季的真实 Episode，以及有准确母体与卷身份的 ComicVolume／NovelVolume                  |
| 其他 Part          | 仅为已明确 refs 的 ComicChapter／AnimeExtra 补充适用字段，不自动生成话、附加内容或卷话收录 |
| 标签               | 作品明确 P136 题材／类型陈述；不把整个分类继承树转成标签                                   |
| 图片与正文         | 不提供图片采集或百科正文；简短 description 用于搜索消歧，不填充剧情或档案长简介            |
| 本人接入与 Webview | 匿名资料扩展，无账号、导入、同步、编辑知识库或独立 Webview 页面                            |

字段、语言、关系选择与来源顺序由本体资料方案管理，不另设一套属性勾选器、用户 SPARQL 编辑器或图谱配置。普通 Wikidata 条目链接沿 externalLinks 提供。

当前官方范围没有独立 Wikimedia Commons 接入，本方案不额外调用其图片检索、许可或文件 API，也不凭 P18／P154 文件名拼出图片原图。图片文件页可以作为明确出处外链保留；结构化数据的 CC0 不替代图片自身许可。

## 身份、类型与粒度

source 使用 wikidata，sourceId 是规范大写 QID，例如 Q98642652。QID 不按标题、语言或请求顺序变化；P 属性、statement GUID、引用哈希和 sitelink 标题不作为 Entry／Part 身份。

官方重定向只有在实际响应明确给出新旧 QID 对应时才形成等价身份；不能用 same label、different from、part of 或版本关系猜等价。更正和合并沿本体身份合同处理，不维护隐藏旧 ID 跳转库。

类型判断依据 P31、P7937 与经过核对的 P279 继承，不根据短描述、名称字符或维基分类页面推断。原生类别映射保持显式，未知类型不通过标签包含“anime”“novel”等词强行归类；先识别分部、版本、整剧及其他不适用范围，虚构角色也不能因“人类”子类误入 Person。互相矛盾的类型报告冲突。

| 来源对象                                                                | 本体范围                                                                |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| video game（如 Q7889）及明确适用子类                                    | Game；平台、游戏系列和制作工具不是游戏作品                              |
| anime film（如 Q20650540）、独立动画作品、anime season（如 Q100269041） | 范围一致的 Anime                                                        |
| anime television series（如 Q63952888）                                 | 整剧上下文，不把多季整体绑定为一个季度                                  |
| manga series、明确漫画作品                                              | Comic；单册与版本另行处理                                               |
| 明确叙事小说、light novel series（如 Q104213567）                       | 范围一致的 Novel；作者作品集、任意书系或跨媒体 franchise 不当作小说母体 |
| human（Q5）                                                             | Person；职业、国籍或性别不是主体类型                                    |
| 真实公司、工作室、出版社、品牌或创作团体                                | Organization，按实际类别与署名区分                                      |
| 明确虚构角色                                                            | Character；虚构组织、场所、机体、舰船、软件声库和现实演员不自动成为角色 |

实测《芙莉莲》的整剧 Q115792176、第一季 Q130377145、漫画 Q98642652、各卷与英语版本分别存在。跨媒体文章、季、单册和译版不能只因标题相近合并；拥有外站编号也不能掩盖已知范围冲突。

既有 Entry 身份、相关 Entry refs 和 Part refs 分别按请求范围读取。Part 不成为独立 search、resolve 或会话根。只补充已知 refs 时可以省略根身份，不能根据一个分部反推出本地作品已经绑定其上层 QID。

## 陈述采用规则

读取完整 statements，保留 snaktype、rank、qualifiers、references 及语言、单位、日期精度等实际结构；不使用会丢失限定信息的 truthy 摘要作为最终资料。

1. 先按目标范围、媒介、人物／组织类别、版本、语言和适用时间筛选。
2. 排除 deprecated；同一语义范围内优先 preferred，再使用 normal。
3. value 才提供具体值；somevalue 表示未知，字段保持缺席。
4. novalue 只对它明确声明的字段及范围表示无值，不能扩大为整类关系为空。
5. 多个同等有效值无法归并或选择时报告冲突，不取第一条凑成单值。

不同语言、出版版本、地区、分部或有效期属于不同范围，不能因一个 preferred 值就抹去另一范围的全部正常陈述。没有属性不表示来源断言“没有”；缺项、查询未命中和被删除陈述不自动清除本地事实。

《刀剑神域》P8731 的 11757 实际为 deprecated，51479 才是正常陈述。引用部分仍可能带有旧编号，不能扫描 references 或外链把已排除的值重新补回来。

qualifiers 中的 P518（适用于部分）、P478（卷号）、P407（语言）、P580／P582（有效期）等直接影响范围，不能只保留主值。未知且可能改变目标含义的限定信息不能静默丢弃。引用用于出处与核对，不自动访问每一个被引用网站。

名称是同一对象的实际名称形式，不使用短描述、页面消歧后缀、查询词或作者名字生成别名。P1477 等出生名不自动成为当前 originalName，转写也不替代原文发表用名。sitelinks 提供百科页面引用，不抓取正文补简介。

日期保留来源 year／month／day 精度。有效 Gregorian 日期才进入相应部分日期；未知月／日不补 1，不按本地时区移日。Julian、超出本体年份范围、存在不能表达的不确定区间或非法组合时说明未采用。组织年份只有 precision=9 时仍保存为年，不因为 time 文本带 01-01 就补出完整日期。

先解释日期的限定范围，再选择该范围的最早明确原始发行；不同卷、译本、再版和平台移植日期不能混为一个最小值。实测《芙莉莲》漫画的多条 P577 都附有卷号与 ISBN，它们不是整作日期；该作品 P580 才记录连载开始。

P364 可提供动画原始语言。漫画／小说的 P407 仅在来源明确描述原作内容对象时采用；译版的 P407 仍是译文语言。游戏的 P407 不能可靠区分原始语言与支持语言，本方案不提供 Game.originalLanguages，不从国家、标题、字幕或演员语种补足。

角色的年龄不从生日与现实时间推算；P3629 表示事件发生时的年龄，不能直接成为当前设定年龄。没有可靠同义字段的 age、bust、waist、hips、cupSize 保持缺席，不从介绍文字解析尺寸。身高、体重不按常见人体尺度裁剪，也不把多个时期或形态的数值取第一条；真实范围、约数与条件以本体允许的文字分支保留。

P136 只生成当前作品明确给出的题材／类型标签。Tag 名称固定优先英文，缺少时依次采用日文、简体、繁体及稳定语言码顺序中的真实 label，不使用 QID 作名称；标签说明可以采用其实际定义性质的短描述。只在当前根陈述已明确对应的 genre QID 上读取，不凭同名任意百科概念补标签，也不保存 Tag 外部身份或父分类。没有明确的敏感／剧透字段时，不提供 isNsfw 或 isSpoiler。

P1113 只是集数，不区分本体的正片与特别篇；P2635 只是部分数量，也不等于已完结作品的总卷数。二者不映射为本体细分声明总量。没有明确发行状态字段时，不从当前日期、缺少后续记录或一条结束时间自行生成 releaseStatus。

## 角色、人员与组织参与

P674 只有在目标确为角色、当前来源确为该作品范围时形成 workCharacters。角色顺序不代表主配角，角色存在也不证明本作使用了某个配音。没有明确角色分类、剧透或说明时不补值。

人员／组织先分类，再按真实职责映射，不因属性名就强制把对象转成人物或公司。

| 来源事实                                | 采用                                                                                                             |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| P50 author、P170 creator                | 适用作品的 creator；P170 指向角色或其他非作品时不能自动散布到所有作品                                            |
| P110 illustrator                        | 小说使用 illustration，漫画正文绘制使用 drawing；明确限定封面／插画时使用 illustration，其他或冲突范围不强行归类 |
| P57 director、P58 screenwriter          | 在本体允许的作品类型下采用 director、scenario                                                                    |
| P178 developer                          | Game 的 Organization.developer；明确个人开发方为 creator，不自动推导 programmer                                  |
| P123 publisher                          | 按真实 Person／Organization 出版责任采用 publisher；实际为独立出版品牌时采用组织 imprint                         |
| P272 production company                 | 使用组织 other 并保留“production company”说明；不按机构名称或常见业务推成 studio／producer                       |
| P86 composer                            | Game／Anime 的 music，note 保留作曲职责；不由音乐相关链接生成作品参与                                            |
| P162 producer、P1431 executive producer | 在本体允许范围中采用人物／组织 producer，并保留具体职责                                                          |
| P98 editor                              | 明确人物的 editor；组织编辑参与使用 other 与实际说明                                                             |
| P287 designer                           | 采用 other 与设计说明，不自动推导角色设计、美术或程序工作                                                        |
| P655 translator                         | 在实际目标原作范围内采用人物 translator／组织 localization，译版工作不升为原作参与                               |
| P750 distributed by                     | 明确组织发行协助采用 distributor，不等同作品创作者                                                               |
| P725 voice actor                        | 只在具体作品、人物、必要角色及原作语种均有明确证据时采用 voiceActor                                              |

P1932 保存当前署名所使用的对象名称，可进入关系 note；P1810 描述的是陈述主体的记录名称，不能混作参与者署名。明确单册或分集参与只有在作品尺度仍准确时才可形成作品参与，并保留实际范围，不宣称覆盖全作。

原作出版与译版、本地化参与保持区别。实测《芙莉莲》的 P123 同时出现日语与英语限定的不同出版品牌，不能全部当作原作出版社；组织自身 P31 及每条参与上的语言和角色都要核对。

P725 的定义包括译配，P161 主要是实演演员，不能相互替代。作品的原始语言不能证明未标语种的每条 P725 都是原配；角色自身的无作品配音记录也不扩散到所有出场作品。实测《芙莉莲》第一季有多条只附角色而没有配音语种的署名，这些条目不能凭演员国籍或姓名进入原配关系。

反向履历使用限定到当前 QID 的 SPARQL 发现候选，再读取完整对象与陈述，核对 rank、限定与粒度。整作、单册和语言版本分别解释；单册参与只有在作品尺度仍准确时才能采用，并保留实际范围说明。来源验证中的混合反查样本用于检验这一分流。

公司隶属、出生地、婚姻、职业、网站用户关系及虚构世界内部组织关系不进入本体没有提供的关系表。

## 作品之间的直接联系

来源能够明确对应本体现有关系类型时，采用具体类型；明确的 P2512 has spin-off 在两端都是适用 Work 时映射为 spinOff，其反向沿共同规则展示为 spinOffOrigin。

P144 的 based on 与反向 P4969 derivative work 表达创作基础，P155／P156 表达来源序列中的相邻顺序。这些都是有明确含义的直接联系，但范围宽于 adaptation、spinOff、sequel。只有陈述限定或明确作品上下文能够唯一证明现有具体类型时才采用该类型；否则采用 related，在 note 中保留“基于”“衍生自／衍生作品”“来源序列中的前一项／后一项”及实际方向。跨媒介、发布时间和共有角色本身不能确定具体类型。

P155／P156 既可能是主陈述，也可能限定 P179；读取限定形式时同时核对该序列范围。保留直接前后项不等于把同一系列的所有成员两两关联。本方案接受 related 与说明承接较宽的语义，不新增通用基于、派生或序列关系类型。属性定义见 [P144](https://www.wikidata.org/wiki/Property:P144)、[P4969](https://www.wikidata.org/wiki/Property:P4969)、[P155](https://www.wikidata.org/wiki/Property:P155)、[P156](https://www.wikidata.org/wiki/Property:P156)和 [P2512](https://www.wikidata.org/wiki/Property:P2512)。

同一来源方向规范化后合并重复事实，保留有用说明；不因多个属性相互指向就创建重复关系。来源未提供相应类型时，不自行补成改编、前传、外传或重制。

P179 的同系列、共同世界观、推荐、同作者及同角色不是两两作品联系。P527／P361 要先判断是否为本体真实 Part；P747／P629 是版本与译本范围，不建成另一作品或笼统的关联作品。相关目标不属于四种 Work，或仍是整剧、系列分组和版本时，说明未采用，不递归扩建图谱。

## 真实内容目录与已知分部

动画季通过自身 P527 与 Episode 的 P4908 反向陈述读取真实分集，逐项核对它确实属于当前季。当前季与原始归属发生矛盾时不能强行归入；只有整剧上下文或声明集数时不生成目录。实测第一季有 28 个独立 QID，每集可以读取自身名称、日期等字段。

漫画／小说卷要求明确的卷类或卷形式、实际卷号 P478，以及与当前作品一致的 P179／P361 范围；通过直接成员或限定反向查询取得。实测《芙莉莲》有 15 个独立内容卷，卷一是 Q139603319，其英语版本 Q139603331 是另一种来源资源，不能再建第二卷。SAO 本次没有返回同样的真实卷对象，不能用声明数量补齐。

edition／translation 只在用户已明确对应的版本范围内补字段；P629／P747 本身不证明任意节选、合订或改写与原作内容完全等价。不能把版本 ISBN、页数、语言和日期复制到全部内容卷，也不自动把每个版本 QID 宣布为同一 Part 的等价身份。

P478 是明确的卷号，可提供 volume.numberLabel。P1545 是序位，默认只用于首次采用的排列，不作为分集、话或卷的印刷编号；不会因当前值恰好是 1、2、3 就混用。已有本地顺序由正常刷新保留。

已知 Episode、Extra、ComicVolume、ComicChapter、NovelVolume refs 可以读取其真实名称、适用原文名／别名、外链、日期及适用时长／页数。没有本体同义依据的字段保持缺席；普通电视分集没有明确 regular／special 分类时保持未知，不默认正片，Extra 也不默认 other。

不提供 workExtras、workChapters、volumeChapters 的自动成员发现。片头曲、主题歌、音乐作品、任意文学章节和一般 has part 关系不证明存在本体所需的动画影像、漫画话及卷话收录。已有明确分部仍可补资料，不扩大为独立 Part 搜索或本体新类型。

| P12561               | SteamGridDB 的真实游戏身份，沿该来源正式语法                                          |

IGDB 的 P5794 实际可为 slug，不能冒充其 API 数字 ID；itch.io 的 P7294 是项目 URL，不能直接变成 game ID。TMDB TV ID 不足以构成单季的完整坐标，NDL Authority ID 也不是 NDL 书目 ID。以上只保留有意义的来源链接，不调用另一来源补齐未知坐标或递归扩展身份。

未知属性与不支持网站的真实链接可以保留为普通出处，但不触发额外网站读取。源数据与引用的原始出处按共同规则区分，多个聚合来源引用同一上游不能算多份独立证据。

<a id="queries"></a>

## 完整读取与运行

名称候选使用 wbsearchentities，沿真实 search-continue 处理；关键词可同时命中乐队、人物、游戏和动画影片，逐项分类后才交给 matching。已知对象使用 EntityData JSON；相关对象可以用官方 wbgetentities 的最多 50 项批量读取。重复请求与当前会话中的实体读取共用缓存。

SPARQL 只使用扩展维护的固定查询模板及已验证的 QID、属性 ID，限定当前根与所请求关系。按稳定键分页，不能以 LIMIT 的第一页作为完整履历或目录；查询结果还要按完整陈述复核。索引滞后、超时、分类未决、目标缺失或必要详情失败时不能返回半份可替换关系，独立普通字段可以保留为 partialResult。

不把 SPARQL 当作模糊名称搜索，不下载全量数据或同步全站变更。无有效陈述时保持来源缺项；它不同于明确的 novalue，更不代表该作品或人物在世界上没有相应事实。

声明可识别的 User-Agent 与项目联系地址。请求默认单队列、至少间隔 1.1 秒，普通读取超时 20 秒，限定查询超时 25 秒；安全读取最多重试两次，尊重 429／Retry-After 与 Action API maxlag。公开实体默认缓存一天，名称和反查缓存一小时，明确刷新绕过缓存；引用修订号与响应来源用于诊断，不建立第二份知识库。

## 源码职责

```text
src/
├── entry.ts
├── client/
│   ├── gateway.ts
│   ├── queries.ts
│   └── types.ts
└── metadata/
    ├── provider.ts
    ├── classification.ts
    ├── statements.ts
    ├── identity.ts
    ├── fields.ts
    ├── relations.ts
    └── parts.ts
```

client 负责官方读取、缓存、分页与固定查询。classification 明确本体类型和粒度，statements 统一解释 rank／snaktype／限定信息，其他映射复用这两个边界。entry 只装配和登记；没有账号、同步、Webview、私有 IPC、知识库编辑或任意属性规则引擎。

<a id="verification"></a>

## 验收与默认预设

来源依据见[接口核验](../../../verification/evidence/reference-sources/live-api.md#wikidata)。验收覆盖多页反查、重定向、未知值、互相冲突的限定、取消、部分失败、真实小说卷与其他已知 Part refs，以及本体实际采用。

默认预设中的名称、别名、适用语言、生平日期和外链按既定来源顺序采用。六份非游戏根预设的关联 Game.originalLanguages 不使用 Wikidata；沿其他有效来源采用，没有其他来源时保持不配置。四类作品的 workRelations.note 在其他有效来源后采用 Wikidata，保留其实际关系含义。

默认预设不将 Wikidata 用于全部人员、图片或分部规则；真实目录与其他字段仍可由用户在自定义方案中选用。字段与粒度依据见[来源核验](../../../verification/evidence/reference-sources/live-api.md)。

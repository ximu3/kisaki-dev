# Kana

`@ximu3/kana` 是独立的浏览器阅读内核，负责源内容解析、定位、排版、导航、选择和呈现。它接收文档资源与实际阅读设置，交付技术结果。

<a id="scope"></a>

## 产品边界

Kana 在自己的仓库维护 TypeScript 源码、pnpm 锁文件、测试、文档、版本与发行，对外发布 @ximu3/kana。公开接口面向浏览器能力，独立于 UI 框架、Electron 和 Kisaki 领域模型。Kana 完整拥有阅读流程与源位置语义，浏览器排版、PDF.js 和解压库承担明确的底层能力。

一个包拥有完整阅读能力，不按固定页面、重排文本或文件格式拆成需要分别配对版本的产品。主入口提供 openReader 和浏览器技术句柄；@ximu3/kana/contracts 提供源位置、选区、几何、设置、状态及错误的纯值合同。纯值入口不依赖 DOM 类型、浏览器全局、worker 或框架，Node 消费方可以独立校验值；HTMLElement、Blob 等环境相关输入留在浏览器入口及所属资源适配中。

两个入口均从同一份真实定义生成声明，不维护另一份手写公开镜像。纯值校验只判断形状和已规定的编码约束，目标节点、成员及字节范围是否实际存在，由已经打开的格式实例判断。模块导入不打开文档、联网或创建 worker。

Kisaki 的 desktop-contracts 定义自身持久合同，Kana 定义阅读技术结果。阅读接入按含义对应双方的字段、单位和寿命，并将所需结果转换为本体存储值；两个合同包保持独立依赖。

<a id="principles"></a>

## 设计原则

Foliate 将格式内容、固定／重排呈现和辅助阅读能力分开，再由一个视图入口组合；分页使用浏览器布局，局部目标可以直接使用 Element 或 Range。它的[模块设计](https://github.com/johnfactotum/foliate-js/blob/78914aef4466eb960965702401634c2cb348e9b1/README.md#overview)可以帮助检查 Kana 的职责和协作是否直接。参考设计、采用某段代码和继承一套公共接口分别判断。

| 取向 | 在 Kana 中的具体含义                                                                              |
| ---- | ------------------------------------------------------------------------------------------------- |
| 干净 | 每个模块直接完成明确职责，公开入口暴露实际能力。                                                  |
| 清晰 | 格式解释源事实，资源提供授权字节，视图处理当前布局，Reader 组合操作与寿命；一个状态只有一个拥有者 |
| 统一 | 所有格式经过同一组阅读操作、设置、选区和完成规则；格式固有的地址和页面差异在所属模块内解释        |
| 原生 | 在整体清晰、一致的前提下使用 DOM、Range、浏览器布局等能力；原生机制不决定职责与交互规则           |

干净、清晰、统一发生在职责、状态和用户行为上，优先级高于原生机制的使用比例。若沿用某个原生行为需要维护两套规则、隐含切换或相互纠正的状态，应选择整体更简单一致的实现；也不能仅为摆脱平台机制而重复实现没有实际收益的能力。

浏览器负责其支持的层叠、排字与布局，Kana 负责完整的格式解释、授权资源、源定位、阅读组织和交互。适配由实际拥有者按明确语义实现。核心目标所需的复杂性纳入实现与维护责任；扩展到另一套系统职责时，先讨论范围及代价。

源事实、当前布局和公开持久值按各自的消费方式与寿命组织。格式可直接使用自己的 DOM 或索引，转换需要来源对应时维护相应映射。视图中的 Range 与几何用于当次呈现，发布前由所属格式转换为稳定源值。

浏览器承担排版，各格式采用 PDF.js、ZIP 解码等专用能力。XML 的完整源解释由格式层保证，跨文档选择由阅读交互协调。各实现共享阅读操作与完成规则，同时保留所属格式的源结构和地址语义。

公开使用围绕一个 Reader，直接提供选择、搜索和标记等完整能力。内部模块共同完成格式解释、排版与源位置对应；同一实例协调异步完成、取消和关闭，并管理本次文档的状态与任务。

目录按实际职责组织。EPUB、MOBI/KF8、PDF 的多文件实现各自成目录；较小实现先保留单文件，需要多份逻辑协作时再拆为模块目录。formats 按格式分类，open.ts 负责识别和创建；view 是协作模块，由 view.ts 管理挂载、可见内容和排版更新。index.ts 只列公开导出。

| 拥有者     | 责任                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| reader     | 本次文档句柄、打开完成、公共操作接续、状态交付、关闭及本实例未完成工作 |
| contracts  | 纯公开值和对应校验，不解释某本书的内容                                 |
| formats    | 格式识别、源内容结构、原生地址解释、文字提取和源到呈现输入的对应       |
| resources  | 授权输入读取、归档成员访问及自身临时字节和资源引用的回收               |
| view       | 固定页面与重排内容呈现、可见范围、内容隔离和显示几何                   |
| navigation | 源目标到可见位置的完整定位、前后移动、有界跳转历史及实际结果确认       |
| selection  | 连续文字选择、匹配原文、页面区域和当前交互选区                         |
| search     | 按源内容搜索、取消、增量结果和必要的临时索引                           |
| marks      | 只读标记投影、当前几何与交互、源顺序和无法恢复的 ID                    |

这些模块通过明确依赖协作组成同一个 reader。格式拥有源事实，视图拥有当前布局，reader 协调当前文档、主位置、操作与寿命；状态保存在实际拥有者处，并由使用者按需取得。

## 桌面浏览器支持范围

Reader 的浏览器支持范围由预期消费者与完整阅读能力决定，具体环境如下。contracts 纯值入口的 Node 消费按其独立合同成立。

支持以下桌面环境：

| 环境      | 范围                                               |
| --------- | -------------------------------------------------- |
| Chromium  | 桌面 Chrome、Edge，以及符合实际版本基线的 Electron |
| Firefox   | 桌面 Firefox                                       |
| WebKitGTK | 使用该端口的 Linux 桌面宿主                        |
| Safari    | macOS Safari                                       |

移动端浏览器不在范围内；桌面触摸输入仍按已有交互要求处理。浏览器按下方滚动版本策略维护，不以某个早期试件版本建立永久下限或推导其他引擎的最低版本。

必要能力检查用于当前操作能否执行，不能代替支持范围的产品决定。受支持环境里的缺口需要解决，不给文档增加隐含降级策略，也不以竖排单面替代已经要求的双面。

<a id="browser-versions"></a>

### 版本维护策略

Kana 当前维护的稳定发行采用已确认的滚动版本范围，支持目标跟随上游正式稳定版本；每次发行另记录实际验证过的精确运行时与系统组合。前者说明维护承诺，后者说明已经取得的证据，不能用“最新版”代替可复现的构建输入或验收结果。

| 环境                  | 已确认的维护范围                                         |
| --------------------- | -------------------------------------------------------- |
| Chrome、Edge、Firefox | 各自常规发行通道的当前稳定版本及其最新稳定更新           |
| macOS Safari          | 当前正式稳定版；按实际 macOS 与 Safari 组合验证          |
| Linux WebKitGTK       | 上游当前稳定系列的最新维护版本；按实际端口与系统组合验证 |
| Electron              | 上游最近三个稳定主版本，各取最新稳定次版本与补丁         |

这意味着不另行承诺 Firefox ESR、Chrome／Edge 的扩展稳定通道、固定旧版 Safari 或发行版长期保留的旧 WebKitGTK。ESR 仍有自己的正常维护用途，不将其称为失效或不安全；[Mozilla 的 ESR 周期](https://support.mozilla.org/en-US/kb/firefox-esr-release-cycle)说明它与常规发行具有不同的功能更新节奏。Kana 的这项取舍只决定自己承担哪些运行环境的完整适配。

Electron 随桌面应用一起发行，由宿主控制升级，与独立浏览器的常规更新方式不同。采用最近三个稳定主版本能给桌面宿主明确且有限的升级窗口，也与 [Electron 自己的维护范围](https://www.electronjs.org/docs/latest/tutorial/electron-timelines#version-support-policy)相符；代价是 Kana 要验证多条 Electron 运行线，不能只测试 Kisaki 当前使用的一条。Kisaki 的具体固定版本和六目标制品仍由[构建方案](../../engineering/build.md)拥有，升级继续经过自己的依赖与制品验证。

WebKitGTK 按[上游发布信息](https://webkitgtk.org/)确定稳定系列，Safari 按当前正式稳定版本维护。独立浏览器接入与 Kisaki 打包环境分别核对，Kisaki 的操作系统下限由本体支持合同确定。

新正式版本进入窗口后，其中的阅读回归属于已承诺范围内的问题；不能以“还没测”将该环境临时排除。实际发布按[运行覆盖与交付](../../../verification/acceptance.md#runtime-coverage)完成测试并记录目标覆盖。Beta、Nightly、Safari Technology Preview 和工具附带的测试构建可以用于提前发现问题，其结果不替代正式端口的实测结果。

版本按公开的维护窗口滚动。改变窗口、移除已支持引擎或增加运行条件，都作为兼容性变化说明。每份历史记录对应其实际验证的版本，后续版本由相应新发行验证；旧 Kana 发行按自己的既定支持范围维护。

所属入口在本地检查操作所需能力，条件具备时执行原请求，缺失时返回明确失败。支持窗口用于确定正式验证与兼容维护范围，范围外环境可以尝试运行。运行判断使用实际能力，保留用户选择的阅读方式。

作者 CSS 片段化按[分页能力边界](layout.md)说明，多投影焦点、辅助技术和其他承诺的阅读能力继续在维护窗口内完成适配与验证。

正式实现与联合消费按[验收场景](../../../verification/scenarios/reading.md#kana)核对。

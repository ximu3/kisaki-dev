## 跨领域集成

| 核对范围                 | 集成验证                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| 本体操作与 SDK 开放      | 实际 UI、Node 调用和后台调用产生相同业务事实；多项事务、取消、并发基线与失效实例                      |
| 当前状态、完成与实际活动 | 三种状态与完成历史独立；分部只存标记；列表、统计和 SDK 同义；使用入口不自动改状态，记录操作不控制运行 |
| 个人记录与来源能力       | 独立创建、更新与清空按真实支持核对；不支持时不补状态、占位记录或配套流程，合法独立操作仍可执行        |
| 公共值与引用             | schema/IPC/SDK/deeplink 的同值解释；支持格式的续读、选择及标记，未知值不静默改义                      |
| 来源读取与参与           | 真实分页、取消/失败与有效部分结果；无来源身份对象、共享关联、回退匹配和强绑定分别验证                 |
| 事件与执行               | 提交后通知、订阅隔离、真实结束原因、保存失败、同次调用收尾及不重放                                    |
| 扩展与应用管理           | 安装/替换中断、重开准备包、信任撤销、宿主重建、激活失败与完整退出                                     |
| UI、外观、语言与资源     | 真实 iframe、焦点/关闭、字体加载与回退、资源范围和引用释放                                            |
| 官方扩展与作者流程       | 各真实来源、账号、备份、仓库外 tarball 消费及独立 .kisx 安装；不借私有本体入口                        |

共同合同需要证明同一事实在真实边界上得到一致解释。声明能够编译，不代表序列化、资源释放或执行完成已经正确。已提交数据、运行状态、历史报告和通知应相互一致，同时保留各自用途，不能合并成一个结果实体。

[自动导入](../design/extensions/synchronization.md#automatic-import)另行核对当前远端清单与本地缺项、完整分页、删除后再次导入及已有记录保留。它与本地到平台的同步分别启用，不依赖曾经导入名单或隐藏排除记录。

<a id="flows"></a>

## 完整用户流程

验证各流程的正常完成及特有协作边界；失败或中断场景按实际风险补充，共同机制复用拥有层的证据，不为每条流程重复构造同一故障。核对范围包括所属资料、视图、执行和资源，不能只检查单个函数返回值。

| 流程                        | 需要一起成立的事实                                                     |
| --------------------------- | ---------------------------------------------------------------------- |
| 手动建立动画并补充角色/人物 | 完整基础/类型、关系与配音、窗口/扩展规则一致、详情刷新                 |
| 导入一批游戏后取消          | 同一任务、每项原子提交、已完成保留、调用等待实际结果                   |
| 离线目录重新上线            | 失联不删除、重新观察恢复可用、手动绑定与位置保留                       |
| 统计页选择作品并打开详情    | 完成次数与作品数区分、未知日期不进入期间统计、场景向下依赖和原筛选保持 |
| 阅读中更新资料              | 正常字段修改可进行，精确位置仍属于当前文件；结构删除被阻止             |
| 关闭任务页与主窗口          | 依设置处理应用关闭，任务不因观察者退出被误判或取消                     |
| 扩展进程失败后恢复          | 旧代注册和回复失效，核心资料可用，依赖任务结果准确                     |
| 备份恢复中失败              | 用户存档有恢复前材料，数据库与字节状态可判定                           |
| 新包发布早于桌面版本        | 更新器忽略其他发布，正确应用渠道与目标资源                             |
| 新库建立与重启使用          | 初始化完整、关闭重开保留正式数据、失败不会伪装成可用空库               |

结合 [A 场景](acceptance.md#scenarios)、目标载体和实际窗口补足环境覆盖。开发运行与正式制品分别记录证据。旧演示或设计上合理，不能代替当前版本已经通过。

# 合集、标签与个人整理

合集用于保存用户组织一组条目的意图，标签用于给条目添加可复用的标记。两者各自拥有身份和资料，分别保存合集成员方式、标签应用属性及各侧人工顺序。

<a id="scope"></a>

## 对象与成员范围

合集和标签都不属于 Entry，也不充当系列母体或分部映射。它们只能收纳或标记七类 Entry。EntryPicker、CollectionPicker 和 TagPicker 分别选择实际对象，可以共用基础选择机制，但必须保留对象语义。搜索和导航使用各自的结果投影，不为联合展示增设 AllEntry 或 LibraryObject。

合集通过同一身份和自身资料管理手动成员或动态规则，标签按名称规则复用。界面使用 EntryRef 引用条目，数据库中的成员与标签应用通过真实外键约束目标。

<a id="collection-fields"></a>

## 合集资料与存储约束

collections 保存以下字段：

| 字段             | 含义与约束                                                              |
| ---------------- | ----------------------------------------------------------------------- |
| id               | 稳定合集 ID，非空主键                                                   |
| name             | 显示名称，非空；允许不同合集重名                                        |
| description      | Markdown 说明，可空                                                     |
| primary_image_id | 用户选择的封面，可空，引用 attachments.id 并限制附件删除                |
| is_nsfw          | 合集自身的敏感内容处理标记，非空，默认 FALSE                            |
| membership_mode  | manual 或 dynamic，非空，默认 manual                                    |
| dynamic_rules    | 共同检索、Entry 规则组与统一字段排序；手动模式为 NULL，动态模式为非空值 |
| sort_order       | 合集在全库合集列表中的位置，非空非负整数，默认 0                        |
| created_at       | 首次实际创建合集时的 UTC 毫秒时间，非空                                 |
| updated_at       | 最近一次实际修改合集资料、成员编排或规则的 UTC 毫秒时间，非空           |

合集名称去除首尾空白后必须非空，允许重名，也允许创建只有名称的空合集。打开编辑器不会提前插入记录。新合集默认采用 manual，成员方式在保存时明确写入，后续只可按规定流程转换。说明全为空白时存 NULL，否则保留 Markdown 中有意义的空白。封面由用户明确选择，不随着动态结果变化。合集自身的敏感标记不传播给成员，各成员仍独立处理可见性。

collection_description_attachments 以 (collection_id, attachment_id) 为主键。删除合集会级联解除正文引用；附件仍被引用时不能删除，并须支持反向查询。正文与图片引用同次提交，封面引用也必须可反查。created_at 在创建后固定。只有合集资料、手动成员、成员备注、成员顺序或规则实际改变时，才更新 updated_at；全库合集重排、动态结果变化和无变化保存都不更新时间。

全库合集列表按 sort_order、id 排列，条目中的所属合集也沿用这个顺序，不为每个条目另存一份合集顺序。索引支持该排列与名称检索。membership_mode 和 dynamic_rules 受成对 CHECK 约束：manual 的规则必须为 NULL，dynamic 的规则必须非空，并通过 JSON 合同校验。

collection_members 使用 (collection_id, entry_id) 联合主键，另存可空 note 和非空、非负的 order_in_collection，顺序默认 0。索引支持合集内排序与 entry_id 反查。collections 提供 (id, membership_mode) 唯一键，成员表使用生成的固定 manual 值组成复合外键，确保只有手动合集能够保存成员行，调用方不维护这个辅助值。Entry 端直接引用 entries；删除任一端只解除成员关联。

<a id="manual"></a>

## 手动成员与模式转换

成员修改与实际存在的排列侧使用[关联及排列合同](library-write-contracts.md#membership)，不能拿可见片段替换正式全集。

手动合集由用户明确加入和移出成员。同一条目在同一合集只出现一次，但可以加入多个合集。成员备注只解释这次收纳的用途，不修改条目简介、关系或个人记录。人工顺序覆盖七类 Entry，允许按体验混合编排。按类型或搜索得到的子集不能覆盖未显示成员；字段排序只改变当前视图，人工整理才修改成员的真实顺序。

从条目执行“创建并加入合集”时，操作同时建立手动合集和成员。作品状态或标签后来变化，不会自动移出成员。移出只解除这一项关联；删除合集不删除成员条目、文件或笔记，删除条目也不删除合集。

`collections.convertToManual(id, { expected: { dynamicRules } })` 返回 void。动态合集转为手动合集时，保留合集 id 和资料，按全库实际资料与关系求值，将正式规则的完整去重结果按统一排序写成成员，成员备注初始为空。转换不采用当前分页、临时搜索、类型页签、Section 上限，以及当前查看的敏感内容和剧透过滤；确认界面必须说明实际会转换的内容。

提交时，同步事务重新核对规则、查询结果和编辑基线，再一起切换模式、清空规则并写入全部成员及顺序。失败时整次回滚。

手动成员不足以反推出动态规则，因此模式转换只提供这一方向。需要动态视角时另建查询规则，原有备注和人工编排继续保留。

<a id="dynamic"></a>

## 动态规则与统一排序

dynamic_rules 保存一份共同检索文字、若干 Entry 规则组和一份字段排序，在整个资料库中求值。每组包含启用状态、非空的类型集合，以及一层“全部”或“任一”条件。启用组的结果取并集，并按 Entry 身份去重。没有启用组时结果为空，因此允许保存空动态合集；某个启用组没有条件且共同检索为空时，匹配它声明类型的全部条目。

规则组按用户需要建立，其顺序只影响编辑呈现。各组独立选择类型和条件，全部启用组的结果合并后统一排序。条件的字段、运算和值须对组内所有类型具有相同含义，排序须适用于类型并集。新规则默认按有效排序名升序排列，再按 id 保持稳定。排序只使用共同可比较的字段；合集人工顺序及跨媒介含义不同的数量不适用于此处。

手动和动态合集都使用混合成员视图。需要独立的类型顺序时，用户应另行浏览或建立 Section。动态规则只保存查询定义，不保存 SQL、脚本或匹配结果，也不会通过后台任务持续同步 collection_members。动态结果没有逐项固定加入、排除、置顶、备注或拖动顺序；需要这些安排时应使用手动模式。移出动态结果不能暗中修改条目的状态、标签或评分。

规则编辑提供草稿预览、保存和取消。未完成的条件继续保留，并指出缺少的内容，不能静默删除条件而扩大结果。语法错误、引用失效和查询失败分别报告，不能伪装成空集合。浏览时覆盖排序不回写规则。具体查询值与 referenceLabels 名称快照见[保存查询合同](library-query-contracts.md#saved-references)，比较语义见[库查询](library-queries.md)。

<a id="rule-references"></a>

## 规则引用与未分类查询

保存规则用执行条件中的稳定 id 和 referenceLabels 中最近一次保存时的简短名称保留目标；实际匹配只依据 id。目标可见时可以展示它的新名称，目标隐藏时则保留已有输入，不披露新资料或隐藏状态。保存或启用规则时验证目标类别和有效性，不按名称创建目标。规则中的查询参数可能在目标删除后失效，JSON 内的 id 不等同于受数据库外键保护的正式关联。

目标改名不改变匹配。目标合并时，由完整合并操作重定向并去重参数，同时保留条件的运算含义。目标删除后，条件保留原参数及必要名称，并返回可解释的无效状态；尤其不能删除否定条件而放宽结果。未启用组允许保留待修正的旧引用，但重新启用前必须修正。规则未修改时，仅修改合集封面或名称不要求重写规则。目标只是隐藏时，查询仍按可见事实计算，不将它视为真实失效。

规则只能引用手动合集。动态合集之间不互相引用，也不能将“未分类”作为条件。需要相同查询视角时，应明确填写实际条件，不建立递归依赖图。

“未分类”表示当前可见 Entry 中，未被任何当前可见合集收纳的条目。手动成员和有效动态规则的匹配结果都计入收纳范围；隐藏合集不计入，隐藏 Entry 也不会借未分类查询出现。独立未分类页和 Explorer 的未分类分组使用同一规则，不持久保存已分类标记。普通搜索和筛选只收窄显示结果，不修改成员或规则。

如果某个可见动态合集的规则无法确定成员范围，未分类查询必须报告判断未完成，不能假定这个合集为空。只有排序失效时，已知成员范围仍然有效；请求失效顺序应明确失败，调用方可以主动选择其他合法字段继续浏览。其他可用分组和全库入口保持可访问。

<a id="tag-fields"></a>

## 标签资料与名称匹配

tags 保存以下字段：

| tags 字段   | 含义与约束                                               |
| ----------- | -------------------------------------------------------- |
| id          | 稳定标签 ID，非空主键                                    |
| name        | 显示名称，非空；保留用户选择的实际写法                   |
| name_key    | 按标签名称规则计算的匹配键，非空且唯一，不由用户单独编辑 |
| description | Markdown 说明，可空，解释标签的含义或使用范围            |
| is_nsfw     | 标签自身的敏感内容处理标记，非空，默认 FALSE             |
| created_at  | 标签首次创建的 UTC 毫秒时间，非空                        |
| updated_at  | 标签名称、说明或敏感标记实际修改的 UTC 毫秒时间，非空    |

标签名称去除首尾空白后必须非空，用户可以独立创建尚未使用的标签。name_key 依次执行 NFKC 规范化、去除首尾空白、将连续空白归为一个空格，以及不依赖界面语言的小写转换。名称与匹配键同次写入，并由数据库唯一约束保证不重复。

PC、pc 和 ＰＣ 复用同一身份；AB 与 A B、C 与 C++ 保持不同。界面保留采用的写法，重复使用标签时保留已有说明和敏感标记。不同含义使用能够区分的名称。

科幻、SF 和 Science Fiction 各自保持身份，合并由用户明确执行。标签采用平面命名，没有命名空间、层级或永久同义词映射；名称只表达标签含义。

description 全为空白时存 NULL，其余 Markdown 内容保留。tag_description_attachments 以 (tag_id, attachment_id) 引用两端，删除标签时级联解除引用，被引用附件限制删除并支持反查。正文和引用必须同次提交。标签没有封面，也没有全库人工顺序；全库查询及索引使用 name、id，并允许查看未使用标签。updated_at 只在名称、说明或敏感标记实际变化时更新，不随标签应用、应用备注或列表重排变化。

<a id="tag-links"></a>

## 标签应用及其可见性

entry_tags 以 (entry_id, tag_id) 为联合主键，两端均使用直接外键。删除任一端只解除应用，不额外保存端点类型、另一份 id 或时间戳。应用本身保存以下资料：

| 关联资料       | 含义与约束                                                 |
| -------------- | ---------------------------------------------------------- |
| note           | 此标签在这个条目中的简短纯文本说明，可空                   |
| is_spoiler     | 暴露这项关联是否涉及剧透，非空，默认 FALSE                 |
| order_in_entry | 标签在这个条目的标签列表中的位置，非空非负整数，默认 0     |
| order_in_tag   | 条目在这个标签的关联条目列表中的位置，非空非负整数，默认 0 |

索引分别为 (entry_id, order_in_entry, tag_id) 和 (tag_id, order_in_tag, entry_id)。新应用追加到列表末尾，重排只修改当前侧，并在核对完整关联和顺序基线后同次提交。类型筛选或搜索子集不能替代完整列表。note 只说明这次应用，不改公共标签说明，也不承担独立笔记或带图片的正文。

tags.is_nsfw 控制标签自身的敏感内容处理，不传播给关联条目。entry_tags.is_spoiler 则控制某项具体应用的剧透保护。隐藏应用时，名称、备注和反向列表都必须遵守同一可见范围，不能只遮住备注；其他公开事实仍可展示。隐藏不会删除关联，编辑器也不能把没有显示的应用解释为用户要求解除。可见性和筛选规则详见[库查询](library-queries.md)。

<a id="tag-operations"></a>

## 标签的创建、修改与整理

条目编辑器按 name_key 在全库查重，范围包括选择器中被隐藏的标签。命中已有标签时复用它，并说明实际状态，不创建重复身份。快速新建的标签先属于外层编辑草稿，保存时才解析名称、创建标签并建立应用，取消不残留记录。独立创建则允许保存未使用标签。提交时再次处理并发创建；单纯使用同名标签不修改公共资料。独立创建或重命名遇到冲突时保留输入，不能隐式合并。

应用的新增、解除、备注、剧透标记和顺序按实际改动一起提交。已有组合键原位更新，不全删重建。并发检查针对实际相关字段，不锁住整个 Entry。来源名称仅用于匹配标签和处理已授权应用范围，不能覆盖标签定义或未经授权的应用属性；来源缺席、结果不完整和请求失败也不能清空已有应用。

解除最后一项应用后，标签仍然存在。清理未使用标签必须是另一项明确操作。删除标签会删除标签自身、正文引用和所有应用，不删除条目文件或私人记录。确认摘要说明影响，不逐条预览；引用该标签的规则保留失效参数，不放宽筛选。

标签合并由用户选择保留身份，按下节固定规则整合资料、应用与查询引用。重复应用的备注、剧透和两侧顺序分别有确定取值，不在执行中等待逐字段选择。

<a id="merges"></a>

## 合集与标签的明确合并

library.collections.merge 与 library.tags.merge 各自接收 `{ sourceIds, targetId }`，返回 `{ targetId, removedIds }`。sourceIds 是有序、非空且无重复的实际 ID 数组，不含 targetId；removedIds 按成功处理的 sourceIds 顺序返回。两种操作均不接受 expected：目标由输入固定，取值按提交时的当前事实确定，不把旧查询结果或整份详情当作条件。

合集只直接合并 manual 模式。任一参与合集为 dynamic 时返回 UnsupportedMembershipMode；界面提供已有的“转为手动合集”入口，用户明确转换后再发起合并。转换与合并是两次各自完整的操作，后一步失败不回滚前一步已经成立的转换。

| 内容                       | 固定取值                                                                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 合集或标签的身份与普通资料 | 保留目标 ID、名称、敏感标记及创建时间；目标说明为空时，按 sourceIds 顺序采用第一份非空说明。合集封面同样只补空，全库排列保留目标位置。 |
| 正文附件                   | 只维护最终采用正文和封面的真实引用；未采用来源正文的附件不挂到目标，解除的引用按正常回收处理。                                         |
| 手动合集成员               | 保留目标现有成员和排列；源独有成员按 sourceIds 顺序、各源原成员顺序追加。重复成员只保留一个组合键。                                    |
| 成员或标签应用备注         | 相同的规范文本保留一份；不同非空值按目标、各源顺序以空行分段保留。空值不覆盖非空值，不按相似文字去重。                                 |
| 标签应用的剧透标记         | 任一参与应用为 true，则合并后的应用为 true；后续明确编辑可以调整。                                                                     |
| 标签在条目内的排列         | 条目原有目标标签时保留其位置；没有时占用该条目中最靠前的源标签位置。其他标签的相对顺序保持。                                           |
| 条目在目标标签内的排列     | 保留目标原有条目顺序；新条目按 sourceIds 顺序、各源的 order_in_tag 顺序追加，重复条目不移动。                                          |
| 保存查询及其他正式引用     | 源 ID 改为目标 ID，按所属参数的集合语义去重并保留运算含义；展示柜、动态规则及相关读取共同采用实际提交。                                |

备注的比较使用各字段已经规定的规范值，正文和纯文本不相互转换。合集成员变更按现有规则更新目标 updated_at；标签只有公共资料实际改变时才更新自身 updated_at，应用变化不充当标签资料编辑。源行删除不改 Entry、私人记录、文件或其他合集和标签。

整个合并在同一短同步事务中检查全部参与对象、模式、关联及正式引用，完成取值、迁移、删除和必要的顺序调整。输入结构或重复 ID 非法为 InvalidInput，任一对象缺失为 NotFound，模式不符为 UnsupportedMembershipMode，无法满足的引用或唯一约束为 Conflict。失败完整回滚；提交前取消不写入，提交后的迟到取消不撤销结果。资料整理不因成员作品正在使用而被阻止。

成功分别发布 collectionsMerged 或 tagsMerged，sourceIds 与 targetId 来自实际提交；相关成员、应用与查询按所属变化失效。删除事件不能替代合并事件。界面简要说明保留目标、资料补空、备注及排列规则，执行后打开保留对象；资料改名或正文编辑继续使用普通编辑器。

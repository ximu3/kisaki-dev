# NDL Search、itch.io 与 Wikidata 核验

核验日期：2026-10-17。本组记录 59 次公开请求，另行核验 itch.io 应用登记、本人只读授权、账号范围和公开合集；完整方案与默认预设调整已获确认。来源请求成功不代替完整扩展、页面和本体采用的实现验收。

证据见[公开接口摘要](2026-10-17-public-api.json)与[本人读取及清理摘要](2026-10-17-itch-personal.json)。两份记录均不含访问令牌、密码、账号编号或私人正文；应用 Client ID 是公开标识。

<a id="ndl"></a>

## NDL Search

采用[当前接口规格](https://ndlsearch.ndl.go.jp/help/api/specifications)所列的日文 1.5 版（2026-09-25）及 [DC-NDL RDF 3.0](https://ndlsearch.ndl.go.jp/renkei/dcndl/version3)。官网说明英文规格仍属于旧系统，不能直接作为当前实现合同。

| 核对项          | 实际结果与含义                                                                                                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| SAO 第一卷 ISBN | OpenSearch 返回两个机构的记录，分别描述“アインクラッド”和“ソードアート・オンライン 1”；范围与日期表现不同                       |
| 限定 NDL 藏书   | SRU 使用 iss-ndl-opac 后返回 R100000002-I000010078222，页数 352p、出版文字日期 2009.4                                           |
| 完整 itemno     | 可直接重新读取，机构前缀和前导零不能删除                                                                                        |
| 版本与 XML      | 请求 dcndl_v3，内部为实际 RDF；外层 recordSchema 仍可写通用 dc-v1.1 URI                                                         |
| 日期            | 结构化 issued 只有 2009，date 有 2009.4，RSS pubDate 则是 2026 年更新，三者不能混用                                             |
| 原作单行本      | 《小説君の名は。》对应独立书目，262p、2016.6；“没有卷号”本身仍不是自动判断独立作品的充分条件                                    |
| 名称与分页      | “よつばと”查询有 31 个结果，前两页 next 为 3、5，包含研究书、名言集和育儿书                                                     |
| HTTP 200 诊断   | 未返回正常书目时可以出现 SRU diagnostics，不能只看 HTTP 状态                                                                    |
| 暂时失败        | 单行本请求有一次 25 秒超时，随后一次重试成功；扩大漫画题名查询到 100 条时另有一次超时，没有把它当作完整结果或据此判定平台不可用 |

加入作者条件后的题名查询仍返回照片集与未标页数绘本，进一步说明共享名称／作者不是卷目录依据。

本次另读取了书目明确指向的 Web NDL Authorities 档案。它可以提供独立的 Person 类型、原始姓名与转写，说明权威引用确实有身份价值；但这是另一套独立服务，本组 NDL Search 方案没有因此自动增加人物搜索、人物档案或作品履历。

[数据提供机构清单](https://ndlsearch.ndl.go.jp/help/api/provider)明确区分各机构许可；NDL 自有藏书按其 CC BY 条件提供，不把这一许可扩大到其他聚合来源。当前 SRU 最多读取前 500 条，大范围搜索不能当完整卷目录。

书影 API 已于 **2026-03-31 停止**，官方在[次日公告](https://ndlsearch.ndl.go.jp/news/20260401_thumbnail)确认。旧规格仍可被搜索引擎找到，本方案不采用旧缩略图接口，也不通过网页继续获取同一已停止对外提供的书影。

## itch.io

[当前 OAuth 文档](https://itch.io/docs/api/oauth)支持授权码、S256 PKCE 和动态环回端口，无 Client Secret。token 不过期、没有 refresh token；同一账号再次授权同一应用会复用 token 并扩大权限，撤销对该应用授权的影响需要与单设备断开区别。

用户先说明已有账号及游戏，随后明确允许登记应用并读取本人身份、拥有游戏、可编辑项目及合集。已创建 Kisaki 应用，官网登记页显示 Client ID，实际四项权限与官网授权页一致。

| 本人核验                              | 结果                                                                    |
| ------------------------------------- | ----------------------------------------------------------------------- |
| token 交换、profile、credentials/info | 均为 200，取得稳定身份，权限严格为四项只读 profile scope                |
| collection:view                       | 授权页拒绝 invalid scope，没有取得该次令牌                              |
| owned-keys 两页                       | 均为 200，空集合实际编码为 {}，不是 []                                  |
| profile/games                         | 200，空 games 同样为 {}                                                 |
| 本人合集元信息                        | 200，一个公开合集，声明 20 个项目                                       |
| 本人合集详情                          | 200                                                                     |
| 合集成员 API                          | 四项只读权限下为 403，不能当作空合集                                    |
| 同账号再次核对                        | 200，仍为同一账号                                                       |
| 撤销与清理                            | revoke 返回 200，两次临时接收器均不再响应，访问凭据及完整私人响应已释放 |

“拥有游戏”接口为空与用户已有游戏并不矛盾：该接口列出已产生下载许可的已公开项目，合集则是另一种组织方式。没有请求合集写入或下载权限，用户记录写入次数为 0。

本人公开合集通过真实公开链接匿名读取，取得 20 个不同项目，与 API 数量一致；没有向公开页发送授权头。这仅确认项目枚举，没有逐项确认媒介，不能称为 20 个游戏；素材包不在已确认导入范围内。账号主页没有显示该合集链接，说明不能用主页代替完整本人合集目录。登记页保留供用户查看，测试授权已撤销，应用登记仍保留。

公开资料已验证：

- 《DDLC》项目页、官方 /data.json、真实搜索表单及搜索结果都可读取。
- 官方 embed/106599 返回当前项目地址，因此数字 ID 可独立重新定位，不需隐藏的 URL 对照表。
- 公开 JSON 有项目名、实际标签、作者账号链接、主图与截图，但没有可靠的原始语言、原作首次发行或本人评价字段。
- 原始主图 GET 为 GIF89a，315×250；页面也提供截图原图地址，不需要修改 CDN 路径。
- 另一公开合集读取 30＋11 个不同项目。最后一页仍给出 Next page，后继页为 404，而首页保持可读；这与“看到 Next 就永远继续”或“任何 404 都是空合集”都不同。
- 分类页首个请求曾返回 429；停止该路径后，后续正常间隔的公开项目、搜索、embed 与合集读取成功，不据此对整个平台作永久定性。

公开资料与本人清单分别沿[官方服务端合同](https://itch.io/docs/api/serverside)、[公开 JavaScript API](https://itch.io/docs/api/javascript)和[widget](https://itch.io/docs/creators/widget)解释。官方脚本仅用于核对公开 URL 规则，没有执行其购买功能。

## Wikidata

实际读取 EntityData JSON、名称搜索、批量实体、属性定义及限定反向 SPARQL。采用渠道与速率规则依据[官方数据访问说明](https://www.wikidata.org/wiki/Wikidata:Data_access)。

| 核对项     | 实际结果与含义                                                                        |
| ---------- | ------------------------------------------------------------------------------------- |
| 同名搜索   | Clannad 同时命中乐队、游戏、人物和动画影片；名称不是本体类型                          |
| 动画范围   | 《芙莉莲》整剧、第一／二／三季分别有 QID；第一季具有 28 个实际 Episode 引用           |
| 分集归属   | 已读分集自身有明确季引用、名称和日期；原作与英语播出日通过语言限定区分                |
| 漫画单册   | 反向查询得到 15 个内容卷；卷一与其英语版本是两个不同资源                              |
| 小说目录   | SAO 本次未返回同样的实际卷对象，不能根据卷总量补建                                    |
| 人物履历   | 作者反查 31 项，包含整作、单册及译版，不能全当独立作品                                |
| 废弃标识   | SAO 的 AniList 11757 已标为 deprecated，正常编号是 51479                              |
| 逐卷日期   | 《芙莉莲》漫画的多条 P577 附有卷号与 ISBN，不能混成整作发行日期                       |
| 出版品牌   | 出版项同时有原作与英语语种限定，且主体实际为出版品牌                                  |
| 年份精度   | 京都动画成立时间是 precision=9 的 1981 年，不应保存为 1981-01-01                      |
| 配音语种   | 第一季 40 条配音陈述均没有 P407 语种限定，角色姓名和原作语言不能代替原配证明          |
| 角色与软件 | 初音未来角色 Q552682 与声库 Q112748598 分开，原生类型不同；身高和体重只出现在角色对象 |
| 编号含义   | P1545 是父序列中的位置，P478 才是明确卷号；不能把通用序位当全部分部编号               |
| 跨站类型   | IGDB 属性样本为 slug，itch.io 属性是 URL，NDL Authority ID 不是书目 ID                |

属性定义支持进一步的明确约束：P144 和 P4969 比“改编”更宽，P155／P156 比叙事前后作更宽；P747／P629 描述版本。P725 包含译配，P161 的实演演员不能冒充声优；P1932 才是对象在来源中的署名，P1810 描述主体名称。P1113 未区分正片与特别篇，P1104 则明确属于某个出版版本的页数。

这些都已进入[完整方案](../../../design/extensions/sources/wikidata.md)，没有把开放属性表直接当成本体字段或新增任意关系类型。

## 实现验收边界

本轮没有实现三个正式扩展。后续仍需验证实际安装、声明能力、资料方案调用、所有字段的缺席／空值、源结构变化、完整分页、取消、停用、并发、本体采用及 UI。itch.io 的真实非空购买许可与开发项目、Wikidata 的其他小说卷及已知 Part 场景仍需补样本；私密合集不属于拟提供范围，不能写成延期接入。

本轮核验结束时，默认预设尚未采用这组三项的具体调整；当时 MangaUpdates 已确认并完成采用，总计 14 项方案已确认、19 项尚未定稿。这是当次进度记录，后续规则与状态分别见[官方目录](../../../design/extensions/catalog.md)和[实施状态](../../../implementation/status.md)。

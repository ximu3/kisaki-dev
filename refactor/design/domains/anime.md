# 动画、分集与播放资料

Anime 表示一部独立管理的动画作品，Episode 表示正式分集，Extra 表示附加内容，AnimeFile 表示实际视频文件。资料分类、文件位置、个人完成记录和播放会话分别维护。

<a id="model"></a>

## 作品范围与直接引用

独立季、剧场版或 OVA 可以各自编目为 Anime，同系列作品通过关系和合集组织。接入来源时须核对整剧、某季及实际分集的范围，确保采用的身份与编目范围一致；只修改标题不能将整剧身份变成某季身份。

| 表                  | 关键列与含义                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------ |
| animes              | entry_id 为主键，引用 entries.id，沿用七类 Entry 的具体类型约束                                              |
| anime_directories   | id；anime_id 引用 animes.entry_id；按[内容目录合同](holdings.md#directories)保存发现范围、过滤及识别方案引用 |
| anime_episodes      | id；anime_id 引用 animes.entry_id；一个真实分集及其资料                                                      |
| anime_extras        | id；anime_id 引用 animes.entry_id；一项附加内容及其资料                                                      |
| anime_files         | id；anime_id 引用 animes.entry_id；视频访问、观察事实及文件内当前位置                                        |
| anime_file_episodes | (file_id, episode_id) 联合主键，分别引用文件与分集                                                           |
| anime_file_extras   | (file_id, extra_id) 联合主键，分别引用文件与附加内容                                                         |

文件始终直接属于作品。文件与分集、文件与附加内容的关联都没有独立 ID。同一分部可以关联多个文件，合订文件也可以关联多个分部。完整操作在同步事务中核对两端属于同一作品，组合键防止重复。外键只证明对象存在，不证明文件内时间范围或覆盖完整性。Episode 与 Extra 共用视频技术模型，字幕和字体不属于 Extra 或 Attachment。

anime_files 保存[关联方式](holdings.md#association-mode)。自动匹配只采用 automatic 模式下的空关联；用户编辑或清空关联后使用 manual，刷新与重启均保留该选择。

正式特别篇属于 Episode；PV、片头、片尾和访谈等附加内容属于 Extra。需要独立收藏和评价的特别篇作品，也可以另建 Anime。首次资料采用可以使用已明确的来源分类约定，例如 [Bangumi 的 SP 对应](../extensions/sources/bangumi.md#parts)；来源分类与实际内容不同时，通过普通种类更正处理。文件名中的 SP、短时长和零号季等宽泛线索不能直接决定对象类型。文件命名识别只形成查找已有分部的条件，不创建分部或改写其种类；明确内容标记的处理见[内置识别](file-recognition.md#builtin-anime-content)。Extra 是逻辑对象，可以没有文件，也可以有多个文件，不表示应用保存的字节。

没有真实分集的影片直接使用 Anime 与 AnimeFile，不补造“第 1 集”“正文”或人为总集数。零分集也可能只是资料未知，不能据此判断作品是电影。

同一集的 TV、BD、不同字幕组或发布修订文件可以共存于同一内容目录，也可以分布在不同目录。多份实际文件分别保存稳定身份和播放位置，并关联同一 Episode；新增文件不替换已有文件，也不自动改变首选。目录不对每集设置文件数量限制，不需要为每份文件建立另一条分集资料。

包含多集的视频使用一份文件位置，通过文件章节和时间轴导航。当前模型只将文件关联到分集；文件内部的逐集时间范围、进度和完成需要另有准确内容边界，不能从声明时长推算。

## 作品详情与播放器的内容列表

作品详情的内容 tab 与播放器都以当前 Anime 为完整范围，提供“资料”和“文件”两种查看方式，共用资料、文件身份和相应查询顺序。播放器中的列表不另建身份，也不保存一份从详情页复制的播放清单。

| 查看方式 | 内容与顺序                                                                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 资料     | 分集与附加内容分别展示，沿用各自在作品中的 sort_order、id 顺序；分集显示正片、特别篇和未知分类。个人记录与文件选择位于对应资料项，同一项的多个版本不拆成多个分集 |
| 文件     | 展示当前作品的全部实际视频文件，包括未关联、单集、多集、附加内容、不同版本和失联记录；默认按规范路径的自然数字顺序、id 排列，每个文件只出现一次                  |

两种视图都提供适用的筛选控件：资料可按内容分类、完成状态筛选，文件可按目录、关联情况和已保存的可用性筛选。筛选只帮助查找当前视图中的项目，不生成新的播放范围，不改变作品的正式顺序或隐藏项目的归属；清除后恢复完整视图。详情页与播放器各自持有视图和筛选状态，不互相驱动。

从详情页主按钮、某一集或某个文件开始播放，只决定实际打开目标。播放器仍能浏览当前作品的全部资料与文件，不接收详情页的筛选结果作为播放清单。新播放器有分集时默认显示资料，没有分集时默认显示文件；用户可以自由切换，后续资料补充不抢先改变其选择。切换查看方式或筛选不立即切换视频，也不修改首选、续播位置或计时。

没有分集的作品可以直接播放，不补造占位集。Extra 在资料视图中有独立区域，不接在分集末尾自动播放。后来补充资料只增加已经确认的关联，保留文件和位置；全部文件也不能被当作正式分集。

## 作品描述与内容分类

TV、剧场版、OVA 和 ONA 等作品描述使用普通标签，不增加 AnimeFormat、AnimeCategory、固定类别表或隐藏副本。标签没有保留名称或 ID，也不驱动播放、分集创建或文件绑定。缺少标签不默认表示 TV。

来源自己的分类仍用于识别范围和选择候选。不能因为本体没有对应枚举，就忽略电影、整剧、季和分集之间的区别。

anime_episodes.type 使用 regular、special 或 NULL，用于分组、筛选与统计。未知分类仍出现在全部分集内，不默认作为正片。更正分类时保留 ID、编号、顺序、文件关联、首选和记录，不切换正在播放的文件。

anime_extras.type 使用以下值，未知时为 NULL：

| 值        | 含义                     | 名称可以保留的具体称呼 |
| --------- | ------------------------ | ---------------------- |
| opening   | 片头影像                 | OP 1、NCOP 2           |
| ending    | 片尾影像                 | ED、NCED、特别 ED      |
| promotion | 宣传、预告与广告影像     | PV、CM、Teaser         |
| interview | 访谈                     | 制作访谈、声优访谈     |
| other     | 已知不属于上述类别的内容 | 制作花絮等实际名称     |

附加内容的分类不控制完成阈值、连播或删除，也不以枚举顺序覆盖人工排列。PV 和 trailer 统一归为 promotion，具体称呼保留在名称中。NCOP 和 NCED 分别属于 opening 与 ending，不另设 creditless，也不根据字幕是否开启推断版本。

已经确认是同一项内容的多个文件可以共用一个 Extra，但各自续播。类别相同或名称近似不足以确认内容身份。Extra 保持附加内容的分部身份，使用自身的分类字段。

来源未回答分类时保留已有值，无法判断时保持未知；other 只用于明确知道属于其他内容的情况。界面分别展示名称、编号、类别和状态，每项独立成列，不在名称下堆叠次要字段。

## 编号、顺序与来源映射

| 字段         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| number_label | 当前采用的实际分集编号，可空文本，例如 0、1、12.5、SP1、前篇 |
| sort_order   | 当前作品分集列表中的排列位置，非负整数                       |

分集使用独立 ID 标识，编号与分类用于描述和检索。同号分集和无编号分集都合法，(anime_id, type, number_label) 不设唯一约束。sort_order、id 形成作品当前的一套顺序，分类视图取其中相应子集。

首次导入可以采用明确来源顺序，普通刷新保留已有顺序；新项没有明确位置时追加，只有明确重排才改变排列。改号不改序，改序也不重新编号。

Extra 在所属作品内独立排列，没有结构化 number_label。“NCOP 2”“第二弹 PV”等内容保留完整名称，同名也不要求唯一。改名、排序和分类变化都保留对象与私人记录。

Episode 与 Extra 使用各自的外部身份表，通过父 Entry 的 parts 范围读取。需要父范围的来源 ID 已包含完整、规范的范围，不另加 locator。Profile 负责来源之间的对应，ingest 核对本地对象。完整身份优先；其他启用的范围、分类、编号和名称依据，只有得到唯一且明确的对应后才可用于复用，同号不自动合并。

未匹配本身不能证明应该新建。已确认属于当前作品、本地尚无对应的真实分部，只能在本次明确新增或补充分部清单的范围内由 ingest 创建。归属、身份或对应存在歧义时报告问题，文件识别仍只绑定已有分部，详见[本地采用](metadata.md#adoption)。

Bangumi 的 sort 与 ep 按具体类型的实际含义映射。非本篇 ep 不能通用解释，名为 sort 的字段也不直接等于本地序位。不能按数值去重或丢弃未编号项。OP、ED 和宣传内容返回适用的 Extra 及其真实身份。

TMDB 不接入剧集组，TV 只作为季查询上下文。作品只对应适用影片或范围一致的标准季；来源标准季跨越多个实际季度时，不自动拆分或绑定到其中一季。已明确身份及本地归属的分集仍可直接读取字段，无须作品具有同源根身份，详见[TMDB 接入范围](../extensions/sources/tmdb.md#scope)。

TMDB 分集保留标准季集路径对应的身份。来源季号、集号与本地排列分别表达，数组位置不能补成正式集号，也不据此把所有内容改为正片。清单与已有分部字段的更新分别遵守[采用范围](metadata.md#update)。

来源不完整、没有回答或读取失败时，保留已有对象、关系和私人记录。最后编号为 12 不证明共有十二集，12.5 也不是可以截断的数量。来源记录“已看十集”不能映射为列表前十项，逐集状态必须先明确目标。

## 内容种类更正

用户可以在现有内容编辑中，将误归类的 Episode 更正为 Extra，或反向更正。这项能力用于纠正同一作品内的同一项内容，保留原 ID、创建时间、共同资料、来源身份、附件引用、文件关联及其首选、个人完成标记。更正同时更新资料修改时间，不要求用户删除后重建并逐项恢复。来源刷新不自动执行种类更正。

表单只显示当前所选种类的适用字段，使用普通保存和关闭规则。切换种类不清空本次草稿中已经填写的专属值，保存前切回时继续编辑；界面不增加旧编号展示、额外说明或转换确认。提交只采用目标种类的字段，未采用的草稿值随编辑结束释放。

Episode 转为 Extra 后不保存 number_label，也不将编号自动拼入名称、别名或说明。Extra 转为 Episode 时，没有本次草稿值的编号初始为空。目标分类使用该种类的合法值，没有本次草稿值时初始为 NULL；原种类的分类不自动映射到目标分类。更正后的内容追加到目标种类列表末尾，其他项目的相对顺序不变，后续可以正常重排。

明确指向该内容的已有观看记录自动随之更正分类，保留记录身份、实际时间、时长和文件。作品总观看时长不变，分类统计按更正后的归属计算，不提供是否迁移历史的选项。分部完成标记原样保留，不生成作品完成记录。文件身份、位置、设置和标注保持；仅文件范围或其他内容的活动不因共享文件而改变归属。

library.parts.changeKind(ref, input) 完成这次更正，返回新种类的 PartRef。ref 只接受 animeEpisode 或 animeExtra；input.target 明确另一种类及其专属字段，input.changes 只提交本次共同资料的修改，expected 沿用相关字段基线。目标为 animeEpisode 时，target 包含 kind、type 和可空 numberLabel；目标为 animeExtra 时只包含 kind 和 type。kind 使用对应的 PartRef 类型值，type 使用目标种类的分类值。操作不接受另一份目标 ID 或更换所属作品。

共同资料采用本次明确修改，其余保留提交时的当前值。源种类、归属、实际修改或移除的字段、目标身份约束与使用占用在同一次短事务中核对，资料和所有相关引用、记录一起迁移；失败时整次不提交。原生界面与扩展调用同一操作，不通过串行删除、创建或先更正再补存资料完成。

成功提交后，library.changed 使用 partKindChanged 表达原引用、新引用及所属作品，并使受影响的分部、文件和活动读取失效。旧种类的引用不再有效，调用方采用返回的新引用。作品详情与播放器正常刷新资料列表；已经发出并仍使用旧引用的播放请求按目标变化处理，不静默转向新种类或跳过目标。

## 当前个人记录与播放事实

| 表                    | 主键与引用                               | 当前记录                                             |
| --------------------- | ---------------------------------------- | ---------------------------------------------------- |
| anime_records         | anime_id，主键并引用 animes.entry_id     | 三种作品当前状态或 null，以及 additional_duration_ms |
| anime_episode_records | episode_id，主键并引用 anime_episodes.id | is_completed 布尔标记                                |
| anime_extra_records   | extra_id，主键并引用 anime_extras.id     | is_completed 布尔标记                                |

三张当前记录表均为可选的一对一附属记录，以所属对象的 ID 为键。分部记录只保存当前完成标记；作品的逐次完成历史保存在[work_completion_records](records.md#schema)，评价属于 Entry。

作品附加观看时长使用非负安全整数毫秒，缺行按 0 读取；与实际活动合成累计时长，编辑和来源采用遵守[共同附加时长合同](records.md#duration)。分集与 Extra 不增加附加时长字段，没有日期的附加值不分摊到分部或期间统计。

作品完成与分部已看分别遵守[共同记录操作](records.md#operations)和[分部边界](records.md#parts)。没有分集的影片也由用户明确记录作品完成，附加内容不构成完成前提。来源单集记录采用到对应分部，播放中的自动标记则按下一节处理；实际活动沿[会话规则](sessions.md#personal-status)保存。

每个视频文件保存一份以秒表示的位置，不另存位置内容修订。合订视频通过文件章节使用，活动只记一次。动画播放活动保留发生时的作品；自动记录时，文件唯一关联一个 Episode 或 Extra 才明确归属该分部，关联多项或没有关联时只记文件范围，不按点击入口推断唯一分部。普通解绑或文件关联调整不改变历史归属，也不能把同一段时长复制到三个分集；对同一内容执行[种类更正](#kind-correction)时，其已有记录的分类随之修正。有效时长与生命周期见 [使用会话](sessions.md)，手动补录和修正见[活动编辑](library-operations.md#activities)。

正片、特别篇和 Extra 的计数按明示范围查询。例如，可以分别显示分集 10/12、附加内容 3/5；合计 13/17 只能称为全部已登记内容，不能称为正片进度。声明集数不作为混合范围的分母，个人记录也不从文件覆盖持续重算。

删除分部时，移除该分部的完成标记和文件关系，保留视频文件与应留活动。删除文件记录时，移除关联、首选和位置，保留作品完成历史、分部标记，以及标注和活动所需的发生时上下文。文件失联不触发删除。明确删除作品时，按完整删除合同处理其从属记录，确认摘要说明影响，不展示逐层记录预览，也不删除用户媒体文件。

<a id="auto-completion"></a>

## 本次播放的自动已看

autoMarkWatched 默认启用，只标记当前文件直接关联的 Episode 和 Extra，不标记作品完成。整份文件在本次播放中的实际覆盖达到 90% 时，将这些分部通过普通“标记已看”操作统一采用。一份视频关联第 1、2 集时，可以将两集一并标为已看；没有任何分部关联时，只保存实际位置和观看活动，不建立占位分部，也不改为标记作品。

目标来自实际文件的完整正式关联，从主按钮、某一集、文件列表或深链打开都使用同一规则，与播放器的资料／文件视图和筛选无关。sessions 在文件打开时取得这些关联，使用占用按[文件修改边界](file-maintenance.md#file-use)保护它们；同一文件的普通复用不更换目标或重新累计覆盖，切换实际文件后采用新文件的关联。不增加供调用方另行指定的完成目标或持久播放清单。

自动已看依据整文件观看判断，为关联分部设置可由用户更正的标记。它描述此次文件观看所推定的完成，不测量每个分部的覆盖率或认证片源完整性。一次触发涉及的分部标记在同一完整操作中提交；活动时长和播放次数仍按实际文件会话记录。

覆盖只在一次实际文件打开到关闭或切换的上下文内累计。暂停后继续仍属于同次播放，重新打开则重新计算。只合并已经确认的连续播放区间，跳转空隙、暂停和缓冲不计入，重复片段不重复累计，也不保存跨次覆盖账本。分几次看完时可能需要手动标记，恢复到文件末尾不会触发自动已看。

本次播放至多触发一次自动标记，不改变位置、作品当前状态或作品完成历史。用户在本次播放中明确更正某分部后，该分部不再被本次自动标记写回，其余关联分部仍按规则处理；下次真正打开文件时可以重新判断。上下文结束后，迟到观察不能再写记录。

## 首选与继续播放

| 所属表              | 字段及适用范围                       | 唯一性                          |
| ------------------- | ------------------------------------ | ------------------------------- |
| anime_files         | is_preferred，作品直接播放的首选文件 | 每个 anime_id 至多一条为 TRUE   |
| anime_file_episodes | is_preferred，某集的首选文件         | 每个 episode_id 至多一条为 TRUE |
| anime_file_extras   | is_preferred，某项附加内容的首选文件 | 每个 extra_id 至多一条为 TRUE   |

三种首选均默认 false，各自范围内允许零条或一条 true，切换在同一事务完成。作品首选保存在直接文件上，分集与 Extra 的首选保存在各自关联上。首选由用户明确设置；取消或删除后可以保持未选择。

多个内容目录同时参与文件发现，不选择整套 TV 或 BD 作为当前版本。可以按目录筛选文件，再按[批量默认文件规则](holdings.md#selection)设置明确分集或 Extra 的首选。目录入口、文件选择与当前播放各自独立，界面遵守[使用与位置操作](../ui/components.md#local-actions)。

打开前先确定作品、分集、Extra 或文件的实际意图，再按[共同目标选择规则](sessions.md#open)处理相应范围。没有活动会话且未显式指定文件时，范围首选优先于最近实际文件。界面已经展示具体目标后，请求携带该 ID 并重新校验，不能点击后悄悄换目标。替代文件恢复自身位置，不修改首选，也不自行越过缺集。

作品详情 bar 的主播放按钮在有继续目标时，恢复最近实际使用的作品文件或分集文件。Extra 有独立继续入口，访谈或 PV 不替换正片目标。合订可以成为作品文件继续目标，但不为每集生成最近记录。已经打开相同实际目标时回到原播放器，保留当前查看方式、播放位置和暂停状态。

没有继续目标时，先使用作品首选；作品有分集时，再提供作品完整分集顺序中的第一项，并说明目标。主按钮不使用详情页的临时筛选结果选择起点。Extra 即使是唯一视频，也不自动作为正片。没有分集时可以按作品文件打开，但不据此写入“无分集”或“电影”的结论，也不自动标记作品完成。

“继续”和“播放未看”是不同操作。完成标记不移动普通继续目标，资料更新时间、已看数量和排序也不能用来推断最近位置。

<a id="sequence"></a>

## 作品内导航与连续播放

播放器按当前查看方式表达相邻项：资料视图中的“上一集／下一集”沿作品完整分集顺序选择，文件视图中的“上一文件／下一文件”沿作品完整文件顺序选择。筛选不参与相邻项计算，例如只显示未看的第 3、5、8 集时，从第 3 集执行下一集仍选择正式顺序中的第 4 集。已看状态本身不跳过目标，界面在操作处明确显示下一项，不能因为它被筛选隐藏就改用其他内容。

当前文件只有一个对应的分集时，资料视图可定位这一集并提供相邻分集操作，与本次从主按钮、分集行还是文件行打开无关。合订文件不能因点击了其中一集，就推定当前时间属于该集；无法确定当前分集时仍可明确选择其他资料项，按文件、章节和时间轴使用当前内容，不任取一个关联作为相邻分集的起点。

Extra 在资料视图中默认单项播放，不自动跨入分集，也不在分集结束后接入附加内容。文件视图按实际文件导航，可以依次打开同一集的不同版本，但不能将这些文件显示或记录为连续几集。文件、分集和附加内容的身份分别保持。

资料或文件变化后，详情页与播放器通过正常查询刷新列表，保留仍有效的当前项和视图选择。相邻项由本体在操作时按所属作品、查看方式、当前项和完整顺序解析，不依赖 renderer 已加载的局部行，也不另存持久队列或冻结的成员副本。已经发出打开请求后，目标按该请求固定并在执行时核对；刷新不能把失败目标静默换成另一个。真正打开下一集时，按其当前关联与首选选择文件，文件恢复自己的位置。下一集仍对应同一合订文件且没有准确范围时，不重新打开、归零或连续跳过。

autoAdvance 默认 false。开启后，只有正常播放到末尾且当前查看方式存在明确下一项时，才按同一相邻项规则推进。资料视图执行下一集，文件视图执行下一文件；切换查看方式本身不发起播放。提前自动已看或手动标记不会提前切换，重新打开后恢复到末尾也不会连续跳转。下一项缺文件、失联或失败时，明确说明情况，允许重试、选择或明确跳过。

切换时先处理原位置，新内容就绪后才建立新会话。失败时保留仍然可用的原内容；原内容已经切离时，如实显示当前阶段。失效请求释放资源，加载失败不计观看。共同切换规则见 [使用会话](sessions.md)。

## 完整播放配置与当前采用

| 范围       | 保存位置                                                | 作用                                   |
| ---------- | ------------------------------------------------------- | -------------------------------------- |
| 全局默认   | preferences 对应的固定 JSON 配置列，由 preferences 管理 | 完整的动画播放默认配置                 |
| 作品自定义 | anime_playback_preferences，anime_id 为主键并引用作品   | 可选自定义单元，包含启用状态与完整设置 |
| 文件自定义 | anime_files 上可空的完整配置 JSON 列                    | 当前文件自己的启用状态与完整设置       |

作品配置是可选的一对一记录，没有独立 ID，也不放入 anime_records。Episode 和 Extra 不增加偏好层。自定义配置使用包含 enabled 和完整 settings 的 customType JSON。文件自定义启用时优先使用文件整套配置，否则使用作品整套配置，再否则使用全局配置，不逐字段继承。初始化、禁用时保留设置和复制规则见 [偏好](preferences.md)。

完整设置包含 audioLanguages、subtitleLanguages、subtitlesEnabled、playbackSpeed、subtitleScale、autoAdvance 和 autoMarkWatched。语言列表有优先顺序，空列表表示没有偏好。默认播放速度和字幕缩放为 1，字幕与自动已看开启，连播关闭，不擅自推断语言。具体轨道和同步偏移属于文件专属值，修改它们不要求开启整套自定义。

管理界面保存配置只影响下次打开。当前播放器的播放配置编辑器在明确保存成功后，将配置应用于当前内容，不改变其他窗口。快捷倍速调整按 [setSpeed](sessions.md#playback-controls) 只影响当前实际文件，下一集或重新打开时恢复目标已保存的配置，不自动记成长期默认值。选轨与文件记忆由 sessions.selectTrack 按明确的 remember 输入完整组织，各入口共用行为。保存失败时保留旧正式值；实际引擎应用失败时，显示未生效和真实状态，不能把存库成功当作已经选轨。

快捷字幕大小按[即时保存规则](sessions.md#subtitle-scale)记入当前采用的文件、作品或全局配置，并只调整当前播放器的字幕缩放。保存范围在控件中明确显示，不要求每次调整后另行保存，也不重置临时倍速或其他当前控制值；其他已经打开的播放器不随之改变。

引擎观察、自动恢复或 mpv 脚本操作不回写持久偏好，只有明确的 Kisaki 操作才保存。音量和静音保存上次使用值供后续打开，不附着到作品或分部；调整当前窗口不会改变其他播放实例。全屏与尺寸属于窗口状态。

文件失联时保留配置。删除文件记录时移除其专属设置，保留作品与全局配置。删除作品不会删除用户的视频、字幕或字体文件。

## 轨道记忆与外挂字幕

anime_files 可以保存具体音轨、字幕选择及各自的同步偏移。明确的具体选择优先；没有具体选择时，按有效语言优先级、文件默认和引擎正常规则回退。界面显示实际采用的轨道与语言名称，不能只展示偏好而假称已经命中。

```ts
type FileTrackSelection =
  { type: 'embedded'; index: number } | { type: 'external'; path: string; index: number }
```

index 表示来源文件内同类轨道的零基序号，轨道种类由字段限定；下拉列表下标、mpv 轨道 ID 与来源文件内的同类序号在接入处转换。语言、标题和编码用于展示与偏好。保存的轨道选择以当前文件的种类和序号为依据，文件改写后的跨文件追踪与轨道身份表不在此合同内。

运行期 PlaybackTrackRef 包含 video、audio 或 subtitle 类型与不透明 id，并限定实际 sessionId。它不能用于重新打开文件，也不能直接保存为偏好。

恢复选择时核对来源、类别和范围。文件失联或序号越界时，保留原选择，显示其不可用及本次回退结果；回退不写回。文件改写后，只要同序号仍存在，就按当前内容解释，不保证仍是原轨道。单纯重定位可以保留选择。同步偏移使用有符号时间，0 表示无修正，只调整本文件对齐，不改变位置和活动，也不复制到下一集。

明确选择字幕轨可以立即显示并保存选择，不自动开启文件自定义。本次临时隐藏字幕时保留轨道，下次打开先由完整配置决定 subtitlesEnabled，再恢复轨道。需要以后始终关闭时，显式修改文件自定义中的该字段，不再增加另一层布尔覆盖。

默认使用 mpv exact 发现同目录、同名及带规范语言后缀的字幕，不使用 fuzzy。手动选择其他路径属于本视频配置，不创建 Extra 或附件。字幕失联时保留路径，并明确提供改选或重定位，不能静默写回另一份字幕。自动发现随当前视频位置变化，手动路径则通过明确文件操作维护。

保留 ASS、SSA 样式与适用字体。字幕缩放只调整显示，字幕开关不能改变 NCOP 或 NCED 的资料描述。

## libmpv 接入与高级配置

主进程 infrastructure/media 直接加载独立正式包 @ximu3/libmpv-node，该包使用 Rust 和 napi-rs 实现 libmpv 的 Node 原生绑定。它保留 mpv 命令、属性与事件的含义，并负责原生类型、异步调用、线程及资源适配。可选受管渲染在 Render API 上管理图形上下文、共享纹理生产与释放；该包不识别 Work、AnimeSession、数据库或 Electron 窗口。

接入采用[绑定模型与应用流程的职责划分](../projects/libmpv-node/api.md#model)。库通过同一 Mpv 实例提供命令、属性读写、属性观察、事件和日志。media 组合加载与初始定位、判断内容就绪和本次定位完成，并组织 screenshot-raw、紧邻媒体位置读取与实际文件的一致性；命令回复不能单独证明内容已经可用。mpv 脚本和基础命令造成的变化同样来自引擎事实，media 据此处理内容替换及旧等待失效，绑定负责实例与帧资源安全。Kisaki 的暂停、倍速和轨道等产品操作仍由 sessions 核对当前会话并执行，不直接向产品入口透出任意 mpv 命令。

原生源码、预编译制品和发行归独立仓库，不加入本仓库 packages。不增加 utilityProcess、helper，或进程内外两套模式。

原生播放、阻塞和图形工作交给适当的原生线程，遵守图形上下文与调用线程约束。JS 通过明确桥接接收结果，不能只给同步阻塞函数标上 async。关闭后，线程和回调都不能访问已经失效的资源。

主进程通过 Electron sharedTexture 导入并交付视频，renderer 将视频与 UI 合成。[Mpv、输出与帧分别维护寿命](../projects/libmpv-node/lifecycle.md#ownership)：已经交付的 NativeFrame 不因 Mpv 关闭而失效，接入等待 allReferencesReleased 后归还本次帧持有。消费期间必须保持纹理有效，释放反馈给实际拥有者，不能假定跨进程完全没有 GPU 复制。

sessions.anime 管理产品会话，library 保存正式位置、活动、完成和标注，infrastructure/media 通过 libmpv-node 获取技术事实。多个播放实例分别持有状态与资源，不增加第二个公开会话 ID。原生实例关联只用于拒绝失效回调。原生故障可能影响主进程，因此须验证六个目标的正式制品、napi-rs 接入、音视频同步和完整资源寿命。

应用提供独立的 mpv 配置目录，支持渲染、着色器、字体、快捷键和脚本，不读取系统中的另一套配置。普通 UI 管理的选项、IPC、位置恢复、会话和连播以 Kisaki 的有效值为准，说明文档列出受管范围。其他高级选项交给 mpv，不建立相互竞争的配置，也不用 watch-later 代替文件位置。

验收覆盖零分集影片、同集多文件、合订视频、Extra 多文件、补充资料后身份保留、来源顺序歧义、未编号与同号分集、三种首选范围、看过访谈后继续正片、缺集与切换失败、末尾恢复、轨道顺序变化或失效、字幕临时隐藏与重开、字幕失联、ASS 样式、设置保存与应用失败，以及高级配置的优先级。

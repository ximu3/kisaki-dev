# SteamGridDB 接入设计

SteamGridDB 通过官方图片 API 提供游戏对应与 grids、heroes、logos、icons 四类素材。本文规定候选读取、图片用途、凭据和本体采用的分工。

<a id="scope"></a>

## 职责与能力

SteamGridDB 为 Game 提供游戏目录对应和四类美术资源。普通资料读取只输出 primaryImage、backdropImage、titleLogo、iconImage；来源游戏名称用于搜索、识别和候选说明，不把图库的日期、平台缓存、图片投票或上传者转成游戏发行资料、个人评分或制作人员。

| 能力                               | 方案                                                                         |
| ---------------------------------- | ---------------------------------------------------------------------------- |
| Game 搜索                          | 提供名称候选，使用来源 autocomplete 的实际结果                               |
| Game 定位                          | 支持完整 SGDB 游戏身份、已核实的 Steam 应用对应；名称只交候选给共同 matching |
| Game 图片读取                      | 四个图片字段按所选用途读取，完成该范围所需分页                               |
| 独立图片候选                       | 四类用途均提供；支持名称、SGDB 游戏编号和明确的来源平台编号                  |
| 人物、组织、角色及分部资料         | 不提供；图片上传者不成为库内实体                                             |
| 库导入、个人记录同步、图库内容发布 | 不提供；不注册导入或同步页面，不调用上传和删除接口                           |

图库中的平台标记如 types=['steam'] 表达平台归类，不是本体游戏类型。verified 也不表示本地目标已经对应。图库可收录不同版本或其他软件，读取仍需符合当前目标的作品范围。

<a id="lookup"></a>

## 身份、名称与分页

规范 SGDB 游戏身份使用 source=steamgriddb、sourceId=game/{gameId}。图片编号与游戏编号分别表达；不同图片类别的编号不能合并成同一图片身份。只有正式采用来源身份时才可能保存游戏绑定，单独换图不写绑定。

已知 SGDB 编号时读取真实游戏记录；已有 Steam 应用身份时使用来源的明确编号对应端点，核对响应后形成 SGDB 目标。平台其他编号可用于用户明确输入的图片检索，使用来源支持的 steam、origin、egs、bnet、uplay、flashpoint、eshop 名称和实际编号；不因此建立其他平台扩展或猜测本体中尚未约定的跨站身份格式。

平台缓存资料不代替对应平台的元数据。官方对 platformdata 的及时性与准确性有明确保留，扩展不从中提供本体首发日期、原作语种或其他普通字段；只在确有身份对应需要时读取必要信息。

名称来自真实响应，不能在缺席时复制查询词。仅按名称取得记录时返回 candidates，由本体 matching 决定；即使只有一项也不直接宣布强对应，不保留当前实现按年份或首项自动选定的行为。

已核验的名称建议响应最多返回 10 项，附加 page=1 或 limit=50 不改变结果，官方端点没有声明续读参数。独立搜索保留来源返回的顺序，不进一步截取，也不伪造 nextCursor 或全站 total。注册说明写明这是有限名称建议，用户可使用更具体名称或明确编号。

名称 resolve 遇到 10 项或更多结果时，按候选范围可能截断返回 insufficientInput，等待更明确线索；少于该上限时交付全部实际候选，仍不以首项或 verified 绕过 matching。这个防护属于当前来源适配，需要随接口核验更新，不作为其他来源的共同数字阈值。

图片列表按真实 page、limit 续读，以原始批次的实际记录判断结束。过滤后的空批次不代表来源已结束。icons 的实测 total=16 对应 5 个独立文件，不能直接拿 total 当可选图片数量；短页、空页和实际图片身份去重共同限定本次读取，不补造记录或无界追逐计数。

<a id="images"></a>

## 图片用途与采用

| 来源类别 | 本体字段      | 处理规则                                       |
| -------- | ------------- | ---------------------------------------------- |
| grids    | primaryImage  | 保留竖幅、横幅和方形封面，不固定为 600×900     |
| heroes   | backdropImage | 使用来源实际背景图，不从 grid 裁切生成         |
| logos    | titleLogo     | 保留透明度及来源真实颜色、样式                 |
| icons    | iconImage     | 支持 PNG 与 ICO 输入；ICO 转换由本体准备层负责 |

PNG、JPEG 和 WebP 按实际格式处理，静态与动态资源均可采用。候选以来源图片身份区分用途和尺寸，原图与可用缩略预览属于同一候选。字段读取取得所选类别，独立浏览按有限批次交付；本体按资料方案或用户选定结果准备原图并完成采用。

候选保留真实原图、可用预览、来源类别、语言、尺寸和实际署名信息。SGDB 返回的 language 可以用于语言选择；缺失时保持未知，不从标题、文件名或画面猜测。图片 NSFW 标记不能直接成为 Game.isNsfw，图片 score／upvotes 不成为个人评分。author 表达来源上传者或提供者，不能推成游戏职员或原始权利人。

候选排序先遵守本次语言规则，同等条件保留来源的推荐顺序。完整字段读取可以在完整候选范围内处理语言偏好；按页浏览保留真实分页位置，不为了局部排序宣称已经遍历全部图库。

实测的动态 WebP 原图带有 WebM 缩略预览。本方案不支持 WebM 或其他视频缩略：来源适配省略已知的视频预览，保留受支持的动态原图；本体仍按实际内容验证图片，不能因预览不受支持而丢掉整张候选。原图与可选图片缩略继续使用现有 FileInput，不扩充视频预览合同。

现有图片合同已覆盖原样保留动画、列表静态缩略与完整查看时播放。缺少可用图片缩略时，可在当前可见范围内按需读取原图、生成并缓存静态缩略，受既有字节、解码、并发及取消约束；不能因此预取全图库或正式采用附件。首次预览可能需要读取体积更大的原图。

ICO 可能包含多个尺寸层；来源报告的宽高为 0 时，尺寸保持未知。[公共图片能力](../../domains/attachments.md#images)已纳入 ICO 准备：本体选择最大有效尺寸层，同尺寸优先更高位深，转换为保留透明度的 PNG，以最终预览为准；多尺寸不作为动画帧。转换失败或超限时保留原有字段，不在扩展内另写转换链。

ICO 转换与完整图片采用分别验收。扩展只提供资源和真实信息，下载、校验、转换、裁剪、附件登记与取消沿本体流程执行。

<a id="settings"></a>

## 凭据与一个配置页面

只注册“资料采集”页面，使用既定 Solid 与基础 UI。页面包含访问凭据、图片偏好、网络参数和连接测试，图库浏览与选图继续使用本体共享界面。

使用用户自己的 API key，经 [SteamGridDB 设置页](https://www.steamgriddb.com/profile/preferences/api)取得。key 沿 secrets 保存，界面只读配置状态；没有额外浏览器授权或账号同步流程，也不内置维护者的个人 key。API key 只发送到明确的 API 请求，不进入图片资源或 CDN 请求。

| 配置           | 默认值与含义                                             |
| -------------- | -------------------------------------------------------- |
| 包含 NSFW 图片 | 开启；关闭时只过滤来源标记的相应图片，不改变作品敏感标记 |
| 包含恶搞图片   | 关闭；开启时包含来源 humor 标记图片                      |
| 包含闪烁图片   | 关闭；对应来源 epilepsy 标记，不据未标记断言图片无闪烁   |
| 图像类型       | 静态与动态均可用，可选择仅静态或仅动态                   |
| 单次超时       | 20 秒                                                    |
| 安全读取重试   | 2 次；429 尊重 Retry-After                               |

“包含”布尔值映射为来源 any／false，不能误用 true 而变成只取被标记图片。不增加固定尺寸限制或一套字段语言优先级；语言仍来自本体资料方案和图片查找输入。

保存合法配置与联网测试分别操作，离线可以保存。明确移除 key 与恢复普通默认设置分别处理；配置变更只影响后续执行和对应缓存，不主动刷新图库条目或替换已采用图片。当前调用使用开始时的配置快照。

## 内部组织

```text
src/
├── node/
│   ├── entry.ts
│   ├── client/
│   │   ├── gateway.ts
│   │   ├── validation.ts
│   │   └── types.ts
│   ├── metadata/
│   │   ├── provider.ts
│   │   ├── identity.ts
│   │   ├── lookup.ts
│   │   └── images.ts
│   ├── settings.ts
│   └── ipc.ts
├── webview/
│   ├── index.html
│   ├── entry.tsx
│   └── settings/
└── shared/
    ├── contracts.ts
    └── validation.ts
```

client 负责真实 HTTP、取消、重试和响应校验；metadata 负责身份、候选、用途和分页。settings 持有普通配置并通过 secrets 操作凭据，ipc 只转发完整配置操作。Webview 不直接请求来源或读秘密，不设 account、import、sync 或图库镜像模块。

来源错误按 HTTP 状态、响应形状和本次操作分类，不能解析错误文字。404 记录不存在、认证失败、网络失败和正常空图片列表分别处理。官方示例与真实响应不一致时以已核验合同建模，不加入兼容多个猜测形状的回退。

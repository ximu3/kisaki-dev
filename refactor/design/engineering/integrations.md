# Kisaki 的独立项目接入

本页定义独立技术能力进入 Kisaki 的接入责任。完整业务流程仍由[游戏会话](../domains/games.md)、[媒体会话](../domains/sessions.md)、[阅读会话](../domains/reader.md)及[来源认证](../extensions/private-data.md)拥有。

| 接入        | 直接消费的合同                                                                       | Kisaki 拥有的工作                                                       |
| ----------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| [Vantage](#vantage) | [公共 API](../projects/vantage/api.md)                                               | 监测集合、计时、窗口选择、完整采集及退出后的业务处理                    |
| [Kana](#reading) | [阅读 API](../projects/kana/api.md)                                                  | 文件与窗口、偏好解析、持久值映射、记录与标注                            |
| [libmpv-node](#media) | [调用](../projects/libmpv-node/api.md)及[视频输出](../projects/libmpv-node/video.md) | 媒体就绪、操作排序、Electron 显示引用与产品会话                         |
| oauth-relay | [HTTP 协议](../projects/oauth-relay/protocol.md)                                     | [授权、账号核验和凭据采用](../extensions/private-data.md#authorization) |

独立项目不导入 Work、Part、Session、数据库或 desktop-contracts；接入不复制解析、原生身份和播放内核。

<a id="vantage"></a>

## Vantage：技术接入与业务操作

| 层次                  | 拥有的事实与操作                                                 |
| --------------------- | ---------------------------------------------------------------- |
| 平台后端              | 原生实例、权限、桌面连接、状态读取、控制请求、有效帧与原生资源。 |
| Vantage core          | 统一公共语义、实例对应、局部不可用、观察接续、取消和各操作收尾。 |
| Node binding          | 本环境引用对象、Promise、回调、字节所有权和环境退出。            |
| Kisaki processes 接入 | 消费公开包，连接本体取消与系统集成流程，转换必要值与错误。       |
| Kisaki sessions.game  | 启动确认、监测集合、前台计时、窗口选择、恢复后采集、结束与备份。 |

Vantage 通过原生后端提供进程、窗口与采集能力，Kisaki 组织游戏监测和截图等完整操作。图形后端初始化与普通进程查询分开；缺少桌面或截图权限不应阻止进程能力独立使用。

<a id="实例保证与实际操作边界"></a>

## 实例保证与实际操作边界

Kisaki 使用 Vantage 提供的原实例引用执行观察和控制，并按[引用与平台并发合同](../projects/vantage/backends.md#identity)处理失效。平台句柄、pidfd、窗口对象及其核验机制由 Vantage 拥有；接入不根据 PID、窗口编号或旧快照重建替代引用。

业务选择、计时、截图流程和退出后的处理使用这些技术事实。窗口身份校验与原生操作不能原子完成的平台，继续保留所属后端的并发限制；产品接入不增加另一套身份保证。

<a id="观察中断与游戏会话分别收尾"></a>

## 观察中断与游戏会话分别收尾

Vantage 的 interrupted 结束一项无法可靠继续的观察，GameSession 的 interrupted 表示本次受管理运行已经无法继续记录。两者不直接一一映射。以下规则承接[游戏观察与计时](../domains/games.md#observation)，统一库与本体的处理边界。

| 发生的情况                             | Vantage 的交付                                              | Kisaki 的处理                                                                  |
| -------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 路径、标题或单个窗口字段暂时不可读     | 保留有效引用及其他字段，局部 unavailable。                  | 已确认成员继续按原实例观察，不因路径变化或暂时不可读移出集合。                 |
| 进程存活可靠，前台事实暂时未知         | 前台字段 unavailable，进程事实保留。                        | 前台计时暂停相应区间；运行计时仍可使用已经可靠确认的存活事实，不切换计时模式。 |
| 窗口后端断连，进程观察仍可靠           | 结束受影响观察，使无法继续核实的窗口引用失效。              | 保留仍可维持的游戏上下文；相关操作准确失败，重新建立窗口观察时取得新引用。     |
| 实际运行所需的原实例关系已无法恢复     | referenceInvalidated 或相关观察 interrupted，不能伪造退出。 | 按既定条件中断游戏会话，保存已确认记录；不自动终止程序或触发退出备份。         |
| 某次聚焦、关闭或截图失败               | 结束该次操作，保留独立可靠的观察。                          | 由发起方反馈；不把操作失败直接变成游戏结束。                                   |
| 确认全部成员实际退出且满足退出确认规则 | 原实例结束事实。                                            | 完成正常会话收尾及适用备份。                                                   |

本体可以在同一活跃会话里显式重建受影响观察，只使用仍成立的原进程身份与固定监测规则；库不在旧订阅内部暗中换绑。这里的“显式”指接入代码建立新的订阅，不要求为每次恢复新增用户确认。恢复不补未知区间，不清除用户暂停，也不复活已经结束的 GameSession。

截图依次确定窗口、按需恢复、取得恢复后的有效帧并固定原图，然后进入裁剪或保存。有效帧是本次采集的完成依据，等待期限由本体传入。原生库在同一目标与期限内完成采集。

## 媒体：技术寿命与产品会话

Kisaki 按[视频宿主接入](#integration)完成打开和切换：执行原生命令，核对实际文件与轨道状态，完成定位及所需首帧消费，全部条件成立后才返回产品操作成功。Mpv 可按既定规则复用，fileId 和产品会话由本体持有。

输出资源经原生同步后交付，宿主导入并呈现，再在 allReferencesReleased 后归还对应 NativeFrame。Mpv.close、帧 release 与产品会话的显示引用回收分别完成；不能把其中一步的结果当作其余步骤已经结束。

screenshot-raw 保持独立截图数据合同，本体使用已就绪的受管 sRGB GPU 输出、screenshot-sw=no、subtitles 与 rgba，核对尺寸、stride、数据范围及同一内容上下文。[截图接入条件](#screenshot)通过逐结果 source 标记核对，验收覆盖正常 GPU、显式软件、强制回退、负 stride、持续采集与完整失败路径。颜色不从通道格式推导，也不把上游软件回退视为同色保证；不增加第二套截图接口或把最后显示帧当作必然逐像素相同的截图。

文件会话结束时完成本次记录保存、显示交接及所属资源收尾；切换文件可以由同一播放器执行者继续持有 Mpv。播放器执行者最终关闭时，完成 Mpv 关闭及其全部显示引用回收。screenshot-raw 交付的独立字节用于后续裁剪、编码和保存，不持有显示 NativeFrame；显示帧统一按 allReferencesReleased 归还。

Kisaki 取得 NativeFrame 后，通过 Electron 接入导入并转交显示端，收到 allReferencesReleased 后再调用 NativeFrame.release。单个导入对象的 release 解除本对象引用，最终回调确认全部下游引用结束，见 [SharedTextureImported](https://www.electronjs.org/docs/latest/api/structures/shared-texture-imported) 与[共享纹理回收](https://www.electronjs.org/docs/latest/api/shared-texture)。独立库保持自身的帧持有和释放合同，Electron 对应由本体完成。

infrastructure/media 负责加载、初始定位和内容就绪，协调截图、紧邻位置读取及当前文件的一致性，并按实际上下文安排控制与等待。内容替换或脚本改变上下文后，相应旧等待失效。sessions 管理作品与文件归属、业务会话、标注和正式记录；SDK 使用这些产品操作，底层库提供原生命令、事件和资源能力。

## 播放核心与文件会话的接续

每个播放器执行者独立创建、持有和关闭 Mpv 与 VideoOutput，正常切换文件时复用这份资源。并行播放、明确的独立环境或设备／核心失效可以要求创建新实例；更换核心按这些实际条件决定。

文件会话按[切换合同](../domains/sessions.md#switch)执行：切换实际文件时结束旧 AnimeSession，新内容就绪后发布新 sessionId，并建立新的作品归属、位置、计时与采集上下文。技术执行者在这次切换中可以继续使用原核心，直到执行者整体结束时再关闭 Mpv。

sessions.anime.switchFile 按[文件切换合同](../domains/sessions.md#switch)组织目标准备、旧上下文收尾和新内容就绪，接入交付同一 FileSwitchResult 或带合法部分结果的失败。目标配置、初始位置和暂停意图由本体按会话合同采用；media 的核心复用不改变产品会话的结束与创建边界。

每次打开实际新文件时，sessions 读取 preferences.playback 的正式音量与静音记忆并交给执行者初始化；核心复用也采用这份输入，不从旧 Mpv 的残留值或上游默认值推导产品初值。完整播放配置与这两个控制值分别采用；明确的音量/静音调整按[会话保存合同](../domains/sessions.md#playback-controls)保存后只作用于当前执行者，原生观察不回写偏好。

infrastructure/media 关联打开、控制请求与显示交接。切换、采集和定位按既定次序执行；实际替换开始时停止旧上下文接纳与记录，并撤去待交付旧画面。后续结果只交付给仍有效的对应上下文，旧请求和显示任务各自完成资源归还。

接入按影响范围组织执行顺序：换文件、定位和采集共享内容操作顺序，保证采集原图与紧邻位置之间不插入另一次切换或定位。正常播放中的音量、暂停等普通控制不因此全部等待同一个长队列；开始替换文件时关闭旧上下文的接纳关口，并收尾已经接纳的控制，再采用新文件配置。连续定位可以合并尚未执行的意图，被替代调用按既有合同明确结束，不把最后一次成功当作所有请求成功。

打开成功须满足适用内容的四项条件：原生加载完成、请求的初始定位完成、轨道与实际位置可用、显示接入就绪。loadfile 的回复完成原生调用，file-loaded 报告引擎文件加载，playback-restart 报告不连续变化后的引擎恢复；宿主显示由实际消费另行确认。无视频轨或明确关闭视频时按相应内容状态完成。事件含义见[原生定义](https://github.com/mpv-player/mpv/blob/01e2533f3143b8940857ca419b0b367f583e05ca/include/mpv/client.h)。

显示准备包含原生核心、纹理导入及消费端就绪。createMpv 完成核心准备后，由 infrastructure/media 继续组织实际导入；失败时归还尚未交接的持有，已导入引用等待消费端最终回收。交接、SDR 颜色和连续播放按各自条件验证。

本体结合命令回复、原生条目身份、加载与定位完成事件及渲染边界，确认文件归属和内容就绪。请求序号只关联本体调用，NativeFrame 保持实际原生字段；文件归属由接入根据上述事实核对。跨文件复用的交接边界以真实原生时序验证为依据。

源码中，普通渲染 reset 会保留当前帧用于重绘；没有下一帧时 render 也可以复用当前帧。因此交接时必须隔离旧接收与在途显示工作，不能将重置、重新订阅或任意一次重绘直接当作新文件画面的证据。该事实支持显式交接要求，不单独证明整个跨线程交接方案已经成立。[渲染重置与当前帧](https://github.com/mpv-player/mpv/blob/01e2533f3143b8940857ca419b0b367f583e05ca/video/out/vo_libmpv.c)

受控换文件与帧持有的依据见[Node／Electron 交接检查](../../verification/evidence/libmpv-handoff/verification.md)，包括跨线程、原生 hook 与迟到消费回调。运行输入和实际覆盖范围保留在证据中；正式接入另验证脚本变化、并发加载取消、公共订阅和同一播放器内的核心复用，不额外建立核心池。

原生层可使用 on_before_start_file 与 on_after_end_file 作为明确协调点。接入验证覆盖事件与渲染的不同处理顺序、同核心换文件、定位、加载失败后的恢复及旧帧持有期间关闭；旧画面重绘不构成新文件就绪。依据见[切换证据](../../verification/evidence/libmpv-playback/verification.md#switching)。

Node 接入管理自身的停止与交接。每个 hook 使用独立弱客户端。hook 与属性观察独立接续，开始 hook 时其他属性回调可能尚未完成；按[hook 合同](../projects/libmpv-node/api.md#hooks)停止旧订阅、处理已接纳工作并采用实际上下文对应的结果。正式验收分别覆盖 Node 交付、快速取消及 Electron 在途交接。

若脚本或其他原生操作实际改换内容，本体停止将后续位置写到原 fileId，再按实际内容变化处理，不能仅凭 Mpv 对象未变继续沿用旧归属。截图的图像、紧邻媒体位置和文件关联仍由 media 的一次明确采集操作取得，不从持续帧订阅中猜测。

Electron 接入位于 infrastructure/media；libmpv-node 不引用 Electron，也不把其导入对象或 VideoFrame 类型纳入库的公共合同。库负责交付可安全读取的帧，接入层负责导入、传递、显示及最终引用回收，sessions 负责文件与记录身份。

Electron sharedTexture 是官方标记为 Experimental 的接口。Kisaki 固定 Electron 版本，将映射与版本适配集中在接入层；每次升级验证导入、格式和释放行为，按[官方合同](https://www.electronjs.org/docs/latest/api/shared-texture)维护适配。

原生帧订阅与主进程到显示端的传递各自保持有界：传递侧至多维护正在处理的交付与最新待处理帧，被替换的持有立即归还。接收回调不以 Promise 回压播放器；导入失败由适配器归还尚未交接的帧，导入成功后按宿主最终引用回收通知归还。发送失败、窗口关闭和 renderer 崩溃均须验证，不能用固定延时冒充消费完成。

本体在 Windows 采用直接 D3D11，各平台使用固定上游输入和核心复用，由自身接入负责宿主生命周期与可靠文件归属。最终构建及跨线程交接按正式验收执行。原生接口若无法提供所需依据，应重新比较实例隔离及资源成本，并按实施讨论规则处理策略变更。

<a id="host-lifecycle"></a>

## 播放宿主的显示变化与故障

Kisaki 使用以下接入策略，库本身不因一个消费界面的行为自动关闭播放核心：

| 情况                           | Kisaki 的处理                                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 窗口缩放或移动到另一显示器     | 更新物理像素尺寸并核对消费环境，保持 sRGB 目标与文件会话；仅显示器变化不重建核心                             |
| 窗口最小化或暂时不需要绘制     | 保留用户原有播放／暂停状态；可以停止接收画面，原生继续处理渲染更新与音频时钟                                 |
| 显示端 renderer 崩溃           | 停止向失效接收方交付，暂停播放并停止相应有效播放计时；保留实际文件与最后可信位置，由主进程组织界面恢复       |
| 目标文件加载失败               | 按实际切换阶段结束操作；尚未离开旧文件则保留旧内容，已经离开则不伪装回滚；健康核心可以继续接纳下一次明确打开 |
| 图形设备失效或输出进入失败终态 | 暂停并报告，按实际拥有关系清理；由明确的恢复操作新建核心和设备并采用可信位置，不重放未知脚本或原生调用       |
| 用户关闭播放器                 | 拒绝新操作，完成已接纳工作的结束、最后可信记录保存、原生核心收尾和显示资源清理                               |

窗口最小化继续遵守用户的播放意图，显示端故障按对应失败分支处理。renderer 恢复后等待用户明确继续；设备恢复使用本体已知的文件、位置和配置重新建立必要资源。

显示接入始终负责归还自己取得的资源：拒绝迟到交付时释放该次持有，已经导入的资源等待最终引用回收。Mpv.close 完成核心收尾，Kisaki 继续完成显示侧与正式记录清理；窗口关闭或会话替换后，这些释放责任仍持续到资源归还。

Kisaki 的输出目标固定为 sRGB，HDR 片源和系统设置按这条显示链路处理。独立宿主显式切换 SDR 表示时采用 configure 的失败与快照合同；设备或输出故障沿实际失败状态处理。

## 视频帧的 Electron 字段映射

Kisaki 的 infrastructure/media 负责将 NativeFrameSurface 映射到当前 Electron 的输入形状；libmpv-node 不导入 Electron，也不返回 Electron 对象。

| 库交付值                    | 宿主对应处理                                                         |
| --------------------------- | -------------------------------------------------------------------- |
| d3d11／ioSurface 的借用字节 | 在持有有效期间构造导入所需 Buffer，在当前进程导入                    |
| dmaBuf modifier: bigint     | 转为精确的十进制字符串，不经过浮点数                                 |
| dmaBuf offset／size: bigint | 按当前 Electron 的 number 输入核对安全整数后转换；不可精确表达则失败 |
| planes、fourcc、pixelFormat | 核对真实布局对应，不丢辅助 plane、不按名称猜字节顺序                 |
| target                      | 使用本页的原色、传递曲线、RGB 与 full-range 描述，不沿用源文件标记   |
| coded size 与 visibleRect   | 沿实际图像和可见范围传递，不混入 CSS 尺寸或显示器缩放                |

Linux 的 WebGPU usage 按当前平台导入能力解释，supportsZeroCopyWebGpuImport 用于报告能力。Kisaki 使用 VideoFrame 与 Canvas／video 消费路径；时间字段、生产编号及 reportSwap 各按[原生时序合同](../projects/libmpv-node/video.md#timing)使用。

导入、传输对象、VideoFrame／clone 和原始 NativeFrame 分别释放。调用单个导入对象的 release 不代表 renderer 已读完；本体在 allReferencesReleased 后归还对应 NativeFrame。打开完成、输出失败与产品会话的关系继续见[宿主接入](#integration)。

目标颜色映射如下；像素转换由库完成，宿主描述实际结果。

| 目标       | 原生输出条件                        | Electron 导入颜色描述  | WebCodecs 读回名称                     |
| ---------- | ----------------------------------- | ---------------------- | -------------------------------------- |
| sRGB       | BT.709 原色、真实 sRGB 传递曲线     | bt709／srgb／rgb／full | bt709／iec61966-2-1／rgb／fullRange    |
| Display P3 | Display P3 原色、真实 sRGB 传递曲线 | p3／srgb／rgb／full    | smpte432／iec61966-2-1／rgb／fullRange |

<a id="screenshot"></a>

## 视频截图的布局与颜色

Kisaki 沿同一 command 入口请求 screenshot-raw subtitles rgba，使用已就绪的受管 sRGB GPU 输出，并明确设置 screenshot-sw=no。subtitles 取得视频内容和字幕；rgba 指定通道排列，不表达颜色空间。screenshot-sw=yes 不属于本体这条 SDR 采集路径的使用条件，可检测的配置冲突沿既有约定处理，不增加原生配置锁。

返回的 w、h、stride、format 和 data 按原生值合同保留，media 核对可表示范围及实际行布局，再准备独立图片。截图尺寸不从视口推导，行 padding 不作为有效像素；结果没有源帧时间和文件归属，由本次采集操作关联紧邻位置及内容上下文。通用绑定也不从 NativeFrame 或稍后属性读取补造截图颜色字段。

固定上游在 GPU 后端未返回图像时仍可能转入软件截图，screenshot-sw=no 不禁止回退。本项目采用[截图来源补丁](../projects/libmpv-node/distribution.md#screenshot-source)：同一次 screenshot-raw 结果附带 source: vo 或 software，直接来自实际取图分支，绑定原样交付，不从选项、日志或稍后的状态推断。

media 只接纳 source 为 vo、属于本次有效受管 GPU 输出且仍满足 sRGB 使用约定的结果。source 为 software、缺失或未知时，以 CaptureUnavailable 结束本次采集，不创建 PreparedImage、不编码或保存图片，也不自动重试、暂停或改变播放设置。尺寸、stride 和独立字节仍分别核对；source 只证明取图路径，不单独证明颜色、文件归属或精确帧时间。正常 GPU 路径的颜色由既定输出条件与对应像素回归保证。[原始回退路径](https://github.com/mpv-player/mpv/blob/01e2533f3143b8940857ca419b0b367f583e05ca/player/screenshot.c#L345)

<a id="host"></a>

## 阅读画面采集与 Electron 像素尺度

Kisaki 阅读接入在 readView 回调中调用受控窗口采集。主进程核对真实来源与当前绑定，使用对应 webContents.capturePage 取得像素；回调不接收任意 windowId，也不允许调用方截取其他窗口。

Kana 交付 CSS 像素矩形；Electron 接入负责将其转换为当前 webContents 页面缩放下的采集矩形，并依据实际返回位图尺寸处理像素边界。外扩的整数边界只用于取得完整像素，最终采用时收敛到请求区域，不反向修改源 region。操作同时核对当前缩放及视图有效性。

devicePixelRatio、Electron zoomFactor、NativeImage 的表示 scaleFactor 和实际位图尺寸分别描述不同的缩放与尺寸事实。采集尺寸依据真实位图，不能从表示 scaleFactor 推断设备缩放或实际像素尺寸。

主进程取得原始内容后，像素转换、图片编码、PreparedImage 与 Annotation 保存由已有拥有者接续。存入的源位置、原文或区域来自同次绑定的阅读操作，图片不用于反推源坐标。

<a id="reading"></a>

## 阅读：会话与公共能力的接入

Kisaki 构建把清单中的资源复制到程序资源目录的 kana／资产身份子目录，通过阅读窗口所属 session 的受控同源协议提供 assetsBaseUrl。协议能力、内容 CSP 与专用作用域沿已有部署合同；不创建运行期本机 HTTP 服务，不使用户文件路径直接成为书内网络地址。

一次打开的接入次序如下：

1. 固定这次产品会话的实际文件与目标，取得授权读取范围和需要的临时存储。
2. 选择完整的文件／作品／全局偏好，解析主题颜色与字体资源，形成 Kana 的完整技术设置。
3. 用明确容器、source、settings、assetsBaseUrl、初始位置和可选 handleKeyDown 调用 openReader。回调绑定本次会话；未成功打开前不把请求位置写成实际进度。
4. 成功后采用实际位置与状态，订阅主阅读、选区、标记及外链通知。设置变化、标记投影和导航继续通过同一 Reader 协作。
5. 切换或关闭时先结束本次输入和未完成工作，完成 Reader.close，再在本体的 finally 中释放自己拥有的授权、字体与临时占用，并完成记录保存。某步失败也继续收尾其他资源。

内容中的局部按键先由 Kana 处理；宿主回调只映射自己的快捷键，使用实际 forwardDirection，不同时从 Electron 的窗口入口重复执行。参考查看不改主阅读进度，宿主观察到新回调时也不能把它归到后来切换的另一文件。

本体复制按钮通过 getSelection 取得完整源文字，再使用自己的剪贴板能力；view 采集通过 readView 固定当次几何与位置，再由本体取得画面、生成附件并保存。书籍解析、文字拼接、截图定位修补和浏览器 Range 不进入主应用接入。

## Kisaki 与 Kana 的值映射

| ------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------- |
| fileId 与正式阅读位置           | ReadingLocation                             | 文件身份由会话绑定；源锚点、编码和页面身份保持，临时资源 URL 不入库                |
| ReadingTextSelection 与保存原文 | TextRange、ReadingSelection.text            | 应用字段 selection 与库字段 range 明确对应；非空范围、相同寻址分支与源顺序都须成立 |
| ReadingPageRegion               | PageRegion                                  | 固有页及 0–1 规范几何保持，不保存缩放、显示旋转后的像素框                          |
| Annotation 及其排序             | MarkProjection、MarkOrder                   | 本体保存记录与批注；库只解释位置、绘制并交付源顺序和 unresolved                    |
| ReadingPreferences              | ReadingSettings 与 FontResource             | 本体独立解析默认值和偏好层级；主题、字体库记录及资源占用在接入处转换               |
| 当前工具与实际阅读反馈          | interactionMode、ReadingView、referenceView | 运行态按既有范围使用，不反向覆盖持久偏好或把参考查看写成主位置                     |
| 保存的书签画面／区域图片        | readView 与宿主采集                         | 源目标与像素来自同一次稳定视图读取，独立图片取得后不继续持有书籍视图               |

两侧合同分别由 desktop-contracts 和 Kana 拥有。结构、单位和含义一致时可以直接对应值；名字不同的字段明确映射，不通过类型别名、强制断言或 JSON 整体透传跳过责任。纯值合法由本体合同核对，当前文件里目标是否存在由 Kana 恢复时确认。

TXT 按已存 encoding 解释 offset；XML 路径、完整 CFI、MOBI/KF8 原始字节规则、图片成员名称及规范页面几何均沿[源位置合同](../projects/kana/positions.md#addresses)。库升级不自动改写数据库值；失败保留位置、原文和批注，不能以首页或相邻目标充当恢复成功。

## 连贯阅读中的共同约束

| 场景                                 | 各项机制如何衔接                                                                                       |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 竖排小说穿插固定插图和参考注释       | 格式给出真实顺序与版式；view 安排阅读面，输入按当前方向接续；注释选区指向真实源内容而主进度保持        |
| 双面阅读中改字体并跨章摘录           | 同一布局采用字号、源位置与几何；固定／活动端保持，复制取完整源范围；不要求中间所有章节 DOM 常驻        |
| 读屏到达当前语义范围边界             | 稳定节点保留，明确接续后交接新内容；视觉预取不提前淘汰语义范围，失败仍可阅读原内容                     |
| 大型 ZIP／图片目录或 PDF             | 根输入按需读取，成员／页面／worker 各自占用；源页序与成员身份保持，取消后完成实际清理                  |

| 关闭后立即打开另一文件               | 每次 Reader 与授权各有寿命，旧回调不更新新会话；静态资产可复用，书籍字节和活动任务不跨文件复用         |

以上是实施与验收共同使用的场景，不新增另一层状态机。阅读行为、源定位、样式、输入和释放已经分别有实际拥有者，接入只组织它们的已有完成条件。

## 阅读与播放的职责边界

| 范围                | Kana                                         | libmpv-node                                   |
| ------------------- | -------------------------------------------- | --------------------------------------------- |
| 技术职责            | 文档解析、排版、呈现、导航、定位与选区       | libmpv 的 Node 绑定、运行时适配与可选受管渲染 |
| Kisaki 中的运行位置 | 阅读窗口的渲染进程；纯类型与校验可用于主进程 | 主进程直接加载，包内适当原生线程承担原生工作  |
| 接收内容            | 文档资源、呈现容器、实际阅读设置与初始位置   | mpv 初始化选项、命令、属性及渲染配置          |
| 交付内容            | 阅读画面、位置、目录、搜索结果及选区等       | 播放状态、时间位置、轨道信息及帧资源等        |

Kana 提供文档与阅读能力，libmpv-node 提供媒体控制与输出能力，各自通过符合职责的接口交付技术句柄。Kisaki 将这些资源纳入产品会话，并管理 Work、Part、数据库、TaskRun 和应用窗口。

Kisaki 负责作品与文件选择、窗口、使用会话、偏好和正式记录。Kana 根据源内容与当前排版计算高亮，并交付源位置、所选原文及指定位置的邻近原文；它还按同一源解释反馈标记的内容顺序和无法恢复的 ID，宿主不自行比较地址字符串。Kisaki 保存 location、quote、归属及批注，并负责书签或区域标注所需的视图图像采集。libmpv-node 交付秒数、技术状态和原生帧，Kisaki 组织视频标注时间轴与操作界面。

独立库不依赖 Electron 或 desktop-contracts。Electron 接入负责导入纹理，并按 allReferencesReleased 向帧资源拥有者反馈释放情况；只要消费者仍持有引用，生产者就不能复用或释放该资源。

Kisaki 的完整打开操作成功表示目标已经可用。阅读接入采用 Kana 的内容合同，视频 media 接入组合 libmpv 的命令、属性与事件判断实际就绪；创建 Mpv 或命令完成不单独表示媒体可用。关闭完成表示对应句柄拥有的工作与资源已按本库合同收尾。Mpv 关闭与已交付帧的释放分别遵守[播放资源寿命](../projects/libmpv-node/lifecycle.md#ownership)；Kisaki 会话还要回收自身持有的显示引用并完成记录收尾，旧内容的回调不得修改新目标。稳定源位置和播放秒数可以进入持久记录，DOM、GPU 资源及临时 URL 只用于运行期间。

技术库按自己的合同报告错误，Kisaki 接入将其映射为安全的业务失败。纯类型、校验能力和浏览器运行入口按各自环境导出，消费方不复制阅读或播放内核。

<a id="reading-values"></a>

## 阅读持久值的映射与兼容

Kisaki 的 desktop-contracts 定义 [ReadingPosition、ReadingTextSelection 和 ReadingPageRegion](../domains/reader.md#values)，负责它们的字段、持久编码、合法性和兼容规则。持久类型不导入或别名引用 Kana 类型，存储也不把 Kana 返回对象的全部字段当作格式。Kana 的公开合同不依赖 Kisaki，技术句柄不进入正式记录。

Kisaki 的持久值采用本页明确规定的源寻址、计数和几何语义。阅读接入同时理解双方合同：结构、单位和含义一致时直接对应字段，有差异时在接入处转换。源解析和恢复仍由 Kana 执行。

既有地址按保存时的编码、单位与规则解释。Kana 出现不兼容变化时，定义新编码及旧值处理方式，再由 Kisaki 按自身持久合同决定接入。库升级本身保留正式记录，具体规则见[定位兼容](../domains/reader.md#stability)。

格式非法、编码未知、目标缺失或地址越界时，定位返回对应失败并保留原值与已保存内容。源文件改写可能使位置失效或改变它指向的内容；恢复以实际源地址为依据，用户通过原有编辑操作处理失效位置。

Kisaki 保存 fileId、原文、批注、图片和个人记录，Kana 负责源内容、位置及标记呈现。接入沿用两者各自的身份和资源合同。

Kana 格式测试覆盖合法与损坏边界、固定 KF8、不同编码、跨节点和章节的完整选区、页面成员歧义，以及资源释放；不同内部文本分片须能恢复同一合法源字节地址。Kisaki 另行验证业务值映射、保存后重开、Annotation 留存和实际会话生命周期。

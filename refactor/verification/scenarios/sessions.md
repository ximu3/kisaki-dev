# 游戏、播放与备份验收

验证同一产品会话中的目标、控制、计时与完整收尾。

环境、证据与完成条件见[验收标准](../acceptance.md)，各场景引用对应设计规则。

<a id="targets"></a>

## 目标选择与记录保存

A10–A12 验证共同目标选择：没有活动会话且未显式指定目标时，首选 A 优先于最近使用的 B；明确“继续 B”仍打开 B。已有会话按复用规则处理，首选不可用时报告问题并明确选择替代，不静默改用历史目标。原生界面、SDK、deeplink 与后台使用相同输入时遵守同一顺序。

A10–A12 和 A27 验证[记录保存节奏](../../design/domains/sessions.md#timing)：四类会话的已确认时长或位置变化按 5 秒周期保存，没有变化时不产生写入；周期内最后一次位置变化即使没有后续进度事件，也须正常提交。活动区间收束、切换实际文件及会话结束时立即保存最后确认值，不能等到周期结束。多次保存只更新同一活动的绝对累计值，不增加活动数量或重复时长，未确认的暂离间隔不写入；UI 计时不随写入节奏跳动。

<a id="clock"></a>

## 系统校时与活动区间

A10–A12 和 A27 按[时钟映射](../../design/domains/sessions.md#clock)使用可控制的 UTC／单调时钟验证回拨和前跳。旧区间在最后可信采样处结束，间隙不计时；计时条件仍成立时，新区间采用当前 UTC，sessionId、文件和用户暂停状态保持。累计为两个区间已经确认的有效时长之和，不因 UTC 重叠重复补入或因前跳填满空隙。

容差内采样沿同一锚点，1,000 毫秒边界按合同判断，不随每次采样移动活动起点。暂离等待中校时不补计等待；暂停中不制造新区间。已保存历史、完成记录、最近使用和跨日统计保持各自口径，旧 UTC 暂时晚于当前系统时间仍可读取。保存失败重试沿用固定检查点，不重新采样后改写旧结果；校时不发布会话结束或自动备份事件。单调时刻失效按观察中断处理。

<a id="games"></a>

## 游戏启动、监测与结束

### 启动配置、监测与确认

A10 验证监测目标的填写：从内容目录创建配置时，目录监测目标自动填入该目录，保存后形成正式字段值；改变或移除目录登记不联动改写配置。其他新建情形在用户未填写时保持目标未设置，选择启动文件、修改完整命令或工作目录均不自动填入。空目标可保存为未完成配置，启动前要求补齐，不使用隐藏推导；不提供查看当前匹配结果入口。

A10 验证已有运行的处理：除同一游戏的会话复用外，监测范围内已有匹配进程时，不发送启动请求、不建立会话，也不补记此前时长，该进程是否被其他游戏观察不改变结果；范围外的平台客户端不因此阻止启动。同一游戏已有本体会话时，重复打开返回原 sessionId，保留有效时长和计时暂停状态；明确请求另一配置时，报告已有运行，不能假称已经切换配置。暂停与恢复计时不解除进程观察，也不补记主动暂停区间。

A10、A29 验证[开始游戏反馈](../../design/ui/components.md#game-start-feedback)：可开始状态、启动确认超时后及游戏结束后的主按钮文案均为“开始游戏”。启动确认超时的 Toast 准确说明请求已发出但未检测到匹配进程，action 打开本次实际配置，不改用后来设置的默认配置；主按钮不切换为编辑动作。保存配置只保存，不自动开始游戏；没有会话时不出现关闭或强制终止入口，再次开始仍检查已有运行。

A10 验证文件、链接与完整命令三种启动方式。命令中的参数、引号和操作符按约定解释器语法处理，不经应用自行拆分，也不存在另一份参数字段；明确工作目录独立影响执行环境。目录监测覆盖子目录并排除仅有相同路径前缀的兄弟目录，多个匹配进程自动进入集合，不弹主进程选择。启动器先退出而其他成员仍存活时保留会话，任一成员前台均可满足进程前台条件，多个成员不能成倍增加时长。常驻辅助程序如实影响运行判定；已结束会话不会因后来出现匹配进程而恢复。

A10、A23 和 A33 验证完整可执行文件名的匹配：Game.exe 不命中 GameHelper.exe 或 Game，不同目录下的同名程序均可命中进程方式；Windows 名称比较不区分大小写，macOS 和 Linux 区分大小写。原生库保留完整名称、扩展名与实际大小写，不以截断的系统显示标签替代；完整名称未知时准确表达。已纳入的同一真实实例在名称、路径变化或这些字段暂时不可读时仍保留成员身份，实际退出后才移除；同时继续接纳新匹配成员，观察未知时不伪造退出或累计时间。

A10 验证 Windows 命令固定使用系统 cmd.exe，macOS 和 Linux 固定使用 /bin/sh；命令可以显式调用 PowerShell、bash 或 zsh，不增加解释器选择，不跟随终端默认配置。只有命令配置提供工作目录，未填时采用用户主目录，从内容目录创建时只复制初值；明确目录不可用时不替换，不从命令或监测范围猜测目录。启动最多等待 120 秒，配置选择不消耗该预算，取消或超时不杀死已启动内容；连续可靠空集合 5 秒才确认退出，成员出现和观察未知分别中止该次确认，空集合区间不计时。关闭的 10 秒包含退出确认，但不截断实际退出后的必要保存和资源收尾。

A05、A10 和 A29 核对 GameLaunchUnconfirmed：系统已接受启动请求，但确认等待结束或必要观察失败使会话未建立时，原生与 SDK 返回同一错误码和安全说明，不附带 partialResult，也不发布 sessionStarted。请求发出前的输入或系统请求失败保留自身分类；主动取消与实例失效保留 Cancelled／InstanceExpired 等实际结果，不改成确认超时。任何未确认结果都不触发自动重试或终止未知进程。

### 并发操作与共享进程

A10 验证同一配置建立中的重复 open 只发送一次启动请求，明确另一配置时不排队启动。相同结束操作重复调用不重发请求或刷新预算，各等待者的取消不取消其他调用。明确 terminate 可以立即接替 close，旧调用准确结束且不再发出普通关闭请求；新操作按自身预算执行，同一会话仍只提交一次结束事实与记录。两个会话对共享进程并发正常关闭时只发送一轮实际退出请求，一方强制终止共享成员不把另一方范围内的其他成员自动升级为强制终止。

A10 验证目录、文件、进程三种监测均观察全部匹配实例。两个规则仅有潜在重叠时不阻止启动；后出现的共享成员可以参与两个会话计时，每个会话只计一份时间。结束其中一方直接处理其当前范围，不增加跨会话确认；另一方根据共享成员的真实退出和自己剩余成员继续或结束，不被直接标为结束。重复请求遇到已退出成员时遵守成员级结束规则，各会话不重复保存或触发备份。

### 观察失败与结束范围

A10 验证观察失败分类：存活已确认而前台未知时，前台计时暂停，运行计时仍依据存活事实继续；必要进程状态未知时不累计、不按空集合处理。临时故障持续时不按次数或时长自动结束，恢复后保留原计时方式和用户暂停状态，不补未知区间。必要观察能力明确失效才以 interrupted 收尾，不宣称游戏已退出、不自动终止进程或触发退出备份；观察仍正常时，截图、聚焦或关闭失败不结束会话。

A10 验证动态集合的结束：固定截止时间内新确认的范围内成员也被处理，成员出现不重置等待预算；取消、超时和完成后不再发送新的请求，范围外进程不被连带纳入。正常退出请求不反复作用于同一进程或其新弹出的保存确认窗口。覆盖关闭 A 后 B 自行退出、检查 B 后但请求发出前 B 退出、底层失败后确认原实例已退出，以及旧 PID 被新进程复用。确认已退出视为成员完成，真实权限拒绝与状态未知仍被准确报告；集合只结束一次，活动与备份不重复提交。

### 结束入口与反馈

A10、A29 验证[游戏结束入口](../../design/ui/components.md#game-end-actions)：运行中主按钮请求正常关闭，等待时显示忙碌；超时后，原按钮仍执行普通关闭重试。强制终止位于独立危险操作或既有菜单，并可由对应 Toast action 触发，用户明确选择后直接执行。

连续点击原按钮保持同一副作用。Toast 消失后菜单仍可强制终止，正常关闭等待中也可明确选择。游戏退出后撤下强制入口和旧 action，旧提示始终绑定原会话；仅记录保存失败时不显示强制终止，关闭面板也不结束游戏。

<a id="shutdown"></a>

## 共同退出与保存失败

A10–A13、A29 验证[共用退出流程](../../design/ui/navigation.md#shutdown)：四类作品同时使用、同一作品多个文件会话及只有非游戏会话时，均由同一界面按会话显示进度与问题。未保存检查被取消时不开始后续内容关闭；继续等待不重复发出已发送的关闭请求，取消退出不重开已经结束的内容。返回内容定位实际会话，游戏项的明确强制终止不跳过其他类型的结束与收尾，也不向其他类型添加强制终止按钮。内容已结束但保存或释放失败时准确显示阶段，不显示虚假运行或强制终止入口。各参与者不重复发送关闭结果 Toast，更新重启只有在相同完整退出条件满足后才继续。

A10–A12、A27 和 A29 验证[最后记录保存失败](../../design/domains/sessions.md#pending-recordings)：本次 close 拒绝，已经提交的记录保留，剩余单位进入运行内快照；实际会话结束、资源释放，get 返回 null，结束事件保留真实原因与 recordingError。进行中的重复 close 等待同次结果，结束后幂等完成；重试保存使用明确的 recordings.retry，不重发结束事件或备份。退出与更新重启等待用户重试、明确放弃或取消退出，具体后续操作按下方未保存记录场景验证。

<a id="game-ui"></a>

## 游戏窗口、快捷键和采集

A10、A17 和 A29 验证游戏窗口与截图：目标按当前前台、最近实际前台、唯一窗口和必要选择的顺序确定，面板不冒充游戏窗口，取消选择不结束会话。最小化目标先恢复，不能用固定延时或请求已发出冒充画面就绪；恢复、权限或采集失败时不换截其他目标。先固定真实原图再裁剪，编辑期间游戏画面变化不影响裁剪输入，取得原图后游戏退出仍能继续编辑保存，标注最终采用实际裁剪结果。

A10、A20 和 A29 验证游戏系统快捷键：默认面板切换为 Shift + F8，新建截图标注为 Shift + F9，其余游戏动作默认未绑定，不使用 Ctrl 或 Shift + F10 作为游戏默认组合。自定义、清空、注册失败和游戏会话结束后的释放都保留准确状态；不另行拦截游戏的 Ctrl 按下或释放事件。窗口内编辑快捷键不被游戏默认组合规则误禁。

A10、A20 和 A29 验证多个游戏的面板各自按需创建，同一会话不重复建窗，各面板的草稿、折叠和显示状态独立。托盘分别打开活动游戏面板；关闭面板不结束游戏，活动会话可重新打开。会话结束后，没有未保存编辑的面板无论显示、隐藏或折叠均自动关闭并移除入口，不提供保留开关或已结束面板列表。未保存编辑只处理一次关闭检查，保存成功或放弃后关闭，继续编辑或保存失败时暂留原面板与入口；草稿处理完成后关闭，不恢复会话、补计时长或丢弃内容。前台共享进程对应多个会话时明确选择，前台面板直接定位自身会话，不向多个游戏广播动作。

A10、A11、A12 和 A29 验证[使用与位置操作](../../design/ui/components.md#local-actions)。游戏启动按钮不显示配置标题，多配置通过右侧下拉明确启动，临时采用 B 不把默认 A 改成 B；运行期间修改默认不切换已有实例。四类作品使用单个目录图标，零目录不可打开、单目录直接打开、多目录显示全部登记路径。打开目录不受配置或文件首选影响，也不生成会话。失联项不静默替换，文件位置入口使用实际文件，配置工作目录入口不改用启动文件目录。

## 文件切换的结果与已完成阶段

A05、A11、A12、A20 和 A27 按[FileSwitchResult](../../design/domains/sessions.md#switch)分别验证动画、漫画和小说。原生调用、IPC 与 Node SDK 使用同一判别值和失败结果，测试通过实际会话与持久记录核对，声明检查只证明形状。

| 场景 | 预期结果 |
| --- | --- |
| 目标仍为当前文件，可选定位成功 | ready 携带原 Session，身份不变，不重发开始或结束事件 |
| 目标准备失败，或已经被另一会话使用 | 操作失败且没有 partialResult，本次不结束旧内容 |
| 旧上下文收尾成功，新目标加载与定位就绪 | ready 携带新 Session；旧 replaced 先于新 sessionStarted，各一次 |
| 已离开旧文件，新目标加载、定位或呈现失败 | 失败携带 previousEnded、原 sessionId 和本次 targetFileId；旧 get 为 null，没有新 sessionStarted，不自动重开旧文件 |
| 旧内容已结束，最后记录保存失败 | RecordingSaveFailed 携带 previousEnded；已提交值保留，其余进入原会话的待保存快照，新会话不发布 |
| 原内容结束后必要资源清理失败 | 按实际错误及 previousEnded 报告；其他清理继续，未释放资源和占用仍由原拥有者管理，不把结果形状当作清理已完成 |
| 离开旧文件之前取消 | Cancelled，不带 previousEnded，不因取消结束仍有效的旧会话 |
| 离开旧文件之后、发布新会话之前取消 | Cancelled 携带 previousEnded；等待必要收尾，清理未交付的新目标资源 |
| 新会话已经提交后发生迟到取消 | 保留 ready 与已建立会话，不将成功改成取消或关闭新内容 |
| 失败后再次明确打开目标 | 使用对应 open；旧结束事实不重发，旧 sessionId 的切换请求不转向新会话 |
| 结果交付前连接丢失 | 沿 ConnectionClosed 及未知结果合同处理，不构造未经确认的 ready／previousEnded 或自动重放 |

previousEnded 只用于失败的合法部分结果，不能作为正常完成返回；缺少就绪 Session 的值不得进入 ready。类型反例另覆盖跨媒介 Session、缺少原会话身份，以及将 previousEnded 当新 Session 使用。

<a id="playback"></a>

## 播放控制与配置

A05、A11 和 A27 对[PlaybackSettingResult](../../design/domains/sessions.md#playback-setting-result)验证跨 IPC／SDK 的完整传递：记忆轨道、字幕缩放、音量、静音和文件同步偏移保存成功但采用失败时，收到 PlaybackApplyFailed 及 saved 部分结果，实际范围、值和文件均属于原调用。保存失败没有该部分结果；保存后取消或目标失效保留原分类与已保存事实。不记忆选轨成功返回 applied 与 saved: null，不能以 saved 分支正常返回而显示全部完成。运行观察保留实际采用值，不用于反推保存结果。

音量和静音按[独立播放控制记忆](../../design/domains/preferences.md#fields)核对首次使用、关闭重开与换文件：初始 100% 和未静音，音量只接受 0–100 的有限数；单项调整保存到 preferences.playback，保留另一项及无关并发修改，只采用到当前执行者。其他已打开播放器保持实际状态，新文件读取正式记忆，同文件复用保持当前值。完整播放配置的保存或采用不覆盖这两项，原生观察、恢复与脚本操作不回写。

A11 验证 selectTrack 的临时选择与明确 remember 输入。选择并记住由 sessions 完整组织，覆盖保存失败、保存成功但采用失败，以及换文件或结束会话期间的旧请求；各入口行为不因来自 UI、SDK 或后台而改变。

A11、A18 和 A20 验证[快捷倍速](../../design/domains/sessions.md#playback-controls)：将当前文件调到 1.25 倍后，实际播放更新，全局、作品、文件配置均不改变，也不自动启用自定义。暂停、聚焦、定位及同一文件的普通复用保留 1.25 倍；下一集、切换文件及关闭后重开使用目标有效配置中的倍速，不能携带临时值或一律强制回到 1 倍。通过配置编辑器明确保存的长期默认值正常持久化并按采用规则生效，其他播放窗口不被联动。

A04、A11 和 A27 验证完整播放配置与快捷控制使用同一[参数值域](../../design/domains/preferences.md#fields)。倍速 0.01 和 100 可采用，小于 0.01 或大于 100 时拒绝；字幕缩放要求大于 0 且不超过 100。非有限数与越界值在产生保存或控制副作用前被拒绝，不能先保存无法采用的值，也不能钳制后报告原值已经生效。

A11、A18、A20 和 A27 验证[快捷字幕大小的即时保存](../../design/domains/sessions.md#subtitle-scale)：分别采用全局、作品自定义和文件自定义时，控件显示的范围与实际写入一致，只修改该来源的 subtitleScale；未启用的自定义保持原状，不被顺带创建或启用。当前播放器立即采用新缩放，其他打开实例保持原样；下一文件和重开按各自实际采用的配置读取保存值。临时倍速为 1.25 倍时调整字幕大小，实际速度仍为 1.25，已保存 playbackSpeed 也不变，字幕显隐、位置和轨道保持。

字幕缩放保存失败不继续采用，保存成功但采用失败不能显示为已经生效。配置来源失效、换文件或会话结束期间，旧请求不写入另一范围或控制新内容。初始恢复与引擎观察不触发偏好写入，原生、SDK 和后台采用相同规则。

<a id="playlist"></a>

## 播放列表与自动已看

A11、A18、A19 和 A29 验证[作品级播放列表](../../design/domains/anime.md#views)：从详情页主按钮、分集行、文件行或深链打开后，播放器均可浏览当前作品的完整资料和文件。资料视图中的同集多个版本保持在同一项内，文件视图中的合订及不同版本各按实际文件列出且不重复。两处保留分类、完成状态等适用筛选，各自修改不影响另一处；切换查看方式和筛选不切换视频、不重置位置和时长、不修改首选。

只显示未看的第 3、5、8 集时，主按钮仍按正式继续或默认目标打开；从第 3 集执行下一集明确指向完整顺序中的第 4 集，不能跳到第 5 集。文件视图显示“下一文件”并采用完整文件顺序，不把同集版本记成多个分集。资料新增、种类更正和重排后正常刷新列表，已经发出的目标请求保持原引用并重新核对。覆盖下一项位于未加载区间、被筛选隐藏、没有文件、失联、目标变更或仍为同一合订文件的情形；失败不静默跳过。复用原播放器保持查看方式，跨作品切换不沿用旧作品筛选。

A11、A18 和 A27 验证[分部自动已看](../../design/domains/anime.md#auto-completion)：单集、附加内容和关联多集的合订视频达到整文件 90% 实际覆盖后，分别更新全部适用的直接关联分部标记；文件活动与时长只记录一次，不建立逐集时间段、分部完成日期或作品完成记录。主按钮、分集行、文件行、深链及两种查看方式采用相同目标，筛选不减少目标。同一文件的复用不重开覆盖累计，真正重开后重新累计，跳转到末尾不代替实际观看。

本次播放中用户明确更正过的分部不会被自动写回，其他关联分部仍可正常标记。没有关联时不补造分部或转为完成作品。零分集影片播放到末尾、全部分集已看、作品已完结且资料齐全，均不自动新增作品完成记录；用户明确记录本次完成仍可正常保存，也不要求先看完全部附加内容。个人状态的明确编辑与来源采用不被此播放规则禁止。

<a id="backups"></a>

## 自动备份与保留数量

A10、A13、A16 和 A27 验证[自动备份接纳](../../design/domains/backups.md#automatic)：游戏启动时开启、处理结束事实前关闭时不接纳新备份；启动时关闭、结束时开启且本次来源明确时，可以接纳合法备份。始终核对事件对应的同一启动配置，切换首选不改变开关来源，修改配置路径不改变会话的 saveSource。当前配置不存在时不新接纳，读取失败不能伪装为关闭；开关已启用但本次缺少来源快照时报告问题，不使用当前路径替代。已接纳工作即使仍在准备或等待同路径执行，也不因之后关闭开关而隐式取消，仍可按自身合同明确取消。

A13、A18 和 A27 验证[备份保留数量](../../design/domains/backups.md#retention)：默认 5，正整数可保存，留空保存为 NULL 并且不因数量清理。0、负数和小数拒绝保存，各入口使用同一规则；不把 0 当作关闭自动备份。保留数量为 1 时，新备份登记成功后才清理同一来源的旧未锁定备份，锁定项不占名额，创建失败仍保留全部旧备份。

<a id="detach"></a>

## 明确停止游戏记录后退出

A10、A20 和 A29 验证游戏仍运行时选择“停止游戏记录并退出”：先完成草稿检查，保存已确认活动，再结束管理；不发送 close／terminate，不等待外部进程退出，不触发自动备份。sessionEnded 只发布一次，reason 为 detached，旧回调不再写入，其他播放与阅读会话正常 close。

保存失败时拒绝脱离，保留会话与观察供重试，不转入已结束内容的待保存集合，也不能自动丢弃记录后退出。未保存检查被取消时不开始脱离；提交后的迟到取消不重新接入会话。已有结束请求尚在发送时返回 Busy，结束该请求后再明确脱离，已发系统请求不被描述为撤回。重启后不自动接管残留游戏，也不为其补算活动或补发 exited。

最终区间捕获、同步提交与回调失效之间没有异步间隙；提交后到来的观察不再增加时长。资源清理失败时显示记录已停止而收尾未完成，保留必要句柄与占用；再次 detach 只重试清理，不重复保存或发送退出请求，全部释放后只发一次 detached。取消应用退出不把已经脱离的游戏重新接入。

<a id="pending-recordings"></a>

## 最后记录保存失败后的处理

A10–A13、A20 和 A27 验证[运行内快照](../../design/domains/sessions.md#pending-recordings)：实际内容结束后故意使最后活动或位置提交失败。Session 从运行列表消失，资源释放且 sessionEnded 只发生一次；原生未保存记录入口仍能看到该 sessionId 的剩余内容，关闭来源窗口或重载 renderer 不清除它。

| 后续操作                                   | 通过条件                                                                                          |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 修复存储问题后重试两次                     | 原活动 ID、结束时间及绝对时长不变；首次成功后再次调用没有写入，统计不重复增加。                   |
| 活动已保存，文件位置失败                   | 结果分别说明两部分；再次重试只写位置，不重建活动，已提交事实不因失败回滚。                        |
| 同一文件已建立后来会话，或用户已经改过位置 | 新使用正常继续；旧位置为 PositionSuperseded，不覆盖新选择；原活动仍可保存，剩余旧位置可明确放弃。 |
| 用户已编辑待保存活动，或尝试删除被引用文件 | 活动重试报告 Conflict 并保留快照；删除返回 PendingRecording，先处理快照；无关元数据编辑不受阻挡。 |
| 重试期间取消、重复点击或明确放弃           | 当前短提交按真实结果结束，重复等待同次处理；只放弃剩余单位，已经提交的内容保持。                  |
| 退出或更新重启                             | 有剩余快照时等待重试、明确放弃或取消退出；不能自动丢弃，处理成功后不重发游戏退出或自动备份。      |
| 主进程异常终止                             | 仅数据库已提交事实保留；本测试不要求跨重启恢复内存快照，也不把丢失值报告为已保存。                |

## 存档归档与内容摘要

A13、A14 和 A27 按[ZIP 与版本化清单](../../design/domains/backups.md#archive-format)核对普通文件、零字节文件、目录、空目录和含中文的嵌套路径。ZIP 成员与 manifest 逐项相符，压缩方式、成员顺序及 ZIP 时间字段变化不改变 treeDigest；源字节、文件名、大小写、Unicode 组合形式、空目录或文件／目录种类变化则按确定编码改变摘要。只修改来源文件的修改时间，不因其变化建立新的内容摘要，也不在恢复后声称还原了该时间。

分别以真实空目录、零字节文件及仅含零字节文件的目录作为手动、自动和恢复保护的来源，验证它们沿同一归档、摘要、结果与恢复规则处理；允许跳过未变化时，仍须有同一来源的可用备份。来源不存在、不可读、部分枚举或读取期间变化均失败，不产生伪造的空归档。空状态同样参与普通保留规则，锁定备份继续按既有规则保留。

未知格式／版本使用 UnsupportedBackupFormat，版本 1 的缺项、额外成员、重复键／成员、错误类型、损坏字节或不符摘要使用 DataIntegrityError；真实读取失败仍单独报告。恢复到不能表示某名称或产生大小写／规范化冲突的目标时，在修改用户存档前失败，保留原归档和目标。验证 ZIP64 的真实较大输入与资源预算，不能靠头部声明冒充已读取完整内容。

内容树摘要由归档创建、已有备份比较、恢复前后检查和 basis 共同使用。逐项比较清单、实际字节与数据库 tree_digest／unpacked_size_bytes，不能只比较 ZIP 的 CRC 或附件摘要。升级应用后读取版本 1 归档仍采用其原编码规则，未知版本不按空存档继续。

## 存档恢复中断与保留现状

A13、A27 和 A28 按[恢复合同](../../design/domains/backups.md#recovery-verification)使用隔离文件与目录。至少在旧目标已经移走但阶段未更新、新目标已经就位但数据库未提交，以及撤回的两次移动之间终止进程；重开后按实际内容选择继续或撤回，并核对原目标、选定备份及保护材料的字节。

外部程序在中断后新建或改写目标时，恢复不得覆盖新内容；“保留现状并结束恢复”只改变处理结果，目标与全部材料保持，后续启动和恢复解除阻挡。修改 basis 后发出的旧请求返回 Conflict，正在进行的恢复不接受 keepCurrent；已完成索引不重放写入。清理只针对已核实的本体材料，额外或被修改文件保留。

恢复索引、任务历史和资料根备份分别验证：清理 TaskRun 不移除材料，重启不自动继续，外部卷或工作区失联时显示不可核实。各目标平台核对“不覆盖移动”原语、刷盘与失败分类，进程中断证据不能代替掉电或其他文件系统验证。

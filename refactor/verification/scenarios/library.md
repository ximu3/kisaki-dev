# 资料库、记录与标注验收

验证真实持久读写、完整操作与查询口径。

环境、证据与完成条件见[验收标准](../acceptance.md)，各场景引用对应设计规则。

<a id="completion"></a>

## 当前状态与完成记录

摘要统一使用 completionCount、firstCompletedDate 和 lastCompletedDate。未知日期只影响两个日期投影，不减少次数；Part 查询只返回自身完成标记，不提供逐次完成历史。字段名在领域读取、列表投影、SDK 和生成声明中一致。

完成记录写入核对真实 Work 目标：以合法引用形状指向 Person 等非作品 ID 时，完整操作拒绝并保持数据库原样；普通 Entry 外键的存在性不代替目标类型校验。

A04、A05、A18 和 A27 验证[作品完成记录](../../design/domains/records.md)：三种当前状态及 null 与完成历史独立，active 与多条完成记录可以并存。CalendarDate 必须有完整合法年月日，空日期和空备注不使记录失效；不接受可写 completed、dropped、完成次数或分部完成日期。记录本次完成的新增与清除当前状态在同一事务成功或失败，补录保持当前状态，编辑和删除使用稳定 ID。清空日期保留事实，删除最后一条只撤回完成情况，不改活动、位置或分部标记。

A04、A05、A22 和 A27 验证[新增记录的历史数量基线](../../design/domains/records.md#creation-baseline)：create、createMany、recordCurrent 和 recordCurrentMany 只接受所属作品的 completionCount 比较，不接受其他作品或无关字段。读取时为零而提交前已有记录时，条件新增整体失败；记录本次完成的单条与批量操作均不清状态。为同一空历史初始化三条记录时，基线在批次新增前核对一次，不能插入第一条后阻挡其余两条；相同作品的矛盾基线被拒绝，未提供基线的项目不取消其他项目的条件。未提供基线的普通新增保留原有追加语义，数量投影不成为可写字段、完整历史版本或防重机制。数量基线符合也不跳过目标与归属校验。

完成记录的[批量输入](../../design/domains/records.md#batch)复用单条日期、备注和数量基线。recordCurrentMany 对兼容的重复作品输入只执行一次动作，矛盾日期、备注或基线使整批失败；任一目标失败时，其他目标的新增与状态清除也不提交。createMany 保留同一作品的多条独立事实，包括日期与备注相同的输入。界面共同日期和备注仅用于填充各项目，两种批量结果分别与去重后的作品或原始记录项目对应。

批量当前完成和补录按固定、去重后的每部作品各新增一条，已有历史不跳过。筛选结果因修改而变化时，本次目标不扩大或减少；必要目标失效时短批次整次不提交。分部只设置或清除布尔标记，全部已登记分部完成不产生作品历史，后来新增分部也不撤销旧完成事实。

A04、A19 和 A27 验证[完成查询与统计](../../design/domains/library-queries.md#completion-records)：同一作品在 2024 年有两条已知日期记录，另有一条日期未知记录时，该年为两次完成、一部作品，累计为三次。未知日期不落到创建或导入当年；日期修改后按新的实际日期归组。当前状态与历史条件可以组合，日期与备注的条件须由同一记录满足；关系连接不重复计数。最早和最近已知日期分别取非空日期的最小值和最大值，历史日期降序、未知在后；排序变化不改变编辑目标。

## 合并与个人资料

A17、A18 和 A29 验证[固定合并规则](../../design/domains/library-operations.md#identity-operations)：A 并入 B 后保留 B 的当前个人值，包括 null、false 和 0；完成记录保留 ID、日期和备注迁入 B，同日记录不自动删除，合并不另增完成。分部保留各自身份与标记并迁入 B；后续只有明确分部合并才整合标记，不能按同名同号自动对应。合并只选择对象和保留方，不提供字段差异编辑或记录取舍预览；不能合法提交时完整失败。

<a id="relations"></a>

## 关系与角色

A03 验证作品联系从两端读取和编辑同一身份，正反表达及对称关系不能重复保存。两端排列独立；更正类型、合并条目或规范方向时，顺序仍跟随实际作品。更新某作品的明确关系范围只影响与它直接相连的所选事实，删除同一关系后两端都不再显示。普通关系更正遇到重复业务键时保存失败并指出既有关系，不自动合并；明确条目合并产生重复关系时按固定说明与剧透规则处理。

配音资料只记录作品正式采用的原作语种角色—声优关系，译配不进入人物工作关系，也不转换为 other。按作品归属与配音语种判断，不以首发时间截断。来源适配须按明确语种或已确认的来源采用约定取得名单，未标语种的缺省和资料质量限制须与来源设计一致；声优母语和界面语言不作为筛选依据。VNDB 未标语种时按作品原语种采用，明确标注其他语种时排除，括号中的版本说明不能覆盖明确语种。

A01、A03、A05 和 A27 验证[角色范围](../../design/domains/catalog.md#characters)及 [Bangumi 的类别采用](../../design/extensions/sources/bangumi.md#characters)：非人角色可以正常编目，不要求补填人体资料；普通机体、舰船与虚构组织不自动进入条目或关系。搜索、resolve、直接读取与关联名册都只采用来源 type = 1；当前页全被过滤且来源还有后续页时继续读取。来源类型缺失不默认角色，作品内定位不代替对象类别，被排除对象的配音不改写成无角色工作。

## 动画种类更正

A01、A11、A18 和 A27 验证[动画内容种类更正](../../design/domains/anime.md#kind-correction)：现有编辑器只显示所选种类的适用字段，切回时恢复未提交编号，不增加旧值展示、说明或转换确认。一次保存完成共同资料修改和种类更正，保留 ID、创建时间、来源与附件引用、文件关联、首选和分部完成标记；目标列表追加，其他项目顺序保持。Extra 不保存或自动转写分集编号，目标分类使用明确值或 NULL。

已有活动中明确指向该内容的记录自动修正分类，时间、时长、文件和记录身份不变；仅文件范围及其他内容的活动不受影响，作品总时长与完成次数不增加。来源身份冲突、相关基线变化或关联文件正在使用时，整次不提交。成功返回新 PartRef，并以一次 partKindChanged 表达更正；资料列表采用新种类，已经发出的旧引用请求不能静默转向另一种类或跳过目标。原生与 SDK 的效果一致，失败不留下半份迁移。

<a id="values"></a>

## 逐值读写

A04、A18 和 A27 验证[宽容读取、严格写入](../../design/domains/values.md#read-write)。混有非法项目的别名或相关链接列表保留合法项目与原顺序，无法解析的列表读为空；非法部分日期整值读为 null，不拼补分量。单个普通偏好字段异常只采用该字段默认值，其他字段和配置组仍可读取。无效扫描或查询定义仍可展示问题并修正，但不能按空限制执行，也不阻断其他有效配置和资料的读取。读取前后的原始保存值不变，修改独立字段不覆盖其他未修改的异常值；提交非法项目或分量时拒绝该次写入，不静默筛除后报告成功。

<a id="activity"></a>

## 活动、附加时长与统计

A04、A18、A19 和 A27 验证四类作品的[活动编辑](../../design/domains/library-operations.md#activities)：没有本地文件或配置时，仍能补录明确时间段；补录 30 分钟、更正为 15 分钟、再删除后，列表与累计时长依次反映实际记录。非法时间段或超出区间长度的手动时长按普通校验失败，草稿保留。当前仍在计时更新的记录不能手动修改或删除，其他已结束记录不受影响。活动编辑保留上下文，不改变作品完成记录、位置或当前会话；最近使用采用发生时间，四类作品没有日期的附加时长不进入日期统计，也不被补录自动扣减。原生界面与 SDK 的结果一致。

A04、A18、A19 和 A27 分别在游戏、动画、漫画和小说验证[附加时长](../../design/domains/records.md#duration)：四张当前记录表及 record.additionalDurationMs 使用相同非负安全整数毫秒规则，缺行读取 0，显式零、未知和非法值不混淆。新作品初始采用、已有 3 小时活动采用 10 小时总量后附加值为 7 小时、增加 1 小时活动后总计 11 小时、再次明确采用 10 小时后附加值为 6 小时，均通过原生和 SDK 完整写入。覆盖较小来源总量不采用、重复源键与多书归集、溢出、相关基线冲突及固定绝对值重试；默认保留已有值，不生成概况笔记。详情编辑、库排序及无日期累计包含附加值，日期图表、活动条数、单次统计和最近使用不包含；合并保留目标值，分部不新增附加时长。

A19 和 A27 验证[活动统计口径](../../design/domains/library-queries.md#activity-statistics)：23:30–次日 00:30 的活动按 60 分钟或 30 分钟有效时长，分别在两天计入 30 分钟或 15 分钟；只查询其中一天时只返回该日份额。两个作品同时各使用一小时，总计两小时。跨日活动的原记录不拆分，整段查询的记录数为一条；分组计数不能相加代替总记录数。切换显示时区后按新日界分组，原 UTC 值不变；非 24 小时的日界沿用真实日历。平均、最长、活跃日期与连续天数使用同一有效时长口径，四类作品附加时长只影响不限定发生日期的累计总量。修改或删除活动后，各统计入口结果一致，次数名称不混淆启动或完成。

<a id="use-and-records"></a>

## 实际使用与个人记录

A04、A10–A12、A18 和 A27 验证[实际使用与个人记录](../../design/domains/sessions.md#personal-status)：四类作品的打开、首次有效计时、继续、同文件复用、下一分部、文件切换和退出，都不自动设置或清除当前状态，不生成完成记录。当前记录原本不存在时也不为了使用而创建 planned 或 active。普通收录保持未设置，实际活动按自己的规则保存。

设置或清除当前状态、记录本次完成、补录和修改历史，都不打开、暂停、关闭或终止内容，不改文件位置、分部标记或游戏备份。结束后重新打开也不推进状态。片尾播放期间可以记录完成，后续真实活动继续保存；动画自动已看仅按分部规则执行。

## 书签、视频值与标注列表

A17 按[标注值合同](../../design/domains/annotation-contracts.md)验证四类创建目标、独立标题修改和完整 target 比较。文件删除后的标注可以读取及编辑文字；有效 fileId 不能被清空。list 的 scope、空 refs／workTypes、区间与稳定补序一致，定位投影不夹带正文和图片，内容索引取得完整集合后才宣称完整顺序。错误媒介坐标、跨作品文件与非法几何分别由声明、归属和内容值边界拒绝。

A11、A12、A14 和 A29 验证[书签的内容与辨认](../../design/domains/annotations.md#bookmarks)：添加书签同时保存点位和邻近原文或实际画面，不要求标题、颜色选择或截图确认。文字片段不变成选区高亮，可重排内容无文字时与文本读取失败分别处理；固定页面使用当时可见的内容画面，视频位置与截图来自同次采集。滚动、换文件和后续布局变化不改写已保存内容，源文件离线后仍可查看，缩略图不重新依赖源文件生成。续读变化不移动书签，统一标记与选中样式在不同阅读配色下保持可辨。

A11、A14 和 A27 验证[视频时间值及画面采用](../../design/domains/annotations.md#video-values)：0 和小数秒可保存，负数、非有限值、空范围和反向范围写入失败。在 12:40 取得画面，将范围设为 12:30–12:50 再修改时，图片不变；范围不再包含原采集时刻也不自动换图。明确重取同一文件画面只替换图片，不改写原范围；换文件后的采集不能误挂到旧目标。返回片段使用起点并显示范围，不自动循环或在终点停止。源内容变化造成实际定位失败时，仍保留历史范围、图片和批注。

A12、A14、A18、A27 和 A29 验证[标注字段与列表](../../design/domains/annotations.md#fields)：空白标题按 NULL 保存，批注保留 Markdown 有意义空白，显示名称不写回，完整摘录不因列表摘要而截短。无变化保存、打开内容、源文件变化及缩略图生成不更新时间，实际修改只更新 updated_at。全库与作品列表按创建时间稳定分页，编辑旧项不跳到首位；当前文件面板按完整内容顺序排列，同一位置和无法恢复的项有稳定顺序。覆盖编码字典序不同于实际文档顺序的阅读样本，以及标注很多、批注很长时的区间响应与按需读取，不能只重排已加载的一页。

## 重复分部的明确修正

A01、A05、A17 和 A27 验证[分部合并](../../design/domains/library-operations.md#part-merges)：同一作品的同类分部由用户指定保留目标；同名同号的普通新增和作品合并仍保留不同身份。以五类 Part 分别验证固定规则，漫画卷与话的收录关系增加各自断言。

| 输入或变化                                    | 通过条件                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------- |
| 目标有编号和资料，源有不同资料及额外来源身份  | 保留目标 ID、创建时间、顺序及已填写值，只补空；来源身份转到目标，后续资料读取仍找到目标 |
| 两端各有文件、首选和完成标记                  | 关联整合、重复配对去重；目标首选优先，完成取 OR，各文件位置与关联方式不变               |
| 卷合并，双方包含同一话及各自独有话            | 重复话保留目标侧属性，源独有话按原顺序追加；话身份不被合并                              |
| 话合并，双方同时属于某卷                      | 该卷只保留目标关系及其属性；其他卷重定向到目标                                          |
| 来源分部被活动与附件引用                      | 活动 ID、时长和快照保留；正式分部引用改到目标，附件按最终资料维护                       |
| 同一 ID、跨类型、跨作品、目标删除或文件被占用 | 按所属原因失败，双方、关系与历史均无部分迁移                                            |
| 提交中约束失败或成功后重读                    | 失败完整回滚；成功只发布一次 partMerged，受影响读取按正式引用更新                       |

界面与 SDK 使用同一操作，不生成自动候选对应或逐字段取舍。一次作品合并后再明确合并分部，验证两个完整操作各自成立，不能用合并分部隐式跨越作品归属。

<a id="organizer-merges"></a>

## 合集与标签合并的确定结果

A05、A17、A18 和 A27 按[整理合并](../../design/domains/collections-and-tags.md#merges)验证：目标手动合集成员为 [E2, E1]，源依次为 [E1, E3] 与 [E4, E3]，结果为 [E2, E1, E3, E4]。目标资料保留，空说明只取第一份非空来源；重复成员的不同备注按目标、源顺序保留，相同备注不重复。

标签合并时，条目原顺序 [S1, X, S2, Y] 且目标 T 不存在，结果为 [T, X, Y]；原顺序 [S1, X, T, S2, Y] 时，结果为 [X, T, Y]。目标标签原条目 [E3, E1]，源依次为 [E2, E1] 与 [E4, E2]，反向列表为 [E3, E1, E2, E4]。重复应用的剧透标记取 OR，备注合并不改变其他标签的相对顺序。

含动态合集的直接 merge 完整拒绝；用户先明确转为手动再合并，后续合并失败不撤销转换。源缺失、重复 ID、目标混入 sourceIds 或约束失败均不留下部分迁移。保存查询的参数随合并重定向并保持运算含义，分别发布 collectionsMerged／tagsMerged，不能将来源作为普通删除处理。

## 写入范围与编辑基线

A01、A02 和 A05 按[图写入值](../../design/domains/library-graph-contracts.md)验证七类 Entry、五类 Part、标签和初始登记的请求内引用。无主 key、错类端点、重复更新及互相矛盾的关系动作在提交前拒绝；任何最终写入失败均不留下部分图。替换关系只删除固定范围内且仍符合原快照的关系，在途新增关系保留，未修改属性不被无关基线阻止。动画业务分类与 PartRef.type 分开，已存在标签不会被 create 静默复用。

A02、A05、A14、A17 和 A27 按[基线目录](../../design/domains/library-write-contracts.md#expected)验证：标题与正文分别编辑可以共存；同一正文冲突整次不保存；关系端点或职责已改变时，旧说明草稿不能贴到新事实；Annotation 标题编辑不被无关定位阻止，重新选目标必须比较完整原 target。

标签替换核对其成员、属性和条目侧顺序；条目的合集替换只核对成员与备注，不创造每条 Entry 自己的合集顺序，也不受无关全局重排阻挡。关系排列必须使用真实关系 ID。完整排列与筛选子集重排都先核对完整原顺序，显式即时 move 按当前锚点执行；失效锚点不能偷偷变成末尾。

未知 expected 字段、createdAt／updatedAt 假版本、非 Work 的 record、写入派生总量或其他对象的条件均在边界拒绝。空操作、无变化和已移除关联按各自合同成功且不发伪事件；主体删除仍返回 NotFound。完整事务失败不带伪造的半结果，跨 IPC 保持相同 code 与合法 partialResult。

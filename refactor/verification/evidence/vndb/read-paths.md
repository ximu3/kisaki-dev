# VNDB 反向读取路径

验证日期：2026-10-13。依据 [Kana 查询合同](https://api.vndb.org/kana)完成三次匿名公开 POST 读取，没有连接用户账号或修改列表。[请求与完整响应](2026-10-13-read-paths.json)记录实际状态和返回值。

| 查询                                 | 本次结果                                                              | 可以支持的结论                                                        |
| ------------------------------------ | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| POST /vn，staff = [id = s81]         | 首项为 v11；s81 出现在 va，与角色 c39 对应，不在该 VN 的 staff 数组中 | Staff 反向筛选可以包含配音参与，实际工作必须从返回的具体关系读取      |
| POST /release，producer = [id = p15] | 首项为 r40，关联 v103，p15 同时带 developer 与 publisher 标记         | Producer 可以反查发行与关联作品；仍须另行应用已确定的开发发行采用范围 |
| POST /character，id = c42            | 返回 v11 的 primary、非剧透定位，以及 v50 的 appears、剧透定位        | 同一角色在不同作品中的定位与剧透值分别成立                            |

前两个请求的 more 为 true，只验证了首段请求和关系字段，不能据此宣称该主体的全部作品已经读取。第三个请求按唯一角色身份读取，more 为 false。数据文件不包含账号凭据或私人记录。

[正式读取路径](../../../design/extensions/sources/vndb.md#read-paths)统一正向与反向采用规则：反向筛选先产生候选，实际关系仍按每部作品的来源范围解释。原版职员、原作语种配音和选定发行批次不会因为从人物、组织或角色入口读取而扩大。

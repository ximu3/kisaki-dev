# Kana 跨引擎呈现机制对照

2026-10-20，本轮在已确认的[内容文档职责](../../../design/projects/kana/layout.md#documents)下，对照正常事件、内容 CSP、原生分页和多份展示投影。结果用于[浏览器与投影取舍](../../../design/projects/kana/layout.md#projections)，不自动改变终态支持名单。

## 实际运行环境

使用工具环境已经提供的 Playwright 1.62.1，复用既有 Chromium 测试包，将 Firefox 与 WebKit 测试包准备到被忽略的工作区缓存。没有安装到系统浏览器列表，没有改变默认浏览器、工作区依赖或锁文件。三个引擎都以无可见窗口的独立测试配置运行，页面没有 Node 接入。

| 引擎     | 实际报告版本  | 运行载体                                            |
| -------- | ------------- | --------------------------------------------------- |
| Chromium | 149.0.7827.55 | 既有 Chrome for Testing 缓存                        |
| Firefox  | 153.0         | Playwright 固定修订 1538 的 Firefox 测试构建        |
| WebKit   | 26.5          | Playwright 固定修订 2336 的 Windows WebKit 测试构建 |

包元信息、修订、实际可执行文件与脚本摘要见 [source-input.json](source-input.json)，运行观察见 [browser-contract.json](browser-contract.json)。Playwright 的 Firefox 和 WebKit 是其测试构建；WebKit 的版本字符串不等于已验证同号 Safari。本轮没有运行真实 macOS Safari、WKWebView 或 Linux WebKitGTK。相关载体边界见 [Playwright 浏览器说明](https://playwright.dev/docs/browsers#webkit)。

## 正常交互与内容执行限制

同一内容文档先后使用 allow-same-origin，以及 allow-same-origin＋allow-scripts 两组 sandbox 参数；两者都在书籍内容前建立同一 CSP。宿主控制代码从宿主文档加载，内容策略禁止书内脚本和自动网络访问，只允许本次提供的 Blob／data 图像等明确资源。

书籍夹具包含内联脚本、外部脚本引用、事件属性、未授权图像引用，以及正常按钮、链接、文字和一张由资源入口提供的图像。Playwright 发出真实鼠标点击，父级注册的监听器记录可信 pointerdown／click；没有以 dispatchEvent 伪造这些输入。

| 引擎            | 无 allow-scripts 时记录事件数 | 有 allow-scripts 时记录事件数 | 书内代码执行计数 |
| --------------- | ----------------------------- | ----------------------------- | ---------------- |
| Chromium        | 4                             | 4                             | 两种参数均为 0   |
| Firefox         | 4                             | 4                             | 两种参数均为 0   |
| WebKit 测试构建 | 0                             | 4                             | 两种参数均为 0   |

三者在包含 allow-scripts 的路径都保留正常文字、点击、80px 图像与资源入口提供的 Blob 样式表，书籍样式没有改变宿主背景。被夹具引用的外部脚本与未授权图像没有到达本机服务器，测试页面的外部请求也为零。没有系统剪贴板写入。

宿主 CSP 与内容 CSP 必须允许正常接入所需的资源形式：本次宿主允许 Blob 样式表，内容文档再限制自己的资源范围。只修改内容策略不能放宽继承的宿主限制；提供的样式表通过实际计算样式确认已经采用，而不是仅检查创建了 link 元素。

这支持按各自职责组合 iframe、CSP 和资源入口。WebKit 的旧参数事件差异与[上游报告](https://bugs.webkit.org/show_bug.cgi?id=218086)相符；它没有证明整个 WebKit 平台已验收，也没有把 sandbox 重新算作禁脚本的独立保障。正式文档转换、宿主权限接入和所有资源语法仍按既有合同验证。

## 单份展示 DOM 的原生分页差异

[probe.mjs](probe.mjs) 对每个引擎运行 13 组配置：普通横排，以及两种竖排下的普通分栏、分栏换行、两种嵌套分栏和两种 WebKit 扩展配置。每组分别检查显式分栏指令和 792 字符的自然流，两者不互相代替。

自然流逐字符读取 Range，核对源文字、几何、页序、400px 面高和 20px 间隔。判断间隔很重要：一条没有页间隔的连续竖排流，即使沿横轴溢出，也不被计作目标页面片段带。

| 范围                               | Chromium               | Firefox                | WebKit 测试构建            |
| ---------------------------------- | ---------------------- | ---------------------- | -------------------------- |
| 普通横排自动分栏                   | 满足本次片段预期       | 满足本次片段预期       | 满足本次片段预期           |
| column-height／column-wrap 竖排    | 满足本次片段预期       | 没有该能力             | 没有该能力                 |
| 嵌套分栏及 WebKit column-axis 竖排 | 本次配置未得到目标片段 | 本次配置未得到目标片段 | 存在满足本次片段预期的配置 |
| break-before:column 显式分栏       | 本次指令生效           | 本次版本未支持该值     | 本次指令生效               |

Firefox 的自然横排通过，与它没有执行显式分栏指令同时成立，不能概括成“不支持横排分页”。其显式分栏缺口另有 [Mozilla 549114](https://bugzilla.mozilla.org/show_bug.cgi?id=549114) 记录。WebKit 的 column-progression 值在本次不受支持，两个输入的效果相同；不能把忽略属性后的成功算成该属性通过。

这些观察没有穷尽所有可能的单 DOM 路线，也没有证明某个浏览器永远无法实现目标。它们说明当前已经选定的分栏换行机制不能直接当作三个引擎的共同实现。

## 一份源内容、两份完整展示投影

另运行三个 writing-mode × 三个引擎，共 9 个场景。每个场景将同一份受控源内容交给两个完整的内容文档；各文档都按一面大小进行普通原生分栏，分别显示相邻片段，再在宿主视图中按阅读顺序左右放置。没有将源内容按页切成两段，也没有为各引擎编写三套文字排版算法。

所有场景均验证：

- 第一面与第二面的可见源范围相邻，没有缺口或重叠。
- vertical-rl 的第一面在右，另两种模式的第一面在左，源顺序与物理位置分别保持。
- 在两份实际文档中调用 caret 命中，得到对应的源文字偏移；两个端点可以回到同一源内容中的一个连续范围。
- 字号从 20px 改成 28px 后，根据同一个源偏移重新取得片段和显示组，目标恰好在一面可见，两份源文字都没有改变。

这支持多投影的几何与来源对应机制。测试中的源值是自有文字节点 offset，没有执行完整 EPUB CFI、FB2 或 MOBI 绑定；也没有执行跨投影的完整指针拖选、复制、辅助技术内容去重、焦点切换或真实长章节预算。两份完整 DOM 的额外成本存在，不能因源内容共享就称其零开销。

多投影没有解决 Firefox 的显式分栏指令，也没有证明复杂 CSS、ruby、表格和跨类型页位的全部行为。后续已确认[分页支持边界](../../../design/projects/kana/layout.md)，作者 CSS 的该项缺口明确列为限制；其余已承诺阅读能力仍须完成验证，不以本次几何成功替代。

## 复现

```powershell
python -B refactor/verification/evidence/kana-browser-scope/prepare.py
node refactor/verification/evidence/kana-browser-scope/run.cjs
```

准备脚本只使用明确的隔离浏览器缓存，不执行系统依赖安装；运行脚本逐项关闭浏览器和本机服务。源码与实际输入摘要保存在运行记录中。共同输入不等于完整产品符合性测试，设计选择、机制证据与终态支持决定分别记录。

## 验证中修复的两处问题

第一次并行启动根工程和本体测试时，共用的工作区默认 Vitest 缓存在锁文件变化后发生清理冲突；[错误输出摘录](cache-initial.log)保留。检查了 [Vitest 的原生缓存选项](https://vitest.dev/config/fsmodulecachepath)和当前源码后，使用项目本地缓存路径。根、本体、tooling 三个进程随后在同一时刻并行通过，完整 pnpm check 也验证了 Turbo 调度下的运行；没有关闭缓存或增加跨命令锁。

第一次完整开发回归在主进程配置变更处失败，见 [development.log](development.log)。原因是首次采用依赖触发 Vite 重启后，原先添加的非 renderer 监听路径没有重建。改由 [configureServer 生命周期](https://vite.dev/guide/api-plugin#configureserver)注册后，原有完整场景全部通过；没有降低超时检查、删除断言或缩小场景。

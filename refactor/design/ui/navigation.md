# 页面导航、应用入口与退出

app 接收外部激活并分派明确的业务意图，ui 协调页面和宿主视图，windows 管理原生窗口，renderer 在路由就绪后执行导航。公开链接、通知和原生入口共用目标校验与完整操作，避免不同入口产生不同的选择规则。

<a id="identity"></a>

## 应用身份与条目寻址

项目域名为 kisaki.me，通用授权中转为 oauth-relay.ximu.dev。独立服务不会因项目域名变化而迁移回调。正式应用使用 appId me.kisaki 和协议 kisaki://，开发应用使用 me.kisaki.dev 和 kisaki-dev://，安装身份见[工程配置](../engineering/repository.md)。原生业务入口提供 view、open 和 add，分别表示查看、实际使用作品和直接新增；extension 将请求交给明确扩展登记的处理器，见[扩展 deeplink 入口](#extension-deeplinks)。不提供 launch、play、read、manga 别名或通用命令 URL。

```ts
type EntryIdentifier = { type: 'local'; id: string } | ({ type: 'external' } & ExternalIdentity)
```

路由确定 Entry 类型，EntryIdentifier 在接收实例的当前资料库内定位根条目：`local/<id>` 读取本地对象，`external/<source>/<sourceId>` 查询已保存的准确来源映射。查找只使用当前库的数据，可以离线执行。命中后核对类别、显式选择与可见范围；数据库身份和外键继续使用本体存储合同。

每个路径值作为独立 URL 组件编码一次。完整 sourceId 中的 / 不改变路由层级，不增加 JSON 或 base64 包装，也不拆分来源 ID。例如 kisaki://view/anime/external/bangumi/subject%2F123。被删除或合并掉的旧 local ID 直接失效，不建立专用跳转记录；external 则随正式身份映射自然指向保留对象。

external 只寻找根 Entry。Part 身份不会自动寻找父作品，分部、文件和配置仍须明确提供本地 ID。主应用和 SDK 共用生成与解析实现，不能猜测字符串形状。

<a id="routes"></a>

## 公开路径与选择参数

下表省略 kisaki://。entryType 是七种 Entry 之一，identifier 使用前述两种根标识。内部页面不会仅因存在就自动获得公开 URL。

| 用途                 | 地址                                       | 参数                                             |
| -------------------- | ------------------------------------------ | ------------------------------------------------ |
| 资料库入口           | `view/library`                             | 无                                               |
| 某类条目列表         | `view/<entryType>`                         | 无                                               |
| 查看条目             | `view/<entryType>/<identifier>`            | 适用的配置、分部、文件定位参数                   |
| 合集、标签、笔记列表 | `view/collection`、`view/tag`、`view/note` | 无                                               |
| 单个合集、标签、笔记 | 上述地址追加 `/<id>`                       | 无                                               |
| TaskCenter           | `view/tasks`                               | 可选 runId                                       |
| 扫描管理与报告       | `view/scanner`                             | 可选 configId、runId                             |
| 资料方案管理         | `view/metadata-profiles`                   | 可选 profileId                                   |
| 应用偏好             | `view/preferences`                         | 无                                               |
| 扩展管理与页面       | `view/extensions`                          | 可选 extensionId、pageId                         |
| 启动游戏             | `open/game/<identifier>`                   | 可选 launchConfigId                              |
| 播放动画             | `open/anime/<identifier>`                  | 可选 episodeId 或 extraId，以及 fileId、position |
| 阅读漫画             | `open/comic/<identifier>`                  | 可选 volumeId、chapterId、fileId、position       |
| 阅读小说             | `open/novel/<identifier>`                  | 可选 volumeId、fileId、position                  |
| 添加条目             | `add`                                      | 下方添加参数                                     |
| 扩展业务入口         | `extension/<extensionId>[/<path>...]`      | 由目标扩展定义的查询参数                         |

Collection、Tag 和 Note 只使用本地 ID，路径不增加 local。view 作品可以定位配置、分部或文件，但不会实际使用内容。position 只适用于 open 动画、漫画或小说，并且必须同时指定 fileId。preferences 不接受 sectionId。主题、字体、系统集成和更新 Dialog 不自动获得公开地址，应用内部仍可以使用原生导航进入具体设置。

open 只用于四种 Work。目标与复用统一遵循[会话选择规则](../domains/sessions.md#open)：省略目标时，在有效会话之后优先考虑首选，再考虑最近实际目标。显式参数只约束本次操作，不保存为首选。界面的“继续”操作和由它生成的链接携带已经确定的实际目标，不借助另一套入口默认规则。

游戏使用 launchConfigId；动画的 episodeId 与 extraId 互斥；漫画使用 volumeId 和 chapterId；小说使用 volumeId。文件、分部和根必须同时核对归属，不能按处理顺序忽略任何已提供条件，也不能增加通用 partId 来猜测所属表。

漫画只指定卷时按卷选择文件，只指定话时按话选择文件。卷与话同时指定时，先核对收录关系，再按话选择文件，不能把卷视作唯一父级或暗中使用卷首选。仅能使用收录卷文件时，须通过已有的明确整卷动作打开，不能制造话的文件内坐标。漫画和小说的链接参数只约束实际打开目标，阅读器继续提供当前作品的[实时资料与文件列表](../domains/reader.md#work-navigation)，不由链接形成固定阅读序列。

position 可以是本体的具体坐标或 start，两者都要求 fileId。省略 position 时使用该文件正常续读位置；位置失效时不能归零或换文件，不增加 revision 或哈希。fileId 只固定当前目标，不限制之后的作品内导航；动画仍显示所属作品的资料和文件列表，不将深链参数变成播放清单。扫描入口同时提供 configId 和 runId 时，核对历史归属；原配置已经删除时，历史仍可查看。

从属对象通过所属作品的入口定位；人物、角色和组织等独立对象使用自己的入口。URI、按钮和快捷键汇入同一原生请求，业务默认选择和归属规则由该请求统一处理。

<a id="add"></a>

## 后台直接新增

kisaki://add 只接受查询参数，直接调用 ingest.add。不提供 interactive、direct、mode、预填界面，或 `add/<type>/local/external` 路径。普通人工新增先在原生编辑界面准备输入，再调用同一完整业务。

| 添加参数           | 含义                           |
| ------------------ | ------------------------------ |
| entryType          | 必填，添加的七类条目之一       |
| source、sourceId   | 可选完整外部身份，必须成对出现 |
| name、originalName | 可选名称与原文名线索           |
| releaseDate        | 四类作品的首发日期线索         |
| birthDate          | 人物、角色的生日线索           |
| foundedDate        | 组织成立日期线索               |
| profileId          | 可选，省略时使用该类型默认方案 |

输入必须能够有效支持定位。source 与 sourceId 成对出现，可以同时提供名称或日期线索，不分成 ID 与名称两种模式。明确身份优先，身份冲突后不能忽略它，再按名称新增另一项。source 不选择搜索 provider，具体来源由 Profile 决定。外部网页 URL 不作为定位输入，也不增加页面识别或抓取能力。

省略 profileId 时，使用接收端为该类型明确设置的默认方案。没有默认方案就报告无法执行，不弹出方案选择。显式方案类型错误或已经失效时，不回退。执行前固定方案快照，不继承上次更新或预览的临时策略。歧义、输入不足或无法采用按结果失败，不让任务一直等待搜索选择。对象已经存在时，不自动转为更新；合法局部结果遵循 [ingest 合同](../domains/metadata.md)。

解析结果直接形成 clues 与执行选项，不先创建 EntryIdentifier 或解析本地目标。冷启动也不闪现添加窗口，后台结果通过桌面通知反馈，不自动打开 TaskCenter 或新增结果区。例如 kisaki://add?entryType=game&source=vndb&sourceId=v17。

<a id="encoding"></a>

## 参数编码、校验与复制

原生入口的字符串、ID 和枚举使用普通查询参数。日期和 position 先使用原生 JSON，再进行 URL 编码，解码与编码各执行一次。PartialDate 不拆成 releaseDate.year，也不建立日期小语言。

```text
kisaki://add?entryType=game&name=CLANNAD&releaseDate=%7B%22year%22%3A2004%7D
```

start 编码为 JSON 字符串，不增加 fromStart、page、time、cfi 或短链接表。具体坐标遵循[阅读操作](../domains/reader.md#operations)，start 不持久化。原生 view、open 和 add 拒绝未知参数、重复单值参数、非法空值和错误格式。扩展入口的参数由[所属扩展校验](#extension-deeplinks)，宿主保留顺序与重复值。缺省与无效不同，不能丢掉失败条件后改为执行另一种操作。授权 loopback 由来源协议解析，不经过业务 URL。

| 操作                     | 生成行为                                              |
| ------------------------ | ----------------------------------------------------- |
| 复制条目链接             | 默认生成本地身份的 view 链接                          |
| 复制启动、播放或阅读链接 | 统一使用 open，保留该入口明确选中的配置、分部或文件   |
| 复制当前位置链接         | 使用相应作品类型的 open，固定实际 fileId 和当前位置值 |
| 复制添加链接             | 使用 add，直接新增，不固定接收端的 profileId          |

作品层的使用链接不固定当前首选，只有从具体配置、分部或文件入口复制时，才保留对应选择。复制外部身份链接需要明确选择该方式和一份身份，不设置主外部 ID，也不按 Profile 顺序选取。根使用 external 不会使本地子对象 ID 跨库有效。需要新增时明确使用 add，复制的 add 默认不绑定接收端 profileId。

<a id="delivery"></a>

## 启动等待与一次交付

| 动作                               | 窗口与执行行为                                     |
| ---------------------------------- | -------------------------------------------------- |
| view                               | 在主窗口进入原生页面或条目界面，必要时恢复窗口     |
| open/game                          | 使用正常启动流程，需要选择启动配置时才显示相应界面 |
| open/anime、open/comic、open/novel | 打开或复用对应播放、阅读窗口                       |
| add                                | 主进程后台直接执行，不弹添加窗口，通过桌面通知反馈 |
| extension                          | 交付目标扩展的 Node 处理器，按该入口业务决定所需界面 |

系统激活由主进程 app 校验目标、协调交付，并等待必要能力。需要窗口的操作由 windows 创建、恢复、显示和聚焦窗口，renderer 明确报告 router 与 receiver 就绪后才接收页面请求，不能依靠固定延时。窗口加载固定 UI 入口，不调用 loadURL(kisaki://)。冷启动的 view 直接成为初始路由，避免先闪首页。阅读可以直接打开阅读窗口，无须等待无关 provider 或全部扩展；扩展请求交付 Node 处理器，不以主窗口或 Webview 就绪为前提。

未交付队列的工程默认上限为 32 条，最多等待 60 秒。超时或超量时明确失败，不能积压后突然执行。队列只等待本次请求真正依赖的能力；已知缺失、停用或失败时直接报告。该限制不计算业务执行或用户选择耗时。交付后由业务拥有取消和结果，未交付请求只保存在内存中。退出开始后停止接收新请求，下次启动不重放。

待交付的相同原生规范请求可以合并，参数顺序不同仍可视为同一请求，但不建立永久去重表。扩展请求不由宿主合并或重排参数，重复资源的处理由扩展业务决定。Windows 与 Linux 处理冷启动参数和 second-instance；macOS 在启动早期同步监听 open-url，再进行异步初始化。单实例机制避免重复打开数据库，制品按 [Electron 接入规则](https://www.electronjs.org/docs/latest/tutorial/launch-app-from-url-in-another-app)验证。

通知携带可序列化业务目标。新增结果通知打开实际条目或任务，应用内导航直接使用原生请求。Windows 可以采用[协议激活](https://learn.microsoft.com/en-us/dotnet/api/microsoft.toolkit.uwp.notifications.toastcontentbuilder.setprotocolactivation?view=win-comm-toolkit-dotnet-7.1)；各平台按安装身份验证运行中与冷启动投递，确保一次点击只触发一次导航。

先请求 A 再请求 B 时，迟到的 A 不能把界面拉回。取消后不能被迟到响应重新打开，观察页关闭也不能使后台操作失去归属。导航共用可见性、归属、窗口复用和草稿确认规则。目标不存在或不可见时，统一提示“当前可见范围内，没有相应记录。”；参数错误明确说明无法执行。普通失败不强制打开主窗口，普通导航不产生 TaskRun 或历史中心记录。

反馈遵循[入口责任](components.md#notifications)：后台 add 使用桌面通知，进入界面的操作使用局部 Toast。同一结果不重复提示，也不按窗口焦点切换渠道。

<a id="extension-pages"></a>

## 扩展页面寻址

```text
kisaki://view/extensions
kisaki://view/extensions?extensionId=E
kisaki://view/extensions?extensionId=E&pageId=P
```

三个地址分别进入扩展管理、扩展详情和具体登记页面。pageId 必须与 extensionId 同时出现，并在扩展内稳定且唯一，不使用文件名、组件名或临时 Dialog、Webview 身份。登记绑定真实拥有者，重复时报错。扩展不能替其他扩展登记，也不能透传任意 URL、脚本或命令。

扩展停用后仍可查看原生详情，但运行页面应报告不可用，不自动启用。已经交付的调用绑定实际实例，旧结果不能覆盖新实例状态。认证不经过该分发入口。

<a id="extension-deeplinks"></a>

## 扩展 deeplink 入口

扩展通过自己的地址范围接收外部业务请求，与原生入口共用协议关联、系统接收及交付机制：

```text
kisaki://extension/<extensionId>/install?resourceId=123&version=1.2
kisaki-dev://extension/<extensionId>/install?resourceId=123&version=1.2
kisaki://extension/example/show?resourceId=123#description
```

extensionId 使用[扩展身份合同](../extensions/distribution.md#package)中的正式 ID，解析后与 manifest 共用同一校验，不从 npm 包名推导身份，也不因 URL 编码放宽格式。含 / 的值及其他非法 ID 必须拒绝。后续路径、查询参数与 fragment 由该扩展定义，不要求路径动作在宿主逐项登记。注册不创建新的操作系统协议，也不能占用原生 view、open、add 或其他扩展的地址范围。

desktop-contracts/deeplink 的 extension 请求分支保存 extensionId、path、query 与可选 fragment；格式化和解析复用基于 [WHATWG URL 标准](https://url.spec.whatwg.org/)的纯实现。宿主校验协议、目标结构、扩展身份格式与编码，拒绝用户名、密码和端口。路径先按组件划分，再各解码一次，查询参数遵循标准 URL 查询语义，fragment 按其组件规则解码一次。非法百分号转义或非法 UTF-8 必须拒绝，不能替换为其他字符后继续。不能先解码整个路径再拆分，也不能修改扩展身份的大小写或把格式错误的目标解释为另一个入口。

对实际收到的 URL，在标准规范化消除点路径前，检查并拒绝完整的 .、.. 路径组件及其等价编码，包括 %2e、.%2e、%2e. 和 %2e%2e 的大小写变体。format 同样拒绝输入 path 中完整的 . 或 ..，不能生成会改变扩展目标或业务路径的链接。点号出现在其他组件内容中不受此限制。合法请求经 format 和 parse 往返后，扩展归属、路径组件、查询项顺序与重复值，以及 fragment 的业务值保持一致。

交付给处理器的输入包含业务路径、查询参数与可选片段：

```ts
interface ExtensionDeeplinkRequest {
  readonly path: readonly string[]
  readonly query: readonly (readonly [name: string, value: string])[]
  readonly fragment?: string
}
```

path 不包含 extensionId，省略后续路径时为空数组。路径中的空组件、查询项的顺序、同名多值与空值保留，由扩展校验；query 不转成会覆盖重复键的对象。未知路径、参数或不满足业务要求的值由扩展明确拒绝，不套用原生入口的参数白名单，也不丢掉条件后执行其他动作。

fragment 不包含开头的 #；没有片段时省略，显式的空片段保留为空字符串，其中的 + 不按查询参数解释为空格。片段只作为业务数据交付，由扩展解释或校验，不参与选择扩展、权限判断或宿主页面导航，也不扩大原生 view、open、add 的公开输入。上例的 description 可以由扩展解释为资源介绍位置，但宿主不替它执行定位。

Node 扩展通过 context.deeplink.register(handler) 登记：

```ts
const registration = await context.deeplink.register(async (request, execution) => {
  const input = parseInstallRequest(request)
  await downloads.install(input, execution)
})
```

每个扩展实例至多持有一个有效处理器；多个路径在扩展内部组织和分发。宿主从真实 ExtensionContext 绑定拥有者与代际，作者不传 extensionId 或 localId。返回句柄提供只读 ref（包含绑定的 extensionId）及可重复调用的 dispose。重复登记失败，不覆盖已有处理器。登记沿用[激活与贡献发布](../extensions/runtime.md#activation)：激活成功后才对外可用，失败时撤销；提前 dispose 停止后续交付，已经交付的调用继续按自己的执行合同收尾，实例失效则遵循[停用规则](../extensions/runtime.md#disable)。旧句柄不能撤销新实例的登记。

app 拥有外部请求分发和扩展入口的运行期路由，extensions 适配层绑定真实实例并接入登记，extension-host 执行回调。原生请求与扩展请求共用接收和交付规则，各业务拥有者继续负责实际操作。冷启动只等待目标已启用扩展的正常激活与贡献发布，不等待全部扩展。已知未安装、停用、激活失败或激活完成后未登记时直接报告不可用，不自动安装、启用或反复激活。未交付请求沿用[共同队列与等待预算](#delivery)，退出后不保留。

同一处理器的请求按接收顺序发起交付，不等待前一次异步处理结束才交付下一次。每次调用有独立输入与执行上下文，业务并发、同资源互斥和重复安装由扩展处理；没有全局“当前链接”。交付后绑定实际实例，断连或重启不自动重放，迟到结果不能采用到后来创建的实例。

handler 返回 `Promise<void>`，完成表示该链接约定的请求处理已经结束：下载安装入口等待真实业务及收尾，打开界面的入口等待界面就绪。长期进度、取消和后台执行使用既有任务与[完整操作合同](../communication.md#operations)，不因耗时长就提前返回或套用未交付预算。execution 的 signal 与 allowInteraction 由宿主绑定和桥接，不能由 URL 提供。

扩展入口允许业务所需的界面交互，宿主不额外弹出“是否允许此扩展处理链接”的通用确认框；浏览器或系统自身的协议打开提示按实际环境处理。打开页面、定位内容可以直接进入相应业务。外部链接发起资源下载安装时，由扩展的完整业务先展示资源、资源来源、版本、安装位置与覆盖影响，用户确认本次具体操作后再下载和安装。已有同等业务确认直接复用，不重复询问；取消确认则结束本次操作并清理准备资源，不开始下载安装。确认与本次确定的资源及安装范围绑定，链接不能代替确认或证明来源网站身份。allowInteraction 只允许业务所需的交互，不表示已经获得用户授权。

处理器可以打开 Dialog、页面或执行后台业务，页面参数通过既有私有通信交付，不把安装挂到页面初始化上。宿主报告解析、目标不可用和未处理的调用失败；扩展业务负责进度与业务结果，按[入口责任](components.md#notifications)反馈一次。交付成功不显示为安装成功，普通协议也不向发起网页返回业务响应。浏览器授权继续使用下方 loopback 合同。

<a id="authorization"></a>

## 浏览器授权边界

浏览器授权使用 loopback，由来源 Node 扩展和普通依赖完成会话、回调及核验，平台能力负责打开外部浏览器。个人令牌、API key、client_credentials 等流程按来源自身的凭据合同接入。

授权期间只监听本机回环，结束、取消、超时或实例失效时释放。来源允许动态端口时使用动态端口，要求精确登记时才使用固定地址。固定地址被占用时，在打开浏览器前报告，不把请求交给另一实例或自动切换 scheme。回调绑定发起操作、预期来源和地址，重复、过期或旧操作的回调不能影响新授权。应用重启不继续未完成操作。

公共原生客户端的授权码流程使用 PKCE S256，loopback 不能代替完整保护，见 [RFC8252](https://www.rfc-editor.org/rfc/rfc8252.html#section-7.3)、[Google 桌面客户端](https://developers.google.com/identity/protocols/oauth2/native-app) 和 [RFC9700](https://www.rfc-editor.org/rfc/rfc9700.html#section-2.1.1)。MAL 的固定直连 loopback 与 plain PKCE 是明确兼容例外，不先尝试 S256 再自动降级。MangaDex 个人客户端按[来源认证](../extensions/private-data.md)使用明确方式，主动连接中输入的密码不持久化。

使用 relay 的来源先回到登记的 HTTPS 地址，最后一跳到 Kisaki 时使用 loopback。该要求不限制独立 relay 其他消费者的回调类型。凭据保存和来源兼容验收属于认证合同，普通协议关联与授权分别管理。

## 侧栏顺序与更多面板

```ts
type PageRef =
  { type: 'native'; id: string } | { type: 'extension'; extensionId: string; pageId: string }
```

PageRef 属于 desktop-contracts/ui。native.id 来自本体页面目录的稳定登记键；extension 分支使用扩展与页面的准确登记身份。非空字符串在运行时核对目录，不能把标题、路由、组件路径或任意 URL 当作页面键。主窗口、侧栏和应用搜索引用同一目录，暂不可用页面沿下述保留规则处理。搜索的对象目标使用[SearchTarget](../domains/search.md#results)，其值定义由导航合同拥有，搜索合同直接引用。

preferences.navigation 保存一份完整 order 和 visibleLimit。visibleLimit 是非负整数，默认 7；当前有效项目中的前 min(N, total) 项常显，其余进入更多。0 表示全部收进更多。固定工具和更多按钮本身不占名额，没有剩余项时不显示空的更多控制。侧栏保持固定导航宽度，页面可见范围只由完整顺序与常显数量决定。

更多面板从导航区向内容区横向展开，形成连续覆盖层，不挤压内容。面板显示完整顺序，包括前 N 个常显项。每项使用紧凑的图标和名称，可以多列呈现，按从左到右、从上到下对应 order，超高时内部滚动。面板共用图标、字体、选中和浮层规则。打开它不会新增页面或历史，也不改变 N 或当前页。

全部项目在同一顺序中拖拽，并标明前 N 个常显范围，不建立两列独立排序。例如 N=3 时，A/B/C/D/E 中的 E 移到第二位，常显项成为 A/E/B。拖拽完成立即提交，面板保持打开，不触发导航。等价键盘操作遵循共同[重排规则](virtualization.md)。配置编辑入口则在草稿保存后生效，不预览侧栏；两个入口共用同一规则。

当前页不在前 N 项时，高亮更多，面板内高亮实际页面。“包含当前页”和“面板已展开”是不同状态。关闭被拒绝或导航失败时，不提前修改当前页，也不为显示当前页而重排。选择页面后收起面板，再次触发、点击外部或按 Escape 也会关闭并恢复焦点。拖拽不能被误判为导航或外部点击，临时展开状态不持久化。

导航顺序使用原生稳定页面引用或 { extensionId, pageId } 保存。新页面统一追加到末尾，暂不可用页面保留位置并让出有效名额，恢复后回到原位。标题、图标和实例信息按当前呈现读取，扩展页面使用同一排序规则。

## 快捷键与当前内容控制

快捷键按主窗口、阅读器、播放器和游戏面板场景配置已定义动作，稳定键见 [preferences](../domains/preferences.md#game-and-shortcuts)。它们不构成公共动作调用器，也不能绑定任意参数。窗口内快捷键由所属 UI 调用自己的函数，系统快捷键由主进程进入原生流程，扩展私有界面管理自己的按键。

只有可能重叠的作用范围使用同一按键时才算冲突，无关的阅读和播放场景可以使用同一键。输入框、菜单、Dialog 和编辑器优先，每次按键只交付一次。Kana 直接操作当前文档，播放器经私有 IPC 控制主进程 libmpv，换文件和结束操作走 sessions。已经处理的控制不能再以原始输入送给引擎。系统窗口移动、最小化、最大化，以及位置、尺寸和全屏记忆由 windows 负责，不新增通用使用窗口设置。

修改快捷键先进入草稿，保存后更新绑定。冲突需要用户改键或停用，不能按列表顺序决定胜者。录入必须明确开始，期间暂停应用快捷键触发；确认后写入草稿，Escape 取消，独立按钮清除。使用 Electron Accelerator，默认可以使用 CommandOrControl，用户设置保留实际修饰键。

快捷键注册失败时保留选择并显示未生效，用户可修改后重试。冲突检查覆盖动作所有可能重叠的范围，包括游戏尚未开始的情况。按住时是否重复触发由实际动作决定。

| 场景/动作          | 默认                                       |
| ------------------ | ------------------------------------------ |
| 主窗口搜索 / 偏好  | Ctrl/Cmd+Shift+F / Ctrl/Cmd+逗号           |
| 有保存语义的编辑器 | Ctrl/Cmd+S；复用本编辑器保存，无动作不接   |
| 阅读器文内查找     | Ctrl/Cmd+F；不猜其他列表搜索               |
| 播放器播放/暂停    | Space                                      |
| 播放器后退/前进    | 左右键，各 5 秒                            |
| 播放器音量         | 上下键，各 5 个百分点                      |
| 播放器静音 / 字幕  | M / V                                      |
| 阅读器、播放器全屏 | Windows/Linux F11；macOS Control+Command+F |

Mod 在 Windows 和 Linux 中表示 Ctrl，在 macOS 中表示 Command。

| 操作               | 阅读器、播放器：窗口内 | 游戏：系统级 |
| ------------------ | ---------------------- | ------------ |
| 新建标注           | Mod + Shift + A        | Shift + F9   |
| 显示或隐藏标注列表 | Mod + Shift + L        | 默认不绑定   |
| 显示或隐藏游戏面板 | 不适用                 | Shift + F8   |
| 暂停或恢复计时     | 默认不绑定             | 默认不绑定   |
| 查看所属作品       | 默认不绑定             | 默认不绑定   |

游戏系统快捷键默认避开 Ctrl 和 Shift + F10，分别减少视觉小说按住快进和 Windows 上下文菜单的冲突。默认只绑定面板切换与新建截图标注，标注列表、计时和作品详情保留入口并允许自行绑定。

用户可以修改或清空组合。添加修饰键未必使游戏忽略 Ctrl，因此应用不额外拦截其按下或释放事件；默认值仍需按实际游戏核对。窗口内编辑快捷键使用自己的规则。参考 [Ren'Py 按键](https://www.renpy.org/doc/html/keymap.html)与 [Windows 快捷键](https://support.microsoft.com/en-us/windows/keyboard-shortcuts-in-windows-dcc61a57-8ff0-cffe-9796-cb9706c75eec)。

新建标注使用当前内容的真实目标：阅读使用选区或位置，视频使用范围或位置，游戏使用截图。存在游戏会话时注册游戏系统快捷键，最后一个游戏会话结束后释放，面板展开或折叠不影响注册。其他系统快捷键按自身范围管理。游戏目标按[面板规则](../domains/preferences.md#game-and-shortcuts)选择，不向多个会话广播。

阅读内容分页且不需要滚动时，左右键按阅读方向翻页，上下键分别到上一页和下一页。连续纵向阅读时，上下键滚动，左右键没有默认翻页动作。放大后内容可以滚动时，方向键只移动视口，到边缘也不暗中转为翻页。PageUp、PageDown、Shift+Space 和 Space 在分页模式固定对应前后页，在连续模式固定对应前后一屏，不随左右阅读方向反转。输入框和编辑器的按键不能被抢占。

## 应用菜单与系统集成

左下角应用菜单使用单层结构，同级入口固定为偏好、主题、字体、系统集成和更新，通过分隔线组织；关于独立呈现。各项直接打开所属界面并可被搜索，更新使用主窗口 Dialog，界面状态和草稿由各自拥有者管理。

这是应用内容中的菜单，不替代 macOS 系统菜单栏或窗口的标准编辑能力。系统菜单按平台接入 Electron Menu，标准编辑、窗口与应用动作优先使用适用的 role；产品菜单项复用同一业务操作。修饰键、系统窗口控制与菜单习惯遵守[原生交互规则](components.md#native-interaction)，不因共用视觉样式而重写另一套基础编辑行为。

关于界面显示版本、项目、许可和致谢。复制环境信息只包含 Kisaki 版本、实际操作系统名称与版本，以及应用进程的 x64 或 arm64 架构，不拿物理设备架构代替。内容不包含路径、资料、日志、账号或完整扩展列表。只有用户点击并通过现有剪贴板实际复制成功后才提示，不自动上传，也不建立诊断流程。

系统集成 Dialog 读取自启动和协议的真实状态，显示适用开关、修复操作及必要系统设置入口。操作完成后重新读取，关闭 Dialog 不撤销操作。preferences 不保存假设已经生效的布尔值，登录项是否登记与是否获准按平台分别判断，见 [Electron 登录项](https://www.electronjs.org/docs/latest/api/app#appgetloginitemsettingsoptions-macos-windows)。

便携选择由 app/paths 管理，载体旁标记决定下次启动模式，在打开数据库前解析；本次数据根始终固定。界面显示当前模式、路径及待重启状态。主进程核对载体与路径能力，变更在重启后生效，原资料保持原位，见[构建与载体](../engineering/build.md)。Linux 免安装形态的 .desktop 登记由用户明确发起。

协议关联只在安装或用户主动登记、修复时建立，便携需要显式操作，开发与正式身份分开。普通启动不能抢占关联，卸载只删除仍属于自己的登记。各平台使用真实制品验证注册、接收和通知，调用成功不能代替系统真实状态。

<a id="shutdown"></a>

## 完整退出与安装重启

app 为游戏、动画、漫画和小说协调同一个正常退出流程与界面，直接调用各拥有者完成收尾。sessions 按实际类型结束内容，updates 只有在应用成功退出后才安装并重启，不建立持久退出计划或新的会话身份。存在活动使用时，提供“结束使用并退出”和取消；包含游戏会话时，另提供“停止游戏记录并退出”，说明游戏继续运行且本次不做退出备份。先完成各编辑器的未保存检查，再执行不可撤回的内容关闭；任何检查被取消就停止后续步骤，已经明确保存的内容不回滚。

确认退出后停止接纳新会话与自动下一项，收束已经开始建立的操作，并按其实际结果处理在途启动和已发出的外部请求。已建立会话按用户选择关闭：游戏通过 close 等待真实退出，或通过[原生 detach](../domains/sessions.md#detach)保存记录并解除管理；动画停止播放并释放媒体资源，漫画和小说关闭阅读内容并释放资源。各类会话完成适用的计时、位置、记录与资源收尾后，才满足本次退出条件。

准备退出与等待收尾期间保留应用的固定跨模块连接，使本次真实会话结束仍能交给备份等接收能力。按[通知交接](../communication.md#event-delivery)已经接纳的工作，从异步准备开始就计入所属能力的在途范围；不能仅凭当前 TaskRun 列表为空认定可以退出。满足本节规定的退出条件后，才解除固定连接并释放依赖，最后关闭数据库。等待期间取消退出时恢复正常接纳，保留的连接继续使用，不重新登记或重放事实；已经结束的内容和已经提交的结果保持原状。

退出界面统一列出本次退出参与的使用会话，按实际 sessionId 区分，不仅列出游戏或按作品合并多个会话。显示所属作品、适用的当前文件或配置，以及关闭与收尾的实际进度和结果；内容已结束但保存或资源释放失败时，明确显示对应阶段；明确脱离的游戏显示记录已停止及清理状态，不把它描述为进程已经退出。进度与问题由本次退出流程统一反馈，不再为每个参与会话另外发送一份关闭结果 Toast。

等待超时时，用户可以继续等待、取消退出，或返回仍可使用的对应内容。“继续等待”只继续观察已接纳的关闭与收尾，不重复发送相同退出请求或周期性重复提示。取消退出不会回滚已经结束的内容，也不会重启游戏或重新打开文件。尚未结束的会话继续管理，之前发出的关闭请求若随后生效，仍须完成收尾。

退出界面按内容类型提供操作。仍运行的游戏可以由用户明确选择强制终止，复用 sessions.game.terminate 的结束条件，选择后直接执行。动画、漫画和小说通过各自的 close 完成结束与资源释放。

同一协调器等待游戏 exited 或用户明确选择的 detached，以及其他内容的结束和必要收尾；更新重启复用该流程。自动强杀、终止宿主进程或把普通失败改报 interrupted，都不构成正常退出。

会话结束时处理最后可信位置、有效时长与资源释放，正常游戏退出触发的已启用备份按备份合同执行。最后记录保存失败时，按[会话关闭合同](../domains/sessions.md#close)结束实际会话并继续必要清理，同时保留[未保存记录](../domains/sessions.md#pending-recordings)。退出和更新重启等待用户重试保存或明确放弃剩余快照；取消退出则保留快照供本次运行继续处理。备份失败独立提示；它不能代替未保存记录的处理结果。明确脱离的保存失败遵守其自身规则：保留会话并阻止这次脱离，不能用内容已结束的保存失败政策跳过。

其他在途任务按自己的等待、取消和安全收尾合同处理，不一律终止。本次退出被取消或失败时，更新保持待安装，应用恢复正常接纳，已经结束的内容不自动重开。会话仍在运行或必要收尾仍在执行时，继续按相应合同等待或取消。崩溃、系统终止或无法继续观察时，可以记录异常中断，但只保留已提交事实，不承诺完整时长或结束事件。重启不恢复计时，也不自动接管残留进程；正常失败不能故意改报异常来绕过约束。

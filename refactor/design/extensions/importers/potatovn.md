# PotatoVN Importer 接入方案

PotatoVN 导入器迁入游戏资料、本人记录、评论、整理和所选本地配置。输入基线为 v1.10.2.0、提交 d877bbe166e5b71d6520784f9d268e6df7eb4487，范围依据固定源码与[合成核验](../../../verification/evidence/potatovn-importer/source-and-fixtures.md)。

<a id="scope"></a>

## 用途与输入

提供本地手动导入页面，迁移游戏资料、记录、文字、整理与所选本地配置。新作品沿[共同流程](../importers.md#flow)以合法来源字段形成 prepared 输入，已有条目按准确身份复用。没有源账号连接、云同步、metadata provider 或远端写入，联网补充由用户另行发起。

支持两类明确输入：

| 输入                            | 识别与范围                                                                                                                                                                              |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 官方 .pvnExport.zip 全库导出    | 根目录的 data.galgames.json，以及 data.galgameSources.json、data.categoryGroups.json、data.staff.json、data.dataStatus.json 和 Images 资源；实际是 JSON，不是运行目录内的 LiteDB 数据库 |
| 单游戏 GameMetaBackup Version 2 | 明确选定的 meta.json 及配套资源目录，根为 Version、Game、Installation；本地目录通常为 .PotatoVN，Steam 的元数据另放在 steamapps/.PotatoVN 下                                            |

文件名和后缀不代替结构识别。全库导出没有独立数值 schemaVersion，按已核实的文件、字段包装、枚举与关联格式识别；dataStatus 是源软件的升级和恢复标志，不是本体迁移状态。官方新导出也会将 GalgameMultiInstallUpgrade 等字段重设为 false，不能据此拒绝正常输入。单游戏输入只声明 Version 2，不把 Version ≥ 2 或旧平面 Galgame JSON 都视为同一格式。

全库输入需要有效的游戏数组；可选文件缺少时只影响相应整理或配置范围。单个游戏、关联或图片失败分别报告，不把未知引用当成空值清除目标。读取选定条目需要的 JSON 和资源，源包保持只读，不调用 PotatoVN 恢复、数据库升级、自动扫描、解压游戏或插件入口。

GameMetaBackup 同时包含普通资料、个人记录与安装配置，按软件库快照解释。新对象直接采用能够准确映射的来源事实，不因 meta.json 文件名而漏掉私人数据。可选择一份全库导出或一组明确 Version 2 目录，不自动扫描整盘寻找 sidecar。

<a id="identity"></a>

## 游戏身份与来源资料

Uuid 是源逻辑游戏内部身份，用于固定输入中的分类、库条目与 StaffGame 关联。库 Id、EntryId 与职员 Id 也用于本批次对应，步骤进度可保留这些键，但不登记为公开外部身份。同一个 Uuid 的多份安装只产生一个 Game；不能按每个安装路径复制作品及私人记录。

Ids 按固定 RssType 位置解释，使用实际来源字段，不能把所有数字槽位视为同一种身份：

| 槽位 | 来源含义 | 正式采用                                 |
| ---- | -------- | ---------------------------------------- |
| 0    | VNDB     | 纯 VN 数字或 v 编号规范化为 vndb / v{id} |
| 1    | Bangumi  | bangumi / subject/{id}                   |
| 5    | YMGal    | ymgal / ga{id}                           |
| 7    | Steam    | steam / app/{appid}                      |

VNDB 槽位也可能保存 r 编号，它指向发行记录，不能改写成同号 v 身份或直接绑定为游戏。导入使用其他有效作品身份或本次明确的本地目标完成对应；没有对应时，以已知名称、类型及合法资料形成 prepared 新增输入。r 链接可以在用户选择保留来源链接时作为普通外链保存。本项不另行调用 VNDB 接口把一个发行包猜成某个作品，联网补充仍是导入后的独立操作。

Mixed 槽位是源软件的复合表达，PotatoVN 自身和插件槽位属于其内部约定；它们不冒充上述正式身份。Cngal、Hikarinagi 等未纳入本体正式来源合同的槽位不自动产生身份。空值和 -1 不是有效 ID，也不从来源名称或任意文本中提取数字。

有效身份共同对应一个本地游戏时复用；没有对应时，向 ingest.add 提供 prepared 候选与合法来源字段。同名不触发合并。多份单游戏快照对应同一逻辑游戏时，安装分别处理；矛盾私人值不按文件排列或最近时间择一覆盖。

<a id="metadata"></a>

## 来源资料与图片保留

来源普通资料默认选中，以本页明确映射形成 prepared 候选。Name、Description、ImagePath 等 LockableProperty 读取 Value，IsLock 是源软件保护偏好，不形成本体锁定字段。角色、人员与关系只有满足下文身份及语义要求时才采用，联网补充不作为导入前提。

| 来源字段                                              | 可采用内容                                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Name.Value、OriginalName.Value                        | 主名称与已知原文名称                                                                                   |
| ChineseName.Value                                     | 中文名称按普通别名规则追加；不替换方案已有别名，也不将旧 CnName 镜像覆盖当前字段                       |
| Description.Value                                     | 按普通文字转换为 Markdown，保留换行和字面文本，不将尖括号直接解释为 HTML                               |
| ReleaseDate.Value                                     | 来源实际日历日期；DateTime.MinValue 表示未知，其他合法第一日正常采用                                   |
| ImagePath.Value、HeaderImagePath.Value                | 当前主图与背景图                                                                                       |
| AddTime                                               | 选择加入日期时，按导入时系统时区取得日历日期；不改写技术创建时间                                       |
| Tags.Value、Engine.Value                              | 选择标签与分类文字后形成普通标签，按共同 nameKey 规则复用；默认占位值不作为标签                        |
| Developer.Value、ExpectedPlayTime.Value、Rating.Value | 可选补充资料笔记中的开发方文字、预计时长和来源公共评分；不直接新建组织，不转换为实际游玩时长或本人评分 |

源默认值“——”只在有明确占位约定的普通资料字段中作为未知处理，不删除评论中的同样文字。空资料和默认图标不清除已有值。来源普通资料默认选中，补充资料笔记默认关闭；已有对象按用户明确的补空或覆盖选择更新。

角色和职员字段另有明确保留范围：按正式外部身份对应本次已建立或本地已有的实际对象后，可以采用所选名称、简介、图片及该类型适用的合法基础资料。选择这些字段时，相应共享对象本身就是本次明确更新目标。角色的 ImagePath 作为主图，PreviewImagePath 是来源预览，不额外制造第二项主图。Staff 的主体类型由已对应的本体对象及来源明确的类型事实确定，不能仅凭姓名、职业或性别创建 Person / Organization，也不为迁入这些字段隐式发起资料方案获取。

相关对象的 Ids 使用其自身资源类别：角色可对应 VNDB c、Bangumi character 和 YMGal ca；职员使用实际 VNDB s／p、Bangumi person 或 YMGal pa 身份。编号不能在游戏、角色和现实主体之间通用，也不从一个不明类型的数字猜 s 或 p。可选字段逐项采用：

| 来源相关资料                                   | 已对应对象的采用方式                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Character.Name、Summary、ImagePath             | 角色名称、普通文字简介、当前主图                                                             |
| Character.Gender                               | 1 为 male、2 为 female；0 是未知，不覆盖已有明确值                                           |
| BirthYear、BirthMon、BirthDay                  | 合法部分生日，可以只有月日，不补当前年份；自由 BirthDate 文字不能冒充完整日期                |
| BloodType                                      | 明确 A、B、AB、O 转为共同分类；其他设定只进入选中的补充资料笔记                              |
| Height、Weight                                 | 明确单值及单位按共同合同换算；范围、约数或单位不明时保留完整文字                             |
| BWH                                            | 只有三项定位和单位明确时分别采用 bust、waist、hips；其余原文进入选中的补充资料笔记，不猜罩杯 |
| Staff.Name、各语言名称、Description、ImagePath | 名称、按普通规则追加的别名、普通文字简介与主图；不把语言名称自动标为本名                     |
| Staff.Gender、BirthDate                        | 仅对已确定的 Person 采用明确性别和合法出生日期；不将出生日期改写为组织成立日期               |

备份角色的 Relation 自由文字和 StaffGame 职务列表只有在满足本体职责与身份合同后才能采用，不能据此推断配音关系。无法准确对应的角色／职员资料，可在选择“补充资料笔记”后保留文字与实际图片，不按姓名建图。没有选择的内容不逐项告警。

全库图片通常使用 .\Images\...，单游戏图片通常相对元数据目录；先规范化分隔符，再在所选资源根内定位。应用占位 URI 不作为真实图片。图片通过 attachments 正式接收，保存后不依赖原包；源缓存绝对路径不能授予根外读取权限。引用不存在时保留已经取得的其他内容，不按相似文件名替换图片。源码的单游戏背景图复制与引用命名可能不一致，这种情况按实际资源结果报告。

## 评分、当前状态与完成事实

MyRate 是本人 0–10 的整数值：0 表示未评分，1–10 乘 10 转为本体评分。Rating.Value 是资料源公共评分，不能作为本人评分。PotatoVN 没有同义的特别喜爱字段，不从高分、评论或某个分类名称推断。

PlayType 是固定数值枚举，按其真实含义采用：

| 来源值       | 当前安排                 | 完成事实                             |
| ------------ | ------------------------ | ------------------------------------ |
| 0 None       | null                     | 不新增                               |
| 1 Playing    | active                   | 不新增                               |
| 2 Played     | null                     | 本地没有历史时初始化一条未知日期记录 |
| 3 Shelved    | onHold                   | 不新增                               |
| 4 Abandoned  | 不采用该状态，保留已有值 | 不新增，不替换为搁置                 |
| 5 WantToPlay | planned                  | 不新增                               |

None 不因源编辑对话框预选“想玩”而变成计划。PlayCount 是有效游玩次数；源码在一次游玩达到计数阈值后增加，它不代表通关次数。LastPlayTime、LastPlay 和安装的 LastSuccessfulLaunchTime 都不是完成日期。源输入没有逐次完成历史，不提供按次数追加或恢复具体完成日期的选项。

新作品的评分、当前状态及初始完成记录随 initial 同次提交。已有条目默认保留，明确采用来源个人值时才写入所选字段；0 未评分可以按这次选择清空原评分。为已有空历史初始化一条完成事实时使用共同的 expected.completionCount: 0 条件，有历史则保留。

<a id="duration"></a>

## 分钟总量与按日记录

TotalPlayTime 为累计分钟，是本次“采用来源总时长”的主值，乘 60,000 转为毫秒。PlayedTime 是日字符串到分钟数的字典，描述同一累计量的按日分布，不能再加到 TotalPlayTime 上。源编辑器会按日值重算总量，但备份内两者都是独立保存的字段；不能声称它们在所有输入中必定一致。

明确的合法 TotalPlayTime 按原值采用，不用按日求和覆盖它或取较大值；只有该字段缺席时，才可将全部合法日值求和取得来源总量。求和使用精确整数并检查本体范围，非法总量不静默改用另一值。累计采用不需要猜测旧日字符串的地区格式。

新游戏选定的总量可以放入初始 record 的附加时长。已有游戏默认保留；明确选择采用来源总时长时，按[共同绝对值规则](../importers.md#duration)扣除已有实际活动量，再设置 additional_duration_ms，不反复累加。来源总量小于本地真实活动时，不删除活动来适配。

按日分钟没有精确起止区间，不生成日历活动，也不把整天或导入当天补成游玩过程。本项不读取 PotatoVN 云端 PlayLog，不将云端模型中的其他字段冒充本地导出已经提供的记录。

<a id="organization-data"></a>

## 评论、标签、分类与库分组

Comment 是多行普通文字，选择后创建关联游戏的独立 Note；PrivateComment 只说明来源发布方式，迁入本地不公开或同步。没有写作时间时不使用 AddTime 或最近游玩时间补造。空正文不创建笔记，同批次继续跳过已完成评论，另建批次可明确追加。

标签使用 Tags.Value 及选中的有效引擎文字。自定义分类只采用 CategoryGroupType.Custom（数值 2），将每个实际 Category 迁为手动合集，保留名称、可用封面及 GalgamesX 中的成员顺序；分类组名称保留在合集说明中，不为来源分组新增本体层级。GalgameIds / CategoryIds 是同一关系的序列化镜像，不能再产生一份成员。

Developer、Status、Engine 自动分类组是源软件按资料和状态生成的视图，不转成手动合集或猜测本体动态规则。用户可以另选“库分组”，将所选游戏库的当前成员保存为手动合集，保留库名、封面与 SortOrder；此操作与内容目录登记分开，不开启扫描或以后持续同步成员。

已有同名合集不自动合并。用户可以本次新建，或明确选择已有手动合集；已有成员顺序保留，新成员按来源顺序追加。成员引用在本次 Uuid 对应中解析，未迁入的游戏不制造占位成员。主页列表、页面排序和过滤设置不恢复为本体展示配置。

<a id="local"></a>

## 多安装、启动与存档位置

本地配置默认关闭。data.galgameSources.json 的 Galgames 项通过 Galgame 引用逻辑游戏，EntryId 区分安装条目；LocalConfig 是该安装的配置。LocalFolder（1）与 Steam（4）提供实际安装目录；LocalZip（2）只是游戏归档所在位置，Virtual（3）只是库成员，都不登记为有效游戏目录或启动配置，也不替用户解压游戏。

每份有效安装可以分别登记 GameDirectory 和启动配置。结构化路径可应用用户本次给出的旧根到新根映射，随后核验实际目录、执行文件和存档位置；不替换命令参数正文。同一游戏的多份安装各自保留配置，不复制个人评分、状态、评论或累计时长。明确 LocalConfig 优先，根 Game 中仍随导出存在的旧启动字段不能覆盖它，也不能复制到每一份安装。

Version 2 单游戏输入使用 Installation，而非 Game 的旧配置字段。元数据目录不总是游戏目录，尤其 Steam 会将元数据集中存放；迁入本地配置时使用用户明确的实际安装根，不能一律把 meta.json 的父目录或 .PotatoVN 的父目录当安装位置。

普通启动转为 Windows 完整命令，工作目录单独保存为安装目录。当前源实现把整个 ExeArguments 字符串作为一个 ArgumentList 项传入，不能按空格拆分或当作多个参数拼接；null 和空字符串也分别表示无参数与一个空参数。Windows 参数引用及 cmd 元字符必须在实现验收中验证，不能仅检查生成字符串外观。

| 来源设置                                      | 采用方式                                                                                                               |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 普通 ExePath 与 ExeArguments                  | 实际执行文件和上述单参数语义组成命令，使用明确安装工作目录                                                             |
| Steam 安装与有效 Steam appid                  | 采用来源实际的 steam://run/{appid} 链接；缺少 appid 时不扫描清单猜 ID                                                  |
| RunAsAdmin                                    | Windows 完整命令显式使用系统 PowerShell 的 Start-Process / RunAs，保留执行目标、参数和工作目录；不在导入时请求提权     |
| RunInLocaleEmulator                           | 用户本次提供当前工具路径后，保存调用该工具的命令；按源实现只将游戏 ExePath 作为工具的一个参数，不另外附加 ExeArguments |
| HighDpi、Magpie、后台静音、按键映射、TextPath | 属于系统兼容性、运行增强或独立文档入口，不修改注册表、恢复插件或自动打开说明文件                                       |

全库导出不含全局 LocaleEmulatorPath。需要转区工具却没有明确当前路径时，只报告该启动配置未迁入，其他目录和记录继续；不改为普通启动后声称配置完整。平台命令只在适用的 Windows 环境中建立，其他平台可以迁入资料和个人记录，再通过普通配置入口设置启动方式。

ProcessName 非空时按 Windows 不带扩展名的进程名解释，转换为本体完整 EXE 名称并使用本体平台比较规则。未指定进程名时，源程序跟踪启动进程并可能在安装目录内重新附着；本项按“从目录创建配置”的正常行为采用已核验安装目录监测，不声称恢复源 PID 或重新附着算法。所采用的监测方式在结果中说明，缺少可用目标的配置不能显示为已经可启动。

PreferredInstallationId 随源软件每次成功启动更新，表达最近采用的安装，不能直接当作本体人工首选。LastSuccessfulLaunchTime 也不生成实际活动。新配置不据此设置首选，已有本体首选保持不变。

选择存档设置时，优先采用当前 DetectedSavePath：%GameRoot% 绑定本次明确安装根，AppData、LocalAppData、Documents、UserProfile、LocalLow 按当前 Windows 已知目录解析，再核验实际位置。没有该字段时，可采用经核验的 SavePath 所指现有存档位置；两者不叠加为多处备份根。未知标签不任意展开。源云存档的移动、符号链接建立与网盘连接不恢复，现存链接遵守本体存档位置规则，不暗中扩大读取范围。

导出不包含游戏本体或历史存档归档。本项只登记能够对应的现有位置，保留本体默认关闭的自动备份，不从源软件云同步状态推断备份设置；所有导入操作都不启动游戏、移动存档或恢复旧存档。

<a id="interface"></a>

## 单页选择、执行与默认值

页面选择输入、游戏与数据范围，按需填写根映射、单游戏安装根及转区工具路径。来源普通资料默认选中，无须资料方案；结果可另行联网补充。名称、身份、目标与结果各占一列，不增加整批差异稿或逐项配对向导。

评分与状态、累计时长、评论、标签和自定义分类默认选择，作用于新作品。已有个人值与总时长、库分组、补充资料笔记及本地配置分别选择，默认保留已有值；本地配置默认关闭，普通资料沿共同默认选中。正常空值和未选内容不增加提示，实际未完成部分准确报告。

新增使用 prepared 与独立 initial，alreadyExists 按已有对象选项处理。其他字段、Note、合集与本地配置分别完整提交。单个配置失败不撤销作品或评论；取消保留实际结果，关闭页面不取消任务。步骤与源键对应按[批次合同](../importers.md#repeat)保存，继续只补未完成，未知提交先核对。

## 源码职责与验收

    src/
    ├── node/
    │   ├── entry.ts
    │   ├── input/
    │   │   ├── archive.ts
    │   │   ├── metadata.ts
    │   │   ├── validation.ts
    │   │   └── types.ts
    │   ├── mapping/
    │   │   ├── identity.ts
    │   │   ├── metadata.ts

    │   │   ├── organization.ts

archive 读取全库 ZIP 的明确成员，input/metadata 读取 Version 2 文件及资源根，validation 识别格式和安全读取范围；mapping 分别解释身份、资料、记录、整理和本地配置，import 调用公开本体操作并组织实际结果。IPC 只转发完整业务，Webview 不访问源文件。使用成熟 ZIP 库和普通 JSON 解析，不加载来源程序集、不按 $type 激活类型，也不需要读取源运行数据库或附带 .NET 程序。

实现验收覆盖离线 prepared 新增与原批次继续、同次 initial、已有条目复用和冲突、相关共享对象的明确更新、角色部分生日及尺寸文字、累计时长绝对值、评论及合集、全部图片准备、真实 Windows 参数和管理员／转区命令、目录与进程监测、存档 token、多个安装及跨快照冲突、取消与部分提交、输入大小和资源边界，以及六个桌面目标的独立制品。真实导出核验与合成夹具分别构成来源格式和边界行为的证据，二者不能互相替代。

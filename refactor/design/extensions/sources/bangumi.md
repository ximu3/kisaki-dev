# Bangumi 接入设计

本页规定 Bangumi 的对象、搜索、普通字段、正文、图片、参与关系、分部及个人记录采用。主要资料通过官方 v0 API 读取，版本署名与原配类别按本页规则补充官网公开资料；资料与账号操作沿[共同来源合同](../sources.md)分工。对象身份由来源实际资源及编号确定，不因它在网站上统一称为“条目”而采用同一本体粒度。

关系成员由本页的对象类别、参与范围、职责和原配规则确定，不随普通字段选择改变。即使关系 fields 为空，判断所需的类型、版本分组、参与说明与页面分类仍须读取；返回的普通资料和 note 则继续遵守请求选择。

<a id="identities"></a>

## 作品与分部身份

正式身份使用 source = bangumi，sourceId 包含资源类别及 API 数值 ID 的规范十进制形式。subject/<id> 用于作品或真实卷，episode/<id> 用于实际分集与附加内容；同一记录不能同时绑定为作品及其卷。

| 来源对象                                         | 本体采用                                            |
| ------------------------------------------------ | --------------------------------------------------- |
| type = 4 的游戏 subject                          | Game                                                |
| type = 2 的动画 subject                          | 一部独立 Anime；同系列不同季按各自 subject 分别对应 |
| type = 1、platform = 小说或漫画、series = true   | 相应 Novel 或 Comic                                 |
| 同类非系列书籍，明确通过“系列”关系归属于相应作品 | 相应作品下的 NovelVolume 或 ComicVolume             |
| 小说或漫画的非系列书籍，没有系列归属关系         | 作为独立 Novel 或 Comic，不补造正文卷               |

书籍分类使用来源明确的 platform。只有 type = 1 不足以区分漫画、小说与其他书籍；画集、公式书等不按标题猜成漫画或小说。音乐和三次元 subject 不转换为本次支持的作品。

series = false 同时可能表示单行本与独立作品，必须读取实际关联。没有系列归属时按独立作品采用，是本接入的明确约定；来源漏写关系可能使该记录先作为独立作品收录，不能宣称字段本身证明它没有所属作品。

系列与单行本关系还须核对实际类型与唯一归属。来源关系冲突、多个父项无法确定同一作品，或父项不是可采用的相应作品时，报告该项无法对应，不删除标题中的卷号来制造母体，不按返回顺序选择父项。

<a id="characters"></a>

## 角色采用范围

character/<id> 只采用 CharacterType = 1 的角色。type = 2 的机体、type = 3 的舰船和 type = 4 的虚构组织不进入本体条目或关系，也不将虚构组织转换为 Organization。机器人、AI 和拟人形象可以具有角色身份；本接入遵循来源的角色类别，不通过名称或简介重新推断，不另设自动判定字段。

同一规则适用于角色搜索、resolve、根资料与 refs 读取，以及作品角色名单和带角色的人员工作。搜索使用 POST /v0/search/characters；当前接口没有 CharacterType 筛选参数，由扩展核对返回类型并保持来源顺序。过滤后没有适用候选且来源仍有后续页时继续读取，不能把一页非角色对象当作搜索结束。

明确指向被排除类别的身份不能交付为角色 SourceEntry 或角色资料；resolve 没有其他合法线索时返回 insufficientInput。关系读取不为被排除的对象建立角色，也不把依赖该对象的具体角色工作改写为无角色工作。判断所需类型缺失时补读公开档案；仍无法确认则按相应读取失败处理，不默认 type = 1。页面上的主角、配角等作品内定位与资源的 CharacterType 分别解释。

本体按[角色范围](../../domains/catalog.md#characters)管理条目，用户可以手动建立符合角色含义的对象。Bangumi 接入采用本页的来源分类，来源本身可能存在误差；其他来源按各自的明确规则采用。

<a id="participants"></a>

## 人物与组织身份

person/<id> 用于来源现实参与者。PersonType = 1 对应 Person，2 的公司与 3 的组合对应 Organization；career 只表示通常职业，不决定主体类别，也不产生本作职责。搜索、根与 refs 读取、作品参与名册都核对同一类型规则；必要类型缺失时补读档案，不能默认个人。

本规则按来源类型采用，不根据姓名、机构后缀、简介或国籍重新分类。来源可能录入错误，按字段采用不等于已经核实所有主体的现实身份；作品岗位与主体类型仍分别解释，不因一个人承担发行就将其改为组织。

主体信息框明确给出出版社、出版品牌或连载杂志品牌，却没有对应 person 档案时，可以提供按该署名确定的组织名称和相应参与事实；不生成 person/<名称> 等假身份。普通姓名署名若不足以确认人物或组织，则不凭名字决定类别。已提供真实链接的署名复用相同 person 身份，不因名称形式不同再建一个对象。

无来源身份的对象是否复用或新建，由本体共同 matching 与采用规则决定；本接入不因只有名称就放宽身份匹配，也不直接建立疑似重复的条目。

<a id="search"></a>

## 根条目搜索与分部读取

沿用 metadata.search 的七类 Entry 边界，不增加 grain 参数、分部搜索目标或 Part resolve。作品搜索只交付适用的作品候选；明确属于卷的 subject 不作为作品返回，也不替换成其所属作品候选。

作品关键词搜索使用 POST /v0/search/subjects，按目标作品类型设置 type 过滤，使用 sort = match 并保持来源顺序。书籍候选还须补齐分类与系列归属依据，再判断是否属于本次 Entry 类型。使用 limit、offset 和来源返回的分页信息续读；过滤后没有适用候选而来源仍有结果时继续读取，不将一页卷记录解释为整次作品搜索结束。

人物与组织关键词搜索都使用 POST /v0/search/persons，按上述 PersonType 过滤为目标 Entry 类型。接口没有 PersonType 参数，不能用 career 代替；筛选、保留来源顺序及空页续读与角色搜索一致。

搜索与 resolve 不会把单卷身份绑定到作品。针对作品的定位输入若只指向一卷，不能将父作品返回为同一目标的 resolved 结果；没有其他合法的同目标线索时返回 insufficientInput。

分部身份已知时，可以通过 refs 直接读取该 subject 或 episode 的字段，不要求同时具有同源作品身份，也不读取全部兄弟分部。身份未知时，按已经对应的作品目录及现有 matching 规则取得对应。分部仍使用所属作品的资料方案，搜索结果与字段读取都不直接保存绑定。

本地应用搜索可以定位已经登记的卷、话、集和附加内容，与本节的来源搜索范围分别成立。

<a id="read-paths"></a>

## 读取上下文与反向查询

来源提供七种 Entry 上下文。根与相关对象使用同一身份、资料和关系规则；反向读取只改变候选入口，不改变角色、版本、原配或作品粒度。主要路径如下：

| 读取目标                    | 查询与采用                                                                                                       |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 作品根资料与关系            | /v0/subjects/<id> 读取根资料，/subjects 取得直接作品关联和书籍目录；先区分 Work、卷与不支持的对象                |
| 作品角色                    | /v0/subjects/<id>/characters；仅采用真实角色，relation 映射本作定位                                              |
| 作品人物与组织              | /v0/subjects/<id>/persons，并结合 subject infobox 与必要官网署名位置；采用主体范围与对应职责                     |
| 角色根与相关作品            | /v0/characters/<id> 及 /subjects；staff 表达本作定位，每个 subject 仍核对真实作品类别与粒度                      |
| 人物或组织根与参与作品      | /v0/persons/<id> 及 /subjects；按 subject 身份归并候选，再读取每部作品的主体与版本依据，只交付当前主体的实际工作 |
| 角色或人物的配音工作        | 角色 /persons、人物 /characters 提供人物、角色和实际 subject 候选，再读取相应作品官网角色页核对原配类别          |
| 已知相关 Entry 或 Part 字段 | 根 identity 可缺席，按 refs 中真实资源直接读取所选字段；不补造根身份或根关系                                     |

普通人物参与与带角色的配音分别读取，再组成所请求的 personWorks。人物 /subjects 不替代 /characters 的配音候选；反向命中也不能绕过作品侧的版本与原配范围。例如某出版社出现在漫画的反向名单，只证明它参与过该来源记录，不证明属于原版出版方。

作品角色中的主角、配角、客串分别采用 main、supporting、cameo；闲角采用 other。人物—角色接口的 staff 也可能使用这些定位文字，不能将它当作人物工作职责。已知定位为空可保留 NULL，不能据此补成主角。

以上关联接口按当前 v0 合同返回普通数组，不额外传入未声明的分页参数；搜索和章节接口使用各自的 limit、offset。所请求集合须取得全部候选及必要的范围依据后交付，失败沿共同 partialResult 合同处理。同次会话复用已经读取的主体、作品与页面，按 subject 身份归并请求，不按显示名归并，也不递归扩展未请求的资料图。

单卷中的署名、角色或其他关系不自动提升为整部作品的事实；Part 字段读取也不能因此建立 Work 参与关系。两端都确认为支持的作品后，才采用 workRelations。

<a id="ordinary-fields"></a>

## 普通资料字段

普通字段使用本体已有的[固定目录](../../domains/metadata-profiles.md#fields)。根对象、相关对象和明确 refs 使用相同映射，只交付本次请求的字段；搜索摘要不代替正式详情，来源派生字段也不代替对原始信息框含义的核对。

| 来源资料                                                              | 本体字段                                                                      | 采用方式                                                                                                   |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| subject、episode 的 name、name_cn；角色、人物、组织的 name 与明确译名 | name、originalName                                                            | name 按下文语言规则选择；originalName 保存来源主档案明确的原文名称，不由选中的译名反填                     |
| infobox 中的别名、艺名、笔名、昵称和实际其他名称形式                  | aliases                                                                       | 保留来源名称及必要限定，按共同名称规范去重；不将一整段简介或任意信息框值当作名称                           |
| subject、character、person 的 summary；episode 的 desc                | description                                                                   | 使用下节的正文转换与显式剧透规则                                                                           |
| 当前资源页面、信息框中的实际官网及相关链接                            | externalLinks                                                                 | 保留链接名称与完整 URL；跨站身份另按共同来源对应与真实粒度核对                                             |
| subject、character 明确提供的 nsfw                                    | isNsfw                                                                        | 按该对象自己的布尔值采用；person 档案没有同义字段时不回答，不从参与作品传播                                |
| 作品的首次发行、放送开始或开始发表资料                                | releaseDate                                                                   | 保存当前作品范围的首次正式公开或已公布计划日期；连载开始与首册出版分别解释                                 |
| 作品明确的原作语种资料                                                | originalLanguages                                                             | 转为规范语言标识；可用语言、配音版本、标题文字或中文界面均不构成依据                                       |
| 动画、漫画、小说明确的发行状态与结束日期                              | releaseStatus、releaseEndDate                                                 | 按本体同义值与日期精度采用；不从时间已过、目录长度或长期未更新推断                                         |
| 明确属于当前动画的时长、正片数与特别篇数                              | declaredDurationMs、declaredRegularEpisodeCount、declaredSpecialEpisodeCount  | 保持声明范围，分别采用；单集片长和混合章节总数不能填入作品总量或正片数                                     |
| 漫画、小说当前范围的页数、册数，漫画的话数                            | declaredPageCount、declaredVolumeCount、declaredChapterCount                  | 仅采用本体类型适用且范围明确的声明，不合计分部、不按目录或最后编号造数                                     |
| 真实卷自身的发行日期、卷号、页数及漫画卷话数                          | releaseDate、numberLabel、declaredPageCount、declaredChapterCount             | 保留该卷的范围，不上提作品，也不从父作品复制日期与数量                                                     |
| episode 的 airdate、ep、sort、type、duration、duration_seconds        | releaseDate、numberLabel、type、declaredDurationMs                            | 按[章节分类](#parts)确定对象；编号与顺序分别解释，时长换算为毫秒                                           |
| 角色明确的生日、性别、年龄、血型、身高、体重、三围与罩杯              | birthDate、gender、age、bloodType、height、weight、bust、waist、hips、cupSize | 沿用[角色资料](../../domains/catalog.md#characters)的部分日期、分类与 number/text 值，不推算年龄或身体资料 |
| 人物出生、逝世日期与性别                                              | birthDate、deathDate、gender                                                  | 只采用明确资料；不把人物血型、身高等变成角色字段，也不持久保存推算年龄                                     |
| 组织成立与解散资料                                                    | foundedDate、dissolvedDate                                                    | 读取组织自己的明确字段，不直接复用人物生日分量，不从最新活动推断解散                                       |

名称遵守 preferredLanguages 的有序偏好，使用来源明确标注的现有语言形式；没有匹配或未指定偏好时采用主档案 name。name_cn 与“中文名”作为来源实际提供的中文名称，明确的简繁标注分别保留；不能仅凭 name_cn 就宣称它提供了繁体译名，也不自动转换字形。明确标注的其他语言名称可以参与选择，罗马字转写不能一概视为正式英文名。简介只有原站提供的一份正文，不因偏好为英文而翻译或伪称英文资料。

别名按来源结构取得，不盲目按斜线、等号或括号拆出新名字；必要说明不被截成无依据的独立身份。人物本名与艺名均可作为实际别名，但 originalName 仍表示原文名称，不暗中改成“本名”字段。其他版本中的名称与普通资料也须属于当前对象，不能因信息框可展开就把译版内容摊平覆盖主体资料。

日期保留来源实际精度，允许只有年月或角色生日的月日；不补日、不用来源更新时间填日期。漫画 subject/10086 的开始发表为 2003-01-21，主 date 为首册出版的 2003-08-27，作品首次发表采用前者，真实首卷仍采用自己的出版日期。组织 person/603 的成立日期存在于信息框，即使 birth_year、birth_mon、birth_day 全为空也不能忽略。

API 的生日分量、blood_type、eps、volumes 等派生字段须与原信息框的含义相符。派生值为空而原资料明确时，可以按该原资料解析；冲突或无法解析时不拼凑分量，不把未知当作明确清除。角色 character/10596 的 blood_type 为空，信息框仍明确为 O 型；其无年份生日保留月日，B77/W57/H80 未明确单位时不能直接作为三项厘米数值。带条件、范围或单位不明的身体资料继续使用相应字段的完整文字值。

声明数量遵守[资料声明范围](../../domains/catalog.md#declared-values)。eps 与 volumes 的零可能表示来源未解析到值，不能直接当作明确零；total_episodes 仅为数据库登记章节数。混合正片与附加内容、多个书籍类别或版本的数量，必须先明确各自范围，不能全部相加或只截第一个数字。来源的“既刊”数量也不能被宣称为最终完结总量。

duration_seconds 是来源已声明的秒数，正值按毫秒换算；其零值同时承担无法解析的含义，须结合原始 duration 判断。可解析的时间文字按明确单位转换，原资料未明确时不补零。分集时长不变成整部动画总时长，正文中的任意数字也不补作日期或数量。

<a id="description"></a>

## 简介与信息框

description 保留来源原有介绍正文，转换为本体统一 Markdown。段落、基本强调、普通删除线和可采用的链接、正文图片按实际格式转换；来源颜色、字号等展示样式不引入另一套阅读器。安全呈现及正文图片的采用继续使用本体共同规则，BBCode 适配由 Bangumi 扩展负责，不依赖用户另选字段加工器。

Bangumi 的 [mask] 用于遮盖内容，官方人物简介约定将剧情与剧透放入其中。本接入沿用 VNDB 的显式剧透边界：转换前移除完整 mask 内容块，包括嵌套内容及其中的链接、图片，不仅去掉遮盖标记。普通 [s] 删除线正常保留，未标记文字不另做剧情分析；不以作品或角色整体排除替代局部处理。原有正文自然包含的生平、背景或创作介绍照常保留。

infobox 按已有字段与关系逐项映射，主体、职责和版本范围遵守本页合同。其余内容通过来源链接回看。正文按支持的结构转换，转换失败作为字段读取失败报告，保留其他独立取得的资料。

<a id="images"></a>

## 图片用途与候选

四类作品、角色、人物和组织的 images 用于各自 primaryImage；真实卷 subject 的封面只用于该卷。作品是封面、人物与角色是肖像、组织是标志，不将组织标志放入作品 titleLogo，也不把父作品封面复制为分集或卷自己的图片。

同一 images 对象中的 large、common、medium、small、grid 是同一主图的尺寸版本，不作为多张不同候选。优先使用来源提供的 large，缺少时选用同图的可用尺寸；图片接口的重定向与详情已给地址不重复产生候选。保留真实 URL 及其查询参数，不仅按 subject 或 person 编号判定不同时间提供的图片永远相同。

来源已知的无图占位地址不作为对象图片下载或采用。详情与图片接口都须区分确实无图、字段未回答和读取失败，不用默认占位图覆盖本地已有主图。

本接入只为七类 Entry 声明 primaryImage 的图片候选能力，按相同搜索范围与身份规则取得对象主图；已知卷可随 Part 字段读取自己的封面，不增加 Part 搜索。当前 episode 资料没有图片字段，不声明分集或附加内容的主图读取；也不凭尺寸、裁剪或名称为四类作品声明 backdropImage、titleLogo，或为游戏声明 iconImage。其他来源实际提供的相应用途仍可经资料方案补充。

<a id="tags"></a>

## 公开标签与扩展设置

四类作品的公开标签从已对应 subject 的详情读取。默认采用全部 meta_tags 公共标签，再合并按当前作品使用人数排序的前十个用户标签。tags.count 表示对当前作品使用该标签的用户数，total_count 表示该标签在全站的使用总次数，不能用后者替代本作排序，也不将这两个数写成本地标签使用数。

公共标签保持来源顺序；用户标签按 count 降序、同值按来源顺序排列，先取配置数量，再与公共标签按本体 nameKey 去重。同名时保留先取得的名称形式，不为补足去重后的数量继续越过原定前 N 项。只读取详情实际提供的标签，搜索摘要不代替正式字段读取，也不宣称这些候选穷尽了全站对该作品的全部标记。

标签保留来源名称，不根据作者名、年份或题材词表自动筛去所谓杂项，不翻译名称，也不合并近义表达。它们作为普通 Tag 使用，不据此建立人物、组织或作品关系。来源没有为标签提供说明或敏感标记时，不借用作品简介或作品 isNsfw 补齐这些字段。

本接入在扩展设置中提供以下采集选项；Profile 仍决定是否采用标签及其关系，不增加主应用全局偏好或逐字段 options。

| 设置             | 默认值 | 含义                                                     |
| ---------------- | ------ | -------------------------------------------------------- |
| 附加热门用户标签 | 开启   | 关闭后仅采用公共标签                                     |
| 用户标签数量上限 | 10     | 正安全整数，最多取详情本次实际返回的数量；仅影响用户标签 |

一次读取固定使用开始时的设置，缓存按实际设置区分。修改设置只影响后续采集，不主动更名、删除库内标签或重跑既有操作；正式采用仍按本次更新范围执行。公共标签为空时，开启的用户标签分支仍可正常提供标签；本次启用的标签分支均正常回答且合并结果为空时，才交付相应空集合，失败或字段缺席继续遵守共同完整性合同。

此规则不把单卷标签提升到所属作品，也不根据正文或任意 infobox 键批量生成标签。本人收藏中的 tags 属于连接账号的整理记录，只经明确个人记录导入采用，不混入公开资料读取。

## 作品目录与章节分类

书籍目录从 GET /v0/subjects/{subject_id}/subjects 的明确“单行本”关系取得，逐项读取必要卷资料。关系属于哪个作品、卷自身的身份及其资料分别保留。别的书籍关联不因同名或同作者进入卷清单，来源声明数量也不用于补造卷。

动画目录从 GET /v0/episodes?subject_id=<id> 完整分页取得。首次采用按来源章节类别对应：

| 来源 type          | 本体对象与分类                  |
| ------------------ | ------------------------------- |
| 0 本篇             | AnimeEpisode，regular           |
| 1 SP               | AnimeEpisode，special           |
| 2 OP               | AnimeExtra，opening             |
| 3 ED               | AnimeExtra，ending              |
| 4 预告／宣传／广告 | AnimeExtra，promotion           |
| 5 MAD、6 其他      | AnimeExtra，other；保留实际名称 |

本接入采用来源明确分类，不通过标题或简介中的关键词另行猜测内容类别。Bangumi 的 SP 范围可能包含谈话或宣传节目，首次采用仍为 special；用户通过[种类更正](../../domains/anime.md#kind-correction)调整实际对象。更正保留原来源身份，后续资料刷新遵守[既有分部的采用](../../domains/metadata.md#adoption)，不把它迁回来源默认种类。

eps、total_episodes 与实际目录分别解释。total_episodes 是来源登记章节的数量，可能包含 SP、OP、ED 等，不能直接写入本体正片声明数；也不能以它作为个人正片进度的分母。目录中的编号、顺序及分类使用相应字段，不把非本篇的 ep = 0 当作真实集号。

<a id="staff-scope"></a>

## 主体参与与版本范围

自动采集聚焦作品原作的创作、制作与出版署名。明确属于译版或其他版本的专属工作不混入主体名单；原版制作中的跨国协力正常采用，不按参与者姓名、国籍或界面语言筛选。本节不移除本体已有的 translator 和 localization 职责，用户仍可通过普通关系编辑记录实际参与与版本说明。

作品参与从关联名单、主体 infobox 和版本资料共同取得。书籍 infobox 中“版本:<版本名>”的字段数组属于相应版本，不能将其中的作者、译者、出版社、图书品牌等摊平为作品主体字段。存在版本分组时读取官网 #infobox 中对应分组与字段的真实 person 链接，用作品、主体及具体岗位确定署名范围；不只按两个版本名称字面相等来对应，也不通过参与者名称猜测版本。

同一作品和岗位只在其他版本分组中出现的主体，不因参与者 API 的 eps 为空而重新进入主体名单。同一主体也明确出现在主体资料或其他主体岗位时，保留相应事实；排除一项版本工作不等于排除这个主体的全部工作。主体出版署名可能没有出现在 API 参与者名单中，仍应按实际 infobox 资料和[身份规则](#participants)读取。

关系 eps 中明确的版本说明同样参与筛选。它可能表示集数、版本或其他范围，普通集数、空字符串和任意包含“版”字的文字都不是独立版本判据。版本分组及明确版本说明已经核对后，仍未注明版本的署名按作品主体资料采用。这是本接入的缺省约定，可能受到源站漏标影响；不能将“没有说明”本身宣称为原版证明。需要的请求或页面解析失败时仍按读取失败处理，不能转入这个缺省。

原始职责、实际署名及适用范围在已选择 note 时保留。同一主体、作品和本体职责的细项按共同业务键归并，版本中被排除的说明不混入主体工作。来源版本分组仅用于解释本次资料，不持久化为版本实体，也不自动生成标签或合集。

本节不使用“最早的一家出版社”截断连续出版作品。主体信息框明确登记的原版出版方更替属于本作出版资料，名称分别对应实际主体，必要先后说明保留在 note；它不产生组织控制或沿革关系，也不复用 VNDB 的首发批次规则。

## 作品直接关系

GET /v0/subjects/<id>/subjects 的关系先核对两端是否为本体 Work。系列与单行本用于真实卷归属，音乐、三次元与其他不支持的对象不因存在关联而进入作品图。明确且适用的关系使用下表；方向都表示从当前作品看目标作品，再沿本体共同规则规范化。

| 来源关系                                                                       | 本体关系                                        |
| ------------------------------------------------------------------------------ | ----------------------------------------------- |
| 前传、续集                                                                     | prequel、sequel                                 |
| 番外篇、外传；主线故事                                                         | sideStory；mainStory                            |
| 衍生                                                                           | spinOff                                         |
| 总集篇、全集                                                                   | summary、fullStory                              |
| 不同演绎                                                                       | alternativeVersion                              |
| 扩展包                                                                         | expansion；仅游戏之间                           |
| 合集、收录作品                                                                 | compilation、includedWork；仅目标确为独立作品时 |
| 动画、书籍、游戏等只指明媒介的直接关联；未给出方向的改编                       | related，保留来源实际称谓                       |
| 相同世界观、不同世界观、角色出演、联动、其他；含义不足以细分的不同版本与主版本 | related，保留来源实际称谓                       |

未知关系名称不能一律转换为 related；按相应关系读取失败及共同 partialResult 合同处理。取得两端的反向表达后按同一规范业务键归并，不因 API 从两个入口返回就保存两条关系。

<a id="personal-records"></a>

## 个人记录的对象与字段

本人清单先完成作品与卷的真实对应，再沿[共同导入与同步](../synchronization.md)采用所选个人值。来源上的 subject 收藏不自动等于本体 Work 记录。

本人清单支持手动导入和默认关闭的[自动导入](../synchronization.md#automatic-import)。作品与单卷从 /v0/users/<username>/collections 读取，人物与组织、角色分别从对应 persons、characters 收藏列表取得；各对象继续核对本页的真实类别。读取当前所选清单的完整分页，不以 updated_at 当作可靠的加入时间，也不把第一页或过滤后的空页当作完整结果。

自动导入仅补齐本地缺少的实际对象，已有条目或分部只复用，不自动覆盖个人记录。新对象的所选个人初值必须来自当前已核验账号且符合本节语义；合集只采用能够作为 Entry 的成员，不把一卷替换成其所属作品加入合集。本地删除后，只要来源对象仍在所选范围中，就可以再次导入，不保存“已经导入过”的排除记录。

导入明确单卷时，创建或复用真实所属作品及该卷，个人记录只作用于选中的卷。来源明确返回当前单卷收藏状态时，type = 2 采用为已读标记，其余已知状态采用为未标记已读；缺少个人记录、读取失败和未知状态不作为清除依据。单卷评分没有本体同义字段，不转成整部作品评分；卷标记也不新增作品完成历史。

对应 Work 时，type = 1、3、4 分别采用为 planned、active、onHold。type = 2 清除当前状态，并仅在本地没有完成历史时初始化一条完成事实。type = 5 沿共同无法映射规则处理，保留已有状态与历史，不触发本地删除。

当前公开收藏接口没有完成日期字段，updated_at 也不表示完成时间。由收藏状态初始化的完成记录日期为空，不使用更新时间、发行日期或导入时间补齐。该来源不声明单一完成日期的持续同步能力。

评分正值 1–10 对应本体 10–100，0 表示未评分或清除评分；本体有效 0 分不能写成来源 0。其他精度与有效范围遵守[评分规则](../synchronization.md#ratings)。单册个人值与相应 Part 标记的回写能力须按实际平台字段分别核对，不能把整部记录与分部记录混为同一操作。

作品收藏 type 只接受 1–5，没有独立空状态。同步目标为未设置且没有完成记录时，不用其他状态或删除整条收藏来模拟清空；来源已有状态不能同义表达时报告该字段未同步。参数缺席表示不修改，不表示清除。

<a id="personal-writes"></a>

## 个人记录写入

沿[共同原生写入规则](../synchronization.md#writes)，已有 subject 收藏可单独更新合法评分；没有收藏时，也可通过评分创建同一作品的收藏，接受来源默认 type = 3，并明确传入已选择的新记录可见性。不要求补选状态，不追加请求清除默认状态。

选中作品状态时，按本地当前状态与完成投影提交可表达的 type。空状态没有同义来源值时报告该字段未同步，其他合法字段仍可处理；只清空评分且没有记录时无需创建。未选文字、标签与已有 private 不直接覆盖。

逐分集写入要求父 subject 已有本人收藏。只同步分部标记而缺少父收藏时，报告不支持该操作，不另建未选父作品的收藏；这是直接操作的条目范围约束。父作品本身也在本次所选范围且其正常写入已建立收藏时，可以继续分集写入。来源重算父记录 ep_status 属于分集操作的原生结果，接受并说明，不据此生成本地作品完成历史。

来源当前代码在 type = 1 时将提交的 rate 置为 0；需要在这一状态下写入正评分时，判为不支持该取值组合，不将零当作成功保存的评分，也不改为其他状态来保存分数。合法的清空评分与已一致值仍按普通规则处理。本地记录保持原值，独立且合法的其他所选修改可以继续。

上述创建默认值、评分行为和所需父记录见[个人操作验证](../../../verification/evidence/bangumi/account-operations.md)。实现仍须对实际平台进行授权读写与回读验证；未验证的行为不能作为新增能力的依据。

<a id="cast"></a>

## 原配名册与三方关系

GET /v0/subjects/{subject_id}/characters 提供作品角色及 actors，但 actors 不区分原配与译配。角色反向接口 /v0/characters/{character_id}/persons 也不能仅凭 staff 字段区分语种；其中“主角”等文字表示角色在作品中的定位，不能当作配音岗位或语言。

配音分类从同一作品官网公开页面 /subject/<id>/characters 的角色行及演员块取得，按真实 character、person 和 subject 身份组成三方事实。采用演员块中 attr-rlt-type = 0、类别名为 CV 的记录；中配、日配等另外标出的语言版本及真人演员类别不进入 voiceActor。本接入将该来源的 CV 类别作为原配采用，不根据演员姓名、国籍、母语或界面语言判断。

演员主体仍按[人物与组织身份](#participants)核实，只有 Person 可以形成 voiceActor 工作；不能因为来源提供了 CV 关联就把公司或组合改为人物。

已验证日本动画《葬送的芙莉莲》的种崎敦美为 CV、中配另列；中文动画《时光代理人》的杨天翔为 CV、日配另列。CV 类别不是“日本声优”的别名。该规则依赖来源正确标注关系类型，不宣称能够识别来源误标或漏标的译配。

读取时先按[角色采用范围](#characters)限定本次 API 名册，再在同一作品页面的对应角色行中取得配音类别。只解析资料列表，不采用评论、推荐或页面用户状态。必要角色行、演员身份或类型标记缺失时，按相应集合读取失败处理，不退回混合演员数组，也不以空名单掩盖失败；其他独立资料沿共同 partialResult 合同处理。

同一角色的多个 CV 都可以形成参与关系，不以 attr-rlt-primary 只留下一个人。相同作品、人物、voiceActor 和角色的重复项按业务键归并；来源没有年龄阶段等说明时不补造。反向角色或人物读取也必须保留实际作品范围，不能把某人给这个角色配过音扩展到该角色出现的全部作品。

同次读取复用已经取得的作品角色页面和身份资料。Bangumi 扩展解析来源页面结构，正文与图片字段使用各自声明的读取能力，配音采用本体已有的人员工作关系。

来源核对与样本范围见[验证记录](../../../verification/evidence/extensions.md#bangumi)。

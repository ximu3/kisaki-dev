# 当前状态、附加时长与完成记录

个人记录支持快速管理当前状态，并回顾、修改每次完成的记录。当前状态、作品完成记录、分部完成标记、文件位置和实际活动分别保存，不组成体验轮次或使用过程。

条目当前个人值及附加时长由 library 的 entries 实现，完成历史位于 records/completions；分部标记、文件位置与活动遵守[内部归属](library-operations.md#personal-regions)。本篇将相关产品含义一起说明，不据此建立统一记录实体或把所有实现放入同一模块。

<a id="model"></a>

## 作品状态与完成事实

游戏、动画、漫画和小说的当前状态只有 planned（计划中）、active（进行中）、onHold（搁置），另以 null 表示未设置。当前状态表达用户现在的安排；新建、收录或发现本地文件都不自动填写 planned。缺少当前记录行时按未设置读取。

每条作品完成记录表示一次已经登记的完成事实，可以没有日期和备注。作品是否完成过及完成次数从这些记录得出，不另存可写的 completed 状态、完成布尔值、完成次数或最近完成日期。没有完成记录只表示尚未登记，不证明用户从未完成。

当前状态与完成历史可以同时成立。例如，active 与两条完成记录表示当前在玩、看或读，并且已经登记过两次完成。重新设为 active、planned 或 onHold 不修改历史；清除当前状态也不撤回完成记录。没有当前安排但仍要保留资料或历史时，使用未设置；不再保留条目时执行普通条目删除。

完成标准由用户判断，不自动等于全成就、全路线、全部附加内容或全部已登记分部完成。实际打开、有效计时、播放末尾、末页和退出都不产生作品完成记录，也不自动改变当前状态。反过来，修改个人记录不打开、暂停、关闭或终止实际内容。

<a id="schema"></a>

## 存储与读取值

各媒介的当前记录仍分别保存在 game_records、anime_records、comic_records 和 novel_records，以所属作品为主键。四张表均保存 status 和 additional_duration_ms：前者使用三种当前状态或 null，后者为未包含在实际活动中的附加使用时长，使用非负安全整数毫秒，默认 0。缺少当前记录行时分别按 null 和 0 读取，不强制建立占位行。评分和收藏继续属于条目评价，不放进完成记录。

四类作品共用 work_completion_records。work_id 的外键保证 Entry 存在；completions、条目创建和合并等受控写入在同一事务内核对目标属于四类 Work，并具有对应类型行。作品类型限制由这些完整操作承担，不依赖 TypeScript 联合类型或普通外键代为检查。

| 字段           | 值与含义                                                      |
| -------------- | ------------------------------------------------------------- |
| id             | 创建后稳定的完成记录 ID                                       |
| work_id        | 引用 entries.id，目标必须是四类 Work 之一；不重复保存作品类型 |
| completed_date | 可空的完整 CalendarDate，表示本次完成的日历日期               |
| note           | 可空纯文本备注；全为空白时保存 null，其余内容保留原文         |
| created_at     | 本条记录实际建立的 UTC 毫秒时间                               |
| updated_at     | 本条记录日期或备注实际修改的 UTC 毫秒时间                     |

CalendarDate 的完整分量、编码与校验见[完整日历日期](values.md#calendar-date)。日期未知时整值为 null，不使用 PartialDate，不补齐来源缺少的月日，也不拿创建、编辑或导入时间充当完成日期。没有日期和备注的记录仍然是一条完整的完成事实。

记录归属于作品，只有完整条目合并可以迁移归属。日常编辑不改变 id 或 work_id。索引覆盖作品内的日期与稳定补序、work_id 与创建顺序，以及完成日期范围到 work_id 的期间查询。相同日期、相同备注和同时为空都不构成唯一约束。

读取提供 completionCount、firstCompletedDate 和 lastCompletedDate，与[公共查询值](library-query-contracts.md#projection)使用同一字段名。次数是该作品记录行数；两个日期分别取已知非空日期中的最小值和最大值，没有已知日期时为 null。未知日期的记录仍计入次数，不据此推断实际最早或最后一次完成发生在何时。它们都是只读投影，日期按年、月、日比较，不比较 JSON 编码文字。查询、期间统计和未知日期口径见[完成记录查询](library-queries.md#completion-records)。

## 附加时长与来源累计量

附加时长用于保留没有本地活动明细的游玩、观看或阅读时间，游戏、动画、漫画和小说使用相同规则。累计使用时长等于本体已保存有效活动之和，加上 additional_duration_ms；当前尚未提交的有效增量可以另行显示，不能重复计入。不保存另一列可编辑的 total_duration 镜像。

公开当前记录字段统一为 record.additionalDurationMs，随 entries.create／update、原生新增的 initial 或明确图写入采用。修改只设置非负绝对值，不提供递增总时长或按来源账号保存累计值的接口。已有值编辑沿用 expected.record.additionalDurationMs；缺行的基线为 0。来源资料候选不携带此个人值，不增加游戏专属旧字段或兼容别名。

四类作品详情都允许编辑附加时长，无需本地文件、启动配置、分部完成或作品完成记录。表单区分已经记录的活动时长与附加时长，只编辑后者。已知明确发生区间时使用[活动补录](library-operations.md#activities)；活动更正或删除不自动反算附加值，也不允许用负附加值抵消错误活动。

采用外部累计总量时，先明确目标 Work 和来源覆盖范围。用户选定来源总量 T，以本次读取的已保存活动量 A 为基准，将附加时长设置为 T−A；已有附加值不再次叠加。新作品没有本地活动，选中的来源总量直接作为初始附加值。来源总量小于 A 时，该总量不采用，不截断、不生成负数、不删除活动。

例如已有 3 小时活动，采用来源总量 10 小时，则附加时长设为 7 小时；之后新增 1 小时活动，累计为 11 小时。再次明确采用 10 小时是新的设置，此时附加值为 6 小时。操作固定本次来源总量、活动基准和附加值基线，重试仍提交同一个绝对值；期间正常新增的活动继续计入，不在后台循环对齐来源总量，也不维护跨次采用账本。

来源有多本书、多卷、多个版本或多个时间字段时，由来源适配先确定互不重复的累计范围，再按 Work 形成一次采用。累计量、按日分解和同范围活动明细不能直接相加，重复源键也不能重复计时。尚无精确 Part 对应不妨碍采用明确属于该 Work 的使用时间；不会因此生成 Part 时长字段或把使用时间解释成完成。

附加时长没有发生日期，只进入不限定发生日期的累计使用时长；不进入日、周、月图表、热力图、期间排名、活动条数或单次活动统计，也不改变最近使用、文件位置、当前状态和完成记录。来源日汇总本身不构成真实活动区间，不用导入当天或“最后时间减总量”补造日期。作品合并保留所选目标的附加值，不自动相加或取最大值；实际活动按各自身份迁移。

## 完整操作

| 操作                   | 修改结果                                                        |
| ---------------------- | --------------------------------------------------------------- |
| 设置或清除当前状态     | 只修改三种当前状态或 null，保留所有完成记录                     |
| 记录本次完成           | 新增一条完成记录，并在同一事务清除当前状态；不要求此前为 active |
| 补录完成记录           | 新增一条完成记录，保留当前状态                                  |
| 编辑完成记录           | 按稳定 ID 修改该条的日期或备注，保留其他记录及当前状态          |
| 清除完成日期           | 将该条日期改为 null，保留完成事实及备注                         |
| 删除完成记录           | 删除指定记录，保留当前状态；次数和完成情况按剩余记录计算        |
| 设置或清除分部完成标记 | 只修改明确分部的已看或已读标记                                  |

“记录本次完成”的界面日期默认今天，用户可以清空；补录默认日期未知。完整操作接收明确日期值或 null，不在主进程、SDK 或来源适配中用调用时刻补出完成日期。两种新增操作共用日期和备注字段，通过入口决定是否清除当前状态，不增加“同时修改状态”的选项。

删除最后一条完成记录后，作品不再满足“有完成记录”，但当前状态、评分、分部标记、文件位置和活动不变。以上操作均不生成游玩、观看或阅读时长，不重置文件位置、存档或标注。

完整操作由 library 拥有，UI、批量入口、SDK 和来源扩展共用。公开能力如下：

| 能力                                  | 输入与结果                                                                                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| library.entries.setEvaluation         | EntryRef 与适用的评价字段修改；只改变明确提供的评分或收藏，成功返回 void                                                                          |
| library.entries.setWorkStatus         | WorkRef 与三种状态或 null；完成后返回 void                                                                                                        |
| library.completions.list、get         | 读取指定作品的有界记录列表及总量，或按作品和 completionId 读取一条；get 未命中返回 null                                                           |
| library.completions.statistics        | 接收明确 Work 范围及完成日期条件，返回完成次数、去重作品数和日历分组；同一 Work 范围的未知日期数量单独返回，不充当期间次数                        |
| library.completions.create            | WorkRef、completedDate、note 和可选 expected；新增历史记录并返回 completionId，保留当前状态                                                       |
| library.completions.createMany        | 明确的完成记录输入数组，每项包含 work（WorkRef）、completedDate、note 和可选 expected；同一作品可以有多项，整个短批次一起提交并按输入返回 ID      |
| library.completions.recordCurrent     | 与 create 相同的输入；新增记录和清除当前状态一起提交，返回 completionId                                                                           |
| library.completions.recordCurrentMany | 非空项目数组，每项包含 work（WorkRef）、completedDate、note 和可选 expected；按去重后的每部作品各新增一条并清除当前状态，返回作品与记录 ID 的对应 |
| library.completions.update、delete    | WorkRef 与 completionId；update 只接受日期、备注及相关 expected，delete 只删除该记录；完成后返回 void                                             |

新增记录的空日期和空备注使用 null；调用方可以明确创建两项都为空的完成事实。recordCurrent 表达“记录本次完成”的明确动作，按传入日期和备注新增完成记录并清除当前状态；存在运行会话或当前安排均非前提。普通历史新增保留当前状态。修改或删除的目标已经不存在时正常失败。

条目当前个人值使用 entries.update 或相应的即时设置操作。作品状态只适用于 Work，其他 Entry 只接受适用评价字段。完成历史使用 completions 的完整操作，不与评分、收藏和状态组合成另一种个人记录写入接口。创建条目和 writeGraph 可以携带明确的初始完成记录；completionRecords 是逐条事实的输入数组，不是独立完成计数。metadata 候选和资料方案不携带这些个人值。

相关提交实际改变业务事实后，按[完整写入](library-operations.md)发布对应变更摘要，供列表、详情、统计和同步重读；摘要不携带备注正文。新增记录不会因日期或备注与已有记录相同而自动省略。

<a id="creation-baseline"></a>

## 新增记录的历史数量基线

create、createMany、recordCurrent 和 recordCurrentMany 的 expected 只允许 completionCount，取值为非负安全整数，表示本次决定依赖的目标作品完成记录数量。单条与批量项目使用相同的日期、备注和数量基线合同。基线属于本次操作的 WorkRef，不能借此比较其他作品或无关条目字段。已有完成记录的日期与备注编辑，仍按该记录的实际字段基线处理。创建条目时的初始 completionRecords 只提供日期与备注，不携带已有作品的数量基线。

来源扩展读取到作品尚无历史，并决定仅在这一前提下初始化时，可以使用：

```ts
await library.completions.create(workRef, {
  completedDate: null,
  note: null,
  expected: { completionCount: 0 }
})
```

本体在核对目标合法性的同一短同步事务内比较当前数量并执行写入。数量不符时返回 Conflict，该次完整操作不写入；recordCurrent 和 recordCurrentMany 也不清除当前状态。省略该条件时，新增不依赖已有历史数量，普通补录和记录本次完成继续按明确意图新增。

createMany 和 recordCurrentMany 的基线按作品核对。相同作品的各项若提供数量基线，值必须一致；未提供的项不取消其他项已声明的条件。所有相关作品的数量都在本批新增前读取和核对，再共同提交全部记录及适用的状态清除，不能每插入一条后重新比较初始数量。矛盾的数量基线作为无效输入拒绝；任一必要条件失败，整个短批次不提交。

completionCount 在这里是只读前提，不是可写计数或历史版本。数量相同不证明成员、日期或备注没有变化，也不证明期间从未发生修改。该条件不用于匹配或去重完成事实，不形成跨次导入状态。条件失败按共同冲突规则处理，不自动刷新基线重放。

<a id="batch"></a>

## 批量操作

批量状态设置只写当前状态。批量“记录本次完成”给每部选中作品各新增一条，并清除其当前状态；批量补录给每部选中作品各新增一条，保留当前状态。已有完成记录不使这两个新增动作跳过目标。

界面说明“为 N 部作品各新增一条完成记录”，将共同日期和备注填入各目标的输入项目，并直接执行普通批量补录。只为尚无历史的作品补录时，先使用“无完成记录”筛选确定目标。

界面批量操作的作品目标遵守[固定目标集合](library-operations.md#selection)：在开始前固定并按作品身份去重，修改后离开筛选结果的作品仍属于原批次，新进入结果的作品不加入。短数据库批次共同成功或失败，不静默跳过失效或不适用目标。

recordCurrentMany 接收明确的非空项目数组，每项表达对一部作品执行一次完成动作。同一作品重复出现时，日期与备注按正式字段规范化后必须相同，所提供的数量基线也必须一致；符合条件的项目合并为一次动作，输入矛盾时整批拒绝，不选择其中一项覆盖其他项。结果按作品首次出现的顺序返回，每部作品对应一个新记录 ID。

createMany 的每项表示一条独立历史事实，允许同一作品出现多项，包括日期和备注相同的记录，返回值仍与输入项目逐项对应。这与按作品去重的完成动作分别处理。再次明确发起任一种新增操作仍会新增记录，除非本次提供的数量基线不成立；不建立跨次防重状态。

批量输入按[容量边界](../engineering/performance.md#results)接纳。合法安全整数不代表能够一次创建同样数量的记录；来源总数须先通过展开预算检查。超限的原子批次整批拒绝，已存在历史保持不变。

## 分部标记与作品的边界

AnimeEpisode、AnimeExtra、NovelVolume、ComicVolume 和 ComicChapter 的个人记录只有 is_completed 布尔标记。各类型的可选一对一记录表以对应 Part 为主键，缺行按 false 读取。

作品与分部之间不自动传播完成。标记一集、一卷或一话不新增作品完成记录；全部已登记分部都有标记，也不能证明作品内容完整。记录作品完成不自动标记所有分部。明确的批量分部操作只修改本次提供的 PartRef；后来新增的分部不继承旧选择。

作品当前状态和完成历史变化不清除分部标记，分部标记变化也不修改文件位置或实际活动。新增第四卷可以使分部计数从三／三变为三／四，过去的作品完成记录仍然保留。分部数量、文件进度与作品完成次数分别显示，不能相加或互相推导。

动画的[自动已看](anime.md#auto-completion)只设置分部布尔标记。漫画、小说和各层完成行为仍按对应媒介的明确操作处理，不从末页或合订文件位置推导整个作品完成。

## 来源采用、合并与删除

平台状态快照按[个人记录导入与同步](../extensions/synchronization.md)采用。已完成状态或语义明确的完整完成日期可以为没有历史的作品初始化一条完成记录；来源处于进行中并具有完成日期时，可以同时采用 active 和这条过去的完成事实。本地已有历史时不追加、不覆盖，也不按日期认为两条记录是同一次完成。

来源解释、采用字段和操作选择由扩展负责。已有作品的历史初始化通过上述数量基线保证前提，当前值和历史分别调用适用的完整操作；需要新增完成事实并清除当前状态时使用 recordCurrent。各独立操作按实际结果报告，不承诺同一来源项目的全部个人值共同原子提交。

管理软件的真实逐次历史和明确的完成总数按[迁移导入](../extensions/importers.md)处理。初始化空历史与明确追加历史分别表达；普通新增不按同日或同备注去重。导入器继续原批次时复用已完成步骤，新建批次的明确追加仍可新增，批次进度不成为完成记录的身份或通用防重状态。

合并作品时，完成记录保留 ID、日期和备注并迁入保留作品；不按同日、相同文字或空日期自动删除记录。当前状态采用保留作品的值，包括 null。作品合并保留各分部身份及标记；用户另行明确合并同一内容的分部时，按[分部合并](library-operations.md#part-merges)将标记取任一侧为 true。合并不另外产生完成记录，完整规则见[合并与删除](library-operations.md#identity-operations)。

删除作品会删除其拥有的完成记录，独立笔记、文件字节及其他数据按各自删除合同处理。作品删除后退出该来源同步范围，不以本地条目缺失为由删除平台收藏。删除文件登记、移除目录或文件暂时失联不删除作品完成历史。

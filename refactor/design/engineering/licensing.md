# 许可、第三方材料与分发

桌面客户端和官方扩展的自有实现采用 AGPL-3.0-only，八个公共包及自有脚手架模板采用 MIT。独立第三方扩展可以自行选择许可，其与本体的组合通过明确的额外许可授权。第三方代码、字体、图像和其他资源按各自实际许可处理。

AGPL-3.0-only 不预先授予使用未来版本的选择权。项目保留完整标准正文，另行列出独立扩展的额外许可。任何后续授权都须有相应权利，并检查外部贡献是否纳入该权利范围，不能仅凭维护者身份重新授权，见 [SPDX 定义](https://spdx.org/licenses/AGPL-3.0-only.html)。

MIT 包不限定只能用于 Kisaki 或客户端，外部 Web、服务和工具可以按许可条件复用；每个包仍只提供自己声明的公共能力。MIT 层围绕清楚的用途划分，不把全部业务搬入 shared 或 core。适用许可由实际文件和交付内容决定，不能只看目录名称。

四个独立项目分别核对自身权利和依赖许可，不因与 Kisaki 协作而自动改变授权。

site 与候选 server 不在当前桌面交付范围内，各自的公开范围和许可在对应项目建立前明确，目录规划不预先决定其许可。只有可共同公开的源码才纳入同一公开仓库；客户端构建与交付不依赖私有服务端实现或生产凭据。

## 原创图像与品牌

作者原创的 Kisaki 图标、标志及源文件随本体采用 AGPL-3.0-only，可以按许可条件复制、修改和用于构建。完整源码包含这些资源。字体、图标集合和继承图片继续遵守各自许可，不因原创图像的授权方式而改变。

软件和图像的复制许可不代表官方认证、背书或额外商标授权。修改版需要说明来源和修改，品牌身份说明与复制许可分别表达。项目不声称拥有已注册商标，也不因此改变应用的分发身份。

## 本地客户端与服务

官方云采用账号订阅模式，不提供自部署产品。当前桌面交付不实现套餐、配额、计费、保留期限、第三方服务访问或加密展示规则。客户端开源不授予无限云资源，购买服务也不改变用户对本地数据的控制。

本地资料管理、阅读、播放和读写不要求持续登录或订阅，在云服务不可用时仍然成立。私人同步和公开展示是不同操作，Note、账号信息和位置不能自动公开。oauth-relay 不承担 Kisaki 账号、计费或云同步职责。

[AGPLv3](https://opensource.org/license/agpl-3.0) 和 [MIT](https://opensource.org/license/mit) 分别规定其分发、适用网络交互及代码复用条件，二者都允许符合条件的商业使用。修改版的源码义务不等于向官方提交 PR，也不要求官方合并。

通过协议通信不会自动授予双方实现的版权。实际复制或组合代码时，不能仅以分仓、分进程或不同 HTTP 地址规避许可条件。拥有完整权利的自有代码可以另行授权，外部贡献和第三方材料不自动包含在内；其他产品应通过 MIT 层或真实授权复用实现。

浏览器中的 JavaScript 可以被取得，服务权益、支付和配额仍由服务端判断。闭源不代表前端字节无法读取。

## 独立扩展的额外许可

独立新写的第三方扩展可以开源或闭源，也可以提供重要的新功能。是否收费与选择哪种许可分别决定。闭源扩展的审查、修改和持续维护可能依赖作者，官方的开放承诺不因此覆盖所有第三方扩展。

MIT SDK、进程隔离和包边界本身不能代替组合授权。有权授权者依据 [AGPL 第 7 条](https://spdx.org/licenses/AGPL-3.0-only.html)，为必要的实际接入代码提供范围明确的额外许可，同时保留本体及其修改的源码要求。

额外许可不覆盖对本体或官方扩展实现的复制、改写，也不豁免第三方材料的条件。正式许可正文和授权覆盖范围是发行前必须完成的内容，不能通过改写标准 AGPL 形成含糊例外。

独立扩展可以闭源；官方收录仍以 33 项目录为准，维护状态和可信度需要分别判断。扩展 Node 运行在可信执行环境中，拥有进程可用的系统能力。包签名遵守分发合同。许可证声明说明可用范围，来源与维护信息供用户判断信任。

扩展离开后，核心资料仍应能够维护。外部服务能否继续提供能力与源码是否开放分别判断。

# 独立项目与联合交付验收

本页落实 A23、A28、A31、A33 的独立制品与联合消费要求，并接续各业务场景。使用正式候选制品及目标环境；声明、源码依据、机制原型、真实 addon／服务、宿主流程与最终制品分别提供证据。

<a id="delivery"></a>

## 共同交付

每个项目在自己的仓库提供源码、合同、锁文件、测试、工具、使用文档及发行材料。仓库外从 tarball 或固定服务镜像消费，核对声明和实际导出、匹配版本与资源、依赖及许可。Kisaki 锁定这些制品后完成联合调用，不使用跨仓源码 link。

两个原生库覆盖 Windows、macOS、glibc Linux 的 x64／arm64。最低系统、Node-API、Node／Electron 范围及桌面版本按[构建合同](../../design/engineering/build.md)与[原生交付合同](../../design/projects/native-runtime.md)逐项记录。各场景使用对应目标环境执行，记录实际结果与兼容性依据，交付按[运行覆盖规则](../acceptance.md#runtime-coverage)判定。

<a id="scenarios"></a>

## 专项场景与宿主接续

| 项目                          | 独立能力与联合消费                                                             |
| ----------------------------- | ------------------------------------------------------------------------------ |
| [Vantage](vantage.md)         | 实例与观察、前台、窗口控制、单窗采集、权限和桌面后端；接续游戏监测与退出备份   |
| [Kana](reading.md)            | 格式、源地址、呈现、阅读交互、资源与整包部署；接续持久位置、标注和产品会话     |
| [libmpv-node](libmpv.md)      | 命令与值、线程和实例寿命、颜色、共享帧、关闭及最终包；接续媒体就绪、播放与标注 |
| [oauth-relay](oauth-relay.md) | 公开 HTTP、来源能力、凭据保存、镜像与停止；接续实际来源扩展的授权和刷新        |

每个项目先证明自身公开承诺，再由 Kisaki 或对应扩展证明实际消费。结果分别记录版本、输入、目标环境和制品，联合结果不覆盖尚未执行的独立场景。

首次正式交付至少取得[主要后端与实际端口的最低链路](../acceptance.md#minimum-runtime)。独立项目与 Kisaki 可以共用同一次完整运行的不同断言，前提是它确实消费本次候选制品；没有实际执行的另一后端、架构或宿主不能随之记为通过。

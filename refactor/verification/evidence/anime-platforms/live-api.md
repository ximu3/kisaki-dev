# MAL 与 AniList 来源核验

核验日期：2026-10-16。来源设计见 [MAL](../../../design/extensions/sources/mal.md)与 [AniList](../../../design/extensions/sources/anilist.md)。

本报告区分接口事实、待确认的采用规则和实现验收。结构化记录收录 148 次请求，其中 71 次为用户明确授权的临时个人记录写入或清理；另检查了 4 个实际图片地址。初次浏览器授权按认证结果另行记录，不将这些计数称为全部网络活动。

[结构化记录](2026-10-16-api.json)保留必要字段、测试业务值和回读结果，不保存凭据、本人身份、完整私人列表或原始正文。所有测试均限于事前确认不存在本人记录的两部作品，没有修改其他作品或公共资料。

## 样本与清理

| 样本                 | MAL         | AniList      |
| -------------------- | ----------- | ------------ |
| 《葬送的芙莉莲》动画 | anime/52991 | media/154587 |
| 《刀剑神域》小说     | manga/21479 | media/51479  |

开始时，两站的本人动画和书籍列表均为空，AniList 五类喜爱也为空。测试使用明确的临时评分、数量与日期，不代表用户真实体验。

MAL 动画和小说测试项均已 DELETE，逐项回读 my_list_status 不存在，相应本人列表重新为空。AniList 两个测试列表项已删除，动画喜爱已撤回；逐项及全部列表回读均为空，五类喜爱均为 0，两个目标的列表动态查询也均为空。AniList 评分格式仍为 POINT_10_DECIMAL，高级评分仍未启用。

AniList 临时修改的应用回调已经保存恢复为原 HTTPS 地址，并重新加载页面确认。MAL 的固定 loopback 登记已由用户保存；本次两个来源共用的临时本机接收器已关闭。清理结论指向上述实际记录和核验范围，不宣称撤销整个应用授权或完成产品实现。

## 认证与刷新

| 项目                   | 实际结果                                                                 |
| ---------------------- | ------------------------------------------------------------------------ |
| MAL 公共作品读取       | Client ID 认证成功，未要求本人登录                                       |
| MAL 本人授权           | plain PKCE 与已登记固定 loopback 成功                                    |
| MAL 本人身份／两类列表 | /users/@me、animelist、mangalist 均为 200                                |
| MAL 刷新               | 200，返回新访问／刷新令牌，随后仍识别为同一账号                          |
| AniList 本人授权       | 临时本机回调的 authorization_code 交换成功，原登记已恢复                 |
| AniList 本人读取       | Viewer、两类媒体列表、五类喜爱及平面列表分页查询成功                     |
| AniList 刷新           | 实际返回 refresh token；refresh_token grant 为 200，随后 Viewer 身份一致 |

MAL 令牌响应的有效期为 2,682,000 秒，AniList 为 31,536,000 秒；实现应使用实际 expires_in，不把样本值硬编码为协议保证。

AniList [当前认证文档](https://raw.githubusercontent.com/AniList/docs/master/docs/guide/auth/index.md)仍说明没有刷新支持，与这次真实响应和刷新结果不同。新方案采用已经读通的上游刷新能力；来源认证核验不替代正式 relay 消费链路的实现验收。

## MAL 的个人操作事实

本次使用 PATCH，而不是沿用 OpenAPI operationId 或示例里的旧 PUT 字样。接口响应与独立读取共同核对，不能只看 HTTP 200。

| 操作                       | 动画结果                               | 书籍结果                                   |
| -------------------------- | -------------------------------------- | ------------------------------------------ |
| 写入 8 分、清除为 0        | 成功                                   | 成功                                       |
| 已有记录清除 status        | 空字符串成功，字段随后省略，其他值保留 | 同样成功                                   |
| 写入／更改 finish_date     | 成功，日期能独立回读                   | 成功，日期能独立回读                       |
| 清除 finish_date           | 空字符串成功，随后省略                 | 同样成功                                   |
| 只改变 completed           | 不自动填满集数或日期                   | 不自动改动已有卷话数量                     |
| 只增加集数进度             | 2、28 均成功，仍保持 watching          | 本次已核对独立卷话字段及其在状态变化时保留 |
| 没有记录，仅写评分         | 默认 watching                          | 创建无状态的评分记录                       |
| 没有记录，评分加显式空状态 | 仍默认 watching                        | 无须此技巧即可无状态创建                   |
| 没有记录，仅写完成日期     | 默认 watching                          | 创建无状态的日期记录                       |
| 没有记录，仅写动画进度     | 默认 watching                          | 本轮不提供书籍数量到本地分部的同步         |

书籍独立评分创建在删除前为无状态和明确 reading 两种情形下重复核对，结果均保持无状态，不把已清空状态的残留误认为普遍创建规则。

官方[当前 v2 规格](https://myanimelist.net/apiconfig/references/api/v2)的更新参数没有列出日期，状态说明也只列五种非空值；实际读写已补齐上述差异。读取方必须区分：记录存在且所请求的可空字段已清空，与整个本人记录不存在。

重看标记也不是另一条完成历史。本次 status=completed、is_rewatching=true 的记录会出现在 watching 筛选中，而不在 completed 筛选中；普通原始 status 不能单独代表其当前状态。重看布尔值、次数和数量分别保留，不从它们补出多条历史。

这些结果区分动画与书籍的真实创建行为。当前设计均提供评分和日期创建：动画接受默认 watching，书籍可以无状态；不额外补选状态，也不通过后续请求清除默认状态。原始响应不因采用规则调整而改变。

## AniList 的个人操作事实

| 操作                                 | 实际结果                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------- |
| scoreRaw=87                          | POINT_100 为 87；POINT_10 为 8；POINT_10_DECIMAL 为 8.7；POINT_5 为 4；POINT_3 为 3 |
| scoreRaw=1、0                        | 1 可保存；0 为清除评分                                                              |
| 只写评分创建记录                     | 默认 CURRENT，并填入当天开始日期                                                    |
| 显式全空 startedAt                   | 可以清除或在 CURRENT 写入时保持未知                                                 |
| 单独写／清 completedAt               | 动画、小说均成功，状态和已有数量可以保留                                            |
| 仅将动画状态改成 COMPLETED           | progress 自动变为 28，并自动填写完成日期                                            |
| 完成时显式传原进度 0 或 2            | 仍被强制写为 28                                                                     |
| 完成时显式传原日期或全空日期         | 日期可以保留                                                                        |
| REPEATING 完成，显式传原 repeat=2    | 实际增加到 3                                                                        |
| 仅将动画 progress 提高至 28          | 联动为 COMPLETED，并填写完成日期                                                    |
| 已完成后单独降低 progress            | 可以保留 COMPLETED，说明不能在每次评分更新时重发状态                                |
| 已有 CURRENT／COMPLETED 上仅更新评分 | 保留原状态、数量、repeat 和日期                                                     |
| 小说总话数、总卷数为 null 时完成     | 保留原有 2 话、1 卷进度                                                             |
| status:null                          | 不会形成空状态；小说样本由 COMPLETED 变为 CURRENT                                   |

按百分制读写可以避免显示分制转换损失。当前设计正常提交状态并接受自动日期、强制满进度和重看次数增加；不附带未选字段原值保护，也不先写后补偿。完成日期被选中时才提交其本地投影，具体见[原生写入规则](../../../design/extensions/synchronization.md#writes)。

本次账号没有启用高级多维评分，没有修改该设置。当前方案仍通过 scoreRaw 接入正式总分，不因模式本身关闭入口；实际重算和回读保留为尚未完成的来源核验，不把本次结果扩大到未测试模式，也不自行平均或回写各维度。

## 喜爱切换与写后旧值

对动画 154587 的 ToggleFavourite 实际加入成功，mutation 返回的收藏连接包含该作品；首次紧接着读取 Media.isFavourite 却仍为 false，后续读取才为 true。撤回后，mutation、本人收藏连接和 Media.isFavourite 均确认不再喜爱，列表项已经删除。

这证明切换操作不能按“立即回读仍是旧值”自动重放。它也不能按分页重复调用；后续核对须使用查询。未知结果需要等待并进行有界读取，不能宣称 toggle 本身具有幂等性。本次只实际切换动画喜爱；其他四类的读取与参数合同不代替各类写入验收。

## 作品、图谱和分页

MAL 的小说 21479 返回 light_novel，num_volumes 与 num_chapters 均为 0；规格明确这些零可表示未知。AniList 对应 51479 为 MANGA／NOVEL，两个总量为 null。两站都提供作品正文与实际封面，但这些字段不证明存在逐卷、逐话目录。

AniList 的角色、Staff、Studio、图谱关系、标签和本人字段均已读取当前 schema。实际 CLAMP 为 Staff 96877，证明 Staff 不能整体等同 Person；官方[人员手册](https://anilist-submission-manual.super.site/staff)也明确容纳公司与团队。该事实支持沿用已确认的混合主体边界。

官方[角色手册](https://anilist-submission-manual.super.site/characters)指定了全站旁白 36309 与其他声音 36310，本次按这些 ID 读取成功。它们属于署名占位。角色别名还有独立 alternativeSpoiler 字段，不能混入普通别名。

《芙莉莲》角色连接实际完成 25、25、25、25、0 五页；前四页报告 total=500，第五页才报告 total=100 且结束。小说搜索前两页各取得 3 条不同候选，但 total=5000。因此分页使用 hasNextPage 与真实页面，不依赖估计总量。

Studio 档案只有名称、分类、作品连接和站点链接等字段，没有原生简介、图片或成立日期。isMain 表示本作主动画制作；组织通常业务不能代替每部作品的具体职责。

AniList [关系手册](https://anilist-submission-manual.super.site/relations)将 PARENT 用作多个关系的反向集合，并明确 COMPILATION／CONTAINS 的方向；不能把所有 PARENT 固定写成 mainStory。其[动画目录规则](https://anilist-submission-manual.super.site/animated-media-criteria)及[书籍目录规则](https://anilist-submission-manual.super.site/written-media-criteria)也说明了序章、拆集、再版和合编范围差异，根编号不能作为进度顺序一致的证据。

## 已移除渠道的历史调查

取得了[当前 OpenAPI](https://docs.api.jikan.moe/)，确认其只读性质、作品／角色／人员／producer／分集／公开用户喜爱等端点，以及每分钟 60 次、每秒 3 次和 24 小时缓存说明。其文档还将“不存在或未确定”的数组统一描述为空，因此不能未经判断就用 [] 清除既有关系。

本机 Node、curl、浏览器与本次网页读取均未取得该 API 的实际响应；浏览器明确为 ERR_TIMED_OUT。没有使用其他镜像，也没有把网络失败记成空名单。

Jikan 已从当前 MAL 接入方案移除，不再声明这些补充能力，也不再要求完成其来源验收。以上仅保留当时真实调查与网络结果，不能作为现行依赖或能力依据。

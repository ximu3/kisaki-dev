## 完成日期清空与文档差异

[API 文档](https://api.vndb.org/kana#list-management)称非标签字段可用 null 清空。实际向已有日期发送 finished = null 返回 HTTP 400，回读仍为 2026-10-11；评分的 vote = null 则成功。

[写入 schema](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/API.pm#L560)为 started、finished 使用 caldate；[日历日期校验](https://code.blicky.net/yorhel/vndb/src/branch/master/lib/VNWeb/Validation.pm#L88)限定 1970–2099 年的完整年月日，没有为这两个写入字段声明可空值。来源文件与记录的 Git blob、SHA-256 已对应。年份边界来自源码核对；线上只写入了用户授权的 2026-10-11，没有额外试写边界日期。

据此，当前接入支持范围内日期的写入与更正；需要清空已有远端日期时，按该字段无法映射处理，不声称执行成功，也不删除并重建列表项。本体仍保留可空日期，入站 null 和无需变更的空值不受影响。修正后的[合成日期投影](2026-10-12-account-projections.json)包含十项边界检查。

## 零结果计数查询

[查询文档](https://api.vndb.org/kana#query-format)和公开源码允许 results = 0，但本次本人列表的零结果计数请求返回 HTTP 400。为排除空字段选择的影响，随后使用 fields = vote，只改变 results：0 仍为 400，1 返回 200、count = 0。尚未确定公开实现与当前部署产生差异的具体原因。

本人列表接入据实使用 1–100 个结果；只需要计数时也请求一条。不能将该差异解释为令牌失效，或按错误消息文字决定另一套协议。

## 清理与验证边界

三次 DELETE 均返回 204。随后按三个目标回读为空，并用 results = 1 的完整清单计数确认 count = 0、more = false；标签定义和隐私属性与测试前一致。共发送十次写请求，九次成功，唯一被拒绝的写请求为日期清空。最初使用 results = 0 的清理计数确认被拒绝，随后按已核对的一条结果查询完成确认，没有因此重复删除记录。

本次创建的三条临时记录已删除，没有修改全局标签隐私或来源作品资料。删除恢复了业务记录的空清单状态，不承诺还原来源技术时间。

样本不包含既有用户记录、真实自定义或私有标签、私有作品记录、并发修改、令牌失效中的中断恢复；这些不能据三条正常样本推定通过。实际扩展运行、原生界面、SDK 与本地持久化仍需在实现后验收。本轮结果修正的是来源采用规则与验收依据，没有改动运行代码。

# 扩展线性 RGB 的原生对照

范围说明：本组保留此前渲染与 HDR／线性输出研究的原始目标、源码和收据，正文按当时实验说明。现行交付已收敛为[SDR 输出与 HDR 片源到 SDR](../../../design/projects/libmpv-node/video.md#targets)；HDR 显示和亮度单位转换不再是待完成要求，历史结论不直接等同于当前 SDR 验收。

本组核对 BT.709、Display P3 与 BT.2020 作为线性浮点编码坐标时的实际原生行为。它支持统一三个线性目标的表示合同，不代替完整宿主显示或字幕验收。

## 输入与实际路径

[run.cjs](run.cjs)复用 [HDR 映射对照](../libmpv-tonemapping/verification.md)生成的两段 10 位 HEVC／BT.2020 PQ 输入：七色条与七级中性亮度阶梯。输入、既有 addon、DLL 和生产 helper 源码均按既有记录核对摘要，缺少或不匹配就失败。原生二进制仍是此前用于验证的第三方探针制品，不作为正式发行依赖。

运行使用普通 Node 24、直接 D3D11 和 RGBA16F，关闭硬件解码与动态峰值检测，设置目标峰值 418 nit。实际 Lua 调用受检，明确设置 target-trc=linear 与本例原色；旧 helper 的 scrgb 模式参数仅用于选择浮点目标分配，本组没有验证 target-trc=scrgb 或某个宿主的 80 nit 描述。

每组取得 63×47 与 31×23 两个已独立持有的原生帧。核心已销毁后读取参考像素，随后归还全部帧。九种配置共十八帧；本次没有加载 ANGLE，没有使用自定义 shader，也没有创建显示窗口或改动系统 HDR。像素读回仅用于验证。

## 对照与独立判据

每组原色分别运行颜色输入的 auto 与 clip 两种 gamut-mapping-mode，并用 clip 运行中性阶梯。当前固定 gpu 实现的 auto 在原色变化后可能去饱和；clip 跳过该处理，线性输出也跳过非线性曲线前的 0–1 裁剪，RGBA16F 保留扩展数值。不能将选项名字直接解释为此路径已经逐通道裁剪。[上游颜色实现](https://github.com/mpv-player/mpv/blob/01e2533f3143b8940857ca419b0b367f583e05ca/video/out/gpu/video_shaders.c)

[verify.py](verify.py)使用标准原色 xy 坐标和 D65 白点，以有理数独立推导 RGB→XYZ 矩阵，再计算 BT.2020→目标原色矩阵。以同一输入的 BT.2020 原生结果为参照，比较另两组原色的实际值；这保留相同解码与色调映射条件，隔离编码坐标和原色色域处理的差异。容差为 0.002 个原生线性单位，同时要求中性阶梯严格递增、峰值大于 2、Alpha 为 1。[原色与矩阵定义](https://www.w3.org/TR/css-color-4/#color-conversion-code)

| 线性原色   | clip 路径最大分量误差 | auto 对照最大偏差 | 最小保留分量 |
| ---------- | --------------------- | ----------------- | ------------ |
| BT.709     | 0.000341              | 0.324263          | -0.324219    |
| Display P3 | 0.000388              | 0.238181          | -0.168579    |
| BT.2020    | 0，作为比较基准       | 0                 | 0            |

三个目标的中性峰值均约为 2.05859，按本次原生 203 nit 单位解算约为 417.89 nit；不同原色的中性值差异不超过一次相应幅度的半浮点量化间隔。这里描述编码亮度，不是面板实测亮度。[完整原生记录](native-contract.json)、[独立分析](analysis.json)

## 对设计的含义与范围

srgb-linear 与 display-p3-linear 可以用于保留宽色域内容的浮点交付，不能因为坐标名称就先压缩为对应的普通 SDR 原色范围。本次固定来源通过原生选项完成了坐标转换，无须另写色域映射算法。更换上游构建或存储格式时，必须重新核对这个行为。

本组没有执行单位改为 240 nit 的整帧转换、Electron 导入、字幕／OSD、持续帧池、硬件解码或其他平台。因此完整颜色管线、宿主消费与字幕验证仍明确为 false。最终显示器色域管理继续遵守已确认的宿主职责，不能从本组矩阵正确推断显示边界的感知层次保留。

## 复现

准备既有 GPU 探针及 HDR 映射对照的已记录输入后，从仓库根执行：

```sh
node refactor/verification/evidence/libmpv-linear/run.cjs
python refactor/verification/evidence/libmpv-linear/verify.py
```

运行脚本只使用已核对摘要的合成输入；临时 Lua 位于仓库忽略缓存，完整设置和脚本文本同时写入原生记录。它不启动先前带显示窗口或 HDR 切换的对照运行。

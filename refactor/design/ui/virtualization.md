# 虚拟化与人工重排

公共 ui 拥有通用虚拟几何、拖拽接入与交互呈现，职责见[公共 UI 包](package.md#families)。业务视图负责行映射、选择与真实目标，查询拥有者提供完整数量、区间读取和稳定定位。人工重排使用共同交互表达明确移动意图，再由本体操作或编辑草稿完成保存。

<a id="geometry"></a>

## 列表与网格的虚拟化边界

| 拥有者            | 职责                                                                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 通用虚拟化能力    | 视口与尺寸、可见及预留渲染范围、总高度、显示行位置、测量修正与滚动操作；归通用 UI 层                                                    |
| 列表/网格业务视图 | 条目与分组到显示行的映射、查询实例与局部数据、稳定锚点、选择与键盘语义、当前交互项的必要保留                                            |
| 所属业务查询      | 当前总量、适用的分组摘要、任意区间读取及稳定目标定位；按 [区间读取与定位](../domains/library-queries.md#intervals) 的相同范围和排序执行 |

项目使用 TanStack Virtual 的 Solid 适配处理通用几何，固定验证组合为 @tanstack/solid-virtual 3.13.48、@tanstack/virtual-core 3.19.6 与 Solid 1.9.16。UI 层接入其公开 createVirtualizer、测量、范围提取和滚动能力，不复制依赖实现或直接调用私有生命周期方法。以纵向显示行统一表格、列表、规则卡片网格和组标题；业务视图继续决定网格列数及内容到显示行的映射。表格横向使用普通滚动保留列，不扩展成二维数据网格。

已知尺寸直接计算，其他尺寸通过实际测量修正。固定高度和动态高度共用一套合同，不能要求所有视图固定行高。完整 total 独立于已加载数量，尚未读取的区间仍能计算位置，再由视图加载，不能当作空区间。分组使用摘要与数量，不物化全部成员。同一 Entry 的重复显示实例分别定位。

远端候选没有可靠 total 或任意区间读取时，只声明已经取得的范围，续取后再扩大。不能伪造完整数量或允许跳到未知末尾，仍可复用同一虚拟化核心。小型候选列表可以直接呈现。阅读连续页的组织、重排和资源由 Kana 负责，可以复用适用几何，但不套用资料库列表业务 API。

视图锚点包含稳定显示身份、查询或分组，以及行内偏移。布局或排序改变后，按这些信息重新定位，并与核心尺寸补偿协调，避免重复移动。交互可以保留少量活动行，ARIA 引用由所属控件管理。选择不能依赖 DOM 或全部行同时挂载，弹窗草稿也不能绑定到随时可能卸载的行。

测量缓存只属于当前实例，查询或布局改变时明确失效。允许虚拟化库维护与逻辑显示行数成正比的几何索引；它只包含键、尺寸和位置，不要求加载全部 Entry 或构建业务结果镜像。getItemKey、estimateSize 和行映射必须同步取得现有上下文，不能逐项请求数据库、IPC 或文件。滚动复用已有几何，不能每次清空并重建整个索引；初始化、查询切换和测量失效的实际成本分别测量。

未加载行可以按读取代际、组与逻辑位置构造该代际内稳定的几何 key。查询、排序或组成员变化后由视图建立新代际并处理测量失效；实际选择、返回位置和拖拽目标始终使用真实业务身份，不能把几何 key 当作 EntryRef。只为取得所有 ID 而预读全库，不属于虚拟化接入要求。

滚动与尺寸更新合并处理，锚点恢复和库的尺寸补偿只由一个明确流程协调，不能重复补偿。隐藏、零尺寸和销毁分别按实际状态暂停或释放，不能当作列表为空。

几何依赖的选型依据见[虚拟化验证证据](../../verification/evidence/technical-tradeoffs/2026-10-22/README.md#virtualization)。正式界面验收覆盖卡片、数据读取、拖拽、辅助技术和性能预算。

## 统一移动语义与保存

具有人工顺序的列表支持拖拽，包括合集成员、关系、Part、来源优先序、展示区块和列配置。当前按其他字段排序时，先切回人工顺序；动态合集继续遵循自身规则。移动位置不会修改编号、职责、收录关系或归属。

拖拽使用明确的手柄和插入线，表示将项目移到某个位置，默认不交换两项。整行不能抢占文字选择或输入。拖动已选项时可以成组移动并保留组内顺序，拖动未选项时只移动该项。边缘支持自动滚动。Escape、无效落点或取消都不写入顺序。上移、下移、移到开头或末尾等菜单与键盘操作共用同一移动能力。

移动意图是在明确范围内，将稳定对象移到另一对象之前或之后。配置中没有持久 ID 的项目可以使用编辑期 key，不为此增加永久身份。筛选子集移动必须保留隐藏槽位：完整顺序 A、B、C、D、E 中，仅显示 A、C、E，若改为 E、A、C，完整结果应为 E、B、A、D、C。不能用屏幕数组覆盖全部成员。

表单内重排只修改草稿，管理列表则在落下后一次提交，拖动途中不连续写入。失败时按当前已经提交的事实恢复，不能用拖动前的旧快照覆盖并发结果。通用组件只负责交互和移动意图，范围、许可与保存由业务决定。

稳定控制器拥有虚拟列表的拖拽过程，并可临时保留源行。自动滚动后先取得真实目标，目标就绪时才允许放下。源行离屏、容器或监视器结束以及取消都由控制器完成收尾，行组件只管理自身挂载资源。

## 拖拽依赖与验收

| 包                                            | 版本  | 责任                     |
| --------------------------------------------- | ----- | ------------------------ |
| @atlaskit/pragmatic-drag-and-drop             | 3.1.0 | 基础拖拽、落点注册与事件 |
| @atlaskit/pragmatic-drag-and-drop-hitbox      | 2.2.0 | 落点边缘判定             |
| @atlaskit/pragmatic-drag-and-drop-auto-scroll | 3.2.0 | 拖动过程中的自动滚动     |
| @atlaskit/pragmatic-drag-and-drop-live-region | 2.1.0 | 辅助技术播报及共享区域清理 |

实现使用 Pragmatic Drag and Drop 框架无关核心及必要辅助包的公开入口，统一插入线、外观、菜单和可访问反馈。不引入 React 展示层，也不修改依赖库，Solid 按正常挂载与清理接入。依据见[核心](https://atlassian.design/components/pragmatic-drag-and-drop/core-package/)、[辅助包](https://atlassian.design/components/pragmatic-drag-and-drop/optional-packages)和[虚拟化](https://atlassian.design/components/pragmatic-drag-and-drop/core-package/recipes/virtualization)。

公共 ui 提供登记、目标、稳定监视器和自动滚动的 Solid 接入；选项失效或拥有者结束时释放。手柄同时接入键盘可用的等价移动操作，插入线只呈现当前有效边缘。播报文字来自宿主，最后一个拥有者结束后释放共享 live region 及待播报消息。

验收在 Solid 1.9 下覆盖普通列表与网格、动态尺寸、筛选子集、多选、自动滚动后源行离屏、尚未加载的目标、取消和并发失败，并同时验证[完整查询与定位](../domains/library-queries.md)。

# 小说、卷与阅读资料

Novel 表示小说作品，NovelVolume 表示真实卷，NovelFile 表示本地阅读来源。文件直接属于作品，可以与多个卷关联；同一卷也可以关联多个文件。精确位置始终属于实际文件，没有分卷的作品不需要建立“正文卷”。

小说与漫画共用[阅读能力](reader.md)，固定页面、文本重排及混合版式都由实际文档决定。阅读配置使用同一个 ReadingPreferences 合同，按[文件、作品和全局层级](preferences.md#overrides)选取完整值；小说类别负责卷组织与个人记录，不决定版式。

<a id="model"></a>

## 对象与文件关系

| 表                 | 关键列及引用                                                                                                 | 独立身份         |
| ------------------ | ------------------------------------------------------------------------------------------------------------ | ---------------- |
| novels             | entry_id，主键并引用 entries.id，采用类型约束                                                                | 与 Entry 同一 ID |
| novel_directories  | id；novel_id 引用 novels.entry_id；按[内容目录合同](holdings.md#directories)保存发现范围、过滤及识别方案引用 | 有               |
| novel_volumes      | id；novel_id 引用 novels.entry_id；实际卷级资料与顺序                                                        | 有               |
| novel_files        | id；novel_id 引用 novels.entry_id；路径、观察事实、文件位置及必要定位编码                                    | 有               |
| novel_file_volumes | file_id 引用 novel_files.id；volume_id 引用 novel_volumes.id；联合主键 (file_id, volume_id)                  | 无独立 ID        |

NovelFile 直接标识所属小说中的读取目标，记录稳定 ID、novel_id、绝对 path、格式与可访问性等观察事实，以及续读位置、编码和文件备注。不同作品按各自文件记录管理同一物理位置。

novel_files 另保存[关联方式](holdings.md#association-mode)。automatic 允许普通刷新为无关联文件匹配已有卷；manual 保留用户明确保存的完整集合，包括空集合。

novel_file_volumes 只表达文件与卷的关联，不保存位置、完成状态、文件片段或独立生命周期。完整操作在同一个同步事务中核对文件与卷属于同一小说；两端外键保证对象存在，组合主键防止重复关联。

首次创建小说只需要同一 ID 的 Entry 和 novels 行。真实卷可以没有编号或文件，作品也可以没有卷。零卷不证明作品不分卷，没有卷关联也不表示文件必定是整本、未知范围或合订本，更不妨碍阅读。后来补充卷资料时，只新增或复用实际卷与关联，保留已有文件、位置和标注。

| 情形                                  | novels | novel_volumes | novel_files | novel_file_volumes |
| ------------------------------------- | ------ | ------------- | ----------- | ------------------ |
| 不分卷小说，一个 EPUB                 | 1      | 0             | 1           | 0                  |
| 不分卷小说，EPUB 与 PDF               | 1      | 0             | 2           | 0                  |
| 三卷小说，每卷一个文件                | 1      | 3             | 3           | 3                  |
| 三卷小说，第 1—3 卷合订文件且关联已知 | 1      | 3             | 1           | 3                  |
| 已有小说文件，卷资料和关联尚未知      | 1      | 0             | 1           | 0                  |

一个作品可以直接拥有 EPUB 和 PDF，两份文件各自续读。同卷的多个文件分别保存位置，合订多卷的一个文件则只有一个位置。不增加 Content、ReadingUnit、Book、Edition 或公共 parts 身份。一个系列中的多个独立作品不会因为来源将它们分组，就被合成一部 Novel。同一路径下合法的不同使用上下文也不强制合并。

## 卷号、排列与来源对应

| 表与字段                           | 含义与规则                                                            |
| ---------------------------------- | --------------------------------------------------------------------- |
| novel_volumes.id                   | 稳定主键；更正名称、编号或排列不改变身份                              |
| novel_volumes.novel_id             | 引用创建时确定的所属小说；作品合并时统一迁移                          |
| novel_volumes.number_label         | 可空文本，保存实际编号表达，例如 1、5.5、上、3 下；空值表示未登记编号 |
| novel_volumes.sort_order           | 所属作品内的默认排列序位，使用非负整数，不兼任公开卷号                |
| novel_volumes 的名称、简介、封面等 | 实际卷级资料，按各字段含义编辑；不从作品复制一套镜像值                |

卷号按文本保存，名称与编号均允许重复，编号可以缺席，每卷通过独立 ID 区分。修改编号只改变编号字段；改名、重排及自然编号排序通过相应明确操作执行。默认顺序为 sort_order、id，索引覆盖所属作品范围。

文件的[内置命名解释](file-recognition.md#builtin-books)使用明确卷标记，保留上、中、下等文字编号。裸数字、文件扩展名、文档内部章节和电子书分组序位不自动成为本作卷号，也不因此补造正文卷或章节实体。

重排时核对完整卷集合与顺序基线，并在同一事务提交。文件、完成记录和活动继续引用原 ID。首次导入可以采用明确的来源顺序，普通刷新保留人工排列；新增卷按明确位置插入，没有位置时追加。只有主动采用来源顺序才执行重排。

卷可以绑定 novel_volume_external_identities。来源对应优先使用完整身份，其他依据按启用规则处理。ingest 独立核对本地目标，只有结果唯一且没有范围矛盾时才更新，不能仅凭同名同号合并，也不能删除后重建。

显式指定本地卷时始终保留该 ID。来源规范标识变化后，需要明确映射、启用的回退规则或人工更正，不能承诺全部自动恢复。将第 5.5 卷改名为“番外上”、在两卷之间插入新卷，或采用另一条来源记录，都不改变已有文件、首选和私人记录的身份。两条来源都称为“第 1 卷”时，仍须核对实际范围。

## 出版资料与获取范围

作品与真实卷各保存一套当前采用的资料，多份阅读文件独立管理。出版社、语言、ISBN、封面和日期均属于当前采用的对应范围；其他出版版本的背景可保存在说明或来源链接中。不同 ISBN 不自动产生新卷，相同卷号也不证明分卷边界相同。

同一真实卷新增 EPUB、PDF 或译本文件时，关联原卷并独立续读。采用另一来源资料时，明确要修改的字段并保留 ID。分卷边界不同，只能建立已经确认的卷和关联，不能自动换算完成状态。

作品或卷的首次发行日期与某一版本的出版日期不同。更换封面不表示改写出版历史。合订出版物的身份不能复制给所含的每一卷，也不能因为包含三卷就当作整部作品身份。

provider 按对象的实际含义解释来源。Google Books 使用的 Volume 名称不等于 NovelVolume，来源系列也不自动等于一部 Novel。只接纳符合小说范围的作品，不能导入所有书籍或杂志。来源类型字段仍须用于准确识别，也不能只剥掉卷号就声称取得了作品级资料。

公开 search 返回 Entry 候选。卷资料经 Entry 会话中的真实作品范围或明确 Part refs 读取；只补已知 Part 字段时可以省略来源根身份，本地根对应仍单独核对。读取入口及能力声明见[读取合同](../extensions/providers.md#session)。来源分别声明作品资料、卷清单和卷资料，允许复用请求；卷清单是否存在依据来源的实际回答判断。

指定卷更新时固定本地目标和字段范围。第三卷的标题与封面不能覆盖作品卡片。来源归属不明时报告问题，不采用首项，也不创建重复 Entry。

个人账号记录与普通资料分别处理。单册已读不扩大为整作已读；只有进度数量时，不猜测具体卷 ID。单册出版信息和分部参与也按实际范围采用。选择不同出版记录时，界面说明当前资料来源，不宣称系统维护了出版版本快照。

## 合订阅读与文件生命周期

合订文件在全部文件视图中只出现一次。各卷的文件入口都是同一记录的投影，无论从哪里打开，都恢复该文件唯一的位置，并明确说明正在打开哪份合订文件。

卷文件关联不包含卷起点或文件内范围，因此不能自动跳到卷首、分摊时长或完成多个卷。文件内部通过目录和书签导航，卷完成由明确操作管理。

文件失联只改变观察到的可访问性，重定位保留文件身份。另一版本的文件独立保存位置，不能按同名继承。没有卷资料时可以先阅读，后来补充资料也不重建文件。关联可以由用户或明确识别结果采用，但不能直接根据目录数量或文件名范围生成卷。

解除卷关联不删除文件位置，删除卷也不级联删除文件。普通关联变化不追溯修改历史。格式无效、资源缺失或位置越界由实际读取合同报告，不另建逐位置内容修订审计。

<a id="position"></a>

## 当前位置、标注与实际活动

novel_files 在同一次原子写入中保存实际位置与观察到的显示进度。位置使用[阅读合同](reader.md)的稳定坐标和编码版本，百分比用于显示。字体、窗口或排版变化后，从源位置重新计算呈现；源位置能否恢复按实际文档核对。

同文件重定位后，在当前内容中解释已保存坐标。原地改写文件仍保留位置：合法坐标可以定位，但不保证仍是历史上的同一段内容。格式无效、资源缺失或越界时明确失败并保留原位置，不能跳到首页、其他文件或近似位置。新文件不迁移旧位置；标记已读不清空位置；从头阅读只改变定位，不增加完成次数。

novel_annotations 直接属于作品。file_id 可空，主要用于删除文件后保留标注；创建时必须有实际文件，并核对它属于该作品。image_id 可空，正文图片通过 novel_annotation_content_attachments 引用。公共值、操作和引用规则见 [标注](annotations.md)。标注不引用卷文件关系，也不会因文件合订三卷而复制三份。历史中的文件显示信息保存发生时的值，不随名称或关联变化同步改写。

novel_reading_activity 的每一行保存一段有明确起止时间和有效时长的阅读记录，包含 id、必填 novel_id 和已知上下文。file_id 可以为空，手动补录不要求本地文件；只有确知单卷范围时才填写 volume_id。从卷入口打开合订文件，不能把全部阅读时长归入该卷。文件与卷的名称等发生时上下文独立保留，普通资料或关联更新不追溯修改；合并由完整操作处理。手动补录、修正和删除遵守[活动编辑](library-operations.md#activities)。

计时遵守 [使用会话](sessions.md) 的规则。暂停、切换实际文件或结束有效计时时，收束当前区间。短暂离开后在宽限内返回，可以接续区间并计入间隔；超过宽限则从离开时结束，返回后另起区间。待确认间隔不提前落库，运行期间只保存已经确认的部分，崩溃后不补计暂离或停机时间。合订阅读只保存一次活动；即使没有精确卷归属，也能保存作品历史。手动完成不会生成虚假的阅读时长。

## 移除与删除的留存结果

| 操作                   | 文件与位置                                       | 标记、个人记录与历史                                                                         |
| ---------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 磁盘文件失联或不可访问 | 保留记录与位置，更新观察到的可用性               | 全部保留；暂不可定位不等于记录无效                                                           |
| 解除某个卷文件关联     | 移除关联及依赖该关联的卷内首选，文件及位置保留   | 不修改已有标记、卷完成记录或历史                                                             |
| 同一内容重定位         | 更新文件访问位置，保留可用定位                   | 保留原记录身份与实际历史                                                                     |
| 删除真实卷             | 删除卷及相关关联，保留作品下的文件和位置         | 明确删除该卷的从属当前记录；作品笔记、文件标记和历史保留，历史中的卷引用解除并保留显示上下文 |
| 删除文件记录           | 移除卷关联与指向它的首选，删除文件记录及当前位置 | 保留作品与卷的当前个人记录、书签、划线和历史；解除其中的文件引用，保留文字与定位上下文       |
| 删除作品               | 按完整作品删除范围处理其卷、文件记录和关联       | 确认摘要说明私人记录与历史的删除范围；不逐条预览，也不删除用户的实际媒体文件                 |

文件记录删除后，即使重新添加同名文件，也不会自动恢复旧引用。重新连接标注时，必须核对实际目标和定位。解除引用、删除从属当前记录、保留显示上下文和清除首选，在同一个同步事务中完成；外键动作按表中要求配置。

影响正在使用身份的操作，须先满足会话占用规则。Note 独立留存；明确删除作品时，按完整删除合同处理作品自身的标注和活动。文件暂时失联不能决定用户内容的去留。

## 首选与继续阅读

| 所属记录           | 字段                     | 含义与唯一性                                            |
| ------------------ | ------------------------ | ------------------------------------------------------- |
| novel_files        | is_preferred，默认 false | 该记录所属小说的首选文件；同一 novel_id 至多一条为 true |
| novel_file_volumes | is_preferred，默认 false | 该关联所属卷的首选文件；同一 volume_id 至多一条为 true  |

作品和卷各自允许零条或一条首选。切换时在同一事务中取消旧值并设置新值，选择保存在各自文件关联上。同一个合订文件可以成为不同卷的首选；各卷的选择独立维护。

可以按目录筛选文件，再按[批量默认文件规则](holdings.md#selection)设置明确卷的首选；目录不成为当前阅读版本。目录入口、文件选择与当前阅读各自独立，界面遵守[使用与位置操作](../ui/components.md#local-actions)。

普通打开按[共同目标选择规则](sessions.md#open)处理当前作品或卷范围。没有活动会话且未显式指定文件时，该范围首选优先于最近实际文件。“继续”与“使用首选”入口分别传入自己已经明确的目标 ID，不让默认选择覆盖明确意图。

最近阅读来自活动和当前上下文，编辑、扫描、路径变化或首选变化都不算阅读。卷继续要求明确的卷归属，不能仅因合订文件关联了多个卷，就为各卷生成最近记录或独立位置。

继续入口已经显示具体文件后，打开请求必须携带该 ID。目标删除或归属改变时报告问题，不能在点击后重新排序并悄悄打开别的文件。目标失联时保留选择并明确提供替代；替代文件使用自身位置，也不永久改变首选。取消或删除首选不会自动选中另一个文件，解除卷关联只移除该卷的首选。设置首选不切换当前内容，也不修改位置。

例如，第 1–3 卷合订 EPUB 是作品首选，第 2 卷 PDF 是该卷首选。作品继续可以回到最近阅读的 EPUB，明确打开第 2 卷首选则进入 PDF。两份位置独立，首选变化不会制造合订文件的逐卷位置。

## 作品内导航与切换

作品详情和阅读器共用[实时内容列表](reader.md#work-navigation)。资料视图按本作品全部卷的 sort_order、id 排列，提供上一卷和下一卷；文件视图按本作品全部文件的规范路径自然数字顺序、id 排列，提供上一文件和下一文件。两种查看方式都有适用筛选，筛选不缩小相邻项范围，也不改变正式顺序。

当前文件只有一个直接关联卷时，可以确定卷列表中的当前项；没有卷关联或关联多卷时，不根据入口、文件名或文件内位置任选当前卷。合订文件仍通过目录和书签使用，也可以明确选择其他卷或文件。下一卷按其当前关联与首选选择文件，仍为同一合订文件时复用会话和位置，不归零或自动跳过。

新阅读器有卷时默认资料，无卷时默认文件，用户可以自由切换。普通继续、深链和单文件打开都能浏览当前作品的全部资料与文件，不携带旧入口的筛选清单。资料新增与重排正常刷新列表，不抢先改变查看方式或当前内容。末尾停留、下一文件的位置恢复及失败处理使用共同阅读规则。

<a id="records"></a>

## 当前状态、完成历史与卷标记

| 表                   | 主键与引用                             | 保存内容                                             |
| -------------------- | -------------------------------------- | ---------------------------------------------------- |
| novel_records        | novel_id，主键并引用 novels.entry_id   | 三种作品当前状态或 null，以及 additional_duration_ms |
| novel_volume_records | volume_id，主键并引用 novel_volumes.id | is_completed 布尔标记                                |

两张表均为可选的一对一附属记录，以所属对象的 ID 为键。卷记录保存当前完成标记，作品逐次完成记录保存在[work_completion_records](records.md#schema)，评分和收藏属于 Entry。

作品附加阅读时长使用非负安全整数毫秒，缺行按 0 读取；与实际活动合成累计时长，编辑和来源采用遵守[共同附加时长合同](records.md#duration)。卷不增加附加时长字段，没有日期的附加值不生成期间统计或最近阅读。

当前值缺省、完成历史和分部标记遵守[共同记录模型](records.md#schema)与[完整操作](records.md#operations)。批量已读使用明确的卷 ID，“第 N 卷”不表示列表前 N 条；作品与卷之间的传播边界见[分部标记](records.md#parts)。

实际阅读沿[会话规则](sessions.md#personal-status)保存。从头阅读只改变所选文件的位置。界面分别显示作品状态、完成次数、卷标记数量、文件位置、实际时长和最近阅读，这些结果由各自事实查询得到。

来源声明卷数不作为范围不明的分母，无卷时不显示 0/0，合订文件的 70% 也不等于每卷 70%。三卷已读而整作仍在读是正常情况；补充第四卷后显示三／四，前三卷的标记、作品完成历史和文件位置保持。

## 分类与作品界面

小说不设置固定文学分类、出版分类或“是否分卷”字段。轻小说、网络小说、题材和风格使用普通标签，组织顺序使用合集。来源自己的类别仍用于 Entry 映射和明确标签策略，不保留无用途的原始副本、强制保留标签或平行的 NovelFormat 模型。没有标签不表示“一般”或“其他”类别，实际阅读由文件格式决定。

真实卷数通过查询取得。零卷不证明作品已知不分卷，删除最后一卷也不构成结构声明。资料与文件视图是界面选择，不能用 is_divided 或 has_volumes 控制资料。初次进入时，有卷默认资料，无卷默认文件；用户仍能打开空卷视图并新增或获取卷资料。后台更新不能抢先切换用户正在使用的视图。

作品详情提供卷资料和全部文件两个视角。全部文件包含未关联、合订和失联记录，从卷进入看到的仍是相同 ID 的文件。名称、关联卷、格式、可用性和进度分别占列。无卷作品不必进入“第 1 卷”页面；卷可以没有文件而完整编辑，文件也可以没有卷而正常使用。

主阅读动作根据实际会话、文件和位置显示开始、继续及控制。手动标记已读不证明存在续读位置。没有文件时，用户仍能管理资料与个人记录，界面引导添加文件，不先尝试读取再解释失败。卷没有文件关联只表示尚未登记，不证明用户没有通过其他合订文件持有该卷。

## 完整流程与提交边界

从资料添加、从文件登记和后来补卷，最终都操作同一批对象。新增作品建立完整身份，可以没有文件；采用卷资料先确定父作品和本地目标；独立添加文件时，即使资料识别失败，也可以正常登记并阅读。更新作品或卷只修改明确范围，来源遗漏不自动删除分部。合订阅读保持一个位置，整理操作统一处理真实引用和记录。

来源请求、文件探测和附件准备在事务外完成，提交前核对目标与相关基线。metadata 解释并合成来源，ingest 决定本地对应与采用，library 完成写入，sessions 负责实际使用。UI、扩展和批量入口复用这些操作，页面不能通过串行 CRUD 补齐业务，provider 也不能写库。

资料 patch 不携带旧详情去覆盖位置、私人记录或人工关联。阅读期间的位置更新不应阻止无关标题编辑；同字段或身份变化则按明确冲突处理。当前关联不会反向改写历史。合并或删除正在活动的身份前，须结束相应占用。

验收覆盖无文件编目、无卷阅读、补卷后保留文件与位置、卷资料不覆盖作品、来源缺席或部分失败、阅读与编辑并发、合订整体使用，以及失联、解除关联和删除的不同结果。各媒介共用完整提交与读取机制，同时保留真实领域差异。

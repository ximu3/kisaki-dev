# 界面、本地化与导航验收

对照真实界面和完整用户操作验证。

环境、证据与完成条件见[验收标准](../acceptance.md)，各场景引用对应设计规则。

<a id="native-interaction"></a>

## 简洁流程与平台交互

A20、A26 与 A29 按[系统能力与控件语义](../../design/ui/components.md#native-interaction)核对实际任务：常见操作没有无用途的中间步骤，同一结果不重复反馈，用户无需理解内部模块才能完成操作。文件选择、系统菜单和窗口控制使用适用的平台能力，应用内菜单不取代 macOS 系统菜单栏。

基础控件保持键盘、文本选择、复制粘贴、撤销、输入法组合和辅助技术语义。检查快捷键作用域、平台修饰键、焦点返回，以及自定义样式和复杂组件是否保留这些行为。按实际变更选择相应场景与目标平台，不能只根据控件外观或 DOM 标签认定原生体验已经通过。

<a id="languages"></a>

## 三个官方译本

A23 和 A29 按第 31–33 项[完整方案](../../design/extensions/languages.md)分别核对三项稳定身份、完整英语基准、公开生成合同、纯嵌套 ICU 目录、轻量 Node 登记和独立六目标制品。简体中文使用新模型术语；繁体中文按用户选定的台湾措辞独立审校；日文使用自然语序、标签和说明语气。参数允许省略而不能新增或收窄公共调用类型，t 保持普通文本，缺键按英语语法回退，已知坏消息拒绝整份登记；同 locale 切换仍更新译文，失效回退保留选择，用户草稿及正文不重写。A20、A26 和 A29 继续核对实际菜单、无障碍文字、字体、缩放、长名称、安装与更新、仓库外 SDK／CLI 使用。[共享核验](../evidence/language-extensions/contracts-and-fixtures.md)只覆盖实际 Node ICU、类型生成样本、匹配与内存生命周期模型，不代替三份全量译文、正式宿主、浏览器／Webview 和平台安装。

正式交付分别核对三份完整译文、术语和语气审校、公开校验合同、当前真实英语覆盖、所有窗口／原生菜单／无障碍文字，以及实际 Node、浏览器与 Webview 消费。运行验收覆盖零扩展英语、首次安装失败与恢复、同 locale 多译本切换、缺词英语规则、已知坏消息整份拒绝、语言恢复、草稿保持、更新与卸载、首屏预算、字体与长文案，以及仓库外构建和六目标安装。代表性样本不能替代全量译文或正式 UI 验收。

<a id="previews"></a>

## 预览与状态入口

A18、A20 和 A29 验证[共同预览规则](../../design/ui/components.md#previews)及[状态入口](../../design/ui/components.md#personal-records)：常规导入、同步、合并和文件整理没有整批差异稿或配对向导；必要删除确认只说明对象和影响。状态下拉分组提供当前状态与完成操作，历史管理通过同一记录身份完成补录、编辑和删除；真实页面遵守现有密度与表格一字段一列，不能把原型布局直接作为实现模板。

<a id="baseline"></a>

## 既有界面对照

代表场景另覆盖长表单关闭校验提示后再次定位错误、窄窗口中横向访问完整表格、双面阅读空间不足时的反馈，以及首次离线且译本未安装时的引导。检查用户能否完成当前任务，所选布局和正式设置保持原值；确有体验缺口时修订对应局部规则。

A29 还须对照现有界面与代表性交互，确认主要布局、视觉风格、信息密度和常用操作路径整体延续。差异须对应本规格规定的局部调整、新增能力或共同交互规则下的局部修复，不做整体改版，见[现有 UI 保留原则](../../design/ui/components.md#existing-ui)。

对照时记录影响结果的应用版本、运行条件和操作步骤；必要的截图与样本随对应场景保存。

| 代表场景 | 对照重点 |
| --- | --- |
| 库的卡片／表格与分组浏览 | 导航、密度、选择、滚动、远处定位与返回；默认尺寸和现有最小支持尺寸分别记录 |
| 详情、关系与长编辑表单 | 信息层次、资料与个人记录的区分、草稿保持、保存／取消、错误定位和焦点返回 |
| 来源搜索与资料操作 | 选择、目标范围、采用方式、忙碌和部分完成反馈；新模型带来的必要差异有明确依据 |
| 游戏、播放与阅读窗口 | 主动作、内容列表、快捷键、标注、关闭与多窗口独立性；正文与外壳分别判断 |
| 引导、扩展与偏好管理 | 离线、缺少译本、资源失败、管理入口返回及已保存选择的保持 |

新能力没有旧界面时，记录为新增场景，使用既有视觉体系和本规格的业务规则建立预期，不虚构旧版对照。图标、表格列、Toast 与预览等既定形式仍按对应合同实现；若代表场景证明用户无法完成任务或必要信息不可获得，先形成可复核的局部问题，再修订规则。验收比较用户能够看到和操作的结果，不要求新旧 DOM 或组件树相同。

<a id="resources"></a>

## 资源管理与草稿

主题“保存并选用”固定发起时的正式选择基线。A 开始保存后，B 从另一入口选用主题；A 保存完成时，主题内容保持已保存，条件选用返回 Conflict，B 的选择不被覆盖。A 不重新读取基线再提交；无并发修改时正常选用。成功后只结束 A 自己仍持有的预览，不撤销其他编辑器后来取得的预览。

资源选择和偏好中的相关管理入口还须覆盖 A18–A20：复用已有界面，原草稿保持，管理操作独立保存，返回后刷新资源目录，打开或关闭管理界面不提交偏好。更新 Dialog 使用正式偏好，不读取尚未保存的草稿。

<a id="search"></a>

## 应用搜索与导航

A19 和 A29 按[结果合同](../../design/domains/search.md#results)验证类别与 SearchTarget 分支关联、缺省展示值、合法 PreferenceKey 和页面归属；0、201、负数及非整数 limit 拒绝，超出 total 的 offset 返回空项与真实数量。摘要在 160 个 UTF-16 单元内保留完整字素。图标保留扩展资源归属，查询不产生无释放入口的字节占用，过期图片引用按共同缺图规则呈现。

A19、A29 和 A30 验证[应用搜索排序](../../design/domains/search.md#results)：

- 名称完整匹配、前缀匹配、包含全部词、依靠正文或上下文命中依次排列。原名、排序名和别名采用同一档次，完整外部标识归入第一档；词语分布在名称与正文中时归入第四档。
- 同一对象多处命中只计一项。同档覆盖“作品 2”与“作品 10”的自然数字顺序，以及同名结果的完整目标身份补序。
- 每组前三项与该类别结果的开头一致，远处区间沿用相同排序。隐藏内容不影响可见结果的顺序、数量或区间。
- “全部”模式保留分类分组，Explorer 输入文字后保留原有人工或字段顺序。

应用搜索与库查询还须验证[共同文字规则](../../design/domains/library-queries.md#text-and-sort)：相同 Entry 范围和可见范围内，显示名、原名、排序名、别名和简介产生相同的普通文字命中集合。覆盖中文及日文连续文字的中间片段、英文大小写、全半角、查询首尾空白和多词跨字段命中；简繁体、假名与罗马音不自动互转。简介和笔记中的可读文字可以命中，Markdown 标记和内部附件地址不参与匹配，保存与显示的原值保持不变。外部标识仍按完整值准确比较，不套用普通文字规则。

A19 和 A29 验证标注搜索结果携带完整 AnnotationRef，经[原生导航](../../design/communication.md#capabilities)打开已保存内容；不会直接启动游戏或打开源文件，也不为此增加公开 deeplink。展示柜的最近加入区块与普通查询使用相同有效加入日期：空 added_date 回退到创建日期，部分日期保持原精度，筛选、排序和定位一致。

A19、A27 和 A30 按[名称比较的确定序列](../../design/domains/library-queries.md#name-order)核对数据库排序与纯比较结果一致，包括中文码点、兼容字符、组合重音、各类 Nd、前导零、数字后的文字、标点及超安全整数。等价名称使用稳定 ID，降序不把缺省项移到前面，ID 补序保持；切换四种界面语言后顺序不变。对同一固定资料分别调用 list、locate 与应用搜索，在相同相关性档次内取得一致顺序。Unicode 数据或键编码升级的索引重建保留原字段与身份，不将比较相等的条目合并。

<a id="onboarding-commit"></a>

## 引导采用的原子范围

A05、A20 和 A27 验证[有界引导采用](../../design/domains/onboarding.md#composition)：偏好、资料方案、扫描配置和展示柜的本组创建与 handled 同次提交。将失败注入业务写入之后、handled 写入之前，重开后两边均保持原状；同组后一个项目校验失败时，前项也不残留。只有提交成功才发布业务变化与引导失效，通知不承担补写。

准备期间另一个窗口处理同一 itemId 或改变同类型默认方案时，原请求按 expectedHandled 或 expected.defaultProfileId 冲突，保留草稿；无关偏好变化不影响本次提交。展示柜仅按本次选择追加新项，原区块及其相对顺序保持，不接受借引导删除或覆盖已有区块。

扩展安装完成而处理记录保存失败时，报告真实安装成果与未采用标记；再次处理核对同包版本后继续，不因缺少 handled 盲目重装。激活或扫描监听失败保留已提交配置与 applied，并显示实际运行问题。安装不能代替译本选择，跳过不能覆盖同时完成的采用，也不取消已经接纳的安装。

<a id="virtualization-adapter"></a>

## TanStack 几何接入与业务身份

A18、A19 和 A29 按[虚拟化边界](../../design/ui/virtualization.md#geometry)验证实际 Solid 接入。五万项及正式预算中的更大样本保留完整 total；初始化几何不得触发逐项 IPC 或全库详情读取。记录初始索引构建、普通滚动、测量失效与动态高度的独立成本，不能用只有少量 DOM 就宣布整体性能通过。

查询代际与几何 key 不替代 EntryRef 和真实组身份。未加载行不要求预读完整 ID 表；查询、排序和成员变化后，旧几何失效，稳定业务锚点重新定位。改变网格列数、上方图片或字体导致高度变化时，同一锚点保持且不重复补偿。跨折叠组与重复显示实例的选择仍使用本体解析。

拖拽源行、焦点和必要 ARIA 目标只保留有限活动行；尚未取得真实目标不能放下。覆盖滚动中测量、隐藏／恢复、窗口缩放、退出释放和读屏。隔离 offscreen 试件的成功不代替这些正式控件、真实图片、GPU 和输入延迟验收。

<a id="webview-isolation"></a>

## Webview 来源、联网与权限

A20、A21、A23 和 A26 按[容器合同](../../design/extensions/webview.md#isolation)验证实际发布包、SDK 与三种作者模板。并行打开同扩展的不同视图和不同扩展页面，核对各自真实来源，拒绝父页面 DOM、其他视图、原生 preload、Node 全局和伪造 MessagePort 接入。文档刷新更换端口但不重复 Node setup；视图替换后旧来源、资源与迟到消息失效。

按[发布 CSP](../../design/extensions/webview.md#csp)验证包内脚本、CSS、Worker、嵌套页面与授权图片／字体；内联、eval、远程脚本、blob Worker、远端 iframe 和 HTTP／WS 请求均拒绝。普通页面与 Worker 分别尝试读取已知的其他视图资源地址，均不得取得字节；同视图合法读取和多绑定独立释放仍成立。不能只检查 document 的 webRequest 记录后推定 Worker 已覆盖。加载失败、已撤销绑定、缓存与跨窗口重新绑定均须验证。

使用真实 HTTPS／WSS 服务覆盖成功、CORS 拒绝、Cookie、重定向、流中断与应用代理变化，核对浏览器 Session 和宿主 HTTP 的各自语义。官方业务及凭据留在 Node，页面只能取得业务允许的数据。合成 HTTPS 协议响应不代替 TLS、WebSocket、代理或真实来源服务测试。

包内导航正常建立新文档；跨视图和外部导航拒绝，CSP 先行失败也能清理旧 document 并显示准确状态。明确 ui.openExternal 使用系统浏览器，拒绝非 HTTP(S) 及带用户名／密码的地址；被阻止的链接或弹窗不自动打开浏览器。真实权限检查和请求均默认拒绝，未知权限不获准；普通表单输入、用户复制与粘贴仍可用。

开发模式核对每视图独立来源、受控 loopback 映射、随机 nonce 与精确 HMR WebSocket，覆盖端口改变、构建失效、刷新、断连及会话结束。正式制品不得含开发放行。隔离试件只证明所列机制，不代替这些正式流程与完整资源寿命。

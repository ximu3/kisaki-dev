# 开发测试职责复核与调整

2026-10-28，按用户确认先核对开发回归的必要性，再落实 CI 工程边界。复核覆盖实际用例、较小集成测试、启动与取消实现以及已留存的失败和耗时；没有把运行缓慢或曾经失败直接作为删除或保留用例的理由。

## 已落实的分工

原开发套件包含三个普通 Node／纯合同用例和四个真实开发场景。本次保留原断言，将三个轻量用例移回拥有者：

| 验证                                                   | 当前拥有者与入口                                                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 开发消息的构建事实、采用结果和非法字段                 | desktop-contracts 的 src/development.test.ts，随本包 test 执行。                                         |
| 并发 stop 共享结果、取消后保持连接、断开后观察实际退出 | extension-cli 的 tests/integration/development-application.test.ts，使用本包的隔离 Node 子进程 fixture。 |
| 拒绝不兼容的就绪协议                                   | 同一 extension-cli 接入测试，随本包 test 执行。                                                          |

两包新增实际 test 入口、Vitest 配置与测试类型检查项目，继续完整检查自有测试源码。公共包之间仍通过构建后的 exports 使用依赖，所属包内部测试直接验证自己的源码。应用的开发输入不再包含已迁出的 Node fixture。

既有真实任务图测试增加两个迁移路径：纯合同测试文件和启动器接入测试文件。实际 Turbo 查询必须选择所属包的 test，同时不选择桌面验收或 tarball 消费者。这样轻量用例的维护可通过普通包测试反馈，独立运行公共包测试不需要启动桌面开发回归。

## 四个真实场景的独有保证

| 场景                       | 较小测试已经证明的部分                                         | 仍需验证的连接                                                                                      |
| -------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 初次依赖准备取消与重试     | tooling 的真实进程测试验证取消命令并等待后代退出。             | 开发会话确实把取消传入准备命令，关闭自己的 renderer 与会话目录，同一工作区随后能够完成启动。        |
| 退出取消与正常关闭         | 启动器测试验证 IPC 结果与进程退出；窗口用例验证正常关闭。      | 真实应用拒绝退出后，开发会话、应用与 utility 进程仍可用；后续窗口关闭完整释放会话并保留 profile。   |
| 运行构建失败与源码改名恢复 | Vite 构建测试验证构建配置，输入监听测试验证变化通知。          | 构建失败不关闭正在使用的应用，修复后完整新代际真正接管，并使用改名后的源码。                        |
| 公共包失败恢复与 HMR       | 快照测试验证完整输出、旧快照保留和解析；监听测试验证配置修改。 | 公共包构建失败传入会话后仍保留可用应用，修复可以继续；renderer 更新实际到达页面，同时保持运行进程。 |

本轮没有找到可以直接删除、且已由下层等价证明的真实场景。因此保留四个场景和既有六目标运行范围。三个会话场景已经共用一次隔离工作区准备，各自关闭控制器并恢复输入；没有再通过共享一个可变应用会话压缩测试时间。取消重试用例继续单独拥有其准备状态。

较小测试与完整链路验证同一主题，并不自动构成重复。特别是取消传递、会话可用性和实际进程交接，不能仅由底层函数的局部正确性推出。当前耗时还包含真实编译、隔离安装和宿主准备；移动三个毫秒级用例不应被描述成完整开发回归的显著提速。

## 本机验证

- 两个公共包的三个测试、类型检查和 lint 均通过；单次定向运行中的合同测试为 4 毫秒，两个 Node 接入用例共 426 毫秒。
- 四个真实开发场景全部通过，Vitest 报告耗时 102.74 秒；原启动、恢复、取消和清理断言保持。
- 全仓类型、lint、格式与 51 项常规测试通过，包含两个真实任务图迁移路径。
- 浏览器入口在自身配置中生成 JSON 报告，单项浏览器交互通过；CI 不再通过 Turbo 透传报告参数准备上游构建。
- 五份工作流通过 actionlint 1.7.12；实际工作流 Bash 与真实 Git／Turbo 查询通过 13 种选择输入，最终门禁通过七种成功、跳过及拒绝情况，见 [local-validation.json](local-validation.json)。

首轮全仓检查在 extension-sdk 输出目录交接时出现一次 Windows EPERM，失败按原样保留。核对时没有该工作区的 Node／Electron 任务仍在运行，既有输出已恢复；独立 SDK 构建和相同检查的重试通过，未确定原占用者，也未增加重试代码或声称已修复。其后格式检查指出新增任务图用例的一处排版，修正后格式与常规测试通过。原始日志与开发报告保存在忽略目录 .local/ci-test-review。

新的 CI 工作流按本次分工接入，最终提交的远端结果随关联 PR 检查留存。进一步改变平台覆盖或用替身替换真实开发链路，需要单独说明新增或丢失的保证，不能混入本次职责迁移。

## 判断依据

- [Google SMURF](https://testing.googleblog.com/2024/10/smurf-beyond-test-pyramid.html)：同时比较速度、维护、资源、可靠性和真实性。
- [The Practical Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html#AvoidTestDuplication)：较小测试覆盖细节，高层测试保留其额外证明的连接。
- [既有故障记录](../../ci-exploration/2026-10-27/README.md)：Linux 漏监听由较小的监听集成测试发现，Apple Silicon 退出异常由性能验证定位；开发副本与观察辅助的故障不能被混称为产品缺陷。

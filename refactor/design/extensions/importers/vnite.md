# Vnite Importer 接入方案

Vnite 导入器迁入游戏资料、本人记录、图文回忆、整理和本地配置。输入基线为 v4.14.0，实际备份与合成夹具见[核验记录](../../../verification/evidence/vnite-importer/live-backup.md)。新作品直接采用合法来源资料，其他记录与配置通过各自完整操作迁入。

<a id="scope"></a>

## 用途与输入

读取本地备份进行手动迁移，按[共同流程](../importers.md#flow)选择游戏与数据范围，无须资料方案。只登记一个导入页面，不注册 metadata provider，不连接 Vnite 账号或云同步，也不持续读取运行目录；联网补充另行发起。

支持官方 vnite-database-*.zip 数据库备份。该 ZIP 的根直接包含 game、game-local、game-collection 等 PouchDB / LevelDB 目录，并非条目 JSON；文件名不承担格式识别。按数据库结构和文档字段识别已验证的格式系列，v4.14.0 是源码基线，不把备份文件名中的日期当软件版本。用户通过 Vnite 自己的备份入口产生文件，本扩展不替其关闭数据库、恢复备份或重启应用。

game 是必需数据库；game-local 与 game-collection 缺席时分别表示没有可迁入的本地配置或合集，已存在但无法读取时只影响对应范围。只将这些数据库解压到本次受控临时目录，用 PouchDB 9 的 LevelDB 适配器打开副本。原 ZIP 保持只读，config、config-local、plugin、主题和程序设置不进入迁入数据。PouchDB 打开数据库可能维护底层文件，不能直接把用户的活动数据库当只读句柄。

使用 allDocs 的正常获胜修订，与 Vnite 自身读取一致；删除记录与设计文档不作为游戏，存在其他冲突修订不自动拒绝当前记录，也不合并不同修订中的私人值。分批读取正文和附件索引，需要图片时再读取字节；不会一次把全部图片装入对象列表。

缺失的可选字段按来源正常默认含义解释，例如没有 dailyPlayTimes 表示没有这类明细，没有合集 sortBy 不影响其实际成员。必需数据库无法读取时结束本次输入；单个字段或资源失败按实际项目报告，其他独立内容继续。

<a id="identity"></a>

## 游戏身份与来源资料保留

每个有效 game 文档提供一个 Game 的迁移输入。PouchDB 的 _id、_rev 与修订历史用于固定输入内的关系解释和本批次步骤对应，不登记为公开身份。缺少外部身份时，合法名称及已知资料仍可用于创建；同名不触发本地复用。

已知外部身份沿各来源的正式合同规范化：

| 来源字段         | 正式身份            |
| ---------------- | ------------------- |
| metadata.steamId | steam / app/{appid} |
| metadata.vndbId  | vndb / v{编号}      |
| metadata.igdbId  | igdb / game/{id}    |
| metadata.ymgalId | ymgal / ga{gid}     |

有效身份共同对应一个本地游戏时复用；没有对应时，以合法来源字段形成 prepared 输入，经 ingest 新增。多目标或类型冲突按共同规则处理。relatedSites 是普通外链，不从任意链接猜身份；源文字列表不直接生成主体与参与关系，缺少结构化依据的内容继续按补充笔记选择处理。

以下能够准确映射的来源普通资料默认选中，形成新作品的 prepared 候选；私人内容分别选择：

| 来源内容                                     | 本体采用                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------- |
| name、originalName、sortName                 | 名称、原文名称和排序名称，保留实际值                                       |
| releaseDate                                  | 合法部分日期；空值保持未知                                                 |
| description                                  | HTML 经共同安全转换形成 Markdown；普通文本保留实际段落                     |
| relatedSites                                 | 名称与安全 URL 组成的普通外链                                              |
| apperance.nsfw                               | 本地敏感内容处理标记，沿来源字段的实际拼写读取                             |
| record.addDate                               | 用户选择加入日期时，按导入时系统时区取日历日期，写入 added_date            |
| images/cover.webp                            | 当前主图；没有 cover 时可采用实际 wideCover                                |
| images/background.webp、logo.webp、icon.webp | 背景图、标题标志、游戏图标                                                 |
| metadata.tags、genres、platforms             | 选择“标签和分类”后作为普通标签，按共同 nameKey 规则复用                    |
| developers、publishers、extra                | 选择“补充资料笔记”后保留字段名与文字，不仅凭字符串创建人物、组织或参与关系 |

来源名称、简介、发行日期、外链及已明确本地图片默认选入新作品。已有作品默认保留，选择补空或覆盖后才更新。created_at 和 updated_at 使用本次实际写入时间，来源加入日期与最后运行时间保持各自含义。

本体只有一个当前主图，cover 与 wideCover 不同时登记为两项主图，也不为另一张图片制造私人回忆。源简介中的本地附件随正文准备并改写为本体引用；远端图片保留安全链接，下载沿共同的独立选择处理。图片用途由字段决定，不由尺寸猜测。

“补充资料笔记”默认关闭。选择后，只为有未映射资料文字的游戏创建一篇附加 Note，保持来源字段与值的对应，不改写作品简介。源软件的布局、最近列表隐藏、缓存大小和标记路径属于使用偏好，不转换为作品资料。

## 评分、状态与完成事实

record.score 使用 0–10 分、0.1 步进，乘 10 转为本体整数评分；0 是有效零分，-1 表示未评分。Vnite 没有同义的特别喜爱字段，不按评分、合集名称或回忆置顶推断。

| playStatus          | 当前安排                 | 完成事实                                     |
| ------------------- | ------------------------ | -------------------------------------------- |
| unplayed（未开始）  | null                     | 不新增                                       |
| playing（游玩中）   | active                   | 不新增                                       |
| partial（部分完成） | 不采用该状态，保留既有值 | 不据此生成完成记录                           |
| finished（已完成）  | null                     | 本地没有历史时初始化一条                     |
| multiple（多周目）  | null                     | 采用为至少一次完成，本地没有历史时初始化一条 |
| shelved（搁置中）   | onHold                   | 不新增                                       |

“未开始”不等于明确的游玩计划，“部分完成”也不自动变成正在玩或完成过。多周目没有具体次数，也没有表达当前正在进行哪一周目；不生成两条以上记录或自动设置 active。

完成记录的日期为空。addDate、lastRunDate、最后一段游玩的结束时间和回忆日期都不充当完成日期。既有完成历史保留，初始化使用共同的 expected.completionCount=0 条件；本输入没有逐次完成历史，不提供追加 N 次完成的操作。

## 游玩区间与累计时长

record.timers 中的 start、end 是带时区的时间点。有效区间转为 UTC 毫秒，durationMs 采用 end-start。Vnite 已在生成这些区间时处理暂停、短暂中断合并和短区间筛选，导入不重新计算其前台状态或再次套用当前计时阈值。

源区间没有可靠的历史启动配置身份，迁入活动不强行关联当前 game-local 配置。源区间存在重叠时保留实际记录，本体统计沿[共同活动口径](../../domains/library-queries.md#activity-statistics)处理；不同批次不按相似时间合并，同批次继续按步骤结果跳过已完成项。

record.playTime 的单位是毫秒。源码中的累计值由区间合计、dailyPlayTimes 的按日补录及无日期补记组成。按日值没有准确起止时间，不能伪造零点开始的活动。同时采用明细与总量时：

- 新游戏先迁入有效区间。累计值能够覆盖所选明细时，附加时长取累计值减去已迁入区间的时长；按日补录已包含在这个差额中，不再加一次。
- 累计值缺失或与所选明细矛盾时，保留可采用区间；明确的按日值可合计为附加时长，不生成按日活动。实际矛盾在该累计字段的结果中报告。
- 只选择累计时长时，直接沿共同的总量采用规则设置附加时长，不为它补造活动。

已有游戏默认保留活动与时长。用户选择追加来源区间时，通过普通活动操作保存，并按本批次步骤记录实际引用；继续不重复已完成区间。另建批次明确追加仍可新增。采用来源总量时，以本次实际活动量计算附加绝对值；总量不足时不采用，也不撤销其他已完成操作。

区间缺失、非法或结束晚于当前时间时报告该条未采用，不改成今天。lastRunDate 是来源的最近运行显示值，导入后最近活动由实际迁入记录得出，不能用一个日期补造使用时长。

## 回忆与合集

每条有正文或实际主图的 memory.memoryList 记录迁为独立 Note，关联所属 Game。标题使用游戏名及有效来源日期，原 Markdown 正文保留，images/memories/{memoryId}.webp 作为笔记封面。只有日期、没有正文和图片的空回忆不创建笔记。

正文中的 attachment://game/{gameId}/images/memories/inline/{imageId}.webp 通过备份中的真实附件取得字节，准备后改写为 attachment:{id}。解析正文结构后改写图片引用，保留链接文字、段落和格式，不用字符串全局替换改写普通正文。封面与内嵌图片分别采用，不把回忆图片当游戏截图或作品背景。

没有对应字节的图片报告未迁入，能够保留的文字继续迁入；不能把原 attachment 地址显示成已经迁好的本地图片。图片准备和 Note 完整保存使用共同操作。技术创建时间仍是本地实际保存时间，来源日期通过标题保留。回忆置顶只用于所属游戏内的笔记顺序，不生成全局收藏属性。

game-collection 中的实际合集迁为手动合集，games 数组决定成员与保存的人工顺序，sort 决定本次新建合集的相对顺序。显示排序不转成动态合集条件；源软件自动生成的开发商、状态等分组不在这个数据库中，不据此补造合集。

已有同名合集不自动合并。用户可明确选用已有目标，或本次创建相应合集；已有成员顺序保留，新成员按来源顺序追加。成员引用在本次源 _id 到 GameRef 的对应中解析，游戏未迁入时不制造空成员。

## 内容目录、启动与存档设置

本地配置由用户选择迁入，默认关闭。path.gamePath 可以登记为 GameDirectory；launcher 只转换当前 mode 所用的配置，不把三个分支都变成启动配置。路径可以采用明确的旧根到新根替换，再核对实际位置；替换只作用于结构化路径字段，不改写命令正文、URL 或进程名。文件或目录缺失不阻止游戏资料、回忆和游玩记录迁入。

| 来源启动方式            | 采用方式                                                                                                   |
| ----------------------- | ---------------------------------------------------------------------------------------------------------- |
| file                    | 实际 fileConfig.path 对应文件启动；源实现不使用 fileConfig.args，不把该遗留字段变成新增执行参数            |
| url，未指定 browserPath | 对应链接启动，保留实际 URL                                                                                 |
| url，指定 browserPath   | 在 Windows 按来源的 start 调用语义保存完整命令，保留浏览器与 URL                                           |
| script                  | 在 Windows 将非空 command 项按来源的 && 顺序组合，保留 UTF-8 代码页设置；workingDirectory 对应独立工作目录 |

源启动器自加的可见终端、外层 cmd 包装与 pause 不写入本体命令；用户自己写在 command 中的内容按实际文本保留。导入只保存配置，不执行命令、打开链接或运行游戏。Windows 命令不能作为其他平台的原生命令使用，无法对应的配置单独报告。

file、folder、process 监测方式分别对应文件、目录和进程名，monitorPath 按原含义采用。没有实际启动目标时不创建空配置；已有目标但缺少监测条件的来源配置可以保留为未完成配置，使用时沿正常入口补全，不从其他字段猜测监测路径。

savePaths 只有一项时可以对应本体单一存档位置，多个位置不取第一项，也不复制成虚构的多套启动配置。用户选择存档设置且位置可对应时，可采用 autoBackupSave 与合法 maxBackups；没有可用存档位置时保留本体默认关闭的自动备份。autoRestoreSave、Magpie、插件与全局启动预设不迁入。

saves/{saveId}.zip 保留在原输入中，作为原有归档保存。Vnite 将多处来源按 basename 合并，旧记录缺少各根历史路径与本体所需清单，当前 savePaths 也不足以恢复归档组成，因此这些 ZIP 不迁为本体历史备份。存档路径与可采用的备份设置仍按上文处理。

## 单页流程与默认值

页面依次选择备份、游戏和数据范围，开始后显示进度与结果。名称、来源身份、本地目标及结果分别成列，保持横向滚动；不增加整批差异预览或逐项配对向导。

来源普通资料、评分与状态、活动、回忆、标签与合集默认选中，作用于新游戏。已有对象默认保留，采用来源个人值、追加活动与采用总时长分别选择。补充资料笔记、本地启动及存档设置默认关闭；联网补充通过导入结果另行发起。

游戏创建使用 prepared 与独立 initial，普通资料及初始个人值共同提交。alreadyExists 按已有对象选项处理；活动、笔记、合集和配置分别使用完整操作。进度与源键对应按[批次合同](../importers.md#repeat)保存，失败不撤销已经成立的对象，继续不重复成功步骤。

只对本次选择但实际未完成的内容说明原因；来源的显示偏好、正常默认值和未选择功能不逐项告警。正文、命令、完整记录和用户备份内容不进入运行日志。导入页面遵守[共同文案规范](../../ui/components.md#copy)。

archive 负责只读源包和受控解压；database 封装 PouchDB 副本、分页与附件读取；mapping 解释来源身份、定位线索、保留字段与用户数据；import 负责调用原生新增、采用顺序与任务结果。IPC 只转发完整操作，Webview 不打开数据库。依赖按需加载，不在扩展激活时解压或打开输入。

使用普通 PouchDB 9 及成熟 ZIP、HTML 和 Markdown 解析库，不手写 LevelDB 格式或执行 Vnite 运行代码。LevelDB 原生依赖按目标平台打包，六个桌面制品目标分别验证实际装载和同一合成备份读取。

格式依据与样本范围见[核验记录](../../../verification/evidence/vnite-importer/live-backup.md)。验收覆盖非空数据库、正常获胜修订、三种启动形态、真实区间、回忆引用、图片字节、六种状态、零分与未评分、按日值、累计矛盾、删除记录、缺省合集字段及存档附件识别；完整迁移同时覆盖离线 prepared 新增与原批次继续、已有对象复用、initial 同次提交、明确来源资料保留、本体字段与图片准备、实际单页交互、身份冲突、已有数据采用、重复追加、路径替换、取消、部分提交、临时副本释放和独立制品。

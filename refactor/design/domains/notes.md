# 私人笔记与显式保存

Note 是用户独立保存的私人文字，可以不关联条目，也可以关联多个 Entry。标题、Markdown 正文、封面和关联都在用户明确保存时提交。需要返回作品中的准确位置时，使用 Annotation。

<a id="model"></a>

## 笔记身份与条目关联

library.notes 负责全库笔记，包括没有关联任何条目的笔记。各条目中的笔记列表只是对同一批笔记的关联查询。笔记没有主条目，也不占用 Entry 基础行；相同标题或正文不会使两篇笔记成为同一篇。一篇比较文章可以同时关联多部作品，所有入口读取同一份正文。从条目新建笔记时，编辑器默认带入当前条目，用户可以增减关联，也可以先写一篇没有关联的笔记。

条目简介描述资料，关系的 note 解释某项联系，独立 Note 则用于感想、攻略或考察。Annotation 另行保存位置和摘录。笔记只能关联七类 Entry；涉及具体卷、话或集时，背景写入标题或正文，并关联所属作品，不建立分部关联，也不解析显示编号来推断目标。用户将摘录整理成笔记后，笔记独立保存，原标注后续变化不会改动它。

笔记使用以下表：

| 表                       | 主要内容与引用                                                             |
| ------------------------ | -------------------------------------------------------------------------- |
| notes                    | id，以及标题、Markdown 正文、可选主图、创建和内容修改时间                  |
| note_entry_links         | (note_id, entry_id) 联合主键，分别直接引用 notes.id 与 entries.id          |
| note_content_attachments | (note_id, attachment_id) 联合主键，分别直接引用 notes.id 与 attachments.id |

note_entry_links 保存笔记与条目的关联，条目类别从真实 Entry 取得。关联用于整理和访问笔记；作品关系与人物参与分别通过相应的领域操作建立。

<a id="fields"></a>

## 内容字段与创建条件

notes 保存以下字段：

| 字段             | 含义与约束                                    |
| ---------------- | --------------------------------------------- |
| id               | 稳定笔记 ID，主键                             |
| title            | 可空标题，不唯一；未填写使用 NULL             |
| content          | Markdown 正文，非空列，默认空字符串           |
| primary_image_id | 用户明确采用的封面，可空，引用 attachments.id |
| created_at       | 笔记首次实际保存时的 UTC 毫秒时间             |
| updated_at       | 标题、正文或封面实际修改时的 UTC 毫秒时间     |

标题去除首尾空白后为空时存 NULL。列表可以从正文开头提取简短纯文本作为显示名称；仍没有文字时显示“未命名”。这些显示值不写回标题。正文保留有意义的缩进、行尾空格和换行，不对整篇内容执行 trim。封面必须由用户明确选择；没有封面时显示笔记图标，不自动提取正文图片，也不额外保存摘要。

打开编辑器不会创建记录。新笔记只有在用户明确保存，且至少具有标题、非空白正文或已采用封面时，才能创建。仅选择关联条目或仍在准备图片不满足创建条件。已有笔记允许清空后保存，系统不会自动删除它。首次保存为 created_at 和 updated_at 使用同一个时间；以后只有标题、正文或封面实际变化才更新 updated_at。无变化保存、编辑草稿、改变关联和重排都不更新时间。

索引包含 (updated_at DESC, id ASC) 和封面附件反查，标题没有唯一约束。用户可以保存尚未写完的文章，模型不为此增加另一种持久草稿身份。

<a id="ordering"></a>

## 两侧顺序与查询

笔记关联分别保存两侧顺序：

| 字段           | 排列范围               |
| -------------- | ---------------------- |
| order_in_note  | 这篇笔记的相关条目列表 |
| order_in_entry | 这个条目中的笔记列表   |

两个字段都不能为空，使用非负整数，默认 0。新关联追加到两侧列表末尾，重排只修改当前一侧。索引分别为 (note_id, order_in_note, entry_id) 和 (entry_id, order_in_entry, note_id)。全库笔记默认按 updated_at 降序、id 升序排列，支持检索标题和正文，以及按关联条目或未关联状态筛选。条目内的笔记按 order_in_entry、note_id 排列，笔记内的相关条目按 order_in_note、entry_id 排列，不另设全局人工顺序。

例如，将一篇比较笔记移到游戏列表首位，不会改变它在动画列表中的位置、笔记内部的条目顺序或最近修改时间。重排在核对当前成员和顺序基线后同事务提交，不通过连续交换单行完成，也不能用筛选结果覆盖未显示成员。编辑器中调整的关联和顺序随保存一起提交；独立列表中的明确整理动作则可以直接调用相应的完整操作。

<a id="editing"></a>

## 保存、取消与并发修改

编辑器中的标题、正文、封面和关联都属于当前草稿。普通查询和其他入口继续读取已经保存的内容。保存按钮与保存快捷键执行同一操作，只提交实际改动及[各自允许的基线](library-write-contracts.md#expected)。同一编辑流程中的正文和关联一起生效，不能先保存一部分，再允许用户取消剩余部分。

保存成功后，编辑器以此次结果建立新基线，后续输入仍然需要保存。取消只丢弃上次成功保存后的本地修改，不把打开时的旧快照写回数据库，也不撤销其他窗口或本窗口先前的提交。用户真正离开并准备丢弃有修改的草稿时，界面提供保存、放弃和继续编辑；没有修改则直接结束。恢复为原值、失去焦点或切换到仍保留草稿的页签，不应反复触发询问。

保存失败或冲突时，编辑器保留草稿和资源，供用户重试、比较、整理或另存。独立字段分别比较：标题修改可以与另一窗口的正文修改共存，未修改关联时也可与其他位置的关联重排共存。

同一正文的冲突由用户整理后重新提交，保存过程保持原文，不自动拼接或覆盖。目标已经删除时返回不存在，编辑器保留草稿供另存。

保存进行中不重复提交。未提交文字和图片只在当前运行期内保留，异常退出可能丢失上次保存后的内容，不另建恢复机制。

<a id="attachments"></a>

## 封面与正文图片

封面引用 attachments.id，Markdown 中的图片使用 `attachment:<id>`。本体解析正文后维护 note_content_attachments，并将正文、附件引用和实际条目关联同次提交。正文引用以 (note_id, attachment_id) 为联合主键，笔记端删除时级联解除，附件端限制删除并支持反查。封面引用同样限制附件删除。

插图先在草稿中准备和预览，不为挂载图片提前创建空笔记。只有准备完成且插入意图仍有效时，图片才进入实际草稿。尚未完成或失败的插入需要明确完成、重试或取消，不能漏掉图片后仍宣称保存完整。迟到结果不能恢复用户已经删除的占位，也不能插入已经取消或关闭的旧编辑内容。

保存先准备图片字节，再提交引用。保存失败时，当前编辑所需的资源继续保留，以便重试；取消时只释放本次编辑已经不再需要的准备和占用。仍可能撤销删除的图片保留到编辑结束。正式共享图片是否保留，由全部引用和占用共同决定，详见[附件](attachments.md)。普通资料获取不覆盖私人笔记。[资料库冷备份](../engineering/build.md#library-backup)复制完整资料根并保留正文附件；本次不提供选择性笔记导出，公开展示仍只使用用户明确选择的内容。

<a id="deletion"></a>

## 解除关联、删除与条目合并

解除关联只删除一项 note_entry_links；删除笔记才会删除笔记内容及全部关联。界面名称必须让用户区分这两种效果。删除 Entry、分部或文件都不删除相关笔记。笔记失去最后一项关联后，用户仍可从全库入口找到正文和图片。

条目合并时，笔记关联迁移到保留目标。同一篇笔记的重复关联需要去重并处理顺序，不复制正文；不同笔记也不会因为文字相同而自动合并。只修改笔记内容时，不要求仍有条目关联，也不受条目的 updated_at 锁定；本次明确修改关联时，仍须核对实际目标与相关基线。

## 修正

### 子进程重新继承了明确删除的环境变量

Windows 打包先复制父环境并删除 `CSC_LINK`、`CSC_KEY_PASSWORD`、`WIN_CSC_LINK` 和 `WIN_CSC_KEY_PASSWORD`，但共用进程函数再次执行 `{ ...process.env, ...options.env }`，使已经删除的变量重新出现。该错误违反现有的未签名打包政策；本轮没有读取或使用真实签名凭据。

共用函数现在直接传递显式 `env`；省略时由 Node 继承父环境，字段注释说明这是完整的子环境。已检查所有显式调用方，它们提供的都是完整环境。修正复用 [Node 24.11.1 的 spawn 合同](https://github.com/nodejs/node/blob/v24.11.1/doc/api/child_process.md)，无需增加另一项合并策略或删除标记。[Execa 的 extendEnv](https://github.com/sindresorhus/execa/blob/main/docs/api.md#optionsextendenv)也区分继承与完整环境，但当前缺陷不需要引入新依赖。

回归使用两个合成变量启动真实 Node 子进程，验证删除值保持缺失、保留值正确传入。修正前失败，修正后通过，见 [修正前](environment-before.log)、[修正后](environment-after.log)与[工具包类型检查](tooling-typecheck.log)。这是环境传递验证，不是签名或最终制品验收。

### 消费者测试在浏览器创建失败时未关闭预览服务

消费者测试先创建 Vite 预览服务，再在 `try` 之外启动 Chromium；启动失败时，已创建服务不进入清理。原有清理中，浏览器关闭失败也会跳过服务关闭。

现在每次成功创建资源后立即进入对应的 `try/finally`，外层通过 Vite 公开的 `server.close()` 关闭服务。两项既有消费者回归通过，见 [consumers.log](consumers.log)。没有为这处可直接检查的清理顺序增加常驻故障注入测试。

## 机制与替代方案核对

| 实际需要                                                  | 核对与判断                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 使用系统代理、代理认证，保留最终 URL 与多条 Cookie 响应头 | 比较 Node HTTP／fetch、Electron net.fetch 和 net.request。Node 的环境变量代理不等同于 Chromium Session 的系统／PAC 接入；net.fetch 更直接，但锁定 Electron 44.5.1 的文档明确列出 Response.url 不准确，其实现还合并数组响应头。现有 net.request 接入设计有具体缺口依据，继续保留；正式实现与完整网络验证仍属后续工作包。来源：[Electron net](https://github.com/electron/electron/blob/v44.5.1/docs/api/net.md)、[对应实现](https://github.com/electron/electron/blob/v44.5.1/lib/browser/api/net-fetch.ts)、[Node 环境代理](https://nodejs.org/docs/latest-v24.x/api/http.html#built-in-proxy-support)。 |
| 视图内异步读取、取消、失效后重查和离开时释放              | 对照 Solid 原语、solid-primitives 的取消组合及 TanStack Solid Query。TanStack 已提供 AbortSignal，重试、缓存与自动重查也能配置，不能据其默认值断言不适用。当前合同优先组合现有 Solid 能力，仅补实际共同行为；本轮没有理由预建查询框架或更换既定方案，也没有据文档比较宣称完成 UI 运行验证。来源：[Solid 社区讨论](https://github.com/solidjs/solid/discussions/2129)、[TanStack 取消](https://tanstack.com/query/latest/docs/framework/solid/guides/query-cancellation)、[可调整的默认行为](https://tanstack.com/query/latest/docs/framework/solid/guides/important-defaults)。                          |
